3. VTBench의 500개 레코드는 reasoning·perception·instruction 질문을 함께 둔다. “500 rows”와 프로젝트의 “1,500 QA” 설명은 즉시 모순으로 볼 수 없지만 split/protocol은 사용 전 고정해야 한다.
4. Ultralytics 8.4.208은 predict/tracking NMS IoU 기본값을 0.5로 바꾼다. validation은 0.7이므로 설정 drift가 비교를 왜곡할 수 있다.
5. Ultralytics MPS/CoreML 수정은 static ONNX export의 semantic crash와 CPU drift를 다룬 merged PR이다. export format·ORT 버전·입력 크기를 결과와 함께 기록해야 한다.
6. Transformers Grounding DINO phrase delimiter position-id 이슈는 공개 버그 보고이며, 해결 전 v5 grounding 결과는 환경 축으로 검증해야 한다.
7. FSDP2 checkpoint hook PR은 아직 merge 확인 전이다. 완결된 기능이 아니라 분산 VLM 학습의 검증 항목이다.
8. 오늘의 우선순위는 새 architecture 추종보다 데이터 표현, evaluation bucket, inference/export 기본값을 고정해 failure matrix를 만드는 것이다.

## 1) 오늘의 전체 DL 트렌드 5줄

- 영상·상호작용 VLM은 평균 점수보다 지각, 도구 조작, 증거 누적의 실패 원인을 따로 관찰할 수 있는 데이터 형식으로 이동하고 있다.
- 공개 preview는 연구 재료지만 전체 크기·license·immutable revision·최종 split을 자동으로 보증하지 않는다.
- detection baseline은 NMS 기본값 하나만으로 prediction/tracking과 validation의 동등성이 깨질 수 있다.
- export backend는 같은 ONNX 모델이라도 CoreML 형식과 runtime 버전에서 semantics가 달라질 수 있는 실험 변수다.
- distributed checkpointing과 grounding preprocessor 이슈는 framework revision을 기록해야 할 이유다.

## 2) CV / DL-CV 핵심

### Ultralytics 8.4.208 — predict/tracking 기본 NMS IoU 변경

- **사실:** 공식 8.4.208 릴리스는 predict와 tracking 기본 NMS IoU를 0.7에서 0.5로 바꾸며 validation은 0.7을 유지한다고 공지한다. [공식 릴리스](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.208)
- **저자 주장:** TensorRT 11 FP16 NMS-free export가 최대 3% 더 빠르다고 릴리스 노트에 적혀 있다.
- **진단:** validation과 deployed inference의 서로 다른 NMS default는 AP, ID switch, count error 차이를 학습 변화로 오인하게 한다.
- **가설:** crowded/small-object 영상에서 0.5는 중복 검출을 줄이지만 근접 객체 recall 또는 track continuity를 악화시킬 수 있다.
- **최소 실험:** 동일 checkpoint·입력 크기·tracker에서 IoU 0.5/0.7만 교체하고 AP, small-object recall, IDF1, line-count error를 장면 밀도별로 기록한다.
- **한계:** 3%는 작성자 조건부 수치다. GPU, TensorRT, batch, shape, warm-up, latency percentile 없이 일반화하지 않는다.

### Ultralytics PR #27117 — MPS/CoreML export semantic parity

- **사실:** merged PR은 static ONNX의 MPS CoreML export가 이미지 크기에 따라 semantic crash 및 CPU drift를 낳는 문제를 다루며 static graph 형식을 ML Program으로 변경한다. ORT 1.19.2 abort 때문에 특정 변환 경로도 제외했다. [공식 PR](https://github.com/ultralytics/ultralytics/pull/27117)
- **진단:** export 성공은 numerical/semantic parity를 의미하지 않는다.
- **가설:** backend 문제가 있을 때 detection count와 class assignment drift가 latency보다 먼저 나타날 수 있다.
- **최소 실험:** PyTorch, ONNX Runtime CPU, CoreML MPS에서 동일 고정 입력으로 box 수, class, confidence, IoU agreement를 비교한다.
- **한계:** PR의 결과는 특정 runtime 조합이다. 다른 모델·macOS·ORT에서는 독립 확인이 필요하다.

## 3) VLM / Multimodal / Video 핵심

### V-Thinker 공개 데이터 — perception과 tool-grounded interaction 분리

- **사실:** V-Perception-40K 공식 뷰어는 36.7k 행의 단일 split과 image, question, answer, python_code, element_arrtibute 필드를 보인다. [공식 데이터셋](https://huggingface.co/datasets/We-Math/V-Perception-40K)
- **사실:** V-Interaction-400K 공식 뷰어는 25개 train part와 original_img_code, edited_image, tool_code, CoT_with_code 등을 노출한다. [공식 데이터셋](https://huggingface.co/datasets/We-Math/V-Interaction-400K)
- **저자 주장:** 프로젝트는 point-level perception alignment 뒤에 interactive reasoning을 학습시키는 curriculum을 제안한다. [공식 프로젝트](https://github.com/We-Math/V-Thinker)
- **진단:** 단일 VQA 정답률은 무엇을 봤는지와 도구 조작/수정 지시를 실행했는지를 분리하지 못한다.
- **가설:** 편집 전후 증거와 tool code가 있는 예제에서 오류를 perception, action grounding, readout으로 나누면 context 증가보다 오류 유형별 개입이 효율적일 수 있다.
- **최소 실험:** 동일 base VLM에서 perception-only와 interaction-style 예제를 분리 평가하고 원본 이미지 제거·편집 이미지 제거·tool code 가림의 ablation으로 bucket별 정확도와 오류 전이를 기록한다.
- **한계:** 공개 뷰어의 행 수와 split은 관측치일 뿐 preview/최종 구성·license·데이터 중복 여부를 단정하지 않는다.

### VTBench — 한 레코드, 세 가지 능력 질문

- **사실:** 공식 뷰어의 500개 train 레코드는 question_reasoning, question_perception, question_instruction과 각 답/annotation 이미지를 함께 가진다. [공식 데이터셋](https://huggingface.co/datasets/We-Math/VTBench)
- **진단:** 한 시각 상황에 세 질문을 묶으면 지각 오류가 instruction/reasoning 오류로 전파되는 경로를 볼 수 있다.
- **가설:** visual evidence가 부족하면 perception과 reasoning이 함께 떨어지고, 지시 표현만 바꾸면 instruction bucket이 독립적으로 민감할 수 있다.
- **최소 실험:** original, visual-evidence mask, instruction paraphrase, answer-option permutation 조건에서 세 bucket 변화와 conditional error를 비교한다.
- **한계:** train 뷰어만으로 일반화 성능이나 video-domain robustness를 주장할 수 없다. evaluator와 split을 먼저 동결해야 한다.

### Grounding DINO v5 phrase delimiter issue

- **사실:** Transformers 공식 이슈 #50465는 v5 계열에서 phrase delimiter의 text position id가 0이 된다는 공개 재현 보고다. [공식 이슈](https://github.com/huggingface/transformers/issues/50465)
- **구분:** 이는 커뮤니티/사용자 버그 보고이며 해결·성능 영향은 유지보수자가 확정한 사실이 아니다.
- **최소 실험:** 동일 이미지·caption에 v4와 v5 processor를 고정해 token/position-id, phrase별 box score, phrase recall을 비교하고 preprocessing artifact를 저장한다.

## 6) 오늘의 중요한 Finding 3개

1. **VLM 평가의 단위는 평균 점수가 아니라 오류 전이여야 한다.** 같은 scene에서 perception·instruction·reasoning을 나누면 다음 실험의 개입 위치가 보인다.
2. **deployment default는 protocol이다.** NMS threshold와 export runtime을 고정하지 않으면 잘못된 model comparison이 만들어진다.
3. **공개 이슈는 evidence의 등급을 낮춰야 한다.** Grounding DINO와 FSDP2 신호는 재현할 가치가 있지만 해결된 사실이나 보편 성능 저하로 쓰면 안 된다.

## 7) 과대평가 가능성 / 주의할 연구·릴리스

- V-Thinker의 project-level 수치와 전체 데이터 규모는 작성자 제공 설명이다. 현재 뷰어 row/split과 같은 의미인지, leakage/duplicate가 없는지는 독립 검증 전까지 보류한다.
- Ultralytics 속도 수치는 hardware/runtime 조건이 빠진 일반 성능 주장으로 확장하지 않는다.
- CoreML PR이 merge됐더라도 backend parity는 모델, input shape, OS, converter revision별로 다시 확인해야 한다.
- Grounding DINO 이슈와 FSDP2 PR은 해결 완료 상태가 아니다.

## 9) Top 1 미니 리뷰 — V-Thinker 데이터/VTBench 묶음

**문제 진단:** VLM 결과 하나가 나빠도 visual perception, instruction grounding, multi-step reasoning 중 무엇이 실패했는지 평균 accuracy로는 알기 어렵다.

**핵심 설계:** V-Perception에는 시각 요소/코드 표현을, V-Interaction에는 원본·편집 결과와 tool trace를, VTBench에는 같은 record의 세 질문 축을 둔다.

**저자 주장과 사실의 경계:** 프로젝트의 curriculum/성능 표는 저자 주장이다. 반면 공개 뷰어에서 확인되는 field 구조와 row/split 관측은 사실이다.

**검증 가설:** tool trace와 edited evidence가 있으면 action grounding failure를 perception failure와 분리할 수 있다.

**최소 실험:** 동일 모델에서 image-only, image+tool trace, edited-image-only를 비교하고 perception/instruction/reasoning bucket의 conditional accuracy와 calibration을 기록한다.

**기여 판정:** unseen template와 paraphrase에서도 bucket별 개선이 재현되고, frame/evidence 제거 시 예상한 실패 전이가 나타나야 한다.

**주의:** synthetic/programmatic visual data에서 좋아진 결과가 자연 영상·OCR·작은 객체·geographic shift에 전이된다는 근거는 아직 없다.

## 10) 후속 연구 씨앗

### A. Evidence-to-action failure matrix
- **질문/가설:** interaction VLM의 오류는 visual evidence 부족보다 action grounding에서 더 자주 발생하는가?
- **최소 실험:** visual evidence, edited result, tool trace를 하나씩 가린 2×2×2 ablation을 하고 정확도·self-consistency·오류 유형을 기록한다.
- **판정:** tool trace 추가가 모든 bucket에 동일하게만 작용하면 action-specific 가설은 약해진다.

### B. NMS parity protocol
- **질문/가설:** NMS 0.5/0.7 기본값 차이가 crowded traffic/해양 small-object에서 모델 순위를 바꿀 수 있는가?
- **최소 실험:** 동일 prediction을 IoU/score sweep으로 후처리하고 mAP, small-object recall, IDF1, count error 및 calibration을 기록한다.
- **판정:** 모든 slice와 tracker에서 순위가 유지되면 default sensitivity가 낮다는 유용한 negative result다.

### C. Export semantic checksum
- **질문/가설:** CoreML export drift는 aggregate mAP 전보다 image-level box/class disagreement로 먼저 감지된다.
- **최소 실험:** golden input 100장을 PyTorch/ORT/CoreML에 통과시키고 class, box IoU, score의 tolerance agreement와 failure exemplar를 저장한다.
- **판정:** agreement가 모든 path에서 충분히 높으면 backend-specific anomaly 가설을 기각한다.

- 새로운 video VLM backbone/SOTA를 표방하지만 공개 checkpoint, evaluation script, dataset revision이 없는 공지는 오늘의 실험 설계에 추가하지 않았다.
- FSDP2 PR은 분산 학습을 실제로 쓰지 않는다면 merge/release 확인 전까지 watchlist에만 두면 충분하다.
- Grounding DINO 이슈는 phrase grounding 실험을 운영하지 않는다면 즉시 migration을 중단할 근거는 아니며 environment regression test만 추가하면 된다.
