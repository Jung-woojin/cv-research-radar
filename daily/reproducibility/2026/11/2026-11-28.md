## 1. LTX: noise를 끄는 설정이 결정적 업데이트도 바꾼다

**Claim·관측:** 11/27 13:03 UTC 게시된 [이슈](https://github.com/huggingface/diffusers/issues/15423)는 `eta=1`, `s_noise=0`, sigmas `[0.8, 0.4, 0]`, ones sample과 velocity `0.25`에서 첫 step이 약 `0.85`를 반환했다고 보고한다. reference에 맞는 rescaling을 적용한 기대값은 약 `0.6375`이며, `s_noise=1e-8`에서는 후자에 가까워진다는 보고다. 설치 버전·hardware는 이슈에 명시되지 않았다. 이는 실제 영상 품질 측정이 아닌 tensor fixture다.

**확인 사실·진단:** Diffusers commit `509b7658e8d99a811050f26ce4ed0a40b65ccfee`의 [scheduler](https://github.com/huggingface/diffusers/blob/509b7658e8d99a811050f26ce4ed0a40b65ccfee/src/diffusers/schedulers/scheduling_ltx_euler_ancestral_rf.py#L390-L409)는 signal 비율 곱셈을 `eta > 0 and s_noise > 0` 안에 둔다. [ComfyUI 고정 reference](https://github.com/Comfy-Org/ComfyUI/blob/3ac5d7941dfa2504555260512132d1cb5664648d/comfy/k_diffusion/sampling.py#L240-L266)는 `eta > 0`에서 해당 비율을 적용한다. 이슈의 reference 링크 줄 번호보다 실제 RF 함수가 아래에 있으므로 해당 함수를 직접 확인했다.

**가설:** stochastic amplitude와 deterministic rescaling의 제어 조건을 결합한 것이 0 경계 불연속의 원인이다. noise를 끄는 ablation을 다른 알고리즘으로 바꾸어 해석할 위험이 있다.

**반증 가능한 최소 실험:** CPU FP32, 동일 초기 tensor·schedule로 `eta∈{0,1}` 및 `s_noise∈{0,1e-8,1}`를 비교한다. signal rescaling만 분리한 구현과 reference의 단일 step을 대조한다. terminal sigma=0, dtype, generator state 소비도 별도 검사한다. weights·dataset은 필요 없다.

**GO/KILL:** 정확한 0에서만 reference와 불일치하고 rescaling 분리로 해소되면 GO. 양 구현의 parameterization을 맞춘 뒤 차이가 사라지면 해당 가설 KILL. 영상 품질 개선은 이 실험만으로 주장하지 않는다.

**수정 상태:** open. [다른 사용자의 댓글](https://github.com/huggingface/diffusers/issues/15423#issuecomment-7230009554)은 코드 해석과 작업 의사를 밝힌 것이며 독립 실행 결과가 아니다. 번호 검색에서 연결 PR을 찾지 못했으며, 수정·배포 완료는 확인하지 못했다.

## 2. Ultralytics: 영상 데이터보다 먼저 source manifest가 달라진다

**Claim·재현 조건:** 11/27 19:23 UTC 게시된 [이슈](https://github.com/ultralytics/ultralytics/issues/27409)는 Ultralytics 8.4.220, main `20da7d2f5`, Windows, Python 3.11, torch 2.15.0 CPU에서 두 줄짜리 `.streams` 파일이 공백으로 쪼개져 `ConnectionError`를 일으킨다고 보고한다. 같은 영상의 디렉터리에서 공백을 제거하면 predict·track이 진행된다는 대조다. source 조각 수는 작업 디렉터리 공백에도 의존하므로 고정된 실패 배율로 해석하지 않는다.

**확인 사실·diagnosis:** [고정 loader](https://github.com/ultralytics/ultralytics/blob/20da7d2f5/ultralytics/data/loaders.py#L123-L131)는 `f.read().rsplit()`을 사용한다. [같은 revision 문서](https://github.com/ultralytics/ultralytics/blob/20da7d2f5/docs/en/modes/predict.md#L354-L366)는 한 줄당 source 하나를 명시한다. 공백이 source 경계로 해석되는 코드와 문서 계약이 충돌한다.

**가설:** workstation마다 경로 문자열이 달라지면 데이터 로딩 단계에서 입력 source 집합이 바뀐다. 동일 weights·seed를 맞추어도 해결되지 않는 환경 의존 재현 실패다.

**반증 가능한 최소 실험:** 먼저 weights 없이 두 줄 manifest의 source 문자열·개수·순서를 비교한다. 공백·한글·빈 줄·주변 공백·일반 URL을 포함하고, 줄 단위 파싱으로 source 수가 보존되는지 검사한다. 이후 같은 local video를 두 디렉터리에 복사해 동일 predictor 옵션으로 첫 frame 수신을 확인한다. codec 실패와 경로 파싱 실패는 분리한다.

**GO/KILL:** 줄 단위 파싱만으로 정확한 두 source와 영상 열기가 복구되면 GO. source 문자열이 이미 정확한데도 실패하면 파싱 가설 KILL 후 codec·파일 접근을 조사한다. tracking 정확도나 ID 안정성 개선으로 확대하지 않는다.

**수정 상태:** open. [collaborator 댓글](https://github.com/ultralytics/ultralytics/issues/27409#issuecomment-7227535887)은 PR 요청이며 실행 확인이 아니다. 자동 인사 댓글도 독립 검증이 아니다. 연결 수정 PR·배포는 확인하지 못했다.

## 3. chat template 날짜: seed 이전에 model input을 고정해야 한다

**Claim·관측:** [이슈 #51362](https://github.com/huggingface/transformers/issues/51362)는 Transformers 5.24.1에서 같은 messages를 모의 날짜 하루 간격으로 렌더링하면 날짜 문자열이 바뀐다는 tokenizer-only 재현을 제시한다. 11/27 19:52 UTC 게시된 [PR #51397](https://github.com/huggingface/transformers/pull/51397)은 SmolLM3 tokenizer revision `a07cc9a`로 input IDs 차이, 날짜 고정 후 동일성, 고정 날짜의 원래 template과의 일치를 검증했다고 별도 작성자가 보고한다.

**확인 사실·mechanism:** [공식 SmolLM3 template](https://huggingface.co/HuggingFaceTB/SmolLM3-3B/blob/main/chat_template.jinja)은 기본 system header에 `strftime_now` 결과를 넣는다. Transformers commit `e5bbd1d6fe33295fa200d34dabfbc20579d249cf`의 [helper](https://github.com/huggingface/transformers/blob/e5bbd1d6fe33295fa200d34dabfbc20579d249cf/src/transformers/utils/chat_template_utils.py#L628-L629)는 `datetime.now()`를 읽는다. 따라서 checkpoint revision만 고정해도 시간 의존 입력이 남는다. 모든 template·override 분기가 날짜를 넣는다는 뜻은 아니다.

**증거 경계:** maintainer는 [댓글](https://github.com/huggingface/transformers/issues/51362#issuecomment-7218556045)에서 기본 warning보다 문서화를 선호한다고 밝혔다. PR diff는 문서와 docstring만 바꾼다. 작성자의 utility test 통과 보고가 있지만, upstream bot 댓글은 CI 승인 대기를 알린다. 이를 upstream CI 통과나 새 고정 날짜 API의 배포로 표현하면 안 된다. 연결 논문의 정답 변화 수치는 이번에 독립 검증하지 않아 사용하지 않는다.

**가설·최소 실험:** revision·messages·template·reasoning mode를 고정하고 clock만 하루 바꾼다. 렌더링 문자열과 token IDs hash를 저장한다. template 복사본의 clock 호출을 명시적 `benchmark_date` 변수로 치환한 뒤 같은 날짜 형식으로 값을 넘겨 양 날짜의 동일성을 검사한다. 단순히 kwarg만 추가하면 원래 clock 호출은 남는다. tokenizer-only CPU 실험부터 하고, 이후 날짜×seed×batch 조건을 분리해 답변 변화를 검사한다. VLM 전체로의 영향은 추가 검증 대상이다.

**GO/KILL:** 날짜만 바꿔 input IDs가 달라지고 고정 template에서 일치하면 입력 재현성 audit GO. task 결과가 유지되면 성능 영향 가설은 해당 task에서 KILL. 서로 다른 prompt를 사용한 점수 비교는 `not strictly apples-to-apples`다.

**수정 상태:** PR head `3c9e9c522d75bbd6cfe7518d326dc42d5ca78bfd`, open, `merged_at=null`. 문서 제안과 배포 완료를 구분한다.
