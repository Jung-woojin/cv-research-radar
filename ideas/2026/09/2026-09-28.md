# 후보 1. ConfigGround
## Configuration-Stable Evidence Routing for Tiny-Object VLM Grounding

### 1) 문제 정의
VLM은 작은 resize만으로 image tiling/token arrangement가 바뀌고, 그 결과 answer가 flip될 수 있다. 최근 Reading Right, Answering Wrong은 오답 상태에서도 모델이 정답 내용을 읽을 수 있지만 answering 단계에서 그 evidence를 제대로 사용하지 못하는 경우가 많음을 보였다. Small/tiny object에서는 이 문제가 더 심할 가능성이 높다. 물체가 tile boundary를 넘거나 token partition이 바뀌면 semantic evidence는 살아 있어도 query-to-evidence routing이 흔들릴 수 있다.

핵심 질문은 “해상도를 더 높이면 좋은가?”가 아니라 “동일 scene과 동일 query에서 visual configuration이 바뀌어도 같은 evidence를 사용하게 만들 수 있는가?”다.

### 2) 기존 연구의 빈틈
기존 small-object 연구는 P2, tiling, larger input, super-resolution처럼 representation 자체를 강화한다. VLM robustness 연구는 resize instability를 관찰하지만 tiny-object grounding과 직접 연결하지 않는다. RIS/grounding PEFT는 alignment를 학습하지만 configuration invariance를 명시적으로 강제하지 않는다.

### 3) 핵심 가설
같은 image-query pair의 여러 resize/tiling configuration에서 정답 evidence는 상당 부분 recoverable하지만, evidence routing이 달라져 output이 흔들린다. 따라서 cross-configuration evidence consistency를 학습하면 backbone을 크게 바꾸지 않고 grounding stability와 tiny-target recall을 동시에 높일 수 있다.

### 4) 제안 방법
가칭 ConfigGround.

- Multi-Configuration Sampler: 동일 image를 2~4개 resize/tiling/token-budget configuration으로 생성.
- Evidence Extractor: 각 configuration에서 query-conditioned spatial map 또는 proposal score를 추출.
- Geometry Transport: 원본 좌표계로 evidence map/box score를 역매핑.
- Reciprocal Evidence Adapter: BRL처럼 vision↔language adapter를 양방향으로 두되, 각 configuration에서 같은 target evidence를 강조하도록 공유.
- Configuration Consistency Loss: transported evidence map, top-k proposal ranking, target identity를 일치시킴.
- Confidence Gate: configuration disagreement가 클 때 high-resolution branch를 추가 실행.

구조는 Image+Query → multi-configuration views → shared frozen VLM/grounder → lightweight reciprocal adapter → coordinate-normalized evidence consistency → final grounded answer/box/mask.

### 5) Baseline
- 원본 VLM/grounding model
- fixed high-resolution
- fixed P2 또는 high-res tile
- test-time multi-scale ensemble
- standard PEFT/LoRA
- BRL-style adapter without consistency
- image-only consistency
- answer-only consistency
- oracle best-configuration upper bound

### 6) 데이터셋 / 평가
1차는 RefCOCO/+/g와 작은 target subset. 2차는 remote-sensing referring grounding 또는 자체 aerial/maritime query set. 별도 diagnostic split으로 target box area를 tiny/small/medium/large로 나눈다.

### 8) 예상 실패 모드 / negative result
- 실제 병목이 routing이 아니라 low-resolution representation loss일 수 있다.
- consistency가 잘못된 configuration의 evidence까지 평균내 성능을 떨어뜨릴 수 있다.
- fixed high-resolution이 compute 여유가 있을 때 더 단순하고 강할 수 있다.
- configuration flip이 OCR/document VQA에는 크지만 natural/aerial object grounding에서는 작을 수도 있다.

이 경우에도 “small-object VLM failure에서 configuration instability는 2차 요인이고 representation ceiling이 우세하다”는 진단 결과가 남는다.

### 9) novelty가 약해질 지점 / 방어
단순 multi-scale consistency training으로 보이면 약하다. 논문의 중심은 scale augmentation이 아니라 readable-but-unused evidence를 tiny-object grounding에서 직접 측정하고, configuration change가 evidence routing을 어떻게 바꾸는지 진단한 뒤 그 경로만 교정하는 데 둬야 한다. 반드시 “정답은 읽을 수 있는데 grounding/output만 틀린 사례”를 분리해 분석해야 한다.

### 10) 4~8주 MVP
- Week 1: 기존 VLM/grounder에서 resize/tiling sweep, configuration flip curve 작성.
- Week 2: target-size별 readable-but-unused case 정의. proposal/evidence upper bound 설계.
- Week 3: coordinate-normalized evidence consistency만 추가.
- Week 4: reciprocal adapter 추가.
- Week 5: disagreement-triggered high-res gate.
- Week 6: aerial/remote-sensing external validation.
- Week 7~8: ablation, latency, qualitative analysis.

GO/KILL 기준: tiny/small subset에서 configuration flip이 baseline error의 의미 있는 비중을 차지하고, oracle best-configuration 또는 evidence ensemble이 baseline 대비 명확한 회복을 보여야 한다.

### 11) 성공 시 contribution 3개
1. Tiny-object VLM/grounding에서 configuration-induced evidence-routing failure를 정량화.
2. Frozen foundation model 위 lightweight cross-configuration reciprocal evidence adapter 제안.
3. accuracy뿐 아니라 Configuration Flip Rate와 Same-Target Recovery Consistency를 포함한 evaluation protocol 제시.

# 후보 2. PairRefine
## Paired-Degradation Supervision for Budgeted Small-Object Refinement

### 1) 문제 정의
Fog/night/rain에서 small-object detector는 high-resolution feature를 더 많이 쓰고 싶지만, 항상 P2/tiling을 켜면 latency와 memory가 커진다. Dense Coverage, Sparse Refinement는 “전체 coarse coverage + 선택적 high-res refinement”가 bandwidth-constrained perception에서 효과적임을 보였다. ConSynth-X는 동일 source scene과 adverse version의 paired supervision을 제공하고, C2FXNet은 condition-aware coarse-to-fine routing이 adverse detection에 유효함을 보여준다.

새 질문은 “어디를 refine할 것인가”를 heuristic/attention으로 정하지 않고, clean-adverse pair가 알려주는 실제 recoverable benefit으로 학습할 수 있는가다.

### 2) 기존 빈틈
Selective-resolution detector는 중요도 score를 target presence나 uncertainty로 예측하는 경우가 많다. 그러나 adverse weather에서 어떤 patch가 refinement로 실제 이득을 얻는지에 대한 ground-truth-like supervisory signal은 드물다. Paired clean/adverse data는 이 counterfactual benefit을 근사할 수 있다.

### 3) 핵심 가설
각 adverse patch에 대해 “coarse adverse prediction”과 “high-res adverse prediction”의 차이뿐 아니라 clean counterpart의 feature/box evidence를 사용하면 refinement benefit을 더 정확히 예측할 수 있다. 그러면 same FLOPs에서 always-P2보다 small-object recall을 유지하거나 높일 수 있다.

### 4) 제안 방법
가칭 PairRefine.

- Coarse Coverage Branch: 저비용 P3/P4 또는 downsampled detector로 전체 scene 처리.
- Paired Benefit Teacher: 학습 시 clean/adverse pair를 함께 보고 각 region의 “high-res refinement가 회복할 수 있는 detection loss”를 계산.
- Benefit Predictor: inference에서는 adverse image만 보고 region별 expected recovery score 예측.
- Sparse P2/Tile Refiner: top-budget regions에만 P2 또는 native-resolution crop 적용.
- Fusion Head: coarse detections와 refined detections 통합.
- Optional Scene Prior: fog/dark/clear scene embedding을 benefit predictor에 조건으로 제공.

### 5) Baseline
- standard YOLO/D-FINE
- always-P2
- SAHI/fixed tiling

- confidence-based tile
- entropy/uncertainty-based tile
- saliency-based tile

- oracle benefit using clean-adverse paired labels

### 8) 실패 모드 / negative result
- synthetic pair가 real fog의 statistics를 충분히 대표하지 못할 수 있음.
- benefit predictor가 사실상 objectness predictor로 축소될 수 있음.
- high-res refinement보다 dehazing/feature adaptation이 더 효율적일 수 있음.
- clean counterpart가 알려주는 회복 가능성이 real degradation에서는 과대평가될 수 있음.

이 경우 “paired clean supervision은 region selection에는 유효하지만 real-world domain transfer를 보장하지 않는다”는 data-centric finding으로 전환 가능하다.

### 9) novelty 방어
“adaptive tiling”으로 보이면 약하다. 핵심은 paired clean-adverse data를 counterfactual supervision으로 사용해 “이 region에 추가 spatial compute를 쓰면 얼마만큼의 detection loss가 회복되는가”를 직접 학습하는 것이다. 반드시 random/uncertainty/saliency selector와 benefit calibration을 비교해야 한다.

### 10) 4~8주 MVP

- Week 2: clean/adverse pair에서 oracle regional recovery map 생성.
- Week 3: simple CNN benefit predictor.
- Week 4: top-k sparse refiner.
- Week 5: synthetic→real transfer.

GO/KILL 기준: oracle regional refinement가 20% 이하 area에서 always-P2 성능의 대부분을 회수할 수 있어야 한다. 이게 안 되면 router 연구보다 full-resolution backbone 개선이 맞다.

### 11) contribution
1. Paired clean-adverse supervision을 이용한 regional refinement-benefit formulation.
2. Small-object adverse detection용 budgeted sparse P2/high-res refinement.
3. recovery-per-pixel과 condition-wise Pareto를 포함한 compute-aware robustness evaluation.

# 후보 3. UncertainHier
## Confidence-Gated Semantic Hierarchies for Open-Vocabulary Detection

### 1) 문제 정의
InterHier는 hand-crafted fixed connector 대신 learnable context로 super/sub-category 관계를 더 유연하게 해석한다. 하지만 semantic hierarchy 자체가 항상 옳다는 보장은 없다. 특히 aerial/maritime fine-grained category에서는 유효한 관계도 있지만, visual appearance와 taxonomy가 어긋나는 class pair도 많다.

새 질문은 hierarchy를 주어진 truth로 쓰지 않고 “이 semantic edge를 이번 visual region에서 믿어도 되는가?”를 추정하는 것이다.

### 2) 기존 연구의 빈틈
기존 hierarchy-aware OVD는 super/sub relations를 유용한 prior로 사용하지만 잘못된 ancestor/neighbor transfer가 novel-class prediction을 해칠 때 이를 reject하는 메커니즘이 약하다. 최근 uncertainty-aware multimodal grounding 연구는 semantic/geometric cue를 belief로 결합하고 필요하면 abstention을 선택한다. 이 아이디어를 OVD semantic hierarchy에 가져오면 hierarchy-induced negative transfer를 직접 연구할 수 있다.

### 3) 핵심 가설
모든 hierarchy edge가 모든 visual region에 동일하게 유효하지 않다. Region-text evidence와 hierarchy edge confidence를 함께 사용해 관계를 gate하면 novel class benefit은 유지하면서 base/novel confusion과 negative transfer를 줄일 수 있다.

### 4) 제안 방법
가칭 UncertainHier.

- Hierarchy Graph: class-superclass/subclass 관계.
- Edge Reliability Encoder: text-only relation prior + region-conditioned visual compatibility.
- Confidence Gate: edge별 weight 또는 abstain.
- Evidence Fusion: direct class prompt와 trusted ancestor/descendant prompt evidence를 mixture.
- Conflict Detector: direct class evidence와 hierarchy evidence가 강하게 충돌하면 hierarchy path 차단.
- Optional calibration loss: edge confidence가 실제 gain/loss를 예측하도록 pair-level supervision.

Prediction = direct visual-text score + trusted hierarchy-edge contribution. 단, gate가 낮으면 direct score로 복귀.

### 5) Baseline
- vanilla OVD
- fixed hierarchy prompt
- InterHier
- prompt ensemble
- semantic-similarity weighted hierarchy
- visual-only gating
- text-only gating
- full UncertainHier
- oracle edge gating based on validation gain

### 8) 실패 모드 / negative result
- hierarchy edge confidence를 안정적으로 supervision하기 어려울 수 있음.
- direct class text embedding이 충분히 강하면 hierarchy가 거의 필요 없을 수 있음.
- curated hierarchy에서는 gain이 있지만 automatically generated hierarchy에서는 noise가 커질 수 있음.
- visual region이 작으면 edge reliability 자체도 불안정할 수 있음.

이 경우 “semantic hierarchy의 이득은 특정 low-data novel classes에 국한되며 global prior로 쓰면 오히려 해롭다”는 진단 논문으로 방향 전환 가능.

### 9) novelty 방어
단순 InterHier + gate로 보이면 약하다. 핵심 contribution을 “hierarchy-induced negative transfer를 instance/class level에서 정의하고 측정”하는 데 둬야 한다. 또한 edge confidence가 실제 intervention gain을 예측하는지 검증해야 한다. 즉 architecture보다 diagnostic + selective use of hierarchy가 중심.

## 이번 주 가장 추천: ConfigGround

이번 주는 ConfigGround를 가장 먼저 검증할 가치가 있다. 이유는 새로운 module을 오래 만들기 전에 1~2주 안에 가설의 핵심을 빠르게 죽이거나 살릴 수 있기 때문이다.

첫 실험은 간단하다.

1. 기존 VLM/grounding model 하나를 고른다.
2. 동일 image-query에 resize/tiling/token-budget configuration을 6~10개 만든다.
3. target size별 answer/grounding flip rate를 측정한다.
4. 틀린 configuration에서도 oracle proposal 또는 evidence readout으로 정답 target이 recoverable한지 본다.
5. recoverable case가 충분하면 evidence consistency adapter로 진행한다.

이 실험에서 tiny/small object가 medium/large보다 configuration flip이 높고, 틀렸을 때도 evidence가 남아 있다면 “P2를 더 붙이자”보다 훨씬 강한 연구 질문이 된다.

이번 주 핵심 질문:

**Tiny objects are not always invisible. Sometimes the model sees them, but a configuration change makes it stop using what it saw.**
