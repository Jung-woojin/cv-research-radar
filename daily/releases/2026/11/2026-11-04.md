## 1. ROCm 7.2.4 wheel — package version은 ABI tuple의 일부

- **출처:** [LMCache releases](https://github.com/LMCache/LMCache/releases), [LMCache repository](https://github.com/LMCache/LMCache).
- **사실:** 공식 `v0.5.7rc4-rocm-torch210` release는 11월 3일 공개됐습니다. `v0.5.7rc4` commit `236f3ee` 기반이며, `rocm/pytorch:rocm7.2.4_ubuntu24.04_py3.12_pytorch_release_2.10.0` digest `sha256:4449f856653602317e4101a76fce599c7fcd58ccec2e539951fce5f73083179e`에서 build/test됐다고 밝힙니다.
- **artifact 범위:** wheel은 Torch `2.10.0+rocm7.2.4.git3d3aa833`, HIP `7.2.53211`, CPython 3.12 manylinux 2.39 x86_64, C++11 ABI, gfx942/gfx950 code object를 명시합니다. repository license는 Apache-2.0입니다. pretrained weights, dataset, evaluator script, required VRAM은 이 release에 포함·명시되지 않았습니다.
- **저자/릴리스 주장:** 고정 AMD PyTorch image에서 build/test했고 대응 release integration을 포함한다고 설명합니다.
- **해석:** 정확한 ABI가 공개된 것은 설치·재현의 전제이지 MI300/MI350의 cache-hit latency, throughput 또는 VRAM 절감 증거가 아닙니다. 다른 container/Torch patch/GPU를 통한 비교는 **not strictly apples-to-apples**입니다.
- **10–30분 smoke test:** 해당 image digest에서 `--no-deps` 설치 후 `import lmcache`, Torch/HIP version, GPU arch를 manifest로 기록하고, 작은 public prompt의 cache miss→hit 두 요청이 정상 종료하는지 확인합니다. model weight download나 full serving benchmark는 이 smoke 범위를 벗어납니다.
- **GO/KILL:** package filename·image digest·ABI·GPU arch가 모두 일치하면 GO입니다. install 성공을 다른 AMD GPU의 performance claim이나 model weight provenance로 바꾸는 것은 KILL입니다.

## 2. Rebellions RBLN wheel — host-owned compiler와 driver를 artifact 밖에 둔 release

- **출처:** [LMCache releases](https://github.com/LMCache/LMCache/releases), [LMCache repository](https://github.com/LMCache/LMCache).
- **사실:** official `v0.5.7rc4-rbln` wheel은 11월 3일 공개됐고 같은 signed `236f3ee` release commit을 가리킵니다. release는 `torch-rbln` 0.12.0과 `torch` 2.13.0+cpu 기반임을 밝힙니다.
- **artifact 범위:** `torch-rbln`, `rebel-compiler`, RBLN driver는 wheel에 bundle되지 않고 host environment가 제공해야 합니다. release는 이미 해당 runtime을 가진 environment에서 `pip install lmcache==0.5.7rc4+rbln`하는 표면만 제공합니다. package license는 repository의 Apache-2.0이며, model weights/data/evaluator, compatible NPU 목록, expected VRAM은 release note에 없습니다.
- **저자/릴리스 주장:** host에 torch-rbln과 compiler가 존재하는 환경을 installation precondition으로 제시합니다.
- **해석:** 이 wheel은 accelerator backend artifact이지 standalone NPU runtime bundle이 아닙니다. host compiler/driver가 맞지 않을 때 생기는 compile/load failure를 LMCache code release의 regression으로 단정해서는 안 됩니다.
- **10–30분 smoke test:** host에서 `torch-rbln`, compiler, driver version을 먼저 기록하고 wheel을 설치합니다. import, device discovery, 최소 cache connector initialization까지 확인하며 checkpoint/model weights와 full evaluation은 별도 provenance로 남깁니다.
- **GO/KILL:** host runtime tuple과 wheel version이 기록되고 initialization이 통과하면 GO입니다. host compiler/driver 없이 pip install만 해놓고 RBLN serving이 지원된다고 표기하는 것은 KILL입니다.

## 3. CUDA 12.9 wheels — multi-architecture package가 edge readiness를 뜻하지 않음

- **출처:** [LMCache releases](https://github.com/LMCache/LMCache/releases), [LMCache Docker README](https://github.com/LMCache/LMCache/blob/dev/docker/README.md).
- **사실:** official `v0.5.7rc4-cu129` release는 11월 3일 공개됐으며 linux/amd64와 linux/arm64용 CUDA 12.9 wheel을 제공합니다. 같은 core release commit은 `236f3ee`입니다.
- **artifact 범위:** release의 install path는 CUDA 12.9 PyTorch index와 release asset index를 사용합니다. Docker documentation은 CUDA 12.9 release image variant도 amd64/arm64를 지원한다고 설명합니다. LMCache core license는 Apache-2.0입니다. 이 release에는 vision/LLM pretrained weights, dataset artifact, benchmark score, device별 VRAM floor 또는 Jetson/L4T support claim은 없습니다.
- **해석:** `linux/arm64`는 CPU/OS architecture artifact 표면입니다. 그것만으로 특정 ARM edge board, driver stack, GPU architecture, model size, power envelope에서의 runability나 latency를 보장하지 않습니다.
- **10–30분 smoke test:** target machine에서 `uname -m`, NVIDIA driver, CUDA runtime, Torch CUDA build를 manifest로 남긴 뒤 package import와 one-request cache miss/hit control을 실행합니다. accelerator allocation, model load peak memory, p95 TTFT는 따로 측정합니다.
- **GO/KILL:** package architecture와 actual OS/runtime이 일치하고 smoke control이 통과하면 GO입니다. amd64/arm64 wheel availability를 edge board support, model weight availability 또는 throughput claim으로 바꾸는 것은 KILL입니다.

3. smoke import/initialization과 full serving quality·latency evaluation을 분리하며, accelerator별 ABI가 다르면 **not strictly apples-to-apples**로 표시합니다.
