## 1. ParseBench-2 — 데이터 수정과 evaluator 변경을 분리해야 한다

**확인한 사실:** 공식 공지는 11/12이며 dataset card의 initial release 날짜는 11/11이다. 기존 페이지의 참조 주석을 수정하고 chart의 전체 데이터 참조를 제공하며 forms를 추가했다. [출시 공지](https://www.llamaindex.ai/blog/introducing-parsebench-v2)

**규모·task·split·artifact:** card는 2,645개 원문 문서에서 4,317개 page-level case, 13개 subset을 명시한다. subset은 viewer의 split 이름이며 train/validation/test 분할을 뜻하지 않는다. PDF/JPG, answer-key JSON, 일부 reference Markdown과 JSONL index가 공개돼 있다. text와 formatting은 같은 508개 페이지를 공유한다. [Dataset card](https://huggingface.co/datasets/llamaindex/ParseBench-2)

**License·bias·호환성:** card의 배포 license는 Apache-2.0이다. 어려운 표·양식 등을 의도적으로 보강한 평가 모음이므로 실제 운영 문서의 발생 비율과 같다고 가정하지 않는다. README는 여섯 dimension의 평균 및 dimension 내부 고정 가중치를 설명하고 v1과 점수가 비교 불가능하다고 명시한다. **not strictly apples-to-apples**다. [공식 코드·평가 설명](https://github.com/run-llama/ParseBench)

**진단 → 가설:** 점수 변화에는 parser 변화, 참조 정답 수정, metric 변경, 표본 구성 변화가 섞일 수 있다. 동일 출력도 새 severity policy에서 다른 점수를 받을 수 있다는 해석이며, 모델 개선을 입증한 결과가 아니다.

**최소 audit:** 공통 페이지 ID와 문서 hash를 먼저 매칭한다. 저장된 동일 parser 출력에 대해 가능한 범위에서 구/신 참조와 구/신 scorer를 교차 적용하고, 새 forms는 별도 보고한다. 문서·template family별 중복과 dimension별 오류도 기록한다.

**GO/KILL:** version·공통 페이지·scorer를 고정한 migration audit는 GO. v1 대비 전체 점수 상승을 parser 개선으로 발표하는 것은 KILL. 이 audit는 제안이며 실행하지 않았다.

## 2. RICapBench — 원본 test의 학습 편입과 license 상속

**저자 보고:** 800×800 이미지 26,854장, instance annotation 245,466개, spatial relation tuple 498,005개다. DIOR-R·CODrone·FAIR1M v2.0의 OBB를 유지하고 모델 보조 생성과 수동 검증으로 caption을 구축했다. task는 위치·속성·관계의 통합 예측이다. [논문 본문](https://arxiv.org/html/2611.16413v1)

**직접 확인한 공개 정책:** `train.jsonl`, `val.jsonl`, `evaluation.jsonl`, 관계 정답 JSONL, `images.7z`가 명시돼 있다. DIOR-R의 원래 train+test는 새 train의 source pool이고, 원래 val은 새 val/evaluation의 pool이다. 다른 두 source도 원래 val을 평가 pool로 사용한다. card는 새 val/evaluation이 서로 겹치지 않고 새 train에서 제외된다고 설명한다. 이는 배포자 정책이며 파일 전수 검사 결과는 아니다. [Dataset card](https://huggingface.co/datasets/yubinux/RICapBench)

**License·접근:** 같은 card는 기본 CC BY 4.0과 별개로 원본 이미지·상속 주석의 조건을 유지한다고 명시한다. DIOR-R은 CC BY-NC 4.0, CODrone은 CC BY-NC-SA 4.0, FAIR1M은 CC BY-NC-SA 3.0 및 academic use only로 안내된다. GitHub의 MIT는 코드 저장소에 대한 표시다. [Dataset card](https://huggingface.co/datasets/yubinux/RICapBench), [공식 코드](https://github.com/Xldln/RICapBench)

**관찰·추론:** HF viewer에 column-name mismatch의 CastError가 표시된다. 이는 viewer 변환 실패이며 원본 JSONL 전체의 손상을 입증하지 않는다. 기존 source dataset으로 학습한 모델은 평가 이미지 노출 이력이 다를 수 있다. 작은 객체·source·category 편중과 caption 생성 스타일도 별도 audit 대상이며, 확인된 leakage나 실측 class imbalance로 단정하지 않는다.

**최소 audit:** native JSONL을 split별로 읽어 `source dataset + original image ID`와 image hash의 교집합을 검사한다. 기존 pretraining/fine-tuning manifest와도 대조한다. source/category/object-size별 빈도와 DetA·CapA·RelCap-F1을 분리하고, GT box를 제공하는 probe로 localization 병목과 caption/parser 병목을 구분한다.

**GO/KILL:** provenance 감사와 native schema 점검은 GO. source 학습 이력이 불명확한 모델 간 점수는 **not strictly apples-to-apples**로 취급한다. CC BY 표시만으로 이미지의 상업 사용을 허용한다고 해석하거나 viewer 오류를 label corruption으로 발표하는 것은 KILL.

## 3. Fog-FWL — 평가용 실측 데이터와 참조 기반 label policy

**시점·상태:** v1은 11/12 21:56:55 KST다. 본문은 acceptance 이후 dataset 공개를 예고한다. 논문은 공개됐지만 배포 데이터·simulator·data-specific license를 이번 실행에서 확인하지 못했다. 논문 자체의 license를 데이터 사용권으로 전용하지 않는다. [v1 이력](https://arxiv.org/abs/2611.16742v1), [본문](https://arxiv.org/html/2611.16742v1)

**저자 보고:** Real은 8개 scene·58개 sequence·7,527 frame과 10,719개 3D box의 evaluation-only 모음이며 Sim은 12,000 frame의 학습 모음이다. 야외 주차장에서 인공 안개와 차량 배치를 사용했다. 일반 도로·자연 안개·다양한 센서 분포의 대표성은 별도 검증이 필요하다. [Dataset 설계](https://arxiv.org/html/2611.16742v1)

**Label·split·호환성:** Object/Fog/Noise는 histogram 수준 label이다. Object는 차량뿐 아니라 지면·건물 등 표면을 포함한다. 맑은 날 같은 장면의 참조 waveform으로 Object 위치를 정하며, 난이도는 sequence 단위다. 공개 파일 수준 split manifest는 미확인이다. point-cloud-only benchmark와는 입력 정보가 달라 **not strictly apples-to-apples**다. [Annotation protocol](https://arxiv.org/html/2611.16742v1)

**진단 → 가설:** 성능 이득이 waveform의 추가 정보에서 오는지, 참조 기반 label과 센서·장면 고정 조건에 민감한지 분리해야 한다. 이는 label 오류가 확인됐다는 뜻이 아니다.

**최소 audit:** 공개 후 scene/sequence group과 clear-reference lineage를 고정한다. 실측 평가 데이터가 학습·threshold tuning에 들어가지 않게 하고, 같은 waveform에서 생성한 top-k peak 입력과 full-waveform 입력을 비교한다. 난이도별 object-ray recall, histogram class 빈도, 3D detection을 함께 본다.

**GO/KILL:** schema·group audit 설계는 GO. 다운로드·license 확인 전 학습 착수와 데이터 공개 완료 주장은 KILL. 현재 재현 실행은 보류한다.
