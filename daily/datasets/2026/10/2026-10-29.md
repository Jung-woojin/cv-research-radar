## 1) MoI-Bench — mobile image generation/editing의 failure-cell annotation

- **확인된 사실**: 64 subtasks와 1,150 samples, 16 operations(예: removal/replacement), 8 visual target categories로 구성된다. MoI-Eval은 instruction following, visual quality, detail preservation을 task별로 나누고, sample-level 질문을 축별 profile로 집계한다.
- **task / split**: on-device image generation·editing 평가. train/validation/test split과 sampling policy는 abstract에서 확인되지 않았다.
- **license / artifact**: arXiv 원문은 project page를 연결하지만, 이 실행에서 benchmark download, annotation file, license, evaluator code를 공식적으로 확인하지 못했다.
- **저자 주장**: single-score ranking보다 Operation×Target 분해가 compact model 개선의 capability gap을 더 세밀히 드러낸다.
- **bias / 호환성**: mobile user needs에 맞춘 taxonomy 자체가 다른 general image-edit benchmark와 동일 분포라는 뜻은 아니다. server/on-device 비교도 model, latency budget, device 조건이 다르면 not strictly apples-to-apples다.
- **진단 → 가설 → 최소 audit**: text replacement와 identity preservation에 오류가 몰릴 것이라는 가설을 세운다. 1,150 sample에서 operation·target·device별 error matrix, 동일 prompt의 image duplicate/near-duplicate hash, annotator agreement를 먼저 확인한다.
- **GO/KILL**: error concentration이 random하게 퍼지지 않고 특정 cell의 confidence interval 밖 상승으로 반복되면 cell-aware sampler를 GO; device/model 조건이 기록되지 않으면 leaderboard 비교는 KILL이다.

## 2) ScIntBench — static plausibility와 interaction-time label의 분리

- **확인된 사실**: prescribed manipulation(밀기, 열기, surface probing)을 physics simulation에서 실행하며 task success/capability/progress, post-interaction integrity, dynamic plausibility를 측정한다. 12개 scene-generation system과 10 room type을 평가한다.
- **정량 관찰**: 원문은 near-perfect static plausibility system이 interaction의 11.54%만 완료했고, 12개 중 7개가 어떤 interaction도 지원하지 못했으며, best system도 36.92%였다고 보고한다.
- **task / split**: indoor scene generation의 interaction readiness. room-type, action, held-out split, simulator version은 abstract만으로 확인되지 않았다.
- **license / artifact**: data, action script, simulator assets, evaluator license/release 여부를 이번 확인 범위에서 검증하지 못했다.
- **bias / 호환성**: simulation action success는 real robot contact/noise를 대변하지 않는다. static metric과 action metric은 서로 대체 가능하지 않다.
- **진단 → 가설 → 최소 audit**: semantic/static score가 high인데 action success가 low인 failure cell은 articulation/collision label 누락에서 생길 수 있다. 50 scene에서 asset category·contact point·joint state별 action failure를 수작업 audit한다.
- **GO/KILL**: action script와 seed가 고정된 paired re-simulation에서도 failure가 유지되면 interaction annotation 확장을 GO; simulator version이 불명확하면 수치 순위 비교는 KILL이다.

## 3) GameVerse — long-horizon 데이터의 핵심은 event boundary와 camera consistency

- **확인된 사실**: 69.7K clips, 1,655 hours, 349.6M frames를 보고하며, 1,358 hours의 continuous two-minute sequences를 포함한다. scene-consistent segmentation, quality filtering, camera pose estimation, event-based captions을 사용하고 caption은 static context와 dynamic event를 분리해 event boundary에 맞춘다고 설명한다.
- **task / split**: first-/third-person gameplay로 long-horizon interactive world modeling. game title, train/validation/test separation, identity overlap 방지 방식은 abstract에서 확인되지 않았다.
- **license / artifact**: download manifest, gameplay redistribution license, pose/caption format, public checkpoint는 이번 확인 범위에서 검증하지 못했다.
- **저자 주장**: 기존 공개 dataset보다 scale·diversity·annotation quality가 높고 training이 temporal horizon을 늘린다.
- **bias / 호환성**: gameplay physics·UI·camera style은 natural video/robotics와 다르다. “two minute” sequence가 title-level leakage 없이 split됐는지 확인 전에는 cross-game generalization을 주장할 수 없다.
- **진단 → 가설 → 최소 audit**: fixed-window caption보다 event-boundary caption이 long rollout drift를 줄인다는 가설이다. title/scene/camera trajectory group split을 적용한 뒤 30s·60s·120s rollout의 state-consistency와 event retrieval을 비교한다.
- **GO/KILL**: group split에서도 event-boundary annotation 이득이 유지되면 GO; random clip split에서만 이득이면 overlap/leakage 의심으로 KILL이다.

## 4) ImagiRep — representation을 annotation-controlled variable로 다루기

- **확인된 사실**: 922 questions, 7 question types, Viewpoint Imagination/Cross-view Integration 두 setting; 같은 unobserved state에 oracle RGB와 여섯 대안 표현(depth, panorama, top-down 등)을 제공한다.
- **task / split**: unseen state spatial reasoning. question-type 및 state-level split 세부는 abstract에서 확인되지 않았다.
- **license / artifact**: 공식 프로젝트 링크와 benchmark 언급은 확인했지만 dataset download, simulator license, annotation schema, GEARS source는 이번 실행에서 검증하지 못했다.
- **저자 주장**: accurate imagined RGB도 정확한 spatial reasoning을 보장하지 않으며 adaptive selection인 GEARS가 기존 spatial imagination method를 능가한다.
- **bias / 호환성**: oracle/estimated state가 있는 simulator setup은 real sensor noise와 다르다. 대안 표현 간 information budget 역시 같지 않을 수 있다.
- **진단 → 가설 → 최소 audit**: representation choice가 model capability보다 question-template prior를 반영할 수 있다. 922 question의 state ID·template·answer label에 대해 representation permutation과 state-group split을 수행한다.
- **GO/KILL**: 같은 state/질문에서 representation flip이 spatial error를 예측하면 selector 연구를 GO; template만으로 selection이 설명되면 geometry claim은 KILL이다.

## 5) CodeCap-Bench — temporal annotation은 syntax-validity와 다르다

- **확인된 사실**: 323 videos, structured 2D의 5 categories, fine-grained annotations와 multi-level evaluation framework를 포함한다. code caption은 graphical primitive, layout rule, time function으로 visual content를 표현한다.
- **task / split**: code-vs-natural-language caption의 QA/reconstruction. category split, event boundary protocol, parser/evaluator source는 abstract에서 확인되지 않았다.
- **license / artifact**: paper의 arXiv license와 별개로 benchmark data/code release, annotation license, parser implementation은 이번 확인 범위에서 검증하지 못했다.
- **저자 주장**: code caption이 reasoning accuracy와 reconstruction fidelity에서 우수하나, leading proprietary MLLM도 complex temporal dynamics를 충실히 포착하기 어렵고 open-source가 더 뒤처진다.
- **bias / 호환성**: structured 2D 범주의 evaluator가 code format에 유리할 수 있다. syntax-valid code는 temporal faithfulness가 아니다.
- **진단 → 가설 → 최소 audit**: code caption의 이득이 time function 자체에서 온다는 가설이다. 60 video에서 original code, time-shuffled code, same-length pseudo-code, natural language를 paired QA로 비교한다.
- **GO/KILL**: temporal QA의 gain이 original code에서만 유지되면 GO; shuffle에서도 유지되면 format/evaluator bias로 KILL이다.

## 오늘의 종합 진단

### Observation

새 benchmark들은 평균 score보다 annotation 축, action, camera trajectory, representation, temporal function을 명시적으로 평가 대상으로 삼는다.

### Diagnosis

모두 dataset 규모를 제시하지만, 공개 artifact가 확인되지 않으면 split, license, duplicate, leakage, evaluator implementation을 독립적으로 감사할 수 없다.

### Mechanism 가설

“세분화된 annotation”의 이득은 model generalization보다 hidden overlap, template prior, simulator convention, evaluator-format alignment에서 생길 수도 있다.

### 최소 공통 실험

1. metadata 기반 group split: scene/title/state/video identity를 기준으로 재분할한다.
2. near-duplicate/trajectory duplicate: perceptual hash 또는 pose/camera similarity로 train–test 간 후보를 찾는다.
3. annotation intervention: event boundary/time function/representation을 하나만 shuffle해 score 변화의 원인을 분리한다.
4. release gate: manifest, license, checksum, evaluator commit, split recipe가 없으면 comparative leaderboard로 사용하지 않는다.

## 오늘의 GO / KILL

- **GO**: GameVerse의 title/scene-group split과 CodeCap-Bench의 time-shuffle audit을 먼저 설계한다. 둘 다 long-horizon/temporal claim을 가장 작은 비용으로 반증할 수 있다.
- **GO**: MoI-Bench는 operation×target cell을 별도 sampling/coverage unit으로 기록하는 mobile vision evaluation 설계에 참고한다.
- **KILL**: artifact·license·split이 공개 확인되기 전 이 다섯 benchmark를 재현 가능 dataset 또는 apples-to-apples leaderboard로 인용하지 않는다.
- **KILL**: ScIntBench의 simulator interaction success를 real-world robotics reliability로 직접 일반화하지 않는다.
