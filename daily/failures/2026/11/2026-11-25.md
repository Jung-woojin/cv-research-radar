## 1. SavedModel INT8: export 성공과 실제 산출물 정밀도가 다름

**확인 사실:** #27349는 SavedModel의 quantization 등록과 calibration 인자를 제거해 INT8 요청을 export 전에 거부한다. 11월 25일 02:41 KST 병합됐다. INT8 TFLite는 별도 LiteRT 경로를 사용한다. [공식 PR](https://github.com/ultralytics/ultralytics/pull/27349) · [실제 diff](https://github.com/ultralytics/ultralytics/pull/27349/files) · [maintainer 재현](https://github.com/ultralytics/ultralytics/pull/27349#issuecomment-7139555586)

- **실패 조건·모델·dataset·configuration:** Linux x86-64 CPU, YOLO26n detect/OBB, export(format="saved_model", quantize=8) 또는 int8=True. bus.jpg 추론과 coco8/dota8 검증이 사용됐다. 전체 dependency·dataset revision·seed·calibration subset은 확인되지 않았다.
- **공식 인정·재현 근거:** glenn-jocher는 main에서 export가 성공하나 integer_quant와 full_integer_quant TFLite가 box의 pixel 좌표와 class score에 하나의 INT8 output scale을 공유한다고 재현했다. Detect scale은 2.687, OBB는 4.008로 보고했고 score가 모두 0으로 복원돼 bus.jpg에서 box가 없었다고 한다. 이번 watch의 실측이 아니다.
- **작성자 주장과 community 수준:** 작성자도 여러 task 결과와 benchmark가 FP32 SavedModel로 성공 행을 만들었다고 보고했다. 별도 maintainer 실행은 detect/OBB 실패와 FP32 보존을 뒷받침한다. classify·semantic·depth 전체 결과나 Edge TPU compile까지 독립 재현된 것으로 확대하지 않는다.
- **진단 → 메커니즘:** pixel 단위 box와 작은 score가 같은 정수 양자화 범위를 공유한다. Maintainer는 head normalization이 Edge TPU에만 적용되는 경로 차이를 원인으로 설명했다. SavedModel 자체는 FP32여서 benchmark 성공이 INT8 파일의 유효성을 증명하지 못했다.
- **가설 → 최소 개입:** 지원하지 않는 INT8 요청을 조기에 거부하고, artifact별 dtype·scale·실제 평가 대상을 검증하면 잘못된 성공 판정을 막을 수 있다.
- **최소 실험:** base 82f0bd146dc174306761be60521f2ccc378f3563과 merge a0b816afb56c5df78df5a33a982a227f7ee00c05를 고정한다. 동일 weight·입력·보정 subset으로 기존 SavedModel INT8, FP32, LiteRT INT8을 생성하고 파일별 tensor dtype/scale, score 최대값, 검출 수, 실제 benchmark가 읽는 경로를 기록한다. 수정판의 SavedModel INT8은 예외가 기대 결과다.
- **GO/KILL:** 기존 INT8 score 소실이 재현되고 새 요청이 조기에 실패하며 FP32 결과가 유지되면 GO. LiteRT 정상 동작까지 이 수정의 정확도 이득으로 해석하는 주장은 KILL한다. 원문도 LiteRT calibration 결과가 실행 간 달랐다고 명시한다.
- **기존 주장과 충돌·한계:** “INT8 인자를 넣은 export와 benchmark가 성공하면 INT8 추론이 검증됐다”는 운영 가정의 반례다. 경로·calibration·runtime이 다른 FP32/LiteRT 수치 비교는 not strictly apples-to-apples다. 모든 TensorFlow INT8이 실패한다는 결론은 아니다.
- **점수:** 심각도 **4/5** · 재현 신뢰도 **4/5** · 연구 아이디어 가치 **4/5**.

## 오늘의 실패 패턴 3개

1. **성공 신호와 artifact 계약의 불일치:** export 성공·파일 존재·benchmark 성공은 실제 정밀도와 score 유효성을 보장하지 않는다.
2. **계산과 반환의 단절:** evaluator가 계산한 AP가 API에서 빠지면 자동 연구 분석이 실제 결과를 놓친다.
3. **dependency와 입력 문법의 상호작용:** template 수정은 정상 경로를 고쳐도 다른 유효 placeholder를 깨뜨릴 수 있다.

## 논문 아이디어로 연결 가능한 빈틈

**조사자의 추론:** video reasoning 실패를 모델 표현과 processor 입력 계약으로 나눠 진단할 수 있다. 우선 여러 Qwen3-VL 계열에서 template·dependency 변화에 대한 token 구조 불변성을 검사하고, 같은 frame budget에서 답변 정확도·시간 순서 정합성을 측정한다. CPU에서 오류를 찾을 수 있다는 장점이 있지만 알려진 marker 버그 하나의 수정만으로 novelty를 주장하기 어렵다.

후속 가설은 “답변 품질 변화 중 입력 계약 복구만으로 설명되는 부분이 있는가?”다. 결과가 음성이어도 token 구조 변화가 항상 품질 저하로 이어지지 않는 범위를 정할 수 있다. AP 사례는 별도 연구보다 재현 프로토콜의 관측성 점검으로 우선 사용한다.
