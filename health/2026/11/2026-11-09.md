## 판단과 최소 개입

- **원인 가설:** health script가 stale local Git history/file tree로 당일 원격 아카이브 존재를 판정한다.
- **최소 검증:** 다음 health run에서 local clone의 `HEAD`와 `origin/main`을 read-only로 비교하고, 같은 5개 path를 file API로 표본 재확인한다.
- **GO/KILL:** 원격 SHA가 ledger SHA와 계속 일치하면 missing/backfill을 만들지 않는다. 실제 file API 404 또는 SHA/commit 불일치가 재현될 때만 해당 날짜를 recovery queue의 복구 후보로 승격한다.
- **사용자 조치:** 현재 필요 없음. scheduler를 재활성화하거나 GitHub Issue를 만들지 않았다.
