## 신규 장애 진단과 복구

**확인 사실:** AI Tool Radar의 오늘 파일은 연결된 GitHub 앱 조회에서 404였다. 원래 ledger는 `AUTHOR_EMAIL_UNSUPPORTED`, `create_file_preflight`, `mutation_attempted=false`를 기록했다. 즉 API 요청 실패가 아니라 email 인자 부재 때문에 저장을 시도하지 않은 상태였다.

**가설:** 예약 비활성화가 아니라 기존 도구 제한을 저장 전 중단 조건으로 해석한 것이 이번 누락의 원인이다. 보존된 원문의 SHA256은 원래 ledger와 일치했고 `chat_delivered=true`였다.

**최소 실험·복구:** 이미 전달된 원문과 출처 URL을 그대로 연결된 `create_file`에 전달했다. 새 조사로 과거 내용을 채우지 않았다. 공식 release 원문도 재확인했다. 저장 후 원격 본문이 원문과 정확히 같고, 위 blob SHA와 commit의 파일 항목이 일치하며 Tool 저장소 `main`이 해당 commit을 가리키는지 확인했다. 저장은 복구됐지만 요청 email 충족은 복구되지 않았다.

Release Watch의 어제 원본 ledger는 `daily-paper-code-release-watch`에 있었다. 원격 `main`과 원래 commit `b7ef57cca8e8a001750c6954afa941817f4752ad`에서 blob `fc30796655041fcfd12481ddc2c7b45d78958a0c`가 같음을 확인한 뒤 `daily-paper-code-weight-release-watch`에 사본을 저장했다. 원본은 보존했다. 다음 실행은 설정의 정식 ID에 직접 기록해야 한다.
