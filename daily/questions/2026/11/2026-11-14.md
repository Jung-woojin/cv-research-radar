## Q1. 동일 이미지의 전처리 차이를 제거하면 VLM backend 간 답변 불일치가 줄어드는가?

**Observation·왜 지금:** Dynamo #18676 보고자는 요청의 `media_io_kwargs.image`가 무시돼 투명 PNG의 RGB가 direct vLLM과 달라진다고 제보했다. 이는 CPU pixel 재현 주장이지 VLM 정확도 측정이 아니다. 고정 코드의 옵션 helper가 `video`를 읽는 것은 확인했다. [제보·재현 코드](https://github.com/ai-dynamo/dynamo/issues/18676) · [Dynamo 고정 코드](https://github.com/ai-dynamo/dynamo/blob/164358ac556d65e4e44b16128093908c23d53d2e/components/src/dynamo/vllm/multimodal_utils/request_processor.py#L125-L146)

**문제·Gap:** 같은 checkpoint와 image URL만으로 실제 입력이 같다고 가정하면 전처리 drift를 hallucination 또는 reasoning failure로 오인할 수 있다. 원문은 downstream 답변 차이를 입증하지 않았다.

**Diagnosis → Mechanism → Hypothesis:** 요청 옵션 전달과 cache identity가 실제 RGB를 결정할 수 있다. 추론상 pixel parity를 강제하면 투명도에 민감한 사례의 backend 답변 차이가 줄고 opaque 대조군은 유지될 것이다. Cache에 의한 순서 효과는 아직 검증되지 않은 별도 가설이다.

**최소 개입·MVP:** 먼저 완전/부분 투명 PNG와 opaque RGB fixture에 배경색 요청을 바꾸며 direct vLLM/Dynamo의 decoded RGB hash를 비교한다. Cold/warm cache와 요청 순서를 교차한다. 다음 단계에서 동일하게 RGB로 사전 합성한 입력을 양쪽에 제공해 답변 불일치가 남는지 본다. 옵션 전달 수정과 cache-key 수정은 따로 ablation한다.

**Baseline·dataset:** 보고자가 지정한 vLLM 0.33.0·Dynamo commit과 `Qwen/Qwen3-VL-2B-Instruct`를 출발점으로 삼되 실행 가능성은 확인해야 한다. 자체 생성한 색·도형 질의 fixture를 사용하며 자연영상·해상 안전 VQA로의 일반화는 별도 검증한다. Fixture의 배경색 변경은 정답도 바꿀 수 있으므로 각 변형의 정답을 따로 정의한다.

**Metric·GO/KILL:** RGB hash mismatch, 요청 순서 의존율, 정답률, paired answer disagreement를 기록한다. Pixel parity 후 불일치가 줄면 전처리 기전은 GO; pixel이 같은데 차이가 유지되면 전처리만으로 설명하는 가설은 KILL하고 decoding/runtime을 점검한다. Pixel mismatch만으로 hallucination 원인을 확정하지 않는다.

**기여·위험·기간:** 입력 동등성과 답변 동등성을 연결하는 진단 protocol이 기대 기여다. 단일 서비스 버그 재현에 그치면 novelty가 낮다. 4~8주 내 단기 분석 논문 가능성은 중간이며 여러 backend·입력 유형에서 반복돼야 한다. Negative result도 전처리 설명의 범위를 제한한다.

**Compute:** 난이도 2/5. 첫 pixel 검사는 CPU, 모델 단계는 작은 checkpoint의 단일 이미지부터 시작한다. **점수:** novelty 3/5 · feasibility 5/5 · compute efficiency 5/5 · publication potential 3/5.

## Q2. YOLOE의 shape-only 수정은 tracking을 정상 실행시키면서도 객체 identity를 왜곡하는가?

**Observation·왜 지금:** PR #27171은 YOLOE class embedding을 native ReID 입력에서 분리하고 prompt-free head는 별도 encoder로 보내도록 병합됐다. 작성자는 embedding만 제거하면 실행되지만 detection index와 feature anchor 대응이 틀어진다고 보고했다. PR diff에서 `module.nl`까지의 map 추출과 `lrpc` 경로 분기를 확인했다. [공식 PR](https://github.com/ultralytics/ultralytics/pull/27171) · [diff](https://github.com/ultralytics/ultralytics/pull/27171/files)

**문제·Gap:** 예외가 사라진 것과 의미적으로 올바른 ReID는 다르다. 원문은 단일 이미지의 대응 검사를 제공하지만 장기 tracking metric에 대한 영향은 확정하지 않는다.

**Diagnosis → Mechanism → Hypothesis:** 필터링된 detection index를 원래 feature pyramid index로 쓰면 다른 위치의 특징을 가져올 수 있다. Shape-only 수정은 실행 완료율을 높여도 교차·가림 구간의 ID switch를 남길 것이라는 가설이다.

**최소 개입·MVP:** Parent, shape-only, 병합 수정 세 조건을 비교한다. 먼저 한 frame에서 feature row가 자신의 box 내부 anchor에 대응하는지 검사한다. 이후 고정한 짧은 MOT17 validation clip에서 동일 raw detection·tracker parameter로 ReID 경로만 바꾼다. ReID-off 대조군도 둔다.

**Baseline·dataset:** 작은 YOLOE checkpoint + BoT-SORT, MOT17 validation의 객체 교차 구간. Prompt-free와 text-prompt 조건을 분리하며 VisDrone 전이는 후속 단계다.

**Metric·GO/KILL:** crash, box–feature 대응률, ID switches, IDF1/HOTA, encoder latency를 기록한다. Shape-only에서 대응 오류와 identity 저하가 함께 나타나고 올바른 대응에서 회복되면 GO. 대응 오류가 있어도 tracking이 안정적이면 해당 조건의 downstream 영향 가설은 KILL한다. 별도 encoder는 표현 자체도 바뀌므로 성능 회복 전부를 index 수정의 인과효과로 해석하지 않는다.

**기여·위험·기간:** Shape 검사를 넘는 region-feature contract와 tracking 진단이 기대 기여다. 특정 head 버그에 국한될 위험이 크다. 4~8주 가능성은 중간이며 다른 head에서 유사 대응 위반을 확보해야 한다. Negative result는 tracker가 해당 feature 오류에 얼마나 둔감한지 알려준다.

**Compute:** 난이도 2/5. 단일 이미지·짧은 clip부터 시작하며 8GB 적합성은 실측 전 미확인이다. **점수:** novelty 3/5 · feasibility 4/5 · compute efficiency 4/5 · publication potential 3/5.

## Q3. Annotation 변환의 파일명 충돌이 작은 객체의 누락 편향으로 전파되는가?

**Observation·왜 지금:** PR #27174는 같은 stem의 mask가 같은 label 파일을 덮어쓰는 문제를 사전 검사로 막는다. 작성자는 전경 label이 background-only mask 때문에 빈 파일이 되는 재현을 보고했다. Diff에서 `stem.casefold()` 충돌 검사와 쓰기 전 예외를 확인했다. [공식 PR](https://github.com/ultralytics/ultralytics/pull/27174) · [diff](https://github.com/ultralytics/ultralytics/pull/27174/files)

**문제·Gap:** 조용한 label 손실이 모델의 small-object failure처럼 보일 수 있는지 묻는다. 실제 공개 dataset에서 충돌이 빈번하거나 작은 객체에 편향된다는 증거는 아직 없다.

**Diagnosis → Mechanism → Hypothesis:** 입력 identity를 stem으로 축약하면 서로 다른 mask가 같은 출력 key를 공유한다. 충돌이 특정 수집 장비·클래스·크기에 집중된 경우에만 annotation 누락도 편향될 것이라는 조건부 가설이다.

**최소 개입·MVP:** 임시 디렉터리의 전경/배경 mask로 exact-stem·case-only 충돌과 고유 stem 대조군을 만든다. Parent/수정 버전의 label hash와 instance 보존율을 비교한다. 이어 COCO instance mask의 고정 소표본을 파생 변환해 무작위 충돌과 작은 객체 집중 충돌을 인위적으로 주입한다. 인위적 오류율을 실제 발생률로 해석하지 않는다.

**Baseline·dataset:** 공식 변환기 전후 버전, 원래 instance ID manifest, COCO validation 파생 mask. 원본은 보존하고 파생본만 사용한다. 학습은 첫 MVP에 필요 없다.

**Metric·GO/KILL:** 쓰기 전 차단 여부, label/instance 보존율, 객체 크기·클래스별 누락률. GO는 충돌 차단과 고유 stem 결과의 동일성이다. 작은 객체 편향 주장은 비무작위 충돌 조건에서만 검토한다. 실제 자료에서 충돌이 없으면 해당 dataset의 모델 실패 설명으로는 KILL한다.

**기여·위험·기간:** Annotation provenance와 오류 주입에 대한 민감도 곡선이 기대 기여다. Synthetic corruption만으로는 일반성이 약하다. 4~8주 독립 논문화 가능성은 낮음~중간이며 실제 변환 pipeline 감사와 결합해야 한다. Negative result는 이 실패 경로를 배제하는 근거가 된다.

**Compute:** 난이도 1/5, CPU 중심. 후속 학습을 한다면 정상/오류 label만 바꾸고 동일 detector·seed를 고정한다. **점수:** novelty 3/5 · feasibility 5/5 · compute efficiency 5/5 · publication potential 2/5.

## Q4. 공간 중첩 제거 뒤의 위치추정 변화는 누수 제거 효과인가, 장면 구성 변화인가?

**Observation·왜 지금:** 11월 12일 공개된 GOOSELoc 논문 Appendix J는 full/buffered test를 구분한다. Buffered subset에서 위치·방향 오차가 동일 방향으로 움직이지 않는다. 이는 저자 평가 결과이며 누수 효과의 독립 인과 검증은 아니다. [제출 기록](https://arxiv.org/abs/2611.16162) · [논문 Appendix J](https://arxiv.org/html/2611.16162v1#S0.SS10)

**문제·Gap:** 중첩을 제거하면서 계절·지형·heading 난도도 달라질 수 있다. 서로 다른 표본의 평균만으로 공간 암기 효과를 판단하기 어렵다.

**Diagnosis → Mechanism → Hypothesis:** 학습 장면과의 근접성은 시각적 친숙함뿐 아니라 지형·수집 경로와도 연결된다. 계절×지형×heading 조건을 맞추면 full/buffered 차이 일부가 줄어들 것이라는 추론이다.

**최소 개입·MVP:** 공개 scene metadata와 per-scene 결과부터 사용한다. 계절·paved label·heading 설정을 층화하고 nearest-train 거리 및 tile overlap을 계산한다. 비중첩군과 중첩군의 공통 지지 영역에서 matching/reweighting한 오차를 비교한다. 공간 block bootstrap과 무보정 비교를 ablation으로 둔다.

**Baseline·dataset:** GOOSELoc의 동일 RGB 또는 RGB+LiDAR checkpoint 결과와 full/buffered manifest. 공식 repo는 per-scene results와 evaluator, HF는 metadata·split 파일을 안내한다. 이번에는 다운로드·실행하지 않았다. [공식 코드](https://github.com/GOOSELoc/GOOSELoc) · [데이터 카드](https://huggingface.co/datasets/Skyy93/GOOSELoc) · [프로젝트](https://gooseloc.github.io/)

**Metric·GO/KILL:** 평균 위치오차와 중앙 방향오차를 분리하고 strata별 표본 수·공간 block 불확실성을 보고한다. Matching 후에도 차이가 유지되면 추가 원인 검증으로 GO. 공통 지지 영역이 부족하면 인과 해석은 KILL한다. 관찰 자료 보정만으로 학습 누수의 인과효과를 확정하지 않는다.

**기여·위험·기간:** 공간 독립성 평가에서 selection effect를 분리하는 diagnostic benchmark가 기대 기여다. 원문이 이미 buffered 평가를 제공하므로 단순 재채점의 novelty는 낮다. 4~8주 가능성은 중간이며 다른 항공/지상 dataset으로 검증해야 한다. Negative result는 해당 protocol의 안정성을 뒷받침한다.

**Compute:** 난이도 1/5는 metadata·저장 예측 분석에 한정한다. 새 encoder 학습은 별도 고비용 작업이다. **점수:** novelty 4/5 · feasibility 4/5 · compute efficiency 5/5 · publication potential 4/5.

## Q5. 작은 객체의 strict-IoU 손실은 시각 인식 한계인가, 출력 좌표의 정밀도 손실인가?

**Observation·왜 지금:** 11월 12일 갱신된 Roboflow detection 표에서 low-effort 모델들의 AP50 우열과 AP50:95 우열이 다르다. 공식 방법론의 ±는 반복 실행 half-range이며 신뢰구간이 아니다. 이 관측만으로 tiny-object 원인을 확정할 수 없다. [공식 표](https://playground.roboflow.com/evals/object-detection) · [방법론](https://playground.roboflow.com/evals)

**문제·Gap:** 정밀 localization 저하가 작은 객체에서 커질 때, 모델의 region 인식 실패와 normalized coordinate 반올림·resize 역변환 오류를 분리할 필요가 있다. 공식 aggregate 표는 그 분해를 제공하지 않는다.

**Diagnosis → Mechanism → Hypothesis:** 같은 픽셀 오차는 작은 box의 IoU에 더 큰 영향을 줄 수 있다. 원래 고정밀 box를 보존하면 출력 직렬화에서 잃은 strict-IoU 성능 일부만 회복될 것이라는 가설이다. 인식 단계의 오차는 이 개입으로 회복되지 않아야 한다.

**최소 개입·MVP:** 저장된 고정밀 detection box에 좌표 반올림 수준과 resize 역변환만 바꾸는 replay 실험을 한다. GT box에도 같은 변환을 적용해 순수 기하학적 오차 상한 대조군을 만든다. 이후 VLM raw response의 정밀도와 decoder 정책을 감사한다. 원래부터 저정밀인 출력을 임의 보간해 “복구”했다고 주장하지 않는다.

**Baseline·dataset:** COCO validation의 크기별 subset, 기존 detector의 저장 predictions와 identity transform. 공개 leaderboard raw predictions의 가용성은 미확인이므로 먼저 자체 자료에서 수행한다. 항공 작은 객체 전이는 후속 실험이다.

**Metric·GO/KILL:** AP50/AP75/AP50:95, 크기별 recall, 정규화 center/edge 오차, parse-failure rate를 기록한다. 정밀도 조작에 따라 작은 box 손실이 선택적으로 커지고 원좌표 보존에서 회복되면 GO. 효과가 없으면 직렬화 설명은 KILL하며 시각 입력 해상도·region 인식을 검토한다.

**기여·위험·기간:** Perception error와 coordinate-channel error의 분해가 기대 기여다. 좌표 양자화 자체는 알려진 문제이므로 새로운 protocol·복수 출력 형식 검증이 필요하다. 4~8주 가능성은 중간이다. Negative result도 출력 형식보다 시각 표현에 투자할 근거가 된다.

**Compute:** 난이도 1/5는 저장 box 재채점에 한정한다. 유료 모델 호출은 MVP에 필요 없다. **점수:** novelty 3/5 · feasibility 5/5 · compute efficiency 5/5 · publication potential 3/5.

## 공통 실험 규칙과 우선 선택

수치는 실험 계획의 조건 또는 공식 artifact의 관측이며, 새로 측정한 성능은 없다. 점수는 상대적 우선순위 판단이다. Compute 난이도는 1이 가볍고 5가 무거우며, compute efficiency 점수는 높을수록 유리하다.

모든 실험은 dataset revision·split, checkpoint/backbone·pretraining·external data, 입력 해상도·TTA, prompt·reasoning/frame/token budget, raw output hash, evaluator commit, seed와 hardware를 manifest에 기록한다. 이번 조사에서 완전 고정하지 못한 값은 실행 전에 확인한다. 다른 encoder를 쓰는 Q2, 다른 subset을 쓰는 Q4, 다른 모델·effort를 쓰는 Q5의 원표 비교는 **not strictly apples-to-apples**다. Paired intervention과 별도 대조군이 필요하다.

- **오늘 가장 먼저 테스트:** Q1의 CPU pixel parity. 실제 입력이 다른지부터 확인한 뒤 모델 답변 실험으로 진행한다.
- **RTX 5060 Ti 8GB에서 시작:** Q1 pixel 단계, Q3 변환 감사, Q4 metadata·저장 결과 분석, Q5 box replay. Q2 및 Q1 모델 단계는 작은 checkpoint로 peak VRAM을 먼저 측정한다.
- **장기 박사주제:** Q4의 공간 독립성·selection effect를 중심으로, Q1의 입력 동등성 및 Q5의 metric 민감도를 결합한 도메인 변화 평가. UAV/해상 안전으로 확장하려면 해당 도메인 자료의 별도 근거와 평가가 필요하다.
- **첫 주 GO/KILL:** Parent의 실패 재현 → 최소 개입으로 회복 → 대조군 보존 순서다. 재현되지 않으면 환경 차이를 기록하고 일반적 모델 실패라는 해석을 중단한다.

오늘 바뀐 것은 새 architecture의 우열보다 평가 입력·대응·split·출력 정밀도를 검증할 구체적 근거가 늘었다는 점이다. 아직 해결되지 않은 것은 이런 오류가 실제 task metric과 연구 결론에 미치는 크기다. 다음 연구는 그 인과 경로를 최소 개입으로 분해하는 데 집중한다.
