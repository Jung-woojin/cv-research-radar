## 1. RiO-DETRv2 — 회전 객체 탐지의 가장 완성도 높은 즉시 실험 후보

1. **새로운 내용 — 사실:** 10월 21일 공개된 실시간 oriented DETR 계열 구현이다. N/S/M/L/X 설정, DOTA-v1.0·DIOR-R 설정, 평가 로그, 배포 유틸리티가 함께 공개됐다.
2. **논문/프로젝트:** [논문](https://arxiv.org/abs/2610.29159) · [코드](https://github.com/RicePasteM/RiO-DETRv2) · [가중치](https://huggingface.co/RicePasteM/RiO-DETRv2)
3. **코드 품질·재현성 — 사실:** 모델별 config, EMA checkpoint, 학습 로그, 공식 평가 CSV, manifest와 SHA256SUMS가 있다. 최근 커밋에서 DOTA 공식 평가 이력 링크도 추가됐다.
4. **라이선스 — 사실:** AGPL-3.0. 학습 때만 쓰는 DINOv3 소스와 가중치는 별도 라이선스를 따른다. 상용·폐쇄형 파이프라인에 합칠 때는 법적 검토가 필요하다.
5. **가중치/체크포인트 — 사실:** Hugging Face에 DOTA-v1.0과 DIOR-R 모델군, 훈련 로그가 공개돼 있다.
6. **설치 난이도/의존성 — 사실:** Python 3.10, PyTorch 2.2.2, torchvision 0.17.2, CUDA 12.1, numpy<2 조합을 명시한다. inference는 비교적 직선적이고, 재학습에는 DINOv3 teacher 준비가 추가된다.
7. **GPU/VRAM — 사실과 미확인 구분:** README는 2-GPU 학습 명령과 T4 지연시간 도표를 제공하지만 모델별 최소 VRAM을 수치로 확정하지 않는다. 따라서 VRAM은 직접 측정해야 한다.
8. **즉시 실험 적합성 — 해석:** 항공·위성·항만 영상에서 회전 선박·항공기·차량 탐지에 바로 연결된다. 현재 레이더의 UAV/해양/소형 객체 관심사와 가장 직접적으로 겹친다.
9. **생태계 호환 — 사실/해석:** 독립 PyTorch 코드이며 MMDetection/Ultralytics 플러그인은 아니다. 대신 ONNX와 TensorRT FP16 export 경로가 있어 배포 비교는 쉽다.
10. **유지보수 — 사실:** 공개 후 문서·라이선스·평가 이력을 연속 갱신했고, 10월 23일까지 커밋이 이어졌다. 스냅샷 시점 오픈 이슈는 1개였다.

**저자 주장:** DOTA-v1.0 single-scale에서 L/X가 각각 53.63/54.13 mAP50-95를 기록하며, X는 64.6M 파라미터라고 보고한다. 이 수치는 공개 로그와 공식 평가 이력을 제공하지만 본 보고서에서는 재실행하지 않았다.

**진단 → 가설 → 최소 실험**

- 진단: 수평 박스 기반 detector는 긴 선박과 밀집 항공기의 방향·경계 정보를 잃기 쉽다.
- 가설: RiO-DETRv2-N/S는 비슷한 처리량의 수평 detector보다 회전 IoU와 밀집 장면 AP를 개선한다.
- 최소 실험: DOTA/자체 항만 이미지 100장에 N과 S checkpoint를 적용한다. 측정값은 설치 성공 여부, 1024 타일 기준 peak VRAM, 이미지당 지연시간, AP50·AP75, 길쭉한 객체 오검출률이다. 동일 GPU·동일 타일·동일 confidence로 기존 baseline과 비교한다.

## 2. GIFT — 표현 기하 보존으로 단일 도메인 일반화 탐지

1. **새로운 내용 — 사실:** 코드가 10월 26일, 논문이 10월 27일 공개됐고 NeurIPS 2026 채택을 명시한다.
2. **논문/프로젝트:** [논문](https://arxiv.org/abs/2610.35374) · [코드](https://github.com/zhangyin1996/GIFT)
3. **코드 품질·재현성 — 사실:** DWD와 Cityscapes/Cityscapes-C 데이터 구조, Faster R-CNN과 DINOv2+DINO head의 단일·다중 GPU 명령을 제공한다. 공개 직후 데이터 준비·환경 문서를 여러 차례 보강했다.
4. **라이선스 — 사실:** Apache-2.0.
5. **가중치/체크포인트 — 사실:** 변환된 DINOv2 가중치와 저자 재현 checkpoint를 Google Drive로 제공한다. 저장소 자체 릴리스 자산이나 체크섬은 확인되지 않았다.
6. **설치 난이도/의존성 — 사실:** Python 3.9, CUDA 11.8, PyTorch 2.2.0, MMCV 2.2.0, MMEngine, xformers, numpy 1.26.0을 고정한다. MMDetection 경험이 있으면 중간, 처음이면 높음이다.
7. **GPU/VRAM — 사실과 미확인 구분:** single GPU와 4-GPU 명령을 제공하고 저자 재현 메모에 RTX 3090을 언급하지만, peak VRAM은 공개 수치로 확정되지 않았다.
8. **즉시 실험 적합성 — 해석:** 맑은 날 학습→안개·비·야간 일반화, 합성→실해역 전이처럼 도메인 이동이 큰 과제에 유용하다.
9. **생태계 호환 — 사실:** MMDetection/MMCV 기반이다. Faster R-CNN 계열과 DINOv2 backbone+DINO head 설정을 제공하며 Ultralytics 직접 호환은 아니다.
10. **유지보수 — 사실:** 공개 이틀 안에 환경·데이터·논문 링크 관련 README 커밋이 연속적으로 들어왔다. 성숙도보다 반응 속도가 좋은 초기 프로젝트다.

**저자 주장:** frozen backbone에 1% 미만의 추가 trainable parameter를 넣고 Cityscapes-C와 DWD에서 이전 SOTA 대비 mPC를 각각 7.9%, 2.9% 개선했다고 보고한다. 이는 저자 결과이며 독립 재현 전에는 확정 사실로 취급하지 않는다.

**진단 → 가설 → 최소 실험**

- 진단: 사전학습 VFM을 detection에 전면 미세조정하면 표현의 거리·각도 구조가 깨져 미관측 날씨에 약해질 수 있다.
- 가설: GIFT의 Householder 기반 제약은 일반 fine-tuning보다 source AP 손실을 억제하면서 corruption mPC를 높인다.
- 최소 실험: 공개 RTX 3090 재현 checkpoint로 Cityscapes clean과 corruption 3종 각 severity 1·3·5를 평가한다. clean AP, corruption별 AP, mPC, trainable parameter 비율, 추론 지연 증가량을 plain fine-tuning과 비교한다.

## 3. VMem-Bench — 장영상 생성 메모리를 통제 가능한 문제로 바꾸는 벤치마크

1. **새로운 내용 — 사실:** 10월 26일 공개된 causal long-video generation용 visual memory benchmark다. Track A는 생성 전 reference selection, Track B는 생성 영상의 entity/state 보존을 평가한다.
2. **논문/프로젝트:** [논문](https://arxiv.org/abs/2610.35001) · [프로젝트 페이지](https://suchenl.github.io/VMem-Bench/) · [코드](https://github.com/Suchenl/VMem-Bench) · [데이터](https://huggingface.co/datasets/Suchenl/VMem-Bench)
3. **코드 품질·재현성 — 사실:** adapter template, protocol 문서, shared-generator testbed, scoring 설치 스크립트, annotation pipeline, tests가 분리돼 있다. 새 실행은 code revision·cohort·model·seed를 기록하도록 요구한다.
4. **라이선스 — 사실:** 코드는 Apache-2.0, 저자 작성 gold/prompt는 CC BY 4.0. 원본 영화·LSMDC 자료·모델 가중치는 재배포하지 않는다.
5. **가중치/체크포인트 — 사실:** CPU placeholder 예제는 가중치가 필요 없지만 점수를 만들지 않는다. 실제 scoring model과 source video는 별도 다운로드다.
6. **설치 난이도/의존성 — 사실:** pip editable install 후 CPU 인터페이스 예제를 실행할 수 있다. 정식 평가는 데이터 권리와 scoring 모델 설치 때문에 난도가 올라간다.
7. **GPU/VRAM — 미확인:** 인터페이스 스모크 테스트는 CPU로 가능하다. 실제 video generation/scoring의 GPU·VRAM은 선택 모델에 따라 달라 저장소가 단일 수치로 보장하지 않는다.
8. **즉시 실험 적합성 — 해석:** 장영상 VLM의 “기억 선택”과 생성 모델의 “상태 유지”를 분리해 실패 원인을 진단하는 데 좋다. 자체 생성 모델이 없어도 adapter 계약을 먼저 검증할 수 있다.
9. **생태계 호환 — 사실/해석:** Hugging Face dataset 배포와 Python adapter 구조를 사용한다. MMDetection/Ultralytics/timm 대상은 아니며 video generation pipeline용이다.
10. **유지보수 — 사실:** 공개 다음 날 arXiv 링크와 다국어 프로젝트 페이지를 다듬는 커밋이 이어졌다. 원본 rollout과 per-segment score bundle이 저장소에 포함되지 않은 점은 재현 리스크다.

**저자 주장:** 메모리가 많다고 장영상 품질이 자동으로 좋아지는지, 과거 정보가 실제로 유용한 시점을 통제 비교하겠다는 벤치마크다. 정량 결론은 논문에 있으나 본 보고서는 코드 프로토콜의 재현 가능성만 확인했다.

**진단 → 가설 → 최소 실험**

- 진단: long-video memory 성능 저하가 reference selection 실패인지 generation 중 상태 망각인지 한 숫자로는 구분하기 어렵다.
- 가설: 동일 generator에서 reference budget을 고정하면 단순 last-seen보다 task-aware selection이 Track A와 Track B의 상태 일관성을 함께 높인다.
- 최소 실험: 먼저 CPU placeholder 5개로 adapter 계약과 로그 스키마를 통과시킨다. 다음으로 Track B prompt 30개 중 5개, seed 2026, 동일 generator에서 no-memory/last-seen/custom 세 조건을 비교한다. 실행 성공률, segment당 선택 reference 수, entity/state score, 총 생성 시간, peak VRAM을 기록한다.

## 4. ALPS — 상태·언어·픽셀을 하나의 공개 ViT-B 토큰 공간에 결합

1. **새로운 내용 — 사실:** 10월 21일 논문, 10월 22일 코드가 공개됐다. ViT-B/16 inference package, unified evaluation, JAX/Flax 학습 코드, PyTorch 재구현을 함께 제공한다.
2. **논문/프로젝트:** [논문](https://arxiv.org/abs/2610.30120) · [코드](https://github.com/UCSC-VLAA/ALPS) · [가중치](https://huggingface.co/UCSC-VLAA/ALPS)
3. **코드 품질·재현성 — 사실:** CPU tests, JAX↔PyTorch parity test, model card, validation record, timm export, torch.hub 로딩, 15개 공개 encoder용 통합 평가 인터페이스가 있다.
4. **라이선스 — 사실:** Apache-2.0.
5. **가중치/체크포인트 — 사실:** ALPS와 Stage-1 safetensors, LIBERO policy 8개를 공개한다. 한 줄 로더로 다운로드 가능하다.
6. **설치 난이도/의존성 — 사실:** 기본 inference는 torch·numpy·Pillow 중심이고, test 옵션은 safetensors·timm·transformers·pytest를 추가한다. 전체 학습은 JAX/Flax 또는 PyTorch DDP로 훨씬 무겁다.
7. **GPU/VRAM — 사실과 미확인 구분:** CPU 테스트가 가능하지만 대규모 사전학습의 GPU/TPU 예산과 최소 VRAM은 간단한 단일 수치로 제시되지 않는다. 이번 주 범위는 inference와 frozen-probe로 한정한다.
8. **즉시 실험 적합성 — 해석:** vision encoder가 현재 상태, 텍스트 정렬, 픽셀 복원 중 무엇을 보존하는지 비교하려는 연구에 좋다. 해양 영상 representation probing에도 쓸 수 있지만 탐지 모델 자체는 아니다.
9. **생태계 호환 — 사실:** timm 호환 ViT-B/16 export와 Hugging Face safetensors를 제공한다. MMDetection/Ultralytics에는 backbone adapter가 별도로 필요하다.
10. **유지보수 — 사실:** 공개 커밋 하나가 매우 큰 완성형 릴리스다. training data 자체는 미공개이고 입력 record 형식만 문서화돼 있어 full pretraining 재현은 제한된다.

**저자 주장:** ALPS는 비교한 ViT-B 중 LIBERO state-probe aggregate error가 가장 낮고, 자체 text tower 사용 시 LIBERO 평균 policy success 85.5%를 보고한다. 또한 공개 encoder 중 상태·언어·복원을 동시에 모두 앞서는 단일 비교 대상은 없다고 주장한다.

**진단 → 가설 → 최소 실험**

- 진단: 일반 이미지 encoder의 좋은 분류 성능이 동적 장면의 상태 보존을 보장하지 않는다.
- 가설: ALPS frozen patch token은 DINOv2-B와 CLIP-B보다 해양 영상의 시점 변화·가림 뒤 객체 상태를 선형 probe로 더 잘 복원한다.
- 최소 실험: 200개 짧은 해양 클립에서 프레임 1장의 frozen token으로 1초 후 선박 중심·방향을 예측하는 동일 선형 probe를 학습한다. ALPS/DINOv2/CLIP에 대해 위치 오차, 방향 오차, probe 학습시간, encoder 지연, peak VRAM을 비교한다.

## 5. ST-SAM3 — 저라벨 원격탐사 salient object detection, 단 배포 마찰 존재

1. **새로운 내용 — 사실:** 10월 27일 공개된 원격탐사 SOD 코드로, 5%·10% 라벨 조건에서 SAM3 계열 teacher/student 파이프라인을 제공한다.
2. **논문/프로젝트:** [코드](https://github.com/lyf0801/ST-SAM3). README의 정식 논문 식별자·인용 정보는 아직 비어 있다.
3. **코드 품질·재현성 — 사실:** ORSSD, EORSSD, ORSI-4199 split과 seed, 다단계 학습·평가 스크립트, saliency map export와 metric 계산을 제공한다.
4. **라이선스 — 사실:** MIT.
5. **가중치/체크포인트 — 사실:** ST-SAM3와 DistillMatch 비교용 12개 checkpoint를 공개하지만 Baidu Netdisk 단일 경로다.
6. **설치 난이도/의존성 — 사실:** Python 3.10, PyTorch 2.3.1+cu121, mmcv, timm, einops와 SAM3/DINOv3/MobileSAM 자산이 필요하다. 여러 stage를 순서대로 실행해야 해 높음이다.
7. **GPU/VRAM — 사실과 미확인 구분:** README는 NVIDIA A100 환경을 명시하지만 정확한 최소 VRAM은 제시하지 않는다.
8. **즉시 실험 적합성 — 해석:** 원격탐사와 저라벨 조건은 매우 잘 맞지만, 최초 실험은 전체 재학습보다 공개 checkpoint inference로 제한하는 편이 안전하다.
9. **생태계 호환 — 사실/해석:** mmcv·timm을 쓰지만 MMDetection config 체계나 Ultralytics 플러그인은 아니다. saliency-specific pipeline이다.
10. **유지보수 — 사실:** 현재는 initial commit 하나다. 논문 링크·release asset·체크섬·issue 대응 이력이 쌓이는지 관찰해야 한다.

**저자 주장:** ORSSD/EORSSD/ORSI-4199의 5%·10% 라벨 조건에서 DistillMatch와 ST-SAM3 결과를 제시한다. 정식 논문이 연결되지 않아 수치의 방법론적 맥락은 아직 충분히 교차검증할 수 없다.

**진단 → 가설 → 최소 실험**

- 진단: 저라벨 원격탐사 SOD는 pseudo-label 오류가 작은 객체와 복잡한 배경에서 누적되기 쉽다.
- 가설: 공개 ST-SAM3 checkpoint는 동일 split의 DistillMatch보다 작은 salient object의 MAE를 낮추되 추론비용이 증가한다.
- 최소 실험: ORSSD 5% 공개 split에서 두 checkpoint의 saliency map을 생성한다. MAE, max F, S-measure, 이미지당 지연, peak VRAM, 면적 하위 25% 객체의 누락률을 비교한다. 정식 논문 URL 확인 전에는 재학습·대규모 도입을 보류한다.

## 보류·제외 후보

- **Looking-Ahead:** 1.3B/5B 가중치와 설치 경로가 있어 강한 후보지만, 이번 주 우선 연구축인 탐지·원격탐사·평가 인프라보다 비디오 생성 모델 자체에 가깝다. 다음 video-generation 특집에서 재평가한다.
- **CofactVLA:** Apache-2.0과 LIBERO 코드가 있으나 저자 학습 예시가 4×H100 96GB라 최소 실험 비용이 높다.
- **ST-Pruner:** visual token pruning 주제는 유용하지만 README의 논문 링크가 placeholder여서 공식 원문 교차검증 요건을 충족하지 못했다.
- **NF-UAVTrack:** UAV tracking 데이터 신호는 매력적이나 라이선스와 논문/벤치마크 근거가 불명확해 제외했다.
- **RelationVGGT:** 코드·checkpoint가 “곧 공개” 상태라 재현 실험을 시작할 수 없다.

## 이번 주 실제 클론 순서

1. **RiO-DETRv2:** checkpoint checksum 확인 → N/S inference → 자체 항만 100장 → ONNX export
2. **GIFT:** 환경 생성 → 공개 checkpoint clean/corruption 평가 → plain fine-tuning 대조
3. **VMem-Bench:** CPU adapter 스모크 테스트 → Track B 5 prompt × 3 memory 조건
4. **ALPS:** CPU test → single-GPU frozen-token 추출 → 200 clip linear probe
5. **ST-SAM3:** 논문 URL·checkpoint mirror·checksum 확인 후 inference-only trial

## 운영 판단

- **확인된 사실:** 네 개 즉시 클론 후보는 모두 공식 코드와 명시적 라이선스를 갖고 있고, RiO-DETRv2·GIFT·ALPS는 논문과 가중치까지 연결된다. VMem-Bench는 실제 점수를 내려면 별도 자산이 필요하다.
- **해석:** 이번 주 가장 높은 기대값은 새 구조 자체보다 “실험 경로가 닫혀 있지 않은가”에 있다. 로그·체크섬·tests·adapter protocol이 있는 프로젝트를 우선했다.
- **전망:** RiO-DETRv2의 회전 탐지와 GIFT의 기하 보존 fine-tuning을 결합하면 항공·해양 도메인 이동에서 의미 있는 후속 질문이 생긴다. 다만 두 코드를 바로 합치기보다 각자의 최소 실험을 통과시킨 뒤 adapter 비용을 추정해야 한다.
- **중단 조건:** 설치 2시간 초과, 문서와 다른 checksum, 공개 명령으로 inference 실패, 또는 단일 24GB GPU에서 OOM이면 그 주의 대규모 재학습을 중단하고 원인을 ledger에 남긴다.
