## 2. BoT-SORT 해상도 변경이 일회성 GMC 실패를 지속 상태로 만듦

**확인 사실:** #27270은 미병합이다. Diff는 `GMC.apply_sparseoptflow`의 초기화 조건에 이전/현재 frame shape 불일치를 추가한다. 자동 리뷰의 LGTM은 있지만 사람 maintainer의 독립 재현은 확인하지 못했다. [공식 PR·재현 코드](https://github.com/ultralytics/ultralytics/pull/27270) · [diff·회귀 테스트](https://github.com/ultralytics/ultralytics/pull/27270/files)

- **실패 조건·구성:** YOLO11n, `model.track(..., persist=True, tracker="botsort.yaml", device="cpu", imgsz=320)`, Linux/OpenCV 4.10. 입력 크기를 `(320,480)`에서 `(400,600)`으로 변경하는 통제된 sequence다. 실제 RTSP 카메라 관측은 아니다.
- **작성자 재현:** 기존 코드에서는 마지막 세 호출이 계속 `calcOpticalFlowPyrLK` 실패를 기록하고 cached frame이 `(240,160)`에 남는다. 수정 후 전환 시 `(300,200)`으로 갱신되고 다음 같은 크기 frame에서 motion estimation이 회복된다고 보고했다.
- **공식 인정·community 수준:** contributor의 public API 재현과 실제 OpenCV 회귀 테스트가 근거다. 독립 community 재현·사람 maintainer 인정은 미확인이다. 전체 suite는 offline weight 부재로 중단돼 검증 완료가 아니다.
- **진단 → 메커니즘:** OpenCV shape assertion을 잡아 identity transform으로 fallback하지만 예외 전에 history 갱신에 도달하지 못한다. 다음 frame도 같은 stale history와 비교하므로 실패가 고착된다. 추적 호출 자체가 crash한다는 주장은 아니다.
- **가설 → 최소 개입:** geometry 전환을 새 optical-flow history 시작으로 취급하면 전환 frame은 identity로 처리하되 이후 GMC를 회복할 수 있다.
- **최소 실험:** base `27cf3175a9aff96e12a65b86813d0a98bf7b1b92`와 PR head `d7ab0b9f2a7ffe2b6c75f614513783f6bf533f06`에서 textured 합성 frame에 두 geometry 전환을 넣는다. 각 전환 다음 frame에 알려진 x/y 이동을 주고 downscale 1·2의 history shape, 반복 warning 수, affine 이동 오차를 기록한다. 동일 크기 sequence를 대조군으로 둔다.
- **GO/KILL:** 전환 frame identity와 다음 frame의 알려진 이동 회복이 함께 성립하면 GMC 진단 GO. Track ID continuity·Kalman state rescaling·실제 카메라 복구를 해결했다는 확대 주장은 KILL한다. 원문도 이 항목들을 지원 범위에서 제외한다.
- **기존 주장과 충돌:** “exception을 catch했으므로 정상 복구”와 실제 상태 회복은 다르다. UAV/CCTV의 resize 이후 ID 성능 저하로 이어질 수 있다는 것은 조사자의 추론이며 IDF1/HOTA 감소는 미측정이다.
- **점수:** 심각도 **3/5** · 재현 신뢰도 **3/5** · 연구 아이디어 가치 **4/5**.

## 3. Qwen의 정답 box가 주변 설명문 때문에 빈 검출로 변환됨

**확인 사실:** Supervision #3011은 미병합이다. #3010 제보와 동일 작성자의 PR이며 두 문서를 독립 community 재현 두 건으로 세지 않는다. Diff는 응답 시작에만 있던 fence 제거를 첫 fence 검색으로 바꾼다. [공식 issue](https://github.com/roboflow/supervision/issues/3010) · [PR·테스트 보고](https://github.com/roboflow/supervision/pull/3011) · [diff](https://github.com/roboflow/supervision/pull/3011/files)

- **실패 조건·구성:** Supervision `develop`의 `887a7ae`, `0.32.0.dev0`, Python 3.11, NumPy 2.4.6, Ubuntu/WSL2. Qwen2.5-VL 또는 이를 호출하는 Qwen3-VL 파서에서 fenced JSON 앞에 `[x1, y1, x2, y2]` 같은 대괄호 설명문이 있다. 실제 모델 checkpoint·dataset·새 inference는 필요 없는 합성 응답 재현이다.
- **작성자 재현:** 유효한 `bbox_2d=[100,200,300,400]`, label `cat` payload인데 기존 파서는 빈 결과를 반환한다고 보고했다. 여섯 회귀 case 중 bracket이 fence 앞에 있는 세 case가 base에서 실패하고 수정 후 통과했다고 기재했다.
- **공식 인정·community 수준:** 사람 maintainer의 독립 재현이나 승인·병합은 미확인이다. 공식 저장소 제보와 수정 코드가 구체적이지만 실제 생성 응답에서의 발생 빈도는 알려지지 않았다.
- **진단 → 메커니즘:** JSON payload를 찾기 전에 첫 `[`부터 잘라 설명문의 bracket을 payload 시작으로 오인한다. 모델이 box를 못 찾은 것과 parser가 box를 버린 것을 분리해야 한다.
- **수정안의 negative signal:** Copilot 자동 리뷰는 label 문자열 안의 triple backtick, 앞선 무관한 fenced block, 유효한 unfenced JSON 뒤 fence가 새 방식에서 검출을 잃을 수 있다고 지적했다. 이는 자동 리뷰의 주장과 코드 검사 근거이며 사람 독립 검증 완료가 아니다. [label 내부 backtick 지적](https://github.com/roboflow/supervision/pull/3011#discussion_r4603933144) · [첫 fence 선택 지적](https://github.com/roboflow/supervision/pull/3011#discussion_r4603933218)
- **가설 → 최소 개입:** JSON 문자열 내부와 외부의 구분 및 검출 schema 검증을 통해 payload를 선택하면 주변 자연어 변화에 대한 box 불변성을 높일 수 있다. 첫 fence만 선택하는 수정은 잠정 가설로 남긴다.
- **최소 실험:** 고정 box JSON에 ① 설명 없음 ② bracket 설명 ③ bracket reasoning ④ 무관한 선행 code block ⑤ label 내부 backtick ⑥ 후행 fence를 조합한다. issue base와 head `55e8cff0d56f1abc800c7bc150aca2a6abcc3a3b`에서 box·label·빈 결과·예외를 비교한다. 원문 `887a7ae`를 우선 사용하고 현재 이동한 develop을 같은 baseline으로 취급하지 않는다.
- **GO/KILL:** 정답 payload와 주변 문구만 다른 case에서 box·label이 보존되면 GO. 기존 허용 입력을 잃으면 수정안 채택을 KILL/보완한다. CPU parser 결과만으로 VLM grounding AP 개선을 주장하지 않는다.
- **기존 주장과 충돌:** Answer–Region Gap의 일부가 모델 능력보다 문자열 복구 단계에서 생길 수 있다는 연구 가설이다. 빈 결과를 전부 hallucination 또는 missed object로 집계하면 원인을 혼동한다.
- **점수:** 심각도 **3/5** · 재현 신뢰도 **3/5** · 연구 아이디어 가치 **4/5**.

## 논문 아이디어로 연결 가능한 빈틈

**조사자의 추론:** aerial/UAV·CCTV 파이프라인을 대상으로 모델 출력의 의미는 고정하고 표현·geometry state·주변 응답 형식만 바꾸는 진단 benchmark를 설계할 수 있다. 개입은 compact mask 유지, optical-flow history reset, schema-aware payload 선택으로 제한한다. 각각 peak memory와 pixel parity, state recovery와 motion error, parser invariance와 box/label 보존을 짝지어 측정한다.

알려진 세 버그 재현만으로 novelty가 확보되지는 않는다. 여러 구현에서 같은 계약 위반이 재발하는지, 실제 task metric과 연결되는지 확인해야 한다. tiny-object recall·IDF1·grounding AP에 대한 효과는 현재 미확인이다. 개선된 fixture와 새로 깨진 반례를 함께 공개해야 한다.

## 직접 재현해볼 최소 실험
