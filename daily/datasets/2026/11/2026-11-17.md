## 2. Supervision — 비연속 class ID를 list 위치로 읽는 위험

**새 근거·상태:** 기존 issue #2980은 11/13 공개로 오늘의 72시간 창 밖이다. 오늘 채택한 신호는 11/15 생성된 수정 PR #2985와 공개 patch다. 조회 시 PR은 open, merged=false이며 conflict 상태다. 배포된 fix나 maintainer가 확정한 correction으로 표현하지 않는다. [issue와 재현 환경](https://github.com/roboflow/supervision/issues/2980) · [새 수정 PR](https://github.com/roboflow/supervision/pull/2985)

**기여자 보고:** Supervision `0.32.0.dev0`, develop `f33ce15f`, Python 3.12.13·Windows 11에서 `names: {1: cat, 2: dog}`와 label ID 1을 읽으면 dog로 해석된다고 보고한다. ID가 0부터 연속되지 않는 dict에서 key를 정렬한 이름 list와 원 label ID가 어긋나는 조건이다. 일반적인 연속 `0..N-1` dataset 전체의 오류로 확대하지 않는다.

**직접 확인한 patch:** 제안은 detection·pose loader에 declared ID→내부 index 변환을 추가하고, 선언하지 않은 ID에는 파일 경로가 포함된 ValueError를 내도록 한다. export에서는 이름·label 일관성을 유지하지만 원래 숫자 ID를 보존하지 않는다고 기여자가 명시한다. 테스트 통과 수는 독립 실행하지 않았으므로 이 보고서의 검증 수치로 인용하지 않는다. [공개 diff](https://github.com/roboflow/supervision/pull/2985/files)

**규모·split·artifact·license:** 실제 대형 dataset 배포가 아니라 한 이미지·두 클래스의 재현 fixture와 loader 수정 제안이다. train/val/test split이나 새 label release는 없다. 저장소 code license는 MIT지만 이를 불러오는 데이터의 license까지 의미하지 않는다. [공식 저장소](https://github.com/roboflow/supervision)

**진단 → 가설:** class 제거·taxonomy 병합 후 ID에 gap이 남으면 box 좌표가 정상이어도 label 의미가 달라질 수 있다. 클래스별 성능 저하가 representation 문제로 오인될 수 있다는 **추론**이다. 도구별 gap 처리 정책과 매핑이 다른 결과는 **not strictly apples-to-apples**다.

**최소 실험·GO/KILL:** 연속 dict·1-indexed dict·gap dict·미선언 ID fixture로 `원본 ID→이름→내부 ID→export 이름`을 비교한다. detection과 pose를 각각 검사하며 숫자 ID의 round-trip 보존과 의미 보존을 구분한다. audit는 GO. 미병합 PR을 설치된 릴리스의 해결책으로 안내하는 것은 KILL. 실제 데이터 mapping이 틀리면 모델 변경 전에 mapping부터 고친다.
