## 1. Ultralytics 8.4.217 — calibration과 evaluator를 분리해야 한다

**정확한 배포.** [Tag object](https://api.github.com/repos/ultralytics/ultralytics/git/tags/dd1118b4c0bc8ade1a9bd0a1a63eb34decbc0ab7)는 commit `bc52df894fafc9084977674a537bfd9d47185778`을 가리킨다. tagger 시각은 23일 19:47:34 UTC, release 발행은 19:49:22 UTC다. tag verification은 unsigned다. 이전 보고의 8.4.215·216과 다른 실제 신규 배포다.

### A. TensorRT 11 INT8: 더 많은 calibration data가 항상 안전하지 않다

**코드 사실.** [PR #27340](https://github.com/ultralytics/ultralytics/pull/27340)은 23일 19:47:20 UTC merge됐다. `modelopt_quantize_onnx`에서 `calibration_method="max"`를 삭제한다. [최종 배포 코드](https://github.com/ultralytics/ultralytics/blob/a29082156f44a4cc1d563766543b5a2c7298e48f/ultralytics/utils/export/engine.py)에서도 명시적 `max`가 없다. 즉 `entropy`를 코드에 직접 고정한 것이 아니라 **ModelOpt 기본값에 의존**한다. 개발자는 최소 0.44.0과 측정에 사용한 0.48.0의 기본값을 확인했다고 설명한다. TensorRT 7~10 경로까지 같은 변경이라고 해석하지 않는다.

**저자 측정.** PR은 RTX PRO 6000 Blackwell, TensorRT 11.5.0.63, ModelOpt 0.48.0, torch 2.15.0+cu132, static batch 1 조건을 명시한다. calibration 128장 조건의 YOLO26s-pose에서 mAP50-95(P)는 `max` 0.3130, `entropy` 0.6106, FP16 0.6258이다. 이는 **29.76 percentage points 회복**이며 FP16 초과나 새 architecture gain이 아니다. 검증은 COCO val2017 전체를 사용했다는 개발자 보고다.

반면 기본 4장 calibration의 YOLO26s-OBB는 0.6177→0.6088로 낮아지고, YOLO26n-sem도 mIoU 0.7098→0.7076으로 낮아진다. PR은 반복한 entropy engine이 0.6 point 이내에서 재현됐다고 설명한다. calibration 비용도 늘 수 있다. 큰 회복 수치를 모든 task·data 크기·hardware에 적용하지 않는다.

**진단 → 가설.** 저자는 `max`가 outlier로 범위를 넓혀 일반 activation의 INT8 해상도를 잃게 한다고 설명한다. 추론상 calibration 이미지 수·분포와 clipping 규칙 사이의 상호작용을 먼저 검사해야 한다. 모델 feature 자체가 정보를 잃었다는 결론은 이 배포만으로 성립하지 않는다.

**10~30분 최소 실험 계획.** 준비된 TensorRT 환경과 동일 checkpoint가 있을 때만 작은 모델 하나로 진행한다. 동일 ONNX·이미지 목록과 순서·seed·shape·batch·GPU·ModelOpt·evaluator를 고정하고 calibration method만 바꾼다. FP16 reference와 두 INT8 결과의 고정 subset prediction 오차·task metric·calibration 시간·peak memory를 기록한다. 4장/128장 비교는 별도 축이다. 전체 배포 버전끼리 비교하면 다른 수정도 섞이므로 paired patch를 우선한다. full validation과 새 설치까지 30분 내 끝난다고 약속하지 않는다.

**GO/KILL.** 동일 조건의 accuracy 회복과 export 비용을 함께 확인하면 GO. calibration data가 많아졌다는 이유만으로 더 정확하다고 가정하거나 entropy가 FP16보다 우수하다고 주장하면 KILL이다.

### B. `single_cls`: 점수가 달라진 이유가 evaluator 교체일 수 있다

**코드 사실.** [PR #27320](https://github.com/ultralytics/ultralytics/pull/27320)은 23일 18:34:53 UTC merge됐다. 최종 [detect/val.py](https://github.com/ultralytics/ultralytics/blob/a29082156f44a4cc1d563766543b5a2c7298e48f/ultralytics/models/yolo/detect/val.py)는 COCO/LVIS에 `single_cls=True`인 경우 annotation 기반 외부 평가를 건너뛴다. custom ground truth `gdict`는 계속 평가한다. prediction JSON 저장 자체를 없애는 변경은 아니다.

**저자 주장·검증 한계.** PR은 COCO val2017 500장, CPU, imgsz 640에서 반환 stats의 box mAP50-95가 0.0028→0.4358로 바뀌었다고 보고한다. 전자는 한 클래스로 접힌 prediction을 다중 category annotation으로 평가한 결과이고 후자는 native class-agnostic metric이다. 일반 multiclass와 `classes=[0]` 대조군은 같았다는 보고다. full COCO, 실제 LVIS annotation, segmentation, DDP는 미검증이라고 명시한다.

coco-pose는 원래 person 한 클래스여도 `single_cls`를 켜면 native box/pose metric으로 바뀐다. 외부 evaluator의 size-range breakdown도 제공되지 않는다. 수정 전후 숫자는 **not strictly apples-to-apples**다. 같은 이름의 mAP가 같은 평가 계약을 보장하지 않는다.

**진단 → 가설 → 10~30분 CPU 계획.** 고정 prediction·label fixture로 COCO/LVIS flag, `single_cls`, `gdict` 분기부터 검사한다. 외부 evaluator 호출 여부와 반환 stats의 출처를 기록하고 multiclass·`classes=[0]`·custom JSON 대조군을 둔다. 실제 dataset subset이 이미 준비돼 있으면 native/외부 결과와 학습 종료 logger에 저장되는 값을 분리한다. 재학습은 첫 실험에 필요 없다.

**GO/KILL.** prediction은 같은데 metric 경로만 달라지는지 확인하는 audit는 GO. 이 점수 상승을 checkpoint 개선·학습 향상·논문 SOTA로 보고하면 KILL이다.

8.4.217의 두 진단은 현재 8.4.218 코드에서도 확인했다. pin 후보는 `ultralytics==8.4.218`이며, 217과의 차이를 볼 때만 별도 환경을 사용한다. [배포 pyproject](https://github.com/ultralytics/ultralytics/blob/a29082156f44a4cc1d563766543b5a2c7298e48f/pyproject.toml)는 AGPL-3.0, Python ≥3.8, torch ≥1.8, torchvision ≥0.9 등의 범위 의존성을 명시한다. 이 최소값은 TensorRT 11 export 전체 환경의 최소 조건을 보증하지 않는다.

export에는 ONNX·ModelOpt·TensorRT·CUDA/driver, 평가에는 faster-coco-eval 등 별도 surface가 있다. package pin 하나는 환경 lock이 아니다. 새 weights·dataset·독립 evaluator bundle 공개로 확인한 release가 아니다. 관련 #27334 제보와 #27340·#27320 merged PR을 확인했지만 전체 Issue 해결률이나 독립 재현은 조사하지 않았다. CPU 분기 fixture는 GPU가 필요 없고 TensorRT 실험은 호환 NVIDIA GPU가 필요하다. 최소 VRAM은 확인하지 못했다.

[PR #27341](https://github.com/ultralytics/ultralytics/pull/27341)은 23일 21:55:11 UTC merge, release는 21:55:35 UTC 발행됐다. tag는 unsigned다.

**코드 사실.** Sentry SDK major version이 3 이상이면 `data_collection={"stack_frame_variables": False}`, 이전 버전이면 `include_local_variables=False`를 넘긴다. SDK 3에서 제거된 option 때문에 발생하는 초기화 실패를 막는 변경이다. prediction architecture·weights를 바꾸는 diff는 아니다.

**개발자 검증.** non-editable pip install, `yolo` entry point, online·`sync=True`로 Sentry 초기화가 실제 실행되는 조건에서 SDK 3.0.0·2.76.0·2.40.0·1.45.1 조합을 검사했다고 보고한다. SDK 3에서만 217이 실패하고 수정본은 통과했다는 주장이다. offline이나 telemetry 비활성 환경의 통과만으로 이 분기를 검증했다고 할 수 없다.

**가용성과 checksum.** [공식 PyPI metadata](https://pypi.org/pypi/ultralytics/8.4.218/json)에서 wheel 업로드는 23일 21:56:18.77879 UTC다. `ultralytics-8.4.218-py3-none-any.whl`의 SHA256은 `ea65ef2804d5085da14c117345fffbc53bff33190a2a8fc17e7524f2c8ab7e2d`다. metadata 확인이며 다운로드 검산·provenance attestation 검증은 하지 않았다. source license·설치 surface는 앞 항목과 같고, 새 weight·data는 확인하지 않았다. 초기화 계약 검사는 GPU/VRAM이 필요 없다.

**진단 → 가설 → 10~30분 최소 계획.** “모델이 실행되지 않는다”는 제보에서 inference 이전 dependency 초기화를 먼저 분리한다. 네트워크 전송을 하지 않는 mocked Sentry init으로 major-version별 전달 인자와 금지된 구 option의 부재를 검사한다. telemetry를 켜거나 weight를 다운로드하는 단계는 이 fixture에 필요 없다. 실제 CLI 검증은 준비된 격리 환경에서만 별도 진행한다.
