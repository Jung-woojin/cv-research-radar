## 핵심 사례

### 1. V-Interaction-400K preview

- **사실:** 공식 저장소는 11/07에 252K samples의 preview를 공개했다고 공지했다. HF viewer는 25개 `train_part` split을 보이며, 예시 schema에는 `question`, `image`, `original_img_code`, `edited_image`, `tool_code`, `CoT_with_code`, `answer`가 있다.
- **저자 주장:** “large-scale, high-quality visual interaction dataset”이며 image-to-code로 확장 가능하다고 설명한다.
- **규모·task·artifact:** image/text Parquet; viewer 기준 100K–1M 규모 표기. 원본과 편집된 시각 artifact 및 tool/code supervision을 함께 제공하는 visual interaction task다.
- **split·license:** 25개 training part는 확인됐지만 holdout/evaluation split과 data-specific license는 이번 공식 페이지에서 확인하지 못했다. 저장소의 MIT는 code repository license다.
- **알려진/의심 bias:** 예시가 programmatic image/code와 편집 과정을 드러내므로, 동일 원본에서 파생된 편집본·template·코드가 train/test 사이에 걸치면 편집 일반화가 아니라 계열 memorization이 될 수 있다. 이는 현재 **추론**이며 leakage가 확인된 사실은 아니다.
- **최소 audit:** pixel hash와 perceptual hash로 `image`–`edited_image` 및 split 간 near duplicate를 찾고, `original_img_code`/`tool_code` canonical hash로 template overlap을 측정한다. group split은 원본 image 또는 code template 단위로 재구성한다.
- **GO/KILL:** group-heldout에서도 text/image-only baseline 대비 tool-conditioned 이득이 유지되면 사용 검토(GO); template-heldout에서 이득이 사라지면 code-template shortcut으로 보고 training claim에는 쓰지 않는다(KILL).

### 2. V-Perception-40K preview

- **사실:** 공식 저장소는 11/07에 37K-sample preview를 공지했고, HF viewer의 `v_perception_40k` split은 36.7K rows를 표시한다. schema에는 `image`, `question`, `answer`, `python_code`, `element_arrtibute`가 있다.
- **저자 주장:** point-level perceptual alignment dataset이다.
- **규모·task·artifact:** image/text Parquet, 10K–100K 규모 표기. viewer 예시는 점/도형/좌표와 semantic attribute가 포함된 spatial grounding·structured perception supervision이다.
- **split·license:** viewer에서 하나의 named split만 확인됐고 dev/test 분리와 data-specific license는 확인하지 못했다.
- **알려진/의심 bias:** viewer examples는 합성 도형·chart-like scene에 치우친 인상을 준다. 실제 사진, OCR noise, occlusion, low-resolution 환경으로의 전이는 아직 공식 근거로 검증되지 않았다.
- **최소 audit:** `element_arrtibute`의 label type/attribute count/이미지 크기/질문 template 분포를 집계하고, code template 또는 geometry family 단위 heldout에서 point-coordinate error와 exact-match를 보고한다.
- **GO/KILL:** template-heldout와 image-size shift에서 성능 하락이 제한적이면 perception probe로 GO; random split만 높고 family-heldout가 무너지면 일반 vision grounding claim에는 KILL이다.

### 3. VTBench — three-task annotation/evaluation layout

- **사실:** 공식 저장소는 Perception, Instruction-Guided Interaction, Interactive Reasoning 세 task를 포함한 VTBench를 11/07 공개했다고 밝힌다. HF viewer는 Parquet image/text dataset, 하나의 `train` split 500 rows와 각 row의 `annotation_instruction`, `annotation_perception`, `question_reasoning`, `answer_reasoning`, `question_perception`, `question_instruction`, `answer_instruction` field를 보인다.
- **규모 해석:** 저장소는 1,500 QA pairs라고 설명한다. viewer의 500 rows가 세 task QA를 각각 갖는 schema이므로 500×3으로 계산하면 이 설명과 양립한다. 이는 viewer schema 기반 해석이다.
- **split·license·artifact:** 공개 artifact는 viewer/Parquet와 annotation images다. 현재 확인된 split은 `train` 하나이며 data-specific license, hidden test, judge prompt/aggregation rule은 확인하지 못했다.
- **진단:** 동일 row의 세 task가 공유 이미지/문맥을 갖는 구조라면, multi-task score는 task 간 독립 sample 수보다 shared template/image family의 영향을 받을 수 있다.
- **최소 audit:** row ID를 group으로 고정해 task별 QA를 함께 hold out하고, (a) annotation image 제거, (b) instruction paraphrase, (c) reasoning question permutation을 적용한다. task별 exact/semantic judge 결과와 cross-task error correlation을 함께 기록한다.
- **GO/KILL:** group-heldout에서도 세 task의 error profile이 분리되고 instruction/annotation ablation이 예상 방향으로 작동하면 diagnostic benchmark로 GO; image/template memorization으로 세 score가 함께 움직이면 aggregate leaderboard 용도는 KILL이다.

## 오늘의 진단 → 가설 → 최소 실험

- **관찰:** 세 artifact가 image와 code/template 또는 annotation image를 함께 제공한다.
- **가설:** random split의 높은 성능 일부는 시각 추론 자체보다 원본·편집·코드·template family 재사용에서 올 수 있다.
- **최소 실험:** file/pixel/perceptual hash와 normalized code hash로 lineage graph를 만들고, lineage-group split과 random split을 비교한다.
- **성공 판정:** lineage-group split에서도 task별 이득과 error taxonomy가 유지된다.
- **실패 판정:** random-to-group gap이 크면, 그 gap을 dataset defect로 단정하지 않고 “template/lineage sensitivity”로 보고한다.

## 오늘의 GO / KILL

- **GO:** V-Perception-40K를 synthetic geometry·point grounding probe로 사용하되 code/geometry-family heldout을 의무화한다.
- **GO:** VTBench를 세 failure bucket의 진단용으로만 사용하고 row-group split과 task별 결과를 함께 보고한다.
- **KILL:** data-specific license·final split·judge rule을 확인하기 전 V-Interaction-400K/VTBench 결과를 상업적 학습 또는 일반 VLM SOTA 근거로 사용하지 않는다.
