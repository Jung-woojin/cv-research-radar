## 1. GOOSELoc — 공간 중첩과 계절 차이를 나눠 보는 항공–지상 평가

**무엇이 바뀌었나 — 사실과 주장.** 11월 12일 제출된 새 benchmark다. 저자들은 9,356개 장면의 surround RGB·LiDAR·항공 정사영상을 제공하고, 비포장 지형에서 기존 방법이 저하된다고 보고한다. 이는 저자 측 결과이며 독립 검증은 아니다. [arXiv 제출 기록·초록](https://arxiv.org/abs/2611.16162)

논문 Appendix J는 full test 1,862개와 항공 타일 중첩을 보수적으로 제거한 buffered test 840개를 구분한다. Table A7의 north-up RGB+LiDAR 결과는 위치오차 27.1→26.2m, 방향오차 24.8→29.6도로 서로 다른 방향으로 움직인다. 이를 독립 실측이나 누수의 인과효과로 해석하지 않는다. [논문 Appendix J·Table A7](https://arxiv.org/html/2611.16162v1#S0.SS10)

**진단·기전 — 추론.** buffered subset은 공간 중첩뿐 아니라 장면 구성도 바꾼다. 따라서 단순 점수 차이는 암기, 지형 난도, 계절 구성 효과를 분리하지 못한다.

**가설.** 지형·계절·heading prior를 맞춘 비교가 전체 평균보다 domain shift와 공간 근접성의 영향을 잘 구분할 수 있다.

**최소 개입·실험 제안.** 먼저 학습 없이 split manifest의 좌표·타일 경계·계절·paved label을 감사한다. 이후 동일 checkpoint의 저장 예측을 full/buffered와 계절×지형별로 재채점한다. 위치·방향오차를 별도 기록하고, 장면 수와 지리적 block별 불확실성을 함께 보고한다.

**GO/KILL.** split과 metadata를 복구하고 동일 모델에서 slice 차이를 확인하면 GO. subset 구성 차이가 통제되지 않으면 “중첩 제거가 성능을 바꿨다”는 인과 주장은 KILL.

**비교 한계.** RGB와 RGB+LiDAR, front와 surround, north-up과 IMU prior는 **not strictly apples-to-apples**다. 프로젝트 페이지는 이번 도구에서 접근 오류가 발생했으므로 실제 데이터 다운로드, 코드·가중치 공개 상태, evaluator commit은 미확인이다. 논문의 공개 주장을 코드 재현 가능성으로 바꾸어 쓰지 않는다. [저자가 연결한 프로젝트](https://gooseloc.github.io/)

## 2. Roboflow Vision Evals — mAP@50 선두가 정밀 위치추정 선두는 아니다

**무엇이 바뀌었나 — 확인 사실.** 공식 11월 12일 평가 스냅샷에서 low-effort detection은 GPT-6.1 Terra 84.7 mAP@50, Gemini 4 Carbon 84.5다. 같은 행의 mAP@50:95는 각각 63.6과 68.5다. mAP@50 실행 범위는 중첩한다. 이는 현재 표의 관측이며 전일 대비 상승량은 아니다. [공식 detection 표](https://playground.roboflow.com/evals/object-detection)

현재 방법론은 effort별 3회 평균과 half-range를 사용하지만, 이전 단일 실행 결과가 남아 있고 OCR은 단일 preliminary run이다. 이 protocol의 도입 시점 자체는 확인하지 못했다. [공식 평가 방법론](https://playground.roboflow.com/evals)

**진단·기전 — 추론.** 느슨한 IoU의 작은 차이는 box precision의 우열을 대표하지 않는다. 반복 횟수와 task coverage가 다른 overall 평균도 detector 선택의 단일 근거가 되기 어렵다. half-range를 confidence interval로 해석해서는 안 된다.

**가설.** tiny-object에서는 같은 픽셀 좌표 오차가 더 큰 IoU 저하를 만들므로 mAP@50보다 엄격한 IoU와 크기별 분석에서 실패가 선명해질 수 있다.

**최소 개입·실험 제안.** 보유한 동일 이미지·저장 box를 사용해 AP50/AP75/AP50:95, 크기별 recall, 좌표 변환·JSON parse 실패율을 재계산한다. 모델 호출이 필요하면 prompt·이미지 전처리·effort·출력 token 상한을 고정하고 3회 반복한다. normalized coordinate의 반올림 전후도 분리한다. 공식 데이터의 size metadata 가용성은 미확인이므로 자체 검증셋에서 먼저 진행한다.

**GO/KILL.** strict-IoU 손실이 작은 box와 좌표 양자화에 집중되면 좌표 변환만 수정하는 최소 개입을 테스트한다. GT 크기·전처리가 다르거나 오차가 전 크기에 균등하면 tiny-object 기전 주장을 보류한다.

**비교 한계.** low/high effort 간 비교는 **not strictly apples-to-apples**다. 같은 low tier도 실제 FLOPs·토큰·지연을 동일하게 보장하지 않는다. backbone, pretraining, external data, 정확한 입력 해상도, TTA, dataset revision, evaluator commit은 이번 열람으로 고정하지 못했다. 공식 표와 방법론은 확인했으나 코드 수준 일치는 미확인이다.

## 3. VideoFDB V1.2 — 신규 결과보다 먼저 timing contract를 읽어야 한다

**무엇이 바뀌었나 — 사실.** 11월 11일 V1.2는 MAUI·Atmanity·Tavus 결과와 architecture/weights 필터를 추가하고 audio-only perception 및 human-reference 행을 제거했다. MAUI 시스템은 미공개 외부 controller를 포함하며, MAUI+Qwen timing은 생성 시간을 제외한 오프라인 시뮬레이션이라고 명시돼 있다. [공식 changelog·timing 주석](https://research.nvidia.com/labs/amri/projects/video-fdb/leaderboard.html)

데이터 카드는 dataset version을 1.0.0으로 표시하며 접근 승인이 필요한 비상업 연구용 평가 데이터임을 밝힌다. leaderboard V1.2를 dataset V1.2로 기록하면 안 된다. [공식 데이터 카드](https://huggingface.co/datasets/nvidia/video-full-duplex-benchmark)

**진단·기전 — 추론.** frame timing, controller, generation, transport 시간을 일부 제외하면 낮은 지연이 실제 실시간 응답의 개선으로 보일 수 있다. 표에서 human reference가 사라진 것도 인간과의 gap 축소를 뜻하지 않는다.

**가설.** semantic response score를 유지하면서도 timing 산정 경계에 따라 시스템 순위가 달라질 수 있다.

**최소 개입·실험 제안.** 데이터 접근이 승인되면 동일 event clip에 event onset, frame ingestion, generation start, first audible response를 기록한다. 모델·frame budget·prompt를 고정하고 controller on/off를 비교한다. end-to-end latency와 TOR-Alignment를 별도로 보고하며 simulation 결과는 별도 표에 둔다. 접근 승인 전에는 공개 metadata와 timing 정의 감사까지만 진행한다.

**GO/KILL.** paired 실행에서 semantic score를 보존하며 실제 응답 시점이 개선되면 GO. generation 시간을 제외해야만 이득이 보이거나 미공개 controller를 재현할 수 없으면 시스템 속도 우월성 주장은 KILL.

**비교 한계.** native full-duplex와 cascaded, 외부 controller 포함 여부, offline simulation과 online serving은 **not strictly apples-to-apples**다. 이 버전은 모델 결과·표시 갱신이며 새 metric·새 dataset split 도입으로 확인된 것은 아니다. 코드·가중치와 전체 표의 일치 여부는 독립 재현하지 않았다.

## 오늘의 benchmark signal 3개

1. **Split 독립성:** spatial buffering 이후 점수 변화는 장면 구성 변화와 함께 해석한다.
2. **Metric 해상도:** AP50 순위와 strict-IoU 성능을 분리하고 실행 범위를 통계적 유의성으로 바꾸지 않는다.
3. **Timing 경계:** controller·생성 시간을 포함한 실제 지연과 오프라인 timing을 구분한다.

## 내 연구에 바로 연결되는 포인트

- **small/tiny object·P2:** AP50의 작은 차이보다 크기별 strict-IoU와 좌표 양자화 진단을 먼저 한다. P2 추가의 이득은 그다음 동일 조건에서 검증한다.
- **aerial/UAV·remote sensing:** 인접 타일 중첩 감사와 계절×지형 slice를 실험 manifest에 추가한다. GOOSELoc 결과를 UAV detection 향상으로 직접 전이 해석하지 않는다.
- **video memory·CCTV·해상 안전 VQA:** 답변 정확도와 evidence 도착 시점·응답 시점을 분리한다. VideoFDB는 대화 평가이므로 안전 도메인의 성능 근거로 직접 쓰지 않는다.
- 오늘 가장 작은 시작점은 기존 detection 예측 재채점이다. 새 학습이나 대형 모델 다운로드 없이 metric·parser 병목을 확인할 수 있다.
