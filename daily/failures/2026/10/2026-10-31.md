## 1. Test-time augmentation이 단일-pass 비교를 무너뜨릴 위험 — TopoField

**실패 조건**

- **[사실]** TopoField는 ECCV 2026 SceneFun3D validation 30 scenes·561 ground-truth instances에서 AP 28.286%, AP50 41.383%, AP25 47.558%를 보고한다. [arXiv](https://arxiv.org/abs/2610.37218)
- **[사실]** 이 결과를 위해 semantic consensus field에 13회 test-time forward pass를 사용한다.
- **[저자 주장]** deterministic decoder와 class-aware ranking이 field-to-instance gap을 줄인다고 주장한다.

**진단 → 기제 → 가설**

- **[해석]** 13-pass consensus는 candidate construction을 안정화할 수 있지만, single-pass baseline과 같은 비용으로 읽히면 실제 online setting에서 latency/throughput 실패가 발생한다.
- 성능 상승이 decoder보다 multi-pass aggregation에서 주로 나왔을 가능성이 있다.

**후속 검증**

- 같은 backbone과 evaluator로 1/4/13-pass를 비교한다.
- AP/AP50/AP25, candidate existence, top-1 coverage, p50/p95 latency, GPU-hours를 한 표에 기록한다.
- 13-pass가 아닌 1-pass에서도 상대 순위가 유지될 때만 decoder 개선으로 해석한다.

**평가**

- 심각도: **4/5**
- 재현 신뢰도: **4/5** — 13-pass 조건은 저자 원문에 명시됐다.
- 연구 아이디어 가치: **5/5**
- 비교 상태: **not strictly apples-to-apples** (test-time budget 불일치).

## 2. Cross-dataset·소표본 이벤트 평가의 metric artifact 위험 — Soccer zero-shot spotting

**실패 조건**

- **[사실]** 저자 원문은 3개 수동 주석 경기, 130 events에서 best configuration F1@5s 72.0%를 보고한다. [arXiv](https://arxiv.org/abs/2610.37583)
- **[사실]** storyboard와 commentary transcript를 함께 쓰며 individual frames 대비 inference cost 72% 감소를 보고한다.
- **[저자 주장]** SoccerNet-trained CALF와 NetVLAD++를 cross-dataset 조건에서 능가한다고 주장한다.

**진단 → 기제 → 가설**

- **[해석]** 3경기 표본, event taxonomy, 수동 annotation policy, 5초 허용창, commentary 가용성은 모두 F1 순위를 바꿀 수 있다.
- Cross-dataset 비교에서는 “zero-shot이 더 좋다”가 아니라 annotation/protocol mismatch가 결과를 만든 것일 수 있다.

**후속 검증**

- 동일 3경기에서 individual frame과 storyboard를 같은 model·prompt·clip stride로 비교한다.
- 1초/3초/5초 tolerance별 F1과 event-class별 recall을 공개한다.
- SoccerNet standard split으로 옮긴 재평가가 나오기 전까지는 exploratory result로만 취급한다.

**평가**

- 심각도: **4/5**
- 재현 신뢰도: **3/5** — 비교 설정은 확인됐으나 독립 재현은 확인하지 못했다.
- 연구 아이디어 가치: **4/5**
- 비교 상태: **not strictly apples-to-apples** (cross-dataset 및 annotation protocol 불일치).

## 3. Real-time 주장의 deployment 조건 미확인 위험 — FastBEVFusion

**실패 조건**

- **[사실]** 저자 원문은 nuScenes에서 deployment libraries 없이 50 FPS 초과를 달성하고 calibration error에 강건하다고 기술한다. [arXiv](https://arxiv.org/abs/2610.37153)
- **[사실]** 공개 초록에서는 mAP/NDS, GPU·CPU, batch size, input resolution, sensor configuration, preprocessing/postprocessing 범위를 확인할 수 없다.
- **[저자 주장]** 기존 real-time systems를 능가한다고 주장한다.

**진단 → 기제 → 가설**

- **[해석]** FPS만으로는 정확도·latency·VRAM의 동시 달성을 판단할 수 없다. input 또는 pipeline 범위가 다르면 현장 deployment에서 target FPS 또는 detection quality가 무너질 수 있다.
- depth estimation을 생략한 설계가 latency를 줄이는 대신 calibration perturbation·small object 조건에서 trade-off를 낼 수 있다.

**후속 검증**

- nuScenes validation에서 batch 1, 동일 GPU, 동일 input, 동일 postprocessing을 고정한다.
- mAP/NDS, p50/p95 end-to-end latency, FPS, VRAM과 calibration perturbation 크기별 정확도를 함께 측정한다.
- 50 FPS를 만족하면서 baseline보다 mAP/NDS가 유지되는지를 GO 기준으로 둔다.

**평가**

- 심각도: **3/5**
- 재현 신뢰도: **2/5** — 공개 초록의 세부 조건이 부족하고 독립 재현은 없다.
- 연구 아이디어 가치: **4/5**
- 비교 상태: **not strictly apples-to-apples** (hardware/pipeline/accuracy 조건 미확인).

## 보조 신호: 자원 지표 혼용 위험 — Honeycomb-Surfels

- **[사실]** 저자 프로젝트 페이지는 memory-matched Mip-NeRF 360 조건에서 Hexels 24.82 dB/0.90 GiB, Nexels 22.49 dB/7.15 GiB, Triangle Splatting 22.36 dB/1.12 GiB를 제시한다. [project page](https://honeycomb-surfels.github.io/)
- **[사실]** 저자 원문은 34 scenes에서 memory-matched 2DGS 대비 PSNR 4.53–7.38 dB, 15 DTU scans에서 error 28.9% 감소를 보고한다. [arXiv](https://arxiv.org/abs/2610.37668)
- **[해석]** model memory·training VRAM·inference FPS는 서로 대체 가능한 한 숫자가 아니다. memory-matched 성과를 unrestricted quality 또는 online latency 개선으로 확대 해석하는 것이 위험하다.
- 최소 실험: 동일 memory / 동일 primitive count / 동일 training-time 세 축을 분리하고 PSNR·LPIPS·train VRAM·inference FPS를 각각 보고한다.

## 오늘의 실패 패턴 3개

1. **Test-time budget 은폐**: multi-pass gain을 single-pass 성능으로 읽는 오류.
2. **평가 protocol 이동**: cross-dataset·소표본·허용 시간 차이를 모델 우위로 읽는 오류.
3. **자원 지표 혼용**: training VRAM 또는 FPS 하나만으로 deployment 효율을 판단하는 오류.

## 논문 아이디어로 연결 가능한 빈틈

“조건-인식 benchmark card”를 만들 수 있다. 결과마다 dataset/split, annotation policy, input, hardware, TTA pass, preprocessing/postprocessing, train/inference memory를 구조화하고, 점수 대신 **동일 조건 하에서만 비교 가능한 Pareto frontier**를 자동 생성한다. 핵심 기여는 새 모델이 아니라 score claim의 반례를 빠르게 찾는 evaluator다.
