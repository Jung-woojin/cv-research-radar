## 1. 타일 추론 — baseline 선택에 따라 강건성 결론이 바뀐다

**확인 사실.** 문서만 바꾼 merge `34a977737907906b79ec0d563f0c623206e50838`에 새 비교표가 추가됐다. 런타임 개선 PR이 아니다. [공식 diff](https://github.com/ultralytics/ultralytics/pull/27303/files)

**작성자 보고·shift cell.** Ultralytics 8.4.216, PyTorch FP32, RTX PRO 6000 Blackwell Server Edition 1장이다. COCO-pretrained YOLO26을 fine-tuning 없이 VisDrone val 548장·공통 6개 class로 평가했다. `tile=640`은 `imgsz=640`보다 mAP50–95가 높지만 `imgsz=1920`보다 **5/5 모델 집계 cell에서 낮다**. 예를 들어 s는 23.7→21.7, x는 30.8→29.1이다. `tile=320`은 `tile=640`보다 recall이 5/5 모델에서 높지만 mAP는 **4/5에서 낮다**. 객체별 악화 cell 총수·통계적 유의성은 미확인이다. [PR 측정 조건·표](https://github.com/ultralytics/ultralytics/pull/27303)

반면 1024 crop으로 학습한 OBB 모델의 DOTAv1 원본 val 458장에서는 `tile=1024`가 `imgsz=4096`보다 mAP가 **5/5 모델에서 높다**. 두 dataset은 task·weights·학습 crop·class mapping이 달라 **not strictly apples-to-apples**다. 도메인만의 인과효과로 해석하지 않는다. ECE·Brier·selective coverage는 제공되지 않았다.

**평가자 진단 → 가설.** 확대에 따른 detail 회복과 crop에 따른 context 손실·중복 오탐이 경쟁할 수 있다. recall 상승이 mAP 상승을 보장하지 않는다는 관측은 이 가설과 양립하지만 mechanism을 확정하지 않는다.

**최소 intervention·실험 제안.** 같은 checkpoint·원본 split·class mapping·evaluator에서 whole-image 해상도 sweep과 tile-size sweep만 비교한다. overlap·confidence·IoU·max_det를 고정하고 작은/큰 객체, seam/non-seam, crowding별 AP·recall·FP와 ECE·risk–coverage를 기록한다. 학습 crop 효과는 별도 통제 실험으로 분리한다.

**GO/KILL.** 작은 객체 recall뿐 아니라 worst-cell AP·FP와 latency 예산이 통과하면 타일을 GO한다. 낮은 해상도 baseline만 이겼다는 이유로 일괄 적용하면 KILL이다. 원문의 DOTAv1 latency는 39장 평균, VisDrone은 19장 median이며 이미 decode된 입력 기준이다. 서로 다른 요약량을 통합 속도 순위로 만들지 않는다.

## 2. Axelera — head와 decoder 계약부터 검사한다

**확인 사실.** merge `c747ded440c5bf8d7a4da40f33f084976c60da9e`는 지원하지 않는 `nms=True`를 head 선택 전에 정규화하고 YOLO26 Axelera의 one-to-one head를 유지한다. [코드 diff](https://github.com/ultralytics/ultralytics/pull/27304/files)

**작성자 보고·failure cell.** x86 Linux, axelera-devkit/rt 1.9.0, YOLO26n, imgsz640에서 기존 `nms=True` 출력은 `(1,84,8400)`이고 YAML/AXM의 end2end 값은 false/true로 불일치했다. 수정 후 `(1,300,6)`, true/true가 된다. coco128 mAP50–95는 0.171→0.471, precision은 0.213→0.640이며 default export 수치와 맞는다. **보고된 detection 정확도 비교 두 행의 악화는 0/2**지만 seg·pose·OBB·자연 shift의 정확도 cell 총수는 미확인이다. [공식 재현 표·제약](https://github.com/ultralytics/ultralytics/pull/27304)

**검증 범위.** 실제 backend/runtime을 사용했지만 AIPU 호출은 FP32 head 출력으로 emulation했다. Metis 실기 검증이 아니다. ECE·selective coverage·기상/카메라별 AP는 미보고다. 실기 정밀도·latency와 비교하면 **not strictly apples-to-apples**다.

**평가자 진단 → 가설 → 최소 intervention.** 배포 후 domain-shift처럼 보이는 저하의 일부는 출력 의미와 decoder 불일치일 수 있다. 새 adaptation 전에 export 옵션×task별 tensor shape·metadata·decoder를 assert하고 동일 입력 canary를 통과시킨다.

**최소 실험·GO/KILL.** 동일 weights·입력·threshold에서 default/True/False export와 native 출력을 비교한 뒤 실제 Metis에서 task별 AP·FP·ECE를 확인한다. 계약 일치와 untouched 배포 cell의 비열화를 확인하면 GO다. emulation 수치만으로 실기 강건성 회복을 선언하면 KILL이다.

## 3. Embedding index — representation 진단 전에 feature의 정체를 확인한다

**확인 사실.** merge `8f8488189d94ce6a8170cb36495697e00eb86aa8`는 네 predict loop에서 음수 index를 Python layer indexing으로 해석하고 범위 밖 index를 오류로 처리한다. 기존에는 layer index가 음수가 아니어서 요청이 매칭되지 않았다. [공식 diff](https://github.com/ultralytics/ultralytics/pull/27316/files)

**작성자 보고·cell·metric.** CPU·imgsz320·공개 API에서 detection의 `embed=[-2]`는 기존 raw head `(1,84,1680)` 대신 256차원 embedding을 반환한다. classifier는 합이 1인 1000-class probability 대신 256차원 embedding이 된다. detection의 양수 `[22]`와 음수 `[-2]`가 일치하며, RT-DETR·World·YOLOE에서도 해당 양수 index와 일치한다고 보고한다. **OOD AUROC·task AP의 baseline 대비 악화 cell 수는 미확인**이다. shape/type 및 index 동등성 검증을 강건성 성능으로 바꾸어 쓰지 않는다. [PR 재현표](https://github.com/ultralytics/ultralytics/pull/27316)

**진단·남은 한계.** 이것이 OOD 진단을 오염시킬 수 있다는 것은 평가자 추론이다. 이 PR은 실제 OOD 실험을 제시하지 않는다. `[-1]`처럼 head를 직접 고르면 기존 양수 head index와 같은 AttributeError가 남으며, 모든 layer를 embedding으로 지원하는 수정이 아니다. ECE·coverage도 미보고다.

**가설 → 최소 intervention·실험.** readout 병목처럼 보인 현상이 잘못 추출한 feature 때문인지 먼저 배제한다. layer ID·shape·dtype·정규화·checkpoint hash를 manifest에 남기고 `[-2]`/동등 양수 index/`model.embed()`를 비교한다. 다음으로 동일 ID/OOD split에서 수정 전 출력과 올바른 feature의 frozen linear probe·kNN·OOD AUROC 및 risk–coverage를 비교한다. 두 출력의 차원·의미가 다르므로 기존 OOD 결과와의 비교는 **not strictly apples-to-apples**로 표시한다.

**GO/KILL.** index 동등성·feature provenance가 통과하면 probe를 GO한다. 이 audit 전에 encoder 정보 손실이나 adaptation 효과를 주장하면 KILL이다.
