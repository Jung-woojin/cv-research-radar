## 1. SAM mask 제거가 polygon의 class까지 뒤섞음

**확인 사실:** `yolo_bbox2segment()` 수정은 `534f8d107636dfa7109229321e764d95c88c47fc`로 병합됐다. diff는 남은 mask와 함께 `res.boxes.cls`의 prompt index로 원래 label class를 선택한다. Maintainer glenn-jocher는 실제 MobileSAM 추론으로 원본의 class 혼동과 수정 후 회복을 확인했다고 댓글에 기록했다. [공식 PR·재현·검토](https://github.com/ultralytics/ultralytics/pull/27193) · [diff](https://github.com/ultralytics/ultralytics/pull/27193/files)

- **실패 조건·구성:** `mobile_sam.pt`, CPU, `bus.jpg`, 먼저 낮은 confidence의 얇은 box(class 0), 뒤에 person box(class 1)를 입력한다. SAM의 confidence 필터로 앞 mask만 사라지면 발생한다.
- **원문 재현:** 남은 person polygon의 출력 class가 원본에서는 0, 수정 후에는 1이다. 전체 데이터셋의 오표기율이나 AP 영향은 측정되지 않았다.
- **공식 인정·community 수준:** contributor 제안에 maintainer의 별도 실재현과 병합이 있다. 외부 독립 community 재현은 확인하지 않았고, 이번 watch도 실행하지 않았다.
- **진단 → 메커니즘:** mask 목록은 필터링됐지만 converter는 class 목록을 원래 위치 순서로 소비했다. mask geometry가 타당해도 class 대응이 무너지는 annotation 오류다.
- **가설 → 최소 개입:** 살아남은 prompt index로 class를 같이 선택하면 재학습 없이 label 무결성을 회복할 수 있다.
- **최소 실험:** parent와 병합 commit에서 동일 이미지·box·checkpoint·confidence를 고정한다. 두 box의 입력 순서를 바꾸고, 앞/뒤/전체 mask 제거 및 제거 없음 조건을 비교한다. 출력 polygon마다 원 prompt ID와 class를 대조하며, 전체 제거 시 빈 label 파일도 검사한다.

## 2. RT-DETR class weight 로그와 실제 loss 적용의 불일치

**확인 사실:** #27210은 `8cec1d10b8c2b6f9767914d4bae7105235887d4d`로 병합됐다. `RTDETRTrainer`에 `get_class_counts = BaseTrainer.get_class_counts`를 지정해 사용하지 않는 weight 계산·출력을 건너뛴다. loss에 class weighting을 새로 구현한 수정은 아니다. Maintainer는 원본에서 weight 로그가 나오고 수정 전후 loss가 같음을 재현했다고 명시했다. [공식 PR·검토](https://github.com/ultralytics/ultralytics/pull/27210) · [diff](https://github.com/ultralytics/ultralytics/pull/27210/files)

- **실패 조건·구성:** `RTDETR("rtdetr-l.yaml")`, `coco8.yaml`, CPU, `epochs=1`, `imgsz=160`, `cls_pw=0.5`. 상속된 trainer가 weight를 계산하지만 `RTDETRDetectionLoss`는 이를 읽지 않는다.
- **원문 재현:** 수정 전에는 weight 배열이 출력되고 수정 후에는 사라진다. 동일 loss가 보고됐지만 정확도 개선이나 class imbalance 완화는 입증되지 않았다.
- **공식 인정·community 수준:** maintainer가 PR 설명에 재현을 보완하고 병합했다. 외부 독립 재현은 확인하지 않았다.
- **진단 → 메커니즘:** 공통 trainer의 설정·로그가 task 전용 loss의 실제 기능과 일치하지 않았다. “설정이 받아들여지고 출력됨”이 “gradient에 반영됨”을 보장하지 않는다.
- **가설 → 최소 개입:** 설정 적용 여부를 loss·gradient에서 확인하는 검사를 넣으면 불균형 대응 실험의 무효 ablation을 사전에 찾을 수 있다.
- **최소 실험:** 같은 초기 weight·batch·seed로 `cls_pw=0`과 양수의 단일 forward/backward를 비교한다. loss 각 항과 분류 관련 parameter gradient, model의 class-weight 저장 상태를 기록한다. parent/병합 commit에서 반복하고, class weighting을 실제 지원하는 detector는 검사 양성 대조군으로 둔다.
- **GO/KILL:** RT-DETR에서 설정 변화가 loss·gradient를 바꾸지 않는지 먼저 확인한다. 바뀐다면 해당 revision·별도 소비 경로를 조사하며 “항상 무효” 가설을 KILL한다. 수정 후 로그만 사라졌다면 기능 추가로 보고하지 않는다.
- **기존 주장과 충돌:** class weighting 자체의 부정 결과가 아니다. tiny-object/class imbalance 연구에서 설정을 켰다는 기록만으로 유효한 baseline을 주장하기 어렵다. 서로 다른 loss·architecture의 AP 비교는 `not strictly apples-to-apples`다.
- **점수:** 심각도 **3/5** · 재현 신뢰도 **4/5** · 연구 아이디어 가치 **4/5**.

## 3. PIL·tensor 입력의 RGB/BGR 불일치가 결과 이미지를 바꿈

**확인 사실:** #27196은 `23023be7e7a5abcfae0f4ef06ed66115f3ed8eb5`로 병합됐다. PIL 입력을 Annotator의 BGR buffer로 변환하고, SAM3 semantic·video semantic의 기존 tensor 후처리 분기에서 channel 순서를 뒤집는다. Maintainer는 두 경로를 각각 재현했다고 확인했다. [공식 PR·검토](https://github.com/ultralytics/ultralytics/pull/27196) · [diff](https://github.com/ultralytics/ultralytics/pull/27196/files)

- **실패 조건·구성:** 첫 경로는 그리기 작업도 하지 않은 빨간 PIL RGB 이미지의 `result(pil=True)`·저장 출력이다. 둘째는 `bus.jpg`를 RGB tensor로 준 SAM3 semantic postprocess의 `Results.orig_img`다.
- **원문 재현:** 빨간 pixel `(255,0,0)`이 원본에서는 파란 `(0,0,255)`으로 출력되고 수정 후 보존된다. SAM3의 원 이미지 불일치도 maintainer가 확인했다. 이 보고서는 모델 mask·AP가 나빠졌다는 증거를 확보하지 않았다.
- **공식 인정·community 수준:** contributor와 maintainer의 재현 및 병합이 있다. 일반 tensor video 입력 지원을 추가한 수정은 아니며, NumPy/list 경로까지 오류 범위를 넓히지 않는다.
- **진단 → 메커니즘:** RGB 데이터가 BGR을 기대하는 저장·표시 경계로 들어갔다. predictor 내부 결과 표현과 외부 이미지의 의미 계약이 달랐다.
- **가설 → 최소 개입:** 모델을 바꾸기 전에 입력 형식별 canonical BGR round-trip을 검사하면 시각적 domain shift로 오인할 결과 왜곡을 분리할 수 있다.
- **최소 실험:** red/blue 비대칭 color chart를 PIL·BGR NumPy·RGB tensor로 표현한다. parent/병합 commit에서 Annotator 저장·PIL 반환·BGR 반환과 SAM3 `orig_img`를 비교한다. 저장 파일을 같은 decoder로 읽어 pixel parity를 검사하고, 실제 mask 변화 여부는 별도 고정 prediction으로 비교한다.
- **GO/KILL:** 입력 형식에 따른 색상 차이만 단일 변환으로 사라지면 GO. 결과 이미지가 회복돼도 mask가 동일하면 “segmentation 정확도 개선” 주장은 KILL한다.
- **기존 주장과 충돌:** SAM3의 색상 이해 실패나 해상도 효과를 입증하지 않는다. dtype·channel order·decode 조건이 다른 비교는 `not strictly apples-to-apples`다.
- **점수:** 심각도 **3/5** · 재현 신뢰도 **4/5** · 연구 아이디어 가치 **3/5**.

## 오늘의 실패 패턴 3개

1. **필터 이후 식별자 손실:** geometry·class·prompt index를 함께 전달하지 않으면 타당한 mask에 잘못된 class가 붙는다.
2. **설정의 수용과 실제 효과의 분리:** 로그보다 loss·gradient에서 intervention의 적용 여부를 확인해야 한다.
3. **모델 출력과 결과 표현의 분리:** 저장·표시 오류를 encoder나 domain robustness의 실패로 확대하면 진단이 어긋난다.

## 논문 아이디어로 연결 가능한 빈틈

**추론:** aerial/UAV·maritime의 가늘고 작은 객체를 pseudo-label로 확장할 때, mask confidence에 따른 누락과 class 전이를 따로 측정하는 감사가 유용할 수 있다. prompt 순서를 바꾸어도 같은 객체의 class가 유지되는지 보는 검사는 학습 없이 시작할 수 있다. 이후 같은 checkpoint·split·입력 크기·threshold로 원본/수정 label만 바꿔 per-class confusion과 small-object AP를 비교한다.

또 다른 빈틈은 class imbalance intervention의 “실제 적용” 검증이다. 단일 batch의 gradient 변화와 전체 데이터의 효과를 분리하면 무효 설정과 효과 없는 학습 기법을 구별할 수 있다. 다만 알려진 버그 세 개의 재정리는 논문 신규성이 부족하다. 여러 converter·trainer에서 같은 유형이 반복되는지와 진단의 일반성을 보여야 한다.

## 직접 재현해볼 최소 실험

우선 CPU에서 MobileSAM 두 box의 순서·confidence 제거 조건을 바꾸어 prompt–polygon–class 대응을 확인한다. 그 다음 RT-DETR 단일 batch의 loss·gradient 적용 검사, PIL color chart의 pixel parity를 진행한다. 신규 학습 없이 진단을 시작할 수 있으며 실제 실행시간·VRAM은 이번 watch에서 측정하지 않았다. RTX 5060 Ti 8GB에서 SAM3 전체 실행이 가능하다고 보장하지 않는다.

**공통 GO:** 원본에서 조건부 실패가 재현되고 단일 개입 후 사라지며 대조군이 유지된다. **공통 KILL/축소:** 재현되지 않으면 revision·호출 경로·입력 표현을 먼저 확인하고 모델 능력 실패라는 해석을 중단한다.

모든 /5 점수는 조사자의 우선순위 판단이며 실측 성능·발생 확률이 아니다.
