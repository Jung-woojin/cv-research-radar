## 1. MPS의 ONNX 정적 export: semantic crash 및 CPU 결과 drift

**확인된 사실.** Ultralytics PR #27117은 2026-11-09에 main으로 병합됐다. PR 설명은 device="mps"에서 ONNX Runtime CoreML provider가 기본 NeuralNetwork 형식으로 정적 graph를 컴파일하면서 semantic task가 imgsz >= 128에서 오류를 내고, 다른 task도 CPU 결과와 달라질 수 있었다고 적는다. 작성자가 제시한 동일 ONNX 파일 비교에서는 semantic이 main에서 오류였고, 수정 후 pixel difference 0으로 보고됐다. dynamic export는 기존처럼 CPU provider를 쓰므로 이 변경의 대상이 아니다. [공식 병합 PR](https://github.com/ultralytics/ultralytics/pull/27117)

- 실패 조건: 정적 ONNX export + Apple MPS/CoreML provider; semantic은 imgsz >= 128 사례가 명시됨.
- 모델·구성: YOLO26n ONNX, ORT 1.31.1, Apple M5 Pro/macOS 26.6의 PR 작성자 환경. onnxruntime 1.19.2는 새 flag에서 abort하므로 수정은 1.20.0 이상에만 적용한다.
- 공식 인정: **있음** — maintainer가 병합했다.
- 재현 근거: **PR 작성자 보고**이며 이 watch에서 독립 실행하지 않았다.
- 진단: provider format 선택이 semantic execution과 CPU/MPS parity를 동시에 흔든다.
- 가설: 정적 export artifact라도 provider 선택이 달라지면 정확도·실행 가능성은 동등하지 않다.
- 최소 실험: 같은 .onnx와 이미지 20장을 CPU/MPS에서 실행해 오류율, detection box/score 차이, semantic pixel disagreement를 비교한다. ORT 1.19.x와 1.20+를 분리한다.
- GO/KILL: 수정 후 semantic error가 0이고 task별 출력 차이가 사전 허용오차 안이면 GO; dynamic export나 구버전 ORT에서 문제가 재현되지 않으면 이 원인을 일반화하지 않는다.
- 점수: 심각도 **4/5**, 재현 신뢰도 **4/5**, 연구 아이디어 가치 **3/5**.

## 2. Grounding DINO v5 phrase delimiter position-id 오류

**확인된 사실.** Transformers issue #50465는 transformers 5.18.0과 main의 Grounding DINO에서 phrase를 닫는 . 또는 ?가 position id 0을 받는다고 보고했다. issue의 CPU 재현은 "a cat."에서 v5.x position ids를 [0, 0, 1, 0, 0], v4 loop의 기대값을 [0, 0, 1, 2, 0]으로 제시한다. 보고자는 dtype fix와 delimiter fix를 함께 적용하고 PIL image processor를 쓸 때 object-detection test tolerance를 통과했다고 적었으며, 이슈는 현재 open이다. [공식 issue](https://github.com/huggingface/transformers/issues/50465)

- 실패 조건: transformers v5.x Grounding DINO, special token으로 끝나는 phrase를 포함한 text prompt.
- 모델·구성: IDEA-Research/grounding-dino-tiny, transformers 5.18.0, torch 2.14.1, Python 3.12.13/macOS arm64의 보고자 환경.
- 공식 인정: **부분적** — 공식 저장소의 bug issue이나 maintainer merge/릴리스는 아직 확인하지 못했다.
- community reproduction 여부: **있음** — issue 작성자의 재현이며 독립 재현은 미실시.
- 의심 원인: vectorized mask 함수가 현재 special token을 이전 delimiter로 포함해 -1을 clamp한 것으로 보고됐다.
- 기존 주장과 충돌: 동일 weight/prompt라도 v4·v5 preprocessing 경로는 not strictly apples-to-apples다. 위치 embedding과 text sine embedding이 달라지므로 grounding 결과를 단순 model regression으로 해석하면 안 된다.
- 최소 실험: phrase 수 1/3/8의 prompt set에서 v4 reference, v5 current, delimiter patch를 비교해 box AP, text-memory max abs diff, phrase별 false negative를 기록한다.
- GO/KILL: patch가 multi-phrase에서 reference parity와 AP를 함께 회복하면 GO; text-memory 차이가 줄어도 AP가 안정적으로 변하지 않으면 preprocessing sensitivity 결과로 제한한다.
- 점수: 심각도 **4/5**, 재현 신뢰도 **3/5**, 연구 아이디어 가치 **5/5**.

## 3. FSDP2와 GradientCheckpointingLayer hook 순서

**확인된 사실.** Transformers PR #50490은 issue #50424를 수정 대상으로 명시하며, GradientCheckpointingLayer가 module의 __call__ 전체를 checkpoint해 FSDP2 hook도 checkpoint 내부에 넣는다고 설명한다. PR의 변경안은 FSDP pre/post hook의 바깥에 checkpoint(forward)만 두는 순서다. 11월 9일 review-ready가 되었지만, 현재 open 상태다. [공식 fix PR](https://github.com/huggingface/transformers/pull/50490)

- 실패 조건: FSDP2와 reentrant gradient checkpointing을 함께 쓰고, 한 backward에 같은 layer forward가 여러 번 들어가는 학습 경로.
- 모델·구성: 특정 vision model·GPU·seed는 PR 본문에서 확정하지 못했다.
- 공식 인정: **부분적** — 공식 프로젝트의 열린 fix PR이며 merge/릴리스 전이다.
- 재현 근거: issue/PR 작성자 설명; 이번 watch의 독립 학습 재현은 없다.
- 진단: activation checkpointing boundary가 distributed parameter-sharding hook의 의도된 순서를 바꾼다.
- 가설: 실제 loss가 내려가도 일부 forward의 gradient가 빠지면 multi-image/VLM fine-tuning의 학습 동역학이 조용히 왜곡될 수 있다.
- 최소 실험: 작은 vision-language encoder에서 FSDP2 on/off × reentrant/non-reentrant × patch on/off를 3 seeds로 비교하고 parameter-gradient sum, loss trajectory, validation grounding score를 기록한다.
- GO/KILL: reference 대비 gradient-sum 차이와 validation gap이 patch로 사라지면 GO; 단일-forward 또는 non-reentrant에서 차이가 없으면 적용 범위를 그 조합으로 한정한다.
- 점수: 심각도 **5/5**, 재현 신뢰도 **3/5**, 연구 아이디어 가치 **4/5**.

## 오늘의 실패 패턴 3개

1. export artifact가 같아도 execution provider가 달라지면 crash와 semantic drift가 동시에 나타날 수 있다.
2. VLM/grounding의 text-side preprocessing 한 token 차이가 region prediction까지 전파될 수 있다.
3. distributed-training wrapper의 hook 경계는 loss 로그에 드러나지 않는 gradient loss를 만들 수 있다.

## 논문 아이디어로 연결 가능한 빈틈

“Answer–Region Gap”을 모델 capacity 문제가 아니라 **prompt tokenization·position encoding·image preprocessing 경로의 version drift**로 분해하는 연구가 가능하다. 동일 checkpoint에서 text position, image resize, runtime provider를 교차 통제하고 phrase complexity별 region stability를 측정하는 것이 핵심이다.
