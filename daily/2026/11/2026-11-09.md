## 2) CV / DL-CV 핵심

### Ultralytics 8.4.208 — NMS 기본값과 TensorRT 경로 변경

- **구분:** 최근 며칠 사이 공식 릴리스(2026-11-08). [릴리스](https://github.com/ultralytics/ultralytics/releases)
- **사실:** `predict`와 tracking의 기본 NMS IoU threshold가 0.7에서 0.5로 변경됐고, validation 기본값은 0.7로 유지된다. visual-prompt confidence 기본값 0.05, multi-GPU gradient accumulation의 불필요한 동기화 회피도 포함된다.
- **저자 주장:** TensorRT 11의 FP16 NMS-free export가 최대 3% 더 빠르다.
- **진단:** inference/tracking과 validation의 기본값이 다르므로 릴리스 전후의 mAP·IDF1·count 결과를 그대로 비교하면 설정 차이가 모델 차이로 오인될 수 있다.
- **최소 실험:** 동일 checkpoint·입력 해상도·tracker에서 IoU 0.5/0.7만 바꿔 AP, ID switches, small-object recall, line-count error를 기록한다. TensorRT 비교는 GPU, TensorRT, batch, input shape, warm-up과 percentile latency를 고정한다.
- **공개/재현성·한계:** 코드와 release note는 공개됐으나 속도 주장의 전체 측정 조건과 variance는 릴리스 노트만으로 확인되지 않는다. 새 학습법/논문이 아니라 운영 기본값 변화다.

### Supervision 0.31.5 — 가림을 통과하는 LineZone 및 exact OBB clipper

- **구분:** 최근 공식 릴리스(2026-11-05). [릴리스](https://github.com/roboflow/supervision/releases)
- **사실:** LineZone은 객체가 선을 지나는 동안 tracker가 잠시 사라져도 상태를 보존하도록 바뀌었으며 `max_absent_frames`가 제공된다. OpenCV 설치 환경에서 oriented-box IoU, NMS, metric은 exact clipper 경로를 사용한다.
- **진단/최소 실험:** 0.31.4/0.31.5를 고정한 두 환경에서 가림 길이를 단계적으로 만든 clip과 실제 혼잡 장면에 대해 count error·OBB mAP/IoU 차이를 비교한다.
- **주의:** 결과 변화는 detector 개선이 아니라 evaluation/후처리 변경일 수 있다. 버전, OpenCV 유무, tracker, absent-frame 값을 보고서에 함께 적어야 한다.

## 3) VLM / Multimodal / Video 핵심

### V-Thinker — Interaction/Perception preview와 VTBench

- **구분:** 최근 공식 저장소 공지(2026-11-07). [프로젝트 저장소](https://github.com/We-Math/V-Thinker) · [VTBench 데이터셋](https://huggingface.co/datasets/We-Math/VTBench)
- **사실:** 저장소는 V-Interaction-400K의 252K-sample preview, V-Perception-40K의 37K-sample preview, 그리고 Perception·Instruction-Guided Interaction·Interactive Reasoning 세 유형의 VTBench를 공지한다. VTBench는 1,500 QA pair로 설명된다.
- **저자 주장:** 저장소 표는 VThinker와 기준 모델들의 세 유형 점수를 제시한다. 이는 작성자 제공 결과이며 독립 재현은 확인하지 못했다.
- **진단:** 단일 정답률로 묶었던 VLM 능력을 “지각 오류”, “지시를 따른 상호작용 오류”, “시간을 누적한 추론 오류”로 분해할 수 있는 출발점이다.
- **최소 실험:** 공개 preview에서 동일 vision encoder를 고정하고 지각·상호작용·시간적 추론 세 bucket별 정확도와 오류 전이를 측정한다. video frame 순서를 섞거나 관측 frame을 제거해 temporal evidence 의존성을 확인한다.
- **공개/재현성·한계:** 코드/데이터 링크는 있으나 저장소가 코드 발전 중임을 명시한다. preview가 실험 데이터/최종 split과 동일한지는 이 시점의 공개 정보만으로 단정할 수 없다.
- **사용자 연결:** grounding·video VLM·persistent identity에서 평균 점수보다 task bucket별 failure matrix를 만드는 데 직접 쓸 수 있다.

## 6) 오늘의 중요한 Finding 3개

1. **기본값은 benchmark protocol이다.** NMS threshold나 tracker 상태 보존 규칙은 구현 세부사항이 아니라 결과를 바꾸는 실험 조건이다.
2. **시간적 VLM은 score보다 실패 원인 분해가 먼저다.** perception·interaction·reasoning bucket을 분리하면 더 많은 frame이 필요한지, 지시 grounding이 약한지, readout이 약한지 검사할 수 있다.
3. **도구 체인은 모델의 일부다.** 분산 runtime, geometry library, template sandbox, agent 입력 권한은 실험 결과와 재현성의 경계 조건이다.

## 7) 과대평가 가능성 / 주의할 연구·릴리스

- V-Thinker 표의 수치는 **저자 주장**이다. preview 데이터, 평가 protocol, seed variance, cross-domain 결과를 독립적으로 확인하기 전에는 일반화/SOTA 결론을 내리지 않는다.
- Ultralytics의 “최대 3%” 속도는 **저자 릴리스 노트의 조건부 성능 주장**이다. 평균 latency, hardware, input/batch, precision, warm-up이 없는 상태에서는 다른 runtime이나 edge device에 전이할 수 없다.
- Supervision의 LineZone/OBB 변경 후 수치 상승은 모델 향상으로 해석하지 말고 package/OpenCV/parameter 차이를 우선 배제한다.

## 9) Top 1 미니 리뷰 — V-Thinker / VTBench

**왜 중요한가:** 영상 VLM의 실패를 단순 “temporal reasoning 부족”으로 부르는 대신, 지각·지시 기반 상호작용·누적 추론으로 분리해 관찰할 수 있게 한다.

**기존 blind spot:** 전체 평균 정확도는 object를 놓친 오류, 지시를 잘못 적용한 오류, 여러 시점 증거를 합치지 못한 오류를 같은 숫자로 만든다.

**핵심 실험 논리:** 동일 모델에 대해 세 bucket의 결과와 frame ablation을 함께 보면, 더 긴 context가 실제로 필요한지, 지각 encoder/grounding/readout 중 어디가 병목인지 가설을 세울 수 있다.

**진짜 기여로 판정될 조건:** 공개 split·judge·frame sampling을 고정하고 각 bucket에서 baseline 대비 개선과 error taxonomy가 재현되어야 한다.

**과장될 수 있는 부분:** preview 데이터 및 저자 제공 표만으로 데이터 구성의 독립성, prompt sensitivity, seed variance, 다른 video domain 일반화는 판단할 수 없다.

**바로 가져올 실험:** VTBench류 세 bucket을 UAV/해양 영상의 작은 객체 지속 추적 문제에 맞춰 재구성하고, frame dropping·object occlusion·instruction paraphrase를 교차시켜 failure matrix를 만든다.

## 10) 후속 연구 씨앗

### A. NMS default drift가 작은 객체와 tracking에 미치는 영향
- **질문/가설:** IoU 0.5/0.7 차이가 작은 객체 AP와 ID switch를 서로 다른 방향으로 바꾼다.
- **최소 실험:** 동일 checkpoint와 tracker에서 threshold만 sweep하고 COCO small-object slice와 사용자 video slice에 AP, IDF1, count error를 기록한다.
- **판정:** 모든 tracker/scene에서 일관된 무차이가면 이 가설은 기각하며, 그 자체가 configuration robustness 결과다.

### B. Video VLM의 temporal failure matrix
- **질문/가설:** temporal reasoning 오류는 관측 frame 부족인가, 지시 grounding 실패인가? frame 추가의 이득은 reasoning bucket에서 더 크고, frame shuffle은 reasoning을 더 크게 손상시킨다.
- **최소 실험:** VTBench 공개 preview 또는 허가된 동등 video QA에서 full/half/shuffled frame 조건을 만들고 bucket별 정확도와 오류 유형을 비교한다.
- **판정:** shuffle 영향이 bucket별로 분리되지 않으면 temporal cue 의존성 가설은 약해진다.

### C. OBB evaluation backend sensitivity
- **질문/가설:** OBB IoU/NMS 구현 경로가 모델 순위를 바꿀 수 있다.
- **최소 실험:** Supervision 0.31.4/0.31.5 및 OpenCV 유무를 고정한 matrix로 같은 predictions를 재평가한다.
- **판정:** 모든 IoU regime에서 순위가 유지되면 backend sensitivity가 낮다는 결론도 유효하다.

## 11) 오늘 안 읽어도 되는 것

- Codex alpha 릴리스는 CV 모델 성능 근거가 아니므로 연구 읽기 우선순위는 낮다. 에이전트 workflow를 실제로 운영할 때만 stable 0.167.0의 입력/로그 관리 변화를 확인하면 된다.
