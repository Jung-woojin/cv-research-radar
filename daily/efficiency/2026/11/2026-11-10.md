1. 최근 후보 6개를 재검토했지만, 전일 TensorRT/OpenVINO/WebGPU signal 이후 새 throughput/VRAM 실측을 공식적으로 확인할 수 있는 항목은 제한적이었다.

3. 이는 “더 빠른 CoreML” 주장보다 export 형식이 계산 결과 자체를 바꿀 수 있다는 deployment-correctness 신호다.
4. PR은 static graph의 CoreML format을 ML Program으로 바꾸고, ORT 1.19.2 abort 때문에 특정 변환 경로를 피한다.

## 핵심 사례 — static ONNX MPS CoreML export

- **사실:** merged PR #27117은 static ONNX export가 MPS에서 CoreML로 실행될 때 semantic crash 및 CPU drift를 보이는 문제를 다루며 static graph의 CoreML 형식을 ML Program으로 변경한다.
- **사실:** PR은 ORT 1.19.2가 abort되는 경우를 별도로 다뤄 runtime-version dependence가 있음을 드러낸다.
- **진단:** export 완료/compile 성공은 original model과 output-equivalent라는 보증이 아니다.
- **가설:** graph format과 static input shape의 조합이 box/class score drift를 만들어 aggregate latency 이전에 image-level semantic mismatch로 드러난다.
- **최소 실험:** golden input 100장을 PyTorch, ORT CPU, CoreML MPS에 통과시켜 class agreement, box IoU, score tolerance, failure exemplar와 p50/p95 end-to-end latency를 기록한다. 모델 hash, macOS, CoreML/ORT version, precision, input shape, warm-up, transfer 포함 여부를 manifest에 남긴다.
- **GO/KILL:** 모든 output tolerance가 충족되고 target device에서 p95 latency를 따로 개선하면 ML Program deployment를 GO한다. class/box mismatch가 하나라도 재현되면 speed 비교를 KILL하고 exporter/runtime path부터 격리한다.
- **한계:** PR은 특정 정적 ONNX/MPS path의 수정이다. power, VRAM, throughput 개선 수치와 타 platform 전이는 확인되지 않았다.

## 오늘의 GO / KILL

- **GO:** edge benchmark의 acceptance criterion을 throughput만이 아니라 semantic checksum으로 확장한다.
- **GO:** p50/p95 latency와 host/device memory를 prefill/transfer/postprocess 포함 여부와 함께 기록한다.
- **KILL:** converter version 또는 input shape가 다른 결과를 단일 CoreML 성능으로 평균내지 않는다.
