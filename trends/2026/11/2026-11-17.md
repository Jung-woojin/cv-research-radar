# Biweekly CV Trend Map — 2026-11-17

관찰 구간: 2026-11-03 04:30 ~ 2026-11-17 04:30 KST. 직전 구간: 2026-10-20 ~ 11-03. 기준일 2026-10-06에서 42일 경과한 정규 발행일이다.

## 핵심 요약

- 이번 2주의 핵심은 **시각 정보를 더 많이 처리하기보다, 필요한 증거를 확보하고 사용했는지 비용과 함께 진단하는 것**이다.
- ZoomGain과 grounded reasoning 분석은 확대 관측의 효과와 좌표 출력의 효과를 구분하게 한다.
- SAVE는 복잡한 video agent의 이득을 동일 backbone·비용 조건에서 다시 검토한다.
- PR-OVD와 MUMU는 novel category 보존이 큰 detector와 작은 통합 모델 모두의 병목임을 보여준다.
- Frozen encoder의 다층 readout은 유효한 대안이지만, 코드 접근성과 전체 추론 비용을 별도로 확인해야 한다.
- 영상 평가는 최종 정답에서 준비·대기·취소의 시간 정합성과 물리적 annotation coverage로 확장된다.
- UAV 정합에서는 정상적인 inlier 통계가 실제 배경 정렬 실패를 숨길 수 있다.
- 우선 실험은 OVD의 표현·readout 분리와 tiny-object crop 선택의 누락 진단이다.

## 1. 이번 2주를 한 문장으로 요약

**CV 연구의 유망한 문제 정의는 증거의 존재→접근→표현 보존→readout→행동 시점이라는 실패 사슬을 분해하고, 필요한 단계에만 최소 개입하는 것이다.** 이는 이번에 확인한 연구 묶음의 해석이며 분야 전체의 통계적 추세를 입증한 것은 아니다.

## 2. 핵심 트렌드 7개

**T1. 시각적 근거에 접근하는 능력과 grounding 문법을 분리한다.**  
[사실] ZoomGain은 global-to-zoom gap을 이용하는 데이터 구성과 benchmark를 제시한다. Grounded reasoning 연구는 좌표를 포함하는 추론의 효과를 과제별로 분석한다. [저자 주장] 전자는 확대에서 얻은 세부 정보가 supervision에 유용하다고 보고하고, 후자는 counting 개선과 달리 여러 공간·지각 평가에서 일관된 이득을 찾지 못했다. [추론] Crop 접근, evidence 사용, 좌표 출력은 별도 변수다. 작은 물체에서 oracle crop조차 실패하면 추론 길이를 늘리는 개입의 우선순위는 낮다. [ZoomGain](https://arxiv.org/abs/2611.14076), [Where and Why is Grounded Reasoning Useful?](https://arxiv.org/abs/2611.08485)

**T2. Video agent의 복잡도보다 선택적 관측의 필요조건을 묻는다.**  
[사실] SAVE는 두 backbone과 세 benchmark에서 agent 방법들을 통제 비교하고 token·금전 비용을 계산한다. [저자 주장] 여러 기존 agent는 native inference를 일관되게 개선하지 못하며, 긴 영상의 짧은 관련 사건에서 선택적 탐색의 이득이 커진다. [추론] “Agent가 더 좋다”보다 “균일 관측이 어떤 사건을 놓치는가”가 먼저다. 전체 지연은 논문의 평가에서 제외됐으므로 속도 우위로 해석할 수 없다. [SAVE 원문·limitations](https://arxiv.org/html/2611.15079v1)

**T3. OVD의 novel 의미 보존은 compact model에서도 해결되지 않았다.**  
[사실] PR-OVD는 base·novel·background partition과 refinement를 제안한다. MUMU는 tagging·OVD·captioning을 하나의 모델에서 평가한다. [저자 주장] PR-OVD는 novel 범주의 개선을 보고하지만 MUMU에서는 novel detection이 주요 병목으로 남는다. [추론] Backbone 확대나 통합만으로 해결됐다고 보기 어렵다. Feature 손실과 classifier/calibration 억제를 분리해야 한다. 서로 다른 데이터·평가이므로 두 결과의 직접 성능 비교는 **not strictly apples-to-apples**다. [PR-OVD](https://arxiv.org/html/2611.12976v1), [MUMU](https://arxiv.org/html/2611.16925v1)

**T4. Foundation model을 고정하고 readout·역할 배분을 바꾼다.**  
[사실] HiVE-VQA는 frozen V-JEPA 2.1의 여러 깊이 feature를 compact 3D convolution head로 융합한다. MUMU 상위 해법은 공유 Florence-2-base에 서로 다른 adaptation·decoding을 적용한다. [저자 주장] HiVE-VQA는 head만 학습하며 cross-dataset 품질 평가에서 강한 결과를 보고한다. [추론] CNN·ViT·SSM 중 승자를 고르는 것보다 locality·semantic feature·temporal readout의 역할 배분이 유용한 비교 축이다. 이 기간 자료로 CNN 또는 SSM의 점유율 상승은 입증하지 못했다. [HiVE-VQA](https://arxiv.org/abs/2611.17146), [MUMU](https://arxiv.org/abs/2611.16925)

**T5. Streaming video에서 기다림·준비·취소를 평가한다.**  
[사실] FuGIBench는 미래 프레임 없이 causal prefix를 보고 대기·가역적 준비·응답을 선택하게 한다. [저자 주장] 더 일찍 준비하는 시스템도 응답 정합성이 낮거나 불필요한 활동이 많을 수 있다. [추론] Persistent state는 기억량만이 아니라 필요가 사라졌을 때 상태를 철회하는 능력까지 포함한다. 합성 도구 지원 환경의 결과를 실제 항만 안전 성능으로 일반화할 수 없다. [FuGIBench](https://arxiv.org/abs/2611.16400)

**T6. 영상 annotation의 의미적 정답과 물리적 coverage를 분리한다.**  
[사실] PhysCapBench는 third-person·egocentric·handheld-gripper 영상의 물리적 caption을 평가한다. [저자 주장] 자연스러운 caption도 상호작용과 상태 전이를 누락할 수 있고, 더 물리적인 설명이 일부 downstream task에 유용하다. [추론] 더 많은 비디오보다 supervision이 보존하는 동역학을 진단할 가치가 있다. Caption 개선이 곧 일반 world model의 물리 이해 개선이라는 결론은 과하다. [PhysCapBench](https://arxiv.org/abs/2611.16424)

**T7. 내부 proxy가 정상이어도 실제 관측 좌표계가 틀릴 수 있다.**  
[사실] UAV stabilization 연구는 함께 움직이는 차량의 대응점이 배경 homography를 끌어가는 consensus capture를 분석한다. [저자 주장] Inlier 수·비율이 정상 범위여도 정합이 틀리고, 평가한 조건에서 object masking이 capture를 제거한다. [추론] Tiny-object tracking 오류를 detector 탓으로 돌리기 전에 배경 정합과 객체 위치 오차를 측정해야 한다. 해상도·feature budget·site split을 고정하는 설계가 핵심이다. [공식 원문](https://arxiv.org/html/2611.17190v1), [공식 코드](https://github.com/rfonod/stabilo-benchmark)

## 5. Benchmark와 dataset 변화

- ZoomGainBench는 전체 이미지와 세부 근거 접근의 격차를 평가한다. 공식 repo의 evidence box를 활용하면 정답과 근거 접근을 따로 측정할 수 있다. [공식 데이터 안내](https://github.com/inclusionAI/ZoomGain)
- MUMU는 0.5B parameter·PC 측 peak inference memory 8GB 제한에서 tagging·novel-aware detection·captioning을 평가한다. 실제 edge 장치의 실시간 성능을 보증하지 않는다. [평가 규칙](https://arxiv.org/html/2611.16925v1)
- FuGIBench는 19,893개 합성 영상과 causal prefix 기반 의사결정 평가를 제시한다. 데이터 규모는 저자 기재값이며 내려받아 검산하지 않았다. [원문](https://arxiv.org/abs/2611.16400)
- PhysCapBench는 물리적 정확성과 coverage를 분리하고, UAV benchmark는 static/dynamic protocol과 지상 기준점 audit를 분리한다. [PhysCapBench](https://arxiv.org/abs/2611.16424), [UAV protocol](https://github.com/rfonod/stabilo-benchmark)
- 이번 검토에서 COCO·LVIS·VisDrone 공식 규칙의 전면 변경은 확인하지 못했다. 새 평가 제안과 기존 leaderboard 개편을 혼동하지 않는다.

## 6. Architecture·training·inference 변화

**Architecture:** Frozen encoder에서 어떤 깊이·공간·시간 정보를 readout할지 설계한다. OVD는 semantic partition, 영상 품질 평가는 다층 feature fusion이 사례다. 서로 다른 task의 성능을 합쳐 구조 우월성을 주장하지 않는다.

**Training:** 전체 fine-tuning 이전에 novel 의미 보존과 supervision coverage를 진단한다. ZoomGain의 작은 대상 확대 supervision도 데이터 선택 효과와 학습 효과를 분리해야 한다.

**Inference:** 항상 확대하거나 agent를 호출하기보다 evidence가 희소한 조건에서만 관측을 추가한다. 전처리·decode·crop 선택·모델 호출을 포함한 지연과 peak memory를 측정한다. SAVE의 token/금전 비용은 이 전체 비용과 동일하지 않다.

## 7. 반복되는 미해결 문제

1. 정답에 필요한 정보가 없었던 것인지, encoder에서 소실됐는지, head가 읽지 못했는지 구별하기 어렵다.
2. Oracle crop의 개선이 해상도·배경 제거·선택 편향 중 무엇 때문인지 불명확하다.
3. Novel AP와 source/base 보존을 동시에 개선하는 조건이 충분히 분리되지 않았다.
4. Offline 미래 정보나 전체 영상 접근이 streaming 성능처럼 보고될 위험이 있다.
5. Caption coverage·inlier 수·평균 정답률이 실제 물리 상태와 객체 좌표 정확성을 대변하지 못한다.
6. 공개 선언과 실제 접근 가능한 코드·weights·고정 protocol 사이에 간극이 있다.

## 8. 앞으로 1~3개월 전망

[추론] Evidence 접근과 사용을 따로 측정하는 benchmark, frozen encoder의 작은 readout, 비용 제한 내 novel OVD 보존은 후속 실험이 늘어날 가능성이 있다. 여러 독립 연구가 문제를 공유하므로 상대적으로 강한 전망이다.

[추론] 준비 철회·대기 calibration과 물리 caption coverage도 확대 가능성이 있으나 이번 근거는 제한적이다. 실제 배포 채택이나 일정은 확인하지 못했다. CNN/SSM이 ViT를 대체한다는 전망은 보류한다.

## 9. Hype 대비 기여를 재검토할 흐름

- Grounded CoT를 출력했다는 사실만으로 시각적 근거 사용을 입증하지 못한다.
- 복잡한 agent의 높은 점수는 backbone·관측 예산·API 비용을 맞춘 뒤 판단해야 한다.
- Compact model의 parameter 제한 충족은 전체 task 품질이나 edge latency 보증이 아니다.
- PR-OVD의 평균 6.5% 개선은 저자 보고의 **상대 개선**이며 6.5 AP point로 바꾸면 안 된다. [원문](https://arxiv.org/html/2611.12976v1)
- HiVE-VQA의 코드·checkpoint 공개 주장은 이번 조회에서 확인되지 않았다. 404는 접근 실패의 관측이며 영구 미공개를 뜻하지 않는다.
- 서로 다른 backbone·pretraining·resolution·TTA·hardware의 수치를 직접 순위화하면 **not strictly apples-to-apples**다.

## 10. 정우진의 연구 기회 4개

아래는 수행하지 않은 제안이다. 샘플 수는 실험 계획이며 결과 수치가 아니다. GO/KILL은 사전 판정 규칙이다.

**A. OVD negative transfer의 표현·readout 분리 — 우선순위 1**

- 관찰·진단: PR-OVD와 MUMU가 novel 구분의 병목을 드러내지만 발생 위치는 설정마다 다를 수 있다.
- 가설: Adaptation 후 novel 오류 일부는 feature 정보 소실보다 readout/calibration에 기인한다.
- 최소 실험: 동일 validation 이미지에서 adaptation 전후 encoder, GT crop/예측 RoI, 원래 head/고정 prototype의 교차 비교. Base·novel·small AP와 margin을 기록한다.
- GO: Held-out split에서 head 교체만으로 novel 회복이 반복되고 base 손실도 설명 가능할 때. KILL/전환: Oracle crop·probe 모두 회복하지 못하면 표현 또는 관측 손실로 질문을 바꾼다.
- 위험·음성 결과 가치: Probe 학습량과 crop 변화가 confound다. 회복 실패도 정보 손실 단계의 범위를 좁힌다. 4~6주 MVP, backbone 재학습보다 feature 추출부터 시작한다.

**B. Tiny UAV·해상 표적의 zoom 정책 누락 — 우선순위 2**

- 진단: Confidence 기반 crop 선택은 탐지 자체가 안 된 작은 물체를 건너뛸 수 있다.
- 가설: 관측 budget을 맞추면 uncertainty-only보다 coverage-aware 선택이 고위험 FN을 줄인다.
- 최소 실험: VisDrone validation 또는 사용 권한이 있는 해상 영상에서 uniform tiling·confidence crop·coverage crop·oracle crop을 비교한다. 동일 총 pixel/token 예산과 해상도별 층화를 적용한다.
- 지표·판정: Tiny recall, evidence hit rate, FN, decode 포함 지연. Held-out 영상에서 oracle gap을 줄이면 GO, 선택 overhead가 이득을 상쇄하면 KILL.
- 위험: Oracle은 배포 가능한 방법이 아니라 상한 진단이다. 항만·촬영 시점별 분리로 누수를 줄인다. 2~4주 진단 MVP.

**C. UAV 정합 오류와 detector 오류의 분리**

- 진단: 정상 inlier 통계에서도 배경 좌표가 틀릴 수 있다.
- 가설: 일부 tracking 위치 오류는 detector보다 정합의 움직이는 전경 포획에서 온다.
- 최소 실험: 공개 stabilo sample에서 동일 keypoint budget으로 no mask/HBB/OBB mask를 비교하고, 지상 기준점 오차와 객체 위치 오차를 기록한다. Small-object recall도 함께 검사한다.
- GO: 독립 장면에서 masking이 배경·객체 오차를 함께 낮출 때. KILL: 단순 detector 개선만으로 설명되거나 mask 비용이 실시간 예산을 넘을 때.
- 위험·가치: Pseudo-GT audit와 그 오차 범위가 필요하다. 음성 결과도 detector/정합 책임을 분리한다. 2~4주 MVP.

**D. Streaming 항만 이벤트의 대기·취소 평가**

- 진단: 일찍 경고해도 불필요한 경고를 철회하지 못하면 평균 정답률은 운영 품질을 숨긴다.
- 가설: Timestamp별 상태 readout과 hysteresis만으로 불필요한 준비·경고가 줄어든다.
- 최소 실험: 허가된 영상의 소규모 이벤트에 시작·취소 시점을 주석하고, frozen encoder+선형 head, 짧은 temporal head, hysteresis 후처리를 비교한다. 미래 프레임은 금지한다.
- 지표·판정: False alarm duration, 취소 지연, event recall, 처리 지연을 측정한다. Recall 손실 없이 두 시간 지표가 개선되면 GO; annotation 합의가 낮으면 모델보다 rubric을 먼저 수정한다.
- 위험·가치: 실제 안전 효과는 별도 검증 대상이다. 4~8주 MVP이며 FuGIBench는 평가 설계 참고로만 사용한다.

## 11. 다음 2주 집중 읽기

1. [SAVE](https://arxiv.org/html/2611.15079v1) — native baseline, 관측 예산, limitations를 먼저 읽기.
2. [PR-OVD](https://arxiv.org/html/2611.12976v1) — partition·layer grouping·합성 context ablation.
3. [ZoomGain](https://github.com/inclusionAI/ZoomGain) — evidence bbox와 full-image/crop 비교를 진단에 재사용.
4. [UAV consensus capture](https://github.com/rfonod/stabilo-benchmark) — sample·audit·masking protocol.
5. [MUMU](https://arxiv.org/html/2611.16925v1) — task 간 품질 상충과 실제 memory 규칙.
6. [FuGIBench](https://arxiv.org/abs/2611.16400), [PhysCapBench](https://arxiv.org/abs/2611.16424) — 상태 철회와 supervision coverage.

키워드: `evidence access vs use`, `oracle crop gap`, `novel capacity`, `frozen encoder readout`, `native vs agentic cost`, `causal video prefix`, `cancellation latency`, `consensus capture`.

## 12. Text trend map

```text
Closed-set detection
  → Open-vocabulary detection
    → novel semantic capacity 진단 [PR-OVD / MUMU]
      → representation vs readout 교차 실험
        → 작은 specialist의 실제 비용·오류 검증

Full-image / uniform-frame observation
  → 필요한 증거가 들어왔는가? [ZoomGain / SAVE]
    → 들어온 증거를 사용했는가? [Grounded reasoning]
      → 상태·상호작용을 보존했는가? [PhysCapBench]
        → 기다리고 준비하고 철회했는가? [FuGIBench]

Large pretrained encoder
  → frozen multi-layer feature [HiVE-VQA]
    → compact task readout / selective decoding [MUMU]
      → decode·selection·memory·latency를 포함한 평가

정상 proxy score
  → 실제 배경·객체 위치 audit [UAV consensus capture]
    → 실패 단계 귀속
      → 가설 → 최소 개입 → 동일 조건 검증 → GO/KILL
```

검증 범위: 웹 검색, arXiv 원문·submission history, 공식 프로젝트·repository를 조회했다. 논문 결과는 저자 보고이고 독립 재현은 수행하지 않았다. 이전 보고서의 수치를 재검증 없이 새 사실로 옮기지 않았으며, 미확인 release·하드웨어 성능·실험 결과는 만들지 않았다.
