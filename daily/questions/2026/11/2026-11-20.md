**Expected Contribution·negative result:** calibration 대표성과 객체 크기별 손실의 분해. 효과가 없으면 표본 선택만으로 해결되지 않는 경계를 제시하고 연산별 민감도 진단으로 이동한다.

## Q3. VLM judge 교체가 모델 간 우열과 evidence-grounded 판정을 얼마나 바꾸는가?

**문제·Observation·왜 지금:** VLMEvalKit `ed3e918edf4a62e0bf42a2768655e02d45312fef`는 실제 resolved 모델에 대한 종료 경고와 향후 기본 judge 교체 안내를 추가했다. 이번 변경 자체는 judge 교체나 새 점수 발표가 아니다. 별칭과 `LOCAL_LLM` override가 실제 모델 선택에 관여한다. [공식 commit](https://github.com/open-compass/VLMEvalKit/commit/ed3e918edf4a62e0bf42a2768655e02d45312fef) · [고정 judge 구현](https://github.com/open-compass/VLMEvalKit/blob/ed3e918edf4a62e0bf42a2768655e02d45312fef/vlmeval/dataset/utils/judge_util.py)

**Gap·Diagnosis·Mechanism:** 응답 생성기를 고정해도 judge의 지식·문체 선호·rubric 해석이 바뀔 수 있다. 정답 판정과 영역 증거 판정을 합치면 Answer–Region Gap 변화가 생성 모델 때문인지 평가자 때문인지 분리하기 어렵다.

**Hypothesis:** judge 간 불일치는 단순 정답보다 시각적 증거의 충분성 판정에서 더 크며, 결정적 정답 검사와 명시적 evidence rubric을 분리하면 그 불일치가 줄어든다.

**최소 개입·Experimental Design:** 먼저 API 호출 없이 alias→snapshot·override·prompt hash·evaluator commit·cache 정책 manifest를 만든다. 보존된 동일 VQA 응답과 이미지·영역 annotation을 old/new judge로 paired 비교하고, 정답·증거 판정을 분리한 rubric을 ablation한다. old 결과가 없고 old judge를 호출할 수도 없으면 전환 효과는 식별 불가로 남긴다. 인간 이중 감사와 결정적 정답 검사를 baseline으로 사용한다. 데이터 revision·split은 확보 후 고정하며 현재 지정 데이터 확보는 미확인이다.

**Metric·GO/KILL:** label 전환율, 인간과의 일치, judge 내부 반복 분산, 모델 쌍별 우열 전환, answer-correct/evidence-wrong 비율을 기록한다. judge 간 차이가 반복 분산을 넘고 인간 감사로 설명되면 GO. 과거 paired 기록이 없으면 시계열 인과 주장 KILL, 새 baseline 연구로 축소한다.

**Expected Contribution·negative result:** judge migration을 평가 버전으로 기록하는 paired audit. 차이가 작으면 고정 데이터·rubric 범위에서의 안정성 결과다.

**Compute·Risk·4~8주:** 설정 감사 cost **1/5**, 실제 judge 비교 **3/5**의 계획상 판단. 유료 호출은 하지 않았고 비용은 미확인이다. 기존 judge-bias 연구와 중복 위험이 있어 grounding 판정 분해가 필요하다. 1~2주 manifest·보존 응답, 3~4주 paired 판정, 5~8주 인간 감사와 복수 task 검증을 목표로 한다. judge·prompt가 다른 headline 점수는 **not strictly apples-to-apples**다.

## Q4. “마지막 grid”는 최종 답을 복구하는가, 뒤쪽 부가 예시를 오수락하는가?

**문제·Observation·왜 지금:** lmms-eval `a6982d978d88f39fca83c5d7845672817bcaddf3`는 ARC-AGI의 앞쪽 grid 선택을 역순 탐색으로 수정하고 회귀 fixture를 추가했다. 반면 고정 ARC Prize parser는 boxed 추출을 먼저 시도한다. 완전한 구현 동등성은 성립하지 않는다. **Gap·Diagnosis·Mechanism:** 전일 grounding JSON 질문이 직렬화 문맥의 불변성을 다뤘다면, 오늘은 여러 유효 답 후보 사이의 최종 의도 선택을 다룬다. 첫 답·수정 답·boxed 답·마지막 예시는 서로 다른 의미 역할이다. parser가 올바르게 작동해도 평가 계약이 모호할 수 있다.

**Hypothesis:** 역순 parser는 입력 복사 오류를 줄이지만 “명시적 최종 답 뒤의 부가 grid”에서는 오수락을 늘릴 수 있다. 명시적 final-answer 계약은 의도 선택 오류를 줄이지만 형식 위반에 따른 거부 비용이 생긴다.

**최소 개입·Experimental Design:** 같은 ARC sample ID·정답·저장 응답을 parent, 수정 parser, 고정 공식 parser로 재채점한다. 입력 인용·수정 답·boxed 뒤 예시·복수 boxed·잘못된 suffix·답 없음으로 분류한다. 합성 fixture는 경계 검사용으로, 자연 응답은 빈도 추정용으로 분리한다. 계약 기반 parser는 추가 baseline으로 두되 자연 응답의 의도는 사람이 감사한다. 새 모델 추론은 첫 단계에 필요하지 않다.

**Metric·GO/KILL:** parse 실패율, 추출 불일치, 정오답 전환표, 의도 오선택률과 거부율을 함께 본다. 실제 응답에서 개선·회귀 양쪽이 확인되면 GO. 합성 경계에서만 차이가 나면 실제 모델 영향 주장을 KILL하고 구현 감사로 축소한다.

**Expected Contribution·negative result:** 답 추출 성공과 의도 보존을 구분하는 평가. 차이가 없으면 해당 응답 집합에서 수정의 영향이 없다는 유효한 결론이다.

**Compute·Risk·4~8주:** CPU cost **1/5**. 알려진 parser 버그 재현에 머물 위험이 크다. 1~2주 경계 fixture, 3~4주 자연 응답 감사, 5~8주 다른 구조화 시각 task로 확장해야 논문 기여가 생긴다. 공식 비교는 입력 modality·test pair·attempt·집계 단위도 맞춰야 한다.

**Gap·Diagnosis·Mechanism:** 관측 파일이 run 속도에 따라 누락된다면, 보존된 시각화만으로 augmentation·annotation 실패를 감사할 때 표본이 선택될 수 있다. 실제 annotation 오류나 AP 편향 발생은 아직 확인되지 않았다. 작성자의 누락 보고와 타 환경에서 누락이 없었다는 전일 watch의 반대 근거도 구분해야 한다.

**Hypothesis:** epoch 길이와 plot 지연을 독립적으로 조작하면 소비 시점의 증거 누락이 완료 순서로 설명되며, 생산자 완료 대기는 그 속도 의존성을 제거한다.

**최소 개입·Experimental Design:** 동일 COCO8 소형 학습 조건에서 수정 전후를 비교하고 자연 실행·통제 plot 지연을 분리한다. 먼저 CPU의 생산자–등록–callback 최소 harness로 순서를 확인한다. baseline은 기존 비동기 경로, 개입은 생산자 join이다. 파일 존재·등록·upload 대상으로 선택되는 시각을 계측한다. 등록 확인은 실제 원격 업로드 성공과 별도다. Plot 예외·plots 비활성·짧은 epoch를 대조군으로 둔다.

**Metric·GO/KILL:** 예상 대비 완료·등록·선택 파일 비율, callback까지의 시간 여유, live thread, 대기 비용을 기록한다. 통제 지연에서 속도 의존 누락이 생기고 join으로 사라지면 순서 가설 GO. 파일 내용 오류나 학습 성능 변화까지 join의 효과로 해석하면 KILL. 자연 실행에서 누락이 없으면 그 환경의 경계로 보고한다.

**Expected Contribution·negative result:** 비동기 연구 증거의 완전성 검사. 실제 실패 분석의 편향까지 확인하려면 알려진 오류가 든 batch의 감사 회수율을 추가 측정해야 한다. 누락이 없다는 결과도 기록한다.

**Compute·Risk·4~8주:** CPU harness cost **1/5**, 소형 학습 **2/5**. 알려진 경쟁 조건 재현만으로 출판 가능성은 낮다. 1~2주 순서 진단, 3~4주 복수 logging 경로, 5~8주 실제 오류 감사의 선택 편향까지 입증하면 재현성 연구 후보가 된다.
