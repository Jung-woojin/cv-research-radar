## Q1. 최종 답 보상만으로 학습한 tool-use MLLM은 좌표 충실도를 잃는가?

1. **문제 정의**: 최종 답이 맞더라도 crop·box·annotation이 실제 근거와 어긋나는 coordinate drift를 정량화하고, answer-only reward가 이를 악화시키는지 묻는다.
2. **왜 지금 가치가 있는가**: **확인된 사실** — PerceptRL은 tool-use 학습 모델에서도 잘못된 crop/annotation이 증거를 왜곡하고 오류를 전파하는 coordinate drift를 관찰했다고 쓴다.
3. **직접 근거**: [PerceptRL](https://arxiv.org/abs/2610.37471). **저자 주장** — Coordinate Injection과 grounding-aware process reward를 도입해, shared protocol에서 7개 benchmark 평균 71.6%를 보고했다.
4. **핵심 가설**: answer-only reward는 우연히 정답인 trajectory를 강화해 evidence IoU와 crop perturbation 안정성을 낮출 수 있고, 중간 좌표 reward가 그 간극을 줄인다.
5. **최소 실험(MVP)**: 문서·항공 VQA 각각 25개씩, 총 50문항에서 predicted crop, oracle crop, 같은 면적의 random crop을 생성한다. 답·근거 영역·좌표를 로그로 보존하고 crop을 ±5%, ±10% 이동시킨다.
6. **baseline과 dataset**: 공개 grounded VQA 또는 RefCOCO+의 question–region 쌍; frozen base VLM, answer-only fine-tune 가능 모델, process-reward 또는 좌표-verifier variant를 비교한다. 모델·prompt·crop 면적은 고정한다.
7. **성공/실패 판정 metric**: answer accuracy, evidence IoU, answer-stability-under-perturbation, correct-but-misgrounded rate. **GO**는 accuracy 손실 1 point 이내에서 evidence IoU와 stability가 함께 개선되는 경우다.
8. **compute 난이도**: 낮음–중간. 우선 inference와 소량 수동 region audit만 필요하며 RTX 5060 Ti 8GB에서 subset 실행 가능하다.
9. **novelty 위험요인**: grounding metric과 process supervision은 기존 연구가 많다. 최종 정답을 조건으로 한 *counterfactual coordinate audit*과 correct-but-misgrounded rate가 핵심 차별점이어야 한다.
10. **4–8주 내 논문화 가능성**: 높음. 작은 audit로 효과 크기를 확인한 뒤 domain과 tool 종류를 확장할 수 있다.
11. **negative result의 가치**: answer-only와 process-aware가 같은 좌표 안정성을 보이면 drift는 reward가 아니라 tool UI·visual encoder 해상도 병목에서 주로 발생한다는 반증이 된다.

## Q2. 공간추론 정답은 RGB·depth·top-down 표현을 바꿔도 유지되는가?

1. **문제 정의**: 같은 unseen state를 다른 표현으로 제시했을 때 공간 질의의 답이 뒤집히는지, 그리고 그 flip이 오류를 예고하는지 묻는다.
2. **왜 지금 가치가 있는가**: **확인된 사실** — ImagiRep은 922문항, 7 question type, 두 setting에서 oracle RGB와 depth·panorama·top-down 등을 제공한다. 원문은 정확한 imagined RGB도 정확한 spatial reasoning을 보장하지 않는다고 보고한다.
3. **직접 근거**: [ImagiRep](https://arxiv.org/abs/2610.37437), [공식 프로젝트](https://imagirep.github.io/).
4. **핵심 가설**: 여러 표현에서 일치하는 답은 단일 RGB 답보다 신뢰도가 높고, representation flip은 모델 confidence보다 강한 error predictor가 될 수 있다.
5. **최소 실험(MVP)**: ImagiRep의 공개 가능 subset 또는 simulator로 60문항을 고정한다. RGB, depth, top-down, panorama에 동일 prompt를 넣고 distance·angle·presence별 answer flip과 confidence를 기록한다.
6. **baseline과 dataset**: RGB-only, 무작위 표현 선택, 다수결, 저자 제안 GEARS 재현 가능 시 이를 비교한다. 표현이 다른 입력 간 점수는 direct accuracy 비교만 하며 generation quality 비교와 섞지 않는다.
7. **성공/실패 판정 metric**: per-question accuracy, flip rate, error detection AUROC, selective risk–coverage, representation별 latency. **GO**는 flip flag가 confidence보다 error AUROC를 높이거나 같은 coverage에서 risk를 낮추는 경우다.
8. **compute 난이도**: 낮음. backbone 재학습 없이 다중 입력 inference와 표본 분석으로 시작한다.
9. **novelty 위험요인**: test-time augmentation과 ensemble로 환원될 수 있다. 질문 type에 따라 어떤 표현 불일치가 informative한지 사전 등록하고, 같은 world state라는 통제를 유지해야 한다.
10. **4–8주 내 논문화 가능성**: 높음. 분석 benchmark/evaluation note로 시작해 real-world depth-estimation 조건으로 확장할 수 있다.
11. **negative result의 가치**: flip이 오류를 예고하지 않으면 representation consensus는 uncertainty proxy가 아니며, question-conditioned semantic verifier가 필요하다는 결론을 준다.

## Q3. adaptive representation selection은 world-state 추정 오류를 가리는가, 줄이는가?

1. **문제 정의**: world model의 estimated state가 틀렸을 때 표현 selector가 RGB 대신 depth·top-down을 선택하는 것이 진짜 recovery인지, 서로 일관된 오답을 더 설득력 있게 만드는 것인지 구분한다.
2. **왜 지금 가치가 있는가**: **확인된 사실** — ImagiRep은 estimated state에서 파생한 표현도 서로 보완적 이점을 보인다고 보고하지만, estimated RGB 단독은 spatial reasoning을 오도할 수 있다고 명시한다.
3. **직접 근거**: [ImagiRep](https://arxiv.org/abs/2610.37437). **저자 주장** — lightweight test-time GEARS가 기존 spatial imagination 방법보다 낫다고 보고한다.
4. **핵심 가설**: selector의 이득은 state-error가 작은 경우에 집중될 것이며, state-error가 큰 경우엔 표현 다양성보다 oracle/estimated 표현 간 불일치가 abstention 신호가 된다.
5. **최소 실험(MVP)**: simulator에서 pose·depth에 작은/중간/큰 noise를 주입한다. RGB-only, best-fixed representation, adaptive selector, disagreement-abstain을 같은 문항·같은 compute budget에서 비교한다.
6. **baseline과 dataset**: ImagiRep Viewpoint Imagination/Cross-view Integration setting 또는 동등 simulator; oracle state와 perturbed estimated state를 분리한다.
7. **성공/실패 판정 metric**: state-error bin별 accuracy, calibration error, risk–coverage, harmful-selection rate, average number of representations. **GO**는 큰-noise bin에서 selector가 fixed baseline보다 harmful selection을 낮추는 경우다.
8. **compute 난이도**: 중간. simulator access와 representation renderer가 필요하나 모델 학습 없이 먼저 측정 가능하다.
9. **novelty 위험요인**: robust planning·sensor fusion과 중첩된다. 핵심은 model answer가 아니라 *estimated visual world state의 error strata*에서 selector를 평가하는 것이다.
10. **4–8주 내 논문화 가능성**: 중상. controlled simulator 결과 뒤 embodied/navigation VLM으로 하나만 외부 검증하면 평가 논문 구성이 가능하다.
11. **negative result의 가치**: selector가 모든 noise bin에서 고르게 이득을 보이면 state-error-aware routing의 필요성이 약해지고, 표현 선택만으로도 회복 가능하다는 강한 반례가 된다.

## Q4. code caption의 문법적 유효성은 시간 구조 충실성을 대신할 수 있는가?

1. **문제 정의**: 실행 가능하거나 parse되는 code caption이 실제 object motion·event order를 보존하는지, 아니면 단지 잘 형식화된 허구인지를 묻는다.
2. **왜 지금 가치가 있는가**: **확인된 사실** — CodeCap-Bench는 323개 structured-2D 동영상과 fine-grained annotation을 제공하며, leading MLLM도 복잡한 temporal dynamics를 충실히 포착하기 어렵다고 보고한다.
3. **직접 근거**: [CodeCap-Bench](https://arxiv.org/abs/2610.37341).
4. **핵심 가설**: syntax validity는 temporal faithfulness와 약하게만 상관하며, time function의 계수·event order·object identity를 바꾸는 반사실 테스트가 별도 필요하다.
5. **최소 실험(MVP)**: 80개 clip에서 생성 code caption의 syntax/parse 성공, time primitive 추출, object trajectory와 event-order를 annotation에 맞춰 채점한다. 동일 caption의 time variable 또는 순서를 교환한 뒤 QA 답 변화도 측정한다.
6. **baseline과 dataset**: CodeCap-Bench의 공개 가능 evaluation split; natural-language caption, raw code caption, syntax-repaired code caption을 비교한다.
7. **성공/실패 판정 metric**: syntax validity, temporal primitive F1, event-order accuracy, QA accuracy, counterfactual answer sensitivity. **GO**는 syntax validity가 높아도 temporal F1이 낮은 분명한 gap 또는 repair 뒤 faithfulness 저하가 재현되는 경우다.
8. **compute 난이도**: 낮음–중간. caption 생성과 parser·rule-based evaluator가 중심이며 학습은 필요 없다.
9. **novelty 위험요인**: program-execution evaluation과 유사하다. 코드를 실행 가능한 artifact가 아니라 “동영상의 시간 증거”로 취급하고 answer sensitivity까지 연결해야 한다.
10. **4–8주 내 논문화 가능성**: 중상. benchmark annotation 접근성에 좌우되지만 diagnostic extension으로 명확하다.
11. **negative result의 가치**: syntax validity가 temporal F1을 강하게 예측하면 별도 시간 metric의 실익이 작으며 parser-based filtering이 실용적 baseline이 된다.

## Q5. code caption의 QA 이득은 시간 인과 구조 보존에서 오는가?

1. **문제 정의**: code caption이 natural language보다 QA·reconstruction에서 낫다는 결과가, 실제로 시간 인과 구조를 더 보존해서인지 아니면 evaluator가 code format에 유리해서인지 분리한다.
2. **왜 지금 가치가 있는가**: **확인된 사실** — CodeCap-Bench 원문은 code caption이 QA accuracy와 reconstruction fidelity에서 natural-language caption보다 좋다고 보고하면서도 복잡한 temporal dynamics가 병목이라고 밝힌다.
3. **직접 근거**: [CodeCap-Bench](https://arxiv.org/abs/2610.37341). **저자 주장** — graphical primitive·layout rule·time function이 compact representation으로 작동한다.
4. **핵심 가설**: code의 장점이 시간 구조에 있다면 object identity·event order·velocity sign을 보존한 code만 QA 이득을 유지하고, 동일 길이의 pseudo-code 또는 shuffled-time code는 이득을 잃어야 한다.
5. **최소 실험(MVP)**: 60 clip에서 (a) 자연어, (b) 원 code, (c) time-shuffled code, (d) same-length pseudo-code를 만들고, temporal·spatial·appearance 질문을 분리해 blind evaluator로 채점한다.
6. **baseline과 dataset**: CodeCap-Bench 또는 구조화 2D synthetic video; caption length, tokenizer budget, answering model, question type을 고정한다.
7. **성공/실패 판정 metric**: question-type accuracy, reconstruction score, temporal intervention effect, format-only gain, human/annotation agreement. **GO**는 temporal 질문에서만 원 code의 paired gain이 남고 shuffled-time condition에서 유의하게 사라지는 경우다.
8. **compute 난이도**: 중간. 여러 caption condition과 QA/reconstruction pass가 필요하지만 60 clip pilot은 단일 GPU에서 가능하다.
9. **novelty 위험요인**: representation ablation의 재포장일 수 있다. code 길이·lexical cue·evaluator prompt를 엄격히 맞춰 causal mediation을 주장해야 한다.
10. **4–8주 내 논문화 가능성**: 높음. 원 benchmark를 바꾸지 않고 counterfactual caption suite를 덧붙일 수 있다.
11. **negative result의 가치**: shuffled-time code도 성능을 유지하면 code caption 이득은 시간 인과 구조보다 format prior·object inventory에서 왔다는 중요한 한계가 된다.

## 오늘 먼저 돌릴 최소 실험

**선택: Q1 — answer-only 보상과 좌표 충실도 간극.**

1. question–region 정답이 있는 50문항을 사전 고정하고, model answer와 crop/box를 저장한다.
2. 같은 면적의 predicted·oracle·random crop을 사용해 입력 조건을 맞춘다.
3. 각 crop을 ±5%, ±10% 이동해 answer stability와 evidence IoU를 함께 측정한다.
4. “정답이지만 근거가 틀린” 비율을 별도 보고한다. accuracy만으로 성공을 선언하지 않는다.
5. Q1의 GO 기준을 못 넘으면 reward 설계 연구로 확장하지 않고, tool interface와 encoder resolution을 먼저 진단한다.
