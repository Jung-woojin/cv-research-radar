## 1. NVIDIA ModelOpt 0.48.0 — BEVFormer 양자화 경로

**공식 출처:**  
- https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.48.0  
- https://github.com/NVIDIA/Model-Optimizer  
- https://github.com/NVIDIA/Model-Optimizer/blob/0.48.0/LICENSE  
- https://github.com/NVIDIA/Model-Optimizer/blob/0.48.0/examples/onnx_ptq/bevformer/README.md

### 사실

- 0.48.0은 2026-11-02에 게시됐다. 배포 휠 `nvidia_modelopt-0.48.0-py3-none-any.whl`의 공개 SHA-256은 `bfcfd425eab15e05eccf065b58d11cc33f9c27b4859a6efb78aba74bfb9f225c`다.
- 이 릴리스는 시간 순서를 고려한 calibration data, INT8/FP8 설정, TensorRT 엔진 빌드, nuScenes 평가를 포함하는 BEVFormer ONNX PTQ 예제를 추가했다.
- 예제 README는 BEVFormer tiny 체크포인트 SHA-256 `7305046dbaa4fe8b1fa6d6acb9e0e3d605a70a3c473f763e936103428d2b2f12`, calibration 600개 순서 샘플, nuScenes validation 6,019개를 명시한다.
- 저장소 라이선스는 Apache-2.0이다.
- 릴리스는 RADIO 계열 VLM의 Hugging Face export 이름 보존, KV cache 비활성 시 이미지 입력 누락, FP16 activation에서 ONNX INT8 entropy calibration 실패, MaxViT Transpose 축 오류도 수정했다고 적었다.
- TensorRT serialized engine은 TensorRT 버전과 목표 GPU에 종속된다고 README가 명시한다.

### 저자 주장

- 예제의 과거 통합 수치는 FP16 NDS/mAP `0.3546/0.2515`, INT8/FP16 `0.3512/0.2505`, FP8/FP16 `0.3526/0.2489`이며, 속도 비교는 각각 기준 1x, 1.87x, 1.18x다.
- 이 수치는 릴리스에서 새로 재실행한 독립 결과가 아니라 예제 문서의 참조 값이다.

### 추론과 최소 실험

- **진단:** 일반 PTQ 검증은 단일 이미지에서 끝나기 쉬우나 BEVFormer는 시간 상태(`prev_bev`)와 scene reset을 보존해야 한다.
- **가설:** 0.48.0의 예제는 이 상태 보존을 포함하므로, 기존 단순 calibration보다 export 실패와 정확도 저하를 조기에 드러낼 가능성이 높다.
- **최소 실험:** 격리 환경에서 태그 `0.48.0`과 공개 휠 해시만 검증하고, 공식 예제의 첫 3개 순서 샘플로 ONNX→TensorRT export smoke test를 수행한다. 엔진 생성, 입력 이름, `prev_bev` 전달 여부만 확인하며 NDS/mAP 전체 재현은 실행하지 않는다.
- **GO:** 세 샘플 모두 엔진 생성 및 상태 전달이 확인될 때. **KILL:** TensorRT/GPU 버전 불일치 또는 이미지·상태 입력 누락이 확인될 때.
- **운영 판단:** 연구 실험 가치는 5/5, 재현성 4/5, 신규성 4/5, 즉시 실용성 3/5다. CUDA/TensorRT가 없는 환경에는 적합하지 않다.
- **가중치·의존성·하드웨어:** 릴리스 자체는 공식 새 pretrained weight를 배포한다고 명시하지 않는다. 예제는 TensorRT 10.14 Dockerfile과 목표 GPU용 plugin build를 전제한다. 필요한 VRAM 수치는 원문에서 확인하지 못했으므로 기록하지 않는다.
- **보안:** wheel 해시를 확인하고, native plugin과 Docker 빌드는 고정된 공식 커밋에서만 수행한다.

## 2. Ultralytics 8.4.201 — plotting 경로와 PPE 데이터셋

**공식 출처:**  
- https://github.com/ultralytics/ultralytics/releases/tag/v8.4.201  
- https://github.com/ultralytics/ultralytics  
- https://github.com/ultralytics/ultralytics/blob/v8.4.201/LICENSE

### 사실

- `v8.4.201`은 2026-11-03에 게시됐다. 릴리스에는 `sbom.spdx.json`이 있으며 공개 SHA-256은 `f2faa5ea17806a72a227394dc3e2d0774007a37f5217b3a3e7833d8dce1c0cad`다.
- 릴리스는 training/validation mosaic와 `Results.plot(pil=True)`에서 PIL plotting을 최대 15배 빠르게 했다고 설명한다. font·label patch cache, 이미지 변환 축소, uint8 이미지 전달, mask blending 경로가 대상이다.
- `construction-ppe`를 canonical dataset 이름과 다운로드 경로로 정비했다. 릴리스 설명상 이 데이터셋은 1,000 이미지·12 클래스·CC BY 4.0이다.
- 릴리스는 모델 architecture 변경이 없다고 명시한다.
- 저장소 라이선스 파일은 AGPL-3.0 조건을 제시한다.

### 저자 주장

- “최대 15배”는 plotting 경로에 대한 주장이다. 모델 추론 latency, data loader, GPU 학습 시간, 검출 정확도 향상이라는 주장은 릴리스에 없다.

### 추론과 최소 실험

- **진단:** 시각화가 느린 학습/검증에서는 사용자가 전체 pipeline이 느리다고 오판할 수 있다.
- **가설:** 동일 prediction 결과를 사용하면 8.4.201은 이미지·mask가 많은 결과의 plotting 시간을 유의미하게 낮추되, detector 출력은 바꾸지 않아야 한다.
- **최소 실험:** 태그 `v8.4.201`에서 10개 고정 prediction을 대상으로 `Results.plot(pil=True)`만 구버전과 비교하고, 출력 이미지 hash·검출 tensor·plot wall-clock을 분리 기록한다. 모델 추론이나 학습 wall-clock은 이 시험의 성공 지표로 쓰지 않는다.
- **GO:** detector 출력은 같고 plotting 시간만 개선될 때. **KILL:** 예측 결과나 export 결과가 달라지거나 라이선스 검토가 미완료일 때.
- **운영 판단:** 연구 실험 가치 4/5, 재현성 4/5, 신규성 3/5, 즉시 실용성 4/5다.
- **가중치·의존성·하드웨어:** 새 모델 weight는 릴리스에 포함되지 않았고, plotting 검사 자체는 GPU가 필수라고 확인되지 않았다. 설치는 가상환경에서 고정 태그로만 검토하며 이번 실행에서 패키지 설치는 하지 않았다.
- **보안·호환성:** SBOM 해시를 확인할 수 있는 점은 장점이다. AGPL-3.0은 재배포·서비스 통합 전에 별도 라이선스 검토가 필요하다. ONNX/TensorRT 등 개별 export 경로의 이번 버전 호환성은 이번 실행에서 재검증하지 않았다.

## 3. System One Bench 1.13.0 — 비전 평가 artefact

**공식 출처:**  
- https://github.com/alilibx/system-one-bench/releases/tag/v1.13.0  
- https://github.com/alilibx/system-one-bench  
- https://github.com/alilibx/system-one-bench/blob/main/LICENSE

### 사실

- `v1.13.0`은 2026-11-02 공개됐고, 리포지토리 코드는 Apache-2.0이다.
- 릴리스는 Fastino GLiDE 자체 API를 같은 요청 본문으로 3,250 text cases와 5개 Vision Index 데이터셋에서 평가했다고 설명한다.
- 릴리스의 표에는 Index 84.1(35개 중 2위), Vision Index 82.5(13개 중 7위), 두 번째 실행 84.13, 4,850개 중 7개 의사결정 변화가 기록돼 있다.
- 같은 릴리스는 Arabic picture 51.5와 같은 tweet text 73.5를 비교해 22포인트 차이를 보고한다.
- 저장소는 동일 요청·SHA data lock을 재현 기준으로 두며, 외부 모델 평가는 OpenRouter API key가 필요하다고 문서화한다.
- GLiDE는 API 대상이고, open-weight V1.2와 동일한 artifact로 간주하면 안 된다.

### 저자 주장

- 릴리스는 3.6% calibration과 호출 1,000회당 $0.017을 제시한다. 또한 latency는 환경 차이 때문에 리더보드 비교에 포함하지 않았다고 명시한다.

### 추론과 최소 실험

- **진단:** vision leaderboard는 모델 weight 품질, API serving 조건, 데이터 락을 혼합해 해석하기 쉽다.
- **가설:** 요청 body와 data lock SHA를 먼저 검증하면 API 모델을 실제로 호출하지 않고도 benchmark drift를 감지할 수 있다.
- **최소 실험:** `v1.13.0` checkout에서 Vision Index fixture의 lock·request schema만 검사한다. API key를 넣거나 외부 모델을 호출하지 않는다.
- **GO:** 공개된 lock과 request schema가 일관될 때. **KILL:** API 모델과 open-weight 모델의 provenance가 섞이거나 재현에 필요한 비공개 입력이 확인될 때.
- **운영 판단:** 연구 실험 가치 3/5, 재현성 4/5, 신규성 3/5, 즉시 실용성 3/5다. 객체 검출/분할의 표준 훈련 저장소로 사용할 대상은 아니다.
- **가중치·의존성·하드웨어:** 새 CV model weight 배포는 확인되지 않았다. 외부 API key가 필요하며 GPU/VRAM 요구사항은 공개 원문에서 확인하지 못했다.
