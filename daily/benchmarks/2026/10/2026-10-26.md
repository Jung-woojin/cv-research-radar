## 1. AnyGameRenderer — 생성 비디오 평가가 “보기 좋은가”에서 “개체가 맞게 살아 있는가”로 이동

**확인된 사실.** 논문은 59개 held-out case와 753개 annotated entity로 구성된 entity-level benchmark를 제시한다. 구성은 Unreal Engine two-stream 11개, 실제 게임 기록 14개, GEAR multi-stream 34개다. 모든 모델은 같은 seed, 20 sampling steps, 같은 caption을 사용한다. 지표는 temporal match, position match, unrendered rate, hallucination rate이며, 보조 지표로 on-time appearance, never appears, missed count changes를 둔다. 생성 결과의 개체는 SAM3 open-vocabulary segmentation과 tracking으로 찾고, Hungarian matching 뒤 IoU 0.3 이상 또는 중심 오프셋 조건을 만족해야 match로 인정한다. [논문](https://arxiv.org/abs/2610.31466) · [HTML 원문](https://arxiv.org/html/2610.31466) · [공식 코드](https://github.com/AlayaLab/AnyGameRenderer)

**저자 주장과 수치.** zero-shot base 대비 temporal match는 50.9%에서 62.9%, position match는 57.1%에서 61.9%, unrendered rate는 4.1%에서 2.9%, hallucination rate는 52.1%에서 46.0%로 변했다. 75개 count-change event 중 missed rate는 34.7%에서 21.3%로 낮아졌다. 다만 실제 게임 14개에서는 temporal match가 46.5%에서 51.1%로만 상승했고 missed count change는 20.0%로 동일했다. 또한 GT RGB를 동일 detector/matcher에 통과시킨 `GT floor`의 전체 temporal match가 80.9%이고 hallucination rate가 34.1%라서, 측정 파이프라인의 상한·오차가 크다.

**진단.** 기존 frame-level perceptual metric은 entity가 늦게 등장하거나 하나 더 생겨도 영상 전체가 그럴듯하면 높은 점수를 줄 수 있다. 이 benchmark는 게임 상태 보존 실패를 개체 단위로 분리한다.

**가설.** video-to-video 생성에서 사용자 체감 실패는 평균 화질보다 작은 개체의 생멸 시점과 count 변화에서 더 먼저 드러난다. 특히 실제 영상처럼 detector가 불안정한 도메인에서는 metric noise가 개선 폭을 가릴 수 있다.

**최소 실험.** 공개 예제 중 count-change가 있는 10개 clip을 고르고, base와 fine-tuned 결과에 동일 detector를 적용한다. 자동 missed count change와 사람이 세는 개체 수 오차를 함께 기록한다. 두 지표의 순위가 일치하지 않으면 detector-free point/track 보조 지표를 추가한다.

**판정.** **중요한 benchmark 이동**이다. 다만 새 SOTA 숫자보다 “entity lifecycle을 별도 평가한다”는 설계가 핵심이며, 실제 게임 split의 작은 개선과 GT floor를 함께 보고해야 한다.

## 2. BrickWright — 3D 생성 benchmark에 실행 가능한 물리 validator가 들어옴

**확인된 사실.** BrickWright는 BrickNet-512의 512개 텍스트 프롬프트를 사용한다. 물리 유효성은 실제 부품 사용, collision 없음, floater 없음, 가능한 경우 단일 connected component로 정의된다. 같은 에이전트에서 assembly API와 validator를 제거한 ablation이 있으며, prompt adherence는 VQA·Perception Encoder·SigLIP2 지표로 함께 보고한다. [논문](https://arxiv.org/abs/2610.31651) · [HTML 원문](https://arxiv.org/html/2610.31651) · [공식 프로젝트/코드](https://avalovelace1.github.io/brickwright/)

**저자 주장과 수치.** 일반 도구만 쓴 baseline의 valid rate는 GPT-6 Luna 0.086, GPT-6.1 Sol 0.641, GPT-6 Astra 0.693이었다. BrickWright full은 세 모델과 Claude Haiku 5.5에서 모두 1.000을 기록했다. Luna의 full 설정은 평균 4.62회 validate call, 415초, $0.03으로 보고됐고, Astra full은 2.40회, 267초, $1.28이었다. Luna에서 validator 제거 시 valid rate는 0.529, assembly API 제거 시 0.996이었다. Sol에서는 validator 제거 시 0.779, assembly API 제거 시 1.000이었다.

**같은 조건 비교.** 에이전트별로 동일 BrickNet-512 prompt와 validator 기준을 쓰므로 full/ablation 비교는 강하다. 그러나 모델 간 비용·시간 비교는 모델 가격과 harness가 다르므로 방법 효과와 모델 효과를 섞어 해석하면 안 된다. specialized model인 BrickGPT의 valid 0.990은 높은 물리 유효성에도 prompt adherence가 훨씬 낮아, valid rate 단독 순위가 품질 순위가 아님을 보여준다.

**진단.** 3D 생성 benchmark가 렌더링 유사도만 측정하면 조립 불가능한 결과를 통과시킨다. 반대로 validator만 최적화하면 단순하지만 유효한 구조로 도피할 수 있다.

**가설.** 구조 생성에서는 학습 규모보다 도메인 API와 검증 feedback loop가 물리 위반을 더 싸게 줄인다. 다만 실제 중력 안정성·하중·조립 순서는 현재 validator 밖이어서 100%를 현실 물리 성공률로 읽으면 과대평가다.

**최소 실험.** 공개 코드에서 20개 prompt를 stratified sample로 뽑아 `full`, `validator off`, `assembly API off`를 한 모델로 실행한다. valid rate, unique parts, prompt similarity, validate call 수를 함께 기록하고, 유효하지만 지나치게 단순화된 결과는 사람이 별도 표기한다.

**판정.** **평가 harness가 성능의 일부가 되는 이동**이다. 재현 시 모델명보다 validator의 검사 범위와 실패 후 재시도 budget을 먼저 고정해야 한다.

## 3. Progress Probes P² — VLA 실패 감지를 외부 VLM 점수에서 내부 상태의 시간 궤적으로 이동

**확인된 사실.** P²는 open-source VLA π0.5의 내부 activation에서 정규화된 task progress를 예측하는 선형 probe다. 학습에는 성공 demonstration만 사용한다. 실험은 600개 rollout에서 episode-level과 state-level failure AUROC를 측정하고, 6개 task 중 3개를 unseen으로 두는 모든 20개 split을 평가한다. detection time은 5% false-positive rate에서 episode 진행 비율로 잰다. [논문](https://arxiv.org/abs/2610.31613) · [HTML 원문](https://arxiv.org/html/2610.31613)

**저자 주장과 수치.** 전체 평가에서 P²는 episode AUROC 0.909, state AUROC 0.788을 기록했다. unseen-task 평균은 0.900/0.794였다. 같은 unseen 조건의 SAFE-MLP는 0.896/0.866, SAFE-LSTM은 0.859/0.803, FIPER(ACE)는 0.843/0.800으로 보고됐다. P²는 episode의 75% 지점에서 TPR 0.54, 종료 시 0.64를 기록했고 평균 detection time은 0.60이었다. 논문은 probe가 약 2K parameters이며 fine-tuned Robometer의 4B parameters보다 10,000배 이상 빠르다고 주장한다.

**같은 조건 비교.** 동일 rollout에서 discriminability를 비교한 부분은 비교 가능성이 높다. 그러나 Robometer zero-shot/fine-tuned와 SAFE는 학습 데이터 요구가 다르고, P²는 성공 데이터만 쓴다는 점이 장점인 동시에 학습 조건을 완전히 동일하게 만들지 않는다. state AUROC에서는 SAFE 계열이 더 높으므로 “전반적 우위”가 아니라 episode-level 효율과 성공-only training의 trade-off로 읽어야 한다.

**진단.** terminal success 하나만 보면 실패를 언제 감지했는지 알 수 없다. 외부 VLM monitor는 계산 비용이 크고, failure label을 모으는 것도 비싸다.

**가설.** 성공 rollout의 progress trajectory만으로도 deadlock·진행 지연을 포착할 수 있지만, 갑작스러운 마지막 단계 실패나 정상적으로 느린 실행에는 약할 수 있다.

**최소 실험.** 한 manipulation task에서 성공 30개로 probe를 학습하고, 성공 10개·deadlock 10개·late-stage drop 10개를 평가한다. episode AUROC와 함께 5% FPR의 detection time, 실패 유형별 recall을 보고한다. progress가 느린 성공을 hard negative로 반드시 포함한다.

**판정.** **runtime benchmark의 축이 정확도에서 조기성·비용·failure-data 의존성으로 넓어졌다.** 다른 backbone·embodiment에서 그대로 유지되는지는 미확인이다.

## 4. OpenTac — 촉각 benchmark가 고정 센서 성능에서 geometry-aware 전이와 sampling budget으로 확장

**확인된 사실.** OpenTac은 31개 fabricated board의 설계 규칙 통과를 확인하고 네 가지 실제 robot embodiment에서 시험했다. cross-sensor transfer는 4개 skin, 5개 object, 95개 위치, 1–8 N 조건에서 5,290개 예측을 만든다. metric은 한 pitch blur와 peak의 25% threshold 뒤 active-taxel shape F1이다. 32×32, 1024-taxel skin의 adaptive acquisition은 update당 16 taxel을 읽을 때 1,286 Hz, full raster는 67 Hz다. [논문](https://arxiv.org/abs/2610.31661) · [HTML 원문](https://arxiv.org/html/2610.31661) · [공식 프로젝트/코드](https://opentac.github.io/)

**저자 주장과 수치.** geometry와 calibration을 쓰는 transfer의 median F1은 0.750으로, resize+manifest 0.714와 geometry 없는 bilinear resize 0.634보다 높았다. 공통 support에서는 0.788로 same-skin repeatability 0.800에 근접했다. load가 있는 bimanual grasp 20회에서 OpenTac-3D는 16회 cup을 40초 유지하고 slip 2.6±1.2 cm를 기록했다. F/T sensor와 OpenTac-1D는 각각 9회 유지, slip 5.5±1.3 cm와 5.8±2.1 cm였다. adaptive sampling은 19.2× rate 증가를 보였고, 30 cm tennis-ball drop에서 raster는 6번 impact 중 2번만 잡은 반면 M=16–256 조건은 조건별 3번을 모두 탐지했다.

**같은 조건 비교.** transfer baselines는 동일 prediction set과 metric을 사용해 비교 가능하다. grasp 조건도 trajectory·gain·2.5 N nominal grip을 고정했다고 명시한다. 반면 sampling rate 향상은 읽는 taxel 수를 줄인 결과라 공간 완전성과 속도 사이 교환이며, 1,286 Hz를 full-field 1,286 Hz로 해석하면 안 된다.

**진단.** 촉각 학습 결과가 센서 배치와 해상도에 과적합되면 새 gripper로 옮길 때 benchmark가 붕괴한다. 또한 full raster 평균 주파수는 짧은 접촉을 놓칠 수 있다.

**가설.** 물리 좌표와 local frame을 명시한 sensor manifest는 learned representation 없이도 센서 간 shape transfer의 강한 baseline이 된다. 고속 partial scan은 sparse contact에는 유리하지만 넓은 접촉에서는 이점이 줄어든다.

**최소 실험.** 서로 다른 pitch의 두 skin에서 동일 10개 위치·3개 힘으로 contact map을 수집한다. raw resize, manifest transfer, same-skin repeatability를 같은 threshold sweep으로 비교하고, F1뿐 아니라 force integral error도 추가한다. adaptive budget은 16/64/full 세 조건에서 3 ms impulse recall과 spatial coverage를 함께 기록한다.

**판정.** **센서 benchmark의 외삽 조건이 명시되기 시작한 의미 있는 이동**이다. 다만 논문 스스로 force magnitude transfer와 sim-to-real policy transfer를 검증하지 않았다고 제한한다.

## 공통 해석

### 무엇이 실제로 변했나

1. 평가 대상이 최종 출력 한 장·한 점수에서 **시간 궤적과 구조적 제약**으로 이동했다.
2. benchmark harness가 수동 채점 대신 detector, validator, probe, sensor manifest 같은 실행 가능한 도구를 포함한다.
3. 같은 평균 성능이어도 실패 시점, 물리 위반, 개체 수 변화, sensor geometry 변화에서 순위가 달라질 수 있다.

### 의미 있는 변화와 노이즈 구분

- **의미 있음:** 동일 입력·seed·budget 또는 동일 prediction set에서 새 지표가 기존 방법의 숨은 실패를 드러낸 경우.
- **보류:** 저자 방법만 새 metric에 최적화되어 있고 독립 재현이 없는 경우.
- **노이즈 가능성:** 작은 split에서 detector 기반 metric의 측정 상한이 낮거나, 100% validator pass를 실제 물리 성공으로 확장 해석하는 경우.

### 재현 시 고정해야 할 변수

- 생성 비디오: backbone, 해상도, sampling steps, seed, caption, detector 버전.
- 3D 조립: agent model·reasoning effort, tool budget, validator 버전, retry count, 부품 catalog.
- VLA monitor: backbone layer, success-demo 수, threshold calibration, task split, FPR.
- 촉각 전이: taxel pitch, calibration, contact pose, blur/threshold, sampling budget.

## 오늘의 benchmark signal 3개

1. **Entity/structure-level metric이 frame-level 평균을 대체하기 시작했다.** 작은 개체와 물리 제약을 별도 축으로 보지 않으면 개선을 잘못 읽을 가능성이 크다.
2. **검증 가능한 도구가 benchmark 성능을 크게 바꾼다.** BrickWright와 P² 모두 더 큰 모델보다 도메인 validator·내부 probe가 효율적인 경우를 보여준다.
3. **외삽 조건을 split 이름보다 명시적으로 적어야 한다.** unseen task, real-game source, 다른 sensor pitch처럼 무엇이 바뀌었는지를 표에 고정해야 결과가 재사용된다.

## 내 연구에 바로 연결되는 포인트

- detection/grounding 연구라면 mAP 하나에 더해 **개체의 등장·소멸 시점, count-change recall, hallucinated track rate**를 작은 동영상 subset에 추가한다.
- VLM/VLA 연구라면 failure label을 대량 수집하기 전에 성공 trajectory로 linear probe를 붙이고, **AUROC와 detection time을 함께** 본다.
- 3D·robotics 연구라면 결과물 metric 옆에 실행 가능한 validator를 두고, validator가 검사하지 않는 물리 조건을 명시한다.
- sensor·remote-sensing domain shift 연구라면 resize baseline 외에 좌표계·해상도 metadata를 쓰는 geometry-aware baseline을 둔다.
- 오늘 권장하는 첫 실험은 AnyGameRenderer식 10-clip count-change audit다. annotation 부담이 작고, 기존 frame metric이 놓치는 오류를 하루 안에 확인할 수 있다.
