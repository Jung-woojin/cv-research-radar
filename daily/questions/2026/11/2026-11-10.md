## Q1. Phrase delimiter 하나의 position-id 변화가 open-vocabulary grounding의 phrase별 localization을 바꾸는가?

1. **문제 정의:** transformers v5 Grounding DINO에서 delimiter (. 또는 ?)의 position id가 0으로 처리되는 경로가 phrase별 box selection을 바꾸는지 묻는다.
2. **왜 지금 가치가 있는가:** 공식 issue는 v5.x와 v4의 position-id 차이, encoder text-memory 차이, object-detection test의 출력 차이를 함께 제시한다. [공식 issue #50465](https://github.com/huggingface/transformers/issues/50465)
3. **직접 근거:** issue 작성자의 환경에서 IDEA-Research/grounding-dino-tiny와 multi-phrase prompt의 재현이 제공됐지만, maintainer merge와 독립 재현은 아직 없다.
4. **핵심 가설:** phrase delimiter의 위치 embedding 오류는 긴 prompt일수록 phrase-specific attention을 흐려, 전체 AP보다 phrase별 false negative를 먼저 키운다.
5. **최소 실험(MVP):** 이미지 20장, phrase 수 1/3/8의 prompt set에서 v4 reference, v5 current, delimiter patch를 비교한다.
6. **baseline·dataset:** Grounding DINO tiny; COCO val의 category phrase subset과 동일 image/prompt/weight를 고정한다.
7. **성공/실패 metric:** phrase별 recall, box IoU, text-memory max-absolute difference, 전체 AP. version 간 비교는 preprocessing이 달라질 수 있어 **not strictly apples-to-apples**로 표시한다.
8. **compute 난이도:** **1/5** — RTX 5060 Ti 8GB에서도 inference만으로 가능하다.
9. **novelty 위험:** 이미 알려진 implementation bug의 단순 재현으로 끝날 위험이 있다. phrase complexity와 evidence stability라는 분석축이 추가 기여가 되어야 한다.
10. **4–8주 내 논문화 가능성:** **중간** — 여러 grounding model과 tokenizer에 일반화할 수 있을 때만 workshop/analysis paper 범위를 넘는다.
11. **negative result의 결론:** patch가 phrase별 성능을 바꾸지 않으면, 해당 bug는 output-sensitive benchmark가 아닌 implementation parity 문제로 범위를 좁힐 수 있다.
12. **점수:** novelty **4/5**, feasibility **5/5**, compute efficiency **5/5**, publication potential **3/5**.

## Q2. 같은 ONNX detector가 CPU와 MPS/CoreML provider에서 다른 prediction을 내는 현상을 자동 검출할 수 있는가?

1. **문제 정의:** export artifact hash가 같아도 provider와 graph format이 바뀌면 crash 또는 prediction drift가 생기는지를 runtime contract로 검증한다.
2. **왜 지금 가치가 있는가:** Ultralytics는 정적 ONNX semantic export의 MPS 오류와 CPU/MPS drift를 해결하는 PR을 11월 9일 병합했다. [공식 PR #27117](https://github.com/ultralytics/ultralytics/pull/27117)
3. **직접 근거:** PR 작성자는 YOLO26n ONNX, ORT 1.31.1, Apple M5 Pro 환경에서 task별 전후 차이를 제시했다. 다른 hardware와 dynamic export까지의 일반화는 미확인이다.
4. **핵심 가설:** provider drift는 output tensor 평균오차보다 “실행 가능/불가능”과 task-specific structural error로 먼저 포착된다.
5. **최소 실험(MVP):** 정적 ONNX detector/segmenter 2개와 이미지 30장을 CPU, MPS/CoreML에서 실행하고 execution status, box matching, mask disagreement를 기록한다.
6. **baseline·dataset:** Ultralytics export와 COCO-derived 30-image slice; 동일 opset, input size, NMS flag, runtime version을 manifest로 고정한다.
7. **성공/실패 metric:** crash rate, matched-box IoU, score rank correlation, mask pixel disagreement, warm latency. provider가 다르므로 정확도 비교는 **not strictly apples-to-apples**다.
8. **compute 난이도:** **2/5** — MPS 장비 접근이 필요하고 GPU 메모리는 작다.
9. **novelty 위험:** 단일 framework의 regression test가 될 수 있다. artifact/provider manifest와 failure taxonomy가 framework-independent해야 한다.
10. **4–8주 내 논문화 가능성:** **중간** — PyTorch/ONNX/CoreML/TensorRT로 확장해 reproducibility benchmark가 되면 가능하다.
11. **negative result의 결론:** parity가 안정적이면 provider contract의 필요성보다 PR의 특정 static semantic 경로가 원인임을 뒷받침한다.
12. **점수:** novelty **3/5**, feasibility **4/5**, compute efficiency **4/5**, publication potential **3/5**.

## Q3. prediction NMS IoU 기본값 변경이 small/crowded object의 모델 순위를 바꾸는가?

1. **문제 정의:** inference default NMS IoU가 0.7에서 0.5로 바뀔 때, detection quality가 아니라 suppression policy가 crowded/small-object 결과와 rank를 얼마나 변화시키는지 분리한다.
2. **왜 지금 가치가 있는가:** Ultralytics v8.4.208은 predict NMS IoU default를 0.5로 바꿨고 validation default는 0.7로 유지한다고 공지했다. [공식 release v8.4.208](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.208)
3. **직접 근거:** release는 crowded objects가 더 많이 suppress될 수 있고 필요 시 설정을 조정하라고 명시한다. 특정 dataset에서의 정확도 개선/저하는 공지에서 확인되지 않았다.
4. **핵심 가설:** 객체 중심거리와 box overlap이 높은 stratum에서 default 차이의 효과가 집중되고, validation/predict mismatch가 deployment ranking을 바꾼다.
5. **최소 실험(MVP):** 같은 checkpoint로 NMS 0.5/0.7을 paired inference하고 object size와 nearest-neighbor overlap으로 결과를 층화한다.
6. **baseline·dataset:** YOLO baseline; VisDrone 또는 UAVDT의 작은/인접 객체 subset과 COCO crowded subset.
7. **성공/실패 metric:** AP/AR, count error, duplicate/over-suppression rate, model rank correlation. input size, confidence threshold, TTA를 고정하지 않으면 **not strictly apples-to-apples**다.
8. **compute 난이도:** **2/5** — pretrained inference 중심이다.
9. **novelty 위험:** threshold sweep 자체는 새롭지 않다. 작은 객체·counting·default-policy mismatch를 함께 분석해야 한다.
10. **4–8주 내 논문화 가능성:** **중간** — multiple detector와 aerial dataset에서 rank instability를 보이면 evaluation note가 가능하다.
11. **negative result의 결론:** 순위·count가 안정적이면 이 default 변화는 특정 crowded regime의 운영 이슈로 한정된다.
12. **점수:** novelty **3/5**, feasibility **5/5**, compute efficiency **5/5**, publication potential **3/5**.

## Q4. 좌표 정답과 semantic attribute를 함께 쓰면 VLM의 “맞은 답”과 “맞은 근거”를 분리할 수 있는가?

1. **문제 정의:** point/coordinate 답과 element-level semantic attribute를 동시 평가해, final answer 정확도만으로 놓치는 evidence-grounding 오류를 측정한다.
2. **왜 지금 가치가 있는가:** V-Perception-40K viewer는 36.7k-row split과 image/question/answer/python_code/element_arrtibute 필드를 공개한다. [공식 dataset viewer](https://huggingface.co/datasets/We-Math/V-Perception-40K)
3. **직접 근거:** viewer의 예시는 좌표 답과 point type·좌표·semantic을 함께 보인다. dataset license, immutable revision, 전체 sampling policy는 이번 확인만으로 확정하지 못했다.
4. **핵심 가설:** coordinate answer가 맞아도 semantic attribute alignment가 낮은 사례는 shortcut 또는 format matching에 의해 과대평가될 수 있다.
5. **최소 실험(MVP):** 500개 예제를 무작위 고정하고 answer-only score와 coordinate tolerance + attribute agreement를 나란히 계산한다.
6. **baseline·dataset:** 공개 split의 V-Perception-40K 500-example fixed sample; coordinate-aware prompting을 하지 않은 VLM과 structured-output prompting VLM을 비교한다.
7. **성공/실패 metric:** answer exact match, coordinate distance, attribute F1, answer–evidence disagreement rate. sampled shard는 전체 split과 **not strictly apples-to-apples**다.
8. **compute 난이도:** **2/5** — API 또는 작은 VLM inference와 parsing이 핵심이다.
9. **novelty 위험:** dataset viewer field를 새 metric으로 과해석할 수 있다. annotation quality audit과 parse-failure 분리가 필요하다.
10. **4–8주 내 논문화 가능성:** **중간** — natural-image grounding benchmark로 전이 가능함을 보여야 한다.
11. **negative result의 결론:** answer score와 evidence score가 항상 함께 움직이면, 이 schema에서는 별도 evidence metric의 추가 가치가 작다는 유용한 결론이 된다.
12. **점수:** novelty **4/5**, feasibility **4/5**, compute efficiency **4/5**, publication potential **4/5**.

## Q5. original/edited image와 tool code trace는 counterfactual visual reasoning을 검증하기에 충분한가?

1. **문제 정의:** image edit 전후와 tool/reasoning code가 함께 있는 데이터에서, 모델이 편집된 시각 증거에 맞게 답을 바꾸는지를 검증한다.
2. **왜 지금 가치가 있는가:** V-Interaction-400K viewer는 25개 train shard, original image code, edited image, tool code, CoT-with-code, answer 필드를 공개한다. [공식 dataset viewer](https://huggingface.co/datasets/We-Math/V-Interaction-400K)
3. **직접 근거:** viewer는 edit artifact와 code trace의 존재를 확인하지만, shard 간 중복·편집 성공률·정답 검증 정책은 이 실행에서 확인하지 못했다.
4. **핵심 가설:** counterfactual answer consistency는 final answer accuracy보다 visual evidence use를 더 직접적으로 측정하며, tool-code imitation과 실제 visual grounding을 분리한다.
5. **최소 실험(MVP):** 200 paired example에서 original/edited image를 같은 prompt에 넣고 answer flip consistency와 edit-target relevance를 수동 audit한다.
6. **baseline·dataset:** V-Interaction-400K 한 shard의 fixed 200-pair sample; image-only VLM, code-augmented prompt, no-image text baseline.
7. **성공/실패 metric:** expected answer-flip accuracy, invariant-case stability, edit-target region relevance, text-only gap. shard sample은 전체 400K와 **not strictly apples-to-apples**다.
8. **compute 난이도:** **3/5** — image inference와 paired parsing, 200-case audit이 필요하다.
9. **novelty 위험:** synthetic edit artifact나 answer leakage가 shortcut을 만들 수 있다. original/edited leakage 및 code-only baseline이 필수다.
10. **4–8주 내 논문화 가능성:** **중간~높음** — counterfactual grounding failure set을 별도로 구축하면 VLM reliability paper로 확장 가능하다.
11. **negative result의 결론:** text-only baseline도 동일한 flip consistency를 내면 visual intervention이 아니라 question/template leakage가 핵심이라는 결론을 낼 수 있다.
12. **점수:** novelty **5/5**, feasibility **3/5**, compute efficiency **3/5**, publication potential **4/5**.
