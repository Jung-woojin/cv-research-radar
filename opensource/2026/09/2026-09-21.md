## 1. D-FINE-seg — detector부터 배포까지 연결된 실험 후보

**변경·연결:** 기존 detection에 instance/semantic segmentation과 multi-backend deployment를 묶은 framework다. 해당 주의 v0.4.2 Release 이벤트를 확인했다. 논문 v1은 2026년 2월이므로 새 논문 출시와 새 package release를 구분한다. [공식 release](https://github.com/ArgoHA/D-FINE-seg/releases/tag/v0.4.2), [당시 README](https://github.com/ArgoHA/D-FINE-seg/blob/9edc7d0520852d46dca3e9365b5a7bc775036d3f/README.md)

**구현·재현:** Python package, C++ 배포 코드, scripts/tests/config와 export backend 안내가 존재한다. 당시 HF commit 93351f275ac9640b89ba89b3657b270e878279e7에서 detection/segmentation .pt 파일 14개를 확인했다. 이는 weight load 성공을 뜻하지 않는다. [당시 weight tree](https://huggingface.co/ArgoSA/D-FINE-seg/tree/93351f275ac9640b89ba89b3657b270e878279e7)

**설치·자원:** 당시 안내는 pip package와 backend별 extras다. 역사 재현은 위 SHA 또는 0.4.2를 고정하고 dependency lock을 확인해야 한다. PyTorch/ONNX/TensorRT/OpenVINO/CoreML/LiteRT 경로가 문서화돼 있으며 TensorRT engine은 대상 GPU에서 build한다. 정확한 최소 VRAM은 확인하지 못했다. MMDetection/timm의 drop-in plugin으로 확인된 것은 아니며, YOLO식 데이터 처리 및 자체 export를 별도로 점검한다.

**라이선스·유지보수:** 코드 Apache-2.0. 당시 tests와 changelog가 있다는 구조적 근거는 있지만 통과 여부와 issue 응답시간은 미확인이다. Gradio demo 문서는 기본 LAN 노출 및 경로 접근 위험을 명시하므로 trial은 localhost로 제한한다.

**진단 → 최소 실험:** detector forward만 비교하면 tiling·mask resize·postprocess 비용을 놓친다. 같은 100개 이미지, 해상도·precision·batch=1·threshold를 고정해 PyTorch와 ONNX의 end-to-end latency/P95·peak VRAM·box/mask output 차이를 기록한다. GO는 허용한 출력 오차 안에서 전체 지연 개선, KILL은 export 오차나 준비 비용이 이득을 상쇄하는 경우다.

## 2. VPRef — visual drift와 language drift를 나누는 remote sensing benchmark

**변경·연결:** 당시 README는 09/16 코드 공개를 명시하고, SAM3 기반 remote sensing referring segmentation 및 표현 생성 규칙을 제공한다. 09/18 공개 이벤트의 snapshot에서 configs, SAM3/LoRA 코드 및 scripts를 확인했다. [당시 코드](https://github.com/quanweiliu/VPRef/tree/a801eb6b4939d47bccc1728cb2967bc0e134bbf5), [논문](https://arxiv.org/abs/2609.16486)

**재현·weights/data:** README에는 Google Drive dataset 링크가 있지만 cutoff 당시 다운로드 파일 전체와 별도 finetuned checkpoint를 확인하지 못했다. 링크 존재를 dataset 검증 완료로 처리하지 않는다. 파라미터 수정량이 적다는 주장은 전체 SAM3 backbone의 VRAM이 작다는 뜻이 아니다.

**설치·호환성:** repo의 SAM3/LoRA 환경과 configs를 따라야 하며 README의 환경 안내는 상대적으로 제한적이다. MMDetection/Ultralytics/timm/HF 범용 adapter 호환은 확인하지 못했다. GPU/VRAM 및 fresh install 성공도 미확인이다.

**라이선스·품질:** README Apache-2.0 배지와 snapshot의 MIT LICENSE가 불일치한다. upstream SAM3와 원 데이터 권리는 별도로 따른다. 이 불일치를 근거 없이 Apache로 통일하지 않는다. prompt 규칙은 공개돼 있어 language generation bias를 조사하기 좋지만 재현 문서·checkpoint 접근은 먼저 확인해야 한다.

**진단 → 최소 실험:** 같은 tile에서 Standard/Complex 문장만 바꾸고, 같은 문장에서 spatial domain만 바꾸는 2×2 평가를 만든다. baseline은 같은 SAM3 checkpoint와 고정 resolution이며 mIoU·작은 객체 recall·실패 문장 유형을 기록한다. 데이터 접근 전에는 prompt/평가 구조만 검토한다. GO는 두 drift 효과가 분리되는 경우, KILL은 split 누출이나 문장 template shortcut이 대부분을 설명하는 경우다.

## 3. OPD-Aha — real-image와 visual-null teacher를 비교하는 distillation

**변경·연결:** 최초 코드 release 주장은 8/29이며 해당 주에는 9/16 공개 push를 확인했다. 따라서 “이번 주 처음 공개”가 아니라 관련 code/model 업데이트 후보로 다룬다. frozen visual teacher에 counterfactual input을 주어 visual evidence가 teacher distribution에 주는 차이를 학습한다. [당시 README](https://github.com/Echochef/OPD-Aha/blob/66982fbd74d533f66d7c14000c8506c950d0eb6a/README.md), [논문](https://arxiv.org/abs/2609.16459)

**재현·자원:** verl 기반 multi-node training, FSDP merge, vLLM serving, fine-grained perception/math evaluation scripts가 있다. HF의 9/16 commit에서 4B와 9B 각각 model.safetensors를 확인했다. [4B snapshot](https://huggingface.co/CewEhao/OPD-Aha/tree/48dd8825e7a5edc2f53dd144bc2db5869da2afae), [9B snapshot](https://huggingface.co/CewEhao/OPD-Aha/tree/ed87c7b2b3bda9c402c01fadfa617c6737e428a6)

**설치·호환성:** Python 3.12 환경, requirements, editable install, Ray·verl·vLLM을 사용하는 연구 stack이다. HF model과 OpenAI-compatible serving/evaluation interface가 있지만 evaluator/judge를 함께 준비해야 한다. 8GB GPU에서 full training 가능이라고 주장하지 않는다. 정확한 VRAM·quantized inference 조건은 미확인이다.

**라이선스·유지보수:** Apache-2.0 코드이며 base model·dataset의 별도 조건을 따른다. training/evaluation 경로가 분리돼 있다는 구조는 확인했지만 tests 통과·issue/PR 응답 상태는 검증하지 못했다.

**진단 → 최소 실험:** 학습 전에 50개 grounded 질문에 real image / null image / wrong image를 같은 prompt·decode budget으로 비교한다. 정답률과 evidence-sensitive answer change를 분리한다. GO는 실제 이미지에서만 정답과 grounding이 개선되는 경우, KILL은 null에서도 같은 이득이 생겨 language prior로 설명되는 경우다. 이 protocol은 제안이며 결과가 아니다.

## 4. PANORAMA — phrase와 mask proposal의 선택 문제

**변경·연결:** 9/16 공개 이벤트에 연결된 snapshot은 phrase-conditioned mask proposals에서 단일/여러/없는 region을 선택하는 panoptic grounded captioning 구현을 제공한다. README의 당시 paper 링크가 비어 있으므로 이후 채워진 arXiv URL을 당시 제공된 링크로 바꾸지 않았다. [당시 README](https://github.com/sarapieri/panorama_grounding/blob/3d655e3943ad423a10b2d9fb8e46647762957480/README.md)

**재현·weights/data:** code·requirements·train/eval 및 데이터 구성 안내가 있다. 당시 README는 모델·dataset 공개를 주장하지만 cutoff 시점의 HF 파일 tree 전체는 검증하지 못했다. 따라서 다운로드·weight load까지 즉시 재현 가능한 것으로 확정하지 않는다.

**설치·자원·호환:** Python 3.11, torch 2.6/CUDA12.4, xtuner와 caption metric용 Java8/NLTK dependencies를 안내한다. flash-attn 없이 SDPA 경로도 문서에 있다. 일반 detector보다 설치·평가 준비가 복잡하고 정확한 peak VRAM은 미확인이다. MMDetection/Ultralytics/timm adapter 호환도 확인되지 않았다.

**라이선스·품질:** repo 계열의 CC BY-NC 4.0 조건을 확인했으며 연구·비상업 범위 및 원 이미지 조건을 검토해야 한다. 당시 snapshot의 dependency 파일 존재를 확인했지만 installation test와 issue 활동 상태는 미확인이다.

**진단 → 최소 실험:** caption의 phrase가 맞더라도 mask 선택이 틀릴 수 있다. 같은 candidate masks에서 random / phrase-similarity / native selector를 비교하고 empty/multi-instance phrase를 따로 평가한다. GO는 selector가 이 두 failure subset에서 이득을 보이는 경우, KILL은 proposal recall이 ceiling을 결정해 selector 변화로 개선되지 않는 경우다.
