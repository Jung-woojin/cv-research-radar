## 1. Video-Arena — 비디오 이해를 ‘상태 갱신 추적’으로 분해

**무엇이 바뀌었나.** Video-Arena는 9개 경쟁 게임의 180개 golden-set task를 T1 사건 인지, T2 상태 변화 해석, T3 결과 상태 추적으로 연결한다. 정답은 game record/engine에서 만들며, 예측 시각이 정답 사건의 ±3초 안이고 tuple의 모든 필드가 맞아야 하는 strict tuple F1을 사용한다.

**조건과 수치.** native visual protocol은 1 FPS, 최대 256 frames, one-pass 답변이다. tool-assisted agentic protocol은 전체 video를 최대 200 turns·2시간 동안 탐색한다. 프로젝트 페이지가 보고한 최고 strict F1은 각각 13.2와 51.0이다. 같은 256-frame budget의 temporal ceiling은 90.2이고, visual protocol 평균은 4.6이다. 이는 모델 간 단순 순위보다 protocol gap이 훨씬 큰 benchmark 이동이다.

**동일 조건인가.** 두 protocol은 입력 접근권과 계산 예산이 다르므로 13.2→51.0을 동일 모델의 순수 시각 능력 향상으로 읽으면 안 된다. 저자들은 Claude-Opus-5.0이 visual 7.2에서 agentic 51.0으로 상승했다고 보고하지만, 이는 tool/harness가 포함된 system-level 결과다. 게임별 event density와 state label 공간도 달라 macro 결과만으로 일반 video VLM 우열을 확정하기 어렵다.

**진단 → 가설 → 최소 실험.** 진단은 모델이 사건을 봐도 그 결과 상태를 누적 유지하지 못한다는 것이다. 가설은 명시적 event ledger와 state-update memory가 T3 오류를 줄인다는 것. 최소 실험은 동일 256-frame 표본에서 (a) one-pass, (b) event timestamp scratchpad, (c) structured state table을 비교하고 T1/T2/T3 F1 및 누적 drift를 각각 기록하는 것이다.

**판정.** 연구 신호는 강하다. 자동 정답, protocol budget, tuple matcher가 공개됐다. 다만 game video의 구조성이 자연 video로 얼마나 전이되는지는 별도 검증이 필요하다.

- 공식 원문: https://arxiv.org/abs/2610.14158
- 프로젝트·protocol·dataset/code: https://videoarena-bench.github.io/

## 2. Token-Budgeted Candidate Retrieval — 3D grounding에서 ‘전체 graph’보다 후보 예산 통제가 핵심

**무엇이 바뀌었나.** 이 연구는 3D scene-grounded VLM에 전체 object graph를 넣는 대신 query당 제한된 후보 object만 검색해 넣는 평가를 제안한다. 핵심 평가는 downstream model을 바꾸기 전에 같은 object-token budget에서 retrieval recall과 grounding accuracy를 함께 보는 것이다.

**조건과 수치.** ScanRefer `gt_val`과 Nr3D/Sr3D의 scan-id 기준 사용자 정의 20% split, 총 35,504 query를 사용한다. 이 split은 공식 ReferIt3D validation이 아니다. ScanRefer R@10에서 additive noun matching 0.864, QCRR 0.626, MiniLM/BGE-small 0.911–0.913을 보고한다. Nr3D에서는 MiniLM/BGE-small이 0.941–0.947이다. 수정한 3DGraphLLM harness의 300-sample 점검에서 Acc@0.25는 full graph 0.67, 동일 object budget random 0.44, QCRR 0.56, MiniLM 0.67, oracle 0.70이다.

**동일 조건인가.** matched-budget 비교는 random/QCRR/MiniLM 사이에서만 직접적이다. full graph는 token 수가 더 크고, oracle은 실제 deployment가 아니다. 사용자 정의 Nr3D/Sr3D split 결과를 공식 leaderboard와 합치면 안 된다. n=300 downstream check는 탐색적 규모다. 논문은 protocol·retriever·per-query output 공개를 예고하지만, 오늘 확인 범위에서는 영구 release 상태를 확정하지 않았다.

**진단 → 가설 → 최소 실험.** 진단은 scene graph token이 많을수록 좋다는 가정이 attention dilution과 비용을 숨긴다는 것. 가설은 top-k recall이 충분하면 작은 후보 집합이 full graph 정확도를 유지한다는 것. 최소 실험은 ScanRefer에서 k={5,10,20,all}을 고정하고 recall@k, Acc@0.25, input tokens, latency, VRAM을 함께 그려 Pareto frontier를 재현하는 것이다.

**판정.** ‘같은 token budget’이라는 비교 축은 강한 신호다. 절대 성능 주장은 custom split과 작은 downstream subset 때문에 중간 신뢰도로 둔다.

- 공식 원문: https://arxiv.org/abs/2610.14207

## 3. SlideBench / SliderEdit++ — endpoint가 아닌 편집 궤적을 leaderboard 대상으로

**무엇이 바뀌었나.** SlideBench는 lighting, composition, camera, environment, character, style, object의 7개 범주와 57개 세부 범주, 각 5개 sample로 총 285개 편집 축을 만든다. 각 slider는 0~1 사이 8개 위치에서 렌더링하며, 단조 진행, 인접 frame의 perceptual/semantic uniformity, multi-slider disentanglement를 평가한다.

**조건과 수치.** SliderEdit++는 FLUX-Klein 4B, rank-32 LoRA, 8-step Euler, 8×H100에서 1,000 steps로 학습했다. 같은 Klein-4B로 재학습한 SliderEdit baseline도 포함해 regularizer 효과를 분리한다. 저자 표에서 overall score는 strongest prior 대비 상대 18.5% 개선이며, multi-slider score는 base SliderEdit 0.7097에서 0.8811로 상승한다. 3×–20× 속도 주장은 few-step backbone과 서로 다른 기존 방법의 latency 비교를 포함한다.

**metric 주의.** monotonicity 주 평가는 GPT-5와 Claude Opus 4.8 판단을 사용하고, continuity는 LPIPS·CLIP·SigLIP·DINOv2를 집계한다. 저자도 CLIP/SigLIP/BLIP feature가 미세한 disentanglement에 충분히 민감하지 않다고 적었다. 따라서 18.5%는 SlideBench의 composite score 안에서의 결과이며, 일반 편집 품질 18.5% 향상으로 확장하면 안 된다.

**진단 → 가설 → 최소 실험.** 진단은 endpoint-only metric이 중간 단계의 jump와 attribute leakage를 놓친다는 것. 가설은 trajectory regularization이 동일 endpoint 품질에서 step 간 변동을 줄인다는 것. 최소 실험은 동일 backbone·seed·8 positions에서 regularizer on/off를 비교하고, 자동 metric 외에 30개 축의 pairwise human preference와 worst-step regression을 함께 기록하는 것이다.

**판정.** 평가 대상이 ‘이미지’에서 ‘경로’로 이동한 점은 강한 신호다. proprietary VLM judge 의존성과 composite metric 민감도 분석이 재현성의 핵심 위험이다.

- 공식 원문: https://arxiv.org/abs/2610.14253
- 프로젝트: https://armanzarei.github.io/SliderEditPlusPlud/

## 4. RoboFake — deepfake detector의 OOD score를 합성 탐지로 오해하지 않기

**무엇이 바뀌었나.** FaceForensics++로 학습된 공개 detector 6개를 physical lip-sync robot, 같은 robot의 synthesized video, rendered robot face에 평가한다. 모든 threshold는 FaceForensics++ real human에서 5% FPR가 되도록 고정하고, robot 영상과 같은 처리를 거친 real human control을 둔다.

**확인된 결과와 저자 주장.** 해당 threshold에서 detector 3개는 physical robot frame 거의 전부를 flag하지만, 2개는 7% 미만을 flag한다. face-only 비교에서도 6개 중 3개가 synthesized robot보다 physical robot에 더 높은 fake score를 준다. 가벼운 JPEG 압축만으로 일부 detector의 robot frame 대부분이 threshold 아래로 내려간다. 저자 해석은 detector가 ‘합성 여부’보다 ‘사람 얼굴처럼 보이지 않음’에 반응한다는 것이다.

**동일 조건인가.** threshold와 matched human control은 잘 통제됐지만, detector별 architecture·training recipe가 같지 않아 detector 간 수치 순위를 일반화하면 안 된다. frame-level flag rate는 identity/video-level calibration을 대신하지 않는다. physical robot은 중요한 신규 OOD이지만 실제 공격 성공률 benchmark 전체를 대표하지 않는다.

**진단 → 가설 → 최소 실험.** 진단은 benchmark의 real/fake label과 detector가 실제로 학습한 anthropomorphic prior가 분리되지 않았다는 것. 가설은 robot realism과 compression 수준을 연속 변수로 넣으면 score가 synthesis flag보다 appearance distance에 더 강하게 반응한다는 것. 최소 실험은 동일 identity에서 physical/synthesized/rendered × JPEG quality를 factorial로 구성하고 AUROC 외에 5% FPR TPR, ECE, paired score delta를 보고하는 것이다.

**판정.** failure benchmark로서 강한 신호다. protocol과 code 공개가 명시됐지만, 현 시점 결과는 6개 detector와 제한된 robot domain에 국한된다.

- 공식 원문: https://arxiv.org/abs/2610.14269

## 5. GeoFix / FOCAL — FOV overlap을 보정한 4D geometry metric

**무엇이 바뀌었나.** GeoFix는 static region의 cross-view depth reprojection을 쓰되, 첫·마지막 camera field-of-view의 area-weighted IoU로 overlap을 구하고 reference video에서 score–overlap 추세를 적합해 빼는 FOCAL reward를 제안한다. 실제 video와 4D dataset에서도 overlap이 클수록 raw depth agreement가 좋아져 작은 camera motion이 좋은 geometry로 오인되는 현상을 확인했다.

**조건과 수치.** training-time 비교는 Wan2.2-TI2V-5B, 동일 SFT dataset·budget·stitched reconstructor, T2V-CompBench 200 prompts다. WorldScore 3D consistency는 Base 44.39, SFT 50.11, VIST3A 58.32, World-R1 42.26, GeoFix 61.60이다. 저자의 ‘39% 개선’은 Base 대비 상대치다. VBench official Quality Score는 0.7272→0.7588, 즉 +4.3% 상대 개선으로 보고된다. calibration ablation에서 γ=0은 VBench Avg 0.6802·Dynamic 0.395, γ=0.7은 0.6861·0.425다.

**동일 조건인가.** 동일 Wan2.2 계열 내 표는 비교 가능성이 높다. 반면 VGGRPO는 code/checkpoint가 없어 각자의 base 대비 상대 개선만 논문 간 비교했다. WorldScore도 dynamic mask를 text-grounded detector 대신 SegAnyMo로 바꾸고 camera/object control 항목을 제외했으므로 upstream leaderboard와 숫자를 그대로 합치면 안 된다.

**진단 → 가설 → 최소 실험.** 진단은 geometry reward가 camera-motion shortcut을 보상한다는 것. 가설은 FOV overlap을 층화하면 기존 metric 순위가 일부 뒤집힌다는 것. 최소 실험은 동일 video 집합을 overlap quartile로 나누어 raw reprojection·FOCAL·human geometry preference의 Spearman 상관을 비교하고, reward optimization 전후 camera motion magnitude도 함께 확인하는 것이다.

**판정.** 오늘 가장 직접적인 metric-confound 신호다. score 개선보다 ‘metric이 무엇을 보상하는가’를 밝힌 점이 중요하며, 다른 multi-view/novel-view benchmark에도 즉시 점검 가능한 통제 변수를 제공한다.

- 공식 원문: https://arxiv.org/abs/2610.14293
- 프로젝트: https://yeobinhong.github.io/GeoFix/

## 오늘의 benchmark signal 3개

1. **평가 예산을 결과와 함께 고정하라.** frame, token, turns, latency가 다르면 같은 metric 이름이어도 같은 경쟁이 아니다.
2. **nuisance variable을 metric 설계에 넣어라.** FOV overlap, robot appearance, compression처럼 label과 무관한 축이 점수를 지배할 수 있다.
3. **최종 결과보다 경로와 상태를 측정하라.** video state accumulation과 editing trajectory는 endpoint 정확도만으로 보이지 않는 오류를 드러낸다.

## 내 연구에 바로 연결되는 포인트

- 해무·해양 CCTV와 UAV 영상 평가에서 frame budget과 temporal state memory를 분리해 보고한다. 동일 clip을 sparse sampling과 event-ledger 조건으로 재평가하면 시간 누적 오류를 찾을 수 있다.
- small-object/grounding pipeline은 full proposal 입력과 top-k proposal을 **동일 token budget**으로 비교하고 recall, task AP/accuracy, latency를 한 표에 묶는다.
- 영상 복원·생성 평가는 최종 frame 지표 외에 trajectory smoothness, temporal drift, worst-frame 성능을 추가한다.
- domain shift 실험은 global AUROC만 보고하지 않고 운영 FPR에서 TPR·ECE·paired perturbation delta를 기록한다.
- multi-view/4D 지표는 camera overlap, motion magnitude, visible-area ratio로 층화해 metric shortcut 여부를 먼저 점검한다.
