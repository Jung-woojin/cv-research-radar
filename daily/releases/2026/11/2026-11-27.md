## 1. Ultralytics v8.4.220 — COCO 평가 경로 자체가 달라졌다

**확인한 사실.** [공식 release](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.220)는 11월 27일 03:16:50 KST 발행됐다. [annotated tag](https://api.github.com/repos/ultralytics/ultralytics/git/tags/6bec30e79d6cc90507ee01ea49af15d202bb27af)는 `6bec30e79d6cc90507ee01ea49af15d202bb27af`, 대상 commit은 `b62088e5cd032d92de9476ac84a00013b8da9256`이며 tag 서명은 `unsigned`다.

[8.4.219→220 diff](https://github.com/ultralytics/ultralytics/compare/v8.4.219...v8.4.220)와 [고정 detection validator](https://github.com/ultralytics/ultralytics/blob/b62088e5cd032d92de9476ac84a00013b8da9256/ultralytics/models/yolo/detect/val.py)에서 다음을 확인했다.

- 공식 COCO annotation 파일이 존재하고, `val2017.txt`, detect/segment/pose, `single_cls=False` 등 조건을 만족하면 JSON annotation을 읽는 분기를 사용한다.
- original-image 좌표와 JSON export의 box·score 정밀도를 공유한다. box 좌표는 소수 셋째 자리, score는 다섯째 자리로 반올림한다.
- crowd target을 일반 target과 구분하고 confidence stable ordering과 task별 detection limit을 적용한다.
- pose는 `num_keypoints==0`인 annotation을 별도로 ignore하며 공식 annotation의 area를 사용한다.
- segmentation은 해당 분기에서 native mask 처리 경로를 사용한다. 필요한 `faster-coco-eval>=1.6.7`을 사용할 수 없으면 YOLO text label 평가로 돌아가는 경고 분기가 있다.

**저자 주장.** tag/commit 메시지는 box·mask·keypoint mAP를 pycocotools와 machine precision까지 맞춘다고 설명한다. release는 crowd 및 keypoint 미표기 인물 처리를 강조한다. 이는 저자의 주장과 공개 테스트 범위이며 이번 실행의 독립 재현 결과가 아니다.

**주장과 artifact의 경계.** 모든 dataset과 설정에서 자동으로 COCO parity가 성립한다는 의미로 확대하면 안 된다. 공식 annotation의 존재, dataset 식별, single-class 설정, mask decoder 가용성에 따라 실행 경로가 다르다. 어제 보고서의 “AP 적분만 맞춰도 전체 pipeline은 다를 수 있다”는 진단에 대해 오늘 artifact는 실제로 더 많은 경로를 수정했다. 남은 차이가 없다는 결론은 같은 prediction·annotation·maxDet·area 조건으로 확인해야 한다.

특히 annotation 파일 유무만으로 평가 모집단과 ignore 규칙이 달라질 수 있다. 기존 text-label 평가와 새 JSON 평가를 그대로 비교하면 **not strictly apples-to-apples**다. backbone·weights·train data·pretraining이 같아도 evaluator가 바뀌었다는 점을 결과표에 기록해야 한다.

**추가 공개 코드: INT8 segmentation.** [고정 TensorFlow export 코드](https://github.com/ultralytics/ultralytics/blob/b62088e5cd032d92de9476ac84a00013b8da9256/ultralytics/utils/export/tensorflow.py)는 Edge TPU/ST Edge AI용 wrapper에서 mask coefficient를 16으로 나누고 prototype을 16배 한다. 실수 연산에서는 mask logits의 곱을 보존하면서 공유 INT8 range의 영향을 바꾸는 조치다. 양자화 후에도 동일하다는 보장은 아니다. release의 품질 향상 주장을 새 architecture나 모든 하드웨어의 속도 향상으로 옮기지 않는다.

**공개물·설치·자원·무결성·활동.** 새 weights/data 공개로 확인한 이벤트는 아니다. [pyproject](https://github.com/ultralytics/ultralytics/blob/b62088e5cd032d92de9476ac84a00013b8da9256/pyproject.toml)의 code license는 AGPL-3.0, Python은 ≥3.8이다. 비교 시 `ultralytics==8.4.219`와 `8.4.220`을 분리하고 torch·NumPy·mask decoder·reference evaluator 버전까지 기록한다. package pin만으로 전체 환경이 고정되지는 않는다.

release asset `sbom.spdx.json`의 API digest는 `sha256:ff238e4296cec9ba607fbd05fce0b6fbc015cc78c2a51c2d921bfcdfd501f7f7`이다. 이는 SBOM metadata이며 wheel checksum 또는 다운로드 후 검증값이 아니다. 비교 diff에는 평가·export 코드와 regression test 추가가 함께 존재한다. 관련 issue 전체가 해결됐다고 판단하지 않았다.

**추론 — 진단 → 가설 → 최소 실험, 10~30분 계획.**

1. 저장된 소수 COCO prediction과 동일 annotation을 이용해 crowd·미표기 keypoint·confidence tie·detection limit fixture를 만든다. 두 버전과 reference evaluator를 CPU에서 비교한다.
2. annotation JSON 존재/부재, `single_cls`, mask decoder 가용성을 하나씩 바꿔 실제 선택된 평가 분기를 기록한다. annotation을 삭제하는 대신 별도 fixture 디렉터리를 사용한다.
3. 같은 exported prediction에서 matcher·ignore·AP aggregation 차이를 분리한다. backbone, weights, split, resolution, precision, batch, TTA는 고정한다.
4. INT8은 우선 CPU의 작은 coefficient/prototype 배열로 float logits 보존을 확인한다. 실제 export·장치 실행은 별도 단계로 둔다.

**GO:** 공식 annotation 분기와 동일 prediction parity를 먼저 감사한다. CPU fixture에는 GPU VRAM이 필요 없다.  
**조건부 GO:** parity가 확인된 후 고정 checkpoint의 실제 validation과 장치별 INT8 품질을 측정한다. 실제 추론·export의 최소 GPU/VRAM은 이번 조사에서 확인하지 못했다.  
**KILL:** evaluator migration으로 생긴 점수 변화를 모델 학습 개선으로 보고하지 않는다.

## 2. Supervision 0.32.3 — crowd와 class ID 수정에도 남는 비교 조건

**확인한 사실.** [공식 release](https://github.com/roboflow/supervision/releases/tag/0.32.3)는 11월 26일 18:33:59 KST 발행됐다. [tag ref](https://api.github.com/repos/roboflow/supervision/git/ref/tags/0.32.3)는 commit `ded6656370bc3d5ebca87d8599689a323859b8e9`를 직접 가리킨다. 전날 0.32.2의 ViTPose·Qwen parser 수정과 구별되는 새 package release다.

**crowd-aware P/R/F1.** [PR #3071](https://github.com/roboflow/supervision/pull/3071)은 11월 25일 23:03:09 UTC merge됐다. [고정 shared metric 코드](https://github.com/roboflow/supervision/blob/ded6656370bc3d5ebca87d8599689a323859b8e9/src/supervision/metrics/_confusion_matrix_metric.py)는 crowd/ignore target을 정답 개수에서 제외하고, crowd에는 prediction 자체 면적 대비 겹침을 사용한다. crowd region은 여러 prediction을 흡수하지만 일반 ignore target은 일대일로 처리한다.

**저자 주장과 알려진 한계.** 저자는 COCO val2017의 무작위 500장, YOLO11n, confidence 0.25, micro averaging, reference area=all/maxDets=100 조건에서 수정 후 P/R/F1이 pycocotools counts와 일치한다고 보고한다. 이는 새 prediction을 학습한 결과가 아니라 scoring 수정이다. PR은 동시에 일반 greedy matcher가 최고 IoU 우선이고 COCO는 confidence 순서이므로 crowd가 없어도 불일치가 남는다고 명시한다. 따라서 특정 표의 일치를 모든 scene의 완전 parity로 해석하지 않는다. 공개 mask fuzz에도 matching-order 차이 한 사례가 남았다는 저자 보고가 있다. 이번 실행에서는 재현하지 않았다.

**VOC class ID.** [PR #3069](https://github.com/roboflow/supervision/pull/3069)는 11월 25일 22:58:29 UTC merge됐다. [고정 VOC loader](https://github.com/roboflow/supervision/blob/ded6656370bc3d5ebca87d8599689a323859b8e9/src/supervision/dataset/formats/pascal_voc.py)는 전체 class name을 정렬하고 각 detection의 ID를 재매핑한다. train/valid가 같은 class 집합을 갖지만 XML 등장 순서가 다른 경우의 semantic mismatch를 막는다.

단, split의 class 집합 자체가 다르면 정렬만으로 전역 ID가 같아지지 않는다. 이미 학습한 checkpoint와 export label이 이전 ID를 사용한다면 migration mapping이 필요하다. class name을 대조하지 않고 숫자 ID만 비교하는 방식은 여전히 위험하다는 것이 평가자의 추론이다.

**다른 출력 변경.** oriented soft-NMS는 axis-aligned envelope 대신 실제 회전 사각형 겹침을 사용하며 mask가 있으면 mask overlap이 우선한다. `KeyPoints.from_inference(num_keypoints=...)`는 trailing missing joint를 보존한다. 이는 어제의 `from_transformers` ViTPose 수정과 다른 entry point다. `JSONSink`는 non-finite float를 `null`로 저장하므로 Infinity 부호는 복구할 수 없다. 이런 변경도 모델 representation 개선으로 세지 않는다.

**설치·자원·공개물·무결성.** [고정 pyproject](https://github.com/roboflow/supervision/blob/ded6656370bc3d5ebca87d8599689a323859b8e9/pyproject.toml)는 MIT, Python ≥3.10이며 av ≥14.2, NumPy ≥1.21.2, SciPy ≥1.10 등을 선언한다. reference 비교에는 COCO extra의 pycocotools ≥2.0.11을 포함해 실제 설치 버전을 고정한다. `supervision==0.32.2`와 `0.32.3` 비교용 환경은 분리한다. 이 이벤트에서 새 weights·dataset artifact는 확인하지 않았다.

공식 GitHub wheel asset digest는 `sha256:9bd66ee8790f45002e1f1dc33d6ce40ae6f839bcda0ba2e1ba2b8b58461e74b0`이다. API metadata만 확인했으며 파일을 다운로드해 검사하지 않았다. PR #3071/#3069의 merge와 [공식 diff](https://github.com/roboflow/supervision/compare/0.32.2...0.32.3)의 코드·테스트를 확인했다. 저자는 #3071에서 기존 develop에도 나타나는 Windows test failure를 명시하므로 무조건적인 전체 환경 통과로 인용하지 않는다.

**추론 — 진단 → 가설 → 최소 실험, 10~30분 계획.**

1. **crowd fixture:** 일반 target 하나와 crowd 하나, crowd 내부 prediction 두 개를 고정한다. crowd flag 유무 및 ordinary ignore flag를 교차해 TP/FP/FN을 직접 확인한다.
2. **matching-order fixture:** 두 prediction이 하나의 target을 놓고 경쟁하며 confidence 순서와 IoU 순서가 반대가 되도록 한다. crowd 수정 후에도 reference와 차이가 남는지 검사한다.
3. **VOC fixture:** 동일 class 집합·등장 순서 반전과 일부 class가 빠진 split을 각각 만든다. load→name→export→reload에서 의미가 유지되는지 검사한다.
4. **OBB fixture:** edge만 접하는 두 회전 box와 실제 body가 겹치는 box를 비교한다. mask 유무까지 나눠 어떤 overlap이 쓰였는지 기록한다.

모든 fixture는 CPU로 가능하며 GPU VRAM이 필요 없다. 실제 모델 추론 자원은 사용 checkpoint별로 별도 확인해야 한다. 점수 비교에서 data/split, class mapping, evaluator, confidence threshold를 먼저 고정하고 backbone·pretraining·resolution·hardware·precision·batch·TTA도 기록한다.

**GO:** crowd와 class 의미 배선을 저장된 prediction으로 먼저 감사한다.  
**KILL:** 특정 COCO subset의 parity를 일반 matcher 전체의 parity로 확대하지 않는다. class vocabulary가 다른 split을 정렬만으로 정합하다고 선언하지 않는다.
