## 1. RF-DETR 1.12.1 — 고정 배치와 입력 검증을 먼저 검사

**새 공개 내용·시각 — 사실:** 릴리스는 2026-11-12 13:24:29 UTC, 즉 11월 12일 22:24:29 KST에 배포됐다. 고정 배치 predictor가 디렉터리·녹화 영상을 기본적으로 해당 크기로 묶도록 수정했다. 마지막 짧은 배치는 padding 없이 거부한다. 관련 PR #1695는 11월 9일 UTC에 병합됐으므로 신규 알고리즘 발견으로 세지 않는다. [릴리스](https://github.com/roboflow/rf-detr/releases/tag/1.12.1), [PR #1695](https://github.com/roboflow/rf-detr/pull/1695).

**코드 품질·재현성:** 입력 NaN·잘못된 학습 설정의 조기 오류, noncontiguous mask 평가 수정이 문서화돼 있다. PR에는 테스트 변경이 있지만 본 실행에서 테스트를 돌리지는 않았다. “예측 불변·메모리 감소”는 저자 주장으로 남긴다.

**라이선스·가중치:** package와 기본 Nano/Small/Medium/Large detection 및 segmentation 모델은 Apache-2.0으로 안내한다. `plus` 모델군은 별도 PML 1.0이다. 기존 pretrained 모델을 사용할 수 있으나 이번 patch의 신규 가중치는 확인하지 못했다. [tag 고정 README](https://github.com/roboflow/rf-detr/blob/1.12.1/README.md).

**설치·GPU:** 난이도 중간. Python ≥3.10, torch ≥2.2, torchvision ≥0.17, Transformers ≥5.1,<6이 명시돼 있다. export extras는 별도 환경으로 분리할 것을 제안한다. 최소 GPU/VRAM과 RTX 5060 Ti 8GB 적합성은 미확인이다. [의존성](https://github.com/roboflow/rf-detr/blob/1.12.1/pyproject.toml).

**호환·유지보수:** 자체 `rfdetr` API이며 Transformers backbone 의존성이 있다. MMDetection·Ultralytics·timm의 drop-in plugin으로 확인하지 않았다. 배포와 병합 PR은 유지보수 활동의 근거지만 장기 대응 속도를 보장하지 않는다.

**진단 → 가설 → 최소 실험 — 제안:** 영상 실패가 detector보다 batch 계약 위반 때문일 수 있다. 1.12.0/1.12.1, 동일 Small checkpoint·해상도·precision에서 batch=4로 8장과 9장을 각각 입력한다. 완료 frame 수, batch 오류, frame별 box/class/score를 기록한다. NaN 입력의 조기 거부도 별도로 시험한다.

**GO/KILL:** 8장 정상 완료와 9장 tail 거부가 명세에 맞고 정상 frame 출력이 유지되면 GO. 마지막 frame 유실이나 명시적 batch에서도 출력 회귀가 생기면 보류한다. 이는 탐지 정확도 향상을 입증하는 실험이 아니다.

**점수:** 실험 가치 5/5 · 재현성 4/5 · 신규성 2/5 · 실용성 5/5.

## 2. Ultralytics 8.4.215 — dense mask를 언제 만드는가

**새 공개 내용·시각 — 사실:** 2026-11-16 01:18:10 UTC, 즉 11월 16일 10:18:10 KST 배포. plot/save/device 이동과 FastSAM prompt 경로가 bounding box 내부 mask를 활용한다. `masks.data`를 요청하면 dense mask를 생성한다. PR #27216도 같은 날 병합됐다. [릴리스](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.215), [구현 PR](https://github.com/ultralytics/ultralytics/pull/27216).

**코드 품질·재현성:** PR은 변경 경로와 비교 설정을 공개한다. 출력·기본값 불변은 저자 주장이다. 새 architecture나 prediction default 변경은 이 릴리스에 포함되지 않는다. 지난주 8.4.208의 default 변경과 혼동하지 않는다.

**라이선스·가중치·설치:** AGPL-3.0 package이며 이 변경의 새 checkpoint는 확인하지 못했다. Python ≥3.8, torch·torchvision·OpenCV 의존성이 있고 Windows torch 2.4.0 제외 조건이 있다. 일반 추론 설치는 비교적 단순하고 export 추가 의존성은 별도다. [package manifest](https://github.com/ultralytics/ultralytics/blob/v8.4.215/pyproject.toml).

**GPU·호환·유지보수:** 최소 VRAM은 미확인이다. Ultralytics 내부 경로에 직접 적용된다. MMDetection·timm·Hugging Face 모델에 자동 적용되는 기능은 아니다. 여러 기여자의 merged PR과 연속 patch는 활동 근거이며, 공개 issue 개수만으로 품질을 판단하지 않았다.

**진단 → 가설 → 최소 실험 — 제안:** 고해상도 UAV/CCTV에서 OOM이 forward보다 후처리의 N×H×W 확장 때문일 수 있다. 동일 segmentation checkpoint·고정 영상·batch·precision에서 8.4.214/8.4.215를 비교한다. `plot()`, `.cpu()`, `masks.data`를 각각 새 process에서 실행하고 CUDA peak allocated, CPU RSS, mask IoU, box/class 대응, 처리 frame 수를 기록한다.

**GO/KILL:** 필요한 출력 경로에서 동등한 mask를 유지하며 peak memory가 줄면 GO. dense 접근을 포함한 모든 사용법의 절감을 기대하거나 mask/class 불일치가 생기면 보류한다. 해상도·검출 수·접근 경로가 다르면 **not strictly apples-to-apples**다.

**점수:** 실험 가치 5/5 · 재현성 4/5 · 신규성 3/5 · 실용성 5/5.

## 3. Open Vision Banana — 영역 오류와 색상 대응 오류 분리

**논문·실제 공개 — 사실:** arXiv v1 제출은 11월 11일 18:57:34 UTC, 즉 11월 12일 03:57:34 KST다. 코드·데이터 파이프라인·평가 공개 commit은 11월 13일 13:16:45 UTC다. 저장소의 이전 생성일을 코드 공개일로 쓰지 않는다. [논문](https://arxiv.org/abs/2611.15844), [공개 commit 94845ca](https://github.com/OpenVisionBanana/OpenVisionBanana/commit/94845cab7ffd0f7f9316a32ec38997adf9607091).

**새 내용·저자 주장:** FLUX.2 Klein 4B/9B를 perception에 미세조정하고 RGB 출력을 decode한다. 저자는 색상 legend를 바꾸어 반복 예측·투표하면 color–class binding 오류를 줄인다고 주장한다. 영역 품질과 label 오류를 구분할 수 있다는 점이 연구 가치다. [프로젝트 설명](https://openvisionbanana.github.io/).

**재현성·가중치:** final/intermediate/ablation checkpoint와 zero-shot/non-zero-shot 구분, 학습·평가 경로를 공개한다. 실제 다운로드·checksum 대조·논문 재현은 하지 않았다. 모델 카드는 fine-tuned transformer를 base pipeline에 넣는 구체적 subfolder 예제를 제공한다. [코드](https://github.com/OpenVisionBanana/OpenVisionBanana), [모델 카드](https://huggingface.co/FunAILab/Open-Vision-Banana).

**라이선스:** 코드는 Apache-2.0, 가중치는 FLUX Non-Commercial License, dataset은 각 원배포 조건이다. “fully open”이라는 저자 표현을 상업적 사용 허용으로 해석하지 않는다. [라이선스 원문](https://github.com/OpenVisionBanana/OpenVisionBanana/blob/94845cab7ffd0f7f9316a32ec38997adf9607091/LICENSE).

**설치·GPU·호환:** 난이도 높음. README는 CUDA 12.8용 PyTorch 2.11 pinned requirements를 안내하고, 모델 카드는 Diffusers와 CPU offload 예제를 제공한다. 최소 VRAM은 미확인이고 4B라는 이유만으로 8GB 적합성을 단정할 수 없다. Hugging Face/Diffusers 경로가 있으며 MMDetection·Ultralytics·timm plugin은 확인하지 않았다.

**유지보수:** 조회 시 code 공개까지 commit 3개와 open issue 2개가 보였다. issue는 demo·평가 확인 제안이며 maintainer의 독립 재현 인증이 아니다. 장기 유지보수 판단에는 이르다. [활동](https://github.com/OpenVisionBanana/OpenVisionBanana/commits/main/), [issues](https://github.com/OpenVisionBanana/OpenVisionBanana/issues).

**진단 → 가설 → 최소 실험 — 제안:** 예산·라이선스 확인 후 Cityscapes val의 고정 20장으로 동일 zero-shot checkpoint·seed·steps에서 단일 legend와 3개 legend 투표를 비교한다. mIoU와 class-agnostic foreground IoU, 경계 품질, wall time·VRAM을 따로 기록한다. mIoU만 개선되면 binding 교정 가설과 부합하며, 영역 개선까지 주장할 수는 없다.

**GO/KILL:** label 개선이 영역·시간 비용과 분리되고 반복 가능한 경우 GO. non-zero-shot이나 서로 다른 pass budget을 섞으면 보류한다. 타 방법과 training split·TTA·추론 예산이 다르면 **not strictly apples-to-apples**다.

**점수:** 실험 가치 5/5 · 재현성 3/5 · 신규성 5/5 · 실용성 2/5.
