## 1. EyeVLM-Data — 균형 평가와 원본 분포를 구분한다

**확인 사실·시점.** Zenodo record `24301723`은 11/17 생성됐고 `EyeVLM-Data.tar.gz` 36,506,441바이트와 MD5 `6ae794e01deed2b4b4a3e0f1683ee17b`를 게시한다. archive는 내려받지 않아 checksum을 재계산하지 않았다. 논문은 5월 공개됐고 GitHub README는 여전히 Coming Soon이므로 논문·코드·annotation 공개일을 합치지 않는다. [공식 metadata](https://zenodo.org/api/records/24301723) · [논문](https://arxiv.org/abs/2605.19859) · [GitHub](https://github.com/idiap/EyeVLM)

**규모·task·split·license·artifact — 저자 보고.** GazeFollow·VideoAttentionTarget·ChildPlay 기반 VQA JSON 31개와 사회적 시선 Parquet 18개다. gaze point·화면 안팎, LAH·LAEO·Shared Attention을 다루며 train/val/test와 논문의 1K 평가 subset 인덱스를 제공한다. 파일 수는 표본 수가 아니다. 이미지는 포함하지 않고 annotation은 CC BY-NC 4.0이다. 원본 이미지 접근·권리는 별도 확인해야 한다. [배포 설명](https://zenodo.org/records/24301723)

**label·bias·호환성 — 저자 보고.** 사회적 시선은 3프레임마다 하나를 남기고 invalid person ID, 정규화 head box의 폭이나 높이가 0.05 미만인 쌍을 제외한다. 음성 쌍을 무작위 축소해 양성:음성을 정확히 1:1로 맞춘다. 원본 test 양성 비중은 약 2~14%라고 설명한다. 좌표 텍스트는 Qwen3-VL의 0~1000 정수 규약이고, social VQA는 Balanced-Subset과 같은 프레임·쌍·라벨이다. [정책 원문](https://zenodo.org/api/records/24301723)

**진단 → 가설 → 최소 실험.** 작은 head 제거와 prior 변경이 성능을 바꿀 수 있다는 **추론**이다. 먼저 source video/frame/person-pair 키와 split 교집합을 검사하고 VQA와 balanced table의 대응을 확인한다. 이후 같은 모델·예측·evaluator로 원본 prior와 balanced prior를 따로 채점하고 precision/recall·class별 결과를 병기한다. head 크기와 frame/video별로 묶어 불확실성을 계산한다. 좌표 변환은 정규화 GT→0~1000→원좌표 round-trip으로 확인한다.

**GO/KILL.** annotation manifest와 변환 감사는 GO. 균형 subset F1을 원본 분포의 F1과 바로 비교하는 것은 KILL이며 **not strictly apples-to-apples**다. 실제 leakage나 duplicate 존재는 미확인이다.

## 2. Britannica — 모델 작성 설명과 원문 caption의 provenance

**확인 사실.** revision `95baa257c8cf13d7b38d0228c15568560eaca9ed`에서 이전 revision에 없던 `captions/`와 Parquet shard 15개를 확인했다. 기존 mask 추가는 8월이므로 오늘 새 mask release로 세지 않는다. [새 revision tree](https://huggingface.co/datasets/biglam/britannica-illustrated-pages/tree/95baa257c8cf13d7b38d0228c15568560eaca9ed/captions) · [변경 이력](https://huggingface.co/datasets/biglam/britannica-illustrated-pages/commits/main)

**규모·task·split·license — 배포자 보고.** 기존 pages 115,293개에 caption crop 158,595개를 추가하며, 1판 7,808개·11판 150,787개다. retrieval·captioning용이고 `train` 배포 config이며 독립 평가 split은 확인하지 못했다. description은 Inkling-2-Small 출력, caption·heading은 페이지에서 복사한 필드다. 텍스트는 CC0, 이미지는 기존 이미지 조건을 따른다고 명시한다. [고정 card](https://huggingface.co/datasets/biglam/britannica-illustrated-pages/blob/95baa257c8cf13d7b38d0228c15568560eaca9ed/README.md)

**bias·호환성.** 배포자는 여러 그림이 있는 plate에서 옆 그림 caption이 연결될 수 있고, 중복 스캔으로 같은 그림이 여러 번 나올 수 있다고 설명한다. crop bbox는 원본 해상도 좌표이며 `file_key`+`object_index`로 mask·page에 연결된다. 600px thumbnail에 원본 좌표를 그대로 적용하면 안 된다. 이는 배포 정책이며 독립 오류율 측정은 아니다.

**진단 → 가설 → 최소 실험.** 동일 그림·책의 재스캔이 split을 넘거나, 모델 description을 평가 정답으로 쓰면 점수가 부풀 수 있다는 **추론**이다. source page·edition/volume·crop ID를 묶고 exact/near-duplicate 검사를 설계한다. 사람이 crop와 전체 페이지를 대조해 caption 귀속을 검수한 뒤, 같은 encoder·split에서 printed caption과 generated description만 바꿔 retrieval을 비교한다.

**GO/KILL.** provenance join·좌표 감사는 GO. 생성 설명을 사람 정답으로 부르거나 기존 결과와 단일 순위로 합치는 것은 KILL. split·텍스트 생성기·입력 해상도가 다르면 **not strictly apples-to-apples**다.

## 3. MMLA The Wilds — 종 이름 수정이 config 호환성을 바꾼다

**직접 확인.** 구판 `c34b7e94e3ff68d8ed911a2f208a2933286ff8fb`와 신판 `a88449315cb28419c1977fa641da73ca1ad17fc0`의 README를 비교했다. 본문 Onanger→Onager 수정 외에 config가 `Persion-onangers`→`Persion-onagers`로 바뀐다. 신판에도 `Persion` 철자는 남아 있다. session_1~4 directory OID와 `classes.txt` blob OID는 모두 동일하다. 따라서 이번 변경은 annotation 파일 수정이 아니라 loader 설정·표기 변경이다. [공식 이력](https://huggingface.co/datasets/imageomics/mmla_wilds/commits/main) · [고정 card](https://huggingface.co/datasets/imageomics/mmla_wilds/blob/a88449315cb28419c1977fa641da73ca1ad17fc0/README.md)

**규모·task·split·license·artifact — 저자 보고.** drone 동물 detection/classification용 21,744프레임, 4종이며 JPEG·YOLO TXT·일부 ZIP을 제공하고 CC0다. 클래스 ID는 zebra 0, giraffe 1, onager 2, dog 3이다. session별 프레임은 13,749/4,053/3,436/506으로 불균형하다. 다른 MMLA 자료와 함께 학습·평가했다는 설명은 있지만 이 card만으로 정확한 split membership은 확정할 수 없다.

**진단 → 가설 → 최소 실험.** config 문자열을 고정한 consumer는 새 revision에서 로딩 실패나 잘못된 fallback을 겪을 수 있다는 **추론**이다. 종별 session·drone·해상도도 얽혀 있어 무작위 프레임 split은 일반화 근거가 약하다. 먼저 구·신 revision과 구·신 config의 2×2 metadata/loader smoke 검사를 설계하고 실제 image·label 경로, class mapping을 확인한다. 이후 video-heldout manifest를 만들어 frame-random 결과와 구분한다.

**GO/KILL.** config alias·revision pin과 source-video split 감사는 GO. README 수정만으로 annotation 개선이나 모델 성능 변화를 주장하는 것은 KILL. 이번 실행에서는 loader를 실행하지 않았다.
