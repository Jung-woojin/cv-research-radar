## 1. MMVU — 규칙의 잘못된 정답 인정과 judge 이관을 구분한다

**확인 사실.** commit `4e7ee3054e7374b57f72ce359216886e4499d7a4`는 open-ended 규칙에서 빈 예측을 거부하고, 예측이 정답 문자열의 일부이면 통과시키던 조건을 제거했다. 짧은 정답의 단어 검사도 길이 2 초과 단어가 실제 존재할 때만 통과하도록 바꿨다. `all()`이 빈 집합에서 참이 되는 경로를 차단한 것이다. 정답 전체가 예측 안에 포함되는 반대 방향 규칙과 수치 비교 등은 유지된다. [공식 diff](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/4e7ee3054e7374b57f72ce359216886e4499d7a4).

**maintainer 설명.** 기존 규칙은 빈 답변을 모든 정답의 부분 문자열로 보았고, 한 글자 답변도 잘못 인정할 수 있었다. commit에 기재된 validation 오인 개수는 maintainer의 진단이며 이번 실행에서 데이터로 재현하지 않아 자체 측정치로 사용하지 않는다.

**호출 경로 교차검증.** `evaluate_with_llm_judge`는 규칙이 참이면 judge 없이 정답을 반환한다. 거짓인 open-ended 응답은 빈 문자열도 pipeline에 넘긴다. 추가 테스트 역시 stub judge가 빈 응답을 받는지 검사한다. 따라서 “빈 답변 최종 오답이 보장된다”는 설명은 과도하다. 실제 judge 출력에 따라 결과가 정해지며, 예외 시 규칙 결과인 거짓으로 돌아간다. [전체 adapter](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/4e7ee3054e7374b57f72ce359216886e4499d7a4/lmms_eval/tasks/mmvu/utils.py), [공식 회귀 테스트](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/4e7ee3054e7374b57f72ce359216886e4499d7a4/test/tasks/test_mmvu_rule_based.py).

**원본 benchmark와의 차이.** MMVU 원본 `get_acc_async`는 각 응답을 judge로 보내 `extracted_answer`와 boolean `correct`를 구조화해 받는다. 확인한 파일 blob은 `8200d7838c20dd36004b3a2c341d94c5478871a4`다. lmms-eval의 수정은 전체 hybrid 규칙을 제거한 것이 아니다. 원본은 `gpt-4o` 별칭을 사용하고, adapter의 기본 judge는 `gpt-4o-2024-11-20`이며 prompt·출력 형식도 다르다. 두 경로가 채점 동등하다고 볼 수 없다. 원본 코드 자체는 오래된 비교 기준이며 이번 창의 새 공개가 아니다. [원본 평가 코드](https://github.com/yale-nlp/MMVU/blob/4d54223d912f498707c105ab645a921abce6e39a/utils/eval_utils.py), [공식 프로젝트](https://github.com/yale-nlp/MMVU).

**관측 → 진단 → 기전·추론.** 모델의 실패 응답이 규칙의 참 판정으로 가려졌을 수 있다. 수정은 정답률뿐 아니라 judge로 보내는 표본과 호출 비용을 바꿀 수 있다. 단, 현재 유지되는 정답 포함·수치 규칙의 적절성은 별도 감사가 필요하다.

**가설 → 최소 개입 → 실험 제안.** 보존된 동일 응답을 빈 값·단편·완전 답변으로 나눠 이전/수정 규칙의 통과 여부와 judge 이관 여부를 비교한다. judge가 필요한 사례는 별도 목록으로 보존한다. 유료 호출 없이 가능한 첫 단계는 경로 변화 감사다. 이어 같은 judge snapshot·prompt로 paired 평가할 수 있을 때만 최종 점수 차이를 계산한다.

**판정과 한계.** 경로 변경이 확인되면 전체 표본 기준 정확도, 이관률, judge 오류율을 함께 보고한다. 원본과 adapter가 다른 judge·prompt를 쓰면 **not strictly apples-to-apples**다. validation을 지정한 [adapter YAML](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/4e7ee3054e7374b57f72ce359216886e4499d7a4/lmms_eval/tasks/mmvu/mmvu_val.yaml)을 확인했지만 dataset revision은 고정되어 있지 않다. hidden test 결과로 일반화하지 않는다.

## 2. Binary judge — 답변 내용의 숫자와 판정 숫자를 분리한다

**확인 사실.** commit `31e9968e7c8a1c58d469f5ad497f4c8d52425927`은 `0/1` 및 `1/0` 형식에서 응답 어디든 `1`이 있으면 정답으로 보던 검사를 독립된 0/1의 첫 match로 바꿨다. `0.0/1.0`도 허용하고, 긴 숫자·소수·ASCII 단어 안 숫자는 제외한다. CJK 텍스트에 붙은 판정은 허용한다. yes/no 경로는 그대로다. [공식 diff와 테스트](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/31e9968e7c8a1c58d469f5ad497f4c8d52425927).

**maintainer 설명과 코드 대조.** “0으로 판정하고 뒤에서 12와 21을 설명한 응답”이 이전 parser에서 정답이 될 수 있다는 설명은 이전 조건과 일치한다. 추가 테스트는 그런 숫자 오인과 CJK 경계 및 echo judge 경로를 검사한다. 실제 provider 응답을 수집한 성능 검증은 아니다.

**사용 범위.** `ServerInterface.evaluate_binary`와 async 대응 함수는 `ResponseParser.parse_binary_response`를 호출하며 raw response·model·prompt·success를 결과에 남긴다. 저장 응답만으로 paired 감사할 경로가 있다. 다만 모든 benchmark의 verifier가 이 parser를 공유한다고 확인한 것은 아니다. 특히 앞의 MMVU pipeline까지 이 수정의 직접 수혜라고 단정하지 않는다. [호출 구현](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/31e9968e7c8a1c58d469f5ad497f4c8d52425927/lmms_eval/llm_judge/base.py).

**진단·추론.** 이번 수정은 숫자를 포함한 설명이 판정으로 새는 문제를 줄인다. 그러나 처음 나타난 독립 숫자가 실제 verdict라는 가정은 남는다. 설명 속 독립 숫자가 최종 선언보다 먼저 나오거나 verdict가 여러 번 있는 출력은 별도 점검 대상이다. 판정을 읽지 못하면 0을 반환하므로 parser 실패와 실제 오답도 집계에서 섞일 수 있다.

**가설 → 최소 실험.** 같은 raw judge 응답에 이전·수정 parser를 적용하고 1→0, 0→1, 판정 미검출을 나눠 기록한다. prompt·snapshot·응답은 고정하고 parser만 바꾼다. 불일치 표본은 최종 verdict와 설명을 수동으로 감사한다. 이후 strict 단일 판정 형식이나 구조화 출력은 별도 protocol 실험으로 비교한다.

**GO/KILL.** 불일치가 실제 verdict 오독과 연결되면 evaluator migration과 재채점을 진행한다. 해당 parser를 호출하지 않거나 저장 응답이 없다면 그 benchmark의 개선량 주장은 중단한다. 이 수정에서 VLM 능력 향상이나 새 leaderboard 점수는 확인되지 않았다.

## 3. MVBench — 관사 오인을 고쳐도 분모와 fallback은 남는다

**확인 사실.** commit `c969af54173a5b5393a6dfe8304dd87423fc9388`은 `mcq_acc`에서 모든 문자를 소문자로 바꾼 뒤 대소문자 구분 없이 A–E를 찾던 fallback을 수정했다. 단독 문자는 A–E를 허용하되 일반 산문에서는 대문자 B–E만 찾는다. A는 단독 답변, 명시적 형식 또는 공통 final-answer 추출 경로로 처리한다. [공식 diff](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/c969af54173a5b5393a6dfe8304dd87423fc9388).

**maintainer 설명·테스트.** 영어 관사 `a`나 문장 첫머리 `A`가 선택지 A로 읽히는 문제를 다룬다. 테스트는 관사로 시작하는 산문을 A로 인정하지 않고, 단독 문자·명시적 답변은 인정하는 경우를 담는다. 이는 실제 영상 이해 정확도 변화량이 아니다. [공식 테스트](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/c969af54173a5b5393a6dfe8304dd87423fc9388/test/tasks/test_mvbench.py).

**전체 경로 확인.** `extract_final_mcq_answer(pred) or pred` 때문에 공통 추출기가 빈 값을 반환하면 task fallback이 다시 원문을 본다. 수정 후에도 산문의 독립 대문자 B–E는 fallback 후보다. 따라서 공통 parser의 모호성 거부 정책이 task 최종 채점까지 보장된다고 해석하면 안 된다. [task 전체 구현](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/c969af54173a5b5393a6dfe8304dd87423fc9388/lmms_eval/tasks/mvbench/utils.py), [공통 추출기](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/c969af54173a5b5393a6dfe8304dd87423fc9388/lmms_eval/tasks/_task_utils/mcq_extract.py).

**집계의 별도 사실.** `mvbench_aggregate_results`는 raw `pred_answer != ""`인 표본만 분모에 넣는다. 이 commit이 변경한 부분은 아니지만 결과 해석에 중요하다. 응답이 빈 모델과 장황한 모델의 accuracy만 비교하면 coverage 차이가 숨을 수 있다. 공백만 있는 문자열은 빈 문자열과도 다르게 처리된다. 이는 코드 관측이며 실제 모델의 결측률을 측정한 것은 아니다.

**가설 → 최소 실험.** 저장된 동일 응답을 단독 답변·명시적 결론·관사 산문·대문자 언급·빈 값·공백 값으로 분류한다. 이전/수정 task scorer와 공통 추출기의 결과를 따로 기록한다. 원래 집계와 전체 질문 분모 집계를 병기하고, 정답 선택지별 전환을 확인한다.

**GO/KILL.** A 관련 오채점이 교정되고 실제 불일치가 확인되면 같은 영상·응답에서 재채점한다. 정상 답변 손실이 나타나면 format subgroup을 보고하고 일괄 개선으로 결론 내리지 않는다. 공통 추출기가 거부한 산문이 task fallback에서 다시 정답이 되는지도 감사한다. 영상 추론을 다시 실행할 필요는 없다.

## 비교 조건과 근거의 한계

세 건 모두 evaluator 변경이다. 공개된 새 모델의 backbone·pretraining·external data·input resolution·TTA·reasoning effort·context/frame/compute budget을 맞춘 비교 결과는 제공하지 않는다. 해당 조건이 같다는 확인 없이 다른 모델·과거 leaderboard와 비교하면 **not strictly apples-to-apples**다.

이번 diff에서 dataset split 교체나 새 metric 정의는 확인하지 않았다. 같은 metric 이름의 수치라도 parser·judge 이관 정책·분모가 달라지면 의미가 달라질 수 있다. 재평가에서는 dataset revision, sample ID, evaluator 전후 commit, 모델 설정, judge snapshot·prompt, raw response와 제외 이유를 보존해야 한다. 공식 테스트는 검토했으나 실행하지 않았다. 세 수정이 실제 순위를 얼마나 바꾸는지는 미확인이다.

## 오늘의 benchmark signal 3개

1. **모델을 고정한 채 채점 경로가 바뀐다.** MMVU의 규칙 통과율과 judge 이관률을 정확도 옆에 둔다.
2. **judge 응답의 숫자도 오염 경로다.** 최종 판정과 설명 숫자를 구분하고 미검출을 별도 기록한다.
3. **parser 수정과 분모 정책은 별개다.** MVBench accuracy에 유효 응답률과 전체 질문 기준 점수를 병기한다.

## 내 연구에 바로 연결되는 포인트

- 해양·CCTV 안전 VQA에서 빈 응답, 정답 단편, 명시적 부정 및 객체가 없는 상황을 따로 기록한다. 문자열 일치만으로 evidence-grounded 정답을 보장하지 않는다.
- Answer–Region Gap 연구에서는 answer correctness와 region grounding을 독립 평가하고, parser 때문에 answer가 정답이 된 사례를 별도로 감사한다. 이번 수정이 region 품질을 개선했다는 근거는 없다.
- temporal reasoning·video memory 실험은 frame budget을 늘리기 전에 고정된 영상 응답의 채점 안정성을 확인한다.
- **오늘 가장 먼저 할 실험:** 기존 raw judge 응답의 이전/수정 binary parser paired 재채점과 불일치 수동 감사. GPU 없이 가능하다. 저장 응답이 없으면 synthetic fixture는 구현 검증에만 쓰고 실제 점수 변화로 발표하지 않는다.
- GO는 실제 저장 응답에서 verdict 오독과 연결된 차이가 확인되는 경우다. KILL은 응답이 없거나 해당 parser를 호출하지 않는 경우의 benchmark 영향 주장이다. 이번 실행에서 실험 결과나 향상 수치를 만들지 않았다.
