## 1. 목적

매주 일본 주요 대학의 Computer Vision, VLM, multimodal, robotics vision, aerial/UAV vision 관련 연구실과 교수들의 최신 활동을 조사하고, 내가 박사과정 컨택 후보를 지속적으로 업데이트할 수 있도록 보고서를 작성한다.

나는 Computer Vision 연구자이며 특히 다음 주제에 관심이 있다.

- object detection
- small/tiny object detection
- open-vocabulary / open-world detection
- CNN architecture / inductive bias / effective receptive field
- vision encoder
- VLM / VQA / grounding
- video VLM
- aerial / UAV / remote sensing
- maritime vision
- edge vision / efficient vision

단순 대학 랭킹이나 유명세가 아니라 실제 최신 연구 활동과 내 연구 관심사와의 적합도를 중심으로 평가한다.

## 5. 각 연구실별 분석 형식

각 연구실 또는 교수별로 다음을 정리한다.

### 연구실 / 교수명

1. 최근 1개월 핵심 업데이트
   - 새 논문
   - 프로젝트
   - 코드
   - 모집
   - 인사 이동
   - 학회 채택

2. 핵심 논문 또는 연구 1~3개
   - 정확한 제목
   - 공개일 또는 학회
   - 한 줄 핵심 기여

3. 최근 연구 방향 변화
   - 예:
     - traditional CV → VLM
     - detection → open-vocabulary / grounding
     - image → video
     - perception → embodied AI
     - large model → efficient model
     - pure learning → sensing/physics
     - 2D → 3D/4D

4. 나와의 연구 적합도
   다음 기준을 종합해 5점 만점으로 평가한다.
   - object detection
   - small object
   - OVD
   - CNN architecture
   - VLM/VQA
   - aerial/UAV
   - edge/efficient vision

5. 박사과정 / 학생 모집 단서
   - 현재 모집 여부
   - 교수 직접 컨택 필요 여부
   - MEXT / IPGP / 영어 박사 프로그램 존재 여부
   - 공식 출처가 있을 때만 작성

6. 영어 사용 환경 / 국제학생 친화성
   - 영어 박사과정
   - 영어 입시
   - 국제학생 비율
   - 영어 lab page
   - 국제 프로그램
   - 확인 가능한 사실만 작성

7. 향후 컨택 메일에서 언급할 연구
   최근 연구 중 내가 실제로 언급하면 좋은 논문 또는 프로젝트 1~2개를 고른다.

8. 컨택 아이디어
   해당 연구실 연구와 내 관심사를 연결해 2~4문장으로 제안한다.

예:
- maritime CCTV small-object detection과 open-vocabulary grounding 결합
- aerial imagery에서 spatial detail loss와 CLIP semantic representation의 trade-off
- radar/AIS/CCTV + VLM multimodal reasoning
- edge device에서 lightweight VLM 또는 efficient dense prediction

## 6. 전체 랭킹

보고서 초반에 전체 후보 연구실을 표로 정리한다.

컬럼 예시:

| 순위 | 대학 | 연구실 / 교수 | 최근 핵심 신호 | 연구 적합도 | 모집 신호 | 이번 달 변화 |
|---|---|---|---|---:|---|---|

변화는 다음처럼 표시한다.

- ↑↑ : 크게 상승
- ↑ : 상승
- = : 유지
- ↓ : 하락
- ↓↓ : 크게 하락

여기서 하락은 연구실의 절대적인 연구력이 떨어졌다는 뜻이 아니라,
"현재 내가 컨택할 우선순위"가 내려갔다는 의미다.

## 7. 반드시 포함할 섹션

보고서 마지막에는 반드시 다음을 포함한다.

### 이번 달 컨택 우선순위가 올라간 연구실

왜 올라갔는지 설명한다.

예:
- 새 논문이 내 연구와 직접 연결됨
- funded PhD / MEXT 모집 시작
- 최근 VLM/OVD 쪽으로 연구 방향 이동
- 공개 코드가 나와 실제 실험 연결 가능

### 이번 달 우선순위가 내려간 연구실

왜 내려갔는지 설명한다.

단, 단순히 최근 논문이 없다는 이유만으로 연구실의 질이 떨어졌다고 표현하지 않는다.

### 사용자 관점 Top 5

내 연구 관심사를 기준으로 최종 Top 5를 선정한다.

각 후보마다:

- 왜 적합한지
- 가장 강한 연결점
- 잠재적 리스크
- 지금 컨택할 가치

를 짧게 설명한다.

### 실제 컨택 추천 순서

현재 입시/모집 일정까지 고려해서
"지금 먼저 연락할 곳" 순서를 별도로 제안한다.

## 11. GitHub 아카이브

보고서를 채팅에 완전히 전달한 뒤 연결된 GitHub를 사용한다.

저장소:

Jung-woojin/cv-research-radar

새 GitHub Issue를 생성한다.

Issue 제목:

[archive] japan-labs: Japan CV lab watch YYYY-MM-DD

예:

[archive] japan-labs: Japan CV lab watch 2026-10-09

Issue body 첫 줄은 반드시:

<!-- path: japan-labs/YYYY/MM/YYYY-MM-DD.md -->

예:

<!-- path: japan-labs/2026/10/2026-10-09.md -->

두 번째 줄부터는 채팅에 전달한 전체 보고서를 GitHub-compatible Markdown으로 그대로 넣는다.

GitHub Issue에서는 ChatGPT 전용 citation 토큰 대신 가능하면 다음을 사용한다.

- 일반 Markdown 링크
- 논문 URL
- 공식 lab URL
- GitHub URL
- arXiv URL
- 학회 URL

저장소의 GitHub Actions가 이 Issue를 감지해서 자동으로 Markdown 파일로 커밋하고 Issue를 닫는 구조이므로,
직접 파일 commit을 할 필요가 없으면 Issue 생성만 하면 된다.

GitHub 저장이 실패하면 보고서는 그대로 유지하고 마지막에 다음 정도로 짧게 알린다.

"GitHub 아카이브만 실패했습니다. 보고서 생성은 정상 완료되었습니다."
