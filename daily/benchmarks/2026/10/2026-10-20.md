## 1. PanoBench — panoptic occupancy를 synthetic·real·4D 공통 protocol로 재정의

### 무엇이 실제로 바뀌었나

기존 occupancy benchmark가 semantic voxel이나 특정 dataset의 관측 가능한 표면을 주로 측정했다면, PanoBench는 geometry·semantic class·instance identity를 한 sparse voxel 표현으로 통합한다. PanoBench-CarlaOcc, PanoBench-nuScenes, PanoBench-KITTI360을 같은 interface와 temporally aware valid mask로 묶고 semantic occupancy, panoptic occupancy, 1/2/3초 4D forecasting을 함께 평가한다.

### 확인된 사실

공식 원문은 총 963 sequences, 214,622 frames와 0.1/0.2/0.4 m voxel resolution을 보고한다. 세 subset은 각각 CARLA 104,000 frames, nuScenes 34,149 frames, KITTI-360 76,473 frames다. 비교 실험은 subset 안에서 voxel size, spatial range, camera, input resolution, split, 20-epoch optimization budget을 맞추고 8×RTX 4090과 AdamW를 사용한다. multi-frame method는 8 frames, single-frame architecture는 target frame 1장만 사용한다. [arXiv](https://arxiv.org/abs/2610.23537) · [공식 프로젝트](https://mias.group/PanoBench/)

annotation fidelity의 matched-resolution 비교에서 저자들은 PanoBench-nuScenes가 OpenOccupancy보다 0.2 m PixAcc에서 77.2 대 70.0, Occ3D보다 0.4 m에서 73.0 대 69.2라고 보고한다. KITTI-360 0.2 m에서는 81.5 대 SSCBench 69.9다. 공식 Hugging Face upload는 canonical format으로 변환된 공개 semantic occupancy annotation 11.1 GB를 제공하지만, dataset card가 명시하듯 **PanoBench 자체 annotation은 이 upload에 포함되지 않는다**. [공식 dataset card](https://huggingface.co/datasets/fengyi233/PanoBench)

### 저자 주장

저자들은 mesh-derived foreground와 map-regularized background가 LiDAR aggregation보다 observation fidelity, geometry completeness, spatial continuity, temporal consistency를 개선하며, complete thing instance와 stuff voxel을 분리해 평가하는 valid-mask가 instance-aware prediction에 더 적합하다고 주장한다.

### 같은 조건 비교인가

PixAcc 표는 domain과 voxel size를 맞춘 annotation comparison이므로 해당 행 안에서는 비교 가능하다. 다만 CARLA mesh oracle과 real-world reconstruction을 하나의 품질 순위로 합치면 안 된다. semantic prediction method 사이에서도 8-frame과 1-frame 입력 차이가 남는다. 공개 HF artifact에는 PanoBench 자체 label이 없으므로 현재 dataset card만으로 논문 전체 수치를 재현할 수 없다.

### 진단 → 가설 → 최소 실험

- **진단:** 현재 3D perception 실험이 visible-surface semantic IoU만 보면 occluded object의 shape completion과 instance continuity를 놓친다.
- **가설:** 해양 장면에서도 valid mask를 “현재 frame 가시성”과 “temporal evidence로 확인된 complete object”로 분리하면 작은 선박·부표의 temporal consistency 차이가 드러난다.
- **최소 실험:** 100개 multi-view sequence에서 visible-only mask와 temporal-complete mask를 만들고 같은 model을 IoU, instance PQ, identity consistency로 재평가한다.
- **GO/KILL:** ranking이 mask에 따라 뒤집히거나 small-object PQ가 5%p 이상 변하면 mask protocol을 정식 benchmark에 포함한다.

### 판정

새 SOTA 하나보다 **annotation과 valid-mask 정의가 leaderboard를 바꾸는 사례**다. 공개 artifact의 범위가 논문 전체보다 좁으므로 “코드·데이터 공개 완료”로 표기하면 안 된다.

## 2. MIST — memory benchmark의 실패를 setup·execution·reveal로 분해

### 무엇이 실제로 바뀌었나

MIST는 video world model의 memory total을 장면 설정, 숨겨진 변화의 실행, 마지막 frame의 reveal로 분리한다. 낮은 total을 바로 forgetting으로 해석하지 않고, persistence를 시험하기 전에 requested action이 실제로 수행됐는지 먼저 검사한다.

### 확인된 사실

Internal MIST는 frozen Wan2.2-TI2V-5B, 3×5초 shots, 43 cases를 사용한다. baseline setup은 0.852, leak은 0/43이지만 41/43 clips가 lid를 열지 않았고 reveal은 0.147, inside match는 0.047이었다. one-kept rewrite에서는 setup 0.851, reveal 0.492, inside 0.442이며 correct clip은 1개에서 13개로 늘었다. [arXiv](https://arxiv.org/abs/2610.23542) · [공식 프로젝트](https://hku-mmlab.github.io/MIST/)

Official suite는 frozen Wan2.2-T2V-A14B와 각 suite scorer를 사용한다. WRBench unique T는 0.452→0.570(n=40), MBench-T unique U는 0.292→0.446(n=30)이라고 저자들이 보고한다. 그러나 keep-best는 최종 score를 보는 oracle이며, target과 scorer를 보지 않는 last-frame selector는 T 0.466, U 0.248로 baseline을 넘지 못했다.

공식 GitHub는 control loop와 tests를 공개하지만 README에 original experiment tree가 remote 없이 삭제됐고 현재 repository가 paper result를 재생성하지 못한다고 명시한다. 43-case spec, Wan launcher, 122B judge program도 없다. 공개 코드는 protocol 일부를 점검할 수 있으나 결과 재현 package는 아니다. [공식 GitHub](https://github.com/HKU-MMLab/MIST)

### 저자 주장

저자들은 많은 memory failure가 stored state의 소실이 아니라 requested change의 미실행에서 시작하며, memory benchmark는 setup·execution·readout을 별도 cell로 보고해야 한다고 주장한다.

### 같은 조건 비교인가

Internal MIST의 TI2V-5B 수치와 Official WRBench/MBench-T의 T2V-A14B 수치는 generator, clip length, scorer가 달라 합칠 수 없다. best-of-5 0.763과 one-kept 0.492도 search budget과 selection rule이 다르다. scorer-aware keep-best를 deployable method와 비교하면 oracle leakage다.

### 진단 → 가설 → 최소 실험

- **진단:** long-video 기억 점수 하락을 model memory 부족으로 부르면 action execution failure를 잘못 최적화할 수 있다.
- **가설:** 항만 video QA의 “이전 상태 기억” 실패도 state observation, event execution/occurrence, final readout 중 execution gate가 가장 크다.
- **최소 실험:** 60개 sequence에 setup-valid, event-visible, final-evidence 세 binary label을 붙이고 total score와 분리 score를 함께 계산한다.
- **GO/KILL:** total miss의 절반 이상이 event gate 이전에서 발생하면 memory module 추가보다 event verification과 prompt를 먼저 개선한다.

### 판정

강한 benchmark diagnosis지만 headline gain은 oracle selection의 영향을 받는다. 연구 가치가 높은 부분은 SOTA 수치보다 **실패 단계 분리 protocol**이며, 공개 repository의 재현 한계도 결과와 함께 인용해야 한다.

## 3. NAME-Bench — object mention과 existence claim을 분리

### 무엇이 실제로 바뀌었나

기존 object hallucination metric은 caption에 object 단어가 나오면 존재 주장으로 처리한다. NAME-Bench는 mention을 concrete, hallucinated, non-assertive로 나누고 non-assertive를 depictive, purpose, negation, hedged 네 subtype으로 세분한다.

### 확인된 사실

NAME-Bench는 COCO image에 대해 5개 VLM이 만든 caption에서 25,497 object mentions를 수집했다. 모델별 2,000 random images에서 non-assertive share는 LLaVA-1.5-7B 1.3%, Qwen2.5-VL 7B/3B 5.0%/4.8%, InternVL3-8B 4.2%, LLaVA-OneVision-2-8B 4.4%였다. held-out 평가에서는 calibration set의 concrete mention 10%가 flag되도록 detector threshold를 맞추고 3 seeds 평균을 보고한다. [arXiv](https://arxiv.org/abs/2610.23610)

저자들이 평가한 detector는 non-assertive mention을 14–80% 범위에서 hallucination으로 flag했다. LLaVA-1.5에서는 Lookback Lens FPR이 20개 negative example을 섞었을 때 40%→17%로 줄었지만, 네 newer VLM은 5–10배 많은 data가 필요했고 maximum mixing에서 hallucination TPR이 함께 낮아졌다.

### 저자 주장

저자들은 최신 VLM일수록 실제 hallucination rate는 낮아져도 non-assertive language가 상대적으로 더 큰 confounder가 되며, mention 기반 metric이 언어 스타일 차이를 visual grounding failure로 잘못 계산한다고 주장한다.

### 같은 조건 비교인가

동일 model 안에서 detector와 training mix를 바꾼 비교는 calibration rule이 같아 직접 비교할 수 있다. 모델 간 FPR은 caption distribution과 non-assertive subtype 비율이 달라 순위로 읽으면 안 된다. 이번 확인에서 별도 공식 code/data release 링크는 arXiv 원문에서 찾지 못했으므로 독립 재현 가능성을 확인하지 못했다.

### 진단 → 가설 → 최소 실험

- **진단:** “선박이 보이지 않는다” 또는 “선박이 정박할 수 있는 부두” 같은 문장을 object hallucination으로 세면 negation·purpose 표현을 오탐한다.
- **가설:** 해양 VLM caption에서도 존재 assertion을 분리하면 hallucination rate가 의미 있게 낮아지고 model ranking 일부가 바뀐다.
- **최소 실험:** 500개 caption의 object mention을 asserted-present, asserted-absent, purpose, depictive, hedged로 이중 annotation하고 CHAIR-style score와 claim-aware score를 비교한다.
- **GO/KILL:** 기존 hallucination의 10% 이상이 non-assertive로 재분류되거나 model ranking이 바뀌면 claim-aware metric을 유지한다.

### 판정

VLM hallucination benchmark의 label ontology를 수정하는 중요한 신호다. hallucination 감소를 주장하기 전에 metric이 language pragmatics를 visual error로 세고 있지 않은지 확인해야 한다.

## 4. BEHAVIOR-1K 2026 leaderboard — 제출 가시성은 변했지만 공식 점수는 아직 비공개

### 무엇이 실제로 바뀌었나

공식 Hugging Face Space의 최근 commit은 ignored team list에서 `autolab`을 제거해 해당 제출을 leaderboard에 다시 노출했다. 동시에 score masking과 다른 제외 규칙은 유지했다. [공식 commit](https://huggingface.co/spaces/behavior-1k/2026-challenge-leaderboard/commit/35ed86bbd97a6aa386bea20925acd45d5458f4af)

### 확인된 사실

commit은 2026-10-20 KST 기준 약 11시간 전에 반영됐고 `IGNORED_TEAM_NAMES`에서 `autolab`만 제거한 1-line change다. 공식 data directory의 `results.jsonl`, `submissions.jsonl`, `per_task_results.jsonl`은 모두 0 bytes다. repository 문서는 2026 score를 private dataset에 보관하고 organizer approval 뒤에만 public 결과를 publish하며, score는 100개 challenge tasks 전체에 대해 평균하고 미제출 task는 zero로 처리한다고 명시한다. [공식 Space](https://huggingface.co/spaces/behavior-1k/2026-challenge-leaderboard/tree/main) · [공식 data directory](https://huggingface.co/spaces/behavior-1k/2026-challenge-leaderboard/tree/main/data)

### 운영자 주장

공식 결과는 organizer가 OmniGibson setup으로 검증하고, unpublished score와 raw artifact는 public Space에 저장하지 않는다는 운영 정책이다.

### 같은 조건 비교인가

현재 공개 data에는 2026 verified score가 없으므로 Autolab의 노출 복원을 성능 상승이나 순위 이동으로 해석할 수 없다. self-reported score, hidden organizer score, 2025 archived result를 같은 표로 비교해서도 안 된다.

### 진단 → 가설 → 최소 실험

- **진단:** leaderboard UI에 team이 보이는 변화가 score publication처럼 소비될 수 있다.
- **가설:** benchmark monitoring에서 UI diff와 verified result data diff를 분리하면 false movement alert를 줄일 수 있다.
- **최소 실험:** Space commit, public JSONL hash, row count, verified flag를 별도 필드로 기록하고 row count가 0이면 ranking alert를 금지한다.
- **GO/KILL:** UI change만 있고 result hash가 그대로인 이벤트가 반복되면 “governance/update” 채널과 “score movement” 채널을 영구 분리한다.

### 판정

오늘의 변화는 **leaderboard governance와 visibility movement**다. 점수·순위 movement는 확인되지 않았다.

## Apples-to-apples 체크표

| 항목 | 직접 비교 가능한 범위 | 직접 비교하면 안 되는 범위 | 현재 artifact 상태 |
|---|---|---|---|
| PanoBench | 같은 domain·voxel size·ROI의 annotation quality, 같은 subset protocol의 model | synthetic mesh oracle와 real reconstruction, 8-frame과 1-frame을 무시한 순위 | project·code link·converted dataset 확인; 자체 annotation은 HF upload에 없음 |
| MIST | 같은 generator·case·scorer에서 baseline vs rewrite | Internal MIST와 Official suites, one-kept와 best-of-5 | control-loop code 공개; original experiment tree·judge/spec 일부 소실 |
| NAME-Bench | 같은 model·calibration rule의 detector/mixing 비교 | caption distribution이 다른 model 간 FPR 순위 | arXiv 원문 확인; 별도 공식 code/data release 미확인 |
| BEHAVIOR-1K | 동일 public JSONL의 verified rows와 hash 변화 | UI 노출과 private/self-reported score를 공식 순위로 해석 | 2026 public result files 0 bytes, Autolab visibility만 복원 |

## 오늘의 benchmark signal 3개

1. **평가 대상의 단위를 다시 정의하라.** PanoBench의 complete instance, MIST의 execution gate, NAME-Bench의 existence claim은 기존 total이 섞어 세던 항목을 분리한다.
2. **oracle과 공개 범위를 점수 옆에 붙여라.** scorer-aware keep-best와 private leaderboard score는 deployable·verified public result가 아니다.
3. **artifact 존재와 재현 가능성을 구분하라.** 링크가 있어도 PanoBench 자체 label이 빠져 있거나 MIST의 원 실험 tree가 소실되면 full reproduction은 불가능하다.

## 내 연구에 바로 연결되는 포인트

- 해무·항만 segmentation은 visible-only mask와 temporal-complete mask를 나눠 small-object PQ와 identity consistency를 함께 기록한다.
- video reasoning은 total accuracy 전에 setup, event execution, final evidence 세 gate를 annotation한다.
- VLM hallucination 평가는 object word match 대신 assertion 여부를 분리하고 negation·purpose·hedge를 별도 label로 둔다.
- leaderboard watcher는 UI commit, result file hash, verified row count를 분리해 score 없는 노출 변경을 ranking movement로 알리지 않는다.
- 첫 실행 우선순위는 기존 해양 caption 500개에 claim-aware label을 붙이는 것이다. 새 학습 없이 metric bias와 ranking reversal을 확인할 수 있다.
