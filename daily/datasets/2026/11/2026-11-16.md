## 1. Elevator-VIGS — label 수정과 영상 변경을 분리한다

**시점·artifact:** 11/15 수정 commit은 Office5·Office6·Residential4 추가, Mall 4개 sequence 재렌더링, Office4·Station3의 `control_points.json` 안 `rides` 수정과 manifest·checksum 갱신을 기록한다. 최신 revision `71352dfd13aa531e5eae192f7a2bbb1088a9d8cc`는 11/16 01:08:42 UTC의 Residential4 12개 frame face-blur 보강이다. 이는 commit 설명이며 ZIP 내부의 수정 전후를 독립 검사한 결과는 아니다. [수정 이력](https://huggingface.co/datasets/Rui5125/Elevator-VIGS/commits/main)

**규모·task·split·license:** 배포자는 elevator 구간 visual-inertial SLAM용 실측 19개 sequence·10개 건물과 합성 16개 sequence·4개 건물을 설명한다. sequence ZIP, 별도 LiDAR ZIP, `manifest.csv`, `SHA256SUMS`가 있다. 표준 train/val/test membership은 확인하지 못했다. CC BY-NC 4.0이며 얼굴 blur와 무음 배포를 명시한다. 개인정보 처리 완료 여부는 독립 전수 검증하지 않았다. [고정 card](https://huggingface.co/datasets/Rui5125/Elevator-VIGS/blob/71352dfd13aa531e5eae192f7a2bbb1088a9d8cc/README.md)

**Label·호환성:** 실측 `MT-Pose.txt`는 LiDAR-inertial 추정으로 ride 중 drift가 있으며 ground truth가 아니다. 실측 평가는 정지 control-point 구간의 중앙 높이와 laser-measured 높이 또는 왕복 높이 차이를 사용한다. 합성은 `MT-Pose.txt`를 GT로 사용한다. Mall 재렌더는 같은 경로·trajectory·IMU를 유지한다고 배포자가 설명한다. 따라서 구판/신판, 실측/합성을 섞은 단일 점수 비교는 **not strictly apples-to-apples**다.

**진단 → 가설 → 최소 실험:** ride 구간 label 수정의 효과와 cabin appearance 변경 효과가 섞일 수 있다는 **추론**이다. 먼저 첫 release `188c830b5ed403b23fbef9db3fa3c10442cc3db6`와 현재 revision의 sequence·ZIP hash·label을 별도로 대조한다. 이후 같은 예측 trajectory를 수정 전후 label로 재채점하고, Mall은 모델·evaluator를 고정해 영상 변경 효과를 따로 평가한다. 추가 sequence는 건물 identity를 확인한 뒤 building-heldout으로 묶는다. sequence 이름만으로 서로 독립된 건물이라고 가정하지 않는다.

**GO/KILL:** label-only 재채점과 sequence lineage 검사는 GO. 실측 추정 궤적을 GT로 사용하거나 재렌더 효과를 label correction 효과로 합치는 해석은 KILL. 건물·ride·sensor별 불균형은 아직 집계하지 않았다.

## 2. FireViewer — 모델 동의로 선택한 데이터의 편향

**확인 사실:** `903627bf22e2cc5f5eea53b8e7aaf900c138b57e`와 데이터 추가 commit의 `data/` tree를 비교했으며 변경 차이는 `train-legacy-yolo11m` shard 31개 추가였다. 최신 README 수정 자체를 새 데이터 release로 세지 않았다. [추가 commit](https://huggingface.co/datasets/fireviewer/fireviewer_fire_smoke_flame_v3_native/commit/69d5af0d15e15ef756caa9160eaf835f36587d81)

**배포자 보고·규모:** 공식 summary는 legacy 후보 중 YOLO11M과 일치하는 15,257개 이미지를 추가하고 32,733개를 manual review로 분리했다고 기록한다. 원본 box 유지, 기존 validation/test 불변, exact 및 near-duplicate 검사도 보고한다. 현재 card의 train/validation/test는 각각 105,655/11,266/13,523장이다. 이 수치와 duplicate 제거 품질은 parquet 전수 집계로 재현하지 않았다. [고정 summary](https://huggingface.co/datasets/fireviewer/fireviewer_fire_smoke_flame_v3_native/raw/416a15c2d36b363a4c1e8411653f91f3ba4b5c08/metadata/legacy-yolo11m-20261114-summary.json)

**Label·license·bias:** task는 flame/smoke detection과 6종 context classification이다. box는 native-pixel XYWH다. card는 context null 2,866개를 negative로 바꾸지 말라고 명시한다. detection box 부재와 context label 미확인은 별개다. 확인한 card에는 명확한 dataset license가 없어 재배포·상업 사용 허가를 확정하지 않는다. source별 권리도 별도 확인이 필요하다. [고정 card](https://huggingface.co/datasets/fireviewer/fireviewer_fire_smoke_flame_v3_native/blob/416a15c2d36b363a4c1e8411653f91f3ba4b5c08/README.md)

**진단 → 가설 → 최소 실험:** 모델 동의 표본만 추가하면 어려운 smoke·작은 flame·불일치 annotation이 review 집합에 집중될 수 있다는 **추론**이다. summary의 추가 context는 negative 13,112개·null 2,145개여서, 총 이미지 증가를 positive supervision 증가로 해석하면 안 된다. 최소 audit는 원 source/video ID와 hash의 split 교집합, box 경계·좌표 변환, null 처리, agreement/review별 class·크기·source 분포 점검이다. 이후 두 집합에서 표본을 사람이 blind 검수하고, 동일 detector·학습량·seed와 고정 test에서 추가 전후를 비교한다.

**GO/KILL:** provenance·null·source-group audit는 GO. 배포자 duplicate-check를 근거로 leakage-free를 선언하거나, license 확인 전 재배포하는 것은 KILL. selection model과 평가 model이 달라지는 경우도 기록해야 하며 다른 fire benchmark와는 **not strictly apples-to-apples**다.

**GO/KILL:** 10,000행 규모와 이전 ID/hash 보존을 확인한 metadata 단계는 GO. 이 결과를 simulation-valid·near-duplicate-free·real-world 일반화 개선으로 확대하는 주장은 KILL.
