## 1. CPU SPPF — 블록 최적화가 전체 모델 이득으로 얼마나 남는가

**확인한 사실:** 11월 11일 merge된 변경은 CPU에서 5×5 max pooling을 1×5→5×1로 분리한다. CUDA·MPS·export는 기존 square pooling을 유지한다.

**저자 측정:** SPPF 추론 지연은 22–45% 감소하지만 YOLO26n/s 전체 추론은 0.2–4.6% 감소다. CUDA의 separable SPPF는 오히려 8–19% 느려 CPU에만 적용했다.

**비교 조건:** dual AMD EPYC 9655, PyTorch 2.7.0, CPU FP32, 1/8 threads, 입력 640×640, batch 1/8. variant별 warm-up 10회 후 순서를 교대한 3회 trial median이다. 전·후처리와 transfer 제외. 동일 weight/input 비교지만 shared server라는 제약이 있다. 다른 ARM edge CPU로의 전이는 **not strictly apples-to-apples**다.

**진단→가설:** pooling 연산 분해의 이득은 device kernel·thread·메모리 접근에 의존한다. FLOPs나 국소 블록 이득만으로 전체 latency를 예측하기 어렵다.

**최소 실험:** target CPU에서 기존/분리 pooling만 교체하고 thread 1/8, batch 1/8을 반복한다. output parity, 블록 지연, 전체 p50/p95, CPU memory와 처리량을 함께 기록한다.

**GO/KILL:** 출력 동등성과 전체 모델 개선이 반복되면 GO. 블록만 개선되거나 GPU에서 느려지면 해당 배포 경로 적용은 KILL한다.

출처: [조건·측정·재현 스크립트가 포함된 PR](https://github.com/ultralytics/ultralytics/pull/26082).

## 2. ExecuTorch INT8 — 작은 파일과 빠른 추론은 별개다

**확인한 사실:** calibration 기반 XNNPACK static INT8 export가 추가됐고, detect 계열 head는 FP32로 유지한다. INT8에는 ExecuTorch 1.6.0 이상이 필요하다.

**저자 측정:** YOLO26n detect는 FP32→INT8에서 9.86→3.24 MB, 101.1→88.3 ms, coco128 mAP50-95 0.4773→0.4743이다. 반면 semantic은 18.3→20.0 ms, classification은 2.8→3.4 ms로 느려졌다. classification의 PyTorch top-1 일치도도 100/100→82/100이었다.

**비교 조건:** torch 2.15.0, ExecuTorch 1.6.0, imgsz 640. detect 등 앞 네 작업은 Linux x86_64 4 vCPU, semantic 등 뒤 세 작업은 macOS arm64다. CPU 모델·batch·warm-up은 명시 확인되지 않았다. task/platform 간 수치 비교는 **not strictly apples-to-apples**다. calibration에 validation data를 사용했으므로 독립 일반화 평가도 부족하다.

**진단→가설:** 혼합 precision 경계와 작업별 kernel overhead가 크기 감소의 latency 이득을 상쇄할 수 있다.

**최소 실험:** 배포 장치 하나에서 별도 calibration/holdout split을 고정하고 FP32/INT8의 정확도·p95·파일 크기·peak RSS를 비교한다. shape·batch·warm-up을 manifest에 명시한다.

**GO/KILL:** 사전에 정한 품질 허용 범위와 실제 지연 목표를 함께 만족하면 GO. 크기만 줄거나 holdout 품질이 무너지면 속도 목적 INT8 적용은 KILL한다.

출처: [작업별 결과와 head 제외 이유](https://github.com/ultralytics/ultralytics/pull/27150).

## 3. OCR TensorRT FP16 — warm 성능과 cold 비용을 분리한다

**확인한 사실:** PP-OCRv6 recognizer에 GPU architecture·TensorRT version별 cached engine 경로가 추가됐다. crop 처리도 함께 최적화됐다.

**저자 측정:** 251단어 페이지의 `read_words`는 ORT CUDA 249 ms, FP32 engine 99 ms, FP16 engine 82 ms였다. FP16 build는 29초, cached load는 0.05–0.2초였다. 네 페이지 757단어의 text/line grouping은 같았지만 confidence 차이는 남았다.

**비교 조건:** RTX PRO 6000 Blackwell sm120, TensorRT 11.4.0.106, torch 2.15, 48–263단어 scene-text 사진 4장, 10회 median. engine 단독 행은 batch 8이며 batch 8 초과는 profile 밖이다. warm-up 횟수·전체 입력 shape·ORT version은 명시 확인되지 않았다. runtime·precision·crop 경로가 함께 달라지는 ORT 대비 수치는 **not strictly apples-to-apples**다.

**진단→가설:** 작은 recognizer batch에서는 compute보다 launch·crop overhead가 주요 병목일 수 있다.

**최소 실험:** 같은 crops로 ORT/FP32 TRT/FP16 TRT를 비교하고, 별도로 crop 최적화를 on/off한다. build·load·첫 요청·warm p95와 OCR 품질을 나눠 기록한다.

**GO/KILL:** 실제 호출량에서 cold 비용을 상각하고 품질 기준을 지키면 GO. 짧게 실행되는 edge 서비스에서 cold 비용이 절감을 넘으면 KILL한다.

출처: [runtime·cache·validation 조건](https://github.com/ultralytics/ultralytics/pull/27143).

## 4. RT-DETR INT8 — precision을 조금 되돌려 정확도를 복구한다

**확인한 사실:** TensorRT PTQ에서 민감한 head convolution 등을 float로 남기는 규칙을 확장했다. TensorRT 7–10과 11의 적용 방식이 다르다.

**저자 측정:** RT-DETR-l의 TensorRT 10.15 COCO val2017 mAP50-95가 0.0022→0.5179로 복구됐다. latency 변화는 median 추론 시간의 약 ±2% 이내 변동 수준이라고 보고했다.

**비교 조건:** RTX PRO 6000 Blackwell, INT8, imgsz 640, batch 1, default calibration data, full validation split. warm-up·정확한 torch version·보드 전력은 해당 결과에서 확인되지 않았다. 별도 Jetson Orin Nano/JetPack 6.2.1/TRT 10.3 점검은 Detect export 불변에 관한 것이며 RT-DETR 정확도 복구의 edge 재현으로 볼 수 없다. 버전·장치 간 비교는 **not strictly apples-to-apples**다.

**진단→가설:** head의 세 `input_proj` convolution 양자화가 정보 손실을 증폭할 수 있다. 전체 INT8을 포기하기 전에 국소 precision 복원이 유효할 수 있다.

**최소 실험:** 동일 model/calibration으로 기존 PTQ·세 projection FP16·수정된 전체 제외 규칙을 비교한다. mAP와 intermediate activation error, latency를 함께 측정한다.

**GO/KILL:** 국소 복원으로 품질이 회복되고 latency 예산을 지키면 GO. 다른 설정에서 효과가 사라지면 범용 head 규칙이라는 해석은 KILL한다.

출처: [precision 경계와 full-split 결과](https://github.com/ultralytics/ultralytics/pull/26220).

## 오늘의 GO / KILL

- **GO 1순위:** 보유 CPU에서 SPPF 국소/전체 latency를 함께 측정한다. 구현 변경이 작고 반증이 빠르다.
- **GO 2순위:** ExecuTorch INT8을 독립 holdout과 실제 장치에서 평가한다. calibration/validation 혼용을 제거한다.
- **GO 3순위:** 이미 TensorRT 환경이 있다면 RT-DETR projection precision ablation으로 정확도 붕괴를 격리한다.
- **KILL:** 블록 개선율을 전체 모델 개선율로 바꾸거나, 파일 크기 감소를 VRAM·power 감소로 간주하지 않는다.
- **KILL:** 서로 다른 runtime·precision·shape·batch·warm-up의 수치를 하나의 속도 순위로 합치지 않는다.
- 공통 기록 항목: model/weight hash, runtime·driver version, hardware·power mode, precision 경계, batch, input shape, warm-up, thread 수, 전·후처리 포함 범위, p50/p95, throughput, peak memory, 품질 metric. 전력계가 없다면 power는 미측정으로 둔다.
