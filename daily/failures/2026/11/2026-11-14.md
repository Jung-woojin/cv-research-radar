## 1. YOLOE native ReID: shape 수정만으로 해결되지 않는 feature 대응

**확인 사실.** PR #27171은 main에 병합됐다. diff는 detection head 입력의 처음 `nl`개 map만 보존하고, `lrpc`가 있는 prompt-free head는 별도 classification encoder로 보내도록 변경한다. 병합 commit은 `84311153a6b03985122209ba367069af307ac2c9`다. [공식 PR](https://github.com/ultralytics/ultralytics/pull/27171) · [코드 변경](https://github.com/ultralytics/ultralytics/pull/27171/files)

**작성자 보고와 재현 조건.** `with_reid: True`, `model: auto`에서 YOLOE의 추가 class embedding이 native feature 추출에 섞여 첫 frame에 차원 오류를 냈다. CPU, `imgsz=320`, `bus.jpg`, YOLOE segmentation checkpoint들의 전후 예시가 제공된다. prompt-free 경로는 embedding만 제거하면 실행되지만, 필터링된 prediction index와 feature pyramid anchor가 맞지 않는다고 보고한다.

- 공식 인정: maintainer 병합으로 수정 범위는 인정됨. 배포된 package version은 이번 조사에서 확정하지 않았다.
- 재현 수준: PR 작성자의 전후 실험이며, 독립 community 재현이나 이 watch의 실행은 없다.
- 진단 → 메커니즘: tensor list의 의미와 detection index의 좌표계가 소비자의 기대와 다르다.
- 가설·최소 개입: prompt 기반 head는 feature map만 분리하고, prompt-free head는 별도 encoder를 써야 box–feature 대응을 회복한다.
- 최소 실험: parent와 병합 commit에서 동일 checkpoint·이미지·tracker 설정을 고정해 첫 frame 예외, feature row 수, box 내부 anchor 대응률을 기록한다. prompt-free에는 shape-only 수정도 ablation으로 넣는다.
- 판정: crash가 없어져도 대응률이 회복되지 않으면 KILL. 별도 encoder는 compute 경로가 달라지므로 속도·IDF1 비교는 `not strictly apples-to-apples`이며 encoder 시간을 별도 측정한다.
- 기존 주장과의 관계: detector 자체의 AP 하락 증거가 아니다. “지원 head면 native ReID가 동일하게 작동한다”는 통합 가정을 제한한다.
- 점수: **심각도 4/5 · 재현 신뢰도 4/5 · 연구 아이디어 가치 4/5**.

## 2. Mask filename 충돌: 정상 종료 뒤 annotation이 사라지는 변환기

**확인 사실.** PR #27174는 11월 12일 19:31:29 UTC에 병합됐다. diff는 지원 mask 경로를 먼저 수집하고 `stem.casefold()` 중복을 검사해, output 생성·쓰기 전에 `FileExistsError`를 낸다. 병합 commit은 `9bdbbf9c5ed814216214209ce1df85e927eee45c`다. [공식 PR](https://github.com/ultralytics/ultralytics/pull/27174) · [converter 변경](https://github.com/ultralytics/ultralytics/pull/27174/files)

**작성자 보고.** `convert_segment_masks_to_yolo_seg()`에 `frame.jpg`와 `frame.png`를 넣으면 두 입력이 `frame.txt`로 매핑된다. 후자가 background-only이면 기존 annotation이 빈 파일로 바뀔 수 있다. Linux에서 충돌·비충돌 사례를 검증했으나 Windows 실행과 전체 학습 suite는 실행하지 않았다고 명시한다.

- 모델·dataset·구성: 모델 불필요, segmentation mask 변환 단계. 특정 공개 dataset의 피해 규모는 미확인이다.
- 공식 인정: maintainer 병합 있음. 독립 community 재현은 확인하지 못했다.
- 진단 → 메커니즘: 확장자를 지운 output key가 입력 identity를 보존하지 못해 destructive overwrite가 발생한다.
- 가설·최소 개입: 학습 전 label 손실이 false negative 증가처럼 관측될 수 있다. 먼저 중복 stem을 거부하면 이 경로를 차단한다.
- 최소 실험: 복사한 임시 디렉터리에 전경 mask와 같은 stem의 background mask를 넣는다. parent/병합 버전에서 label byte hash·빈 label 수·예외·기존 output 보존 여부를 비교한다. case-only 충돌과 고유 stem 대조군도 포함한다.
- 판정: 충돌 시 쓰기 전에 중단하고 고유 stem 결과가 byte-identical이면 GO. 임의 suffix로 충돌을 피하는 방식은 image–label 연결을 추가 검증하기 전 적용하지 않는다.
- 기존 주장과의 관계: detector나 segmentation 논문의 성능 주장을 반박하는 결과가 아니다. 같은 dataset 이름이라도 변환 artifact가 다르면 `not strictly apples-to-apples`다.
- 점수: **심각도 5/5 · 재현 신뢰도 4/5 · 연구 아이디어 가치 3/5**.

## 3. Dynamo 요청별 이미지 옵션 누락: 동일 PNG가 다른 RGB 입력으로 변환됨

**확인 사실.** Dynamo #18676은 open이며 조회 시 댓글은 없었다. 고정 commit `164358ac556d65e4e44b16128093908c23d53d2e`의 옵션 helper는 `video` key를 읽는다. 비교 대상 vLLM 코드는 `rgba_background_color`를 읽어 image mode 변환에 전달한다. [공식 저장소 제보](https://github.com/ai-dynamo/dynamo/issues/18676) · [Dynamo 고정 코드](https://github.com/ai-dynamo/dynamo/blob/164358ac556d65e4e44b16128093908c23d53d2e/components/src/dynamo/vllm/multimodal_utils/request_processor.py#L125-L146) · [vLLM 고정 코드](https://github.com/vllm-project/vllm/blob/4ba787ec9959e566d3b587a796dff07673324da5/vllm/multimodal/media/image.py#L52-L69)

**보고자 주장.** 완전 투명한 PNG와 빨간 배경 요청에서 Dynamo는 검정, vLLM 직접 경로는 빨강 pixel을 반환한다. 환경은 Dynamo main 위 commit, vLLM 0.33.0, Pillow 13.0.0, Python 3.12, CPU이며 worker 모델 문자열은 `Qwen/Qwen3-VL-2B-Instruct`다. 모델 답변의 정확도는 측정하지 않았다.

- 공식 인정: 공식 저장소에 올라온 community 제보다. maintainer 인정·수정 병합은 미확인이다.
- 재현 근거: 실행 코드·예상/실제 pixel·환경 제공. 이 watch의 독립 실행은 없다.
- 진단 → 메커니즘: request option 전달 계약의 누락으로 decoder 입력이 달라진다는 설명이 코드와 부합한다. 전체 경로의 인과 확정에는 실행 검증이 필요하다.
- 가설·최소 개입: 옵션 전달과 cache identity를 함께 맞춰야 요청별 pixel parity를 보장한다. 옵션을 지원하지 못하면 명시적 거부도 검토할 수 있다.
- 최소 실험: 동일 URL의 투명 PNG에 빨강·흰색 배경 요청을 번갈아 보내 cold/warm cache별 RGB hash를 direct vLLM과 비교한다. 작은 PNG와 opaque RGB 대조군부터 시작한다.
- 판정: 순서와 cache 상태에 관계없이 요청한 RGB가 나오면 GO. 첫 요청의 색을 재사용하면 cache-key 가설을 추가 검증한다. 후자는 아직 관측된 결과가 아닌 실험 가설이다.
- 기존 주장과의 관계: 같은 model·image URL도 실제 pixel이 달라질 수 있어 backend 비교는 `not strictly apples-to-apples`다. hallucination이나 Answer–Region Gap의 원인으로 확정할 근거는 없다.
- 점수: **심각도 3/5 · 재현 신뢰도 3/5 · 연구 아이디어 가치 4/5**.

## 오늘의 실패 패턴 3개

1. **Shape 통과와 의미적 대응은 별개다.** ReID tensor 차원이 맞아도 detection index가 feature anchor를 가리키지 않으면 조용한 오류가 남는다.
2. **입력 identity를 축약하면 annotation을 잃을 수 있다.** filename stem은 고유 식별자라는 검사가 없으면 label 쓰기의 안전한 key가 아니다.
3. **요청 옵션도 실제 입력의 일부다.** 이미지 URL만 같다는 이유로 전처리 결과나 cache 재사용이 동등하다고 볼 수 없다.

## 논문 아이디어로 연결 가능한 빈틈

**추론.** CV/VLM 평가 전에 “sample identity → decoded pixels → region feature”의 대응 보존을 검사하는 작은 harness가 유용하다. 새 모델 학습 없이 filename 충돌·RGBA 옵션·box–feature index를 바꾸고, 대응 위반이 downstream metric에 얼마나 전파되는지 분리할 수 있다.

신규성 위험은 일반적인 integration testing으로 끝날 가능성이다. 단순 bug 모음보다 서로 다른 구현에서 같은 대응 오류가 반복되고, 입력 조건별 task metric 변화가 재현되는지를 보여줘야 연구 주장이 된다. 현재는 그 효과를 측정하지 않았으므로 논문화 가능성을 확정하지 않는다.

## 직접 재현해볼 최소 실험

우선 CPU에서 mask 변환 충돌 실험과 투명 PNG pixel 비교를 수행한다. 원본 dataset은 사용하지 않고 임시 fixture만 만든다. library revision·입력 hash·출력 hash·예외를 저장한다. 이 두 실험은 대형 checkpoint 학습이 필요 없다.

그다음 RTX 5060 Ti 8GB에서 작은 YOLOE checkpoint로 한 이미지의 ReID shape/anchor 대응을 확인한다. 실제 VRAM 사용량은 미측정이다. 단일 frame 검사가 통과한 뒤 짧은 고정 video에서 IDF1과 latency를 측정한다. 다른 encoder 경로의 속도 차이는 별도 항목으로 남긴다.

**GO:** parent에서 문제가 재현되고 단일 수정으로 회복되며 대조군이 유지된다. **KILL/범위 축소:** 재현되지 않으면 checkpoint·processor·backend revision 차이를 먼저 확인하고 모델 일반화 실패라는 해석을 중단한다.
