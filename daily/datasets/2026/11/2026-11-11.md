## 1) LeRobot L2D-v3 문서–schema 불일치

- **사실:** 공식 저장소의 open issue #5302는 `yaak-ai/L2D-v3`의 `v3.0` revision을 읽는 문서 예제가 `observation.state`와 `action` key를 접근하지만, 해당 feature가 없고 대신 `observation.state.vehicle` 및 `action.continuous`가 있다고 보고한다. 이슈는 metadata-only 재현 코드를 제시한다. [원문](https://github.com/huggingface/lerobot/issues/5302)
- **상태:** 사용자 보고이며 open 상태다. maintainer correction release는 확인하지 못했다.
- **dataset/task/split/artifact:** L2D-v3의 `v3.0` revision을 대상으로 한 robot policy training loader example이다. 이슈는 dataset 규모, license, full split policy를 제공하지 않는다.
- **진단:** 문서가 실제 feature schema와 다른 key를 가정하면 random access부터 temporal window/DataLoader까지 failure 또는 잘못된 field selection으로 이어진다.
- **가설:** dataset revision을 pin하지 않은 training recipe는 code version이 같아도 다른 key naming으로 인해 재현 실패 또는 silent feature substitution을 낳는다.
- **최소 audit:** revision hash, `meta.features`, required key set, sample batch shape를 manifest로 저장하고 문서 example의 key를 직접 schema와 비교한다.
- **GO/KILL:** required key가 모두 존재하고 first episode의 random/temporal batch가 통과하면 GO; 하나라도 불일치하면 training 실행은 KILL하고 adapter mapping을 명시한다.

## 2) Hub snapshot dataset의 stats/video rewrite path

- **사실:** open issue #5300은 `recompute_stats`와 `reencode_videos`가 `--root` 없이 Hub dataset에 실행될 때, snapshot cache가 아닌 `$HF_LEROBOT_HOME/<repo_id>`를 source로 가정해 `FileNotFoundError`가 난다고 보고한다. 제안은 실제 dataset root를 resolve하고 Hub cache 내부 출력을 거부하는 것이다. [원문](https://github.com/huggingface/lerobot/issues/5300)
- **상태:** open issue의 재현/제안이며 fixed release는 미확인이다.
- **dataset/task/split/artifact:** Hub snapshot dataset의 metadata/statistics와 encoded video artifact를 대상으로 한다. 이슈에는 dataset 규모, license, split 변경은 제시되지 않았다.
- **진단:** storage location을 data identity로 오인하면 stats/video rewrite가 원 dataset revision과 분리돼 실패하거나 cache safety 문제가 생긴다.
- **가설:** stats 재계산 전후 artifact root와 source revision을 기록하지 않으면 같은 repo ID라도 서로 다른 preprocessing lineage가 만들어진다.
- **최소 audit:** read-only snapshot의 revision·real root·stats hash·video manifest를 기록하고, write output이 cache 밖의 새 destination인지 확인한다.
- **GO/KILL:** output root가 명시되고 source revision과 manifest가 보존되면 GO; default path가 cache 또는 nonexistent directory를 가리키면 rewrite는 KILL이다.

## 3) merged dataset의 episode metadata pointer

- **사실:** open issue #5299는 resumed session처럼 여러 episode-metadata file을 가진 dataset을 merge하거나 destination file rotation이 생길 때 `meta/episodes/{chunk,file}_index`가 틀려 `delete_episodes`나 `split_dataset`가 `FileNotFoundError`를 낼 수 있다고 보고한다. [원문](https://github.com/huggingface/lerobot/issues/5299)
- **상태:** open issue다. maintainer가 검증한 correction 또는 migrated dataset은 확인하지 못했다.
- **dataset/task/split/artifact:** multi-episode robot dataset merge/split artifact가 대상이다. dataset 규모·license·benchmark split policy는 이슈에서 알 수 없다.
- **진단:** row-level data가 보존돼도 episode pointer가 잘못되면 later split/delete에서 sample membership과 metadata provenance를 신뢰할 수 없다.
- **가설:** episode-level identity leakage는 random row split에서 감춰지고, provenance-aware group split에서만 드러날 수 있다.
- **최소 audit:** merge 직후 모든 episode pointer가 실제 Parquet file에 존재하는지 전수 검사하고, merge→split→reload 후 episode ID set과 frame count checksum을 비교한다.
- **GO/KILL:** pointer coverage와 round-trip checksum이 100% 일치하면 GO; 하나라도 dangling pointer면 training split 생성은 KILL이다.

## 4) interrupted encoding 뒤 action–video misalignment

- **사실:** open issue #5298은 `save_episode`가 video encoding보다 먼저 data row를 쓰므로 encoding 중 interruption 뒤 재개하면 orphan row가 later episode video와 조용히 pairing될 수 있다고 보고한다. [원문](https://github.com/huggingface/lerobot/issues/5298)
- **상태:** open issue의 proposed ordering 변경이다. fully atomic commit을 보장하는 fix는 아니라는 설명도 원문에 있다.
- **dataset/task/split/artifact:** video+action robot demonstration의 episode write path가 대상이다. issue는 dataset size, license, named split을 제공하지 않는다.
- **진단:** action label과 video observation이 맞지 않아도 schema는 유효하게 보일 수 있어, corruption이 training loss보다 rollout failure로 늦게 나타날 수 있다.
- **가설:** interruption/recovery를 포함한 capture session에서 episode-local timestamp/length invariant을 검사하지 않으면 action–observation mismatch가 silent label noise가 된다.
- **최소 audit:** controlled interrupt 후 resume fixture에서 episode ID, frame count, timestamps, video duration, action count의 one-to-one invariant을 검증한다.
- **GO/KILL:** 재개 전후 모든 episode의 alignment checksum이 유지되면 GO; orphan row나 cross-episode pair가 하나라도 나오면 해당 capture run은 KILL/quarantine이다.

## Watchlist — near-zero feature spread

- **사실:** #5289은 20-episode dual-arm dataset에서 움직이지 않는 joint의 std가 약 `1.48e-6`일 때 0.2° jitter가 정규화 후 약 135,000이 될 수 있다고 보고한다. 후속 comment는 synthetic reproduction과 environment-specific table을 제공하지만 physical robot evaluation은 수행하지 않았다고 명시한다. [원문](https://github.com/huggingface/lerobot/issues/5289)
- **구분:** issue author와 commenter의 재현 보고이지 maintainer-released dataset policy가 아니다.
- **최소 audit:** per-feature min/max/std distribution, near-zero coordinate count, training-vs-rollout range exceedance를 log하고, floor policy를 쓴다면 dataset statistics·processor config·checkpoint를 함께 version한다.

## 진단 → 가설 → 최소 실험

**관찰:** 네 핵심 신호는 filename/label 자체보다 schema, storage root, episode pointer, encoding commit order처럼 data lifecycle 경계에서 발생한다.

**가설:** dataset card의 task/split 설명만 고정하는 것보다 `revision → schema → episode pointer → video/action alignment → statistics` 순서의 manifest를 요구하면 silent failure를 조기에 차단한다.

**최소 실험:** 10-episode synthetic fixture에 (a) renamed field, (b) missing local root, (c) rotated metadata file, (d) interrupted video encoding을 각각 주입하고 preflight가 어느 단계에서 stop하는지 측정한다. model training은 실행하지 않는다.

## 오늘의 GO / KILL

- **GO:** Hub dataset의 revision hash, schema, split membership, episode/file pointer, video/action count, feature spread를 한 immutable manifest에 기록한다.
- **GO:** dataset mutation은 cache 밖의 explicit output root에서만 하고, source snapshot은 read-only로 유지한다.
- **KILL:** open issue를 maintainer-confirmed correction 또는 전체 dataset defect로 표현하지 않는다.
- **KILL:** pointer/alignment invariant가 확인되기 전 merge·split 결과를 benchmark training data로 사용하지 않는다.
- **KILL:** V-Thinker preview나 전일 label-file issue를 새 revision처럼 재포장하지 않는다.
