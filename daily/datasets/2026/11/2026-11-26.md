## 1. FZI-AURA — 전체 규모와 배포 완료 범위를 분리한다

**확인 사실·artifact.** revision `5117c2028faf373865328b7c4a0334b82c131c23`의 파일 목록에 test base-keyframe TAR와 dataset metadata가 있다. 이력은 여러 차례 블록 추가를 기록한다. 전체 센서 payload·annotation을 내려받아 배포 완료를 확인한 것은 아니다. [고정 tree](https://huggingface.co/datasets/fzi-forschungszentrum-informatik/FZI-AURA/tree/5117c2028faf373865328b7c4a0334b82c131c23)

**배포자 보고·정책.** 2,473 scenes, 3D box 4,106,333행, train/val/test 1,979/247/247이다. task는 3D detection·segmentation·tracking·fusion이다. 지리 비중복 split을 설명하지만 독립 검증하지 않았다. box 0개인 annotated frame은 유효한 negative이며 `object_id`는 scene 내부에서만 유일하다. semantic ignore class는 사용자가 명시해야 한다. [고정 card](https://huggingface.co/datasets/fzi-forschungszentrum-informatik/FZI-AURA/blob/5117c2028faf373865328b7c4a0334b82c131c23/README.md)

**License·bias·호환성.** 기본 CC BY-SA 4.0과 별도로 OSM·OpenWeather metadata 조건이 있다. 남부 독일·도심 중심이며 센서 가용성도 scene마다 다르다. card는 약관 동의·인증을 안내하지만 조회 API의 `gated=false`와 card의 `gated:true`가 달라 실제 payload 접근을 단정하지 않는다.

**진단 → 가설 → 최소 실험.** 누락 block을 negative로, 같은 scene 내부 ID를 전역 ID로 처리하면 annotation 누락·중복 통계가 왜곡될 수 있다는 추론이다. 먼저 revision별 배포 manifest와 split을 대조하고 `(scene_id, object_id)`를 키로 사용한다. `annotated-empty / unannotated / unavailable`을 분리한 뒤 sensor·class별 coverage를 계산한다.

**GO/KILL.** manifest 감사는 GO. 전체 규모를 현재 다운로드 완료량으로 인용하거나 ignore mapping이 다른 점수를 직접 비교하는 것은 KILL. 다른 자율주행 benchmark와는 **not strictly apples-to-apples**다.

## 오늘의 실행 순서와 검증 한계

1. **우선 GO — GREENBOT:** calibration 보고서의 “적용한 clock correction”과 “측정만 한 잔여 offset”을 loader 설정에서 분리한다.
2. **다음 GO — UVG-VCM:** 새 annotation/parser에 기존 예측을 그대로 재채점해 benchmark migration 효과부터 확인한다.
3. **조건부 GO — FZI-AURA:** 배포 block·split·annotation coverage manifest를 확보한 뒤 실험 범위를 정한다.
4. **조건부 GO — UrbanVerse:** source lineage와 batch별 선별 정책을 고정한 후 geometry·runtime 검증으로 확장한다.

이번 실행은 공식 문서·이력·파일 목록 조회와 소형 attribution CSV 감사까지 수행했다. MCAP·TAR·USD·영상 payload 다운로드, SDK 설치, 모델·simulator·evaluator 실행은 하지 않았다. HF 일부 웹 페이지는 검색 도구에서 열리지 않았지만 공개 raw card·API는 별도 HTTP로 확인했다. Saraiki VQA는 인증 필요 오류, Flood Watch는 README 부재로 근거가 제한됐다. HFE 기술 PDF는 웹 도구의 크기 제한으로 열리지 않아 상세 scoring·license를 확정하지 않았다.

후속 성능 비교에서는 backbone, data, split, resolution, pretraining, hardware, precision, batch, TTA와 evaluator를 함께 기록해야 한다. 새 모델 제안은 위 정책·보정 효과를 분리한 뒤 실패가 남을 때 검토한다.
