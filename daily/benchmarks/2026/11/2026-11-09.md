## 1. OBB metric semantics: Supervision 0.31.4 → 0.31.5

### 사실

- Supervision 0.31.5는 2026-11-05에 공개됐으며, OpenCV 설치 환경에서 `oriented_box_iou_batch`, OBB NMS, OBB metrics가 NumPy fallback과 같은 exact convex clipper를 사용하도록 바뀌었다.
- 공식 migration guide는 거의 collinear한 rotated edge 또는 한 변이 매우 작은 box에서 이전 OpenCV 경로가 IoU 0 또는 1을 낼 수 있었다고 설명한다. 예시에서는 true IoU 0.3333인 쌍이 0.31.4/OpenCV에서 1.0으로 나왔고, 새 경로는 0.3333을 낸다.
- 공식 원문은 candidate pair당 clipper 비용이 OpenCV 호출보다 약 10배일 수 있고, 저장해 둔 IoU·NMS·mAP reference를 다시 생성하라고 권고한다.
- 이 변경은 detector backbone, pretraining, train/validation split, TTA 또는 external data의 변경을 공표한 것이 아니다.

출처:
- https://github.com/roboflow/supervision/releases/tag/0.31.5
- https://github.com/roboflow/supervision/pull/2882
- https://github.com/roboflow/supervision/pull/2887

### 진단

기존 leaderboard나 회귀 시험이 OpenCV가 설치된 evaluator로 OBB score를 계산했다면, score 변화와 latency 변화는 모델 성능 이동이 아니라 evaluator semantics 이동일 수 있다. 특히 작은 box, 큰 좌표 원점, 거의 접하는 rotated box가 많은 set에서 영향이 클 수 있다.

### 가설

고정 prediction·ground truth를 0.31.4/OpenCV와 0.31.5/OpenCV에 각각 넣으면, 영향 표본에서 IoU distribution과 NMS keep-set이 달라지고, 그 결과 precision/recall/F1/mAR 또는 mAP reference가 달라질 것이다. 일반적인 축정렬 box만 있는 set에서는 차이가 작거나 없을 수 있다.

### 최소 실험

1. 재추론하지 말고 기존 OBB prediction과 annotation을 100개 이상 고정한다.
2. `supervision==0.31.4`와 `0.31.5`를 각각 OpenCV가 설치된 별도 environment에서 실행한다.
3. IoU matrix, NMS retained indices, 각 threshold별 precision/recall/F1/mAR, wall-clock time을 모두 저장한다.
4. 차이를 annotation geometry category(작은 box, large-origin, near-collinear, 기타)별로 분해한다.

**GO:** geometry-sensitive slice에서 score 차이가 재현되고 새 clipper의 expected behavior와 일치하면 evaluator version을 leaderboard column으로 승격한다.  
**KILL:** 동일 prediction과 geometry slice에서도 keep-set·metric 차이가 없으면 이 migration을 현재 benchmark 이동 원인으로 기록하지 않는다.

## 2. Occlusion-count protocol: `LineZone` retention 변경

### 사실

- 0.31.5에서 `LineZone`은 tracker side state를 기본적으로 `max(30, minimum_crossing_threshold + 1)` consecutive absent frames 동안 보존한다. 이전 기본값은 `max(2, minimum_crossing_threshold + 1)`이었다.
- 공식 예시는 동일 tracker가 선 위쪽에서 검출된 뒤 5 frame 결측, 아래쪽에서 재검출될 때 0.31.5의 `(in_count, out_count)`가 `(0, 1)`이고 0.31.4는 `(0, 0)`임을 보인다.
- 이전 정책을 재현하려면 `max_absent_frames=2`를 명시할 수 있다.
- 이 변경은 tracker 자체의 association accuracy, detector mAP, 비디오 split 또는 calibration data의 개선을 주장하지 않는다.

출처:
- https://github.com/roboflow/supervision/releases/tag/0.31.5
- https://github.com/roboflow/supervision/pull/2873

### 진단

traffic·maritime·CCTV counter에서 release 전후 count를 바로 비교하면, occlusion을 통과한 track를 새로 집계하는 policy 차이가 detector/tracker 개선처럼 보일 수 있다. 결측 시간은 프레임 수로 정의되므로 FPS도 같은 protocol의 일부다.

### 가설

occlusion이 2초과 30이하 frame인 crossing clip에서 새 기본값은 count를 증가시키며, `max_absent_frames=2`를 명시하면 0.31.4와 같은 policy 결과로 돌아간다.

### 최소 실험

1. 같은 tracker output과 same-FPS video clip을 고정한다.
2. 0.31.5 기본값, 0.31.5 `max_absent_frames=2`, 0.31.4를 각각 실행한다.
3. 각 crossing을 “결측 없음 / 1–2 / 3–30 / 31+ frame”으로 나눠 count, false crossing, missed crossing을 수동 label과 비교한다.
4. report에는 total count뿐 아니라 bucket별 변화와 policy 값을 함께 기록한다.

**GO:** 3–30-frame bucket에서 새 정책의 true crossing 회복이 false crossing 증가보다 크면, 운영 count 기준에 정책과 version을 명시해 채택한다.  
**KILL:** count 증가가 수동 label과 맞지 않거나 false crossing이 우세하면 기존 retention을 명시해 유지한다.

## 3. VTBench: 공개 benchmark와 revision 경고

### 사실

- V-Thinker 저장소는 2026-11-07에 VTBench를 Perception, Instruction-Guided Interaction, Interactive Reasoning의 세 과제를 포괄하는 standardized benchmark로 공개했다고 적고 있다.
- 같은 저장소는 VTBench가 세 hierarchical dimension의 1,500 QA pairs라고 설명한다.
- 저장소의 quantitative table에는 GPT-4o, InternVL3-78B, Qwen2.5-VL-7B, V-Thinker-7B 결과가 제시돼 있다. 이는 저장소 저자의 보고이며, 이번 점검에서는 독립 재현하지 않았다.
- 2026-11-19 공지에서 저자들은 Hugging Face의 Instruction-Guided Interaction subset이 실험에 쓴 final version과 일치하지 않는 non-final export라고 밝혔고, upgraded judge component 및 revised subset을 이후 공개하겠다고 적었다.

출처:
- https://github.com/We-Math/V-Thinker
- https://huggingface.co/datasets/We-Math/VTBench

### 진단

VTBench는 새 비교 축을 제공하지만, 공개 subset과 논문/저장소 결과가 동일 revision인지 보장되지 않는다는 공식 경고가 있다. 그러므로 공개 snapshot의 Instruction-Guided Interaction score를 기존 benchmark나 표의 다른 모델 score와 “동일 protocol”로 간주하면 안 된다.

### 가설

dataset revision/hash와 judge revision을 고정하면 Perception·Interactive Reasoning은 재실행 가능한 기준선이 될 수 있으나, Instruction-Guided Interaction은 final subset과 upgraded judge가 명시되기 전까지 score 분산 또는 rank reversal을 보일 가능성이 있다.

### 최소 실험

1. 내려받은 VTBench artifact의 revision/commit/hash, 다운로드 시각, 세 task별 sample count를 manifest에 기록한다.
2. repository가 제공한 task별 inference entry point로 동일 prompt·model revision·sampling seed를 고정해 Perception과 Interactive Reasoning부터 한 번 실행한다.
3. Instruction-Guided Interaction은 “non-final public subset”으로 label하고, 공식 final revision과 judge specification이 확인될 때까지 aggregate score에서 분리한다.
4. final artifact가 공개되면 public snapshot과 final snapshot의 item ID·answer·judge 차이를 diff하고, 이전 score를 덮어쓰지 말고 별도 revision column으로 보존한다.

**GO:** artifact hash와 judge version이 명시되고 task별 rerun이 가능하면 revision별 leaderboard를 만든다.  
**KILL:** evaluator 또는 dataset revision을 식별할 수 없으면 aggregate benchmark claim을 보류하고 qualitative smoke test만 남긴다.

## 즉시 적용할 비교 규칙

1. OBB 결과에는 `evaluator=supervision`, version, OpenCV 유무, IoU/NMS 설정과 runtime을 동시 기록한다.  
2. count benchmark에는 tracker output source, FPS, `max_absent_frames`, crossing definition을 함께 기록한다.  
3. VTBench 결과에는 dataset hash/revision, task subset, judge revision, prompt와 sampling 값을 함께 기록하며, 현재 공개본의 Instruction-Guided Interaction은 잠정값으로 분리한다.  
4. 서로 다른 model, pretraining, input resolution, split, TTA, external data가 고정되지 않은 표는 순위 비교가 아니라 protocol 탐색 결과로 표기한다.
