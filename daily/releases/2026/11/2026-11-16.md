**사실과 저자 설명.** 고정 tag의 YAML은 train 994·val 121, class `tumor` 하나와 기존 v0.0.0 다운로드 URL을 가리킨다. [YAML](https://github.com/ultralytics/ultralytics/blob/v8.4.215/ultralytics/cfg/datasets/brain-tumor.yaml)과 [PR #27218](https://github.com/ultralytics/ultralytics/pull/27218)을 대조했다. PR은 누락 라벨 추가·box 교정·이미지 한 개 제거와 patient-ID 기반 분할을 설명한다. 확인 가능한 환자 ID의 train/val 분리는 적용되지만 train의 ID 불명 이미지 541개와의 환자 중복은 배제하지 못한다고 밝힌다.

**논문 주장과의 간극.** PR의 마지막 실험행은 train 990·val 121 조건이고 배포본은 994·121이다. 저자도 학습 뒤 네 장이 train에 돌아왔다고 명시한다. 따라서 그 점수는 배포 ZIP 그대로의 재현값이 아니다. class taxonomy·라벨·분할이 동시에 바뀌었으므로 과거 두 class 결과와 새 한 class 결과는 **not strictly apples-to-apples**다. tumor-free 예제가 없어 종양 유무 분류의 일반화 성능을 이 artifact로 추정할 수 없다.

**조건·가용성.** YAML/code의 표기는 AGPL-3.0이나 원천 MRI의 독립 data license와 환자 provenance를 이번 원문에서 확정하지 못했다. code license를 데이터 이용 조건으로 자동 확장하지 않는다. 이미지·라벨 ZIP은 공개되어 있고 새 weight/evaluator 배포는 아니다. manifest·split audit는 CPU로 가능하며 GPU/VRAM은 필요하지 않다. 추가 학습의 VRAM은 미확인이다. ZIP은 mutable URL이므로 tag만 pin하지 말고 asset ID·digest도 함께 보존해야 한다.

**활동·10~30분 smoke plan.** #27218은 15일 22:29:01 UTC merge됐고 #27066을 닫는 교정으로 설명된다. Issue 독립 재현 본문은 확인하지 않았다. 다운로드가 별도로 승인된 후 SHA256·ZIP 목록·이미지/라벨 수·class ID·좌표 범위를 먼저 검사하고 filename prefix로 식별 가능한 patient overlap을 audit한다. ID 없는 행은 별도 unknown group으로 기록한다. 모델 재학습은 이 smoke plan의 범위 밖이다.

**진단 → 가설 → 개입.** 관측된 점수 변화가 representation보다 class 통합·라벨 교정·patient split의 조합일 수 있다. 이전 artifact를 확보할 수 있을 때만 동일 prediction을 공통 label mapping으로 평가하고, taxonomy 변경과 split 변경을 분리한다. artifact를 확보하지 못하면 과거 대조군을 추정해 만들지 않는다.

**GO/KILL.** hash·manifest·식별 가능한 patient 분리가 맞으면 data audit로 GO. 환자 ID 불명분을 포함해 완전한 leakage 제거를 선언하거나, PR 점수를 최종 ZIP의 benchmark로 쓰는 것은 KILL.

## 3. ONNX Runtime CUDA Plugin EP 0.4.0 — 설치 성공과 schema 호환성의 차이

**정확한 배포.** tag는 `plugin-ep-cuda/v0.4.0`, 대상 commit은 `bd90e896861ac9e54c147feb0160cf708108f531`이다. 11월 14일 15:34:19 KST 발행. CUDA 12/13, Linux/Windows와 일부 ARM64 binary asset이 존재한다. Windows x64 CUDA 13 ZIP의 API digest는 `sha256:d49409c04f271cbc3a5171edea8da2344794c16e17b31731d7eac222c4a5646a`이다. 새 모델 weight·dataset 공개가 아니다. [Release](https://github.com/microsoft/onnxruntime/releases/tag/plugin-ep-cuda/v0.4.0)

**명시된 호환성 조건.** 최소 core는 1.24.4지만 contrib operator schema 일치가 별도 조건이다. 같은 ORT revision으로 core/plugin을 빌드할 것을 권고하며 matched core는 1.32.0이다. CPU/GPU MoE offload 등 일부 기능은 1.32.0 core가 필요하다. 이 경고를 연결하는 [PR #32855](https://github.com/microsoft/onnxruntime/pull/32855)는 9월 30일 merge된 문서 교정이다. 신규 사건은 11월 14일 0.4.0 배포이며, schema 문제가 이날 처음 발견됐다는 뜻은 아니다.

**설치·라이선스·활동.** source는 [MIT](https://github.com/microsoft/onnxruntime/blob/plugin-ep-cuda/v0.4.0/LICENSE)이고 third-party notice도 확인 대상이다. 설치 surface는 core binary·CUDA Plugin EP binary·CUDA/cuDNN/driver·GPU architecture 조합이다. 일반 `onnxruntime-gpu` package pin 하나를 plugin 설치·revision 정합성의 증거로 쓰지 않는다. 해당 release의 단일 GPU/VRAM minimum은 확인하지 못했으며 모델·precision·shape별로 측정해야 한다. 위 merged PR을 확인했지만 최신 Issue 전체 triage나 독립 재현은 하지 않았다. checksum은 API metadata이며 파일·서명 검증은 미실행이다.

**진단·가설.** 같은 ONNX graph라도 schema·provider 배정·kernel·offload가 달라지면 결과와 비용이 달라진다. 논문 throughput 표와 runtime 교체 결과를 비교하려면 batch·precision·shape·core/plugin revision·warm-up·hardware·provider fallback을 맞춰야 한다. 불명 조건은 **not strictly apples-to-apples**다.

**10~30분 최소 실험 계획.** 먼저 binary·core/plugin commit·driver manifest와 model op/domain/opset을 확인한다. 정합한 환경에서 작은 고정 ONNX graph를 CPU reference와 CUDA plugin에 실행하고 session provider 배정, output tolerance, 실패 로그를 보존한다. 새 MoE offload는 별도 단계로 두어 일반 CV graph parity와 섞지 않는다. 호환성 검토를 위해 crash를 유도하는 mismatched core 조합을 실행할 필요는 없다.

**GO/KILL.** schema·provider·reference parity를 확인하면 제한된 CV inference로 GO. plugin 등록 성공만으로 호환성 또는 논문 성능 재현을 선언하면 KILL.
