## 사례 1 — disk offload: seed가 아니라 buffer의 실제 값부터 확인

**Claim / 재현 조건.** #15332 작성자는 FLUX.2 Klein의 VAE를 disk로 group offload하면 검은 이미지가 나오지만 CPU-memory offload는 reference와 일치한다고 보고한다. 환경은 Diffusers `0.44.0.dev0`, commit `e84bda1c0005da3f48cc4c899635438cb0aa13c1`, Linux·Python 3.12.10·torch `2.16.0a0+rocm10.3.0a20261115`, AMD Radeon AI PRO R9700, Transformers 5.21.0이다. `black-forest-labs/FLUX.2-klein-4B`, BF16, 1024×1024, 4 steps, guidance 1.0, 매번 새 CPU Generator seed 0을 사용한다. immutable checkpoint revision은 원문에서 pin하지 않았다. [원문](https://github.com/huggingface/diffusers/issues/15332)

**Observed gap / 커뮤니티 보고.** 작성자는 offload 후 `bn.running_mean` 불일치와 검은 출력을 제시하며, 수정안에서는 reference와 pixel 차이가 사라졌다고 주장한다. 같은 작성자의 #15329는 LTX-2.5 text encoder에서 두 번째 이후 `encode_prompt`가 달라지거나 NaN이 발생한다고 보고한다. buffer-only scale module을 연속 두 번 호출하는 작은 fixture도 제공한다. 두 이슈는 독립 사용자의 재현 두 건이 아니라 같은 작성자의 서로 다른 접근 경로다. [연속 호출 제보](https://github.com/huggingface/diffusers/issues/15329)

**확인한 소스 / mechanism.** 고정 소스의 `_offload_to_disk`는 보관 대상 tensor를 `torch.empty_like`로 교체한다. FLUX.2 Klein pipeline은 `vae.bn.running_mean`·`running_var`를 직접 읽어 latent를 변환한다. 또한 stream prefetch가 누락됐을 때의 fallback은 parameter 목록을 검사하므로 buffer-only group은 그 조건을 통과하지 못할 수 있다. 이 구조는 “forward hook이 buffer의 모든 사용을 포착한다”는 가정이 깨진다는 제보와 부합한다. 첫 경로는 forward 자체가 없고, 두 번째는 forward가 있으나 재로딩 판정에서 빠지는 차이가 있다. [offload 고정 소스](https://github.com/huggingface/diffusers/blob/e84bda1c0005da3f48cc4c899635438cb0aa13c1/src/diffusers/hooks/group_offloading.py), [Klein 고정 소스](https://github.com/huggingface/diffusers/blob/e84bda1c0005da3f48cc4c899635438cb0aa13c1/src/diffusers/pipelines/flux2/pipeline_flux2_klein.py)

**진단 → 가설 → 최소 실험.** 가설은 “일부 반복 실행 차이는 RNG가 아니라 미초기화 buffer 읽기에서 온다”이다. 학습 없이 상수 buffer를 직접 읽는 fixture와 동일 buffer-only module을 두 번 부르는 fixture를 분리한다. no-offload/CPU-memory/disk × stream on/off에서 buffer hash·finite mask·호출별 출력을 기록한다. 직접 읽기에는 buffer 보존안을, 연속 호출에는 buffer를 포함한 onload 판정안을 각각 적용해 어느 실패만 사라지는지 검사한다. 그다음 고정 checkpoint·동일 입력으로 실제 pipeline을 검증한다.

**GO/KILL.** buffer 값과 반복 출력의 정합성이 통과한 조합만 품질 실험으로 GO. 두 경로 중 하나의 수정으로 모든 offload 문제가 해결됐다고 선언하거나 NaN이 없는 잘못된 출력을 seed variance로 해석하는 것은 KILL. 두 이슈 모두 open·댓글 0이며, 작성자의 로컬 수정 주장을 병합·배포로 간주하지 않는다.

## 사례 2 — MagCache: cache hit도 step을 소비해야 한다

**Claim / 재현 조건.** #15339는 main `2bb9468`, macOS arm64 CPU, Python 3.12.13·torch 2.15.0에서 tiny random `WanTransformer3DModel(num_layers=1)`을 사용한다. 4-step 설정, retention 0, magnitude ratios `[1,1,2,1]`에서 block 실행 여부를 hook으로 기록하는 weights 없는 fixture다. [원문](https://github.com/huggingface/diffusers/issues/15339)

**Observed gap / 작성자 주장.** 작성자는 full-compute 결정이 예상 `True, False, True, False` 대신 `True, False, False, False`이며 step counter가 `[1,1,1,1]`에 머문다고 보고한다. local fix의 회귀 테스트 통과도 주장하지만 공개 released one-block checkpoint나 출력 품질은 검사하지 않았다고 명시한다. AI coding agent의 조사·작성 지원을 공개했으며 독립 재실행 결과는 아니다.

**확인한 소스 / mechanism.** single-block 분기는 동일 block에 tail hook을 적용한 뒤 head hook을 적용한다. head의 cache-hit 경로는 residual을 반환하고, tail에는 별도 step 진행 코드가 있다. 이 구조는 head에서 빠르게 반환하면 tail의 state 갱신에 도달하지 못한다는 진단을 뒷받침한다. “계산을 생략했다”와 “논리적 timestep을 생략했다”를 구분해야 한다. [고정 소스](https://github.com/huggingface/diffusers/blob/2bb9468/src/diffusers/hooks/mag_cache.py)

**진단 → 가설 → 최소 실험.** 가설은 “빠른 실행의 일부가 정책상 필요한 refresh 누락에서 나온다”이다. CPU tiny model의 1-block/2-block, cache off/on에서 호출별 `step_index`, ratio index, 실제 attention 실행, 마지막 reset을 함께 기록한다. 같은 입력의 강제 refresh step에서는 uncached reference와 비교한다. 후속 pipeline 검증에서는 실제 scheduler timestep을 사용하고 두 번째 inference 시작 state도 검사한다.

**GO/KILL.** 논리적 4-step 진행·필요 refresh·종료 reset이 모두 맞으면 실제 checkpoint 검증으로 GO. tiny fixture의 수정만으로 일반 Wan 품질이나 모든 multi-block cache 동작을 검증했다고 말하는 것은 KILL. 수정 뒤 계산량이 늘었다면 이를 성능 회귀로만 판단하지 말고 누락된 계산 복원 여부를 먼저 확인한다. 이슈는 open·댓글 0이며 공개 병합 수정은 확인하지 못했다.

## 사례 3 — Z-Image: 출력 크기와 입력 전처리 크기의 불일치

**Claim / 재현 조건.** #15337은 `Tongyi-MAI/Z-Image-Turbo`, BF16, 256×256 입력에 128×128 출력을 요청하면 noise 결합 단계에서 16 대 32 tensor 크기 오류가 난다고 보고한다. 4 inference steps, strength 0.6, guidance 0이며, 크기를 생략하면 완료된다고 한다. 환경은 Diffusers `0.44.0.dev0`의 `e84bda1`, Linux·Python 3.12.3·torch `2.16.0a0+rocm10.3.0a20261117`, R9700, Transformers 5.23.0이다. checkpoint revision과 seed는 미확인이다. [원문](https://github.com/huggingface/diffusers/issues/15337)

**사실 / observed gap.** 고정 img2img 소스는 입력을 `preprocess(image)`로 처리하면서 noise shape는 별도의 height/width로 구성한다. inpaint도 입력 이미지에는 크기를 전달하지 않지만 mask에는 전달한다. 별도 댓글은 같은 소스 경로를 검토해 진단에 동의했으나 실제 실행 재현을 보고하지는 않았다. 작성자는 maintainer 확인 후 fix를 제출하겠다고 답했다. [img2img 고정 소스](https://github.com/huggingface/diffusers/blob/e84bda1c0005da3f48cc4c899635438cb0aa13c1/src/diffusers/pipelines/z_image/pipeline_z_image_img2img.py), [inpaint 고정 소스](https://github.com/huggingface/diffusers/blob/e84bda1c0005da3f48cc4c899635438cb0aa13c1/src/diffusers/pipelines/z_image/pipeline_z_image_inpaint.py), [별도 코드 검토](https://github.com/huggingface/diffusers/issues/15337#issuecomment-6995974104)

**진단 → 가설 → 최소 실험.** 가설은 “pipeline 간 실행 차이가 backbone이 아니라 resize 계약에서 발생한다”이다. 모델 실행 전에 같은 PIL 이미지·mask를 256→128, 동일 크기, 비정방형 조건으로 전처리하고 image/mask/encoded latent/noise shape를 검사한다. 전처리에 height/width를 전달한 후보와 원본을 비교한다. latent tensor 직접 입력 경로와 VAE 배수 제약도 따로 확인한다. 예외가 사라진 뒤에는 고정 interpolation·crop 정책으로 내용 정합성을 검증한다.

**GO/KILL.** 선언한 크기에 맞는 image/mask/latent/noise와 기대 출력 크기를 확인하면 GO. 단순히 사용자가 미리 resize해 완료됐다는 결과를 공식 수정으로 표시하거나 서로 다른 resize 정책의 품질을 직접 비교하는 것은 KILL. 이슈는 bug label이 있지만 open이며, 댓글의 코드 동의를 독립적인 모델 재현이나 maintainer 승인으로 확대하지 않는다.

## 공통 비교 조건과 오늘의 GO/KILL

세 사례군은 backbone·pretraining·data/split·resolution·hardware·precision·batch·TTA·evaluator가 일치하는 성능 비교가 아니다. 서로의 결과를 비교하는 것은 **not strictly apples-to-apples**다. synthetic fixture에는 dataset/split/TTA가 적용되지 않으며, 실제 모델의 immutable weight revision·일부 batch/evaluator 조건은 미확인이다. seed 숫자를 고정하는 것만으로 buffer·cache state·전처리 계약이 같아지지는 않는다.

- **오늘의 1순위 GO:** weights 없는 offload buffer fixture와 MagCache state trace를 먼저 설계한다. GPU fixture가 필요한 offload와 CPU로 가능한 cache 검사를 구분한다.
- **GO:** source/package revision, weight hash, buffer hash, offload 방식, stream, 호출 순서, cache state, processor resize 정책을 실험 manifest에 기록한다.
- **GO:** 계약 검사가 통과한 뒤 동일 조건의 seed 반복과 downstream metric을 측정한다.
- **KILL:** 사용자 제보·로컬 fix·댓글의 코드 검토를 공식 correction·병합·릴리스·독립 재현 완료로 바꾸어 말하지 않는다.
- **근거 부족:** 새 seed variance의 정량 분포, checkpoint와 논문 표의 동일 조건 격차, 누락 학습 hyperparameter를 확정할 근거는 확보하지 못했다. 이를 채우기 위한 수치를 만들지 않았다.
- **후속 연구 질문:** buffer 수명·논리적 step·shape 계약 검사가 seed sweep 전에 재현 실패를 얼마나 먼저 분리하는가? 같은 fixture의 사전 검사와 후속 실패를 함께 수집해야 반증 가능하며, 현재는 연구 가설이다.
