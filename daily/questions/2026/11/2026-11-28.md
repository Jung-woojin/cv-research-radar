## Q1. smoke dataset의 객체 수 분포가 export 오류를 숨기는 조건을 예측할 수 있는가?

**문제·Observation·왜 지금:** #27394는 SavedModel `nms=True` 변환에서 선택 index의 0 padding이 최고 점수 box의 반복으로 해석되는 문제를 수정했다. 기여자는 작은 detection 검증에서 변화가 없었지만 더 큰 COCO 검증에서는 영향이 있었다고 보고한다. 변경 코드는 `output_nms_with_dynamic_tensor=True`를 추가한다. [공식 PR·검증 조건](https://github.com/ultralytics/ultralytics/pull/27394) · [diff](https://github.com/ultralytics/ultralytics/pull/27394/files)

**Gap → Diagnosis → Mechanism:** 전일 질문은 class 순서와 좌표 표현이었다. 오늘은 평가 표본이 오류 발생 조건을 포함하는지가 문제다. 실제 NMS 선택 수 K가 출력 용량 D보다 작을 때 padding 경로가 실행된다. 이미지의 정답 객체 수만으로 K를 대신할 수는 없다. confidence threshold와 raw proposal 분포도 K를 바꾼다.

**Hypothesis·최소 개입:** 객체 밀도별 무작위 표본보다 K/D와 빈 출력 경계를 포함하는 표본이 이 종류의 export 실패를 더 잘 발견할 것이다. weight·raw prediction을 고정하고 D와 padding 방식만 조작한다.

**MVP·baseline·dataset:** CPU 합성 fixture에서 K=0, 1, D−1, D 및 후보 수가 D를 넘는 조건을 검사한다. 유효 index 0과 padding 0이 충돌하는 사례를 포함한다. baseline은 index gather 후 padding과 selected rows만 gather한 뒤 zero-row padding이다. 후속으로 같은 COCO val2017 이미지·weight의 ONNX/SavedModel을 비교한다. 수정 revision은 `df27cb0b73915192dce9a8049dde38631bceb990`으로 고정한다. 자연 데이터에서는 K/D, 객체 크기·밀도를 함께 층화하며 aerial 자료 확장은 별도 실험이다.

**Metric·GO/KILL:** 유효 행 수, 반복 box 수, count error, 빈 이미지 false positive, AP 및 크기별 recall을 기록한다. 같은 표본 예산의 random smoke와 경계 중심 smoke의 오류 검출률을 비교한다. **GO:** 경계 조건이 실패를 예측하고 padding 개입으로만 사라지면 여러 exporter로 확대한다. **KILL:** threshold나 raw output 차이가 원인이면 padding 단일 기전은 기각한다.

**Expected Contribution·Risk·계획:** export 검증 표본을 실패 경계에 맞춰 설계하는 절차다. 알려진 버그 테스트 한 개면 novelty가 낮다. 음성 결과도 어떤 K/D 범위에서 안전한지 정한다. **Compute cost 1/5**로 시작 가능하다. 1~2주 fixture, 3~4주 cached prediction, 5~8주 다른 backend·자연 데이터로 검증하는 계획이다.

## Q2. prefix cache의 수치 변화는 어느 조건에서 실제 시각 정답 변화로 이어지는가?

**문제·Observation·왜 지금:** #70266에는 greedy·순차 요청에서도 cache on/off의 이미지 응답이 달랐다는 제보가 있다. 후속 community 댓글은 긴 text에서도 cache hit 시 logprob 차이를 보고했다. 다른 text 검사에서는 logprob가 달라도 생성 문자열은 같았다. 따라서 “이미지 cache 손상”이나 “정확도 저하”는 현재 근거로 확정할 수 없다. [issue·최소 요청 코드](https://github.com/vllm-project/vllm/issues/70266) · [dispatch 진단](https://github.com/vllm-project/vllm/issues/70266#issuecomment-7219155297) · [문자열 유지 반례](https://github.com/vllm-project/vllm/issues/70266#issuecomment-7223013380)

**Gap → Diagnosis → Mechanism:** 재현은 출력 동치 위반을 보여주지만 task 의미의 피해량을 분리하지 않는다. community의 설명은 cache hit 이후 prefill 길이가 줄어 kernel dispatch·reduction 순서가 바뀐다는 것이다. 이는 공식 확정 원인이 아닌 진단 제안이다.

**Hypothesis·최소 개입:** 수치 차이의 크기만보다 첫 분기 직전의 top-token margin이 작을 때 의미적 답 전환이 많을 것이다. cache 상태를 조작하되 모델·이미지·질문 의미와 decoding 조건을 고정한다. margin과 분기의 연관만으로 인과를 확정하지 않는다.

**MVP·baseline·dataset:** 먼저 공개 로그에서 cached_tokens, prompt 길이, 첫 logprob·token 불일치를 정리한다. GPU 확보 후 text/image × cache off/cold/warm × cache block 경계 전후 길이의 paired panel을 구성한다. 원 issue의 합성 이미지와 정답을 수작업으로 확인할 수 있는 색·개수·위치 문항부터 시작한다. 길이 개입이 질문 내용까지 바꾸지 않도록 중립 prefix를 고정하고 off/off 새 프로세스 대조군을 둔다. 원 제보 revision과 실제 서버 build를 각각 기록한다.

**Metric·GO/KILL:** cache hit, first divergence, token margin, exact match, 의미 정답률, 위치·개수별 전환, latency를 따로 보고한다. **GO:** 실제 hit에 조건부인 분기가 반복되고 실행 경로 고정 개입으로 줄면 확장한다. **KILL:** preprocessing·template 변화나 cached=0에서도 같은 현상이 있으면 단일 cache 설명을 중단한다. 문자열 불일치만으로 hallucination 증가를 주장하지 않는다.

**Expected Contribution·Risk·계획:** serving 수치 비동치가 task 의미로 전파되는 경계를 진단한다. 기존 batch invariance 연구와 중복되므로 visual task별 기전이 필요하다. 음성 결과는 의미 정답이 유지되는 허용 범위를 제공한다. **로그 감사 cost 1/5, 원 환경 실행 cost 5/5**다. H100급 제보 환경을 RTX 5060 Ti 8GB에서 재현 가능하다고 보지 않는다. 1~2주 로그, 3~4주 paired panel, 5~8주 실행 경로 개입을 계획하되 GPU 미확보 시 보류한다.

## Q3. 다중 이미지 VQA의 실패 중 얼마나 이미지–선택지 결합 부담에서 발생하는가?

**문제·Observation·왜 지금:** MuirBench 변경 `757f01500c77fd9043611bcea6ad8b012579426b`은 chat 입력에서 이미지를 `<image>` marker 위치에 삽입한다. marker 수가 다르면 images-first로 fallback한다. 원본 prompt와 adapter의 선택지 표기 등은 여전히 다르다. 새 정확도 향상량은 이 diff에서 확인되지 않는다. [공식 변경·테스트](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/757f01500c77fd9043611bcea6ad8b012579426b) · [원본 prompt](https://github.com/muirbench/MuirBench/blob/main/eval/utils/preprocess.py)

**Gap → Diagnosis → Mechanism:** marker 개수·순서가 맞아도 실제 이미지 ID와 선택지 의미의 결합이 보장되지는 않는다. reasoning 오류처럼 보이는 실패에 입력 결합 복구 부담이 섞일 수 있다. 이전 이미지–텍스트 대응 질문보다 이번에는 선택지 결합과 순열에 대한 예측을 구체화한다.

**Hypothesis·최소 개입:** interleaving의 효과가 일반적인 이미지 수보다 선택지에 이미지가 포함되는 조건에 집중될 것이다. 선택지 순열과 정답 라벨을 함께 바꾸어 의미를 보존하면 올바른 결합을 사용하는 모델은 답의 의미를 유지해야 한다.

**MVP·baseline·dataset:** MuirBench test의 answerable/unanswerable 쌍을 유지한 소규모 층화 panel을 사용한다. images-first/interleaved × 원래 선택지/의미 보존 순열을 비교한다. prompt 표기·parser·이미지 processor는 동일하게 두고 배치만 바꾼다. 첫 단계는 실제 backend까지 전달된 message와 image hash·option boundary·fallback을 CPU로 감사한다. 이후 같은 checkpoint의 paired 재추론이 필요하다. 저장 답 재채점만으로 입력 효과를 측정할 수 없다.

**Metric·GO/KILL:** 결합 감사 통과율, 순열 동치율, 이미지 선택지/텍스트 선택지별 accuracy, abstention accuracy, 쌍 단위 공동 정답률과 전환 수를 기록한다. **GO:** 결합 복구 후 해당 유형에서 일관된 효과가 나타나면 안전 VQA로 확장한다. **KILL:** backend가 재배열하거나 parser·prompt 변화가 섞이면 reasoning 결론을 중단한다.

**Expected Contribution·Risk·계획:** reasoning과 입력 binding 부담을 분리한 paired diagnostic이다. 기존 image-order bias와 겹치므로 동치 변환과 실제 전송 감사를 함께 제공해야 한다. 음성 결과는 해당 backend에서 배치 강건성이 유지된다는 결론이다. **감사 cost 1/5, 소형 모델 panel cost 2/5**이며 checkpoint의 실제 8GB 적합성은 별도 확인한다. 1~2주 감사, 3~4주 panel, 5~8주 도메인 전이를 계획한다.

## Q4. 문서 VLM의 점수 차이를 내용 인식·출력 형식·평가 분모로 분해할 수 있는가?

**문제·Observation·왜 지금:** ParseBench-2 native adapter는 공식 scorer 2.0.1과 고정 데이터 revision을 사용한다. 잘못된 JSON에서 Markdown을 복구할 수 있고, layout 오류와 내용 점수가 공존할 수 있다. reference 평가 불가·예측 누락·인프라 실패는 동일한 분모 처리를 받지 않는다. [adapter README](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/1a6181731a23a9afb78c74adfe7a2eb8cdbb6400/lmms_eval/tasks/parsebench2/README.md) · [원본 가중치·결측 규칙](https://github.com/run-llama/ParseBench/blob/v2.0.1/src/parse_bench/evaluation/next_score.py)

**Gap → Diagnosis → Mechanism:** 형식 실패율이 낮아도 layout grounding이 정확하다는 뜻은 아니다. 반대로 텍스트가 복구되어도 구조화 출력 계약은 실패할 수 있다. 실패만 있는 subset은 metric slot이 없을 수 있어 모든 실패를 일률적으로 overall 0으로 처리해서도 안 된다. [분모 회귀 테스트](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/1a6181731a23a9afb78c74adfe7a2eb8cdbb6400/test/tasks/test_parsebench2_eligibility.py)

**Hypothesis·최소 개입:** 저장 응답을 고정한 표현 복구와 새 constrained generation을 구별하면 점수 회복 중 parser 기여와 generation 기여를 분리할 수 있다. 복구는 정답을 참조하지 않는 결정론적 규칙으로 제한하고 새 좌표·누락 내용을 생성하지 않는다.

**MVP·baseline·dataset:** 고정 ParseBench-2 snapshot의 저장 출력에서 raw/공식 복구/보수적 표현 복구를 paired 재채점한다. 먼저 reference eligibility와 scorer 오류를 audit하고, 성공·실패·skip·slot별 문서 수를 공식 CLI와 대조한다. 새 모델 비교는 별도 단계다. 부분 panel에서 빠진 dimension을 임의 평균해 overall로 발표하지 않는다.

**Metric·GO/KILL:** 내용 dimension, layout grounding, response status, valid-layout coverage, scorer 오류율·분모와 수작업 의미 보존율을 함께 기록한다. **GO:** 같은 응답의 내용·좌표 의미를 보존한 채 표현 처리 기여가 분리되면 새 generation 실험으로 간다. **KILL:** 어려운 응답을 제외하거나 누락 내용을 만들어 점수를 올리면 기각한다. 공식 점수와 별도의 coverage 진단을 혼합한 새 수치를 공식 지표로 부르지 않는다.

**Expected Contribution·Risk·계획:** Answer–Region Gap의 문서형 사례로, 읽은 내용과 위치 증거·형식 준수를 분리한다. scorer parity 확인만으로는 기여가 작다. 음성 결과는 해당 출력에서 형식 복구로 해결되지 않는 실제 인식·위치 오류의 범위를 정한다. **Compute cost 1/5**부터 시작하며 전체 렌더링은 CPU 시간이 클 수 있다. 1~2주 replay, 3~4주 오류 panel, 5~8주 소형 모델 output contract 비교를 계획한다.

**Gap → Diagnosis → Mechanism:** graph와 config의 shape가 같아도 calibration이 의도한 밴드 순서·동적 범위를 보존한다는 뜻은 아니다. 이번 수정은 grayscale 지원 근거이며 multispectral 지원 근거가 아니다. 원격탐사 모델의 성능 저하를 representation 한계로 분석하기 전에 입력 의미 보존이 확인돼야 한다.

**Hypothesis·최소 개입:** 각 밴드에 구별되는 합성 신호를 넣은 provenance 검사가 shape 검사만으로 놓치는 순서·정규화 손실을 검출할 것이다. 의미 보존 대조군은 밴드 순열과 모델 첫 층의 역대응을 함께 적용하는 경우다. 밴드만 섞는 것은 의도적인 비동치 음성 대조다.

**MVP·baseline·dataset:** 1/3/4/10채널 합성 tensor에서 graph input, JSON, calibration 직후 tensor의 shape·밴드별 통계·hash를 비교한다. baseline은 CPU reference preprocessing이다. DEEPX의 미지원 경로는 지원 실패로 기록하고 가짜 RGB 복제로 통과시키지 않는다. 실제 remote-sensing dataset은 센서·밴드 정의가 확인된 후 선택하며 오늘 특정 데이터의 backend 지원을 주장하지 않는다. 수정 revision은 `7ca61cb80a2e2b0348ebc0c03dbd710638cad217`이다.

**Metric·GO/KILL:** 단계별 지원/실패, 밴드 대응, tensor 오차·포화율을 먼저 본다. 지원되는 실행 경로 확보 후 detection의 작은 객체 recall과 calibration 전후 차이를 측정한다. **GO:** reference 경로에서 의미 동치가 보존되고 특정 변환 단계의 위반이 분리되면 확대한다. **KILL/보류:** loader 미지원이면 실물 정확도 실험을 보류한다. compilation 성공을 센서 정보 보존으로 판정하지 않는다.

**Expected Contribution·Risk·계획:** 밴드 의미의 provenance를 calibration·배포 평가로 연결한다. 알려진 채널 설정 버그만 수정하면 논문화 가치는 낮다. 음성 결과는 지원 범위와 의미 보존 조건을 제공한다. **CPU 감사 cost 1/5**, compiler·실물 평가는 별도 장치가 필요하다. 1~2주 fixture, 3~4주 reference pipeline, 5~8주 지원 backend의 도메인 검증을 계획한다.

## 비교 조건·우선순위·다음 행동

점수는 조사자의 우선순위 판단이며 실측·출판 보장이 아니다. Compute cost는 낮을수록 가볍고 compute efficiency는 높을수록 유리하다. 모든 4~8주 일정은 검증 계획이며 논문화 가능성은 다중 구현·자연 데이터 근거 확보에 달려 있다.

- **오늘 가장 먼저 테스트:** Q1의 CPU 유효 출력 수 경계 검사. 전일 class 순열 실험과 다른 축을 검사한다.
- **RTX 5060 Ti 8GB에서도 시작 가능:** Q1 합성 fixture, Q3 message 감사, Q4 저장 응답 감사, Q5 reference preprocessing은 CPU부터 가능하다. Q2 원 환경·대형 모델·실물 NPU 실행의 가능성은 확인하지 않았다.
- **장기 박사주제로 확장:** UAV·해양 안전의 시각 판단을 입력 대응, 수치·실행 상태, 출력 의미, 평가 계약으로 분해하는 연구다. 공통 틀은 재사용하되 서로 다른 오류를 하나의 기전으로 합치지 않는다.

오늘 달라진 것은 모델 규모가 아니라 변환·전송·채점 경계의 구체적 근거다. 아직 풀리지 않은 문제는 이러한 경계 위반이 실제 시각 정답과 작은 객체 성능을 얼마나 바꾸는지이며, 다음 행동은 고정 입력과 최소 개입으로 그 영향을 분리하는 것이다.
