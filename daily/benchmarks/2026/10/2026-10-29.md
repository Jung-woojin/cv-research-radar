## 1. MoI-Bench — 모바일 생성·편집 평가를 ‘품질 대 배포 가능성’으로 분리

**확인된 사실.** [MoI-Bench](https://arxiv.org/abs/2610.37599)는 2026-10-27 v1으로 공개됐다. 16개 operation(예: removal/replacement)과 portrait/text 등을 포함한 8개 visual target category의 조합으로 64개 subtasks, 1,150 samples를 구성한다. MoI-Eval은 instruction following, visual quality, detail preservation의 task-specific criterion을 사용하며, sample-level 질문을 quality 및 operation/target/criterion profile로 집계한다. 또한 mobile deployment cost를 측정하고 Quality–Deployability capability map을 제안한다.

**저자 주장.** 저자들은 이 설계가 broad application-level 목표보다 text replacement 같은 세부 capability gap을 더 잘 드러내며, 현재 on-device model은 배포 효율보다 task coverage와 identity/text detail 품질 개선이 더 시급하다고 주장한다.

**동조건 판정.** 같은 device, runtime, resolution, quantization, warm-up/measurement rule을 고정한 MoI-Bench 내부 비교만 apples-to-apples다. 서로 다른 paper의 mobile cost나 cloud model quality를 map의 같은 좌표로 놓는 것은 not strictly apples-to-apples다.

**진단 → 가설.** 단일 quality 평균은 사용자에게 중요한 편집 실패(텍스트·identity·세부 보존)를 숨긴다. operation×target failure profile을 기록하면 parameter 수보다 실제 개선 우선순위를 더 잘 정할 수 있다.

**최소 실험.** 30개 항만 이미지에 object removal, vessel replacement, text overlay 수정의 각 10개 요청을 만든다. instruction success, object identity preservation, text legibility, image당 latency/peak memory를 분리 기록한다. 평균 quality만 높은 모델과 worst-subtask 실패가 적은 모델이 실제 선호에서 어떻게 다른지 확인한다.

## 2. ImagiRep — 공간 reasoning은 RGB imagination accuracy와 별개로 평가해야 함

**확인된 사실.** [ImagiRep](https://arxiv.org/abs/2610.37437)는 2026-10-27 v1으로, Viewpoint Imagination과 Cross-view Integration 두 setting에서 7개 질문 유형, 총 922문항을 만든 simulator-grounded benchmark다. 동일한 미관측 상태에 oracle RGB와 depth·panoramic view·top-down geometry 등 여섯 대안 표현을 제공한다. 저자들은 정확한 imagined RGB도 정확한 spatial reasoning을 보장하지 않으며, 질문마다 좋은 표현이 다르다고 보고한다.

**저자 주장.** lightweight test-time representation selector인 GEARS가 기존 spatial-imagination 방법보다 우수하다고 주장한다.

**동조건 판정.** 같은 simulator state와 질문에 oracle representation을 바꾼 controlled comparison은 강한 내부 통제다. 그러나 estimated-state 결과와 실제 aerial/road video는 camera pose error, occlusion, sensor noise가 달라 not strictly apples-to-apples다.

**진단 → 가설.** model이 ‘보이지 않는 곳’을 RGB로 잘 채우는 것과, 거리·방향·open space를 맞히는 것은 다른 readout 문제일 수 있다. answer disagreement가 큰 질문에서 geometry proxy나 panorama로 전환하면 실질 이득이 날 수 있다.

**최소 실험.** 동일 항만 장면 50개에서 original image, 2× crop mosaic, coarse top-down map proxy의 세 표현으로 거리/방향/존재 질문을 낸다. answer consistency, accuracy, token cost를 기록하고, disagreement가 큰 25%에서만 표현 전환이 평균보다 이득인지 본다.

## 3. CodeCap-Bench — video evidence 표현의 충실성을 자연어 밖에서 평가

**확인된 사실.** [CodeCap-Bench](https://arxiv.org/abs/2610.37341)는 2026-10-27 v1으로 공개됐다. time function, graphical primitive, layout rule을 갖는 executable program을 video의 보조 caption으로 쓰는지를 탐색하며, 5개 structured 2D category의 323 videos와 fine-grained annotation, multi-level evaluation framework를 제공한다. 자연어 caption과 code caption을 downstream QA·video reconstruction에서 비교한다.

**저자 주장.** code caption이 reasoning accuracy와 reconstruction fidelity에서 더 좋다고 보고하지만, leading proprietary MLLM도 복잡한 temporal dynamics의 faithful capture에는 어려움이 있고 open-source model은 더 뒤처진다고 주장한다.

**동조건 판정.** 같은 323 video와 동일 evaluation framework 안에서 caption 형식을 비교할 때만 직접 비교 가능하다. 자연 영상·long-video QA·tracking benchmark에 바로 옮긴 우위 주장은 not strictly apples-to-apples다.

**진단 → 가설.** 자연어 rationale은 공간 관계와 시간 순서를 압축하면서 모호해져, 정답은 맞아도 어떤 시각 evidence를 썼는지 감사하기 어렵다. 실행 가능한 event/region trace는 counterfactual edit로 evidence faithfulness를 시험하게 할 수 있다.

**최소 실험.** 구조화된 2D clip 80개에서 `appear`, `move`, `overlap`, `before/after` 네 primitive만 쓰는 trace를 생성한다. natural-language trace와 비교해 syntax validity, QA accuracy, 관련 event를 마스킹했을 때 answer flip rate, hallucinated object rate를 기록한다.

## 오늘의 benchmark signal 3개

1. **평균 품질만으로 배포 우선순위를 정하지 말 것:** task coverage와 device cost를 같은 판에 놓되, runtime 조건을 고정해야 한다.
2. **생성 표현과 추론 표현을 분리할 것:** RGB가 좋다는 점은 spatial question에 가장 좋은 evidence라는 뜻이 아니다.
3. **정답과 evidence fidelity를 분리할 것:** 자연어 rationale만으로는 video evidence 사용을 검증하기 어렵다.
