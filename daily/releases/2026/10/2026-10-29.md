## 진단 — “개발 활동”과 “사용 가능한 research artifact”는 다르다

**확인 사실.** [NVIDIA Model Optimizer pull requests](https://github.com/NVIDIA/Model-Optimizer/pulls)는 10월 27일 기준 expert quantization, exported weight names, VLM collator media-load retry 등의 작업 PR을 표시합니다.  
**판정.** open PR은 향후 artifact 변화 신호일 수 있지만, merge된 revision·release tag·배포 wheel·model/checkpoint URI·evaluator script가 없으면 사용 가능한 공개 release가 아닙니다.  
**가능한 mechanism.** export weight name·per-expert scale 변경은 loader 호환성이나 quantized model correctness에 영향을 줄 수 있으므로, merge 전 checkpoint를 이식하면 silent mismatch가 생길 수 있습니다.  
**최소 검증.** 다음 stable tag에서 release note, wheel checksum, 예제 export command, source/checkpoint revision, one-command load/evaluator를 함께 확인합니다.  
**GO/KILL.** GO: tag와 checksum, supported runtime matrix, smoke-test 결과가 모두 있을 때. KILL/보류: PR만 있고 versioned artifact가 없을 때.

## 관찰 — data lineage 문서는 artifact 준비도의 일부일 뿐이다

**확인 사실.** [QEV vision training-data manifest](https://huggingface.co/datasets/ken-jo/qev-data/blob/main/vision-mix-2026-10/README.md)는 17개 third-party source의 item ID·source·subtask·hash·holdout flag manifest와 synthetic item/image를 기술하며, 일부 third-party data는 재배포하지 않는다고 밝힙니다.  
**판정.** manifest가 data audit에는 도움이 되지만, 이 점검에서는 model authorship, immutable dataset revision, license chain, training/evaluation entry point가 충분히 검증되지 않았습니다. 따라서 신규 official dataset release로 넣지 않습니다.  
**최소 검증.** dataset revision hash, source license 표, split manifest, model-training commit과 evaluator command가 같은 release에 연결되는지 확인합니다.  
**GO/KILL.** GO: immutable revision과 license·split·training/evaluation 연결이 공개될 때. KILL/보류: provenance만 있고 exact artifact identity가 없는 경우.

## 공통 진단 → 가설 → 최소 실험

**진단.** 오늘 조사창에서는 논문·PR·dataset 문서는 있었지만, 재현 가능한 새 release를 판정할 기본 단위—version/tag, immutable artifact hash, license, install surface, evaluator—가 동시에 확인된 신규 항목은 없었습니다.

**가설.** 논문 주장과 공개 artifact의 차이는 release note보다 artifact identity와 evaluator pin을 같은 manifest에 고정할 때 가장 빠르게 드러납니다.

**최소 개입.**

1. release tag/commit, model·data hash, license, dependency lockfile을 한 표에 기록한다.
2. weights가 있으면 base model과 adapter/delta 관계를 명시한다.
3. data는 split/group manifest와 access restriction을 함께 기록한다.
4. 10–30분 smoke test는 install → load → single inference/evaluation → expected output/tolerance 순서로 제한한다.

**오늘의 GO/KILL.**

- GO: 다음 release가 immutable tag·checksum·runtime matrix·evaluator command를 동반하면 즉시 smoke test 후보로 올립니다.
- KILL/보류: paper v1, open PR, topic update, 게시 시각 미확인 model card는 신규 release commit의 근거로 사용하지 않습니다.
