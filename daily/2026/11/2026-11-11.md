4. Ultralytics 8.4.208은 predict/tracking NMS IoU 기본값만 0.7→0.5로 변경하고 validation은 0.7로 유지한다. 배포와 validation의 protocol drift가 핵심 위험이다.
5. 같은 릴리스의 YOLOE visual prompt 기본 confidence 0.05와 TensorRT FP16 속도 표기는 조건부 변경이며, 현장 모델 비교 수치로 일반화할 근거가 아니다.
6. V-Thinker 공개물은 11월 7일 preview 데이터·VTBench를 공개했다. 최신 72시간 핵심 신호로는 두지 않았지만, 지각·지시·추론 오류를 분리하는 평가 설계의 watchlist로 유지한다.
7. 후보 14개를 검토해 공식 릴리스 또는 원문으로 변경 범위가 확인되는 5개 신호만 남겼다. 새 논문 수를 채우기 위한 불확인 성능 수치는 제외했다.
8. 오늘의 실행 우선순위는 모델 교체가 아니라 NMS/adapter/runtime을 고정한 golden-set 회귀 검증과 오류 slice 기록이다.

## 1) 오늘의 CV/VLM 트렌드

- CV 라이브러리의 bug-fix도 detection 수, class name, tracker 출력처럼 평가 입력 자체를 바꿀 수 있다.
- VLM connector는 “로드됨”과 “원 논문의 성능이 재현됨”을 구분해야 한다.
- inference/tracking과 validation의 기본 후처리가 다르면 같은 checkpoint도 서로 다른 protocol에서 비교된다.
- speed claim은 GPU·runtime·shape·batch·warm-up과 함께 기록하지 않으면 의사결정 근거가 되지 못한다.
- 최신 논문보다 검증 가능한 source가 희소한 날에는 변화가 확정된 framework/dataset artifact를 보존하는 편이 더 안전하다.

## 2) CV / DL-CV 핵심

### Supervision 0.31.6 — empty-frame keypoint 회귀 제거

- **사실:** 11월 10일 공식 릴리스는 사람이 없는 frame에서 `KeyPoints.empty()`의 confidence/class array가 `None`이어서 filter가 실패하던 문제와 empty indexing 오류를 수정했다. [공식 릴리스](https://github.com/roboflow/supervision/releases)
- **진단:** pose/video evaluation에서 empty frame이 드물어도, 단일 예외가 batch-level metric 또는 visualization run 전체를 중단시킬 수 있다.
- **가설:** empty-frame을 제외하는 기존 평가 코드는 새 버전에서 “오류 없음”으로 보이는 개선을 score 개선으로 오해할 수 있다.
- **최소 실험:** 사람이 없는 frame을 포함한 고정 100-frame set에서 0.31.5/0.31.6의 exception 수, valid-frame denominator, keypoint metric을 비교한다.
- **한계:** 이는 adapter robustness 수정이며 pose model의 accuracy 향상을 뜻하지 않는다.

### Supervision 0.31.6 — unconfirmed track의 phantom box 제거

- **사실:** 공식 릴리스는 negative `tracker_id`를 갖는 미확정 track들이 기존에는 한 history로 평균화되어 하나의 phantom box가 되던 문제를 수정했고, 이제 각 box를 유지한다. [공식 릴리스](https://github.com/roboflow/supervision/releases)
- **진단:** crowded scene의 count, trajectory, event-trigger 결과가 tracker model 변화 없이 달라질 수 있다.
- **가설:** 미확정 객체가 많은 초반 frame 또는 occlusion 재진입 구간에서 count error와 ID 관련 지표가 가장 크게 달라진다.
- **최소 실험:** 동일 detector/tracker output을 두 버전의 smoother에 투입하고 detection count, IDF1, line-crossing count를 confirmed/unconfirmed 상태별로 비교한다.
- **주의:** release migration note대로 출력 row 수가 달라질 수 있으므로 기존 golden output은 재생성해야 한다.

### Supervision 0.31.6 — Transformers 결과의 semantic label/provenance

- **사실:** 공식 릴리스는 Grounding DINO 결과, RF-DETR binary-map segmentation, OWL-ViT/OWLv2/OmDet-Turbo 결과의 변환을 보완하며, 후자 계열은 `id2label`의 일반 label 대신 `text_labels` 기반 class name을 보존한다. [공식 릴리스](https://github.com/roboflow/supervision/releases)
- **진단:** zero-shot detector의 label text는 prompt와 결과를 잇는 provenance다. 이를 `LABEL_0` 같은 placeholder로 잃으면 class-level slice가 의미를 잃는다.
- **가설:** open-vocabulary evaluator에서 class-name recovery는 aggregate mAP보다 prompt별 error attribution을 먼저 개선한다.
- **최소 실험:** 동일 image/prompt set으로 connector 전후의 box, score, `class_id`, class name을 저장해 prompt-to-label bijection과 per-prompt AP가 유지되는지 검사한다.
- **한계:** connector가 모델의 grounding quality나 segmentation quality를 높였다는 주장은 아니다.

### Ultralytics 8.4.208 — prediction/tracking과 validation의 NMS 기본값 분리

- **사실:** 11월 8일 공식 릴리스는 prediction/tracking에서 미지정 `iou` 기본값을 0.7에서 0.5로 낮췄고 validation은 0.7을 유지한다고 명시한다. [공식 릴리스](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.208)
- **진단:** validation AP와 deployed tracking/count가 서로 다른 suppression rule을 쓰면 모델 개선과 configuration change가 섞인다.
- **가설:** crowded/small-object slice에서 0.5는 duplicate를 줄이는 대신 인접 객체 recall 또는 track continuity를 낮출 수 있다.
- **최소 실험:** checkpoint·입력 크기·score threshold·tracker를 고정하고 IoU 0.5/0.7만 바꿔 AP, small-object recall, IDF1, count error를 scene-density별로 기록한다.
- **한계:** 어느 값이 “더 좋다”는 결론은 task loss와 deployment objective가 정해지기 전에는 낼 수 없다.

### Ultralytics 8.4.208 — visual prompt·TensorRT 수치의 조건부 해석

- **사실:** 동일 릴리스는 YOLOE visual prompt의 기본 `conf`를 0.05로 두고, NMS-free TensorRT 11 FP16 export가 최대 3% 빠를 수 있다고 설명한다. [공식 릴리스](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.208)
- **저자 주장:** 최대 3%는 릴리스에 제시된 조건부 속도 주장이다.
- **진단:** prompt confidence와 NMS 변화는 precision/recall curve를, TensorRT export path는 latency를 바꾸므로 하나의 “release improvement”로 합산할 수 없다.
- **최소 실험:** visual prompt set에서 `conf` 0.05와 기존 설정을 precision/recall·false-positive taxonomy로 비교하고, TensorRT는 GPU·TRT 버전·shape·batch·p50/p95를 별도로 기록한다.

- **사실:** 공식 프로젝트는 11월 7일 V-Interaction-400K preview(252K samples), V-Perception-40K preview(37K samples), 그리고 perception·instruction-guided interaction·interactive reasoning 세 task를 표방하는 VTBench 공개를 알렸다. [공식 프로젝트](https://github.com/We-Math/V-Thinker)

## 8) Top 1 미니 리뷰 — Supervision 0.31.6

**문제 진단:** CV pipeline은 model output을 tracker, converter, annotation, metric으로 넘긴다. 이 사이의 object schema 오류는 model change 없이 결과를 바꾼다.

**확정된 변화:** empty keypoint handling, unconfirmed-track smoothing, Grounding DINO/RF-DETR/OWL 계열 결과 변환이 수정됐다.

**가설:** version upgrade 뒤 가장 민감하게 변하는 값은 headline AP보다 empty-frame pass rate, detection row count, text-label coverage, event count다.

**최소 실험:** 고정된 pose/track/open-vocabulary golden set을 0.31.5와 0.31.6에 통과시켜 exception, boxes/labels, IDF1, line count를 diff한다. seed, input, model checkpoint, connector configuration은 고정한다.

**기여 판정:** output changes가 release note와 일치하고 downstream metric 변화가 해당 slice에 국한되면 version effect로 귀속한다. 그렇지 않으면 model/runtime drift를 추가 조사한다.

**재현 주의:** stored output이나 regression snapshot을 섞어 쓰지 말고, 전후 결과·패키지 lockfile·converter version을 함께 보관한다.

## 9) 후속 연구 씨앗

### A. Adapter provenance audit

- **질문:** open-vocabulary CV/VLM connector가 prompt label을 잃을 때 error analysis는 얼마나 왜곡되는가?
- **최소 실험:** prompt별 golden inputs에서 converter 전후 label coverage, box agreement, per-prompt AP를 비교한다.
- **반증:** class name 복구가 slice 결론을 바꾸지 않으면 label provenance의 실질 영향은 작다.

### B. NMS deployment gap matrix

- **질문:** NMS 기본값 차이가 validation-deployment gap의 주된 원인인가?
- **최소 실험:** IoU 0.4–0.8 sweep과 scene density slice로 AP·IDF1·count error·latency를 함께 기록한다.
- **반증:** 모든 slice에서 모델 순위가 유지되면 default sensitivity가 낮다는 유용한 negative result다.

### C. VLM three-stage error routing

- **질문:** perception 실패, instruction grounding 실패, reasoning 실패는 evidence intervention에 다르게 반응하는가?
- **최소 실험:** VTBench-style scene에서 evidence mask, instruction paraphrase, tool trace를 하나씩 조작하고 conditional error transition을 측정한다.
- **반증:** 모든 개입이 동일한 방향·크기로 작용하면 세 bucket 분리의 실험적 이득은 제한적이다.
