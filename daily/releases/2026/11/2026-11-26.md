## 1. Ultralytics v8.4.219 — AP 규칙 변경을 모델 개선과 분리해야 한다

**확인한 사실.** [공식 release](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.219)는 11월 26일 08:28:37 KST 발행됐다. annotated tag object는 `d892958aa6fc4a7b603bda3ed7147a6edabca760`, 대상 commit은 `3a31e32f2e254a13f86ea274d6331e19d0cb4d47`이다. [태그 metadata](https://api.github.com/repos/ultralytics/ultralytics/git/tags/d892958aa6fc4a7b603bda3ed7147a6edabca760)는 `unsigned`로 표시한다. commit 서명과 tag 서명은 구분해야 한다.

[고정 metrics.py](https://github.com/ultralytics/ultralytics/blob/3a31e32f2e254a13f86ea274d6331e19d0cb4d47/ultralytics/utils/metrics.py)는 trapezoidal interpolation 대신 101개 recall threshold에서 precision envelope를 조회해 평균한다. 클래스별 confidence 정렬은 stable ordering을 사용한다. [PR #27370](https://github.com/ultralytics/ultralytics/pull/27370)은 11월 25일 23:27:25 UTC merge됐으며 태그 대상 commit과 일치한다. 앞선 #27368 수정은 #27369에서 revert됐지만, 최종 태그에는 #27370의 AP 변경이 실제로 존재한다. release의 “앞선 제안이 revert됐다”는 문장을 “AP 변경이 전혀 없다”로 읽으면 안 된다.

**저자 주장.** PR은 동일 match·ignore decision을 입력할 때 COCOeval과 매우 작은 오차로 일치한다고 보고한다. 완벽한 검출의 AP가 기존 0.995에서 1.0이 되고, 동일 weights와 prediction도 native mAP가 오르거나 내릴 수 있다고 명시한다. 공개 regression test는 confidence tie, partial recall, prediction이 없는 class, PR curve 끝점을 포함한다. 이는 저자가 제공한 테스트와 측정이며 이번 실행의 독립 재현 결과가 아니다.

**주장과 공개 artifact의 간극.** “pycocotools와 일치”의 조건을 제거하면 과장된다. PR의 RTX PRO 6000 추론 결과에서 detection box native mAP50–95는 0.400638→0.401626이지만 독립 COCOeval은 0.406341이다. pose keypoint는 0.565125→0.564421이며 독립 COCOeval 0.569669와의 간극이 오히려 커졌다. AP aggregation을 맞춰도 matcher, ignore 처리, export 정밀도, ground-truth population 차이가 남을 수 있다.

같은 PR의 pose-box 비교는 native target 6,352명과 COCO bbox non-crowd 9,349명으로 모집단이 다르다. 이 비교는 **not strictly apples-to-apples**다. DOTA는 5,297개 tile 중 잘못된 annotation 19개를 제외한 5,278개를 사용했다고 저자가 밝힌다. 별도의 Apple M5 Pro 추론 결과와 RTX 결과도 동일 prediction 집합이 아니다.

**효율 수치의 경계.** 약 2.6배 CPU 가속은 모델 추론 가속이 아니다. PR의 cross-task 측정은 AMD EPYC 9655에서 일곱 번의 warm CPU scoring 중앙값이며 peak allocation은 입력 배열을 제외한다. detection·segmentation은 640 px/maxDet 100, pose는 640 px/maxDet 20, OBB는 1,024 px/maxDet 300이다. 이를 전체 validation wall-clock이나 GPU peak VRAM 감소로 옮기지 않는다.

**공개물·설치·license.** 이 이벤트에서 새 model weights나 dataset을 확인하지 않았다. code license는 AGPL-3.0이다. [고정 pyproject](https://github.com/ultralytics/ultralytics/blob/3a31e32f2e254a13f86ea274d6331e19d0cb4d47/pyproject.toml)는 Python ≥3.8, NumPy·torch·torchvision·OpenCV 등의 의존성을 선언한다. 재현 시 `ultralytics==8.4.219`와 비교용 `8.4.218`을 별도 환경에 고정하고 NumPy·pycocotools도 기록해야 한다. package pin만으로 전체 dependency가 고정되지는 않는다.

공식 release asset `sbom.spdx.json`의 API digest는 `sha256:59e456cc88898e40c155488d5b3efedceb0b8f67b93ef6ef0506accac931f7e2`다. 이는 SBOM 파일의 metadata이며 wheel checksum이나 다운로드 후 검증값이 아니다. 공개 PR의 merge·테스트 추가는 확인했으나 모든 관련 issue의 해결을 보장하지 않는다.

**추론 — 진단 → 가설 → 최소 실험, 10~30분 계획.**

1. CPU에서 고정 TP/FP·confidence·class·target count 배열을 두 버전 scorer에 동일하게 입력한다. 완전 검출, 반쪽 recall, tie, missing-class fixture로 AP 규칙 차이만 분리한다.
2. 저장된 COCO prediction 하나를 사용해 **동일 match/ignore → scorer만 교체**한 결과와 **각 matcher까지 포함**한 결과를 나눈다.
3. 남은 차이는 crowd·maxDet·area bucket·annotation population·JSON rounding 순서로 검사한다. backbone, weights, data/split, resolution, pretraining, precision, batch, hardware, TTA는 고정한다.

**GO:** 학습 없이 evaluator migration audit부터 진행한다. CPU fixture에는 GPU VRAM이 필요 없다. full validation의 GPU 최소 VRAM은 확인하지 않았다.  
**KILL:** 패키지 변경 전후 mAP 차이를 새 architecture·weight의 성능 향상으로 보고하지 않는다.

## 2. Supervision 0.32.2 — representation보다 ID 배선과 파서를 먼저 의심한다

**확인한 사실.** [공식 release](https://github.com/roboflow/supervision/releases/tag/0.32.2)는 11월 25일 17:48:22 KST 발행됐다. [태그 ref](https://api.github.com/repos/roboflow/supervision/git/ref/tags/0.32.2)는 commit `33d3659a7cfea550ded8aad2a1d3ac1ad5eebbc5`를 직접 가리킨다. 전날 다룬 0.32.1의 confusion-matrix·split 변경과 다른 새 package event다.

[공식 비교 diff](https://github.com/roboflow/supervision/compare/0.32.1...0.32.2)에서 다음 변경을 확인했다.

- **YOLO class mapping:** `names` dict의 선언 ID를 내부 `classes` 위치로 매핑한다. release 예시의 `{1: cat, 2: dog}`에서 label 1이 dog로 잘못 해석되던 경로를 수정한다. 선언하지 않은 ID, 중복 class key, 중복 `names`는 오류로 처리한다. annotation 또는 YAML만 따로 export할 때는 원래 ID 대응을 보존하며, 클래스·원본 mapping이 바뀐 모순 입력은 거부한다.
- **ViTPose adapter:** `labels`를 관절 슬롯 인덱스로 사용하고 누락 관절을 좌표·confidence 0으로 채운다. `num_keypoints`를 주면 끝쪽 관절이 모두 threshold로 제거돼도 전체 skeleton 크기를 유지한다. 생략하면 가장 큰 retained label+1로 크기를 정하므로 **trailing missing joint까지 자동 복원되는 것은 아니다**.
- **Qwen parser:** 처음 나온 `[`를 detection JSON의 시작으로 간주하던 경로를 바꾼다. `bbox_2d` object를 포함한 배열을 찾고, prose·다른 배열·선행 null·truncated output의 recovery 경로를 다룬다.
- **Gemini parser:** 네 개의 유한 좌표로 읽을 수 없는 box를 제외하고 유효 항목을 유지한다. class filter로 제외된 항목에 confidence가 없다는 이유로 남은 모든 confidence를 버리던 경로도 수정한다.

고정 코드: [ViTPose adapter](https://github.com/roboflow/supervision/blob/33d3659a7cfea550ded8aad2a1d3ac1ad5eebbc5/src/supervision/key_points/core.py), [YOLO loader](https://github.com/roboflow/supervision/blob/33d3659a7cfea550ded8aad2a1d3ac1ad5eebbc5/src/supervision/dataset/formats/yolo.py), [VLM parser](https://github.com/roboflow/supervision/blob/33d3659a7cfea550ded8aad2a1d3ac1ad5eebbc5/src/supervision/detection/vlm.py).

**저자 주장과 간극.** release는 이들을 조용히 잘못 나오던 결과의 수정으로 설명한다. 새 vision encoder나 언어 모델 능력 향상을 주장하는 근거는 아니다. 같은 raw VLM answer를 더 잘 읽으면 검출 수와 downstream grounding score가 변할 수 있다. 반대로 malformed item을 건너뛰면 성공한 항목만 남으므로, parser 성공률과 유효 box 수를 함께 보고해야 한다. “응답 전체가 crash하지 않는다”는 사실이 모든 box가 올바르다는 뜻은 아니다.

관절의 zero-filled slot도 실제 `(0,0)` 관측과 구별해야 한다. downstream evaluator가 confidence/visibility를 무시하면 skeleton shape 수정 후에도 결과가 왜곡될 수 있다는 것은 **평가자의 가설**이다. 새 zero-fill 정책만으로 pose 논문 점수의 재현을 보장할 수 없다.

같은 release에는 empty mask의 center-of-mass anchor를 bbox 중심으로 보내는 수정과 CompactMask mAP의 full-image densification 회피도 포함된다. 공개 테스트는 dense/compact score 및 area boundary parity를 검사한다. 실제 대형 데이터에서의 peak RSS·VRAM 개선량은 이번 조사에서 측정하지 않았다.

**설치·자원·무결성·활동.** code license는 MIT이며 [고정 pyproject](https://github.com/roboflow/supervision/blob/33d3659a7cfea550ded8aad2a1d3ac1ad5eebbc5/pyproject.toml)는 Python ≥3.10, av ≥14.2, NumPy, SciPy, Pillow, PyYAML 등을 선언한다. COCO extra는 pycocotools ≥2.0.11이다. `supervision==0.32.2`를 비교용 0.32.1과 분리해 고정한다. 새 weights/data 공개는 이 package 이벤트에서 확인하지 않았다. synthetic adapter/parser fixture는 CPU로 가능하며 GPU VRAM은 필요 없다. 실제 ViTPose·VLM 추론 자원은 checkpoint에 따라 별도다.

공식 GitHub wheel asset의 API digest는 `sha256:d9ef6588cb18d1eba3e4e3e47f3f5a38830e348108dc415c0309b6af78ba681e`다. 다운로드 후 검증하지 않았다. release가 연결한 [PR #3066](https://github.com/roboflow/supervision/pull/3066)과 비교 diff에서 hardening·regression test 추가를 확인했다. 공개 수정 활동의 존재를 모든 사용자 입력에 대한 보장으로 확대하지 않는다.

**추론 — 진단 → 가설 → 최소 실험, 10~30분 계획.**

1. **클래스 의미 audit:** sparse YAML과 label row를 작게 만들고 load→class name→export→reload가 같은 의미를 보존하는지 확인한다. 정상 연속 ID를 대조군으로 둔다.
2. **관절 슬롯 audit:** 중간 관절 누락, 마지막 관절 누락, 첫 pose가 빈 경우를 분리한다. `num_keypoints` 유무와 confidence mask 적용 유무를 교차해 좌표·shape·관절 edge를 확인한다.
3. **raw-answer replay:** 같은 Qwen 응답에 좌표 설명 bracket, 무관한 JSON 배열, 선행 null을 각각 추가한다. model 호출 없이 파싱된 box·label·좌표와 failure count를 비교한다. Gemini는 정상 box 하나와 malformed box 하나를 섞어 retained item과 confidence를 검사한다.

**GO:** 저장된 출력의 의미·슬롯·파서 감사부터 진행한다.  
**KILL:** raw prediction을 고정하지 않은 채 adapter 수정 후 점수 상승을 모델 representation 향상으로 해석하지 않는다.

## 보류 신호 — MAGI-2와 Preview를 구분한다

[11월 24일 공식 MAGI-2 발표](https://sand.ai/blog/magi-2/)는 새 flagship을 소개하면서 open-source release와 상세 technical report는 뒤이어 공개한다고 설명한다. 기존 August Preview는 다른 모델이다. 이번 조사에서 새 flagship의 immutable checkpoint revision·checksum·license를 확정하지 못했으므로 새 공개 weights로 채택하지 않았다.

[P-H3-Image 기존 주소](https://huggingface.co/PrunaAI/P-H3-Image)가 연결하는 현재 P-Image-OSS card도 최근 weight upload의 증거로는 충분하지 않다. 새 이름, card 수정, integration 날짜, 실제 shard 업로드 날짜를 분리해 확인한 뒤 다시 검토한다.

## 오늘의 GO/KILL

1. **최우선 GO:** Ultralytics 8.4.218/219의 동일 prediction scorer 비교. 점수 변화가 모델 변화 없이 설명되는지 먼저 확인한다.
2. **다음 GO:** Supervision의 sparse class·missing joint·raw-answer replay. 학습·대형 GPU 없이 의미 배선을 진단한다.
3. **조건부 GO:** fixture가 통과하면 고정 checkpoint·split·evaluator로 실제 데이터 재평가를 확장한다.
4. **KILL:** scorer parity를 전체 COCO pipeline parity로, parser recovery를 VLM 능력 향상으로, 제품 발표를 weights 공개로 바꾸어 보고하지 않는다.
5. **미실행:** 위 smoke test는 모두 계획이다. 이번 실행에서는 설치·추론·재학습을 하지 않았다.
