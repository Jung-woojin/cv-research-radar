## 1. Rubric-CEPR — image editing 평가가 “그럴듯함”에서 “계약 충족”으로 이동

- 원문: [arXiv:2610.12469](https://arxiv.org/abs/2610.12469)
- 프로젝트/코드: [Rubric-CEPR project](https://riteshthawkar.github.io/Rubric-CEPR/)
- 공개일: 2026-10-08 UTC

### 확인된 사실

Rubric-CEPR은 Qwen-Image-Edit-2509가 만든 후보를 다시 학습 표적으로 쓰되, 하나의 scalar reward 대신 세 가지 계약을 분리한다.

1. 요청한 새 상태가 실제로 나타났는가
2. 제거해야 할 이전 상태가 사라졌는가
3. 바꾸지 말아야 할 내용이 보존됐는가

후보는 네 개(`K=4`)를 생성하고, 적용 가능한 gate를 모두 통과한 후보 중 최고점 하나만 distillation target이 된다. ImgEdit 평가는 단발 생성으로 수행됐다. 같은 base와 같은 protocol에서 전체 점수는 4.36에서 4.60으로, extraction은 3.41에서 4.26으로 상승했다. 세 training seed 결과는 4.58, 4.60, 4.62로 평균 4.60±0.02 SD였다. 같은 checkpoint를 추가 적응 없이 평가했을 때 GEdit-Bench overall은 7.39→8.31, Complex-Edit overall은 8.77→8.97이었다.

프로젝트 페이지의 210-pair probe에서는 scalar reward가 no-op·손상·잘못된 편집에도 0.39–0.60을 줄 수 있었고, 저자들의 gate는 유효 편집의 51%를 받아들이면서 invalid 후보는 받지 않았다고 보고한다.

### 저자 주장

저자들은 내부 VLM feature와 VAE latent만으로 “자기 생성물을 스스로 검증하는 편집기”가 외부 reward model 없이 개선될 수 있다고 주장한다. 또 가장 약한 edit family에서 개선 폭이 가장 컸다는 결과를 self-verifiability와 available headroom의 결합으로 설명한다.

### 비교 가능성 감사

- **직접 비교 가능:** Qwen-Image-Edit-2509 base 대 Rubric-CEPR은 같은 backbone, 같은 benchmark, 단발 생성 조건이다.
- **직접 비교 주의:** 다른 편집 논문의 row는 judge와 protocol이 다르다. 프로젝트 페이지도 타 논문의 절대 점수는 직접 비교 대상이 아니라고 명시한다.
- **남은 불확실성:** gate가 유효 편집의 49%를 거절한 셈이므로 precision 중심 검증이 coverage를 희생한다. 해무처럼 “변화가 작지만 중요한” 현상에서는 보수적 gate가 실제 양성을 누락할 수 있다.

### 진단 → 가설 → 최소 실험

- **진단:** 해무 복원·합성 모델의 PSNR/LPIPS가 높아도 선박 윤곽, 배경 수평선, 안개 농도 조건 중 하나를 위반할 수 있다.
- **가설:** `fog change / vessel preservation / background preservation`을 비보상식 gate로 분리하면 종합 점수가 숨긴 실패를 더 잘 찾는다.
- **최소 실험:** 기존 해무 이미지 50쌍에서 (a) 안개 농도 변화, (b) 선박 box/contour 유지, (c) 배경 구조 유지의 세 binary gate와 기존 LPIPS를 함께 기록한다. scalar top-10과 gated top-10의 실제 실패율을 사람이 blind review한다.
- **성공 기준:** gated top-10의 명령 불이행 또는 선박 훼손 비율이 scalar top-10보다 30% 이상 낮고, 유효 후보 acceptance가 40% 이상이면 후속 실험 가치가 있다.

## 2. OneSearch-VL — 멀티모달 deep research를 정답이 아니라 근거 연산으로 평가

- 원문: [arXiv:2610.12419](https://arxiv.org/abs/2610.12419)
- 공식 저장소: [appletea233/OneSearch-VL](https://github.com/appletea233/OneSearch-VL)
- 공개일: 2026-10-08 UTC

### 확인된 사실

OneSearch-VL은 visual anchor, 외부 사실, source provenance, 답을 만드는 연산을 **Visually Grounded Evidence Graph(VGEG)**로 묶는다. 새 benchmark는 다음 두 갈래다.

- OneSearch-MI-Bench: 301문항
- OneSearch-Video-Bench: 307문항

총 608문항 중 single-anchor lookup은 53문항이고, 나머지 555문항(91.3%)은 multi-hop retrieval, knowledge-conditioned count, multi-anchor join, arithmetic, comparison이다. multi-image 문항은 2–8장의 이미지를 사용하며 평균 3.05장이다. 난이도는 연산 종류, reasoning hop 수, 사용 사실 수로 계산해 각 benchmark를 easy/medium/hard로 거의 균등 분할한다.

평가는 최종 답을 GPT-4o judge가 reference와 비교해 binary correctness로 판정한다. 동시에 RL reward는 answer correctness, query quality, evidence traceability, visual grounding을 분리한다. OneSearch-VL-8B은 7개 단일 이미지 benchmark 평균 58.3으로 OpenSearch-VL-8B의 56.6보다 1.7 point 높았다. 같은 tool-access 조건의 Qwen3-VL-8B과 비교해 새 multi-image benchmark에서 +20.2 point, video benchmark에서 +17.6 point, VideoDR에서 +27.0 point를 보고했다.

공식 저장소에는 301/307문항 dataset 링크, 약 110K SFT trajectory, 약 10K RL task, inference/evaluation entry point와 Apache-2.0 license가 공개돼 있다.

### 저자 주장

저자들은 단일 이미지·다중 이미지·비디오를 별도 agent로 쪼개는 대신, visual grounding→web retrieval→fact composition이라는 공통 dependency graph로 통합할 수 있다고 주장한다. EVGR가 정답만 맞히는 shortcut보다 실제 근거 추적을 강화한다는 설명이다.

### 비교 가능성 감사

- **직접 비교 가능:** OneSearch-VL-8B과 Qwen3-VL-8B agent는 같은 tool environment와 evaluation protocol을 썼다고 명시돼 있다.
- **해석 제한:** 최종 correctness judge가 하나의 외부 모델에 의존한다. benchmark가 process annotation을 갖고 있어도 공개 headline 수치는 여전히 binary answer judge의 calibration에 영향을 받는다.
- **데이터 위험:** VGEG 기반 생성·검증 pipeline과 평가 rubric이 같은 구조를 공유한다. graph schema에 잘 맞는 agent가 실제 open-world research보다 유리할 수 있으므로 외부 도메인 교차 검증이 필요하다.

### 진단 → 가설 → 최소 실험

- **진단:** 해양 영상 질의응답에서 모델이 “정답”을 맞혀도 어떤 frame·선박·기상 관측·웹 문서를 근거로 썼는지 추적하기 어렵다.
- **가설:** `frame anchor → vessel/weather entity → official observation → answer operation` graph를 붙이면 hallucination과 잘못된 frame grounding을 분리할 수 있다.
- **최소 실험:** 해무 영상 20개로 30문항을 만든다. 각 문항에 key frame, object region, 필요한 KHOA/기상 사실, 연산 종류를 기록한다. 기존 answer accuracy 외에 anchor recall, evidence precision, unsupported-claim rate를 측정한다.
- **성공 기준:** answer accuracy 손실이 3 point 이하인 상태에서 unsupported-claim rate가 25% 이상 감소하면 evidence graph를 연구 pipeline에 유지한다.

## 3. ViSkill — agent benchmark의 단위가 텍스트 전략에서 시각 궤적으로 이동

- 원문: [arXiv:2610.12403](https://arxiv.org/abs/2610.12403)
- 공식 저장소: [ZJU-REAL/ViSkill](https://github.com/ZJU-REAL/ViSkill)
- 공개일: 2026-10-08 UTC

### 확인된 사실

ViSkill은 성공 trajectory를 텍스트로 요약하는 대신 annotation이 포함된 visual skill card로 저장한다. 검색한 skill은 inference guide와 실패 trajectory의 부분 reward에 쓰이고, 새 성공 trajectory는 다시 library에 추가된다.

Qwen2.5-VL-3B 기반 ViSkill의 성공률은 Sokoban 0.82, FrozenLake 0.84, PrimitiveSkill 평균 1.00, overall 0.89였다. cold-start를 넣으면 각각 0.88, 0.85, 1.00, overall 0.91이었다. 비교 대상 Atlas-VA는 overall 0.87이었다.

표현 ablation에서는 visual skill 대비 Text-Skill이 Sokoban/FrozenLake에서 0.63/0.59, OCR-Skill이 0.68/0.62였다. ViSkill은 0.82/0.84였다. core component ablation에서 optimization을 제거하면 0.29/0.33으로 크게 하락했고, skill-guided reward를 빼면 0.77/0.80, strategy를 빼면 0.72/0.81이었다.

공식 저장소에는 MIT license, CUDA/Linux 설치법, 세 환경의 train script, YAML seed 설정, Sokoban·FrozenLake model이 공개돼 있다. cold-start는 외부 API 설정이 필요하고 기본값으로는 꺼져 있다.

### 저자 주장

저자들은 시각 상태와 행동 대응을 그대로 보존해야 공간 구조가 손실되지 않으며, skill library와 policy를 함께 갱신할 때 sample efficiency와 최종 성공률이 좋아진다고 주장한다.

### 비교 가능성 감사

- **직접 비교 가능:** 논문 표 안의 ViSkill/Atlas-VA/VAGEN은 동일 세 환경 성공률로 제시된다.
- **포화 위험:** PrimitiveSkill의 여러 세부 task가 1.00에 도달해 overall 평균의 분별력이 낮다. 실제 movement는 Sokoban과 FrozenLake에서 읽어야 한다.
- **cold-start 비용:** 0.89→0.91의 +0.02에는 외부 모델로 만든 seed skill이 들어간다. 순수 self-evolution 효과와 분리해야 한다.
- **일반화 한계:** 세 환경은 게임/조작 중심이다. 자연 영상의 long-tail geometry로 바로 확장된다는 증거는 아직 없다.

### 진단 → 가설 → 최소 실험

- **진단:** 해무 분류·탐지 실패 사례를 텍스트 메모로만 축적하면 안개 경계, 광원 halo, 선박 silhouette 같은 시각 단서가 손실된다.
- **가설:** 실패→수정 성공 사례를 crop·mask·짧은 전략 문구로 묶은 visual skill card가 유사 기상 조건의 재판정을 돕는다.
- **최소 실험:** 오분류 30건에서 visual card와 text-only card를 각각 만든 뒤, 별도 60건에 retrieval-augmented 판단을 적용한다. top-3 retrieval relevance, 수정 정확도, inference latency를 비교한다.
- **성공 기준:** visual card가 text-only 대비 수정 정확도 +5 point 이상, retrieval relevance +10 point 이상이고 latency 증가가 20% 이하면 다음 단계로 진행한다.

## 4. ContourVLA — segmentation benchmark가 단발 mask에서 폐루프 경계 수정으로 이동

- 원문: [arXiv:2610.12107](https://arxiv.org/abs/2610.12107)
- 공개일: 2026-10-08 UTC
- 코드 상태: arXiv v1에서 공식 저장소 링크를 확인하지 못함

### 확인된 사실

ContourVLA는 referring segmentation을 한 번의 mask decoding이 아니라, contour를 명시적 state로 두고 재관측하면서 geometric action을 반복하는 문제로 바꾼다. 평가는 gRefCOCO의 gIoU/cIoU와 RefCOCO·RefCOCO+·RefCOCOg의 mIoU/cIoU를 함께 사용한다. 네 dataset의 train split을 공동 학습한 하나의 checkpoint를 모든 split에 쓴다.

gRefCOCO에서 val/testA/testB gIoU는 83.5/80.3/74.4였다. 논문이 자체 재평가한 strongest baseline 대비 각각 +8.7/+2.8/+2.7 point다. gRefCOCO val에서 SFT-only는 gIoU 77.6, no-target accuracy 74.6, instance F1@0.5 73.8이었고, full DECT-GRPO는 83.5/83.2/82.4였다. shared-advantage GRPO 대비 full instance credit는 gIoU +3.0, F1 +5.1 point였다.

8-step action budget에서 관측을 갱신한 full loop는 frozen observation보다 Boundary IoU가 59.91→65.98로 6.07 point 높았고, contour latency는 226.96→233.63 ms로 6.67 ms, 2.94% 늘었다.

### 저자 주장

저자들은 variable-number referent, false positive, missed target을 하나의 rollout reward로 뭉개지 않고 instance별 credit로 보내야 grounding token과 contour action을 함께 개선할 수 있다고 주장한다.

### 비교 가능성 감사

- **강점:** gIoU/cIoU뿐 아니라 no-target accuracy와 instance F1을 함께 제시해 empty target과 다중 instance 실패를 분리한다.
- **주의:** 기존 방법 수치는 저자들의 자체 evaluation run이며 각 방법의 원래 보고값과 동일하다고 가정하면 안 된다.
- **재현성 제한:** 현재 arXiv v1에 공식 코드 링크가 없어 checkpoint·preprocessing·latency 환경을 독립 검증할 수 없다.
- **연산 해석:** 2.94%는 contour 단계의 누적 latency 비교이며 end-to-end system overhead로 확대 해석할 수 없다.

### 진단 → 가설 → 최소 실험

- **진단:** 해무 경계·선박 silhouette는 단발 mask가 경계를 뭉개거나, 안개가 없는 이미지에서도 양성 mask를 내는 실패가 잦다.
- **가설:** coarse mask를 state로 되먹임해 2–4회 경계 보정을 하면 작은 latency 증가로 Boundary IoU와 no-target accuracy를 동시에 높일 수 있다.
- **최소 실험:** 기존 segmentation model의 coarse mask 100건을 고정하고, 경계 band에서 point/patch를 재샘플링하는 2-step refinement head만 붙인다. mIoU, Boundary IoU, empty-mask accuracy, 추가 latency를 함께 측정한다.
- **성공 기준:** Boundary IoU +3 point, empty-mask accuracy 유지 또는 개선, end-to-end latency +10% 이하면 폐루프 설계를 유지한다.

## 교차 신호: benchmark 설계가 바꾸는 연구 의사결정

1. **단일 점수는 유지하되 승인 조건으로 쓰지 않는다.** 편집·검색·분할 모두 “겉보기 성공”을 만드는 shortcut이 있다. 종합 점수는 ranking용으로 남기고, 필수 조건은 non-compensatory gate로 분리해야 한다.
2. **과정 평가는 디버깅 가능한 단위여야 한다.** OneSearch의 anchor/trace, ViSkill의 retrieved trajectory, ContourVLA의 instance credit는 성능 향상보다 먼저 실패 위치를 제공한다.
3. **포화 task를 평균에서 분리한다.** ViSkill의 PrimitiveSkill 1.00처럼 포화된 축은 overall 평균을 부풀릴 수 있다. Woojin의 내부 benchmark도 easy/medium/hard와 boundary/no-target slice를 별도로 공개해야 한다.
4. **공개 코드가 있는 신호부터 최소 실험한다.** OneSearch-VL과 ViSkill은 실행 entry point가 확인됐다. ContourVLA는 아이디어만 작은 refinement head로 재구성하고, 논문의 전체 성능 재현을 주장하지 않는다.

## 오늘의 benchmark signal 3개

1. **비보상식 rubric:** 한 축의 높은 점수가 다른 필수 조건 실패를 가리지 못하게 한다.
2. **evidence-operation benchmark:** 답 정확도와 함께 visual anchor, source trace, join/count/arithmetic 연산을 측정한다.
3. **폐루프·instance 평가:** 단발 출력 대신 상태 갱신과 개별 객체 credit를 평가하며, 품질과 latency를 같은 표에 둔다.

## Woojin 연구와의 직접 연결

- **해무 생성·복원:** LPIPS/PSNR 옆에 fog-change, vessel-preservation, background-preservation gate를 추가한다.
- **해양 영상 VLM:** 질문별 key frame, 선박 region, 공식 기상·해양 source, 최종 연산을 작은 evidence graph로 저장한다.
- **실패 사례 재사용:** 오분류 사례를 텍스트 로그만 남기지 않고 crop·mask·결정 근거를 묶은 visual skill card로 축적한다.
- **해무/선박 segmentation:** mIoU 외에 Boundary IoU, no-target accuracy, instance F1, 추가 latency를 필수 열로 둔다.
- **이번 주 최소 실행 순서:** ① 50쌍 editing gate audit → ② 30문항 evidence graph pilot → ③ 100건 2-step contour refinement. 세 실험 모두 기존 모델을 동결해 평가 설계의 효과부터 확인한다.
