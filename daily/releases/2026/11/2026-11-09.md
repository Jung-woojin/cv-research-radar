## 1. Ultralytics v8.4.208 — package release, not a new model artifact

**사실.** `v8.4.208`은 2026-11-08 14:54 UTC에 release됐다. prediction/tracking의 미지정 NMS IoU 기본값은 0.7에서 0.5로 바뀌고 validation 기본값은 0.7로 유지된다. YOLOE visual prompt의 기본 confidence는 0.05가 되며, multi-GPU gradient accumulation과 TensorRT 11 FP16 NMS-free export 개선도 포함된다. release note는 새 model architecture를 도입하지 않는다고 명시한다.

**artifact / license / install surface.** GitHub tag `v8.4.208`과 release asset 3개가 존재한다. repository license는 AGPL-3.0이며, 실제 update surface는 Python package·export runtime이다. release note만으로 특정 pretrained weight, evaluator dataset, GPU/VRAM 요구량, TensorRT 11의 “up to 3% faster” 조건을 확정할 수 없다.

**논문·claim 대비.** 이 tag를 새 YOLO weight나 새로운 benchmark 결과로 취급하면 안 된다. predict/tracking과 validation NMS default가 달라졌으므로, 이전 validation 수치와 새 서비스 출력을 같은 조건의 비교로 읽을 수 없다.

**진단 → 가설 → 최소 smoke test.** 설정 default drift가 artifact 차이보다 결과 차이를 만들 수 있다. clean virtual environment에서 같은 checkpoint와 image set으로 v8.4.207/8.4.208을 비교하고, `iou`를 명시하지 않은 prediction/tracking 및 validation 결과를 별도 저장한다. output count, duplicate boxes, recall, tracking ID switch, package/version manifest를 기록한다. TensorRT speed 비교는 hardware·engine·shape·batch·precision·warm-up이 같은 경우에만 수행한다.

**GO / KILL.** 명시적 `iou` 고정 후 output parity가 필요한 범위에서 확인되면 GO다. validation-only 통과 또는 release note의 speed claim만으로 serving baseline을 바꾸는 것은 KILL이다.

## 2. V-Interaction-400K — preview interactive dataset

**사실.** V-Thinker는 2026-11-07에 preview V-Interaction-400K 252K samples를 공개했다고 알렸다. Hugging Face viewer는 image/text parquet, 25개 `train_part` split과 선택된 shard의 약 10.1K rows를 보인다. viewer schema에는 `question`, 원본 image code, edited image, tool code, code를 포함한 CoT, answer가 있다.

**artifact / license / install surface.** 공개 데이터 artifact는 Hugging Face parquet이며, project repository는 MIT license다. 그러나 검토한 dataset page에는 dataset 자체의 별도 license, checksum, immutable revision이 명시되지 않았다. code MIT가 data 재배포·상업 사용까지 자동 허용한다는 뜻은 아니다. data-only schema inspection은 CPU에서 가능하지만 model-based smoke test의 GPU/VRAM은 명시되지 않았다.

**논문·claim 대비.** 저자 설명은 image-to-code로 확장 가능한 대규모 visual interaction dataset이라는 것이다. 이는 quality 또는 downstream gain의 독립 검증이 아니다. “400K” 명칭과 preview 252K 공개분을 같은 수량으로 기록해서는 안 된다.

**진단 → 가설 → 최소 smoke test.** main risk는 sample count·shard completeness·image/code pairing이 preview announcement와 실제 다운로드에서 어긋나는 것이다. 10–30분 내 `datasets` 또는 parquet metadata로 25 shard의 row count, null image/code, duplicated ID, image decode failure를 집계하고 manifest와 dataset revision을 고정한다. 학습은 하지 않는다.

**GO / KILL.** total rows·ID uniqueness·필수 필드 decode가 명확하고 사용 조건이 확보되면 GO다. dataset license 또는 revision이 불명확하면 연구용 local audit까지만 하고 training corpus 편입은 KILL/보류다.

## 3. V-Perception-40K — preview point-level alignment dataset

**사실.** V-Thinker는 11월 7일 preview V-Perception-40K 37K samples를 point-level perceptual alignment dataset으로 공지했다. Hugging Face viewer의 단일 `v_perception_40k` split은 36.7K rows를 보이며 `image`, `question`, `answer`, `python_code`, `element_arrtibute` 필드를 제시한다.

**artifact / license / install surface.** image/text parquet artifact가 있으며 project code는 MIT다. dataset page에서 별도 data license·checksum·hardware requirement는 확인되지 않았다. 37K announcement와 36.7K viewer row count는 rounding·filtering·preview export 등 여러 설명이 가능하므로 누락이라고 단정할 수 없다.

**논문·claim 대비.** repository는 point-level supervision을 perception-alignment stage로 설명하지만, viewer row 수만으로 label accuracy, coordinate metric, train/validation split, 또는 model gain을 검증할 수 없다.

**진단 → 가설 → 최소 smoke test.** data-to-rendering consistency가 핵심 failure surface다. 1,000행 stratified sample에서 `python_code` render 가능성, `element_arrtibute` 좌표의 image bounds, answer format parse rate를 검사한다. declaration count와 parquet count를 함께 기록한다.

**GO / KILL.** bounds violation·render failure가 낮고 split/revision·license가 확정되면 GO다. code field가 실행 환경을 요구하거나 artifact provenance가 확인되지 않으면 임의 실행 없이 KILL/보류한다.

## 4. VTBench — benchmark artifact와 evaluator 경계

**사실.** V-Thinker는 VTBench를 perception, instruction-guided interaction, interactive reasoning의 세 유형 benchmark로 11월 7일 공개했다. repository는 1,500 QA pairs라고 설명하며, Hugging Face viewer는 500-row `train` split과 원본 image, 두 annotation image, reasoning/perception/instruction question·answer fields를 제공한다. repository는 custom inference script와 task별 evaluation folders, `pip install -e .`, vLLM update를 안내한다.

**artifact / license / install surface.** benchmark data는 image/text parquet, project code는 MIT이다. 검토한 dataset viewer에는 independent benchmark-data license, checksum, official evaluator package version, fixed model checkpoint revision이 없었다. 500 rows에 세 task의 question/answer fields가 함께 있어 1,500 QA 설명과 공존할 수 있지만, 실제 scoring unit은 schema audit으로 확인해야 한다.

**저자 주장 대비.** repository 표의 V-Thinker-7B task scores는 저자 제공 결과다. 검토한 release material에서는 그 checkpoint의 정확한 immutable weight artifact, checksum, required GPU/VRAM을 확인하지 못했다. 따라서 해당 표를 새로 다운로드·재현 가능한 checkpoint result로 단정하지 않는다.

**진단 → 가설 → 최소 smoke test.** benchmark record, task count, image-file path, evaluator import가 서로 맞물리지 않을 수 있다. model 없이 500 records에서 task별 non-empty field, local image path resolution, annotation image decode, question-answer pairing을 audit하고, code revision과 dataset revision을 manifest에 기록한다. 그 다음에만 small subset evaluator dry-run을 고려한다.

**GO / KILL.** 세 task의 record mapping과 official evaluator input contract가 고정되면 GO다. checkpoint revision 또는 judging contract가 불명확하면 점수 비교·leaderboard 사용은 KILL/보류다.
