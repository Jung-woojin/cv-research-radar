## 1. V-Perception-40K — point-grounding을 좌표 정답 이상으로 분해할 수 있는 artifact

**사실.** V-Thinker는 11월 7일 V-Perception-40K preview를 point-level perceptual alignment dataset으로 공개했다고 알렸다. Hugging Face viewer의 v_perception_40k split은 36.7K rows를 보이며 image, question, answer, python_code, element_arrtibute fields를 노출한다. viewer sample에는 좌표 dictionary 답과 point label/semantic/bbox metadata가 함께 보인다. repository의 progressive-training 설명은 저자 주장이다.

**진단.** coordinate exact match는 실제 element 탐색 오류, semantic assignment 오류, serialization 오류를 한 수치에 섞는다. renderer code와 element metadata가 있으면 이를 분리할 수 있다.

**가설.** element-aware scoring은 같은 coordinate EM의 모델 사이에서도 point-localization, semantic assignment, output serialization 병목을 구분한다. 단 code/metadata와 rendered image 대응을 먼저 검증해야 한다.

**최소 실험.** 1,000 rows에서 image decode, coordinate bounds, answer parser, element_arrtibute mapping을 audit한다. baseline output을 normalized coordinate distance, element hit, semantic-label agreement, parse success로 분해하고, font/palette/padding render subset에서 original 대비 coordinate flip을 기록한다. revision, row count, resolution policy, parser commit을 manifest에 남긴다.

**GO / KILL.** metadata–image mapping이 확인되고 error class가 분리되면 element-aware column을 추가한다. code/attribute가 image와 일관되지 않거나 answer contract가 parse되지 않으면 leaderboard 사용을 보류한다.

## 2. V-Interaction-400K — 정답 점수와 action–outcome score를 분리해야 한다

**사실.** V-Thinker는 11월 7일 V-Interaction-400K preview 252K samples 공개를 알렸다. Hugging Face viewer는 25개 train_part split과 선택 shard의 약 10.1K rows를 보인다. schema에는 question, original image code, edited image, tool code, code를 포함한 CoT, answer가 있다. 저자의 image-to-code 확장 가능성 설명은 별도 검증 전 주장이다.

**진단.** final answer만 채점하면 tool code가 실제 edit을 만들었는지, image 변화가 instruction과 맞는지, 또는 text reasoning만 그럴듯한지를 구분하지 못한다. original→tool→edited-image의 세 edge는 독립 평가 단위다.

**가설.** static code analysis와 safe renderer subset outcome check를 결합하면 answer EM만 사용할 때보다 action hallucination과 data pairing error를 더 잘 분리할 수 있다. 실행 권한이 필요한 code를 무조건 실행할 필요는 없다.

**최소 실험.** 500 rows에서 original/edited image decode, code AST parse, tool operation class, image-difference region을 annotate한다. answer accuracy, AST validity, declared-operation/difference agreement, safe-render subset outcome similarity를 별도 보고한다. file/network/subprocess access code는 static-only bucket으로 격리한다. preview 수·shard count·downloadable rows를 revision manifest에 함께 보존한다.

**GO / KILL.** human audit에서 answer-only 오류와 action–outcome 오류가 구별되고 contract가 안정적이면 tri-level score를 추가한다. edited image/code pairing이 불명확하거나 execution safety를 보장할 수 없으면 ranking에 outcome 점수를 합치지 않는다.

## 3. Ultralytics v8.4.208 — post-processing default가 evaluation과 serving을 갈라놓는다

**사실.** v8.4.208은 2026-11-08 14:54 UTC에 발행됐다. release note는 iou를 명시하지 않은 prediction/tracking default를 0.7에서 0.5로 바꾸고 validation은 0.7로 유지한다고 명시한다. same note는 crowded scene에서 가까운 object가 suppress될 수 있으며 사용자가 iou를 조정할 수 있다고 설명한다. 새 model architecture를 도입하지 않는 package release다.

**진단.** validation score와 production prediction/tracking을 동일 YOLO 결과로 비교하면 decision layer가 다르다. dense/small-object cell에서는 duplicate box 감소와 true-object suppression이 동시에 가능하다. 방향과 크기는 release note만으로 확정할 수 없다.

**가설.** 동일 checkpoint의 NMS 0.5/0.7 differential run은 global mAP보다 dense/small/isolated strata의 duplicate rate, recall, ID switch, count error에서 큰 gap을 보일 수 있다. validation과 serving config를 함께 기록하면 이 gap을 model improvement와 분리할 수 있다.

**최소 실험.** checkpoint, image size, confidence, device, precision을 고정하고 prediction/validation/tracking을 IoU 0.5와 0.7로 실행한다. dense/small/isolated strata별 AP/recall, duplicate rate, false suppression, ID switch, count error를 기록한다. default에 의존하지 않고 explicit iou와 package version을 result card에 기록한다.

**GO / KILL.** 특정 strata에서 gap이 재현되고 explicit selector가 global default보다 Pareto 개선을 보이면 config-paired evaluation을 채택한다. 모든 strata 차이가 작거나 data가 crowding을 대표하지 않으면 일반 protocol 주장으로 확장하지 않는다.

## 오늘의 benchmark signal 3개

1. **Metric granularity:** V-Perception-40K는 coordinate/element/format error를 분리할 수 있는 artifact다.
2. **Trajectory correctness:** V-Interaction-400K는 answer만이 아닌 action–outcome contract를 평가할 수 있는 artifact다.
3. **Deployment parity:** Ultralytics NMS default 분리는 validation table과 serving table을 별도 protocol로 기록해야 함을 보여 준다.

## 내 연구에 바로 연결되는 포인트

- small-object·crowded detection은 NMS IoU를 hidden default가 아닌 연구 변수로 고정한다.
- VLM grounding에서는 final answer 외에 element hit와 counterfactual flip을 함께 기록한다.
- image-editing/agent benchmark에서는 unsafe code를 실행하지 않고도 static/action/outcome audit을 먼저 수행한다.
- backbone, pretraining, split, resolution, TTA, evaluator 또는 serving config가 다르면 결과는 not strictly apples-to-apples다.
