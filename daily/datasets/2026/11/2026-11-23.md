## 1. CivicBench — 평가 입력과 원본·생성기 lineage를 고정한다

**확인 사실·시점.** HF revision `0b080803442ef79ca55843ef950b4896b09d1f97`을 확인했다. 11/22 18:19 UTC 업로드 commit들이 있고, 현재 tree에 실제·생성 Parquet와 MP4가 있다. 확인한 tree 페이지에는 생성 Parquet 48개와 실제 Parquet 12개가 나열된다. 이는 shard 파일 수이며 clip 행 수를 직접 집계한 결과가 아니다. [고정 tree](https://huggingface.co/datasets/kurbanintelligencelab/CivicBench/tree/0b080803442ef79ca55843ef950b4896b09d1f97)

**규모·task·split — 저자 보고.** 정치 장면의 생성 영상 탐지용으로 실제 2,632 clip, 생성 10,800 clip이며 생성기는 8종·공유 prompt는 1,350개다. default·real·generated config 모두 test다. 공식 입력은 512×512 PNG 11프레임과 `frames_sha256`이고, MP4 및 별도 `video_sha256`도 제공한다. train split이 있다고 가정하면 안 된다. [고정 card](https://huggingface.co/datasets/kurbanintelligencelab/CivicBench/blob/0b080803442ef79ca55843ef950b4896b09d1f97/README.md)

**License·bias·호환성.** 실제 영상은 clip별 원본 license를 따르고 생성물은 생성기 조건이 추가된다. card는 HunyuanVideo-1.5 생성물의 평가 전용 조건과 한국을 포함한 지역 제한을 기술한다. 이는 배포자의 조건 설명이며 이 실행에서 upstream license 해석을 독립 확정한 것은 아니다. 코드의 Apache-2.0을 데이터 전체에 적용하지 않는다. 실제 정부 영상과 가상 정치인 prompt라는 source·내용 차이도 탐지 shortcut 후보다. 공식 toolkit 입력도 11프레임임을 교차 확인했다. [공식 코드 설명](https://github.com/KurbanIntelligenceLab/CivicBench)

**진단 → 가설 → 최소 실험.** 같은 prompt의 여러 생성기 출력과 같은 원본의 인접 clip은 상관된 표본이다. 파일 경로·generator·prompt·label을 모델 입력으로 넘기면 시각 성능을 오인할 수 있다는 **추론**이다. 먼저 `clip_id`, frame hash, source URL·시작 시각, prompt ID를 묶은 manifest를 만들고 중복·시간 겹침을 검사한다. 이후 공식 프레임만 입력해 generator·scene별 AUC/TPR과 실제 source별 false-positive를 보고한다. threshold calibration 집합은 평가 case와 분리하고 임의 clip-random 분할 대신 source/prompt group을 보존한다.

**GO/KILL.** metadata와 권리 조건 감사는 GO. 전체 test를 학습 데이터로 사용하는 것은 KILL. MP4 재디코딩·프레임 수 변경 결과를 공식 PNG 점수와 바로 비교하면 **not strictly apples-to-apples**다. 독립적인 duplicate·leakage 검사는 미실행이다.

## 2. GeoReSeT — caption 누락과 원본 권리를 함께 감사한다

**확인 사실·시점.** revision `c86c81aa3bee6ad76c1673e5ce4b4d86e42e5b94`은 11/22 21:54:58 UTC의 caption·embedding commit이다. 공식 API에서 고정 revision의 Mapillary caption Parquet 경로·크기·OID를 확인했다. corpus 최초 공개나 모든 사진의 신규 업로드를 뜻하지 않는다. [이력](https://huggingface.co/datasets/NoeFlandre/GeoReSeT-geotagged-photos/commits/main) · [caption artifact](https://huggingface.co/datasets/NoeFlandre/GeoReSeT-geotagged-photos/tree/c86c81aa3bee6ad76c1673e5ce4b4d86e42e5b94/captions/mapillary)

**규모·task·split — 배포자 보고.** card는 저장 사진 9,364,175개, caption 9,344,106개, embedding 4,918,811개를 보고한다. 사진·좌표·license, 모델 caption, SigLIP2 768차원 embedding, landscape score, 다운로드 index가 별도 config이며 join key는 `(platform, photo_id)`다. 표준 held-out test membership은 확인하지 못했다. task는 지리 사진 검색·caption·feature 활용이며 고정된 정답 분류 benchmark로 취급하지 않는다. [고정 card](https://huggingface.co/datasets/NoeFlandre/GeoReSeT-geotagged-photos/blob/c86c81aa3bee6ad76c1673e5ce4b4d86e42e5b94/README.md)

**Annotation·bias.** caption은 Gemma 계열 모델 출력이며 사람이 검수하지 않았다고 명시한다. 좌표·날짜·license도 원본 table에서 복사했고 좌표 오류 가능성을 인정한다. 총 저장 사진과 caption 수의 차이는 기재값 기준 20,069개지만 행별 join으로 재현하지 않았다. card의 “각 사진에 caption”이라는 서술보다 실제 coverage table과 row manifest를 우선 확인해야 한다. landscape subset·platform별 coverage와 panorama 선별 규칙도 선택 편향 후보다.

**License·공개 경계.** 사진마다 license가 다르며 card에는 All Rights Reserved 및 비상업 조건 사진도 나열된다. 공개 다운로드는 일괄 재배포·학습 허가의 증거가 아니다. 원본 작성자 credit과 개별 허가를 확인하고, caption·embedding 자체의 재사용 조건도 별도 확인한다. 인물·위치정보가 포함될 수 있다. [배포자 연결 audit](https://github.com/NoeFlandre/GeoReSeT-Corpus-Fused-audit)

**진단 → 가설 → 최소 실험.** caption·embedding이 모두 있는 행만 inner join하면 platform·장소 분포가 달라질 수 있다는 **추론**이다. 사진 index를 기준으로 left join해 key 중복, caption/embedding 누락을 platform·license·지리 cell별로 계산한다. 같은 `scene_id`, `cluster_id`, 사진 ID와 near-duplicate는 split을 함께 묶는다. 이후 같은 frozen encoder·head·학습량으로 random split과 spatial/group-heldout을 비교한다. 생성 caption은 human GT와 분리해 표본 blind 검수한다.

**GO/KILL.** 권리·coverage manifest는 GO. 저작권 조건이 확인되지 않은 사진의 일괄 학습·재배포와 생성 caption의 정답 취급은 KILL. coverage가 다른 subset의 평균 점수 비교는 **not strictly apples-to-apples**다.

## 3. cross-CholeAct — 새 논문과 기존 데이터 배포를 분리한다

**확인 사실·시점.** 논문은 11/20 공개됐으나 정확한 공개 시각은 미확인이다. [Figshare API](https://api.figshare.com/v2/articles/32575485)는 v2 공개·수정일을 8/21 13:55:08 UTC로 기록하고 `cross_CholeAct_v20260820.tar.gz`를 나열한다. 새 데이터 release가 아니라 새 논문을 계기로 annotation·split 조건을 재점검하는 사례다. [공식 논문](https://www.nature.com/articles/s41597-026-08786-9)

**규모·task·정책 — 저자 보고.** 두 기관 기반 110개 수술, 초 단위 annotation과 3초 clip을 제공한다. 공동 action taxonomy를 사용하지만 희귀 class와 기관별 class 부재가 있다. annotation은 한 외과의사가 먼저 작성했고 이후 일치도 검사를 수행했다. CholeCANE 자료는 CC BY 4.0, Cholec80 쪽은 annotation·split·생성 script만 배포하며 원본 영상 접근은 별도다. 논문의 license를 원본 영상에 적용하지 않는다. [정책 원문](https://www.nature.com/articles/s41597-026-08786-9_reference.pdf)

**진단 → 가설 → 최소 실험.** 인접 clip의 중복 문맥과 기관별 label prior가 domain shift처럼 보일 수 있다는 **추론**이다. 수술 ID·시간 구간·class별 split manifest로 겹침과 기관별 지원 class를 확인하고, 동일 예측을 공통 class와 전체 class에서 따로 채점한다. patient·수술 단위 bootstrap을 사용한다. 영상 해상도·pretraining·evaluator를 고정한 기관 간 비교가 필요하다.

**GO/KILL.** split audit 설계는 GO. clip-random 평가와 원본 영상 미확보 상태의 재현 완료 선언은 KILL. archive 내부와 모델은 실행하지 않았다. 논문이 연결한 GitHub의 `main/README.md`는 직접 조회에서 HTTP 404여서 code 사용 가능을 확정하지 않는다.
