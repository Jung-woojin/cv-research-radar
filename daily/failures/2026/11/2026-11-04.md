## 1. ModelOpt 0.48.0 — KV cache off에서 VLM 이미지 입력이 사라질 수 있음

**[확인된 사실]** NVIDIA ModelOpt 0.48.0 릴리스는 `megatron_generate`에서 KV-cache decoding이 꺼진 경우, 첫 생성 토큰 뒤 `pixel_values`, `image_grid_thw`, `image_sizes`가 drop될 수 있었고 sequence parallelism의 자동 fallback에서도 같은 문제가 발생했다고 기록한다. 릴리스 설명은 이 상태가 generation이 이미지를 조용히 무시하게 만들 수 있었다고 명시한다.  
출처: https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.48.0

**[실패 조건]** Megatron generate 경로, VLM 입력, KV cache 비활성 또는 sequence-parallel fallback이다. 임의의 VLM·일반 image inference 전체가 같은 조건에서 실패한다고 일반화할 수는 없다.

**[의심 메커니즘]** 첫 step과 이후 decode step의 input propagation 경로가 다를 때 multimodal tensor가 text-only decode path에서 탈락할 수 있다.

**[기존 주장과의 충돌]** 이미지 조건 generation의 결과가 있어도, 해당 설정에서는 실제 이미지 evidence를 사용했다는 보장이 없다.

**진단 → 가설 → 최소 실험**
- 진단: answer quality만으로는 text prior로 답한 것과 image conditioning을 사용한 것을 구분하지 못한다.
- 가설: image swap/blank-image counterfactual에서 output이 불변이면 vision input propagation이 끊겼을 가능성이 높다.
- 최소 실험: 동일 prompt에서 원본·blank·swap image를 각각 10개씩 넣고 first token과 후속 token의 logits/output 차이, `pixel_values` 전달 log를 확인한다.
- **GO:** 각 decode step에서 vision tensor가 유지되고 counterfactual에 반응할 때. **KILL:** 첫 토큰 이후 tensor가 사라지거나 swap에 무반응일 때.
- 심각도 **5/5**, 재현 신뢰도 **4/5**, 연구 아이디어 가치 **5/5**. 이번 실행은 독립 재현을 하지 않았다.

## 2. ModelOpt 0.48.0 — FP16 activation ONNX INT8 entropy calibration의 실패/오보

**[확인된 사실]** 같은 릴리스는 FP16 activation이 있는 ONNX 모델에서 INT8 entropy calibration이 실패하거나 invalid quantization parameter를 만들 수 있었음을 수정 사항으로 명시한다.  
출처: https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.48.0

**[실패 조건]** ONNX INT8 entropy calibration과 FP16 activation의 조합이다. 모든 quantization mode나 모든 ONNX Runtime/TensorRT version으로 확대 해석하면 안 된다.

**[의심 메커니즘]** calibration histogram/range 또는 quantization parameter 계산이 FP16 activation의 표현 범위·dtype 동작에 민감할 수 있다.

**[기존 주장과의 충돌]** calibration이 완료됐다는 로그만으로 valid scale·zero-point 또는 배포 엔진의 정확성을 보장하지 않는다.

**진단 → 가설 → 최소 실험**
- 진단: exporter 성공과 quantization parameter 유효성은 별개의 검증 대상이다.
- 가설: representative set의 activation range·scale/zero-point의 finite 여부·FP16/FP32 calibration 결과를 나란히 저장하면 silent invalid parameter를 조기 발견한다.
- 최소 실험: 같은 ONNX graph를 FP16 activation 유지와 FP32 reference 조건에서 calibration하고, invalid/non-finite parameter 수, output cosine similarity, task metric을 비교한다.
- **GO:** 모든 parameter가 finite이고 FP32 reference 대비 task metric 손실을 사전 한계 안에 유지할 때. **KILL:** invalid parameter 또는 graph output anomaly가 하나라도 나올 때.
- 심각도 **5/5**, 재현 신뢰도 **4/5**, 연구 아이디어 가치 **4/5**. 버전·calibration dataset·engine target을 manifest에 고정해야 한다.

## 3. ModelOpt 0.48.0 — MaxViT 계열 Transpose export의 실패와 silent axis 오류

**[확인된 사실]** 릴리스는 consumer 전에 weight가 transpose되는 경우(예: MaxViT attention block)에 `Unsupported op_type for real weight quantization: Transpose`로 ONNX export가 실패할 수 있었음을 수정했다. 같은 수정은 Q/DQ pair가 선언한 축과 consumer default 축이 다를 때 발생할 수 있는 잘못된 `dq_only` output도 바로잡는다고 설명한다.  
출처: https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.48.0

**[실패 조건]** quantized ONNX export, real weight quantization, Transpose를 거쳐 consumer에 도달하는 weight가 조건이다. 모든 ViT가 해당하지는 않는다.

**[의심 메커니즘]** quantization axis의 의미가 graph transpose 뒤에도 보존돼야 하나, consumer default axis로 재해석되면 dequantization이 다른 축에 적용될 수 있다.

**[기존 주장과의 충돌]** export된 ONNX가 로드되거나 일부 smoke inference를 통과해도 축 오류가 있으면 numerical/task-level fidelity가 보장되지 않는다.

**진단 → 가설 → 최소 실험**
- 진단: export 성공 여부는 axis semantics의 보존 여부를 검사하지 않는다.
- 가설: PyTorch/ONNX/TensorRT의 layerwise output 비교와 per-channel scale axis audit가 mismatch를 잡아낸다.
- 최소 실험: MaxViT attention block 또는 동등 transpose graph에 대해 FP reference·quantized ONNX를 고정 입력으로 실행하고 layerwise cosine similarity, max absolute error, top-1 consistency를 측정한다.
- **GO:** graph load뿐 아니라 모든 audited layer에서 axis와 numerical tolerance가 맞을 때. **KILL:** `dq_only` mismatch 또는 output drift가 threshold를 넘을 때.
- 심각도 **4/5**, 재현 신뢰도 **4/5**, 연구 아이디어 가치 **4/5**.

## 4. Ultralytics 8.4.201 — dataset path migration은 재현성 위험

**[확인된 사실]** Ultralytics 8.4.201은 `construction-ppe` archive/directory naming을 canonical 이름으로 정비했으며, 기존 local cache의 이전 directory name은 이 릴리스 지원 범위 밖이라고 공지한다. 모델 architecture 변경은 없다고 릴리스가 명시한다.  
출처: https://github.com/ultralytics/ultralytics/releases/tag/v8.4.201

**해석:** dataset path migration은 accuracy failure 자체가 아니라 재다운로드, 잘못된 dataset resolve, 재현 manifest의 경로 drift를 낳을 수 있는 운영 실패 신호다.

**최소 실험:** 격리된 cache에서 canonical YAML path와 기존 cache path를 각각 dry-run으로 해석하고, resolved archive path·class count·sample hash를 비교한다. 기존 cache를 덮어쓰지 않는다.

- 심각도 **3/5**, 재현 신뢰도 **4/5**, 연구 아이디어 가치 **2/5**.
