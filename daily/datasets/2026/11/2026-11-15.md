## 1. UBID-ER-3D — 투영 label 수보다 물리 손상 identity가 중요하다

**시점·공개 상태:** 공식 저장소는 Version 1.0, Publication Date 2026-11-13을 표시한다. 설명 안의 11/01 날짜와 실제 파일 publication을 구분했다. 공개 목록에는 README와 bridge별 ZIP, MD5가 있으며 전체 32개 파일이 Public으로 표시된다. [공식 배포 페이지](https://rdr.kuleuven.be/dataset.xhtml?persistentId=doi:10.48804/V7O2ED)

**규모·task·label:** 배포자 보고는 교량 5개, 원본 이미지 22,059장, 수동 주석 1,821개, 물리 손상 group 1,332개다. Labell3D 0.9.5가 시점 간 mask를 투영하며, Variant B는 tile 30,674개·label 167,943개, quality-filtered Variant C는 tile 20,751개·label 27,242개다. 노출 철근의 segmentation·다중 시점 손상 mapping을 다룬다. 이 수치는 파일을 전수 집계한 결과가 아니다. [배포자 설명](https://rdr.kuleuven.be/dataset.xhtml?persistentId=doi:10.48804/V7O2ED)

**Split·license·호환성:** 공개 페이지에서 표준 train/val/test membership은 확인하지 못했다. 데이터 license는 CC BY-NC-SA 4.0이다. 같은 손상의 여러 view·tile은 독립 표본으로 볼 수 없고, B와 C의 점수도 표본·label 정책이 달라 **not strictly apples-to-apples**다. 교량 5개의 수집 범위는 다른 구조물·센서·지리로의 일반화를 입증하지 않는다.

**진단 → 가설:** image-random split이면 같은 손상이 학습과 평가에 함께 들어갈 수 있다는 **추론**이다. C에서 점수가 높아져도 모델 개선보다 어려운 투영 label의 제거 효과일 수 있다.

**최소 audit:** `bridge ID → physical damage ID → source image → tile → projected mask` manifest를 만든다. split 간 damage ID 교집합, 겹치는 tile, label 면적·가시성·bridge별 빈도를 검사한다. 공통 손상 집합에서 B/C mask 일치도를 비교하고, 이후 같은 모델·해상도·seed로 random split과 bridge-heldout을 비교한다.

**GO/KILL:** lineage·공통 손상 audit는 GO. split 교집합이 발견되면 독립 평가 주장은 KILL하고 group split을 다시 만든다. 발견되지 않아도 near-duplicate 부재로 확대 해석하지 않는다.

## 2. Visual Cipher Bench — 공개 정답과 agent 입력의 경계

**확인한 공개 구조:** 공식 repo는 40개 task·67개 이미지와 reference solution·verifier를 제공한다. `solution/`과 `tests/`는 정답을 포함하므로 agent filesystem 밖에 둬야 하며 `environment/`만 task image build context로 사용한다고 명시한다. 코드·기술 문서는 Apache-2.0, 원본 퍼즐 콘텐츠는 CC BY 4.0이며 제3자 자료는 별도 조건을 따른다. [공식 README](https://github.com/Einsia/Visual-Cipher-Bench)

**저자 보고·평가 정책:** 네 category에 각 10개 task다. offline sandbox에서 60분 동안 이미지와 공통 지시문만 받고 중간 정오 피드백 없이 풀며, 별도 container의 deterministic exact-match verifier가 최종 답을 채점한다. 공개 문서에서 별도 학습 split은 확인하지 못했다. [논문 설계](https://arxiv.org/html/2611.16861v1)

**Bias·호환성:** 흑백 line drawing과 퍼즐 관습·영어 답안의 영향이 있어 자연 이미지 grounding의 대표 평가로 일반화하지 않는다. 시간·도구·reasoning effort가 다른 single-turn VQA와는 **not strictly apples-to-apples**다.

**진단 → 가설:** repo 전체를 agent 작업 디렉터리에 mount하면 시각 추론 대신 정답 조회가 가능할 수 있다는 **추론**이다. 공식 평가가 실제로 노출됐다는 증거는 아니다. 공개 이후 학습 corpus에 solution이 편입되는 위험도 별도로 추적해야 한다.

**최소 audit:** task별 agent-visible file manifest와 image hash를 고정하고 build context·mount 목록에서 solution, tests, 정답 문자열의 노출을 검사한다. network 비활성 및 verifier 분리를 확인한 뒤 oracle은 evaluator 쪽에서만 실행한다. 재평가 시 모델 snapshot·평가일·공개 정답 노출 이력을 기록하고 category별 결과를 분리한다.

**GO/KILL:** 파일 경계 검사는 GO. 정답·해설을 읽을 수 있는 환경의 점수는 KILL. 경계가 정상이어도 모델의 사전 학습 오염이 없다고 단정하지 않는다.

## 3. PhysCapBench — 주석 보조 정보와 text judge를 분리한다

**시점·규모·task:** v1은 11/12 16:33:09 KST다. 저자는 third-person 500개 영상, egocentric 500개 영상, handheld-gripper 500개 episode의 물리 caption 평가를 제안한다. 일곱 차원으로 정확성과 coverage를 평가한다. [논문·v1 이력](https://arxiv.org/abs/2611.16424v1)

**Annotation policy:** VLM 초안에 source-frame evidence를 연결하고 사람 검토·구조 검증을 수행했다고 보고한다. egocentric은 EgoDex의 hand pose, gripper는 동기화된 여러 view·trajectory를 주석 보조로 활용한다. 사람 검증 완료는 저자 보고이며 이번 독립 재검수 결과가 아니다. [주석 설계](https://arxiv.org/html/2611.16424v1)

**Evaluator·artifact·split·license:** 본문은 Doubao Seed 2.1 Pro text judge, temperature 0·thinking off를 명시한다. egocentric의 mechanism 차원은 고정 Gold의 mechanism field, 나머지는 short caption을 참조한다. 논문과 프로젝트 주소는 확인했으나 프로젝트 본문 추출이 제한돼 downloadable annotation manifest, data-specific license, train/dev/test membership은 확정하지 못했다. [평가 정책](https://arxiv.org/html/2611.16424v1) · [공식 프로젝트](https://hfwang2001.github.io/physcapbench-site/)

**진단 → 가설:** 보조 센서·여러 view로 만든 Gold와 RGB-only caption 사이의 정보 비대칭, 또는 text judge의 표현 선호가 점수에 영향을 줄 수 있다는 **추론**이다. 기존 source 영상 노출과 같은 episode의 여러 view를 독립 표본으로 세는 위험도 audit 대상이다. 입력·참조·judge가 다르면 **not strictly apples-to-apples**다.

**최소 audit:** 공개 artifact를 확보하면 episode/source ID별로 view를 묶고 기존 학습 manifest와 교차한다. Gold의 각 주장에 RGB에서 확인 가능한 evidence가 있는지 표본 검수한다. 같은 caption의 의미 보존 paraphrase와 contact/state 오류 삽입본을 고정 judge·사람 검토에 함께 넣어 표현 민감도와 실제 오류 민감도를 분리한다. domain·task별 빈도와 적용 가능한 평가 차원도 기록한다.

**GO/KILL:** evidence·judge audit 설계는 GO. 데이터 license·split·artifact 확인 전 학습 착수와 독립 재현 완료 주장은 KILL이다.
