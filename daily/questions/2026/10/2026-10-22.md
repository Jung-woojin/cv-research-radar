## Q1. 능력 퇴행을 막는 후학습 체크포인트 선택이 평균 점수 중심 선택보다 안전한가?

### 1. 문제 정의
멀티모달 모델의 SFT·GRPO 후학습에서 전체 평균은 개선되지만, Interaction Timing처럼 안전과 직접 연결된 하위 능력은 퇴행할 수 있다. 체크포인트 선택 목표를 평균 점수 최대화에서 **핵심 능력별 최저 성능 제약이 있는 다목적 선택**으로 바꾸면 이 퇴행을 줄일 수 있는가?

### 2. 왜 지금 중요한가
해양 감시와 로봇 상호작용에서는 객체 인식 평균이 좋아져도 “언제 개입해야 하는가”가 나빠지면 실제 위험이 커진다. 모델 크기 확대보다 후학습 과정의 선택 규칙을 바꾸는 실험이 훨씬 저렴하다.

### 3. 최신 직접 근거
- **사실:** PsycheMME 공식 결과에서 Qwen3.5-4B의 Raw/Verified macro는 47.68/37.71, SFT는 72.58/52.13, SFT+GRPO는 73.19/52.62였다.
- **사실:** Grounding과 Risk는 각각 27.96점, 27.40점 개선됐지만 Interaction Timing은 40.28에서 SFT 31.94, SFT+GRPO 34.72로 낮아졌다.
- **사실:** 72개 Timing MCQ에서 최고 단일 모델 정확도는 66.67%였지만 후보 중 하나라도 정답인 oracle은 91.67%, 단순 plurality는 57.64%였다.
- **공식 코드:** https://github.com/psychemme/PsycheMME

### 4. 핵심 가설
평균 검증 점수만으로 체크포인트를 선택하면 데이터 비중이 작은 능력의 퇴행을 숨긴다. `평균 성능 − λ·핵심 능력 퇴행량` 또는 Pareto 제약을 쓰면 전체 개선을 대부분 유지하면서 Timing 퇴행을 줄일 수 있다.

### 5. MVP
기존 학습 로그 또는 5~10개 체크포인트를 대상으로 다음 세 선택 규칙을 사후 비교한다.

1. 전체 macro 최대
2. 최악 하위 능력 최대
3. 평균 최대이되 Timing이 초기 모델보다 2점 이상 낮아지지 않는 제약

새 학습 없이 먼저 checkpoint selection만 재평가한다.

### 6. 베이스라인과 데이터셋
- 베이스라인: final checkpoint, macro-best checkpoint, early stopping
- 데이터: PsycheMME 공개 평가 세트와 공식 스키마
- 추가 검증: 소규모 해양 위험·개입시점 문항 30~50개를 별도 보유 세트로 구성

### 7. 성공·실패 지표
- 성공: macro 손실이 1점 이내이면서 Timing 퇴행의 절반 이상 회복
- 실패: 어떤 선택 규칙도 Timing을 회복하지 못하거나, 회복 시 다른 핵심 능력이 같은 폭으로 퇴행
- 보조 지표: 능력별 worst-case score, checkpoint 간 순위 안정성, 부트스트랩 신뢰구간

### 8. 계산 난이도
**3/5.** 공개 체크포인트가 충분하면 추론 중심이다. 전체 재학습이 필요할 경우 비용이 커진다.

### 9. 새로움 위험
**4/5.** 다목적 체크포인트 선택 자체는 알려져 있지만, 멀티모달 안전 능력의 명시적 퇴행 제약과 후보 다양성 분석을 결합하면 차별화할 수 있다.

### 10. 4~8주 논문화 가능성
**4/5.** 1~2주 내 사후 선택 실험, 3~4주 내 제약 기반 짧은 후학습, 이후 다른 벤치마크로 일반화 검증이 가능하다.

### 11. 음성 결과의 가치
퇴행이 체크포인트 선택으로 해결되지 않으면 원인이 데이터 충돌이나 목적함수 간 간섭이라는 근거가 된다. 이후 gradient conflict, task routing, 능력별 adapter 연구로 이어질 수 있다.

**평가:** 새로움 4/5 · 실행 가능성 4/5 · 계산 효율 3/5 · 논문화 가능성 4/5

## Q2. 해무 환경의 언어 기반 추적기에서 “텍스트를 알고 있음”과 “텍스트를 사용함”을 분리할 수 있는가?

### 1. 문제 정의
Vision-Language Tracker가 내부 표현에는 텍스트 정보를 담고도 최종 위치 결정에는 사용하지 않을 수 있다. 해무·저조도에서 올바른 설명, 충돌 설명, 무관 설명, 빈 설명을 통제해 **텍스트 보유와 인과적 사용을 분리 측정**할 수 있는가?

### 2. 왜 지금 중요한가
해양 영상은 시각 품질이 자주 떨어진다. 이때 텍스트가 실제 추적 결정에 기여하는지 모르면 멀티모달 설계를 채택할 근거가 약하다. 단순 성능 비교보다 정보 흐름을 진단해야 실패 지점을 고칠 수 있다.

### 3. 최신 직접 근거
- **사실:** DISTRACT는 5개 VLT, 4개 데이터셋에서 correct/conflicting/neutral/blank text와 영상 열화를 짝지어 비교했다.
- **사실:** UVLTrack, MMTrack, DUTrack은 테스트된 설정에서 FDR 보정 후 방향성 있는 의미 텍스트 효과가 없었다.
- **사실:** UVLTrack은 25개 내부 상태 중 14개에서 텍스트 신호가 유의했지만, 최종 pre-localization 상태에서는 유의하지 않았다.
- **사실:** JointNLT는 SportsMOT clean 조건에서 텍스트가 blank보다 11.2% 나쁜 효과를 보였다.
- **저자 주장:** 내부에 언어 정보가 존재하는 것과 최종 예측에서 언어를 사용하는 것은 다르다.
- **논문:** https://arxiv.org/html/2610.28419v1

### 4. 핵심 가설
해무가 심해질수록 텍스트의 잠재적 가치는 커지지만, 현재 late-fusion 또는 gating 구조는 해당 신호를 최종 localization head까지 전달하지 못한다. 결정 직전의 작은 residual text gate를 학습하면 충돌 텍스트에는 둔감하고 올바른 텍스트에는 민감한 인과 효과가 나타난다.

### 5. MVP
한 개 공개 VLT에 대해 맑음·합성 해무 3단계 × 4개 텍스트 조건을 구성한다. 각 조건에서:

1. 출력 박스 변화
2. 내부 텍스트 선형 probe 정확도
3. 텍스트 표현을 제거·교체했을 때의 causal effect
4. decision-near activation patching

을 측정한다. 이후 1~2M 파라미터의 residual gate만 학습한다.

### 6. 베이스라인과 데이터셋
- 베이스라인: image-only tracker, 원본 VLT, text-shuffle, blank-text, late fusion
- 데이터: LaSOT 또는 TrackingNet의 공개 subset + 합성 해무
- 해양 이전: SeaShips 또는 공개 해양 감시 영상에서 수동으로 짧은 tracking subset 구성

### 7. 성공·실패 지표
- 성공: 올바른 텍스트가 blank 대비 Success/AUC를 개선하고, conflicting text는 방향성 있게 악화하며, 이 효과가 FDR 보정 후 유지
- 실패: 내부 probe는 높지만 출력 효과가 계속 없거나, 모든 텍스트 조건이 같은 방향으로 움직임
- 보조 지표: intervention effect size, calibration, 실패 프레임 유형

### 8. 계산 난이도
**3/5.** 추론과 작은 gate 학습이 중심이지만 여러 열화·텍스트 조건의 반복 실행이 필요하다.

### 9. 새로움 위험
**5/5.** 해무 조건에서 정보 보유와 인과적 사용을 분리하고 decision-near intervention까지 연결하는 연구는 차별성이 높다.

### 10. 4~8주 논문화 가능성
**5/5.** 진단 논문으로도 성립하며, 작은 gate가 효과를 보이면 방법론 논문으로 확장할 수 있다.

### 11. 음성 결과의 가치
텍스트가 해무에서도 실제 결정에 기여하지 않는다면, 현 구조의 멀티모달 명칭과 계산 비용을 재검토할 근거가 된다. image-only 강한 베이스라인을 선택하는 실용적 결론도 얻는다.

**평가:** 새로움 5/5 · 실행 가능성 4/5 · 계산 효율 3/5 · 논문화 가능성 5/5

## Q3. 코드 생성형 시각 파이프라인에서 동일 토큰 예산의 “오류 기반 1회 수리”가 재생성보다 효율적인가?

### 1. 문제 정의
시각 결과를 코드로 생성하는 모델은 성공한 샘플의 품질이 높아도 컴파일, API, 런타임 오류 때문에 전체 효용이 크게 낮아진다. 최초 실행 오류를 구조화해 한 번만 수정하는 방식이 처음부터 재생성하는 방식보다 성공률과 품질을 높이는가?

### 2. 왜 지금 중요한가
연구 자동화에서 시각화·데이터 변환·실험 스크립트를 생성할 때 실패의 대부분이 모델 능력보다 실행 계약 위반에서 생길 수 있다. 별도 학습 없이 실행 피드백만으로 개선 가능한 문제다.

### 3. 최신 직접 근거
- **사실:** Code2Video-Compass는 2,104개 과제와 15개 MLLM을 평가했다.
- **사실:** 성공 샘플만 평가한 holistic quality는 GPT-6 Astra 4.19, GPT-6.1 Sol 4.15, Claude Opus 5.5 4.04였지만, 실패까지 포함한 full-set 점수는 각각 3.62, 3.61, 3.87이었다.
- **사실:** 총 2,756개 오류가 관찰됐다.
- **사실:** GPT-6 Astra 실패의 83.4%는 compilation+missing API/package, Qwen3.8-Max 실패의 59.7%는 missing API/package, Claude Opus 5.5 실패의 75%는 runtime exception이었다.
- **논문:** https://arxiv.org/html/2610.28416v1

### 4. 핵심 가설
실행 로그를 `syntax / missing dependency / invalid API / runtime state / timeout`으로 분류하고 해당 부분만 수정하도록 제한하면, 동일 토큰 예산의 전체 재생성보다 성공률이 높고 이미 맞은 시각 요소도 더 잘 보존된다.

### 5. MVP
30개 과제에서 세 전략을 비교한다.

1. 첫 출력 그대로
2. 같은 총 토큰 예산으로 전체 재생성
3. stderr, 실패 줄, 허용 API 목록만 제공한 1회 국소 수리

각 과제는 격리 환경에서 두 번 실행하고, 수리 프롬프트는 수정 범위를 실패 원인과 인접 코드로 제한한다.

### 6. 베이스라인과 데이터셋
- 베이스라인: zero-shot, full regeneration, lint-only repair
- 데이터: Code2Video-Compass에서 재현 가능한 30개 과제 또는 Blender/Manim 혼합 소형 세트
- 모델: 접근 가능한 동일 모델 하나를 고정해 전략만 비교

### 7. 성공·실패 지표
- 성공: 동일 토큰 예산에서 실행 성공률 15%p 이상 개선, 성공 결과의 품질 저하 없음
- 실패: 수리와 재생성의 성공률 차이가 없거나, 수리 과정에서 기능 회귀가 증가
- 보조 지표: 오류 유형별 복구율, wall-clock, 토큰 수, 수정 줄 수, 결과 보존율

### 8. 계산 난이도
**2/5.** 학습이 없고 30개 과제로 시작할 수 있다. 실행 격리와 로그 정규화가 핵심이다.

### 9. 새로움 위험
**4/5.** 일반 코드 수리는 성숙한 분야지만, 실행 가능한 시각 파이프라인의 품질 보존과 토큰 예산을 함께 평가하면 연구 기여가 생긴다.

### 10. 4~8주 논문화 가능성
**4/5.** 첫 주에 결과가 나오며, 오류 분류기와 다단계 정책을 추가해 짧은 시스템 논문으로 확장할 수 있다.

### 11. 음성 결과의 가치
수리가 재생성보다 낫지 않다면 오류 메시지의 정보량이 부족하거나 모델이 국소 수정 제약을 따르지 못한다는 결론을 얻는다. 오류 유형별로 어떤 전략이 맞는지 라우팅 규칙을 만들 수 있다.

## Q4. 해양 안전 VLM에서 멀티모달·멀티카메라 증거를 질의별로 선택하는 것이 “모두 보기”보다 나은가?

### 1. 문제 정의
비디오, 오디오, ASR, 여러 카메라를 모두 입력하면 계산량과 잡음이 늘지만 정답의 시공간 근거가 반드시 좋아지지는 않는다. 제한된 증거 예산에서 질의별로 모달리티·시점·시간 구간을 선택하면 정답과 근거 정합성을 함께 높일 수 있는가?

### 2. 왜 지금 중요한가
항만·선박 안전 시스템은 여러 CCTV와 음향 센서를 동시에 사용할 수 있지만, 엣지 GPU에서 모든 스트림을 고해상도로 처리하기 어렵다. 근거 없는 정답은 사고 분석과 운영 의사결정에도 약하다.

### 3. 최신 직접 근거
- **사실:** EvaOmni에서 Gemini3.7-Flash의 정답률은 79.4였지만 정답이면서 두 모달리티 모두 올바르게 grounding된 비율은 41.8이었다.
- **사실:** Qwen3.8-Omni-Flash는 정답률 58.2, correct-and-grounded 11.8이었다.
- **사실:** 모델별로 정답의 48.1~79.9%가 두 모달리티 IoU≥0.5 조건을 만족하지 못했다.
- **사실:** MiMo-V2.5는 Video+Audio에서 56.8/48.4/20.5, Video+ASR에서 48.7/38.1/11.6으로, 원음과 ASR이 같은 정보를 제공하지 않았다.
- **공식 코드:** https://github.com/VisionXLab/EvaOmni
- **사실:** MindView에서 목표 coverage는 카메라 3/6/10개일 때 57.6/88.4/92.0이었지만, 평가된 11개 생성기와 BAGEL-SFT는 모두 C10 성능이 C6보다 낮았다. MindCue는 평균 7.4개 뷰로 41.1/65.1을 기록했다.
- **논문:** https://arxiv.org/html/2610.28622v1

### 4. 핵심 가설
질의 임베딩을 이용해 먼저 저비용 썸네일·음향 이벤트에서 후보 증거를 고르고, 선택된 구간과 카메라만 고해상도로 처리하면 전체 입력보다 잡음과 계산을 줄이면서 grounded correctness를 높일 수 있다.

### 5. MVP
4개 카메라 × 2분 영상 × 오디오가 있는 소형 시나리오 20개를 구성한다. 다음 네 정책을 비교한다.

1. 단일 카메라
2. 모든 카메라·전체 오디오
3. 균등 예산 샘플링
4. 질의 조건부 top-k 카메라·시간·모달리티 선택

선택기는 frozen encoder의 유사도와 간단한 event detector만 사용한다.

### 6. 베이스라인과 데이터셋
- 베이스라인: all-evidence, random top-k, uniform temporal sampling, modality ablation
- 데이터: EvaOmni 공개 예제·스키마, 멀티뷰 검증용 MindView 설정, 공개 해양 CCTV/음향 자료의 소형 수동 주석 세트
- 모델: 4B~8B급 VLM 1개를 고정

### 7. 성공·실패 지표
- 성공: 전체 입력 대비 토큰·프레임 40% 이상 절감, 정답률 유지, correct-and-grounded 5%p 이상 개선
- 실패: 선택 정책이 핵심 증거를 자주 누락하거나 all-evidence보다 calibration이 악화
- 보조 지표: modality별 IoU, 카메라 coverage, latency, evidence recall, 선택 안정성

### 8. 계산 난이도
**3/5.** frozen encoder와 추론 중심 MVP는 가능하지만 멀티카메라 데이터 정리가 필요하다.

### 9. 새로움 위험
**5/5.** 멀티모달 grounding과 멀티뷰 evidence budget을 해양 안전 문제로 묶는 연구는 장기 확장성이 높다.

### 10. 4~8주 논문화 가능성
**5/5.** 소형 진단 세트와 선택 정책만으로 초기 결과를 만들 수 있고, 이후 능동 센서 선택·불확실성 기반 재조회로 확장 가능하다.

### 11. 음성 결과의 가치
선택이 실패하면 “모든 증거”가 필요한 질의 유형과 저비용 pre-selector가 놓치는 사건 유형을 분리할 수 있다. 이는 센서 배치와 데이터 수집 설계에 직접 도움이 된다.

**평가:** 새로움 5/5 · 실행 가능성 4/5 · 계산 효율 3/5 · 논문화 가능성 5/5

## Q5. 수량 균형 학습과 P2 고해상도 특징이 소형 해양 객체의 실제 계수를 개선하는가, 선호 숫자 편향만 바꾸는가?

### 1. 문제 정의
영상 계수 모델은 작은 숫자에 편중된 데이터에서 특정 정수를 반복 예측할 수 있다. 소형 객체 탐지에서 P2/high-resolution feature와 수량 균형 샘플링을 추가했을 때 진짜 시각적 분해능이 좋아지는지, 단지 예측 숫자 분포만 이동하는지 구분한다.

### 2. 왜 지금 중요한가
항만의 부표, 소형 선박, 인원 계수는 안전 경보 임계치와 직접 연결된다. mAP만 보면 중복 검출과 누락이 상쇄될 수 있어 수량별 오차 구조를 따로 봐야 한다.

### 3. 최신 직접 근거
- **사실:** CountVideoBench가 조사한 기존 9개 VideoQA 계수 벤치마크의 정답 중앙값은 5 이하였고, 가장 흔한 세 수가 전체의 45~93%를 차지했다.
- **사실:** CountVideoBench는 5~50의 26개 cardinality마다 100개씩, 총 2,600개 합성 영상을 제공한다.
- **사실:** 16개 모델·9개 아키텍처 계열 중 Exact Match 27.6%를 넘은 모델이 없었다.
- **저자 주장:** 여러 모델은 특정 정수를 선호하며 인접 cardinality에서도 성능이 급격히 오르내린다.
- **논문:** https://arxiv.org/html/2610.28356v1
- **프로젝트:** https://countvideobench.github.io/

### 4. 핵심 가설
수량 균형만 적용하면 prior 편향은 줄지만 밀집·소형 객체 분리가 해결되지 않는다. P2/high-resolution feature와 균형 샘플링을 함께 써야 per-count bias와 실제 localization error가 동시에 감소한다.

### 5. MVP
소형 객체가 포함된 공개 항공/해양 이미지 subset을 count bin별로 균형화한다. compact detector에서:

1. 기본 FPN
2. P2 추가
3. count-balanced sampler
4. P2 + balanced sampler

를 비교한다. 8프레임과 32프레임의 짧은 비디오 집계도 추론 단계에서 비교한다.

### 6. 베이스라인과 데이터셋
- 베이스라인: 기본 FPN detector, density regression, 단순 temporal average
- 데이터: VisDrone 또는 AI-TOD의 small-object subset, SeaShips/공개 해양 데이터의 count 주석 가능 subset, CountVideoBench의 cardinality-balanced protocol
- 모델: nano/small급 detector, 입력 해상도 640~1024

### 7. 성공·실패 지표
- 성공: 큰 count bin에서 MAE와 undercount bias가 감소하고, AP-small 및 localization recall도 함께 개선
- 실패: Exact Match만 좋아지고 AP-small·recall이 그대로이거나, 선호 숫자만 다른 값으로 이동
- 보조 지표: per-count confusion, prediction entropy, calibration, 중복 검출률, 8/32프레임 일관성

### 8. 계산 난이도
**3/5.** 8GB GPU에서 small 모델·gradient accumulation·부분 데이터로 수행 가능하다.

### 9. 새로움 위험
**4/5.** P2 자체는 새롭지 않지만, cardinality prior와 spatial resolution 효과를 분리하는 진단 설계가 기여가 된다.

### 10. 4~8주 논문화 가능성
**4/5.** 2주 내 ablation이 가능하고, 실제 해무·혼잡도 조건을 추가하면 응용 논문으로 확장할 수 있다.

### 11. 음성 결과의 가치
P2가 count bias를 줄이지 못하면 문제의 핵심이 해상도보다 중복 억제, temporal association, 학습 분포에 있음을 보여준다. 장비 업그레이드보다 데이터·후처리 개선을 우선할 근거가 된다.

**평가:** 새로움 4/5 · 실행 가능성 4/5 · 계산 효율 3/5 · 논문화 가능성 4/5

## Q6. 수량을 바꾼 해양 합성 이미지의 품질을 judge-free 검사가 VLM/CLIP 점수보다 잘 예측하는가?

### 1. 문제 정의
“부표 한 개 추가”, “선박 두 척 제거” 같은 수량 편집은 장면을 보존하면서 정확한 개수만 바꿔야 한다. 현재의 전체 이미지 유사도나 VLM judge가 이 오류를 놓칠 때, 인스턴스 매칭과 장면 보존을 분리한 judge-free 검사가 실제 downstream detector 향상을 더 잘 예측하는가?

### 2. 왜 지금 중요한가
희귀 해양 상황을 합성 데이터로 늘릴 때 수량 오류가 섞이면 탐지기의 false positive와 count calibration을 악화시킬 수 있다. 생성 모델보다 먼저 신뢰할 수 있는 품질 필터가 필요하다.

### 3. 최신 직접 근거
- **사실:** ABACUS는 기존 이미지 편집 벤치마크의 holistic metric과 VLM judge가 계수 오류를 잘 포착하지 못한다는 문제를 다룬다.
- **사실:** add/remove/change 편집을 대상으로 객체 인스턴스 변화와 장면 보존을 분리하는 judge-free evaluator를 제안한다.
- **공식 코드:** https://github.com/CEA-LIST/ABACUS
- **논문:** https://arxiv.org/html/2610.28316v1

### 4. 핵심 가설
인스턴스 대응, 목표 count delta, 비편집 영역 보존을 별도로 검사한 점수가 CLIP similarity나 단일 VLM judge보다 합성 이미지로 학습한 detector의 실제 성능 변화를 더 잘 예측한다.

### 5. MVP
해양 이미지 100장에 대해 객체 추가·제거 편집을 만들고 세 필터를 비교한다.

1. CLIP similarity
2. VLM judge
3. ABACUS식 instance matching + scene conservation

각 필터의 상위 50장으로 같은 detector를 짧게 fine-tune하고 원본 검증 세트에서 비교한다.

### 6. 베이스라인과 데이터셋
- 베이스라인: 무필터, CLIP 상위, VLM judge 상위, 수동 검수 상위
- 데이터: SeaShips 또는 공개 해양 객체 데이터, COCO의 boat/person subset
- 편집기: 동일 모델·동일 prompt template로 고정

### 7. 성공·실패 지표
- 성공: judge-free score가 수동 count 정확도 및 downstream AP/count MAE와 가장 높은 순위 상관을 보임
- 실패: CLIP/VLM과 차이가 없거나, evaluator가 detector segmentation 오류를 그대로 상속
- 보조 지표: 장면 보존률, 편집 성공률, false addition/removal, 필터링 비용

### 8. 계산 난이도
**3/5.** 편집 생성과 detector 단기 fine-tuning이 필요하지만 100장 규모로 시작할 수 있다.

### 9. 새로움 위험
**4/5.** evaluator 개념은 공개됐지만, 합성 데이터 필터 점수가 downstream 해양 탐지 성능을 예측하는지 검증하는 연결은 새롭다.

### 10. 4~8주 논문화 가능성
**4/5.** 2주 내 데이터 생성·평가, 2주 내 downstream 검증이 가능하다. 해무·야간 조건을 추가하면 응용 범위를 넓힐 수 있다.

### 11. 음성 결과의 가치
judge-free 점수가 downstream 성능을 예측하지 못하면 픽셀·인스턴스 정확도 외에 도메인 질감, 편집 흔적, 모델 편향이 더 중요하다는 근거가 된다. 합성 데이터 품질의 평가 목표를 재정의할 수 있다.

**평가:** 새로움 4/5 · 실행 가능성 4/5 · 계산 효율 3/5 · 논문화 가능성 4/5

3. **다음 주:** Q2의 correct/conflicting/neutral/blank text × 해무 강도 실험표를 구성한다.
4. **4주 이내:** Q4용 멀티카메라·오디오 소형 시나리오 20개와 evidence annotation protocol을 만든다.
5. 모든 실험은 평균 점수와 함께 **조건별 실패 분포, 근거 정합성, 계산량**을 기록한다.
