## 1. Roboflow Inference v1.7.4 — production CV runtime의 memory·video 경계 수정

**공식 근거:** [v1.7.4 release](https://github.com/roboflow/inference/releases/tag/v1.7.4) · [repository](https://github.com/roboflow/inference)

1. **새로 나온 내용**  
   2026-10-09 공개된 v1.7.4는 V-JEPA 2.1 action recognition, reduced-resolution mask metadata, FoundAD/PatchCore anomaly-map wire format, SAM3 serverless 병렬 처리, sliced segmentation memory 수정, video total-frame metadata를 포함한다.

2. **논문·프로젝트 연결**  
   특정 논문 하나의 구현보다 detection·segmentation·tracking·VLM·video action recognition을 같은 server/workflow 계층에서 운영하는 inference framework다. V-JEPA 2.1, RF-DETR, SAM3, Grounding DINO, YOLO-World 같은 모델 계열을 실제 pipeline에 연결한다.

3. **코드 품질과 재현성**  
   release note가 관련 PR, test 범위, 실패 원인, 측정 장비를 함께 연결한다. SAM3 변경은 tensor representation 유무별 test 수를 기록하고, sliced segmentation은 8GiB worker OOM이 5.9GiB peak로 완료됐다고 보고한다. 이 수치는 maintainer 측정이며 독립 재현값이 아니다.

4. **라이선스**  
   기본 repository core는 Apache-2.0이다. `inference/models/`의 개별 모델과 enterprise directories에는 별도 license가 적용되므로 전체를 일괄 Apache-2.0으로 취급하면 안 된다.

5. **pretrained weights/checkpoints**  
   runtime 자체 weight는 없고 각 model provider의 weight를 사용한다. Release에는 CPU/GPU Windows installer와 macOS DMG가 있으며 SHA-256 digest가 GitHub asset metadata에 기록돼 있다.

6. **설치 난이도와 의존성**  
   Docker와 NVIDIA Container Toolkit을 설치한 뒤 `pip install inference-cli && inference server start --dev`가 기본 경로다. 단일 Python package보다 image 크기와 model별 backend가 커서 첫 설치 비용은 높다.

7. **GPU/VRAM 요구량**  
   framework 공통 최소 VRAM은 제시되지 않았고 모델마다 다르다. 이번 release에서 8GiB segmentation worker OOM 사례가 5.9GiB peak로 개선됐다는 구체적 경계는 8GB GPU 사용자에게 직접 유용하다.

8. **바로 실험에 붙이기 좋은가**  
   좋다. 특히 기존 segmentation pipeline의 `allow_reduced_mask_resolution`, tiled mask stitching, SAM3 batch 경로를 같은 입력으로 비교하기 쉽다. Wire-format 변경이 있으므로 anomaly map consumer는 migration test가 필요하다.

9. **framework 호환성**  
   Ultralytics·YOLO 계열, RF-DETR, SAM 계열, Grounding DINO, VLM blocks를 runtime interface로 묶는다. MMDetection·timm checkpoint를 임의로 drop-in하는 일반 adapter라고 보기는 어렵다.

10. **maintenance 가능성 / issue·PR 활동성**  
    release 직후에도 main push와 다수 PR이 이어졌고 CI·security refresh가 포함됐다. 다만 공개 issue 수가 많고 model별 license·backend 차이가 커서 특정 model path의 유지 상태는 별도 확인해야 한다.

**진단 → 가설 → 최소 실험**

- **진단:** 8GB 환경의 segmentation 실패는 backbone 자체보다 full-frame mask materialization과 postprocessing에서 발생할 수 있다.
- **가설:** reduced mask grid와 stitched-mask memory 수정은 small-object boundary 손실을 제한하면서 peak VRAM을 의미 있게 낮춘다.
- **최소 실험:** 동일 4K maritime/UAV 이미지 50장에 factor 1.0/0.5/0.25를 적용해 APs·boundary F-score·peak VRAM·warm/cold p95를 측정한다.
- **GO:** peak VRAM 20% 이상 감소, APs 손실 1%p 이하.
- **KILL:** tiny-object boundary 손실이 2%p를 넘거나 첫 Triton compile 비용이 실제 workload에서 상쇄되지 않음.

**평가:** 실험 가치 5/5 · 재현성 5/5 · 신규성 4/5 · 실용성 5/5

## 2. OccStress — 4D occupancy forecasting robustness benchmark

**공식 근거:** [repository](https://github.com/InSAI-Lab/OccStress) · [dataset](https://huggingface.co/datasets/insailab/OccStress) · [paper](https://arxiv.org/abs/2512.15621)

1. **새로 나온 내용**  
   2026-10-06 code, dataset, leaderboard를 함께 공개했다. nuScenes·Waymo·CARLA 기반 3개 benchmark, 21개 corruption family, 61개 severity configuration, 6개 future horizon을 제공한다.

2. **논문·프로젝트 연결**  
   센서 corruption이 3D occupancy estimator를 거쳐 미래 occupancy 예측에 전파되는 upstream track과, forecaster 자체 민감도를 분리하는 manual track을 제공한다. 현재·최근 burst·오래된 history corruption을 나눠 timing failure를 본다.

3. **코드 품질과 재현성**  
   `tests/`, CI, formal evaluation 문서, external-data preparation, environment별 guide가 있다. GPU 없이 `examples/minimal_eval.py`와 protocol validator를 실행할 수 있지만 그 출력은 synthetic score이며 논문 성능이 아니다.

4. **라이선스**  
   repository는 MIT다. nuScenes·Waymo 등 원본 데이터와 외부 model/checkpoint는 각자의 license와 접근 조건을 따른다.

5. **pretrained weights/checkpoints**  
   checkpoint를 포함하지 않는다. 공식 source link와 파일 선택 guide를 제공하지만 일부 weight identity·mirror는 review 중이라고 명시한다.

6. **설치 난이도와 의존성**  
   Python 3.10+와 editable install로 core smoke test는 가볍다. 전체 benchmark는 source dataset, clean GT, metadata, model별 분리 environment가 필요해 무겁다.

7. **GPU/VRAM 요구량**  
   core protocol test는 CPU로 가능하다. 6개 forecaster·7개 upstream source의 small-sample A100 integration check만 확인됐고, 전체 조합의 최소 VRAM은 문서에서 단일 수치로 보장하지 않는다.

8. **바로 실험에 붙이기 좋은가**  
   매우 좋다. 처음에는 released occupancy state와 manual corruption만 사용해 camera/LiDAR 원본 없이 temporal sensitivity를 감사할 수 있다. 75개 archive, 40.95GB compressed 중 필요한 package만 checksum 검증해 받을 수 있다.

9. **framework 호환성**  
   OccWorld, I²-World, COME, GenieDrive, DOME, SparseWorld-TC adapter와 ALOcc, STCOcc, FusionOcc, SDGOcc, CVT-Occ, EFFOcc, FlashOcc export integration이 있다. MMDetection·Ultralytics·timm용 범용 drop-in은 아니다.

10. **maintenance 가능성 / issue·PR 활동성**  
    새 저장소라 장기 유지성은 아직 판단하기 이르다. 반면 formal spec, package index, checksum, tested-scope 문서가 있어 최초 공개 품질은 높다.

**진단 → 가설 → 최소 실험**

- **진단:** 미래 occupancy failure는 corruption 크기뿐 아니라 corruption이 observation history의 어느 시점에 들어왔는지에 따라 달라질 수 있다.
- **가설:** 같은 corruption budget에서도 recent burst가 old-history corruption보다 1~3초 prediction horizon을 더 크게 무너뜨린다.
- **최소 실험:** CPU synthetic fixture로 protocol을 검증한 뒤 CARLA manual track 한 package와 한 forecaster에서 current-only/recent-burst/history-only를 비교한다.
- **GO:** horizon별 degradation ordering이 두 severity 이상에서 일관됨.
- **KILL:** class mapping이나 metric version 차이가 corruption 효과보다 큼.

**평가:** 실험 가치 5/5 · 재현성 4.5/5 · 신규성 5/5 · 실용성 4.5/5

## 3. BiGym 2.0 — humanoid household manipulation과 coding-agent benchmark

**공식 근거:** [repository](https://github.com/swirl-uk/BiGym2) · [paper](https://arxiv.org/abs/2610.07594) · [project](https://bigym2.github.io/)

1. **새로 나온 내용**  
   2026-10-08 code, 20개 task, 1,200개 human VR demonstration, 5,400개 coding-agent evaluation episode를 공개했다. Unitree G1과 frozen GR00T-WBC lower-body controller를 사용한다.

2. **논문·프로젝트 연결**  
   learned policy와 code-writing agent를 같은 100 fixed seed protocol에서 평가한다. 한 demonstration video와 task description을 보고 agent가 `policy.py`를 작성하는 별도 benchmark가 포함된다.

3. **코드 품질과 재현성**  
   `tests/`, GitHub 설정, pre-commit, typed stubs, lockfile, 상세 docs, fixed seed와 bit-exact replay 계약이 있다. training·evaluation뿐 아니라 VR collection과 browser replay도 제공한다.

4. **라이선스**  
   code는 Apache-2.0이다. Unitree G1 assets, scene prop, GR00T-WBC weight는 BSD/CC/NVIDIA Open Model License 등 별도 조건이 명시돼 있다.

5. **pretrained weights/checkpoints**  
   GR00T-WBC 관련 asset과 demonstration/agent rollout은 공식 경로로 제공된다. benchmark의 policy training weight가 모두 하나의 pretrained model로 제공되는 구조는 아니다.

6. **설치 난이도와 의존성**  
   Python 3.10+, `uv sync`가 기본이다. core benchmark 외에 LeRobot, VR, coding-agent 기능은 extras로 분리돼 있다. Linux, NVIDIA GPU, ffmpeg가 coding-agent harness 조건이다.

7. **GPU/VRAM 요구량**  
   정확한 최소 VRAM은 문서에 단일 수치가 없다. 전체 training demonstration은 약 29GB이며 agent benchmark 파일만 받을 때는 68MB 수준으로 줄일 수 있다. 8GB GPU 가능 여부를 추정하지 않는다.

8. **바로 실험에 붙이기 좋은가**  
   시뮬레이터 설치가 되면 좋다. `examples/train_act.py`로 작은 ACT baseline을 학습·평가하고 episode를 다시 볼 수 있다. VLA용 224×224 re-render와 LeRobot export가 특히 유용하다.

9. **framework 호환성**  
   LeRobot export가 명시돼 있고 external task/backend 등록 API가 있다. MMDetection·Ultralytics·timm과 직접 연결되는 vision backbone repo는 아니다.

10. **maintenance 가능성 / issue·PR 활동성**  
    10월 8일 공개 후 10월 11일까지 push가 이어졌고 roadmap에 PyPI·leaderboard가 남아 있다. 초기 활동성은 좋지만 장기 운영은 아직 관찰이 필요하다.

**진단 → 가설 → 최소 실험**

- **진단:** VLA 성능 차이가 policy 학습보다 camera resolution·demo replay·seed protocol에서 생길 수 있다.
- **가설:** 동일 demonstration state를 224와 native resolution로 re-render하면 작은 조작 물체가 있는 task에서 성능 격차가 집중된다.
- **최소 실험:** `move_plate`와 `stack_blocks` 두 task에서 small ACT를 동일 seed·step budget으로 비교하고 success·object visibility·latency를 기록한다.
- **GO:** resolution effect가 task difficulty와 일관되게 연결됨.
- **KILL:** seed variance가 resolution effect보다 큼.

**평가:** 실험 가치 4.5/5 · 재현성 4.5/5 · 신규성 5/5 · 실용성 4/5

## 4. GRACE — pretrained video DiT를 유지한 latent compression inference

**공식 근거:** [repository](https://github.com/cvlab-kaist/GRACE) · [paper](https://arxiv.org/abs/2610.10524) · [weights](https://huggingface.co/chimaharicox/GRACE)

1. **새로 나온 내용**  
   이번 주 official inference code와 T2V/I2V checkpoint를 공개했다. 16× spatial·8× temporal compression, dual latent, generation-aware alignment, asymmetric denoising을 구현한다.

2. **논문·프로젝트 연결**  
   Wan2.1-14B의 pretrained DiT를 처음부터 재학습하지 않고 latent token을 줄이는 video generation 연구다. 저자는 8× token 감소, 480×832×81에서 11.1×, 736×1280×81에서 15.5× latency 개선을 주장한다.

3. **코드 품질과 재현성**  
   pinned PyTorch 2.5.1, prompt set, benchmark command, 필수 `async_delta=0.15`, repository에 포함된 DiffSynth fork 사용 조건을 명시한다. 다만 root에 test/CI가 보이지 않고 training code는 TODO로 남아 있다.

4. **라이선스**  
   GRACE code는 MIT, bundled DiffSynth-Studio는 Apache-2.0이다. Wan2.1 base weight는 재배포하지 않으며 원 제공자의 license를 따라야 한다.

5. **pretrained weights/checkpoints**  
   GRACE 자체 checkpoint는 약 23GB다. T2V base까지 합친 디스크 예산은 약 54GB, I2V는 약 77GB라고 공식 README가 안내한다.

6. **설치 난이도와 의존성**  
   Python 3.11/3.12, PyTorch 2.5.1, repository 내 DiffSynth fork가 필요하다. upstream pip DiffSynth는 두 설정을 무시해 실행은 되지만 다른 영상을 만든다고 경고한다.

7. **GPU/VRAM 요구량**  
   14B base 때문에 높다. 정확한 최소 VRAM은 공식 README에서 보장하지 않으며 RTX 5060 Ti 8GB 대상이라고 볼 근거가 없다.

8. **바로 실험에 붙이기 좋은가**  
   고메모리 GPU가 있으면 official prompt와 single sample inference는 가능하다. 8GB 개인 장비에서는 clone 후 코드·protocol audit까지만 현실적이다.

9. **framework 호환성**  
   Hugging Face에서 checkpoint를 받지만 일반 Transformers pipeline, MMDetection, Ultralytics, timm adapter가 아니다. Wan2.1·DiffSynth 전용에 가깝다.

10. **maintenance 가능성 / issue·PR 활동성**  
    10월 5일 생성 후 10월 10일까지 push가 있었고 issue가 열려 있다. 초기 공개 상태이며 training code와 demo가 미완료라 유지성을 높게 단정하지 않는다.

**진단 → 가설 → 최소 실험**

- **진단:** 저 latency가 token 감소 자체에서 오는지, resolution이 커질수록 attention 비중이 증가해서 커지는지 분리되지 않는다.
- **가설:** speed-up은 전체 token ratio보다 denoiser attention time fraction으로 더 잘 예측된다.
- **최소 실험:** 공개 환경이 가능한 GPU에서 두 resolution, 10 prompt, 3 seed에 preprocessing·VAE·DiT·decode 시간을 분해한다.
- **GO:** attention fraction으로 resolution별 speed-up 오차를 10% 이내 설명.
- **KILL:** I/O·VAE overhead가 대부분을 지배해 scaling law가 재현되지 않음.

**평가:** 실험 가치 4/5 · 재현성 3.5/5 · 신규성 5/5 · 실용성 2.5/5

## 5. Syn-Omni — 81-task omnimodal embedding evaluation code

**공식 근거:** [repository](https://github.com/sony/syn-omni) · [paper](https://arxiv.org/abs/2610.12256) · [3B model](https://huggingface.co/syn-omni-sony/syn-omni-3b) · [7B model](https://huggingface.co/syn-omni-sony/syn-omni-7b)

1. **새로 나온 내용**  
   Sony organization이 2026-10-07 repository를 공개했다. image·video·audio·audiovisual 81개 task evaluation과 5개 baseline script, OME-LoRA/PSR router code가 포함된다.

2. **논문·프로젝트 연결**  
   shared LoRA와 modality-specific expert LoRA를 분리하고 progressive routing으로 cross-modal collaboration을 제어하는 EMNLP 2026 Findings 연구다.

3. **코드 품질과 재현성**  
   Dockerfile, dataset mapping, per-modality YAML, baseline scripts가 있다. VLM2Vec·Tevatron 기반 modified fork라 upstream 지식이 필요하다. 별도 top-level CI·test suite는 확인되지 않았고 commit history는 초기 `init` 한 건이다.

4. **라이선스**  
   Apache-2.0이며 VLM2Vec의 동일 license를 따른다고 명시한다.

5. **pretrained weights/checkpoints**  
   Hugging Face에 3B/7B safetensors repository가 존재한다. 그러나 GitHub README는 아직 models “coming soon”이라고 쓰고 HF model card는 비어 있어 사용 계약·전처리·license 정합성을 먼저 확인해야 한다.

6. **설치 난이도와 의존성**  
   Docker가 권장되고 `--shm-size=128gb`, GPU mount, dataset/cache volume이 예시다. 로컬 설치는 별도 requirements와 `flash_attn==2.8.3`을 마지막에 설치해야 한다.

7. **GPU/VRAM 요구량**  
   3B/7B의 정확한 evaluation VRAM은 문서에서 보장하지 않는다. Docker 예시의 128GB shared memory는 GPU VRAM 수치가 아니므로 혼동하면 안 된다.

8. **바로 실험에 붙이기 좋은가**  
   전체 81-task 재현보다 image/audio 각 한 subset에서 embedding export와 latency를 확인하는 것이 현실적이다. 모델 카드 부재 때문에 즉시 production에 붙이기보다 eval harness 감사용으로 적합하다.

9. **framework 호환성**  
   Hugging Face checkpoint·dataset, VLM2Vec, Tevatron과 연결된다. MMDetection·Ultralytics·timm용 vision drop-in은 아니다.

10. **maintenance 가능성 / issue·PR 활동성**  
    Sony organization 공개라는 장점은 있지만 단일 초기 commit, release tag 부재, 비어 있는 model card 때문에 아직 판단 보류가 맞다.

**진단 → 가설 → 최소 실험**

- **진단:** full soft expert routing의 품질 이득이 runtime overhead를 정당화하는지 deployment 관점의 자료가 부족하다.
- **가설:** top-2 또는 folded adapter가 full routing 대비 retrieval 손실 0.5%p 이내에서 latency를 크게 줄인다.
- **최소 실험:** 3B checkpoint와 image/audio 각각 1개 dataset에서 full/top-1/top-2를 비교해 Hit@1·p95·peak VRAM을 측정한다.
- **GO:** Hit@1 손실 0.5%p 이하, p95 10% 이상 감소.
- **KILL:** absent-modality expert 제거 시 2%p 이상 손실되고 top-k가 회복하지 못함.

**평가:** 실험 가치 4/5 · 재현성 3/5 · 신규성 4.5/5 · 실용성 3/5

## 내 연구에 바로 연결되는 포인트

- **small/tiny object:** Roboflow reduced-mask 속도 이득을 APs·boundary F-score와 함께 측정해야 한다. 평균 mask metric만 보면 작은 선박·부표 손실을 놓친다.
- **temporal reasoning:** OccStress의 corruption timing과 BiGym의 fixed-seed episode replay는 video/VLA memory가 언제 실패하는지 분리하는 protocol로 재사용할 수 있다.
- **evidence-grounded VLM:** Syn-Omni의 modality expert contribution을 retrieval score뿐 아니라 routing latency와 absent-modality activation으로 감사할 수 있다.
- **compute-aware CV:** GRACE의 token 감소, Roboflow의 mask grid, Syn-Omni의 expert routing을 공통 `quality–latency–VRAM` Pareto 형식으로 비교하면 연구 자산이 된다.
