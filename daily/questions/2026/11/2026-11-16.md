## Q1. SAM pseudo-label의 class 혼동은 객체 난이도보다 필터 이후 식별자 손실로 얼마나 설명되는가?

**문제·Observation·왜 지금:** #27193은 앞 prompt의 mask가 제거될 때 뒤 polygon에 앞 class가 붙던 converter를 수정했다. maintainer 보고는 MobileSAM·CPU·bus 이미지의 두 box에서 class 대응이 회복됨을 보여준다. 전체 데이터의 오류율이나 downstream 성능은 입증하지 않았다. [공식 PR·재현](https://github.com/ultralytics/ultralytics/pull/27193) · [diff](https://github.com/ultralytics/ultralytics/pull/27193/files)

**Gap → Diagnosis → Mechanism:** 타당한 polygon에도 잘못된 semantic label이 붙을 수 있다. confidence 필터 뒤 mask 목록과 원 class 목록의 위치를 그대로 대응한 것이 직접 기전이다. 작은·가느다란 객체의 pseudo-label 열화를 모델 표현력 문제로만 해석하기 전에 이 경로를 분리해야 한다.

**Hypothesis·최소 개입:** 살아남은 prompt ID를 class와 함께 보존하면, 동일 mask geometry에서 입력 순서에 따른 class 전이가 사라질 것이다. 이를 tiny-object 전체의 오류 원인으로 확대하는 것은 아직 추론이다.

**MVP·baseline·dataset:** parent와 병합 commit `534f8d107636dfa7109229321e764d95c88c47fc`에서 공식 두-box 예시를 고정한다. prompt 순서, 앞/뒤/전체 mask 제거, 제거 없음 조건을 비교한다. 다음 단계는 class 정답이 있는 보유 UAV 이미지에서 같은 box와 mask를 저장해 converter만 재실행한다.

**Metric·GO/KILL:** prompt ID–polygon–class 불일치율, 누락률, 객체 크기별 class confusion을 측정한다. 원본의 순서 의존 오류가 단일 매핑 수정으로 사라지고 제거 없음 대조군이 유지되면 GO. 순서 교환 자체가 mask를 바꾸면 geometry 변화와 class 매핑을 분리한다. downstream mask 품질이 그대로라면 분할 능력 개선 주장은 KILL한다.

**기여·위험·기간·negative result:** 기대 기여는 pseudo-label의 geometry 실패와 semantic 전이를 분리하는 감사 프로토콜이다. 알려진 버그 재현만으로는 신규성이 낮다. 4~8주에는 다른 converter와 여러 장면에서 일반성을 확인해야 짧은 진단 논문 후보가 된다. 효과가 작아도 구조 변경 전에 제거할 annotation confound를 한정할 수 있다. Compute cost **1/5**: CPU부터 가능하며 전체 학습 비용은 미측정이다.

## Q2. 불균형 대응 ablation 중 무효 설정을 단일 batch의 loss·gradient 검사로 찾아낼 수 있는가?

**문제·Observation·왜 지금:** #27210에서 RT-DETR는 `cls_pw`의 weight를 계산·출력했지만 task loss가 사용하지 않았다. 수정은 사용하지 않는 계산·로그를 생략하며 class weighting을 새로 구현하지 않는다. 원문은 수정 전후 같은 loss를 보고한다. [공식 PR·재현](https://github.com/ultralytics/ultralytics/pull/27210) · [diff](https://github.com/ultralytics/ultralytics/pull/27210/files)

**Gap → Diagnosis → Mechanism:** 설정 수용과 로그 출력은 gradient 개입의 증거가 아니다. 공통 trainer에서 설정이 생성돼도 task 전용 loss가 소비하지 않을 수 있다. 이 상태로 rare-class 개선이 없다고 결론 내리면 기법의 실패와 구현의 무효성을 혼동한다.

**Hypothesis·최소 개입:** 동일 batch에서 설정값 변화에 대한 loss·분류 parameter gradient의 민감도를 검사하면 무효 ablation을 학습 전에 발견할 수 있다.

**MVP·baseline·dataset:** `rtdetr-l.yaml`, `coco8.yaml`, CPU, 동일 초기 state·batch·seed에서 `cls_pw=0`과 양수를 비교한다. parent와 병합 commit `8cec1d10b8c2b6f9767914d4bae7105235887d4d`를 고정한다. loss가 해당 설정을 실제 소비하는 detector를 코드 확인 후 양성 대조군으로 추가하고, batch에는 class 불균형을 명시한다.

**Metric·GO/KILL:** loss 항별 차이, gradient norm 차이·방향 유사도, 실제 weight 소비 경로를 기록한다. RT-DETR에서 무반응이고 양성 대조군이 반응하면 GO. 반응이 관측되면 별도 소비 경로·revision을 조사하고 무효 설정 가설을 KILL한다. 학습 모드·증강·stochastic layer를 통제한다.

**기여·위험·기간·negative result:** 기대 기여는 불균형 실험의 개입 유효성 검사다. 단일 batch 무반응은 모든 데이터에서 무효라는 증명이 아니며 포화·우연한 같은 weight도 대안 설명이다. 4~8주에는 여러 batch·trainer·loss로 확장해야 논문화 가능성이 생긴다. Negative result도 검사로 판정할 수 없는 조건을 알려준다. Compute cost **2/5**: CPU 단일 batch로 시작하며 실제 메모리·시간은 미측정이다.

## Q3. 시각적 domain shift로 보이는 오류 중 얼마가 예측 이후 색상 표현 경계에서 생기는가?

**문제·Observation·왜 지금:** #27196은 PIL Annotator 입력과 SAM3 semantic의 기존 tensor 후처리 경로에서 RGB/BGR 계약을 바로잡았다. maintainer 보고는 빨강·파랑 반전과 `orig_img` 불일치의 회복이다. 모델 mask 정확도 저하를 입증한 것은 아니다. [공식 PR·재현](https://github.com/ultralytics/ultralytics/pull/27196) · [diff](https://github.com/ultralytics/ultralytics/pull/27196/files)

**Gap → Diagnosis → Mechanism:** 입력 색상, 모델 prediction, 저장·표시 결과를 한 평가로 묶으면 색상 왜곡을 encoder의 domain robustness 실패로 오인할 수 있다. 직접 기전은 RGB 데이터가 BGR을 기대하는 결과 buffer에 들어가는 것이다.

**Hypothesis·최소 개입:** prediction을 고정한 색상 round-trip 검사는 모델 능력 변화 없이 생기는 결과 표현 오류를 분리할 것이다. 저장 이미지를 다시 추론에 넣을 때 task 성능에 미치는 영향은 별도 후속 가설이다.

**MVP·baseline·dataset:** 비대칭 red/blue chart와 공식 bus 이미지를 PIL·BGR NumPy·RGB tensor로 표현한다. parent와 병합 commit `23023be7e7a5abcfae0f4ef06ed66115f3ed8eb5`에서 Annotator 반환·저장 파일을 동일 decoder로 읽는다. SAM3는 해당 postprocess 경로를 분리 검증한 뒤 실제 predictor로 확장한다.

**Metric·GO/KILL:** pixel parity, 채널별 오차, 고정 prediction의 mask/box 동일성을 측정한다. 후처리 수정만으로 색상이 회복되고 prediction이 동일하면 표현 오류 진단은 GO, 모델 정확도 개선 주장은 KILL한다. JPEG 손실·dtype·alpha·색공간 차이는 대조군으로 분리한다.

**기여·위험·기간·negative result:** 기대 기여는 입력→prediction→시각화 단계별 오류 분해다. 기존 color-conversion 테스트의 재포장 위험이 높다. 4~8주에는 복수 wrapper·downstream 재입력에서 진단 가치가 반복돼야 논문 후보가 된다. 영향이 없으면 robustness 주장에 영향을 주지 않는 경계를 문서화한다. Compute cost **1/5**: chart 검사는 CPU 가능, SAM3 전체 실행의 8GB 적합성은 미확인이다.

## Q4. VLM grounding 점수의 저하는 위치추정 실패와 출력 계약 실패 중 어디에서 발생하는가?

**문제·Observation·왜 지금:** 공개 평가의 Qwen3-VL-235B grounding JSON은 100 expression·52 이미지에서 Acc@0.5 31%, 실패 53개를 보고한다. 이는 평가자 측정이며 독립 재현이 아니다. 방법론은 parsing 실패를 분모에 유지한다. [고정 결과 JSON](https://github.com/Tenkei/vlm-tasks/blob/ed61cdd1b1df4473d46a519b788ffd33f13bf481/benchmarks/runs/qwen3-vl-235b-bedrock-20261112/ground_box.json) · [고정 방법론](https://github.com/Tenkei/vlm-tasks/blob/ed61cdd1b1df4473d46a519b788ffd33f13bf481/benchmarks/methodology.md)

**Gap → Diagnosis → Mechanism:** 전체 점수에는 시각적 위치추정, schema 준수, abstention이 섞인다. parsing 오류만으로 원응답에 올바른 box가 있다고 가정할 수 없다.

**Hypothesis·최소 개입:** GT를 보지 않는 결정적 형식 정규화로 일부 실패가 회복된다면 출력 계약이 점수 저하의 일부를 설명할 것이다.

**MVP·baseline·dataset:** 고정 commit `ed61cdd1b1df4473d46a519b788ffd33f13bf481`의 저장 응답·manifest를 사용한다. 원 evaluator와 사전 정의한 정규화 후 evaluator를 같은 RefCOCOg UMD val 표본에서 비교한다. malformed JSON, schema mismatch, abstention, 유효하지만 틀린 box를 분리하며 새 모델 호출은 하지 않는다.

**Metric·GO/KILL:** 전체 분모의 Acc@0.5·0.75·0.9, 유효 출력률, abstention율, 기존 유효 출력 손상률을 기록한다. GT 없는 정규화가 실패를 줄이고 기존 유효 출력을 보존하면 GO. 위치 정보가 없거나 IoU가 계속 낮으면 parser 중심 가설을 KILL한다. cap 도달과 실제 truncation은 원문을 확인해 구분한다.

**기여·위험·기간·negative result:** 기대 기여는 grounding 오류의 단계별 분해다. 단순 관대한 parser로 점수를 올리거나 GT를 보고 복원하면 평가 타당성을 잃는다. 4~8주에는 다른 schema·모델·독립 표본에서 일반성이 필요하다. 효과가 없으면 위치추정·abstention이 후속 진단 대상임을 좁힌다. Compute cost **1/5**: 저장 응답 감사는 CPU 가능, 235B 재호출은 MVP에서 제외한다.

## Q5. 반복 이미지가 있는 소규모 grounding 평가에서 expression 단위 불확실성은 모델 차이를 과신하게 만드는가?

**문제·Observation·왜 지금:** 같은 공개는 source 순서의 첫 100개 eligible row를 사용하며 무작위 표본이 아니다. box와 point grounding은 같은 expression을 사용하고 여러 expression이 이미지를 공유한다. [표본·실패 정책](https://github.com/Tenkei/vlm-tasks/blob/ed61cdd1b1df4473d46a519b788ffd33f13bf481/benchmarks/methodology.md)

**Gap → Diagnosis → Mechanism:** 같은 이미지의 여러 질의는 시각적 난이도와 객체 배치를 공유한다. 이를 독립 표본으로 취급하면 불확실성이 작아질 가능성이 있다. 원 보고서가 부당한 유의성 주장을 했다는 뜻은 아니다.

**Hypothesis·최소 개입:** expression 단위와 이미지 cluster 단위 재표집의 구간이 달라지고, 일부 모델 차이의 해석이 표본 단위에 민감할 수 있다.

**MVP·baseline·dataset:** 같은 fingerprint의 저장 grounding 결과를 expression ID·image ID로 결합한다. 동일한 모델쌍의 paired 차이에 naive bootstrap과 image-cluster bootstrap을 적용한다. 각 이미지 내 expression을 함께 보존하며 이미지 수·expression 수를 모두 공개한다. 별도 source 순서 밖 표본은 후속 단계다.

**Metric·GO/KILL:** paired accuracy 차이의 구간 폭, 이미지별 오류 상관, leave-one-image-out 민감도를 기록한다. cluster 처리로 해석이 바뀌고 몇 이미지에만 의존하지 않으면 GO. 차이가 작으면 독립성 효과 가설을 축소한다. 어떤 재표집도 ordered prefix의 대표성 부족을 해결하지 못한다.

**기여·위험·기간·negative result:** 기대 기여는 작은 grounding 감사에서 표본 단위 선택의 실질 영향을 정량화하는 것이다. cluster bootstrap 자체는 알려진 통계 기법으로 신규성이 낮다. 4~8주에는 복수 평가·표본 크기·데이터 선택 정책에서 영향이 반복돼야 논문 가치가 있다. Negative result도 expression 단위 근사가 충분한 조건을 제시한다. Compute cost **1/5**: 저장 결과 기반 CPU 분석이다.

동일 checkpoint의 단일 수정 전후 비교를 우선한다. Q2의 서로 다른 detector, Q4·Q5의 local 2B와 hosted 235B는 **not strictly apples-to-apples**다. 모델·전처리·backend·하드웨어 차이가 있어 모델 크기의 인과효과로 해석하지 않는다. Q5의 재표집은 같은 저장 prediction에 대한 민감도 분석이며 새 성능 측정이 아니다. 서로 다른 VQA·grounding 표본의 평균 차이도 동일 사례의 Answer–Region Gap으로 부르지 않는다.

모든 /5 점수는 조사자의 우선순위 판단이며 실측치가 아니다. Compute efficiency는 높을수록 가볍게 검증하기 좋다는 뜻이며 compute cost와 방향이 반대다.

- **오늘 가장 먼저 테스트: Q1.** 공식 두-box 사례의 순서 교환과 살아남은 prompt ID 검사부터 진행한다.
- **RTX 5060 Ti 8GB에서도 시작 가능한 질문: Q1·Q3·Q4·Q5.** CPU 매핑·chart·저장 응답 분석으로 시작한다. 전체 모델 실행의 VRAM과 소요시간은 측정하지 않았다.
- **장기 박사주제: Q4 중심의 근거 신뢰성 진단.** 출력 계약을 먼저 통제한 뒤 같은 이미지·질문·region의 paired 평가와 증거 제거·교체 개입으로 확장한다. UAV·maritime 안전 판단으로의 전이는 별도 데이터 검증이 필요하다.
- **4~8주 계획:** 1~2주 기전·revision·데이터 계약 확인, 3~4주 복수 장면·구현 대조, 5~8주 일반성·실패 영역·negative result 정리. 알려진 수정의 재현만으로 논문 기여를 주장하지 않는다.

오늘의 변화는 새 architecture보다 label·설정·색상·출력 schema·표본 단위를 감사할 직접 근거가 생겼다는 점이다. 미해결 부분은 이 오류들이 실제 학습과 능력 평가의 결론을 얼마나 바꾸는지이며, 위 최소 실험은 그 기여를 분리하도록 설계했다.
