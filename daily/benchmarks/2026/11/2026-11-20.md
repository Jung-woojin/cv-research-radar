## 1. VLMEvalKit — judge 종료 경고와 실제 모델 교체를 구분한다

**확인 사실.** commit `ed3e918edf4a62e0bf42a2768655e02d45312fef`는 README, 경고 helper, 일반 judge 생성 경로, MEGABench judge 생성자와 테스트를 수정했다. 일반 경로는 별칭과 `LOCAL_LLM` override를 적용한 실제 `model_version`에 대해 경고한다. MEGABench 기본값은 여전히 `gpt-4o-2024-08-06`이다. 따라서 경고 추가를 judge 전환 완료나 새 평가 결과로 해석하면 안 된다. [공식 diff](https://github.com/open-compass/VLMEvalKit/commit/ed3e918edf4a62e0bf42a2768655e02d45312fef), [judge helper](https://github.com/open-compass/VLMEvalKit/blob/ed3e918edf4a62e0bf42a2768655e02d45312fef/vlmeval/dataset/utils/judge_util.py), [MEGABench 생성자](https://github.com/open-compass/VLMEvalKit/blob/ed3e918edf4a62e0bf42a2768655e02d45312fef/vlmeval/dataset/utils/megabench/scoring/vlm_as_judge.py).

**maintainer 설명.** 종료 영향을 받는 기본 judge를 종료 후 `gpt-6-luna`로 바꿀 예정이며 점수와 과거 결과의 비교 가능성이 달라질 수 있다고 안내한다. 이는 미래 계획이며 현재 교체의 실행 증거는 아니다. 추가 테스트도 warning과 override를 검사하고 MEGABench의 기존 모델 유지 여부를 확인한다. wrapper를 대체한 테스트가 실제 API 가용성이나 새 judge의 품질을 입증하지는 않는다. [공식 테스트](https://github.com/open-compass/VLMEvalKit/blob/ed3e918edf4a62e0bf42a2768655e02d45312fef/tests/test_judge_model_retirement.py).

**공급자 원문 대조.** OpenAI 종료 표에는 GPT-4o의 2024-08-06·2024-11-20, GPT-4o mini의 2024-07-18, GPT-4.1·mini의 2025-04-14 snapshot이 2027년 1월 14일 종료 예정이고 권장 대체 모델은 `gpt-6-luna`라고 명시되어 있다. 공지일은 2026년 10월 14일로, 이번 관측 창의 새 공지는 아니다. 공급자의 권장 대체 모델이 benchmark에서 채점 동등성을 보장하는 것은 아니다. [공식 종료 문서](https://developers.openai.com/api/docs/deprecations).

**별칭의 별도 위험·확인 사실.** 같은 코드에서 `gpt-4o`는 `gpt-4o-2024-05-13`으로 연결되고, 새 테스트는 이 별칭에서 종료 경고가 발생하지 않는다고 기대한다. 반면 공급자 공식 표는 해당 snapshot을 2026년 10월 23일 종료된 모델에 넣는다. 이번 경고 집합은 모든 종료 모델의 가용성을 검사하는 범용 검증기가 아니다. 실제 사용자 endpoint나 프록시에서의 동작은 호출하지 않아 미확인이다. [별칭 매핑](https://github.com/open-compass/VLMEvalKit/blob/ed3e918edf4a62e0bf42a2768655e02d45312fef/vlmeval/dataset/utils/judge_util.py), [공급자 종료 이력](https://developers.openai.com/api/docs/deprecations).

**관측 → 진단 → 기전·추론.** 응답을 생성하는 VLM을 고정해도 judge 변경으로 최종 score가 달라질 수 있다. 경고만 기록하고 실제 resolved model·prompt·cache를 기록하지 않으면, 평가자 교체 효과가 모델 능력의 시계열 변화로 섞인다. 경고가 없더라도 별칭·override·endpoint를 감사해야 한다.

**가설 → 최소 개입 → 실험 제안.** 먼저 API 호출 없이 평가 설정을 열거해 요청 별칭, resolved snapshot, override 적용 여부, evaluator commit, judge prompt hash와 cache 구분을 표로 만든다. 이어 보존된 동일 응답을 사용해 기존 judge 결과와 새 judge 결과의 paired 비교를 설계한다. 기존 judge를 더 이상 호출할 수 없고 보존 결과도 없으면, 그 부분은 전환 전후 인과 비교 불가로 남긴다. 새 judge 내부 반복 분산과 인간 감사도 따로 측정한다.

**GO/KILL.** 유효한 paired 기록이 있으면 label 전환율·평균 점수 차·반복 분산·실패 응답 비율을 보고한다. 과거 기록이 없으면 새 protocol baseline만 만들고 개선량을 주장하지 않는다. 이 실행에서는 새 유료 judge 호출을 하지 않았다.

**비교 판정.** judge·prompt·cache 정책이 다른 점수는 **not strictly apples-to-apples**다. 이 commit에서 dataset split·backbone·pretraining·input resolution·TTA가 바뀌었다는 근거도 없다.

## 2. ARC-AGI — 마지막 grid 수정은 유효하지만 공식 parser와 완전히 같지는 않다

**확인 사실.** lmms-eval commit `a6982d978d88f39fca83c5d7845672817bcaddf3`는 ARC-AGI-1·2에서 code fence 우선 탐색을 제거하고 grid 후보를 역순 탐색한다. ARC-AGI-2는 추가 bracket 후보도 역순으로 본다. 전체 문자열 파싱을 먼저 시도하는 경로는 유지한다. 정답과 추출 grid가 같으면 1, 아니면 0이라는 exact-grid 채점 구조는 유지된다. [공식 diff](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/a6982d978d88f39fca83c5d7845672817bcaddf3), [ARC-AGI-2 전체 구현](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/a6982d978d88f39fca83c5d7845672817bcaddf3/lmms_eval/tasks/arc_agi_2/utils.py).

**maintainer 설명과 테스트.** 응답이 입력 grid나 첫 시도를 인용한 뒤 최종 답을 쓰면 이전 parser가 앞쪽 grid를 채점하던 문제를 설명한다. fixture는 입력 인용·fenced 입력/출력·수정 답·boxed grid 등을 검사한다. 이는 실제 모델에서 해당 오류가 얼마나 발생했는지 보여주는 자료가 아니다. [공식 회귀 테스트](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/a6982d978d88f39fca83c5d7845672817bcaddf3/test/tasks/test_arc_agi.py).

**공식 harness 교차검증·중요 제한.** ARC Prize 저장소의 확인한 main commit은 `78f2d3eacb86587d1438ab14f08fb56811eb1f1c`다. `parse_and_validate_json`은 `extract_from_boxed`를 먼저 실행하고 실패하면 `backscan_json_parser`를 실행한다. boxed helper는 첫 regex match를 사용한다. 따라서 “boxed 답 A 뒤에 다른 grid B”라는 응답에서 공식 orchestrator와 lmms-eval의 선택이 달라질 수 있다는 정적 추론이 성립한다. 공식 backward parser도 마지막 닫는 괄호에서 후보 하나를 구성하므로, 뒤의 잘못된 후보를 건너뛰어 앞선 유효 grid를 찾는 lmms-eval과 모든 경계 조건에서 같지 않다. maintainer의 “official harness처럼 마지막 grid”는 일반적 의도를 설명하지만 완전한 구현 동등성은 아니다. [고정 공식 parser](https://github.com/arcprize/arc-agi-benchmarking/blob/78f2d3eacb86587d1438ab14f08fb56811eb1f1c/src/arc_agi_benchmarking/utils/parsing.py).

**split·입력·예산 확인.** ARC-AGI-1은 `mertaylin/arc-agi-images`의 `eval`, ARC-AGI-2는 `vincentkoc/arc-agi-2`의 `evaluation`을 사용한다. 두 template은 temperature 0, 최대 1024 new tokens이며 dataset revision은 고정되지 않는다. ARC-AGI-2 prompt는 이미지뿐 아니라 test input의 text grid도 제공하고 첫 test input/output을 사용한다. 따라서 이를 순수 이미지 추론 또는 공식 전체 task 평가와 자동으로 동일시할 수 없다. 공식 scorer는 task의 test pair들과 그 attempt들을 순회하고 pair별 정답 존재 여부를 집계한다. [AGI-1 설정](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/a6982d978d88f39fca83c5d7845672817bcaddf3/lmms_eval/tasks/arc_agi_1/_default_template_yaml), [AGI-1 split](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/a6982d978d88f39fca83c5d7845672817bcaddf3/lmms_eval/tasks/arc_agi_1/arc_agi_1.yaml), [AGI-2 설정](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/a6982d978d88f39fca83c5d7845672817bcaddf3/lmms_eval/tasks/arc_agi_2/_default_template_yaml), [AGI-2 split](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/a6982d978d88f39fca83c5d7845672817bcaddf3/lmms_eval/tasks/arc_agi_2/arc_agi_2.yaml), [공식 scorer](https://github.com/arcprize/arc-agi-benchmarking/blob/78f2d3eacb86587d1438ab14f08fb56811eb1f1c/src/arc_agi_benchmarking/scoring/scoring.py).

**관측 → 진단 → 기전·추론.** 앞쪽 입력 복사를 채점하면 추론 실패와 답 추출 실패가 섞인다. 역순 탐색은 이를 줄일 수 있지만 뒤에 붙은 예시·비교용 grid를 고르는 새 오수락 가능성도 있다. boxed 우선순위와 test pair·attempt 집계 차이는 parser 하나를 고쳐도 남는다.

**가설 → 최소 개입 → 실험 제안.** 동일 sample ID·정답·원응답을 parent `e08b1736db47064d358aca2812724d3aeeee69ae`, 수정 commit, 위 공식 parser에 넣는다. 입력 인용, 수정 답, boxed 답 뒤 grid, 복수 boxed, 뒤쪽 잘못된 JSON, grid 없음을 따로 분류한다. 전체 분모·parse 실패율·정오답 전환표·추출 grid 불일치율을 기록하고 불일치는 사람이 최종 의도를 감사한다. 공식 parser의 예외도 명시적으로 집계한다. 공식 task score와 비교할 때는 test pair 수·attempt 수·집계 단위부터 맞춘다.

**GO/KILL.** 입력 복사 오채점만 복구되면 evaluator 복구로 보고한다. 부가 grid 오수락이 있으면 응답 계약 또는 추출 규칙을 별도 검토한다. 보유 응답에서 변화가 없으면 영향 없음으로 종료한다. 본 실행은 이 fixture나 실제 응답 재채점을 실행하지 않았다.

**비교 판정.** 동일 저장 응답의 paired 재채점은 parser 효과를 분리할 수 있다. 수정 전후 accuracy를 새 모델의 시각 추론 향상으로 해석하거나 커뮤니티 이미지 adapter 점수를 공식 순위와 합치는 것은 **not strictly apples-to-apples**다.

## 오늘의 benchmark signal 3개

1. **judge의 수명도 평가 버전이다.** 종료 경고, 실제 snapshot, 교체 계획과 교체 후 score를 각각 기록한다.
2. **최종 답 추출 규칙을 공개해야 한다.** 첫 grid·마지막 grid·boxed 우선은 서로 다른 metric 구현이다.
3. **공식 호환 문구보다 전체 경로를 대조한다.** parser뿐 아니라 별칭, test pair, attempt, cache와 집계 단위를 확인한다.

## 내 연구에 바로 연결되는 포인트

- **오늘 먼저:** 저장된 ARC 응답을 세 parser로 감사한다. 변화량이 없으면 그대로 남기고 모델 추론을 추가하지 않는다.
- **Answer–Region Gap·evidence-grounded VQA:** 답 추출 복구와 올바른 영역 증거 사용을 별도 평가한다. 답이 맞아졌다는 사실만으로 grounding이 좋아졌다고 하지 않는다.
- **CCTV·해양 안전 VQA:** judge 교체 전후의 원응답·증거 이미지·rubric·resolved snapshot을 함께 보존한다. 가능하면 객체 존재·개수 같은 결정적 검사를 judge 판정과 나란히 둔다.
- **small/tiny object·P2·UAV:** 오늘 수정은 작은 객체 AP나 고해상도 feature의 개선 근거가 아니다. 크기별 localization 실험과 연결하려면 별도 annotation·metric이 필요하다.
- **RTX 5060 Ti 8GB:** 저장 응답 parser 비교와 설정 감사는 대형 모델 없이 가능하다. 외부 judge나 새 VLM의 8GB 실행 가능성을 확인한 것은 아니다.

모든 최소 실험은 후속 제안이며, 본 보고서는 새로운 benchmark 점수나 테스트 통과를 주장하지 않는다.
