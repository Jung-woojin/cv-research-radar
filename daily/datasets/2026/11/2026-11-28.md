## 1. AgriUnion — 배포 형식 변경에서 split과 표본 대응을 먼저 복원한다

**확인 사실·신규성.** HF revision `a27c6ac8d180d6bce7d5e6b6908e542faa6dbc60`은 11/26 20:40:54 UTC 카드 업로드이며, 실제 dataset 업로드는 직전 `84c2a80b922b777adec210050b834bcf1d472c9e`다. 고정 tree에는 `train-00000-of-00028.parquet`부터 28개 shard가 있다. 원본 Zenodo는 6/14 공개 Version 1.0이므로 신규 수집 release로 세지 않는다. [고정 카드](https://huggingface.co/datasets/InriaXagriscienceFM/multi_crop_incl_vege_agriunion_uav_tiny_object_detection/blob/a27c6ac8d180d6bce7d5e6b6908e542faa6dbc60/README.md) · [원본](https://zenodo.org/records/20688284)

**규모·task·split·license.** 원본 배포자는 UAV tiny-object detection용 8,864장·317,704 bbox·29종·7:2:1 stratified split과 small instance 74.4%를 보고한다. HF 카드는 원본 설명과 함께 변환본 7,973장·286,012 bbox를 기재한다. YAML의 공개 split은 `train` 하나이고, 원래 split은 별도 `split` 열에 보존했다고 설명한다. 원본과 변환본 모두 CC BY 4.0을 명시한다. 이 숫자는 파일 전수 재집계 결과가 아니다.

**직접 확인한 제한.** 공식 viewer statistics 응답은 `num_examples=3135`, `partial=true`이고 해당 부분의 `split` 빈도는 `train:3135`였다. 이것으로 전체 7,973행이 모두 원본 train이라고 결론 내릴 수 없다. 누락된 891장의 정체나 제외 사유도 확인하지 못했다. [통계 API](https://datasets-server.huggingface.co/statistics?dataset=InriaXagriscienceFM%2Fmulti_crop_incl_vege_agriunion_uav_tiny_object_detection&config=default&split=train)

**Label·bias·호환성.** 공개 schema는 bbox 배열과 29개 class label을 포함한다. `Corn`과 `crop: zea mays`, `Waterhemp`와 `weed: amaranthus tuberculatus`처럼 의미가 겹쳐 보이는 이름이 있다. 이는 source별 taxonomy의 차이일 수 있으며 오주석으로 확정하지 않는다. multi-source·촬영 고도·해상도·농장 차이가 class와 결합할 수 있다. bbox의 좌표 단위·형식과 resizing 후 small-object 기준을 별도 확인해야 한다. HF 형식을 원본 YOLO와 곧바로 동일 취급하면 안 된다.

**진단 → 가설 → 최소 실험.** loader의 외부 `train`만 보고 전량 학습하거나 임의 재분할하면 원래 평가 membership을 잃을 수 있다는 **추론**이다. 먼저 이미지 원본 경로·hash·source·원래 split·class mapping을 가진 대응표를 만든다. 28 shard의 `split`·class별 행/box 수를 전수 집계하고 Zenodo manifest와 left join해 누락·중복을 분리한다. 이어 원본 YOLO box와 변환 bbox를 동일 이미지에 겹쳐 좌표·category를 검사한다. taxonomy 통합은 원래 29종 평가를 보존한 별도 ablation으로 수행한다.

**GO/KILL.** 대응표·좌표 검사는 GO. 누락 사유와 test membership을 모른 채 새 random split 점수를 원본 benchmark 개선으로 주장하는 것은 KILL. 원본과 변환본의 직접 점수 비교는 현재 **not strictly apples-to-apples**다.

## 2. PanoRadar — processed 추가와 새 annotation을 구분한다

**규모·task·정책 — 배포자 보고.** 카드는 12개 실내 건물, RF/LiDAR 동기 표본 11,033개, object instance 20,546개, processed 약 461 GB와 CC BY 4.0을 명시한다. task는 RF depth·normal·segmentation·detection이다. machine-assisted labeling과 human correction을 설명하지만 이번 업로드가 label correction이라는 근거는 없다. [고정 카드](https://huggingface.co/datasets/pennwaveslab/PanoRadar-Dataset/blob/1ef0cd0e4a2f6a7d2a61deaa43c2a3012b2ef8ad/README.md)

**교차검증·bias·호환성.** 공식 코드 README는 2024년 initial release, raw/processed 구분, 건물 단위 LOBO 평가를 설명한다. 따라서 오늘 신호는 HF processed 배포 확대이며 새 데이터셋 탄생이 아니다. 같은 trajectory의 moving/static·extra 자료를 별도 archive라는 이유로 다른 split에 배치하면 안 된다. LiDAR 기반 GT는 유리 등 투명 표면에서 불완전할 수 있어 glass mask의 평가 정책을 고정해야 한다. GitHub 코드의 BSD-3-Clause와 HF 데이터의 CC BY 4.0을 구분한다. [공식 코드·평가 설명](https://github.com/penn-waves-lab/PanoRadar)

**진단 → 가설 → 최소 실험.** archive 경계로 random split을 만들면 동일 건물·trajectory 정보가 공유돼 일반화 성능이 부풀 수 있다는 **추론**이다. ZIP 내부 manifest에서 building·trajectory·frame ID를 복원하고 `part1/part2`와 `_extra`를 동일 group에 연결한다. 기존 Box 배포본과 대응 frame의 heatmap·label hash를 비교한 뒤, 같은 LOBO membership과 frozen prediction으로 evaluator만 재실행한다. glass 포함/제외 성적은 분리한다. RF-only와 GT LiDAR 입력 조건도 구분한다.

**GO/KILL.** archive·split manifest 검사는 GO. hash 대조 없이 annotation 개선으로 부르거나 LiDAR 입력 결과를 RF-only 결과와 비교하는 것은 KILL. archive 다운로드·내부 hash·모델 평가는 미실행이다.

## 3. ComboBench — 경로 이동과 공개 coverage를 평가 조건에 넣는다

**확인 사실·시점.** revision `b92133bc5171335a63bfde5665855a59f441230e`의 root에는 `KITTI`만 있고, 그 아래 `sev3`와 `sev5+`를 확인했다. 최근 이력은 “Move sev5+ to KITTI/sev5+”라는 여러 batch 이동이다. 이것으로 label 수정·새 표본 수·파일 내용 불변까지 확정하지 않는다. [고정 tree](https://huggingface.co/datasets/linchunmian/ComboBench/tree/b92133bc5171335a63bfde5665855a59f441230e) · [고정 카드](https://huggingface.co/datasets/linchunmian/ComboBench/blob/b92133bc5171335a63bfde5665855a59f441230e/README.md)

**Task·규모·split·license.** 카드는 KITTI/nuScenes의 camera–LiDAR compositional corruption과 severity 3·5+를 설명한다. severity는 perturbation 개수가 아니라 강도다. training/validation만 포함하고 공식 test는 제외하며, clean annotation·calibration·metadata를 원본에서 연결하도록 안내한다. 전체 공개 frame 수는 확인하지 못했다. HF root에서 nuScenes artifact는 확인되지 않았고, 카드에는 독립적인 데이터 license가 명시되지 않아 원본 KITTI/nuScenes 조건과 파생물 허가를 별도 확인해야 한다.

**공개 상태·bias·호환성.** 공식 project repository는 paper PDF가 아직 공개되지 않았다고 설명하며 별도 구현 저장소를 연결한다. 카드의 framework 범위를 현재 다운로드 가능한 coverage와 구분한다. corruption composition과 severity별 표본 구성 차이, 같은 clean frame의 여러 corrupted view는 독립 표본이 아니다. [공식 resource status](https://github.com/buaa-linx/ComboBench)

**진단 → 가설 → 최소 실험.** 옛 경로를 쓰는 loader가 일부 composition을 놓치거나 clean 데이터로 fallback하면 평균 robustness가 달라질 수 있다는 **추론**이다. `(source frame ID, composition, severity, modality)` manifest와 expected-path 검사를 만든다. 누락 경로는 즉시 오류로 처리하고 clean fallback을 금지한다. 이동 전후 대응 파일 hash·annotation/calibration ID와 split membership을 비교한다. 이후 동일 checkpoint·예측·evaluator로 경로 변경 전후 결과가 같은지 검사한다.

**GO/KILL.** 경로·coverage audit는 GO. nuScenes 공개를 가정한 통합 평균이나 severity 5+를 “5개 이상 corruption”으로 읽는 것은 KILL. 전체 파일 수·hash 불변성과 benchmark 성능은 미검증이다.

## 오늘의 실행 우선순위와 한계

1. **첫 GO:** AgriUnion 원본↔HF ID/split/class 대응표. 원본 평가 집합을 보존할 수 없으면 성능 비교를 보류한다.
2. **다음 GO:** PanoRadar building/trajectory grouping과 processed↔기존 배포본 대응 확인.
3. **조건부 GO:** ComboBench 경로 manifest와 누락 시 fail-fast 검사. 실제 공개 coverage와 권리가 확인된 범위에서만 평가한다.
4. **공통 KILL:** metadata의 `train` 이름, ZIP 경계, 카드의 총괄 설명만으로 학습·평가 membership을 결정하지 않는다.

이번 실행은 원문·API·tree 비교와 부분 viewer 통계 확인까지 수행했다. 실제 leakage, near-duplicate, class imbalance 비율과 annotation 오류율은 측정하지 않았다. 모델·학습·대용량 archive 다운로드도 수행하지 않았다. 성능 비교에는 backbone, data, split, resolution, pretraining, hardware, precision, batch, TTA와 evaluator를 고정해야 한다. 근거 원문과 조회 결과는 로컬 evidence에 보존했다.
