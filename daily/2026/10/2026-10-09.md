## 1. 오늘의 전체 DL 트렌드 5줄

1. **사실:** 장기 비디오 이해는 프레임 수 증대보다 메모리에 무엇을 남기고 어떻게 되찾는지가 핵심 병목으로 이동하고 있다.
2. **사실:** 3D·로보틱스 계열은 외형 복원에서 물리 관계, 객체 지속성, 접촉 신호로 감독 범위를 넓힌다.
3. **저자 주장:** 작은 ViT에서는 Attention과 FFN의 고정 분리가 오히려 제한된 파라미터 배분을 방해할 수 있다.
4. **추론:** 평가 축도 정확도 단독에서 에너지, 지연, 장기 기억 coverage, 실패 탐지까지 넓어져야 한다.
5. **전망:** 모델 크기 경쟁보다 표현·검색·검증 계층을 분리하고 각 병목을 측정하는 연구가 실용 시스템에서 더 빨리 성과를 낼 가능성이 높다.

## 2. CV / DL-CV 핵심 7선

### 2.1 Tetris3D — 객체가 “같이 맞물리는” 단일 이미지 3D 장면 생성
- **상태:** arXiv:2610.10539 v1, 2026-10-07 제출.
- **문제/차별점:** 객체를 독립적으로 만든 뒤 배치하면 접촉부 관통·부유·자세 불일치가 생긴다. Tetris3D는 주변 표면의 거리·방향·법선과 stack/lean/contain/touch/none 관계를 voxel-aligned condition으로 넣고, VLM이 추론한 물리 의존 그래프의 위상 순서대로 객체를 생성한다.
- **데이터:** 저자는 물리 시뮬레이션 기반 ComOb 120만 장면, 340만 annotated sample을 구축했다고 보고한다.
- **결과:** Toys4K 표에서 저자 보고 기준 물리 안정성과 생성 품질 전반이 비교군보다 높다. 예를 들어 penetration depth는 0.0551로, 표의 WorldSculpt 0.1177보다 낮다.
- **재현성/비용:** [프로젝트](https://cvlab-kaist.github.io/Tetris3D/)는 공개됐지만 대규모 데이터 생성과 TRELLIS.2 기반 학습 비용이 진입 장벽이다.
- **주의:** 실제 성능은 VLM 관계 추론, depth, instance mask 오류가 연쇄적으로 누적될 수 있다. synthetic interaction 분포가 실제 복잡한 접촉을 얼마나 덮는지도 미확인이다.
- **우리 연결:** 해상 장면이나 로봇 조작에서 “객체별 정확도”와 “장면 물리 일관성”을 분리 측정할 근거가 된다.
- **최소 실험:** 공개 예제 30장에 관계 입력을 정답/오류/제거 3조건으로 바꾸고 penetration depth·평균 변위·관계 보존율을 비교한다.

### 2.2 Never Look Back (Ledger) — 원본 영상을 다시 읽지 않는 영속 3D 객체 메모리
- **상태:** arXiv:2610.10538 v1, 2026-10-07 제출; [프로젝트](https://ledger-3d.github.io/).
- **문제/차별점:** 긴 egocentric video를 질의 때마다 재탐색하는 대신 객체 중심 3D ledger를 지속 갱신한다.
- **저자 보고:** HD-EPIC에서 GPT-5.4 reader의 blind 29.7%가 Ledger 사용 시 42.6%로 상승했고, UCS-Bench에서는 48프레임+Ledger 46.3% 대 DirectMe graph 42.9%였다. Ego4D VQ3D의 답변된 질의에서 median localization error는 0.99m였다.
- **평가 범위:** HD-EPIC 2,400문항, Ego4D VQ3D validation 164문항, UCS-Bench 2,771문항.
- **주의:** reader와 프로토콜이 다른 수치를 직접 비교하면 안 된다. memory construction은 offline이고, 장면 변화·미탐 객체는 ledger coverage를 무너뜨린다.
- **진단:** 장기 비디오 QA의 실패 원인을 reasoning 이전의 “기억에 증거가 존재하는가”로 분해한다.
- **최소 실험:** 10개 실내 영상에서 객체 recall, query latency, 3D 위치 오차를 프레임 재검색 방식과 비교하고, 장면 변화 전후를 별도 집계한다.

### 2.3 MOTIP2 — ID swap보다 공간적으로 가능한 교란이 추적기를 더 잘 훈련한다
- **상태:** arXiv:2610.10391 v1, BMVC 2026 accepted.
- **차별점:** 추적 학습의 ID corruption을 무작위 swap 대신 GIoU 기반 spatial corruption으로 바꾼다.
- **저자 보고:** PersonPath22에서 uniform ID swap은 long-range non-overlap이 94%였고 HOTA 56.1로, augmentation 없는 59.5보다 낮았다. GIoU corruption은 long-range 비율 31%, HOTA 61.6이었다.
- **해석:** 너무 쉬운 비현실적 음성 샘플은 association을 강화하기보다 shortcut을 가르친다.
- **주의:** 같은 위치에서 동시 출입하는 사람처럼 proximity prior가 무너지는 경우는 여전히 취약하다.
- **최소 실험:** 현재 MOT baseline에 두 corruption을 같은 횟수로 넣고 HOTA/IDF1뿐 아니라 occlusion 길이별 ID switch를 비교한다.

### 2.4 One-Shot Adaptive Segmentation — 한 장의 주석으로 scientific image domain 적응
- **상태:** arXiv:2610.10306 v1.
- **방법:** DINOv3 feature에서 한 장의 annotated reference로 background direction을 추정해 직교화한다.
- **저자 보고:** pool-boiling에서 최강 baseline 대비 mIoU 상대 개선 78.62%를 보고했다. chest radiograph에서는 0.3960으로 SAM2 0.3962와 사실상 동률이다.
- **주의:** pool-boiling 평가는 20프레임에 불과하고 reference 선택 민감도가 충분히 보고되지 않았다.
- **추론:** 강한 사전학습 표현의 “배경 성분 제거”가 소규모 도메인 적응의 값싼 출발점이 될 수 있다.
- **최소 실험:** reference 10장을 하나씩 교체해 평균·표준편차·최악 mIoU를 보고하고, 단순 prototype subtraction과 비교한다.

### 2.5 uViT / AttenFeed — 작은 ViT에서 Attention–FFN 분리 재검토
- **상태:** arXiv:2610.10303 v1.
- **방법:** Attention과 FFN의 기능을 하나의 AttenFeed로 통합하고, 파라미터 수를 맞춘 uViT를 대조군으로 사용한다.
- **저자 보고:** ImageNet-1K에서 ViT-S 53.64% 대 uViT-S 67.11%, Places365 44.63% 대 50.25%, iNaturalist 52.82% 대 66.81%였다. Large scale에서는 ImageNet-1K 77.33% 대 77.18%로 이점이 사라졌다.
- **해석:** 핵심은 “FFN 불필요”가 아니라 작은 예산에서 고정 역할 배분의 비용이다.
- **주의:** 아키텍처 폭·깊이가 달라 wall-clock, memory, throughput 공정성은 별도 검증이 필요하다. 저자도 일부 Large 실험의 수렴 불안정성을 기록했다.
- **최소 실험:** 동일 파라미터·동일 GPU시간 조건에서 small model의 accuracy, images/s, peak memory를 함께 측정한다.

### 2.6 SAPI — 세포 분할을 정확도·에너지·크기로 함께 평가
- **상태:** arXiv:2610.10324 v1; [코드](https://github.com/eiram-mahera/sapi), [CellBinDB](https://doi.org/10.5281/zenodo.15370205).
- **범위:** CellBinDB 6 modality, 1,044 images, 102,480 instances에서 zero-shot 19개와 few-shot 16개 모델을 비교한다.
- **저자 보고:** PathoSAM ViT-B는 performance 0.675, 104.8M params, 164.15J/image; ViT-H는 0.680, 652.1M, 342.71J/image였다. InstanSeg가 4개 dataset에서 zero-shot SAPI 최고였다.
- **주의:** Tesla V100 NVML과 CPU/DRAM RAPL 조건이며 냉각·스토리지·네트워크·사전학습 에너지는 빠진다. composite score의 가중치에 순위가 민감하다.
- **우리 연결:** 모델 선택표에 성능과 함께 joule/image, peak memory, wall time을 고정 열로 추가할 근거다.
- **최소 실험:** 같은 100장 subset을 V100 또는 보유 GPU에서 5회 반복해 median J/image와 변동폭을 재측정한다.

### 2.7 Temporal Residual Bottleneck — 비동기 협업 지각의 진짜 병목은 hard ROI mask
- **상태:** arXiv:2610.10090 v1.
- **진단:** CoBEVFlow 계열 파이프라인에서 flow warp보다 ROI 밖 문맥을 지우는 hard mask가 성능 저하의 주원인인지 검증했다.
- **저자 보고:** DAIR-V2X AP@0.7에서 공개 hard-mask 경로 0.597, mask 제거·identity warp·background-preserving ROI blend가 모두 0.611이었다.
- **해석:** motion alignment 개선 전에 문맥 보존 여부를 확인해야 한다.
- **주의:** 한 파이프라인과 dataset의 진단이므로 모든 collaborative perception으로 일반화할 수 없다.
- **최소 실험:** 현 코드에서 warp는 고정하고 mask만 none/hard/soft 세 조건으로 바꿔 AP·통신량·지연을 비교한다.

## 3. VLM / Multimodal / Video 핵심 4선

### 3.1 VideoEvolve — 기억과 검색을 번갈아 공동 진화
- **상태:** arXiv:2610.10183 v1.
- **방법:** 낮은 frame-rate base memory 위에 selective delta를 만드는 Memory Evolver와 adaptive retrieval을 하는 Retrieval Evolver를 alternating agentic RL로 학습한다.
- **저자 보고:** VideoEvolve-8B는 Video-MME(with subtitles) 73.9, LongVideoBench 70.2, LVBench 58.9, MLVU 72.4, MMVU 75.1이었다. base/no-evolution은 각각 66.8, 62.1, 50.3, 64.7, 67.5였다.
- **강한 ablation:** learned augmentation은 LongVideoBench 70.2로 base memory 64.1보다 높았고, cold-start SFT 제거 시 LVBench가 58.9에서 32.8로 하락했다.
- **주의:** 문헌 baseline은 backbone·frame budget·subtitle protocol이 통일되지 않았다. offline multiple-choice 중심이며 streaming, open-ended dialogue, direct audio는 검증하지 않았다.
- **최소 실험:** 동일 Writer/Reader를 고정하고 uniform·random·learned augmentation을 같은 frame budget으로 비교한다.

### 3.2 Beyond Anonymous Captions — 얼굴 상자와 텍스트 좌표를 결합한 인물 정체성 grounding
- **상태:** arXiv:2610.10163 v1.
- **데이터:** LSMDC v2 기반 수동 검수 750 caption clips, 3,000 person-centric questions.
- **저자 보고:** Qwen3-VL-8B에서 face visual box+face textual coordinate(FVB+FTC)는 Named 88.04%, UNIDENTIFIED 86.93%로 균형이 가장 좋았다. 2B에서는 같은 설정이 Named 92.48%, UNIDENTIFIED 16.09%여서 작은 모델의 과도한 이름 강제가 드러났다.
- **해석:** grounding 신호가 있어도 “모름”을 유지하는 능력은 모델 규모와 별도 calibration 문제다.
- **주의:** 배우 reference image와 영화 얼굴 중심이라 일반 영상·가림·유사 외모로의 전이는 미확인이다.
- **최소 실험:** 얼굴 crop 품질과 unknown threshold를 교차해 identity accuracy와 false naming rate를 함께 그린다.

### 3.3 HeiCo-FOCUS — 96시간 수술 영상에서 장기 임상 비디오 이해를 분해
- **상태:** arXiv:2610.10156 v1; [코드](https://github.com/IMSY-DKFZ/orena-focus).
- **범위:** colorectal surgery 96시간, 약 30k VQA, 5개 track, sigmoid resection held-out.
- **저자 보고:** 10개 frontier VLM 중 약 절반만 text-only를 넘었고, 평균 event/procedural 56.5%, temporal grounding 19.7%였다.
- **주의:** human reference도 20문항씩만 평가돼 event aggregation 35%, duration 40%였다. 데이터 공개 상태와 환자 프라이버시 조건을 확인해야 한다.
- **진단:** 긴 영상의 병목이 지식 부족보다 temporal evidence retrieval일 가능성이 크다.
- **최소 실험:** answer model을 고정하고 oracle timestamp, sparse retrieval, uniform sampling을 비교한다.

### 3.4 TouchScale — 촉각을 대규모 사람 데이터에서 로봇으로 연결
- **상태:** arXiv:2610.10288 v1.
- **데이터:** 약 500시간, 87k episodes, 2k task descriptions, 1,500+ objects, 약 20명; RGB-D·wrist·tactile 포함.
- **저자 보고:** 통제된 cross-dataset 표에서 EgoTouch→TouchScale 사전학습은 EgoTactile contact IoU 0.134→0.181, value IoU 0.185→0.243, CoP error 0.444→0.416, pressure error 0.184→0.148이었다.
- **주의:** abstract의 0.134→0.383은 다른 설정이므로 통제 표와 혼합하지 않았다. 로봇 평가는 1개 platform·4개 task이며 공개 범위도 확인이 필요하다.
- **최소 실험:** 동일 backbone으로 RGB-only/RGB+depth/RGB+depth+tactile을 비교하고 contact IoU와 calibration error를 보고한다.

## 4. LLM / Agent / Reasoning / System 핵심 2선

### 4.1 RECAST — 검색할지, 계산할지, 도구를 합성할지 학습하는 evidence router
- **상태:** arXiv:2610.10507 v1.
- **방법:** 작은 RouterLM이 lexical/semantic/SQL primitive, synthesized Python, accept-context 중 하나를 선택한다. CompilerLM과 AnswerLM은 고정하고 Router만 SFT+GRPO한다.
- **저자 보고:** 6개 benchmark 평균 75.6%로 최강 대형 baseline 59.7%보다 15.9%p 높았고, held-out 3개 평균 79.3% 대 64.3%였다. 총 token도 Gemini Interact-RAG보다 27.9% 적었다.
- **주의:** 공통 AnswerLM과 judge가 Gemini 3.5 Flash라 self-family bias 가능성이 있고, 각 benchmark 100문항·최대 6 rounds다. 코드 실행 sandbox와 data access control이 필수다.
- **우리 연결:** 연구 레이더의 “검색→표 계산→근거 수락”을 명시적 상태 머신으로 만들 수 있다.
- **최소 실험:** 동일 질문 50개에서 fixed top-k RAG와 route-based SQL/Python을 정확도·token·latency·execution failure로 비교한다.

### 4.2 Loud Failures, Quiet Failures — 에이전트는 오류 메시지보다 그럴듯한 오답을 놓친다
- **상태:** arXiv:2610.10062 v1.
- **설계:** 24개 multi-step task, 6개 모델, 1,920 trials에 timeout·missing tool·schema drift·silent corruption을 주입했다.
- **저자 보고:** 명시적 오류 탐지 91.3%, plausible wrong value 탐지 58.8%, clean run에서 문제 보고 26.8%였다. reasoning sibling은 instruct보다 탐지 -9.3%p, plan change +10.4%p였지만 recovery 차이는 유의하지 않았다.
- **부정 결과:** “각 도구 결과를 확인하라”는 한 줄 prompt는 탐지를 유의하게 개선하지 못했다.
- **주의:** 단일 benchmark family의 simulation이고 detection coding κ=.69, 27%가 15-call cap에 도달했다.
- **최소 실험:** 레이더 파이프라인의 API 응답에 합계 불일치·누락 item·날짜 역전을 주입하고 schema validator, semantic invariant, plain prompt 세 조건의 탐지율을 비교한다.

## 6. 오늘의 중요한 발견 3개

1. **Coverage가 reasoning보다 먼저다.** Ledger, VideoEvolve, HeiCo-FOCUS 모두 답변 모델보다 증거가 기억·검색 계층에 남아 있는지가 상한을 만든다.
2. **구조적 prior는 예산에 따라 역전된다.** uViT 결과는 대형 모델에서 유효한 Attention–FFN 분리가 작은 모델에서는 경직된 용량 배분이 될 수 있음을 시사한다.
3. **실패 검증은 prompt가 아니라 측정 가능한 invariant가 필요하다.** 조용한 corruption은 명시적 오류보다 32.5%p 덜 탐지됐고 단순 self-check 문구는 효과가 없었다.

## 7. 과대해석·주의 2개

1. **리더보드 차이를 곧바로 방법 차이로 읽지 말 것:** VideoEvolve 문헌 baseline은 frame 수, subtitle, backbone, test split이 완전히 통일되지 않았다.
2. **복합 지표를 절대 순위로 읽지 말 것:** SAPI 같은 composite score는 가중치와 hardware boundary에 따라 순위가 바뀐다. 원시 성능·에너지·지연을 함께 보존해야 한다.

## 8. 오늘의 Top 3

1. **Ledger** — 연구 질문과 실제 시스템 설계를 동시에 바꾸는 “영속 3D 객체 메모리”라는 명확한 축을 제시한다.
2. **VideoEvolve** — 메모리 생성과 검색을 따로 최적화하지 말아야 한다는 강한 ablation이 있다.
3. **Loud Failures, Quiet Failures** — 현재 자동화 운영에 바로 적용 가능한 실패 주입 설계와 부정 결과를 제공한다.

## 9. Top 1 미니리뷰 — Ledger

Ledger의 핵심 공헌은 “긴 영상을 몇 프레임으로 줄일까”가 아니라 “시간이 지나도 질의 가능한 객체 상태를 어떻게 유지할까”로 문제를 재정의한 데 있다. 객체 중심 3D 상태는 위치·관계 질의에 자연스럽고, 질의 시 원본 영상을 다시 읽지 않아 지연을 줄일 수 있다.

가장 설득력 있는 지점은 여러 데이터셋에서 QA와 localization을 함께 본 점이다. 반면 coverage가 낮으면 reader가 아무리 강해도 회복할 수 없다. 장면 변화, 장기 가림, 동일 객체 재식별 실패가 누적될 때 memory가 오래될수록 더 틀릴 가능성도 있다. 따라서 다음 연구는 평균 QA보다 **시간 경과별 객체 recall, stale-state rate, update cost, query latency**를 함께 봐야 한다.

우리 연구에 적용한다면 해무·항만 영상의 선박·부표·시정 상태를 object/event ledger로 만들고, 새 관측이 들어올 때만 상태를 갱신하는 경량 프로토타입이 적합하다. 성공 기준은 전체 영상을 다시 읽는 baseline 대비 질의 latency 50% 이상 감소, 객체 recall 감소 3%p 이내, 위치 오차 악화 10% 이내로 두는 것이 합리적이다.

## 10. 실행 가능한 연구 씨앗

### Seed A — Coverage-aware Long-Video Memory
- **질문:** 메모리 coverage를 추정해 필요할 때만 원본 영상 재방문을 허용하면 비용 대비 정확도가 좋아지는가?
- **가설:** confidence-gated revisit가 fixed revisit보다 같은 frame budget에서 QA 정확도를 높인다.
- **최소 실험:** Ego4D/자체 10개 영상, Ledger형 memory + coverage head; never/fixed/gated revisit 비교.
- **baseline:** uniform 32/64 frames, text summary memory.
- **성공/실패:** 같은 평균 frame 수에서 QA +3%p 또는 latency -30%면 성공; 둘 다 없으면 실패.

### Seed B — Context-Preserving Cooperative Perception
- **질문:** flow 정교화보다 ROI 밖 저주파 문맥 보존이 비동기 협업 지각에 더 중요한가?
- **가설:** soft residual blend가 hard mask 대비 AP를 회복하면서 통신량 증가는 10% 이내다.
- **최소 실험:** DAIR-V2X에서 none/hard/soft mask와 identity/flow warp의 3×2 factorial.
- **baseline:** 공개 CoBEVFlow 설정.
- **성공/실패:** AP@0.7 +1%p 이상, latency +5% 이내면 성공.

### Seed C — Semantic Invariant Guard for Tool Agents
- **질문:** schema validation 이후에도 남는 plausible corruption을 값 범위·합계·시간 순서 invariant가 잡는가?
- **가설:** semantic guard가 prompt-only check보다 quiet-failure detection을 20%p 이상 높인다.
- **최소 실험:** radar 수집 도구 100 trajectory에 누락·합계 오류·날짜 역전·잘못된 ID를 주입.
- **baseline:** no check, “check your work” prompt, JSON schema only.
- **성공/실패:** false alarm 5% 이하에서 탐지 +20%p면 성공.

### Seed D — Small-ViT Budget Reallocation
- **질문:** 작은 해무 분류 모델에서 FFN 용량을 attention으로 옮기면 정확도보다 calibration이 먼저 좋아지는가?
- **가설:** 20M 이하에서 uViT형 구조가 동일 GPU-hour 기준 ECE와 OOD AUROC를 개선한다.
- **최소 실험:** SeaFog/일반 기상 split에서 ViT-S, no-FFN, AttenFeed 3종 비교.
- **baseline:** 동일 파라미터와 동일 training steps의 ViT-S.
- **성공/실패:** accuracy 유지(±0.5%p)와 ECE 10% 상대 개선을 동시에 만족하면 성공.

## 11. 오늘 안 읽어도 되는 것

- 수치 근거 없이 “foundation model을 적용했다”는 수준의 application paper.
- 단일 dataset의 미세한 SOTA 갱신인데 split·seed·pretraining leakage 설명이 없는 결과.
- 코드·데이터·평가 프로토콜이 모두 비공개인 생성 품질 주장.
- 어제 보고서에서 이미 다룬 HSI leakage, Stable Scores/Unstable Answers, Evidence Readiness, SpaTime, CtrlCache의 반복 소개.
