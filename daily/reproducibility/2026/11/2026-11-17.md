## 핵심 사례 1 — LoRA 출력 순서 변환에서 rank 축까지 바꾸는 문제

**Claim / 재현 조건.** 제보자는 Diffusers `main@43e3002`, torch 2.15.0, Python 3.12, macOS CPU에서 Flux Control 변환기의 `final_layer.adaLN_modulation.1` LoRA를 검사했다. 원본 modulation 출력 순서는 `(shift, scale)`, Diffusers 대상은 `(scale, shift)`라는 설명이다. HunyuanVideo의 별도 변환 경로에도 같은 문제를 제기했다. [제보·코드](https://github.com/huggingface/diffusers/issues/15305)

**Observed gap / 커뮤니티 재현.** Flux Control 예제는 rank 4, inner dimension 3072, `manual_seed(0)`에서 변환된 `B @ A`가 기대 출력 행 순서와 일치하지 않고, A를 원본대로 유지하면 일치한다고 보고한다. 별도 댓글 작성자는 Linux CPU의 Diffusers 0.43.0에서도 동일 예제를 확인했다. 이는 Flux Control 확인이며 HunyuanVideo까지 독립 재현됐다는 뜻은 아니다. maintainer는 PR 제출을 요청했지만 조회 당시 이슈는 open이고 timeline에서 연결된 수정 PR은 확인되지 않았다. [별도 사용자 확인](https://github.com/huggingface/diffusers/issues/15305#issuecomment-6912354094), [maintainer 댓글](https://github.com/huggingface/diffusers/issues/15305#issuecomment-6911022212)

**확인된 소스 / mechanism.** 해당 revision의 Flux Control 코드는 `lora_key`에 따라 A/B 모두에 `swap_scale_shift`를 적용하며, HunyuanVideo remapper도 해당 final-layer key를 분할·연결한다. 출력 행을 재배열할 때 `B`의 행을 바꾸는 것과 `A`의 rank 행을 바꾸는 것은 다른 연산이다. 기대 delta가 `P(BA)`라면 `(PB)A`는 맞지만 `(PB)(PA)`는 일반적으로 같지 않다. [고정 소스](https://github.com/huggingface/diffusers/blob/43e3002/src/diffusers/loaders/lora_conversion_utils.py)

**진단 → 가설 → 최소 실험.** full image 생성에 앞서 두 converter 각각에 대해 원본 `BA`, 변환된 `B'A'`, 기대 행 순서 변환을 비교한다. 기존 경로와 A 보존 경로만 바꾸고 동일 tensor·dtype·scaling을 유지한다. 이후 실제 adapter에서 unfused/fused forward parity를 확인한다. HunyuanVideo는 별도 fixture가 필요하다.

**GO / KILL.** delta 불변식과 adapter forward가 사전에 정한 dtype별 tolerance를 통과하면 해당 변환 조건을 GO한다. shape가 맞거나 load가 성공했다는 이유만으로 변환을 승인하는 것은 KILL한다. tiny 행렬 결과를 이미지 품질 향상이나 논문 재현 완료로 일반화하지 않는다.

## 핵심 사례 2 — Ulysses의 불균등 shard와 mask 정렬

**Claim / 재현 조건.** Diffusers `0.44.0.dev0@1dabc292d`, Python 3.12.4, torch 2.14.1+cu130, H100 80GB의 2~4 GPU 조건이다. 작성자는 random-weight tiny QwenImageTransformer2DModel, FP32, 36 image tokens, text padding mask에서 단일 장치와 context-parallel 결과를 비교했다. [제보](https://github.com/huggingface/diffusers/issues/15310)

**Observed gap / 커뮤니티 재현.** 작성자 표에서 3-rank의 text 10 tokens `[4,3,3]`는 max absolute error 0.0044지만 11 tokens `[4,4,3]`와 균등 12 tokens는 0이었다. 4-rank에서도 짧은 shard가 둘 이상인 조건에 차이가 보고됐다. CPU/Gloo의 3-rank attention-op 대조도 제시됐다. 모두 제보자의 결과이며 공개 QwenImage checkpoint의 생성 품질 측정은 아니다. [실행 조건·대조표](https://github.com/huggingface/diffusers/issues/15310)

**확인된 소스 / mechanism.** 고정 revision은 local mask를 최대 shard 길이로 pad한 뒤 all-gather·concat하고, 전체 길이를 `sum(mask_local_sizes)`로 한 번 자른다. `[4,3,3]`이면 가운데 shard 뒤의 pad가 중간에 남고 마지막 실제 mask 값이 잘릴 수 있다. 각 shard를 원래 길이로 복구한 다음 연결해야 한다는 제보자의 진단은 이 코드와 부합한다. [고정 attention 소스](https://github.com/huggingface/diffusers/blob/1dabc292d/src/diffusers/models/attention_dispatch.py)

**상태 한계.** API timeline에서 11/17 01:43 UTC의 종료 사유는 `not_planned`, closure commit은 null이다. 연결된 수정·릴리스는 확인하지 못했다. closed를 fixed로 읽지 않는다. [종료 기록](https://github.com/huggingface/diffusers/issues/15310#event), [timeline API](https://api.github.com/repos/huggingface/diffusers/issues/15310/timeline)

**진단 → 가설 → 최소 실험.** 우선 GPU 없이 rank별 유효 token ID를 mask와 함께 나열해 gather 후 alignment를 검사한다. 다음 CPU/Gloo 3-rank에서 `[4,3,3]`, `[4,4,3]`, `[4,4,4]`를 full-sequence SDPA와 대조한다. 개별 chunk trim만 바꾼 조건에서 mask index·output max-diff를 보존한다. random weight와 seed는 모든 조건에서 동일하게 둔다.

**GO / KILL.** mask 복원이 정확하고 불균등 shard의 attention parity까지 통과하면 해당 설정을 GO한다. 2-rank 통과를 근거로 3~4-rank 불균등 분할까지 안전하다는 결론은 KILL한다. FP32 tiny-model 차이를 BF16 실사용 품질 하락으로 환산하지 않는다.

## 핵심 사례 3 — Wan Ring Attention의 backend 기능 불일치

**Claim / 재현 조건.** 같은 Diffusers `1dabc292d`, torch 2.14.1+cu130, Transformers 5.23.0, 2×H100 80GB 환경에서 `Wan-AI/Wan2.2-TI2V-5B-Diffusers`, BF16, `ring_degree=2`를 사용한다. 제보 코드는 480×832, 49 frames, 8 inference steps를 요청하지만 기본 backend에서 첫 forward가 실패한다. [원문 코드](https://github.com/huggingface/diffusers/issues/15308)

**Observed gap / 사실과 주장.** 제보 오류는 `Native attention does not support return_lse=True`다. 작성자는 `_native_flash`를 명시하면 실행된다고 보고한다. 고정 소스에서도 native 경로의 `return_lse` 요청을 거부하는 분기를 확인했다. backend를 바꾼 결과의 영상 품질·reference parity는 제시되지 않았다. [고정 소스](https://github.com/huggingface/diffusers/blob/1dabc292d/src/diffusers/models/attention_dispatch.py)

**진단 → 가설.** Ring은 shard 간 attention 결과를 결합하기 위해 LSE가 필요하다는 설명이다. context parallelism 사용 가능 여부와 Ring에 필요한 출력 계약을 별도로 검사하지 않으면 설정 승인 후 실제 forward에서 실패할 수 있다. Ulysses의 mask 문제와는 실패 조건·mechanism이 다르다.

**상태 한계.** 11/16 15:52 UTC에 `not_planned`로 종료됐으며 closure commit은 null이다. 에러 메시지 개선이나 구현 수정이 배포됐다는 근거는 없다. [timeline API](https://api.github.com/repos/huggingface/diffusers/issues/15308/timeline)

**최소 실험.** 먼저 tiny attention fixture로 native와 LSE 반환 backend의 기능 계약을 검사한다. 그다음 동일 checkpoint revision·prompt·initial latent·scheduler·shape를 고정하고 단일 GPU와 Ring의 denoising 출력을 단계별로 대조한다. backend를 바꾸면서 seed까지 바꾸지 않는다.

**GO / KILL.** LSE 계약과 첫 forward, 이어서 고정 latent의 수치 parity를 통과한 backend만 GO한다. native backend로 같은 실패 run을 반복하거나 backend 변경 후 “실행 완료”만으로 품질 재현을 승인하는 것은 KILL한다.

## 공통 비교 조건과 오늘의 판단

- **오늘 첫 GO:** CPU LoRA delta 불변식 검사. weights 다운로드 전 converter 자체를 분리할 수 있다.
- **다음 GO:** Ulysses mask의 shard별 token alignment 검사 후 CPU/Gloo parity 검사.
- **조건부 GO:** Wan Ring은 LSE를 지원하는 backend와 고정 latent 대조를 먼저 통과시킨다.
- **KILL:** closed issue를 수정 완료로 해석하거나, 실패 run을 seed 변경으로 덮거나, 서로 다른 backend·precision의 결과를 동일 조건 benchmark로 합치지 않는다.
- **후속 연구 가설:** seed sweep 전에 adapter 변환·분산 mask·backend 출력 계약을 검사하면 일부 재현 실패를 더 작은 실험으로 분리할 수 있다. 이는 검증할 가설이며 이번 실행의 실측 결론은 아니다.
