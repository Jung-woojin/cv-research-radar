## 1. PerceptRL — tool-use가 있어도 좌표 drift는 evidence를 오염시킨다

**실패 조건·설정(사실).** [PerceptRL](https://arxiv.org/abs/2610.37471)은 fine-grained perception post-training에서 single-turn QA reward와 multi-turn visual-tool inspection을 결합한다. 원문은 visual tool을 쓰도록 학습된 모델에도 incorrect crop 또는 annotation이 evidence를 왜곡하고 오류를 전파하는 coordinate drift가 관찰된다고 명시한다. 이를 위해 Coordinate Injection과 grounding-aware process reward를 추가한다.

**저자 주장.** 공유 tool-use protocol의 7개 benchmark에서 평균 71.6%로 same-tool base model과 가장 강한 평가 대상 frontier VLM보다 각각 15.7/5.2 percentage point 높다고 주장한다.

**실패 해석.** answer-only reward는 잘못된 crop에 우연히 답을 맞히는 trajectory를 구분하지 못한다. 좌표가 틀리면 이후 observation은 더 많아져도 잘못된 region을 강화할 수 있다. 저자 보고 평균은 강하지만, tool schema·crop resolution·coordinate quantization이 다른 시스템과는 not strictly apples-to-apples다.

**후속 가설·최소 실험.** 50개 document/aerial VQA sample에 대해 predicted crop, oracle crop, random crop을 같은 base VLM에 입력한다. final accuracy 외에 IoU, crop 안의 answer-bearing evidence 비율, crop perturbation(±5%, ±10%)에 대한 answer stability를 기록한다. grounding-aware reward가 accuracy는 유지하면서 evidence IoU와 stability를 올리면 진행한다. answer accuracy만 오르고 evidence 지표가 정체되면 tool reward를 최종 답의 대리 지표로 쓰지 않는다.

**평가:** 심각도 4/5 · 재현 신뢰도 3/5 · 연구 아이디어 가치 5/5.

## 2. ImagiRep — 좋은 RGB 상상은 좋은 공간 추론의 증거가 아니다

**실패 조건·설정(사실).** [ImagiRep](https://arxiv.org/abs/2610.37437)은 simulator-grounded 922개 질문에서 같은 미관측 상태의 oracle RGB와 depth, panorama, top-down geometry 등 여섯 대안 표현을 비교한다. 원문은 accurate imagined RGB라도 spatial reasoning이 틀릴 수 있고, 질문마다 좋은 표현이 다르며, estimated RGB alone은 spatial reasoning을 오도할 수 있다고 보고한다.

**저자 주장.** adaptive representation selector GEARS가 기존 spatial-imagination 방법보다 낫다고 주장한다.

**실패 해석.** generative visual fidelity와 distance/direction/open-space readout은 다른 목적 함수다. RGB가 자연스러워도 global geometry가 흐리거나 viewpoint-specific occlusion이 남으면 answer가 틀릴 수 있다. oracle/estimated state 기반 simulator 결과를 실제 UAV·해양·도로 영상으로 일반화하는 것은 미확인이다.

**후속 가설·최소 실험.** 항만/도로 장면 60개에 원본 RGB, 2× crop mosaic, coarse top-down proxy를 만들고 거리·방향·존재 질문을 낸다. 표현 간 answer disagreement, exact accuracy, token cost를 기록한다. disagreement 상위 25%에서만 top-down/crop 전환이 평균보다 유의하게 이득이면 adaptive selector를 진행한다. representation 전환이 token만 늘리고 정확도 gain이 없으면 RGB-first pipeline을 유지한다.

**평가:** 심각도 4/5 · 재현 신뢰도 4/5 · 연구 아이디어 가치 5/5.

## 3. CodeCap-Bench — 자연어 caption은 복잡한 시간 동역학을 충실히 보존하지 못한다

**실패 조건·설정(사실).** [CodeCap-Bench](https://arxiv.org/abs/2610.37341)는 time function, layout rule, graphical primitive를 갖는 executable code caption과 자연어 caption을 비교한다. benchmark는 5개 structured-2D category의 323 video와 fine-grained annotation, multi-level evaluation을 포함한다. 원문은 leading proprietary MLLM도 복잡한 temporal dynamics를 faithfully capture하는 데 어려움이 있으며 open-source 모델은 더 뒤처진다고 보고한다.

**저자 주장.** code caption이 downstream QA와 video reconstruction에서 자연어 caption보다 더 높은 reasoning accuracy와 reconstruction fidelity를 보인다고 주장한다.

**실패 해석.** 자연어는 temporal order와 fine-grained spatial relation을 길고 모호하게 압축한다. 다만 323개 2D structured video에서의 우위를 open-world natural video, tracking, maritime event understanding에 그대로 옮길 수는 없다. executable syntax가 맞더라도 perception·event extraction이 틀리면 evidence 자체는 틀릴 수 있다.

**후속 가설·최소 실험.** 80개 간단 video clip에서 `appear`, `move`, `overlap`, `before/after` 네 primitive만 쓰는 event trace를 만든다. natural-language rationale과 비교해 syntax validity, QA accuracy, relevant event를 마스킹했을 때 answer flip rate, hallucinated-object rate를 측정한다. code trace가 flip sensitivity와 evidence precision을 올리면 확대한다. syntax만 좋아지고 counterfactual sensitivity가 동일하면 program 표현의 audit 가치를 주장하지 않는다.

**평가:** 심각도 3/5 · 재현 신뢰도 4/5 · 연구 아이디어 가치 4/5.

## 오늘의 실패 패턴 3개

1. **Correct answer ≠ correct evidence:** 최종 정답만으로 crop·region·intermediate action이 맞았는지 확인할 수 없다.
2. **High visual fidelity ≠ correct spatial readout:** 생성된 RGB를 공간 추론의 증거로 바로 사용하면 representation mismatch가 난다.
3. **Readable rationale ≠ faithful temporal structure:** 자연어 trace가 시간 순서·객체 관계를 보존한다는 보장이 없다.

## 직접 재현할 최소 실험

동일한 30개 영상/이미지 질문에 대해 (a) base answer, (b) predicted crop/자연어 rationale, (c) oracle 또는 구조 trace를 저장한다. 관련 evidence를 가리거나 시간 순서를 교환한 counterfactual input에서 answer가 바뀌는 비율을 기록한다. 답이 맞았지만 counterfactual에도 변하지 않는 사례를 **correct-but-unfaithful**로 분류한다.

**GO:** oracle evidence 대비 predicted evidence의 answer-stability 차이와 correct-but-unfaithful 비율이 의미 있게 측정되면 evidence-audit benchmark로 확장한다.

**KILL:** trace 형식에 따라 answer와 counterfactual sensitivity가 구분되지 않거나 annotation 비용이 sample당 10분을 넘으면, structured trace 대신 저비용 crop perturbation audit로 축소한다.
