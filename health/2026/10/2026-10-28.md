## 5. 진단 → 가설 → 최소 실험

### 로컬 health false positive

- **진단:** `radar_health.py`는 stale local checkout을 검사해 이미 원격에 있는 오늘 파일을 missing으로 표시했다.
- **가설:** health 판정 전에 원격 manifest 또는 GitHub file API 결과를 우선하면 false positive를 제거할 수 있다.
- **최소 실험:** 다음 실행에서 로컬 결과와 원격 contents API를 경로별로 대조하고, `local_missing && remote_exists`를 별도 `local_stale` 상태로 기록한다. 성공 기준은 오늘 확인된 다섯 건을 missing이 아닌 stale로 분류하는 것이다.

### `github_audit.py` transport 장애

- **진단:** 독립 REST audit는 timeout/네트워크 오류였지만 GitHub 앱 connector는 정상 응답했다.
- **가설:** transport별 timeout과 인증 경로를 분리 표시하면 전체 GitHub 장애로 오판하지 않는다.
- **최소 실험:** 같은 commit/workflow를 script와 connector로 각 1회 조회해 transport, HTTP 상태, latency를 별도 기록한다. 한 경로 성공 시 repository 상태는 `degraded`, 둘 다 실패할 때만 `unavailable`로 판정한다.
