## 1. 빈 pose frame과 미확정 track 상태가 만드는 adapter 실패

**확인된 사실.** Supervision 0.31.6은 빈 frame에서 `KeyPoints.empty()`의 confidence 배열 등이 `None`이어서 confidence filtering이 `TypeError`를 내고, keypoint indexing이 `IndexError`를 내던 문제를 수정했다. 동일 릴리스는 음수 `tracker_id`를 미확정 track으로 사용하는 입력에서 `DetectionsSmoother`가 여러 객체를 하나의 평균 box로 합치던 동작도 수정했다. 릴리스 노트의 예시에서 0.31.5는 `[0,0,10,10]`, `[100,0,110,10]` 두 box를 `[50,0,60,10]` 하나로 반환했고, 0.31.6은 두 box를 분리해 보존한다. [공식 릴리스](https://github.com/roboflow/supervision/releases)

- 실패 조건: pose가 없는 video frame의 keypoint filter/indexing, 또는 여러 미확정 track이 같은 negative ID를 가진 smoothing 경로.
- 공식 인정: **있음** — maintainer가 fixes-only 릴리스로 문서화했다.
- 재현 근거: **공식 릴리스의 전후 코드 예시**; 이 watch에서 독립 실행하지 않았다.
- 진단: “비어 있음”과 “미확정 상태”를 보통 배열/ID로 정규화하지 않으면, downstream filter는 예외를 내고 temporal smoother는 서로 다른 객체를 같은 identity로 취급한다.
- 가설: detector의 AP가 변하지 않아도, 사람 부재 구간과 track warm-up 구간이 많은 동영상에서는 exception rate와 phantom-object rate가 평가 결과를 더 크게 흔들 수 있다.
- 최소 실험: (a) 빈 pose frame 100개에 confidence filter와 keypoint slice를 적용하고 예외 수를 세고, (b) 동일 frame의 두 negative-ID box를 0.31.5/0.31.6에서 smoothing하여 output row 수와 center displacement를 비교한다.
- GO/KILL: 예외가 0이고 두 객체가 분리되면 upgrade를 GO; tracker가 미확정 ID를 고유하게 부여하거나 해당 구간을 버린다면 smoother 원인을 일반화하지 않는다.
- 점수: 심각도 **3/5**, 재현 신뢰도 **4/5**, 연구 아이디어 가치 **3/5**.

## 2. NVFP4 fake-quantization의 Triton compiler API 호환성 실패

**확인된 사실.** NVIDIA ModelOpt 0.47.1은 Triton 3.9를 포함한 PyTorch 26.11 container에서 `NVFP4_DEFAULT_CFG` 등의 NVFP4 fake quantization이 compute capability 8.9 이상 GPU에서 `NotImplementedError: Block pointers have been removed in favor of the tensor descriptor API`로 실패하던 문제를 수정했다고 명시한다. [공식 릴리스](https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.47.1)

- 실패 조건: Triton 3.9 + PyTorch 26.11 container + compute capability 8.9 이상 GPU에서 NVFP4 fake quantization.
- 공식 인정: **있음** — NVIDIA의 0.47.1 bug fix다.
- 재현 근거: **공식 릴리스의 실패 메시지와 환경 조건**; 이 watch에서 독립 실행하지 않았다.
- 진단: quantization algorithm의 정확도 문제가 아니라 Triton의 제거된 block-pointer API와 ModelOpt kernel 경로의 호환성 문제다.
- 가설: 같은 calibration data와 config라도 compiler/runtime 조합을 고정하지 않으면 “quantization failed”를 model sensitivity로 잘못 분류할 수 있다.
- 최소 실험: 해당 container에서 고정 shape tensor에 `NVFP4_DEFAULT_CFG`를 적용해 0.47.0과 0.47.1의 exception 여부를 비교하고, 성공한 경우에만 fixed calibration batch의 dequantized output checksum과 max absolute difference를 기록한다.
- GO/KILL: 0.47.1에서 예외 없이 실행되고 output 검사가 통과하면 GO; 다른 compute capability 또는 Triton 3.9이 아닌 환경에서 차이가 없으면 적용 범위를 해당 조합으로 제한한다.
- 점수: 심각도 **4/5**, 재현 신뢰도 **4/5**, 연구 아이디어 가치 **3/5**.

## 오늘의 실패 패턴

1. 빈 입력과 임시 identity는 “정상적인 edge case”로 표현되어야 하며, `None` 또는 공유 sentinel ID로 넘기면 후단에서 crash·phantom merge가 난다.
2. 모델 adapter의 출력 구조 변화는 accuracy table에 나타나지 않아도 tracker·annotator·filter 조합을 무너뜨릴 수 있다.
3. low-precision quantization 실패는 kernel API·GPU capability·container 버전의 교차 조건을 분리하지 않으면 알고리즘 실패로 오판된다.

## 연구 빈틈과 최소 실험

**추론.** “실패 셀”을 dataset 난이도 대신 input-state × adapter-version × runtime-version의 3축으로 측정하는 evaluation harness가 필요하다. 먼저 빈 frame / two tentative tracks / fixed NVFP4 tensor 세 cell만 만들고, exception 여부·output row count·checksum을 seed와 함께 저장한다. 이 세 지표가 stable하면 그 다음에 task metric을 해석한다.
