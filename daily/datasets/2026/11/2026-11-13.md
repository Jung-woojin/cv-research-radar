## 1. USDCraft-10K — 지속 업로드의 taxonomy·lineage 고정

**확인한 사실.** 공개 HF API의 현재 revision은 `4cbf519c0ac1e8e24f566816e820b1a0c889b188`이며 최신 commit 제목은 “Grow to 600 categories (5,998 objects) (part 21)”이다. 생성일 10/28과 이번 확장일 11/12를 구분한다. pinned card는 Apache-2.0, default config의 `train: manifest.csv`를 명시한다. 별도 validation/test protocol은 확인하지 못했다. [API](https://huggingface.co/api/datasets/nvidia/USDCraft-10K) · [고정 card](https://huggingface.co/datasets/nvidia/USDCraft-10K/blob/4cbf519c0ac1e8e24f566816e820b1a0c889b188/README.md)

**규모·task·artifact.** 텍스트에서 생성한 articulated/static 3D asset으로 OpenUSD/PhysX, object metadata, interaction annotation, manifest 및 hash를 제공한다. pinned manifest를 PowerShell CSV parser로 직접 읽어 5,998행과 category ID 600개를 확인했고, ID와 `physx_sha256` 각각의 중복 그룹은 0개였다. binary 파일 자체의 hash 재계산은 하지 않았다. [고정 manifest](https://huggingface.co/datasets/nvidia/USDCraft-10K/raw/4cbf519c0ac1e8e24f566816e820b1a0c889b188/manifest.csv) · [공식 구현](https://github.com/NVlabs/USDCraft)

**저자 주장과 한계.** 배포자는 simulation-ready asset으로 설명한다. 이번 집계는 물리적 타당성·interaction label 정확도·sim-to-real 성능을 검증하지 않는다. 합성 prompt/category family와 생성기 특성에 의한 bias는 **의심할 가설**이며 관측된 결함이 아니다. 기존 real-object benchmark와의 비교는 데이터 생성 방식과 split이 달라 **not strictly apples-to-apples**다.

**진단 → 가설 → 최소 실험.** 같은 category의 variant를 random split하면 geometry/program family를 공유할 수 있다. category-family heldout과 variant-random split의 차이가 실제 일반화보다 크게 보일 수 있다는 가설을 세운다. 먼저 전체 manifest의 category별 개수·joint type 분포와 누락 hash를 집계하고, 소수 category에서 geometry signature와 렌더 유사도로 후보 duplicate를 수동 판정한다. 그다음 같은 encoder·head·해상도·학습량·seed를 고정해 두 split을 비교한다.

**GO/KILL.** metadata preflight는 GO. 물리 파일 검증과 group split 전 “10,000개를 사용했다”, “중복이 없다”, “실제 물체 일반화가 개선됐다”는 결론은 KILL.

## 2. BabyView — 공개 상태와 cumulative release를 분리

**확인한 사실.** 11/11 updated 상태표에서 2026.1은 2,701시간·50명, October 2026 Released이며 2026.2는 3,914시간·50명, In embargo다. 각 main release는 앞선 release를 포함하므로 시간을 합산하면 안 된다. 수집 총량과 공개량도 다르다. 이 날짜는 페이지 업데이트일이며 11/11에 새 원자료가 공개됐다는 증거는 아니다. [공식 상태표](https://babyview-project.github.io/dataset/)

**task·annotation·artifact.** 아동 egocentric video와 자동 transcript/speaker annotation, IMU를 제공한다. 공식 페이지는 WhisperX large-v3 transcript와 VTC 2.0 speaker type을 설명한다. 이를 expert-corrected ground truth로 해석하지 않는다. 공개 train/val/test 표준 split과 개별 label correction diff는 확인하지 못했다.

**license·access.** 접근은 Databrary의 승인 연구자, 기관 agreement 및 기관 연구 승인을 전제로 한다. 일반 공개 다운로드나 permissive commercial license로 분류하지 않는다. 현재 접근 정책 확인을 새로운 정책 변경 발생의 증거로 쓰지 않는다. [공식 접근 안내](https://babyview-project.github.io/access/)

**진단 → 가설 → 최소 실험.** longitudinal video에서 같은 아동·가정의 인접 클립이 split을 넘으면 identity/environment shortcut이 생길 수 있다는 **추론**이다. 누적 release를 별개 corpus로 결합해도 duplicate가 생길 수 있다. 적법한 접근 확보 후 release ID·video ID의 교집합, child/household group, 촬영 시간 간격을 audit하고 child-heldout을 고정한다. transcript는 confidence·speaker별 표본을 사람이 검토해 noise bucket을 만든다.

**bias·호환성·GO/KILL.** 아동별 촬영시간 차이와 자동 annotation noise를 평가해야 하며 일반 성인 egocentric benchmark와 **not strictly apples-to-apples**다. 공개 상태/manifest 설계는 GO. embargo 자료를 가용 데이터로 세거나 누적 시간을 더하는 것은 KILL. 이 실행에서는 제한 데이터에 접근하지 않았다.

## 3. CaseVBench v6 — 새 결과표와 annotation migration의 구별

**확인한 사실.** 11/11 v6는 119페이지·9개 프로젝트·1,430개 annotation·5개 category, IoU 0.50의 F1 평가다. 공식 설명은 기존 20개 model record가 유지되고 두 model record가 추가됐다고 밝힌다. 이는 새 label revision 확인과 다르다. [공식 설명](https://casevbench.com/) · [v6 JSON](https://casevbench.com/data/casevbench-v6.json)

**artifact·split·license.** 공개 다운로드는 집계 결과이며 source drawing·annotation·prompt를 포함하지 않는다고 명시한다. 공식 repo도 존재하나 원 dataset/annotation의 재사용 license와 train/test split은 이번 확인으로 확정하지 못했다. 원자료 배포와 결과표 공개를 구분한다. [공식 저장소](https://github.com/COXIT-CO/CaseV-bench)

**평가 정책과 한계.** overall F1은 category F1의 단순평균이 아닌 pooled TP/FP/FN 기반이다. 한 모델은 119페이지 중 117페이지만 처리했지만 전체 ground-truth 분모를 유지한다. evaluator/data hash, prompt와 per-page raw record가 없으므로 독립 재현 완료로 취급하지 않는다. 게시 edition 날짜와 실제 측정월도 다르다.

**진단 → 가설 → 최소 실험.** 페이지 밀도·작은 box·프로젝트 style과 처리 누락이 aggregate score에 영향을 줄 수 있다는 **추론**이다. 원 annotation을 확보한다면 project-heldout 및 box-area/density bucket을 만들고 pooled F1, macro-category F1, 누락 페이지를 FN으로 포함한 점수를 함께 계산한다. 현 단계의 최소 audit는 v5/v6 JSON의 기존 record 불변성·새 record·coverage field를 diff하는 것이다. 이번 실행에서는 JSON 열람까지만 했으며 정량 diff나 detector 재평가는 실행하지 않았다.

**GO/KILL.** 버전·coverage를 기록하는 평가 provenance 분석은 GO. leaderboard edition 변경을 dataset correction이나 새로운 일반화 증거로 해석하는 것은 KILL. 다른 해상도·pretraining·TTA·evaluator의 detector 결과와는 **not strictly apples-to-apples**다.
