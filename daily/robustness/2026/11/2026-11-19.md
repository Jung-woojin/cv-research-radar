## 1. ShadowTransfer — 지리 전이는 foreground confidence부터 진단한다

**확인 사실·저자 보고.** 3개 미국 도시, 두 native 해상도의 그림자 검출 LOCO benchmark다. 초록은 vanilla의 도시 holdout 손실을 3.5~7.8 mIoU, adaptation 8개 중 6개의 평균 악화를 보고한다. 이는 **방법별 평균 6/8**이며 개별 도시×architecture 악화 cell 수가 아니다. 저자는 pixel histogram matching으로 설명되지 않는 feature shift, shadow confidence 붕괴, architecture별 encoder/decoder 회복 차이를 주장한다. [공식 초록·이력](https://arxiv.org/abs/2611.24904)

**metric·calibration/coverage·artifact.** 공식 저장소는 per-cell mIoU·ECE·AURC_shadow, source-val에서 정한 `c*_val`의 test selective error, temperature scaling 분석 경로를 명시한다. 이번 실행에서는 결과 JSON의 수치까지 대조하지 않아 ECE·coverage 개선량과 전체 악화 cell 총수는 **미확인**이다. 구현이 있다는 사실과 효과가 입증됐다는 주장을 분리한다. [공식 평가 경로](https://github.com/shagun8/shadowtransfer)

**비교 한계.** 0.3/0.6 m 영상은 같은 원본을 downsample한 것이 아니라 별도 native acquisition이어서 순수 해상도 개입은 **not strictly apples-to-apples**다. 데이터 카드는 3개 미국 도시·단일 가을·NAIP RGB의 한계를 밝힌다. 따라서 세계 지리·계절·센서 일반화로 확대하지 않는다. [공식 데이터 카드](https://huggingface.co/datasets/shagunmittal/ShadowTransfer)

**평가자 진단 → 가설 → 최소 intervention.** 평균 mIoU보다 shadow/background의 confidence 이동을 먼저 분리한다. 가설은 foreground uncertainty와 readout 불일치가 일부 도시의 selective error를 증폭한다는 것이다. 새 모듈 대신 기존 probability map과 manifest를 audit한다.

**최소 실험 제안.** 동일 checkpoint·도시 holdout·해상도·경계 evaluator에서 shadow/background별 confidence, ECE, risk–coverage, mIoU를 기록한다. threshold는 source-val에서만 정하고 target label로 고르지 않는다. histogram matching, temperature scaling, encoder-only/decoder-only 회복 probe를 분리한다. target-label retraining은 원인 진단용 oracle이며 무감독 배포 성능으로 합치지 않는다.

**GO/KILL.** source-val 기준 선택 규칙이 untouched target에서 worst-city risk를 줄이고 coverage 손실이 허용 범위면 GO다. 평균 mIoU만 좋아지거나 target label을 쓴 probe만 회복되면 배포 강건성 주장을 KILL한다.

## 2. ALIVE — 시간 노후화와 task별 채널 통계 민감도

**확인 사실·저자 보고.** frozen DINOv3 feature를 event로 갱신하며 synthetic 학습 후 서로 다른 event camera의 실제 데이터에 적용한다. Table 2에서 full 대비 spatial refinement 제거는 detection mAP 52.55→51.74, segmentation mIoU 66.30→65.57로 낮아지지만 depth AbsRel 0.129→0.127, RMSE 3.741→3.712로 좋아진다. 반대로 보면 refinement 추가 시 **5개 metric 열 중 depth 2/5가 수치상 악화**한다. 유의성·개별 sample cell 총수는 미확인이다. [본문 Tables 1–2](https://arxiv.org/html/2611.24579v1)

**진단·metric·coverage.** anchor age와 event sparsity가 핵심 cell이다. moment matching 제거 시 depth AbsRel이 0.162라는 ablation은 feature 채널 통계 민감도의 단서다. 이것은 confidence calibration이 아니며 ECE·selective coverage는 확인 근거에 없다. update latency는 GH200·FP32·batch 1·640×640에서 측정하며 anchor encoding·초기화·task head를 제외한다. end-to-end latency로 인용하지 않는다. [평가 protocol·ablation](https://arxiv.org/html/2611.24579v1)

**평가자 가설 → 최소 intervention.** 위치를 옮기는 개입과 channel statistics를 보정하는 개입은 task마다 다른 오류를 만든다는 가설이다. decoder를 다시 학습하기 전에 같은 output feature에 moment matching만 켜고 끈다.

**최소 실험 제안.** 같은 target frame을 고정하고 anchor age×sensor×event density를 나눈다. stale/flow/full 및 moment matching on/off를 동일 frozen head로 비교하고 mAP·mIoU·AbsRel·RMSE·최악 cell을 기록한다. depth를 검출 개선의 부수 지표로 취급하지 않는다. timing에는 anchor·preprocess·head까지 포함한 별도 end-to-end 측정을 추가한다.

**GO/KILL.** correction이 depth tail과 worst-age cell을 유지하면서 갱신 이득을 주면 GO다. 검출 평균만 오르고 depth가 악화하면 task 공통 refinement 적용을 KILL한다. baseline의 real-data pretraining 이력은 달라 **not strictly apples-to-apples**다. 원문은 code release 예정이며 실제 공개·재현 완료로 쓰지 않는다. [제출 이력·공개 상태](https://arxiv.org/abs/2611.24579)

## 3. NereidVLA — 평균 항법 개선과 tail 개선은 별개다

**확인 사실·저자 보고.** 수중 spatial pretraining 후 항법으로 전이한다. Table 2에서 SimpleVLN 대비 ADE는 0.18501→0.18082로 낮지만 ADE P95는 0.57398→0.59726으로 높다. **오차 metric 5개 중 1/5 악화**다. Table 3에서는 전체 SR이 InternVLA-N1보다 높아도 pipeline SR은 87.2→86.4%로 낮아 **task 집계 1/4 악화**다. 두 비교는 baseline이 달라 하나의 악화율로 합치지 않는다. [본문 Tables 2–3](https://arxiv.org/html/2611.24864)

**shift cell·calibration/coverage.** simulation은 task별 25 instance×5 water/light 조건이지만 공개 표는 조건별 결과를 합친다. 개별 물·조명 cell 악화 수와 ECE·selective coverage는 미확인이다. 실물 63/80 성공은 실험실 pool이며 외해·탁도 전 범위 보장이 아니다. ADE P95는 오차의 95백분위이지 95% 신뢰구간 coverage가 아니다. [protocol·실물 평가](https://arxiv.org/html/2611.24864)

**평가자 진단 → 가설 → 최소 intervention.** 공간 지식이 평균 목표 접근을 개선해도 드문 경로 오차와 협소 통과 실패는 남을 수 있다. 가설은 perception 개선과 실행 시점의 pose/latency 오차가 분리된 bottleneck이라는 것이다.

**최소 실험 제안.** 기존 offline trajectory를 task×water/light×관측 지연으로 다시 집계한다. 같은 scene·seed·controller에서 초기화만 다른 matched 모델의 ADE/FDE, P95, collision/timeout을 비교한다. 먼저 동일 예측 경로의 capture-time pose 정렬 on/off를 simulator에서 진단하고, risk에 따른 abstention은 coverage와 함께 별도 평가한다.

**GO/KILL.** worst-condition collision과 tail error가 함께 개선되면 추가 전이 실험을 GO한다. 전체 SR만 높고 특정 조건의 안전성이 나빠지면 전체 환경 배포 주장을 KILL한다. architecture·optimization이 다른 모델 간 순위는 **not strictly apples-to-apples**다. 해상도·TTA 등 모든 비교 조건의 일치는 미확인이다. 실물 시스템은 remote RTX 4090 planning을 사용하므로 onboard edge 실행으로 쓰지 않는다. [구현·비교 조건](https://arxiv.org/html/2611.24864)
