### 관측 → 진단 → 기전

**평가자 보고.** Qwen3-VL-235B는 RefCOCOg box grounding 100개 expression·52개 이미지에서 Acc@0.5 31%, Acc@0.75 29%, Acc@0.9 14%, 실패 53개를 기록한다. README와 JSON의 집계는 일치한다. 이는 독립 재현 수치가 아니다. [결과표](https://github.com/Tenkei/vlm-tasks/blob/ed61cdd1b1df4473d46a519b788ffd33f13bf481/benchmarks/README.md), [결과 JSON](https://github.com/Tenkei/vlm-tasks/blob/ed61cdd1b1df4473d46a519b788ffd33f13bf481/benchmarks/runs/qwen3-vl-235b-bedrock-20261112/ground_box.json).

**확인 사실.** JSON의 실패 기록에는 `InvalidModelResponseError`가 포함된다. 방법론은 inference·parsing 실패를 분모에 유지하고 grounding abstention도 0점 처리한다고 명시한다. detection 실패는 빈 box로 취급해 FN을 늘리지만 FP는 만들지 않는다. 4,096-token cap 도달률과 실패율은 서로 다른 집계이며 cap 도달이 곧 실패는 아니다. [방법론](https://github.com/Tenkei/vlm-tasks/blob/ed61cdd1b1df4473d46a519b788ffd33f13bf481/benchmarks/methodology.md).

**추론.** 관측 점수는 시각적 위치추정, 출력 schema 준수, abstention 정책이 섞인 pipeline 성능이다. box grounding 저하를 vision encoder의 결함으로 단정하면 진단이 앞선다. detection에서 Qwen3-VL-235B의 precision 90.67%와 recall 9.18%도 응답 실패·누락 조건과 함께 해석해야 한다. 이 F1@0.5를 COCO mAP로 바꾸어 비교해서는 안 된다. [평가자 detection 결과](https://github.com/Tenkei/vlm-tasks/blob/ed61cdd1b1df4473d46a519b788ffd33f13bf481/benchmarks/README.md#detection).

### 같은 조건 비교인가

| 조건 | 확인 내용과 한계 |
|---|---|
| 표본·split | source 순서의 첫 100개 eligible row, shuffle 없음. COCO128 val은 train과 같은 이미지. RefCOCOg UMD val 사용 |
| 표본 독립성 | box grounding의 100개 expression은 52개 이미지에서 나옴. 100개 독립 이미지로 해석 불가 |
| 모델·pretraining | 2B는 revision이 고정된 Transformers 모델, 235B는 Bedrock model ID. 235B 결과의 revision은 null. 학습 데이터·오염 여부는 미확인 |
| prompt·budget | 같은 frozen data·과제 지시·schema·4,096-token budget·0 correction retry를 명시. 모델별 토큰 수는 같은 compute를 뜻하지 않음 |
| 해상도·TTA | processor 설정 기록 방침은 있으나 모델 간 실제 입력 해상도 동등성·TTA를 이번 조사에서 완전 대조하지 못함 |
| 실행 조건 | 2B는 Apple MPS, 235B는 Bedrock Tokyo. backend·하드웨어·provider 관리 조건 차이가 있음 |
| evaluator | `evaluation.py`는 공통 task validator `.val()`을 호출하고 fingerprint를 검사. 내부 validator 전체 및 raw 응답 전수 재채점은 미실행 |

따라서 모델 간 비교는 **not strictly apples-to-apples**다. frozen subset과 명시적 실패 정책은 진단에 유용하지만, local와 hosted latency 차이를 모델 크기의 인과효과로 볼 수 없다. COCO128 train/val 중복은 일반화 평가의 한계이며 이 모델의 실제 학습 누수를 입증하지는 않는다. [방법론](https://github.com/Tenkei/vlm-tasks/blob/ed61cdd1b1df4473d46a519b788ffd33f13bf481/benchmarks/methodology.md), [235B 설정](https://github.com/Tenkei/vlm-tasks/blob/ed61cdd1b1df4473d46a519b788ffd33f13bf481/benchmarks/runs/qwen3-vl-235b-bedrock-20261112/config.json), [공통 평가 코드](https://github.com/Tenkei/vlm-tasks/blob/ed61cdd1b1df4473d46a519b788ffd33f13bf481/benchmarks/src/evaluation.py).

### 가설 → 최소 개입 → 실험

**가설.** 235B grounding의 낮은 전체 점수 중 일부는 시각 추론보다 응답 형식과 validator의 계약 불일치에서 발생할 수 있다. 오류 유형만으로 이 가설이 입증된 것은 아니다.

**최소 실험 제안 — 아직 실행하지 않음.**

1. 고정 commit의 manifest·JSONL·schema를 확보하고 이미지·target fingerprint가 같은지 먼저 확인한다.
2. 저장 원응답을 읽어 malformed JSON, schema mismatch, 의미적 abstention, 유효하지만 틀린 box를 분리한다. 파서가 실패했다는 이유만으로 원응답에 올바른 box가 있다고 가정하지 않는다.
3. GT를 참조하지 않는 결정적 형식 정규화만 별도 적용하고 원래 evaluator로 paired 재채점한다. 새 모델 호출·학습 없이 원본 점수를 함께 보존한다.
4. 전체 분모의 Acc@0.5·0.75·0.9, 유효 출력률, abstention율을 보고한다. 성공 응답만의 점수는 보조 진단으로 표시하며 원본 leaderboard 점수를 대체하지 않는다.
5. 불확실성을 추정한다면 expression이 아니라 이미지 단위로 묶는다. 이후 별도의 순서 외 표본에서 같은 진단이 반복되는지 확인한다.

**GO/KILL.** GT 없이 사전 정의한 정규화가 기존 유효 출력을 손상하지 않고 실패를 줄이면 출력 계약 개선 실험으로 진행한다. 원응답에 위치 정보가 없거나 유효 출력의 IoU가 계속 낮으면 parser만의 설명을 기각하고 localization·abstention 분석으로 전환한다. 표본 fingerprint가 다르면 모델 간 paired 비교를 중단한다.

**연구 가치 판정 — 추론.** 이 공개는 새 SOTA 주장보다 실패를 포함한 작은 평가의 감사 대상으로 가치가 있다. 전체 dataset 재현과 입력·backend 조건 통제 전에는 모델 우열의 일반 결론을 내리지 않는다.

## 오늘의 benchmark signal 3개

1. **공개일과 측정일:** 새 commit은 새 실험 실행을 뜻하지 않는다. 둘을 따로 기록해야 변화 추적이 정확해진다.
2. **답변 계약과 위치추정:** pipeline 실패율을 분리하지 않으면 grounding 점수가 encoder 능력과 혼동된다.
3. **분모와 표본 독립성:** 실패 포함 여부, ordered prefix, 반복 이미지, train/val 중복이 작은 benchmark 해석을 좌우한다.

위 세 signal은 채택한 한 공개에서 얻은 분석이며 서로 다른 신규 benchmark 3건이라는 뜻이 아니다.

## 내 연구에 바로 연결되는 포인트

- **VLM Answer–Region Gap:** 서로 다른 VQA·grounding 표본의 평균 차이를 동일 이미지의 gap으로 해석하지 않는다. 같은 이미지·질문·region target의 paired 평가를 설계해야 한다.
- **small/tiny object·P2:** 먼저 유효 box의 크기별 IoU와 누락을 나누고, parser 문제가 배제된 뒤 고해상도 feature 개입을 검토한다. 이 공개에는 tiny-object 개선의 직접 근거가 없다.
- **8GB 환경의 첫 작업:** 저장 응답·manifest 감사는 대형 모델 적재 없이 시작할 수 있다. 실제 다운로드 용량·실행시간은 이번에 측정하지 않았다.
- 오늘의 우선순위는 새 학습이 아니라 응답 계약 감사다. evaluator dispatch와 보고 JSON의 정합성은 확인했으나, 독립 재현·새 점수 산출·모델 실행은 하지 않았다.
