# Daily Research Questions — 2026-11-04 (Asia/Seoul)

## Q1. VLM은 실제로 이미지를 조건으로 사용했는가?

1. **문제 정의:** KV cache off/sequence-parallel fallback에서 VLM 결과가 image evidence가 아닌 text prior로 생성됐는지 진단한다.
2. **가치와 근거:** ModelOpt 0.48.0은 후속 decode step에서 vision input이 drop돼 generation이 이미지를 조용히 무시할 수 있었음을 수정했다.  
   출처: https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.48.0
3. **가설:** image-swap·blank-image counterfactual에 불변인 응답은 conditioning path failure를 드러낸다.
4. **MVP/기준선/데이터:** 동일 prompt에서 원본·swap·blank 10개 이미지, 동일 모델의 KV-cache on/off를 비교한다.
5. **성공·실패 metric:** answer change, image-token 전달 여부, evidence-grounded accuracy; first-token 이후 vision tensor가 없으면 실패다.
6. **compute:** 2/5. **novelty risk:** 3/5 — 단순 sanity check로 보일 수 있으므로 failure taxonomy가 필요하다.
7. **negative result 가치:** swap 반응이 정상이어도 어느 decode path가 evidence를 보존하는지 manifest를 남길 수 있다.
8. **4–8주 논문화:** 3/5. 다양한 VLM runtime의 conditioning trace benchmark로 확장할 수 있다.

## Q2. calibration 완료 로그는 valid INT8 model을 의미하는가?

1. **문제 정의:** FP16 activation ONNX 모델에서 entropy calibration 성공 여부와 quantization parameter 유효성·task fidelity의 차이를 측정한다.
2. **가치와 근거:** ModelOpt 0.48.0은 FP16 activation에서 ONNX INT8 entropy calibration이 실패하거나 invalid parameter를 만들 수 있었음을 수정했다.  
   출처: https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.48.0
3. **가설:** activation range와 scale/zero-point의 finite audit을 추가하면 output metric 전의 silent calibration failure를 잡는다.
4. **MVP/기준선/데이터:** 한 ONNX detector 또는 segmentation graph를 FP16 activation 조건과 FP32 reference 조건에서 같은 representative 100 samples로 calibration한다.
5. **성공·실패 metric:** invalid/non-finite parameter 수, cosine similarity, mAP/mIoU; parameter 하나라도 invalid면 KILL이다.
6. **compute:** 3/5. **novelty risk:** 3/5 — framework-specific bug 보고로 끝날 위험이 있다.
7. **negative result 가치:** FP16/FP32 차이가 없으면 calibration manifest의 최소 필요 열을 좁힐 수 있다.
8. **4–8주 논문화:** 4/5. calibration-audit suite를 CV graph와 deployment runtime으로 확장한다.

## Q3. Transpose 뒤 Q/DQ axis는 task error를 예측하는가?

1. **문제 정의:** MaxViT 같은 transpose graph에서 export 성공과 quantization axis 보존을 분리한다.
2. **가치와 근거:** ModelOpt 0.48.0은 Transpose가 있는 real-weight quantized ONNX export failure와 잘못된 `dq_only` output axis를 수정했다.  
   출처: https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.48.0
3. **가설:** per-channel scale axis mismatch는 final top-1보다 layerwise drift에서 먼저 검출된다.
4. **MVP/기준선/데이터:** FP reference와 quantized ONNX를 고정 32-image set에서 실행하고 attention block별 output을 비교한다.
5. **성공·실패 metric:** layerwise cosine, max absolute error, top-1 consistency, per-channel axis agreement; mismatch면 KILL이다.
6. **compute:** 2/5. **novelty risk:** 2/5 — 엔지니어링 audit로 보일 수 있다.
7. **negative result 가치:** axis mismatch가 task metric을 바꾸지 않아도 안전한 tolerance 범위를 제시할 수 있다.
8. **4–8주 논문화:** 3/5. ViT/segmentation/OVD의 graph-structure-aware PTQ study로 확장한다.

## Q4. panoramic video의 오답은 관측 실패인가 evidence 결합 실패인가?

1. **문제 정의:** 360° video VLM이 필요한 view를 찾지 못하는 것과 찾고도 시간적으로 결합하지 못하는 것을 분리한다.
2. **가치와 근거:** PanoVideoBench는 11개 모델에서 cross-view tracking과 sphere-time evidence integration을 약한 능력으로 보고한다.  
   출처: https://arxiv.org/abs/2610.42082
3. **가설:** oracle view를 주면 정답이 개선되는 사례는 observation bottleneck, oracle view에서도 실패하면 temporal reasoning bottleneck이다.
4. **MVP/기준선/데이터:** 100개 질문에서 ERP, random perspective, oracle perspective를 같은 frame/token budget으로 비교한다.
5. **성공·실패 metric:** answer accuracy, target-search recall, evidence F1, latency.
6. **compute:** 3/5. **novelty risk:** 4/5 — oracle annotation 비용이 위험이다.
7. **negative result 가치:** oracle view에서도 불변이면 model-level evidence integration 연구가 정당화된다.
8. **4–8주 논문화:** 4/5. maritime/UAV multi-camera로 직접 확장 가능하다.

## Q5. dataset path migration은 재현 metric을 얼마나 바꾸는가?

1. **문제 정의:** dataset archive/directory rename이 동일 dataset 학습·평가라고 잘못 가정될 때 생기는 provenance drift를 측정한다.
2. **가치와 근거:** Ultralytics 8.4.201은 `construction-ppe` canonical naming을 정비하고 기존 local cache의 이전 directory name을 지원 범위 밖이라고 명시한다.  
   출처: https://github.com/ultralytics/ultralytics/releases/tag/v8.4.201
3. **가설:** archive path, class map, sample hash를 manifest에 넣지 않으면 동일 config 이름이 다른 materialized dataset을 가리킬 수 있다.
4. **MVP/기준선/데이터:** 격리 cache에서 canonical YAML과 legacy path를 dry-run으로 resolve하고 class count·sample hash·split count를 비교한다.
5. **성공·실패 metric:** resolved path identity, class map equality, sample-hash overlap; 하나라도 다르면 same-dataset claim을 KILL한다.
6. **compute:** 1/5. **novelty risk:** 2/5.
7. **negative result 가치:** 완전 일치면 최소 provenance manifest의 효용을 검증한다.
8. **4–8주 논문화:** 2/5. broader dataset artifact audit의 구성 요소로는 가치가 있다.
