## Q1. Tentative track의 공유 sentinel ID가 tracking·counting 평가를 얼마나 왜곡하는가?

1. **문제 정의:** tracker가 아직 확정하지 않은 여러 객체에 같은 negative `tracker_id`를 부여할 때, temporal smoother가 이를 한 객체의 history로 합치는 현상을 평가한다.
2. **왜 지금 가치가 있는가:** Supervision PR #2926은 `-1` ID를 공유한 서로 다른 두 box가 하나의 평균 box가 되어 하나의 detection이 사라지는 예시를 공개했다. [공식 PR #2926](https://github.com/roboflow/supervision/pull/2926)
3. **직접 근거:** PR은 두 unconfirmed object가 하나의 row로 반환되던 전후 동작을 제시한다. PR 페이지는 현재 open이지만, 동일 동작은 0.31.6 릴리스 노트에 수정 사항으로 기록되어 있다. [공식 릴리스](https://github.com/roboflow/supervision/releases)
4. **핵심 가설:** tentative-track 구간을 포함하면 detector AP가 그대로여도 count error와 early-life ID error가 커지며, 교통·UAV·해상 영상처럼 객체 출현/소멸이 잦은 slice에서 효과가 집중된다.
5. **최소 실험(MVP):** 30개 짧은 clip에서 raw detection은 고정하고, (a) negative-ID filter, (b) 기존 smoothing, (c) unconfirmed pass-through를 paired 비교한다.
6. **baseline·dataset:** ByteTrack 또는 동등 tracker + MOT17 validation의 초기 10-frame slice; 작은 객체 조건은 VisDrone-MOT 또는 UAVDT의 공개 validation subset으로 별도 층화한다.
7. **성공/실패 metric:** frame count error, tentative-to-confirmed transition recall, false merge rate, IDF1/HOTA의 tentative-inclusive·confirmed-only 차이. tracker parameter와 detector input size가 다르면 **not strictly apples-to-apples**다.
8. **compute 난이도:** **2/5** — pretrained detection 결과와 offline tracking만으로 시작할 수 있다.
9. **novelty 위험:** 특정 library regression test에 그칠 수 있다. 여러 tracker의 ID convention과 tentative-state metric을 공통 taxonomy로 만들어야 한다.
10. **4–8주 내 논문화 가능성:** **중간** — aerial/traffic/maritime의 object-birth slice에서 evaluator protocol 차이를 보이면 diagnostic note가 가능하다.
11. **negative result의 결론:** 세 조건에서 count·ID metric이 안정적이면 shared sentinel handling은 해당 smoother의 구현 결함으로 범위를 좁힐 수 있다.
12. **점수:** novelty **4/5**, feasibility **5/5**, compute efficiency **5/5**, publication potential **3/5**.

## Q2. 빈 frame API contract가 video benchmark에서 보이지 않는 evaluation censoring을 줄이는가?

1. **문제 정의:** pose/grounding pipeline이 empty result를 `None`으로 표현하는 경우와 shape-preserving empty tensor로 표현하는 경우가 전체 video evaluation의 완료율과 failure slice를 어떻게 바꾸는지 측정한다.
2. **왜 지금 가치가 있는가:** Supervision 0.31.6은 사람 없는 frame에서 `KeyPoints.empty()`의 confidence 관련 값이 `None`이라 filter가 `TypeError`를 내고 selection이 `IndexError`를 내던 문제를 empty array로 바꿨다. [공식 릴리스](https://github.com/roboflow/supervision/releases)
3. **직접 근거:** 릴리스는 empty frame에서의 전후 예외와 출력 shape를 명시하지만, benchmark-level 완료율 또는 score 영향은 제공하지 않는다.
4. **핵심 가설:** “empty but valid”를 type-stable하게 표현하지 않는 evaluator는 사람 부재·occlusion 구간을 조용히 drop하거나 crash로 중단해, event-heavy video의 성능을 과대평가할 수 있다.
5. **최소 실험(MVP):** 사람 없음/한 명/다수/완전 occlusion 각 25 frame으로 fixture를 만들고, legacy `None` adapter와 empty-array adapter의 exception, skipped-frame, aggregate metric을 비교한다.
6. **baseline·dataset:** ViTPose 또는 공개 pose connector + PoseTrack 또는 COCO keypoint video-like ordered sample; inference output은 저장해 adapter만 교체한다.
7. **성공/실패 metric:** exception rate, skipped-frame ratio, frame coverage, empty-class false positive, coverage-adjusted AP. 동일 raw output을 쓰지 않으면 모델 비교가 되어 **not strictly apples-to-apples**다.
8. **compute 난이도:** **1/5** — 저장된 prediction과 작은 fixture로 가능하다.
9. **novelty 위험:** 단순 API hygiene로 보일 수 있다. evaluation censoring과 event-conditioned bias를 수치로 보이지 못하면 연구 기여가 약하다.
10. **4–8주 내 논문화 가능성:** **중간** — pose 외 detection/segmentation/grounding adapter에도 동일 contract failure를 보이면 재현성 연구로 확장된다.
11. **negative result의 결론:** legacy와 type-stable adapter의 coverage-adjusted score가 같으면, 해당 fix는 reliability engineering의 가치로 한정할 수 있다.
12. **점수:** novelty **4/5**, feasibility **5/5**, compute efficiency **5/5**, publication potential **3/5**.

## Q3. Result parser의 label provenance를 고정하지 않으면 open-vocabulary detection 비교가 틀어지는가?

1. **문제 정의:** 같은 raw model output에 대해 parser가 `id2label` 또는 text query/`text_labels`를 어떤 이름·class ID로 해석하는지가 open-vocabulary detection의 per-class analysis를 바꾸는지 검증한다.
2. **왜 지금 가치가 있는가:** Supervision 0.31.6은 Grounding DINO result loading, RF-DETR segmentation result loading, OWL-ViT/OWLv2/OmDet-Turbo class naming을 수정했으며 OWLv2 detection에 text label 기반 실제 class name을 쓰도록 했다. [공식 릴리스](https://github.com/roboflow/supervision/releases)
3. **직접 근거:** 릴리스는 parser의 변경 사항을 명시하지만, COCO/LVIS 등 실제 benchmark에서 per-class AP나 vocabulary expansion 결과가 얼마나 바뀌는지는 제시하지 않는다.
4. **핵심 가설:** query index, model `id2label`, matched phrase가 서로 다를 때 overall box AP는 유지되어도 semantic confusion matrix·negative-transfer 진단은 달라진다.
5. **최소 실험(MVP):** Grounding DINO와 OWLv2의 raw output 200개를 legacy/current parser로 각각 변환하고, class ID/name, phrase-to-box alignment, per-query precision을 비교한다.
6. **baseline·dataset:** COCO validation의 20-class prompt set과 LVIS rare-class subset; 동일 checkpoint, tokenizer, prompts, threshold, raw logits를 고정한다.
7. **성공/실패 metric:** label disagreement rate, phrase–box alignment, per-class AP delta, rare/common confusion shift, raw-box invariant rate. prompt vocabulary가 다르면 **not strictly apples-to-apples**다.
8. **compute 난이도:** **2/5** — inference 1회 후 parser replay가 대부분이다.
9. **novelty 위험:** naming cleanup으로 보일 수 있다. label provenance manifest와 OVD negative-transfer analysis의 민감도를 함께 보여야 한다.
10. **4–8주 내 논문화 가능성:** **중간~높음** — 여러 framework의 parser와 multiple query templates로 reproducibility benchmark를 구성하면 가능하다.
11. **negative result의 결론:** parser 간 semantic mapping과 per-class analysis가 안정적이면, fix는 user-facing naming 개선으로 한정할 수 있다.
12. **점수:** novelty **4/5**, feasibility **4/5**, compute efficiency **4/5**, publication potential **4/5**.

## Q4. 정성 시각화의 renderer version이 human error audit의 결론을 바꾸는가?

1. **문제 정의:** grayscale/BGRA/Pillow palette scene, integer box와 narrow-integer mask shift에서 annotation renderer의 버전 차이가 사람이 판정하는 false positive/false negative와 failure taxonomy를 바꾸는지 측정한다.
2. **왜 지금 가치가 있는가:** Supervision 0.31.6은 해당 rendering 경로의 color, label, box/mask 관련 오류를 수정했다. [공식 릴리스](https://github.com/roboflow/supervision/releases)
3. **직접 근거:** 릴리스는 기존의 검은 palette label, grayscale annotation `TypeError`, integer box wrap 및 mask shift crash를 설명하지만, human audit 영향은 저자 주장에 포함되지 않는다.
4. **핵심 가설:** raw detection tensor가 같아도 overlay가 잘못되면 annotator는 localization failure 또는 class confusion을 과잉 보고하며, low-light/thermal-like grayscale 자료에서 편향이 커진다.
5. **최소 실험(MVP):** raw predictions 100개를 legacy/current renderer로 각각 출력해 blinded reviewer가 failure type을 분류하게 하고, raw tensor 기준 판정과 일치도를 비교한다.
6. **baseline·dataset:** COCO grayscale-converted fixture, BGRA fixture, palette fixture 및 fixed detection output; 필요하면 low-light 공개 subset을 보조 분석으로 쓴다.
7. **성공/실패 metric:** renderer crash rate, overlay hash stability, reviewer agreement, raw-tensor-consistent audit accuracy, failure-label transition matrix.
8. **compute 난이도:** **1/5** — model inference 없이 fixture rendering과 소규모 audit으로 가능하다.
9. **novelty 위험:** human study 표본이 작으면 일반화가 어렵다. raw tensor 판정 규칙과 blinded protocol을 사전에 고정해야 한다.
10. **4–8주 내 논문화 가능성:** **낮음~중간** — VLM/vision audit tooling의 representation-bias study로 확장할 때만 독립 논문화 가능성이 있다.
11. **negative result의 결론:** reviewer의 분류가 renderer와 무관하면, 이 fix는 presentation correctness 문제로 한정된다.
12. **점수:** novelty **3/5**, feasibility **5/5**, compute efficiency **5/5**, publication potential **2/5**.

## Q5. Hardware capability와 compiler version이 low-precision 연구 결과의 선택 편향을 만드는가?

1. **문제 정의:** NVFP4 fake-quantization의 성공 여부가 calibration data나 model architecture보다 GPU compute capability·Triton·container 조합에 의해 먼저 결정되는 범위를 지도화한다.
2. **왜 지금 가치가 있는가:** NVIDIA ModelOpt 0.47.1은 Triton 3.9/PyTorch 26.11 container에서 compute capability 8.9 이상 GPU의 `NVFP4_DEFAULT_CFG`가 removed block-pointer API 오류로 실패하던 문제를 수정했다. [공식 릴리스](https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.47.1)
3. **직접 근거:** 공식 릴리스에는 정확한 error와 대상 조건이 있으나, 수정 전후 model quality·latency·여러 GPU의 결과는 제공되지 않는다.
4. **핵심 가설:** low-precision 논문/benchmark에서 성공한 hardware profile만 남기면, method quality가 아니라 toolchain availability가 algorithm ranking과 reported feasibility를 선택 편향시킬 수 있다.
5. **최소 실험(MVP):** 고정 작은 vision encoder와 tensor shape에 대해 ModelOpt 0.47.0/0.47.1 × Triton 3.9/다른 지원 버전 × available compute capability를 manifest와 함께 matrix로 기록한다.
6. **baseline·dataset:** fixed pretrained vision encoder와 100-image calibration slice; 같은 seed, config, tensor shape, container digest를 고정한다.
7. **성공/실패 metric:** build/run success rate, exception taxonomy, calibration output max-absolute difference, post-quant top-1 delta, latency와 peak memory. GPU가 다르면 latency 비교는 **not strictly apples-to-apples**다.
8. **compute 난이도:** **3/5** — 여러 GPU 또는 CI runner가 있으면 커지지만, 첫 smoke test는 작다.
9. **novelty 위험:** compatibility matrix만으로는 systems bug report에 머문다. outcome-conditioned missingness와 ranking bias를 보여야 한다.
10. **4–8주 내 논문화 가능성:** **중간** — vision/VLM quantization benchmark에 reproducibility manifest와 missingness correction을 결합할 때 가능하다.
11. **negative result의 결론:** 모든 환경에서 0.47.1 이후 같은 성공·정확도 경향을 보이면, 해당 failure는 특정 legacy toolchain regression으로 제한된다.
12. **점수:** novelty **4/5**, feasibility **3/5**, compute efficiency **3/5**, publication potential **3/5**.
