## 1. OmniCapBench — 긴 비디오 캡션을 “글”이 아니라 검증 가능한 구조로 평가

**공식 원문:** [arXiv](https://arxiv.org/abs/2610.12458) · [Project](https://01yzzyu.github.io/OmniCapBench/)

### 무엇이 바뀌었나

**확인된 사실:** 786개 비디오, 총 12.8시간에 대해 5,818개 entity reference, 6,537개 audio event, 11,419개 shot, 39,160개 subshot을 주석화했다. 출력은 자유 형식 문장 대신 `References`, `Shots`, `Events`로 구성된 atomic JSON track이며, ID 유효성·시간 범위·상호 참조는 결정론적으로 검사한다. 의미 일치는 제한된 범위에서 LLM judge를 사용한다.

**확인된 사실:** 동일 예측을 약한 judge와 강한 judge로 채점했을 때 global 평가가 각각 71.24와 93.92로 달라졌다. 저자들이 만든 200개 hard-to-distinguish subset에서는 전통 metric의 선호가 거의 50:50인 반면 구조 기반 평가는 인간 audit의 선호와 74.2:25.8로 정렬됐다.

**저자 주장:** 장문 비디오 이해에서는 유창한 문장 유사도보다 누가·언제·무엇을 했는지 분해한 구조가 오류 위치를 더 안정적으로 드러낸다.

### 비교 조건 점검

- Gemini 3.1 Pro는 schema-valid generation 97.36, reference use 70.39, cross-component consistency 34.43, event semantic alignment 51.46을 기록했다.
- 공개 모델 Qwen3 Omni Instruct는 각각 89.02, 9.85, 13.33을 기록했다. MiniCPM-o 2.6의 event semantic alignment는 2.46이었다.
- 자유 형식 출력을 잘 만드는 모델은 엄격한 schema 생성에서 불리할 수 있다.
- 원본 비디오는 일괄 재배포되지 않고 annotation과 download script를 제공하므로, 원천 영상의 가용성과 라이선스를 재현성의 일부로 봐야 한다.
- 모델별 입력 길이·샘플링·오디오 처리 조건이 완전히 동일한지 확인하지 않고 총점만 비교하면 **not strictly apples-to-apples**다.

### 진단 → 가설 → 최소 실험

- **진단:** 장문 영상 요약의 실패 원인을 하나의 caption score로는 찾기 어렵다.
- **가설:** 해양 감시 영상도 `객체–시간구간–행동–근거 프레임` 구조로 출력하면 hallucination과 temporal mismatch를 분리할 수 있다.
- **최소 실험:** 해무·선박 영상 20개에 대해 자유 형식 캡션과 JSON event track을 각각 생성한다. schema validity, object reference recall, 시간 IoU, 근거 프레임 일치율을 따로 기록한다.

**판정:** 바로 도입할 가치가 높다. 새 모델보다 먼저 평가 출력 형식을 구조화하는 변화다.

## 2. FastBench — streaming VLM은 frame 수보다 “언제 보고 무엇을 기억하는가”가 핵심

**공식 원문:** [arXiv](https://arxiv.org/abs/2610.12427) · [GitHub](https://github.com/Ashone3/FastBench)

### 무엇이 바뀌었나

**확인된 사실:** 300개 clip, 306개 QA, 총 3.77시간으로 구성되며 forward·instant·backward temporal scope와 6개 능력, 8개 domain을 평가한다. 766개 원본 영상에서 33,619개 clip과 16,702개 후보 QA를 만든 뒤 이중 검증과 세 차례 인간 검토를 거쳐 306개를 남겼다.

**확인된 사실:** 공통 입력 예산은 1080p 120 frame에 해당하는 248,832,000 pixel이다. 1초 chunk의 streaming 환경에서 evidence interval보다 일찍 또는 늦게 답하면 0점이며, 늦은 답에는 최대 4초의 완화 창도 별도 평가한다.

**확인된 사실:** 기본 설정에서 Gemini 3.5 Flash 50.7, JoyAI-VL 8B 44.1, Qwen3-VL 8B 32.9였다. ProactiveFrame은 Qwen3-VL을 38.3으로 5.4%p 올렸지만 Gemini는 52.2로 1.5%p 상승하는 데 그쳤다. Gemini의 predictive/causal은 5.9%p, motion/spatiotemporal은 6.8%p 하락했고 Qwen의 instant도 2.2%p 하락했다.

**저자 주장:** 균일 frame sampling은 현재 장면을 자세히 볼수록 과거 문맥을 압축해 잃는 trade-off가 있으며, 능동적 frame 선택도 모든 task에 일관되게 유리하지 않다.

### 비교 조건 점검

- Qwen3-VL은 2 FPS 32.9에서 24 FPS 44.6으로 올랐지만 고 FPS에서 포화한다.
- Mixed-FPS oracle은 Qwen 40.7, Gemini 57.5였고, Qwen의 full 30 FPS는 42.1이었다. 높은 순간 해상도와 긴 history 보존을 별도 축으로 봐야 한다.
- dataset은 306문항으로 작고 sports 29.08%, games 18.63%, arts 16.01%에 치우쳐 있다.
- streaming 전용 모델의 native wait token과 일반 모델에 prompt로 대기 행동을 유도한 결과는 **not strictly apples-to-apples**다.
- 정답 판정에 LLM judge가 포함되므로 judge 교체 민감도도 함께 보고해야 한다.

### 진단 → 가설 → 최소 실험

- **진단:** 해양 영상에서 일정 FPS를 유지하면 장시간 표류·접근 같은 느린 사건의 history가 사라질 수 있다.
- **가설:** 저주파 history buffer와 고주파 recent window를 결합하면 같은 pixel budget에서 조기 경보와 현재 객체 인식이 함께 좋아진다.
- **최소 실험:** 동일 120-frame 예산으로 `uniform`, `최근 구간 집중`, `1 FPS history + 8 FPS recent` 세 정책을 비교한다. event recall, 평균 조기 탐지 시간, late-answer rate, GPU latency를 기록한다.

**판정:** 성능 순위보다 sampling policy audit에 가치가 크다. 실시간 VLM을 쓴다면 필수 확인 항목이다.

## 3. Pumpire — metric 3D를 sensor depth가 아니라 실제 거리로 검증

**공식 원문:** [arXiv](https://arxiv.org/abs/2610.12423) · [Project](https://pumpire.github.io/)

### 무엇이 바뀌었나

**확인된 사실:** pumpire-6k는 실내 40개, 실외 60개 장면의 6,400 frame으로 구성된다. 장면마다 64 frame, 정렬 depth, camera intrinsics, 표식 좌표와 줄자로 측정한 point-pair 실제 거리를 제공한다. 총 29개 설정에서 image/video metric depth estimation과 depth completion을 평가한다.

**확인된 사실:** metric은 absolute error, relative error, log error, δ1.05/1.10/1.25와 view 간 relative scale deviation이며 scene-level macro average를 사용한다.

**확인된 사실:** depth sensor가 정상인 76개 장면에서 raw depth는 AE 0.026, RSD 0.062, δ1.25 98.66이었지만, 어려운 24개 장면에서는 AE 4.047, RSD 0.887, δ1.25 36.72로 무너졌다. 이 어려운 split은 sensor RSD 0.1 초과를 기준으로 구성됐다.

**확인된 사실:** image estimation에서 Metric3D v2는 정상 조건 AE 0.073으로 1위였지만 어려운 조건 AE 1.126, 평균 순위 4였다. 어려운 조건에서는 Depth Pro AE 0.171, MoGe-3 AE 0.158이었다. Video estimation에서는 Depth Anything 3가 정상 AE 0.078, 어려운 조건 AE 0.167로 강했다.

**저자 주장:** sensor depth 자체를 정답처럼 쓰면 반사·투명체·장거리 등 sensor 실패 영역에서 metric scale 능력을 잘못 평가할 수 있다.

### 비교 조건 점검

- estimation 모델은 예측 또는 canonical intrinsics를 쓰지만 completion 모델은 GT intrinsics와 sensor depth를 입력으로 받으므로 두 설정의 순위는 **not strictly apples-to-apples**다.
- 어려운 split이 sensor reliability로 정의돼 실제 optical difficulty와 특정 sensor failure가 섞일 수 있다.
- 평균 AE만으로는 장면 간 scale consistency를 놓치므로 RSD를 함께 봐야 한다.
- 프로젝트 페이지는 공개됐지만 실행 환경과 전체 코드 공개 범위는 재현 전에 다시 확인해야 한다.

### 진단 → 가설 → 최소 실험

- **진단:** 해상 영상의 반사·안개·원거리 객체에서는 depth sensor 또는 pseudo-depth 자체가 평가 오차를 만든다.
- **가설:** 실제 거리 anchor가 소수라도 있으면 모델 오차와 sensor 오차를 분리해 maritime depth 모델의 calibration 실패를 찾을 수 있다.
- **최소 실험:** 부두·선박 장면 10개에서 각 5개 point-pair를 레이저 거리계나 지도 기반 기준값으로 측정한다. normal/fog/specular 조건별 AE와 RSD를 비교하고, sensor depth 기준 순위가 뒤집히는지 본다.

**판정:** metric 3D 실험의 ground truth 설계를 바꾸는 신호다. 센서 취약 조건을 별도 split으로 관리할 가치가 높다.

## 4. SpaceCast-Bench — 정적 공간 QA에서 장면 변화 이후 예측으로 이동

**공식 원문:** [arXiv](https://arxiv.org/abs/2610.12402) · [GitHub](https://github.com/ZJU-REAL/SpaceCast-Bench) · [Dataset](https://huggingface.co/datasets/hongxingli/SpaceCast-Bench)

### 무엇이 바뀌었나

**확인된 사실:** 182개 실제 장면, 3,862개 질문, 16개 task로 구성된다. 정적 perception, local prediction, global prediction의 세 단계에서 장면을 관찰하고 변환한 뒤 결과를 추론하는 `observe–transform–infer` 능력을 본다.

**확인된 사실:** 21개 모델 중 Gemini 3.5 Flash가 58.0으로 최고였고 인간은 87.2, random baseline은 25.9였다. 가장 강한 공개 weight 모델 Qwen3.5-27B는 39.3이었다. 공간 특화 모델은 25.7–29.1로 random에 가까웠다.

**확인된 사실:** bridge view를 제거하면 world-centric direction이 39.9에서 34.6으로 5.3%p 하락했다. 명시적 textual 3D metadata는 proprietary 모델에서 30.7%p, open-weight 모델에서 10.9%p 개선을 보였다.

**확인된 사실:** 600개 local-intervention 질문을 수동 audit했을 때 오답 중 image generation failure와 연결된 비율이 Qwen-Image-Edit 80.3%, GPT-image-2 38.3%였다. 즉 추론 점수에 생성 모델 실패가 섞인다.

**확인된 사실:** Qwen3-VL-4B는 staged SFT 후 in-domain 34.0에서 65.7로 올랐지만, 6개 OOD benchmark 평균은 33.5에서 38.1로 4.6%p 상승했다. MindCube에서는 0.3%p 감소했다.

### 비교 조건 점검

- in-domain 31.7%p 상승을 일반화 성능으로 해석하면 안 된다. OOD 개선은 4.6%p이며 benchmark별 편차가 있다.
- 생성된 결과 이미지를 증거로 쓰는 설정은 생성 실패와 공간 추론 실패를 분리해야 한다.
- textual 3D metadata는 추가 privileged evidence이므로 image-only 모델과 총점 비교가 **not strictly apples-to-apples**다.
- CoT는 일부 단계에 도움을 주고 다른 단계에는 손해를 보여, 일괄 적용보다 task별 ablation이 필요하다.

### 진단 → 가설 → 최소 실험

- **진단:** “현재 어디에 있는가”를 맞히는 모델이 물체 이동·카메라 이동 이후의 관계를 보존한다고 볼 수 없다.
- **가설:** 해양 VLM도 선박 이동 벡터와 카메라 heading을 명시적으로 제공하면 future relation prediction이 크게 개선되지만, 이미지 편집을 중간 증거로 쓰면 오류가 누적된다.
- **최소 실험:** 30개 선박 장면에서 `이미지만`, `이미지+heading`, `이미지+heading+간단한 3D 좌표`를 비교한다. 좌우·접근/이탈·가림·충돌 가능성 정확도와 변환 일관성을 측정한다.

**판정:** 공간 reasoning을 정적 QA 점수 하나로 보지 않게 만드는 benchmark다. world-centric 좌표를 쓰는 해양·UAV 연구와 직접 연결된다.

## 5. Versal 기반 선상 해양 객체 탐지 — AP에서 실제 통신·전력 운용 지표로 확장

**공식 원문:** [arXiv](https://arxiv.org/abs/2610.12182)

### 무엇이 바뀌었나

**확인된 사실:** 68개 Maxar 장면, 43개 선박 class, 30–70cm GSD를 사용했고 1,024×1,024 tile 13,967개로 구성했다. test set은 894개 tile, 1,596개 선박이며 잘린 객체 때문에 box는 1,649개다.

**확인된 사실:** YOLOX-S float 모델의 class-agnostic AP는 86.1, recall 83.8, F1 84.6이었다. Versal VCK190의 INT8 모델은 AP 81.4, recall 76.1, F1 80.9로 각각 4.7%p, 7.7%p, 3.7%p 하락했다. 상위 10개 class mAP는 68.9에서 59.0으로 9.9%p 감소했다.

**확인된 사실:** 6개 tile batch에서 tile당 17.13ms, 61 Mpixel/s, 평균 장면 5.6초, board power 30.4W, tile당 0.52J, 장면당 170J를 보고했다. 저장장치 읽기 시간은 제외됐고, 입력은 raw sensor가 아니라 보정된 지상 영상이다.

**확인된 사실:** confidence 0.10에서 crop 전송은 전체 데이터의 2.8%로 줄지만 full-quality vessel 83%, lost vessel 17%였다. tile 전송은 28.7%의 데이터로 vessel 98%, lost 2%였다. 선택적 coding의 가정상 CR4는 27.1% 데이터로 선박 유실은 없었지만 17%는 압축된 background에만 남았다.

**저자 주장:** on-board detector를 최종 판정기보다 전송 우선순위 결정기로 사용하면 대역폭을 줄이면서 대부분의 관심 객체를 보존할 수 있다.

### 비교 조건 점검

- spatial 80/10/10 split을 썼지만 중심 tile이 block 경계를 넘을 수 있어 동일 선박이 둘 이상의 subset에 등장할 수 있다고 원문이 명시한다. 이는 AP를 낙관적으로 만들 수 있는 leakage 위험이다.
- 항구·연안 밀집 장면 중심 결과이며 open sea에 그대로 일반화되지 않는다.
- 압축률은 실제 codec 실측이 아니라 가정값을 적용했다.
- 한 application과 한 DPU configuration의 결과이며 storage I/O를 제외했다.
- float와 INT8의 입력·post-processing은 가깝지만 hardware pipeline과 class별 calibration 차이가 있으므로 전체 AP만으로 품질을 요약하면 안 된다.

### 진단 → 가설 → 최소 실험

- **진단:** 양자화 후 전체 AP 4.7%p 하락보다 recall 7.7%p, 상위 class mAP 9.9%p 하락이 실제 선박 유실 위험을 더 잘 나타낸다.
- **가설:** class별 quantization calibration과 tile-level 전송을 결합하면 crop 방식보다 대역폭은 더 쓰더라도 소형 선박 recall을 안정적으로 보존할 수 있다.
- **최소 실험:** 보유 해양 데이터 200 tile에서 float/INT8을 비교한다. 전체 AP, 소형 객체 recall, class별 recall, ECE, tile 전송 비율, full-quality vessel 보존률, latency·energy를 한 표에 기록한다. split은 원본 장면 단위로 고정해 tile leakage를 막는다.

**판정:** Woojin의 해양 CV에 가장 직접적인 오늘의 신호다. 모델 정확도와 통신 설계를 같은 실험에서 다뤄야 한다.

## 오늘의 benchmark signal 3개

1. **평가 구조가 모델 구조만큼 중요하다.** 자유 문장→원자 event track, 평균 depth→실거리 anchor, 정적 QA→변환 후 예측으로 평가 단위가 바뀌고 있다.
2. **운용 조건을 숨긴 단일 점수는 위험하다.** frame timing, judge 선택, sensor failure, 생성 실패, INT8 양자화가 순위를 바꾸거나 실제 유실을 만든다.
3. **추가 evidence의 효과를 모델 능력으로 섞지 말아야 한다.** GT intrinsics, textual 3D metadata, bridge view, 높은 FPS, corrected imagery는 모두 별도 실험 축이다.

## Woojin 연구와의 직접 연결

## 실행 우선순위

1. **오늘:** 해양 detector의 float/INT8 비교표에 class별 recall과 vessel 보존률을 추가한다.
2. **이번 주:** scene-level split 검증기를 만들어 tile overlap과 동일 객체 누출을 검사한다.
3. **다음 실험:** 120-frame 고정 예산에서 uniform과 history+recent sampling을 비교한다.
4. **데이터 수집 시:** 저시정·반사 조건에 실제 거리 anchor를 소량이라도 남긴다.
5. **VLM 평가 시:** 응답을 `entity–event–time–evidence` 구조로 저장해 오류 위치를 추적한다.
