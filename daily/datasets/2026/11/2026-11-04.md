## 1. DUMAL — frame 수가 아니라 독립 영상 수를 split 단위로 삼아야 함

**확인된 사실.** DUMAL(Detecting Underwater Megafauna Around Longline fishing gear)은 지중해의 instrumented pelagic longline에서 기록한 55개 독립 영상으로부터 60,870개 주석 프레임과 9개 종의 94,101개 bounding box를 제공한다. 공개 record에는 COCO·YOLO annotation, `data.yaml`, ablation split과 train/val/test image artifact가 있으며, CC BY 4.0으로 표시된다. 저자들은 train/test를 영상 단위로 분리했다고 설명한다.  
출처: https://doi.org/10.7910/DVN/QM19AI

**저자 주장.** 두 inter-annotator 연구에서 localization-only mean IoU 0.811, detection-and-localization mean IoU 0.605, class label Cohen’s κ 0.86을 보고한다. 여덟 detector 구성의 분석에서는 일반화가 instance 수보다 각 class가 나타나는 서로 다른 training video 수에 크게 좌우된다고 주장한다. 이는 저자 평가이며 이번 실행에서 독립 재현하지 않았다.

**dataset/split/license/artifact/bias.** task는 underwater megafauna detection이고, split은 frame-random이 아니라 video-level이다. 공개 artifact·license는 확인했지만, 다른 해역·장비·계절·어업 방식으로의 일반화는 이 record만으로 보장되지 않는다. 고정 카메라와 연속 frame은 동일 영상 내부 near-duplicate와 배경 shortcut을 만들 수 있으므로, 다른 maritime benchmark와는 **not strictly apples-to-apples**다.

**진단 → 가설 → 최소 실험.**
- 진단: frame-random split은 같은 영상의 temporal neighbor를 양쪽에 둘 수 있어 detector가 생물체보다 배경·장비·촬영 조건을 기억할 위험이 있다.
- 가설: class별 독립 video 수를 맞춘 group split에서만 성능의 실질적 data-diversity 효과를 측정할 수 있다.
- 최소 실험: 공식 video split을 기준으로 (1) frame-random, (2) video-group, (3) video-group+temporal near-duplicate 제거를 5 seed로 비교한다. mAP뿐 아니라 class별 unique-video 수, per-video false positive, pHash/embedding near-duplicate edge 수를 함께 기록한다.
- **GO:** video-group 조건에서도 class별 gain과 per-video calibration 개선이 유지될 때. **KILL:** frame-random에서만 gain이 나거나 test video와 train video의 near-duplicate가 발견될 때.

## 2. X-AnyLabeling v4.3.0–v4.3.1 — relation/attribute label은 schema version 없이는 학습 데이터가 아님

**확인된 사실.** 공식 changelog는 v4.3.0(11월 1일)에 AI-assisted object-level multi-task attribute annotation, canvas review-status control, export output-directory 수정이 추가됐고, v4.3.1(11월 3일)에 remote model prediction을 지원하는 directed relation annotation과 cell label이 있는 adjustable image grid가 추가됐다고 기록한다. 도구는 GPL-3.0이며 image/video/point-cloud/multimodal annotation을 지원한다고 저장소가 설명한다.  
출처: https://github.com/CVHub520/X-AnyLabeling/blob/main/CHANGELOG.md  
출처: https://github.com/CVHub520/X-AnyLabeling

**범위의 구분.** 이는 공개 benchmark나 고정 dataset release가 아니다. 따라서 dataset 규모·고정 split·benchmark license는 **해당 없음**이며, 원래 데이터의 license와 export contract를 따로 확인해야 한다. Changelog만으로 relation class ontology, direction convention, export mapping, remote-prediction provenance가 특정 표준과 호환된다고 말할 수 없다.

**해석.** attribute와 directed relation을 도입하면 label의 정보량은 늘지만, annotator가 바뀌거나 predicate 방향·누락 policy가 바뀐 순간 과거 export와 같은 task label이 아닐 수 있다. 특히 remote prediction을 pre-label로 쓸 경우 human edit 여부와 model/version을 남기지 않으면 오류와 자동 생성 label을 분리할 수 없다.

**진단 → 가설 → 최소 실험.**
- 진단: relation edge의 방향 오류·self-loop·ontology drift는 object detection mAP에 나타나지 않아 training 후에야 발견될 수 있다.
- 가설: annotation record에 `schema_version`, `predicate`, `source(manual/model)`, `model_revision`, `review_state`, `export_hash`를 고정하면 relation task의 회귀를 조기에 잡을 수 있다.
- 최소 실험: 50 image/10 relation-pair의 작은 set을 수동-only와 remote-prelabel+review로 이중 annotation한다. direction agreement, invalid edge rate, reviewer acceptance, export/import round-trip loss를 측정하고, schema migration 전후 JSON diff를 보관한다.
- **GO:** direction agreement ≥ 사전 설정 기준, round-trip loss 0, model-prelabel과 manual label의 source 분리가 100%일 때. **KILL:** export에서 direction 또는 review provenance가 사라지거나 annotation convention이 문서화되지 않을 때.

## 오늘의 GO/KILL

- **GO:** maritime/video dataset은 image ID가 아니라 video/recording/source ID를 split manifest의 1급 필드로 둔다.
- **GO:** relation·attribute annotation은 schema version과 provenance가 있는 경우에만 training corpus로 합친다.
- **KILL:** frame-random score, 불명확한 relation direction, remote pre-label을 품질 검증 없이 benchmark 결론으로 사용한다.

## 한계

- DUMAL의 annotation agreement와 detector 분석은 공개 record의 저자 주장이다. 이번 실행에서 파일 checksum, annotation parser, model 재현을 실행하지 않았다.
- X-AnyLabeling의 changelog는 기능 추가를 증명하지만, 그 기능이 특정 dataset의 annotation quality를 향상시킨다는 실증은 아니다.
- 이번 창에는 조건을 모두 갖춘 3번째 사례를 확인하지 못해 수를 억지로 채우지 않았다.
