## 핵심 사례 — Ultralytics brain-tumor assets label 누락 보고

- **사실:** Ultralytics 공식 저장소의 open issue #27066은 brain-tumor.zip assets release v0.0.0의 train 이미지 15장에 대응 label file이 없다고 보고한다. 작성자는 shell loop으로 이미지 basename과 labels/train file의 불일치를 출력하는 최소 재현 명령을 제공했다.
- **커뮤니티 보고:** 작성자는 비전문의이며 인접 scan slice와 눈으로 비교해 누락 이미지에 병변이 보인다고 말한다. 이는 의료 annotation의 독립 검증이 아닌 사용자 관찰이다.
- **가능한 mechanism:** YOLO 형식에서 label file 부재가 background로 해석되면 병변이 실제 존재하는 이미지가 negative supervision을 제공할 수 있다. 단, 해당 이미지가 의도적으로 negative인지, format/parsing 문제가 있는지는 이슈만으로 결론낼 수 없다.
- **규모·task·split·artifact:** 보고의 단위는 train split의 15개 JPEG와 대응 text annotation file이다. object detection annotation issue이며, issue가 링크한 artifact는 Ultralytics assets release v0.0.0 zip이다.
- **license·access:** 이슈 원문은 data-specific license 또는 commercial-use 조건을 제시하지 않는다. code repository license를 dataset license로 전용하지 않는다.
- **bias·benchmark 호환성:** missing-label examples가 특정 patient/scan/lesion-size family에 몰려 있다면 class prevalence와 false-negative rate를 편향시킬 수 있다. split 및 patient-level identity policy가 확인되지 않아 다른 brain-tumor benchmark와의 직접 비교는 **not strictly apples-to-apples**다.
- **진단:** 지금 필요한 것은 detector 재학습이 아니라 annotation integrity 확인이다.
- **가설:** 15개 image가 실제 positive인데 empty label로 처리됐다면, 동일 lineage/scan에서 recall과 calibration이 더 크게 흔들릴 수 있다.
- **최소 audit:** archive hash와 image count를 기록한 뒤, filename 15개에 대해 (a) label file 존재, (b) parse 가능한 box 수, (c) independent qualified annotator의 blinded 판독, (d) patient/scan-group membership을 검사한다. 이후 group-aware validation에서 original, exclusion, corrected-label 세 처리를 비교한다.
- **GO/KILL:** 두 명 이상의 적격 검토 또는 공식 corrected artifact가 positive label 누락을 확인하고 correction이 unseen scan-group의 recall/precision trade-off를 개선하면 repair experiment를 GO한다. annotation policy가 negative임을 보이거나 검토가 불일치하면 label repair와 결함 주장은 KILL하고 issue를 watchlist로만 둔다.

## 진단 → 가설 → 최소 실험

- **관찰:** 공식 issue는 filename 수준의 missing-file 재현을 제공하지만 clinical truth와 split policy는 제공하지 않는다.
- **진단:** file-system completeness와 semantic annotation correctness는 별개의 검증 단계다.
- **가설:** training signal의 오류가 있다면 random image split보다 scan/patient-group heldout에서 부정적 효과가 더 잘 드러난다.
- **최소 실험:** 원본/제외/수정 세 데이터 처리로 같은 seed·augmentation·input size를 고정해 group-heldout recall, precision, false-positive rate, calibration을 비교한다.
- **반증:** independent review가 병변을 확인하지 못하거나 group-heldout 차이가 없으면 이슈를 performance cause로 해석하지 않는다.

## 오늘의 GO / KILL

- **GO:** public dataset을 받을 때 image–label manifest, zero-box rate, missing-file rate, group-level imbalance를 사전 audit하는 checklist에 이 사례를 추가한다.
- **GO:** data lineage를 hash와 scan/patient group으로 보존해 annotation repair 전후를 재현 가능하게 만든다.
- **KILL:** 이슈 작성자의 시각적 판단만으로 의료 label을 새로 만들거나, 15개 사례를 근거로 benchmark 전체 품질을 단정하지 않는다.
- **KILL:** 새 revision이 없는 V-Thinker artifacts를 어제와 같은 내용으로 재커밋하지 않는다.
