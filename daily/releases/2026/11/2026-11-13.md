## 1. Supervision 0.31.7 — small-object mAP의 evaluator drift

**버전·배포 사실:** 11월 12일 03:57:37 KST 발행. tag가 가리키는 commit은 `40e86d6714bb1bbf897ba72821f5546808612357`이다. 새 weight·dataset이 아니라 평가/후처리 라이브러리 release다. [공식 release](https://github.com/roboflow/supervision/releases/tag/0.31.7)

**변경과 주장:** prediction의 `data["area"]` 대신 box/mask/OBB geometry로 면적을 계산하고 target area는 float64로 읽는다. OBB의 `iscrowd` 처리는 COCO crowd IoU를 사용한다. [PR #2939](https://github.com/roboflow/supervision/pull/2939)는 거짓 면적 metadata가 false positive의 크기 bucket을 이동시키고, float32 반올림이 경계 target을 두 bucket에 넣는 원인을 설명한다. PR의 parity 수치와 테스트 통과 수는 저자 제공 결과이며 여기서 재실행하지 않았다.

**논문 주장과 artifact의 간극:** 작은 물체 AP가 오르더라도 representation이나 detection head가 개선됐다는 증거가 아니다. 동일 prediction이라도 evaluator 버전과 면적 정책이 다르면 **not strictly apples-to-apples**다.

**배포 조건:** MIT; Python ≥3.10, NumPy ≥1.21.2, SciPy ≥1.10. `pip install supervision==0.31.7`은 설치 후보이며 dependency 전체 lock은 아니다. wheel과 sdist가 있고 새 학습 data/weight는 없다. CPU fixture로 검증할 수 있어 GPU는 필요하지 않으며 VRAM 요구량은 해당하지 않는다. [버전별 metadata](https://github.com/roboflow/supervision/blob/0.31.7/pyproject.toml)

**무결성:** GitHub API가 제공한 wheel SHA256은 `25d05d0c45fe61d63426f3dfaf40145c567be78a618da3abfe1f1b7be8edba91`이다. 실제 파일을 다운로드해 대조하지 않았고 별도 attestation 검증도 하지 않았다.

**Issue/PR 활동:** #2939는 11월 11일 14:16:30 UTC에 merge됐다. 이 원인은 PR에 독립 Issue 없이 보고됐다고 명시돼 있다. release에는 OBB crowd 수정 #2941도 연결돼 있다. 독립 사용자 재현으로 취급하지 않는다.

**진단 → 가설 → 최소 개입 → 실험:** 고정 prediction에서 AP bucket만 변한다면 모델보다 면적 계산 경로가 원인일 수 있다. 10~30분 CPU 계획으로 0.31.6/0.31.7/pycocotools에 같은 box·mask JSON을 넣는다. geometry와 metadata 면적이 다른 false positive, 32²·96² 경계 바로 위아래 target, OBB crowd 내부 prediction을 각각 검사한다. checkpoint·split·resolution·pretraining·TTA는 고정하거나 학습 없는 fixture에 해당 없음으로 남기고 pycocotools 버전도 기록한다.

**GO/KILL:** 공식 reference와 bucket별 일치가 확인되면 evaluator migration 검토는 GO. 이전 수치와 새 수치를 모델 gain으로 직접 비교하는 것은 KILL. 차이가 남으면 최소 fixture와 버전을 먼저 보존한다.

## 2. Ultralytics v8.4.211 — 혼합 정밀도 export와 calibration 경계

**버전·배포 사실:** 11월 12일 08:09:15 KST 발행. annotated tag를 해석한 commit은 `d2b7876e79ad2e02fd77221622774b511a8f0cb3`이다. release asset은 SBOM이며 새 연구 checkpoint나 dataset release로 확인되지 않았다. [공식 release](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.211)

**저자 주장과 중요한 조건:** [PR #27150](https://github.com/ultralytics/ultralytics/pull/27150)은 ExecuTorch XNNPACK static INT8와 calibration을 추가하면서 detect/segment/pose/OBB head를 FP32로 유지한다. 개발자는 box와 score에 같은 INT8 scale을 적용하면 score가 소실된다고 설명한다. calibration에 각 행의 validation data를 사용했다고 명시하므로, 이 작은 검증표를 별도 calibration split을 가진 일반화 성능으로 해석할 수 없다.

**논문 주장과 artifact의 간극:** “INT8 지원”은 전체 연산이 INT8이거나 모든 task에서 빨라진다는 뜻이 아니다. PR에는 일부 task의 지연이 오히려 늘어난 개발자 측정도 있다. 별도 논문 성능을 이 export 결과가 재현했다는 근거는 확인하지 못했다. hardware·calibration data·head precision이 다르면 **not strictly apples-to-apples**다.

**배포 조건:** code license AGPL-3.0. base package는 Python ≥3.8이지만 새 INT8 경로는 `executorch>=1.6.0`이 필요하고 PR 측정은 torch 2.15.0 + ExecuTorch 1.6.0 조건이다. base 최소 버전만으로 export 호환성을 보장하지 않는다. 설치 후보는 `ultralytics==8.4.211`과 검증된 export stack의 별도 lock이다. CPU XNNPACK 검증을 제안하며 필수 GPU/VRAM 수치는 공식 release에서 확인하지 못했다. 기존 model weight와 calibration data를 따로 준비해야 한다. [버전별 metadata](https://github.com/ultralytics/ultralytics/blob/v8.4.211/pyproject.toml)

**무결성:** SBOM SHA256은 `b903d1d50135fcd6411cf2fb30b0ce0ea198806f2960620929157eb294c39663`이다. 이는 SBOM 파일의 digest이며 model weight checksum이 아니다. tag API의 서명 검증 상태는 `unsigned`다.

**Issue/PR 활동:** #27150는 11월 11일 16:45:51 UTC merge. release는 RT-DETR TensorRT INT8 수정 #26220도 연결한다. merged PR과 배포 tag 연결은 확인했지만 다양한 장치에서의 독립 재현은 미확인이다.

**진단 → 가설 → 최소 개입 → 실험:** score collapse가 representation 손실보다 head의 공통 quantization scale 때문이라는 가설을 검사한다. 10~30분 계획으로 같은 작은 checkpoint, input shape, batch=1을 고정해 FP32와 head-FP32 INT8를 export하고 1~10장으로 score/box, 산출물 크기, 반복 추론 시간을 대조한다. calibration과 평가 이미지를 분리하고 hardware·thread 수·warm-up·runtime을 기록한다. 완전 INT8 head 비교는 backend가 허용할 때만 별도 진단으로 수행한다.

**GO/KILL:** export→load→prediction이 성공하고 score 소실 없이 프로젝트의 기존 허용 오차·지연 예산을 만족하면 GO. 더 작은 파일만으로 정확도 유지·속도 개선을 선언하거나 validation calibration 표를 일반 benchmark로 사용하는 것은 KILL.

## 3. Diffusers v0.43.0 — 같은 인자여도 학습·cache 상태가 달라진다

**버전·배포 사실:** 11월 12일 14:22:22 KST 발행. annotated tag가 가리키는 commit은 `423ab90580b2847998591669b8326f47b6d14d8b`다. MiniMax-H3-Image, Pika H3 Flex, P-H3-Image, Kandinsky S2V, PAN2 통합을 포함한다. package 통합 시각을 각 model weight의 첫 공개 시각으로 간주하지 않는다. GitHub release asset은 없다. [공식 release](https://github.com/huggingface/diffusers/releases/tag/v0.43.0)

**관측과 원인:** [Issue #15178](https://github.com/huggingface/diffusers/issues/15178)은 일부 LoRA script에서 optimizer가 `filter` iterator를 소비해 이후 gradient clipping이 빈 iterator를 받는다고 보고한다. release는 해당 clipping 수정을 포함한다. 또 [PR #15212](https://github.com/huggingface/diffusers/pull/15212)는 예외 발생을 포함해 ModularPipeline 호출 뒤 stateful cache hook을 reset한다. checkpoint 저장 시 다른 variant shard 보존 수정도 포함한다.

**발생 시점 구분:** clipping Issue는 11월 4일 생성·5일 종료, cache PR은 11월 9일 merge다. 이 보고서의 신규 신호는 11월 12일 **release 반영**이며, 버그 최초 발견을 오늘로 옮겨 쓰지 않는다.

**논문 주장과 artifact의 간극:** 수정 전후 같은 `--max_grad_norm`을 써도 실제 clipping 여부가 다를 수 있다. 같은 seed만으로 학습 동등성을 주장할 수 없고 학습 script commit·gradient norm·optimizer 설정을 함께 비교해야 한다. 이는 메커니즘 가설이며 특정 논문의 성능 오류를 확인한 것은 아니다.

**배포 조건:** Apache-2.0. Python ≥3.11; setup metadata의 관련 최소 조건은 torch ≥2.6, Transformers ≥4.41.2, Accelerate ≥0.31.0이다. 최소 조건은 전체 재현 lock이 아니다. 설치 후보는 `diffusers==0.43.0`; 각 통합 model의 weights·license·revision과 학습 data는 별도로 고정해야 한다. GPU/VRAM은 모델에 종속되며 이 package에 공통인 검증 수치는 없다. [버전별 setup.py](https://github.com/huggingface/diffusers/blob/v0.43.0/setup.py)

**무결성·활동:** release에 asset digest가 없고 annotated tag는 `unsigned`다. checksum·attestation 검증 완료로 기록하지 않는다. #15178은 closed, #15212는 merged지만 실제 재현 환경의 해결 여부는 별도 검증이 필요하다.

**진단 → 가설 → 최소 개입 → 실험:** 10~30분 계획으로 큰 모델 대신 작은 trainable module에서 파라미터 iterable이 optimizer 생성 후에도 남는지, clipping 전후 norm이 달라지는지 검사한다. 별도로 tiny/mock modular fixture에 정상 호출→강제 예외→재호출을 넣어 cache 상태가 초기화되는지 검사한다. 두 검사는 각각 학습 제어·상태 오염을 진단하며 model 품질 검증을 대신하지 않는다.

**GO/KILL:** clipping 대상이 비어 있지 않고 threshold가 작동하며 예외 뒤 cache가 초기화되면 해당 수정 검증은 GO. 이전 결과를 재현할 때 script/version을 생략하거나 package 통합만으로 새 weight 전체 재현을 선언하는 것은 KILL.

1. **GO — 우선순위 1:** Supervision CPU parity fixture. 새 모델 학습 없이 small-object 평가 변화의 원인을 분리할 수 있다.
2. **GO — 조건부:** Ultralytics의 분리된 calibration/evaluation smoke test와 Diffusers의 clipping/cache fixture 설계.
