## Q1. Entity-level 생성 비디오 평가에서 모델 오류와 evaluator 오류를 분리할 수 있는가?

### Research Question

Detector·tracker 기반 entity metric의 ground-truth floor와 소량의 사람 라벨을 함께 사용하면, 생성 모델의 실제 lifecycle·position·count 오류와 evaluator의 detection·matching 오류를 분리해 모델 순위를 더 안정적으로 추정할 수 있는가?

### Observation

- **확인된 사실:** AnyGameRenderer benchmark는 59개 held-out case와 753개 entity를 평가하며 temporal match, position match, unrendered, hallucination, count-change miss를 보고한다.
- **확인된 사실:** base 대비 temporal match는 50.9%→62.9%, position match는 57.1%→61.9%, hallucination은 52.1%→46.0%, missed count change는 34.7%→21.3%로 개선됐다.
- **확인된 사실:** 실제 게임 14개 case에서는 temporal match가 46.5%→51.1%, position match가 52.4%→53.2%에 그쳤고 missed count change는 20.0%로 동일했다.
- **확인된 사실:** 동일 detector·matching pipeline을 ground-truth RGB에 적용해도 전체 hallucination 34.1%, temporal match 80.9%가 나왔다. real-game GT hallucination은 37.4%였다.
- **저자 주장:** entity-level protocol은 frame-level perceptual metric이 놓치는 등장·소멸·위치·수량 오류를 드러낸다.
- **레이더 추론:** 새 metric의 방향은 타당하지만, GT floor가 완벽하지 않으면 4~5%p 수준의 model gap은 evaluator noise와 분리되지 않을 수 있다.

직접 근거: [AnyGameRenderer arXiv](https://arxiv.org/abs/2610.31466) · [HTML 원문](https://arxiv.org/html/2610.31466) · [공식 코드](https://github.com/AlayaLab/AnyGameRenderer)

### Gap

현재 보고값은 하나의 detector·tracker·matching rule에서 나온 point estimate다. 사람 라벨 대비 evaluator sensitivity, 짧고 작은 객체의 제외 편향, detector를 바꿨을 때의 model-ranking stability, metric uncertainty를 함께 보고하는 protocol은 부족하다.

### Hypothesis

GT RGB에서 측정한 detector별 confusion matrix와 5개 case의 frame-level 사람 라벨을 이용해 metric을 보정하면 hallucination·temporal match의 절대값은 크게 바뀌지만, 큰 model gap의 순위는 유지될 것이다. 반대로 real-game의 작은 차이는 evaluator에 따라 뒤집힐 가능성이 높다.

### Experimental Design

1. real-game 5개 case와 two-stream 5개 case를 고르고 base/fine-tuned/GT RGB를 동일하게 준비한다.
2. 원 평가기, 다른 open-vocabulary detector+tracker, 사람 frame-level label의 세 평가기를 비교한다.
3. entity duration을 `<12`, `12~31`, `≥32` frame, box area를 tiny/small/medium으로 층화한다.
4. GT RGB의 detector 오류로 confusion-aware correction과 bootstrap interval을 계산한다.
5. 전체 score뿐 아니라 model pair의 순위 보존 확률을 보고한다.

### Baseline·Metric·GO/KILL

- Baseline: 원 SAM3 pipeline, detector ensemble, 사람 라벨, GT-floor correction.
- Metric: evaluator agreement, hallucination absolute error, temporal-match MAE, Kendall rank, count-change recall, 95% bootstrap CI.
- **GO:** 사람 대비 hallucination 오차 50% 이상 감소, model-ranking Kendall τ≥0.8, 보정 후에도 fine-tuned model의 temporal 우위가 유지.
- **KILL:** evaluator 선택에 따라 절반 이상의 pairwise ranking이 뒤집히거나, 보정 interval이 모든 model gap을 포함.

### Expected Contribution

생성 비디오의 entity consistency를 단일 detector 점수가 아니라 **측정 오차를 포함한 leaderboard**로 바꾸고, tiny·short-lived entity에서 어떤 결론까지 허용되는지 명시하는 평가 규약을 제안한다.

### Risk·Compute·논문화

- Risk: 사람 라벨 자체도 identity correspondence에서 불일치할 수 있다. 두 명의 주석자와 합의 규칙이 필요하다.
- Compute 난이도: **2/5**. 생성 재학습 없이 저장된 영상과 detector inference로 시작할 수 있다.
- 4~8주 논문화 가능성: **5/5**. evaluator audit이 다른 video-to-video 모델에도 유지되면 benchmark 논문으로 강하다.
- Negative result 가치: 순위가 안정적이면 현재 metric의 절대값은 부정확해도 비교 도구로는 쓸 수 있다는 범위를 정할 수 있다.

**평가:** 새로움 5/5 · 실행 가능성 5/5 · 계산 효율 5/5 · 논문화 가능성 5/5

## Q2. 실행 가능한 validator는 미검사 물리 제약과 safe-but-trivial 해법에서도 성능을 보존하는가?

### Research Question

Agent가 validator feedback을 반복해서 사용할 때 검사 대상인 collision·floater·connectivity는 해결하면서, 검사하지 않는 하중 안정성·조립 순서·내구성·형상 충실도를 희생하는가? Validator coverage를 확장하거나 무작위로 숨긴 제약을 두면 이러한 reward hacking을 측정할 수 있는가?

### Observation

- **확인된 사실:** BrickWright는 real part, no collision, no floater, 가능한 경우 single connected component를 physical validity로 정의한다.
- **확인된 사실:** BrickNet-512에서 일반 도구 baseline의 valid rate는 GPT-6 Luna 0.086, GPT-6.1 Sol 0.641, GPT-6 Astra 0.693이었고, full BrickWright는 평가한 네 agent에서 1.000이었다.
- **확인된 사실:** Luna에서 validator 제거 시 valid rate는 0.529, assembly API 제거 시 0.996이었다. Sol에서는 각각 0.779와 1.000이었다.
- **저자 주장:** 더 큰 모델보다 domain assembly API와 validator feedback loop가 물리 위반을 안정적으로 줄인다.
- **레이더 추론:** 100%는 정의된 validator 통과율이며 실제 중력 안정성, 하중, 조립 가능 순서까지 100%라는 뜻이 아니다. Agent가 통과하기 쉬운 단순 구조로 도피할 가능성도 남는다.

직접 근거: [BrickWright arXiv](https://arxiv.org/abs/2610.31651) · [HTML 원문](https://arxiv.org/html/2610.31651) · [공식 프로젝트/코드](https://avalovelace1.github.io/brickwright/)

### Gap

Validator가 검사하는 제약의 pass rate는 강하게 평가됐지만, unseen constraint generalization, validator call이 늘 때의 구조 단순화, adversarial prompt, 실제 조립 성공과의 대응은 별도 benchmark가 없다.

### Hypothesis

고정 validator를 오래 사용할수록 agent는 검사된 위반을 줄이지만, 부품 다양성·형상 충실도와 숨은 구조 안정성은 악화할 수 있다. 제약 일부를 episode마다 숨기는 holdout-constraint 평가와 complexity floor를 함께 두면 이 현상을 조기에 검출할 수 있다.

### Experimental Design

1. BrickNet-512에서 형상·관절·돌출 구조를 포함하는 40개 prompt를 층화 추출한다.
2. full validator, validator off, collision-only, connectivity-only, randomized hidden-constraint 조건을 같은 agent와 retry budget으로 실행한다.
3. 공개 validator 밖에서 center-of-mass support, load perturbation, assembly-order feasibility를 사후 검사한다.
4. unique parts, bounding volume, visual prompt similarity로 trivial simplification을 측정한다.
5. 10개 결과는 실제 또는 physics-engine 조립 시험으로 교차검증한다.

### Baseline·Metric·GO/KILL

- Metric: seen/unseen constraint pass, physical assembly success, prompt adherence, unique-part entropy, validator calls, latency, cost.
- **GO:** randomized hidden constraint에서도 unseen pass +15%p 이상, prompt adherence 하락≤2%p, complexity floor 유지.
- **KILL:** 100% seen-valid가 unseen constraint·실제 조립과 상관 ρ<0.3이거나, 단순화가 대부분의 이득을 설명.

### Expected Contribution

Validator를 단순 도구가 아니라 **검사 범위가 명시된 학습·평가 환경**으로 다루고, tool-using generator의 constraint overfitting과 coverage를 측정하는 protocol을 제시한다.

### Risk·Compute·논문화

- Risk: 실제 조립 시험은 비용이 크고 하중 기준이 임의적일 수 있다. physics-engine과 소규모 physical subset을 분리해야 한다.
- Compute 난이도: **3/5**. Agent API 비용과 3D validation이 필요하지만 새 foundation model 학습은 없다.
- 4~8주 논문화 가능성: **4/5**. brick domain을 넘어 CAD·robot plan validator로 확장하면 기여가 커진다.
- Negative result 가치: hidden constraint에서도 성능이 유지되면 validator feedback이 shortcut보다 일반적 constraint reasoning을 유도한다는 근거가 된다.

**평가:** 새로움 5/5 · 실행 가능성 4/5 · 계산 효율 4/5 · 논문화 가능성 4/5

## Q3. Runtime monitor의 AUROC를 실제 조기 개입 효용으로 바꾸려면 무엇을 측정해야 하는가?

### Research Question

실패 분류 AUROC가 높은 VLA monitor가 실제로 피해 전에 충분한 lead time을 제공하는가? Progress residual에 action-distribution shift와 contact proxy를 결합하고, failure severity별 개입 비용을 포함하면 같은 false-positive budget에서 성공 복구율을 높일 수 있는가?

### Observation

- **확인된 사실:** P²는 π0.5 내부 activation에 성공 demonstration만으로 선형 progress probe를 학습한다.
- **확인된 사실:** simulation episode/state AUROC는 0.909/0.788, unseen task는 0.900/0.794였다.
- **확인된 사실:** 5% FPR에서 TPR은 episode 25% 시점 0.00, 50% 시점 0.19, 75% 시점 0.54, 종료 시점 0.64였다. 평균 detection time은 episode fraction 0.60이었다.
- **확인된 사실:** hardware task 간 편차가 컸고 all-task Coffee Bean state AUROC는 0.26이었다.
- **저자 주장:** 작은 internal probe가 외부 VLM monitor보다 훨씬 저렴하게 runtime failure를 감지할 수 있다.
- **레이더 추론:** 종료에 가까워야 잡히는 실패는 통계적으로 분류 가능해도 안전 개입에는 늦다. AUROC와 intervention utility는 별도 목표다.

직접 근거: [Progress Probes P² arXiv](https://arxiv.org/abs/2610.31613) · [HTML 원문](https://arxiv.org/html/2610.31613)

### Gap

현재 protocol은 detection time을 보고하지만, 경보 뒤 정책 정지·재계획·human takeover가 실제 성공률과 피해를 어떻게 바꾸는지 연결하지 않는다. 급작스러운 접촉 실패와 느린 deadlock을 같은 평균으로 묶기도 한다.

### Hypothesis

Progress-only probe는 느린 지연·deadlock에는 강하지만 sudden contact failure에는 늦다. Progress residual, action entropy/shift, contact proxy를 multi-timescale로 결합하면 동일 5% FPR에서 초기 recall과 intervention success를 함께 높일 수 있다.

### Experimental Design

1. simulation 3개 task에서 성공, slow success, deadlock, late drop, collision을 각 30 episode 수집한다.
2. P², SAFE-LSTM, action-shift probe, progress+action+contact detector를 비교한다.
3. 경보 시 stop, last-safe-state reset, replanning의 세 intervention을 실행한다.
4. threshold는 validation success episode에서 5% FPR로 고정하고 test에서는 변경하지 않는다.
5. failure type과 severity별로 lead time과 recovery를 분리한다.

### Baseline·Metric·GO/KILL

- Metric: TPR@25/50/75%, lead time, recovered-success rate, collision/spill severity, false stops/hour, monitor latency.
- **GO:** TPR@50%≥0.45, false stops/hour≤0.1, recovered success +10%p 이상, monitor overhead≤5%.
- **KILL:** AUROC만 상승하고 lead time·복구 성공이 개선되지 않거나 slow success를 실패로 과검출.

### Expected Contribution

Runtime monitor 평가를 사후 분류에서 **개입 가능한 시간과 결과 개선**으로 옮기고, 실패 유형별로 어떤 internal signal이 필요한지 밝힌다.

### Risk·Compute·논문화

- Risk: simulator의 intervention이 실제 robot safety를 과대평가할 수 있다. 마지막 단계에서 소규모 hardware 검증이 필요하다.
- Compute 난이도: **3/5**. 작은 probe 학습은 가볍지만 rollout과 intervention 재실행이 필요하다.
- 4~8주 논문화 가능성: **5/5**. 안전·robotics benchmark의 평가 축을 직접 바꾸는 질문이다.
- Negative result 가치: 조기성 개선이 불가능하면 current VLA backbone 내부에 초기 실패 신호가 부족하다는 근거가 된다.

**평가:** 새로움 5/5 · 실행 가능성 4/5 · 계산 효율 4/5 · 논문화 가능성 5/5

## Q4. Shared memory의 어떤 기록이 coordination 성공보다 더 많은 비용과 오류를 만드는가?

### Research Question

다중 플레이어 visual planning에서 self-authored memory의 각 write/read가 completion에 기여했는지, stale·duplicate·contradictory state로 실패를 유발했는지 counterfactual하게 추적할 수 있는가? 정보 가치 기반 admission·eviction이 자유 notebook보다 성능–비용 Pareto를 개선하는가?

### Observation

- **확인된 사실:** DuoCook은 20개 map·5개 범주에서 한 VLM이 두 player를 중앙집중 제어하게 한다.
- **확인된 사실:** 평균 order completion은 Qwen 8.8%, Gemini 11.2%, Claude 8.8%, Astra 26.2%였다.
- **확인된 사실:** notebook 추가는 모든 모델의 평균 API 비용을 높였고, score 효과는 Claude·Qwen에서 양수, GPT·Gemini에서 음수였다.
- **확인된 사실:** Gemini action acceptance는 notebook 없음 56.4%에서 있음 32.1%로, delivery는 21개에서 12개로 줄었다. Astra acceptance도 70.3%→64.6%로 낮아졌다.
- **저자 주장:** shared self-authored notebook의 효과는 모델별로 혼합되어 있으며 persistent context가 자동으로 coordination을 개선하지 않는다.
- **레이더 추론:** memory 유무의 평균 ablation만으로는 어느 기록이 도움·방해가 됐는지 알 수 없다. live-state JSON과 action history가 이미 있어 중복 context가 attention을 소모했을 수 있다.

직접 근거: [DuoCook arXiv](https://arxiv.org/abs/2610.31511) · [HTML 원문](https://arxiv.org/html/2610.31511)

### Gap

현재 memory ablation은 notebook 전체를 켜고 끈다. Write별 causal value, stale read, 이미 구조화 state에 존재하는 중복, 잘못된 인계 상태의 전파, token·USD 비용을 함께 측정하지 않는다.

### Hypothesis

Memory의 이득은 recipe·handoff처럼 미래 행동을 바꾸는 sparse event에 집중되고, 위치·현재 inventory처럼 live state와 중복되는 기록은 성능을 낮춘다. Counterfactual replay로 write의 value를 추정해 low-value item을 폐기하면 completion을 유지하면서 비용과 invalid action을 줄일 수 있다.

### Experimental Design

1. 고난도 map 5개에서 no memory, 자유 notebook, schema memory를 5 seed로 실행한다.
2. 각 memory item에 source, timestamp, expiry, referenced action을 기록한다.
3. 저장된 trajectory에서 item 하나씩 mask/replay해 다음 1~3 action의 변화와 acceptance를 측정한다.
4. event-only admission, TTL eviction, contradiction-triggered refresh를 ablation한다.
5. model 1개로 정책을 고른 뒤 두 번째 model에서 전이성을 확인한다.

### Baseline·Metric·GO/KILL

- Metric: order completion, action acceptance, stale-read rate, duplicate-write rate, intervention value, tokens, USD/episode, wall-clock.
- **GO:** no-memory 대비 completion +8%p 이상, stale read 50% 이상 감소, 비용 증가≤20%, 두 model에서 방향 일치.
- **KILL:** seed CI가 넓어 효과가 구분되지 않거나, 성능 향상이 context/token 증가량으로만 설명됨.

### Expected Contribution

Agent memory를 저장 공간이 아니라 **측정 가능한 의사결정 개입**으로 다루고, coordination task에서 admission·eviction·contradiction repair의 순효용을 평가하는 protocol을 만든다.

### Risk·Compute·논문화

- Risk: closed model replay는 비결정성과 비용 때문에 exact counterfactual이 어렵다. 동일 prompt·temperature와 paired bootstrap이 필요하다.
- Compute 난이도: **3/5**. 75개 내외 episode와 replay가 필요하지만 model training은 없다.
- 4~8주 논문화 가능성: **4/5**. DuoCook 외 GUI/embodied agent 하나로 전이하면 일반성이 커진다.
- Negative result 가치: item-level value가 안정적으로 추정되지 않으면 memory 효과가 모델 내부 attention과 stochastic policy에 강하게 의존한다는 결론이 된다.

**평가:** 새로움 4/5 · 실행 가능성 4/5 · 계산 효율 3/5 · 논문화 가능성 4/5

## Q5. Geometry-aware sensor transfer는 접촉 형상뿐 아니라 힘 크기와 sampling budget 변화도 견디는가?

### Research Question

물리 좌표와 local surface frame으로 tactile map을 정렬하면 sensor pitch·shape가 달라도 contact geometry뿐 아니라 force magnitude와 downstream control까지 전이되는가? Adaptive partial scan의 불확실성을 포함하면 sparse contact와 broad contact 사이의 실패 경계를 예측할 수 있는가?

### Observation

- **확인된 사실:** OpenTac cross-sensor 평가는 4개 skin, 5개 object, 95개 위치, 1–8N 조건에서 5,290개 prediction을 포함한다.
- **확인된 사실:** geometry와 calibration을 쓰는 transfer의 median contact-shape F1은 0.750으로 resize+manifest 0.714, geometry 없는 bilinear resize 0.634보다 높았다. 공통 support에서는 0.788로 same-skin repeatability 0.800에 근접했다.
- **확인된 사실:** 32×32 skin에서 update당 16 taxel을 읽는 adaptive acquisition은 1,286Hz, full raster는 67Hz였다. 이는 partial readout rate이며 full-field 1,286Hz가 아니다.
- **확인된 사실:** 저자는 cross-sensor force magnitude transfer와 sim-to-real policy transfer를 검증 범위 밖으로 남겼다.
- **저자 주장:** sensor manifest의 geometry·electrical addressing·mechanical metadata가 다른 layout 사이의 interoperability를 가능하게 한다.
- **레이더 추론:** shape F1이 높아도 force integral과 control policy가 보존된다는 보장은 없다. Sparse scan은 짧은 점 접촉에는 유리하지만 넓은 접촉·다중 접촉을 놓칠 수 있다.

직접 근거: [OpenTac arXiv](https://arxiv.org/abs/2610.31661) · [HTML 원문](https://arxiv.org/html/2610.31661) · [공식 프로젝트/코드](https://opentac.github.io/)

### Gap

현재 transfer metric은 thresholded active-taxel shape F1에 집중한다. Force magnitude calibration, uncertainty, broad/multi-contact coverage, source sensor에서 학습한 policy의 target sensor 성능을 같은 protocol에서 평가하지 않는다.

### Hypothesis

Geometry-aware mapping은 접촉 support를 잘 옮기지만 force magnitude에는 sensor별 material·calibration residual이 남는다. Manifest-conditioned scale calibration과 uncertainty-aware partial scan을 추가하면 few-shot target data로 force와 policy transfer gap을 줄일 수 있다.

### Experimental Design

1. pitch·형상이 다른 두 skin에서 10개 위치, 3개 force, point/broad/two-point contact를 수집한다.
2. raw resize, geometry transfer, geometry+global scale, geometry+location-conditioned calibration을 비교한다.
3. full raster와 16/64/256-taxel adaptive budget을 같은 contact trajectory에서 replay한다.
4. source skin에서 학습한 slip detector 또는 force controller를 target skin에 zero/few-shot transfer한다.
5. target calibration sample 수 0/5/20에 따른 성능 곡선을 보고한다.

### Baseline·Metric·GO/KILL

- Metric: contact-shape F1, force integral MAE, shear-direction error, event recall, spatial coverage, policy success, update rate, calibration error.
- **GO:** target force MAE 30% 이상 상대 감소, broad/multi-contact event recall≥90%, source 대비 policy success 하락≤10%p, 10× 이상 update-rate gain.
- **KILL:** shape F1 개선이 force·policy로 이어지지 않거나 partial scan이 broad contact에서 event recall<70%.

### Expected Contribution

Sensor transfer를 binary shape overlap에서 **metric force와 downstream action의 전이**로 확장하고, geometry metadata가 해결하는 변화와 few-shot calibration이 필요한 변화를 분리한다.

### Risk·Compute·논문화

- Risk: hardware fabrication과 synchronized F/T ground truth가 병목이다. 기존 OpenTac hardware 접근이 없으면 simulator+공개 trace로 범위를 줄여야 한다.
- Compute 난이도: **3/5**. 학습 비용은 낮지만 센서 제작·교정·반복 측정 비용이 크다.
- 4~8주 논문화 가능성: **3/5**. 장비가 준비돼 있으면 빠르지만 새 hardware 구축 시 일정 위험이 크다.
- Negative result 가치: geometry만으로 force transfer가 안 되면 sensor-specific mechanical response가 불변 표현의 핵심 병목임을 정량화할 수 있다.

**평가:** 새로움 4/5 · 실행 가능성 3/5 · 계산 효율 4/5 · 논문화 가능성 4/5
