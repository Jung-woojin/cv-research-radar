## 1. MiMo-V2.6 — 실제 영상 시간을 버리고 모든 clip을 30초로 표기할 수 있음

**[확인된 사실]** 11월 4일 vLLM issue #65523은 MiMoV2OmniMultiModalProcessor가 torch.arange(T) / 1.0으로 timestamp를 만들고, loader는 전체 clip에서 32 frame을 균일 sample한다고 설명한다. 보고된 150초 clip 재현에서 prompt의 observed label은 00:00, 00:02, …, 00:30인 반면 expected label은 00:00, 00:09, 00:19, …, 02:25다. issue 작성자는 parser에 존재하는 frames_indices, fps를 보존해 frames_indices / fps로 계산하는 수정을 제안했다.  
출처: https://github.com/vllm-project/vllm/issues/65523

**[커뮤니티 재현/한계]** 작성자는 별도 오래된 build에서 7~194초, 25/29.97 fps clip의 label이 실제 first-frame time과 맞았다고 적었지만, main rebase는 helper unit check와 formatting만 했다고 명시한다. 따라서 main에서 수정이 검증됐거나 maintainer가 인정했다고 쓰지 않는다.

**[실패 조건]** MiMo-V2.6 Flash의 video URL 처리, 기본 균일 32-frame sampling, 실제 clip duration이 30초가 아닌 경우다. 다른 video VLM 일반의 실패로 확대하면 안 된다.

**[의심 메커니즘]** sampled index가 아닌 1 fps 가정으로 prompt time token을 만들면서 temporal grounding target이 원 video time과 분리된다.

**[기존 주장과의 충돌]** 시간 질의의 text answer가 그럴듯해도, model이 받은 timestamp가 잘못되면 정확한 시점 인식 증거가 아니다.

**진단 → 가설 → 최소 실험**
- 진단: video QA exact answer는 시간 label의 fidelity를 측정하지 않는다.
- 가설: prompt timestamp와 실제 sampled-frame time의 absolute error를 별도 release gate로 두면 temporal hallucination을 input metadata 오류와 분리할 수 있다.
- 최소 실험: 7/30/150/194초 synthetic clip을 25와 29.97 fps로 만들고, 각 vision block 앞 label, selected frame index, 실제 seconds를 비교한다. max/mean timestamp error와 time-QA exact accuracy를 함께 기록한다.
- **GO:** label error가 사전 한계 이내이고 prompt label과 cited frame이 일치할 때. **KILL:** duration과 무관하게 30초 endpoint가 반복될 때.
- 심각도 **5/5**, 재현 신뢰도 **4/5**, 연구 아이디어 가치 **5/5**. 이번 실행은 독립 재현을 하지 않았다.

## 2. Precomputed image/video embedding + encoder CUDA graph — 지원되는 두 기능의 조합이 engine crash

**[확인된 사실]** 11월 4일 vLLM issue #65531은 enable_mm_embeds=True 및 cudagraph_mm_encoder=True에서 precomputed embedding request 하나가 engine을 종료시키고, graph를 끄면 같은 request가 동작한다고 보고한다. 공개 코드는 InternVL3-1B, one L40S, BF16 image embedding (1×256×896), temperature 0으로 재현한다. 작성자는 image embedding에서 InternVL·Qwen2/2.5/3-VL·MiniCPM-V·Idefics3·DeepSeek-VL2 등을, video embedding에서 Qwen2/2.5/3-VL·MiniCPM-V 등을 CPU graph-method test에서 실패 목록으로 제시한다.  
출처: https://github.com/vllm-project/vllm/issues/65531

**[중요한 범위]** 이 사례는 pixel image batch가 아니라 precomputed embedding batch의 graph path다. issue에 따르면 pixel과 embedding item은 같은 batch를 공유하지 않으며, image graph 일반이 깨졌다는 뜻은 아니다. issue는 open 상태이며 maintainer merge가 확인되지 않았다.

**[의심 메커니즘]** graph runner가 embedding을 vision tower를 건너뛰어야 하는 입력이 아니라 encoder 작업으로 취급하고 item spec이 비어 assert/KeyError로 끝나는 경로다.

**[기존 주장과의 충돌]** pixel-input smoke test 성공은 retrieval/cache/disaggregated encoder가 precomputed embedding을 보내는 production path의 안전성을 보장하지 않는다.

**진단 → 가설 → 최소 실험**
- 진단: multimodal feature source(pixel vs precomputed embeds)와 CUDA graph flag의 교차 조건이 regression matrix에서 빠지기 쉽다.
- 가설: modality × feature-source × graph on/off matrix를 CI에 넣으면 crash와 silent fallback을 모델별로 분리할 수 있다.
- 최소 실험: image와 video에 대해 pixel/embedding × graph on/off를 각 5회 실행해 request success, output length, engine survival, latency를 기록한다. 동일 request는 별 server에서 실행한다.
- **GO:** 네 조건 모두 engine survival 및 expected output schema를 유지할 때. **KILL:** embed condition에서 crash/empty spec/KeyError가 하나라도 날 때.
- 심각도 **5/5**, 재현 신뢰도 **4/5**, 연구 아이디어 가치 **4/5**.

## 3. Gemma 4 long-video prefill — media span이 있으면 full-attention group이 비싼 routing을 탈 수 있음

**[확인된 사실]** 11월 3일 vLLM issue #65513은 Gemma 4에서 vision bidirectional mask가 sliding-window layer에만 필요하지만 routing이 batch의 media span 존재만 보고 full-attention KV-cache group에도 Triton unified kernel을 선택한다고 주장한다. 작성자가 제시한 H100 nightly workload는 66×32-frame 640×360 clips, 158,418 prompt tokens, FP8 KV에서 stock TTFT 390.3초, span-search 수정 163.2초, full-attention routing prototype 65.3초(반복 63.0초)다. 16 greedy output token은 세 행에서 같았다고 보고한다.  
출처: https://github.com/vllm-project/vllm/issues/65513

**[저자/커뮤니티 주장과 한계]** 수치는 issue 작성자가 실행한 한 server·한 long-video workload의 결과다. issue는 open이고 prototype은 병합되지 않았다. 작성자도 one prompt의 identical greedy token은 충분한 correctness evidence가 아니며 eval이 필요하다고 적었다.

**[실패 조건]** Gemma 4, media span, composite attention backend, 매우 긴 video prefill이 핵심 조건이다. 모든 VLM, 모든 GPU 또는 normal-length request의 일반 TTFT regression으로 일반화할 수 없다.

**[의심 메커니즘]** per-layer mask 필요 여부가 아니라 batch-level requires_mm_prefix가 routing을 결정해 causal full-attention layer까지 prefix-aware kernel을 탄다.

**진단 → 가설 → 최소 실험**
- 진단: 동일 output token은 long-context kernel precision·prompt logprob fidelity·short clip latency를 검증하지 않는다.
- 가설: layer-group별 mask necessity를 routing key로 주면 long-video TTFT를 낮추면서 visual answer/evidence fidelity를 보존할 수 있다.
- 최소 실험: 8/32/66 clips에서 stock과 prototype 또는 causal backend를 비교한다. TTFT, prefill time, prompt logprob drift, answer exact match, cited-frame consistency를 함께 기록한다.
- **GO:** 각 길이에서 task/evidence metric 저하 없이 TTFT가 줄고, numeric drift가 사전 허용 범위 안일 때. **KILL:** short clip에 회귀가 생기거나 evidence/time answer가 달라질 때.
- 심각도 **4/5**, 재현 신뢰도 **3/5**, 연구 아이디어 가치 **4/5**.

## 오늘의 실패 패턴 3개

1. **video temporal answer의 실패 원인은 decoder reasoning이 아니라 injected timestamp metadata일 수 있다.**
2. **precomputed embedding은 pixel input과 다른 multimodal execution path이므로 별도 CI cell이 필요하다.**
3. **긴 video에서 정확한 출력만으로 routing optimization의 correctness를 판정할 수 없다. latency·logprob·evidence를 함께 봐야 한다.**
