## 1. Transformers v5.24.0 — weight보다 위치 정밀도·attention 계약을 먼저 고정

**배포 사실.** tag object는 `89c632fd826f68ecadd176320e9b2c070918f4f2`, 대상 commit은 `eeee11099135592f1d03c2871fbd3d8132e5a4d7`이다. tagger 시각은 21일 12:09:57 UTC, release 발행은 12:28:26 UTC다. tag verification은 unsigned이고 release assets는 비어 있다. 새 package 지원을 새 checkpoint 공개로 세지 않았다. [Tag metadata](https://api.github.com/repos/huggingface/transformers/git/tags/89c632fd826f68ecadd176320e9b2c070918f4f2)

**SAM3 코드 사실·개발자 설명.** [PR #50938](https://github.com/huggingface/transformers/pull/50938)은 19일 13:06:43 UTC merge됐다. BF16으로 모델을 구성할 때 기본 dtype의 영향을 받던 위치 grid를 FP32로 생성한다. 개발자는 global-attention 위치의 1/3 scaling을 BF16이 정확히 표현하지 못한다고 설명한다. [배포 tag의 코드](https://github.com/huggingface/transformers/blob/eeee11099135592f1d03c2871fbd3d8132e5a4d7/src/transformers/models/sam3/modeling_sam3.py)에서도 `precompute_positions`의 두 `torch.arange`에 명시적 float dtype이 있다. 새 사건은 21일 package 배포이며 오류가 이날 처음 발견됐다는 뜻은 아니다.

**VLM backend 계약.** [PR #50724](https://github.com/huggingface/transformers/pull/50724)은 16일 merge됐다. PaliGemma·Gemma3/4·Molmo2·PI0 등의 multimodal class에서 Flash Attention을 요청하면, image/action token의 bidirectional mask를 조용히 잃는 대신 지원하지 않는다고 오류를 내도록 바꾼다. text-only class와 명시적 예외까지 모두 차단한 것은 아니다. 개발자 설명과 merged PR을 확인했으며 독립적인 품질 재현은 없다.

**논문 주장과 artifact 간극 — 추론.** 같은 checkpoint라도 위치 grid dtype이나 attention mask가 다르면 representation 비교의 입력 조건이 달라진다. backend를 바꾼 결과를 모델 architecture의 gain으로 귀속하지 않는다. mask 보존을 위해 backend가 바뀌면 속도와 메모리도 다시 측정해야 한다.

**설치·가용성·활동.** source는 Apache-2.0, pin 후보는 `transformers==5.24.0`이다. [고정 setup.py](https://github.com/huggingface/transformers/blob/eeee11099135592f1d03c2871fbd3d8132e5a4d7/setup.py)는 Python ≥3.11, torch ≥2.6, tokenizers ≥0.23.1,<0.24.0을 명시한다. PEFT 연동은 ≥0.22.0이 필요하다. 전체 환경 lock은 아니다. 새 data·weights·standalone evaluator를 이 release가 제공한다고 검증하지 않았다. GPU/VRAM 최소값은 모델별로 미확인이다. merged PR 두 건의 활동을 확인했지만 전체 Issue 해결률은 조사하지 않았다. wheel checksum·attestation 검증은 미실행이다.

**진단 → 가설 → 10~30분 계획.** 준비된 환경에서 tiny SAM3 config로 global/window position grid의 dtype·값을 비교한다. 같은 seed와 입력으로 BF16 load 경로만 바꾸고, 그다음 실제 고정 이미지에서 logits/mask 차이를 확인한다. VLM은 별도 fixture에서 지원하지 않는 Flash Attention 요청의 명시적 실패와 지원 backend의 mask 계약을 검사한다. 두 문제를 한 성능 수치로 합치지 않는다.

**GO/KILL.** dtype·mask 계약이 맞으면 작은 고정 subset으로 GO. backbone·checkpoint·data/split·resolution·precision·batch·hardware·TTA·evaluator 중 바뀐 조건이 있는 비교는 **not strictly apples-to-apples**다. 지원 차단 자체를 품질 향상 실측으로 부르는 것은 KILL이다.

**진단 → 가설 → 10~30분 계획.** 먼저 CPU에서 config 참조 경로·normalizer key·20-D action schema·model registry mapping을 audit한다. 배포팀의 정확한 loader/code revision과 cache 생성 경로를 확보한 뒤 header dtype·shape를 확인한다. 아직 weight가 없는 환경에서 24GB 다운로드·설치·정책 추론까지 30분 내 완료한다고 약속하지 않는다.

**GO/KILL.** manifest·loader 계약 조사로 GO. preview를 최종 2.0 성능으로 표시하거나 action flag만 임의로 켜서 논문 재현이라 부르는 것은 KILL이다. 동작하더라도 RoboDojo fine-tuning 여부·normalizer·episode split·seed·camera 조건이 다른 성공률은 **not strictly apples-to-apples**다.

## 3. Cosmos WSM F-theta 교정 — world-model 실패 전에 control geometry 검사

**공식 사건.** [PR #426](https://github.com/NVIDIA/cosmos-framework/pull/426)은 21일 05:13:46 UTC merge됐으며 고정 commit은 `a3fb34690e157972a9d04244c11b16022c9d6479`다. package version이나 새 model weight가 아닌 code revision으로 채택한다. formal release tag 포함 여부는 이번 실행에서 확인하지 못했다.

**코드 사실.** [Commit diff](https://github.com/NVIDIA/cosmos-framework/commit/a3fb34690e157972a9d04244c11b16022c9d6479)는 ascending-power 다항식 미분에서 `coeffs[:-1]` 대신 `coeffs[1:]`을 사용한다. vector와 scalar 경로를 함께 고친다. 추가 fixture는 `3+2x+5x²`의 미분이 `2+10x`인지 확인한다. 이는 코드에 포함된 테스트이며 이번 실행에서 통과시킨 결과가 아니다.

**진단과 가설 — 추론.** F-theta ray 범위 결정에 잘못된 미분이 들어가면 control geometry의 유효 범위가 잘못될 수 있다. 영상 왜곡이나 주변부 누락을 world model의 물리 이해 실패로 판단하기 전에 renderer를 고정해야 한다. 실제 benchmark score나 모든 카메라의 출력이 얼마나 바뀌는지는 확인하지 않았다. 특정 논문 표가 잘못됐다고 결론내릴 근거도 없다.

**설치·license·가용성·활동.** [WSM component metadata](https://github.com/NVIDIA/cosmos-framework/blob/a3fb34690e157972a9d04244c11b16022c9d6479/.agents/skills/cosmos3-inference-simulation-auto/scripts/wsm/pyproject.toml)는 `cosmos-auto-wsm` 0.1.0, Python ≥3.11, NumPy ≥1.26, torch ≥2.0, ModernGL 등 범위 의존성을 명시한다. 0.1.0만으로 이 수정 포함을 보장할 수 없어 commit pin이 필요하다. component [license](https://github.com/NVIDIA/cosmos-framework/blob/a3fb34690e157972a9d04244c11b16022c9d6479/.agents/skills/cosmos3-inference-simulation-auto/scripts/wsm/LICENSE)는 OpenMDW-1.1이다. 새 checkpoint·dataset·checksum 배포는 확인하지 않았다. PR merge와 테스트 추가를 확인했으며 독립 재현은 없다.

[공식 Auto guide](https://github.com/NVIDIA/cosmos-framework/blob/a3fb34690e157972a9d04244c11b16022c9d6479/.agents/skills/cosmos3-inference-simulation-auto/SKILL.md)는 Framework 경로에 locked cu130-train 환경·train/guardrail extras·별도 snapshot을 안내한다. 4-GPU 예시가 있으나 최소 VRAM 보장은 없다. 아래 수학 fixture는 GPU가 필요 없고 전체 렌더링은 별도 EGL/GPU 환경이 필요하다.

**10~30분 최소 실험 계획.** scalar/vector derivative를 analytic derivative와 finite difference에 대조한다. 그다음 실제 calibration polynomial 하나에서 parent `82d6f4e`와 수정 commit의 derivative 부호 전환·최대 유효 ray angle을 비교한다. 같은 camera·pose·WSM 입력의 boundary mask와 control raster를 저장하고 generative model은 아직 실행하지 않는다. downstream 비교는 같은 weight·seed·shape·precision·hardware에서 renderer만 바꾼다.

**GO/KILL.** 수학 fixture와 calibration 경계 audit로 GO. 미분 교정만으로 생성 품질·운전 성공률 향상을 선언하거나 camera/control이 다른 결과를 모델 능력 차이로 쓰는 것은 KILL이다.
