## 1. PanoVideoBench — 파노라마 비디오 평가가 “시야 + 시간” 문제로 확장

**[확인된 사실]** 10월 30일 공개된 *Think in 360°*는 PanoVideoBench를 1,000개의 수동 주석 질문, 5개 범주, 15개 질문 유형으로 소개하며, target search와 panoramic capability 진단 주석을 포함한다고 명시한다. 원문은 11개 모델 평가에서 cross-view tracking과 sphere-time evidence integration이 약한 능력으로 나타났다고 서술한다.  
출처: https://arxiv.org/abs/2610.42082

**[저자 주장]** PanoVideoReasoner는 PanoVideoBench에서 55.7%를 기록했고 backbone 대비 12.5점, 기존 SOTA 대비 2.6점 향상했다.

**[비교 조건]** 저자 수치는 동일 benchmark 안의 비교다. 일반 video-VQA, 단일-view video, 다른 frame budget 결과와는 **not strictly apples-to-apples**다. panoramic projection 방식, view sampling, temporal window, evidence view 접근 여부가 함께 달라질 수 있다.

**진단 → 가설 → 최소 실험:**
- 진단: video-VLM 정답률은 필요한 장면을 찾지 못하는 실패와 장면을 찾고도 연결하지 못하는 실패를 섞는다.
- 가설: target-search recall과 cross-view temporal evidence F1을 답 정확도와 분리하면 성능 병목을 식별할 수 있다.
- 최소 실험: 100개 질문에 대해 원본 ERP, oracle perspective view, random perspective view 세 조건을 같은 모델·동일 token/frame budget으로 비교한다. answer accuracy, evidence recall, latency를 함께 기록한다.

## 2. System One Bench — Vision Index의 재현 조건이 점수의 일부가 됨

**[확인된 사실]** 공식 저장소는 11월 2일 기준 roadmap과 Round 9 범위를 명시한다. vision track은 6개 데이터셋에서 총 1,200 image case를 만들며, 입력 이미지는 EXIF 회전 후 한 변 280–1,568 px, 최소 78,400 pixels, 약 300 KB 이하로 조정된다. `data_lock.py`로 입력 데이터 hash를 확인하고, source 변경·prompt 변경·dataset 변경은 새 benchmark version이며 전체 모델 재실행이 필요하다고 명시한다.  
출처: https://github.com/alilibx/system-one-bench

**[운영자 주장/규칙]** OpenRouter Decisions API에서 동일 request shape와 frozen data를 사용한 run만 board에 올리며, vendor 자체 점수는 동일 방식으로 재실행되기 전에는 게시하지 않는다고 설명한다.

**[해석]** Vision Index의 변화는 모델 자체 성능 변화뿐 아니라 image resize 범위, 지원 question type, data lock, latency 측정 환경에 의존한다. 따라서 일반 VQAv2/RefCOCO 논문 표나 API 벤더 표와 직접 합산할 수 없다.

**진단 → 가설 → 최소 실험:**
- 진단: vision benchmark는 preprocessing과 지원 output schema가 다르면 동일 모델도 다른 점수를 낸다.
- 가설: resolution envelope와 box-output 지원 여부를 고정하면 score variance의 일부를 protocol 변수로 설명할 수 있다.
- 최소 실험: VQAv2 yes/no·CountBench·RefCOCO를 각각 200개씩, 3개 resize ceiling과 동일 prompt로 실행한다. exact accuracy, box mIoU, calibration, failure rate를 분리 보고한다.

## 3. NVIDIA PAI-AV OOD Reasoning — 제출 종료와 최종 순위 확정을 분리해야 함

**[확인된 사실]** NVIDIA의 PhysicalAI Autonomous Vehicles OOD Reasoning Challenge 공식 안내는 2026-10-31을 최종 제출 마감 및 public leaderboard 종료일, 2026-11-15를 final results 공개 예정일로 구분한다. reasoning track은 샘플당 6개 rollout을 받고 top-1 score를 ranking metric으로 사용하며, auto-labeling track은 validation split의 290 clips와 top-1 AlpaJudge score를 사용한다고 명시한다.  
출처: https://huggingface.co/spaces/nvidia/PhysicalAI-AV-OOD-Reasoning-Challenge-2026

**[해석]** 현 시점의 public board는 제출 마감 전 snapshot일 수 있다. 11월 15일 이후의 최종 결과·규칙 적용·검증 상태가 나오기 전에는 현재 순위를 “확정 benchmark movement”로 기록하면 안 된다.

**진단 → 가설 → 최소 실험:**
- 진단: multi-rollout의 top-1 ranking은 평균 품질보다 best-of-N 탐색 능력을 보상할 수 있다.
- 가설: top-1·top-k·mean-over-k를 함께 보면 reasoning model의 일관성과 탐색 의존도를 분리할 수 있다.
- 최소 실험: 공개 validation 형식에서 1·3·6 rollout을 같은 seed budget으로 평가하고 top-1, top-k, avg-k, 비용/clip을 함께 표기한다.

## 오늘의 benchmark signal 3개

1. **panoramic video는 frame 수만이 아니라 view search와 evidence 연결을 평가해야 한다.**
2. **frozen data와 image preprocessing이 명시되지 않은 Vision Index 비교는 leaderboard noise가 될 수 있다.**
3. **challenge의 public leaderboard 종료와 최종 결과 공개는 다른 이벤트다.** 제출 종료일 점수는 final rank로 취급하지 않는다.

## 내 연구에 바로 연결되는 포인트

VLM Answer–Region Gap 및 video/aerial 연구에서는 다음 6개를 실험 manifest의 필수 열로 둔다: `view/frame sampling rule`, `resolution`, `evidence access`, `prompt/output schema`, `dataset+evaluator revision`, `top-1 vs multi-rollout aggregation`. 작은 물체나 maritime 영상에서는 oracle crop 조건을 별도 상한선으로 두어 관측 실패와 추론 실패를 분리한다.
