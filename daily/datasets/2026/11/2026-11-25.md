## 1. ReXGroundingCTv2 — annotation correction과 데이터 확장을 분리한다

**확인 사실.** HF 공개 API revision은 `39789e8fb46eb7b0be35aedab1bd416ee1629eb9`, 수정 시각은 11/23 06:25:33 UTC다. 이 revision의 raw README는 HTTP 200으로 읽고 로컬에 보존했다. commit history API는 HTTP 401이었다. 따라서 아래 release 내용은 고정 card의 설명이며 개별 파일 diff나 mask 실측 결과는 아니다. [고정 card](https://huggingface.co/datasets/rajpurkarlab/ReXGroundingCT/blob/39789e8fb46eb7b0be35aedab1bd416ee1629eb9/README.md)

**규모·task·정책 — 배포자 보고.** 흉부 CT의 문장별 3D segmentation용으로 v2는 학습 scan 1,134개·finding 1,895개를 추가하고, finding의 모든 instance를 표시한다. 기존 학습 annotation은 finding당 최대 3개 instance였다. correction판은 scan 2,989개·finding 7,652개이며 수정 mask 디렉터리에는 변경 mask 114개만 있다. 기존 파일은 보존된다. base split과 challenge split은 별개다. CC BY-NC-SA 4.0 및 추가 이용 조건이 있고 CT 볼륨은 CT-RATE에서 별도로 받아야 한다. gated data의 접근 동의나 다운로드는 수행하지 않았다. [공식 데이터 설명](https://huggingface.co/datasets/rajpurkarlab/ReXGroundingCT)

**진단·추론.** 수정 mask 디렉터리만 읽으면 정상적인 기존 mask가 누락될 수 있다. 또한 instance 정의 변화가 recall·instance F1에 영향을 줄 수 있다. 실제 loader 결함이나 성능 변화를 확인한 것은 아니다.

**최소 실험 — 제안, 미실행.**

- scan ID·finding ID·protocol·split·선택된 mask 경로를 manifest로 기록하고, correction 경로가 없을 때 원래 mask를 쓰는 규칙을 확인한다.
- 같은 base 학습 집합에서 원본 annotation과 correction만 바꾼 조건을 먼저 비교한다. v2 데이터 추가는 별도 조건으로 둔다.
- 환자/scan overlap, 누락 mask, category별 instance 수를 확인한 뒤 고정 평가 집합·evaluator로 비교한다. instance annotation 정책별 결과를 따로 보고한다.

**GO:** 접근 권한 확보 후 manifest·fallback 감사를 먼저 한다. **KILL:** annotation 수정과 학습량 증가를 동시에 바꾸고 개선 원인을 하나로 설명한다. label 정책·학습 집합이 다른 점수는 **not strictly apples-to-apples**다.

## 2. 의료영상 curation 감사 — 손상 발견과 삭제 효용은 다른 주장이다

**확인 사실·저자 보고.** v1 제출은 11/23이다. 논문은 CTA patch 7,742개·환자/scan group 1,793개를 다루며 train/val/test 환자를 1,256/270/267개로 분리했다고 보고한다. 양성 1,201개 중 완전한 zero array 232개를 발견했지만, 학습 양성 170개 삭제가 full-data 대비 AUC를 개선하지 않았다. 5개 paired seed의 삭제-minus-full 차이는 −0.0035, 95% CI는 −0.0082~0.0007이다. 이는 저자 실험이며 독립 재현이 아니다. [논문](https://arxiv.org/abs/2611.31096)

**주석·split·bias.** 과거 내부 분석의 321개 subgroup은 ID 없는 결과와 정렬 파일을 위치로 연결해 타당성이 무너졌다. 이번 감사는 ID 기반 join을 사용한다. 논문은 양성만 제거하면 class prior도 변하는 한계를 인정한다. 원본 CTA와 추출 스크립트가 없어 zero patch의 upstream 원인을 복원하지 못했다. task는 patch 분류이며 전체 진단 시스템 성능으로 확대할 수 없다. 재사용 가능한 dataset artifact와 그 license는 이번 조회에서 확인하지 못했다. 논문 license를 데이터 권리로 대체하지 않는다. [본문·한계](https://arxiv.org/html/2611.31096v1)

**진단 → 가설 → 최소 실험 — 평가자 제안.** zero 판정의 정확성과 삭제의 학습 효과를 분리한다. 우선 immutable ID의 1:1 join 및 환자 overlap을 검사하고, 동일 split·모델·seed에서 full, 삭제, 같은 수 random 삭제를 비교한다. 추가로 class weighting을 통제해 양성 prior 변화가 원인인지 검증한다. test를 보고 삭제 규칙을 조정하지 않는다.

**GO:** ID·split 검증 후 prior 통제 실험. **KILL:** “손상이 확실하므로 제거하면 좋아진다”는 자동 삭제 정책. zero 입력이 어떤 표현을 학습시켰는지에 관한 인과 결론은 아직 없다.

## 3. OmniV-Bench — 사람이 본 증거와 모델 입력의 차이를 감사한다

**확인 사실·저자 보고.** v1은 11/23 제출됐고 초록은 데이터·harness를 publication 시 공개하겠다고 명시한다. 저자는 360도 영상 4,123개, 사람 QA 8,923개, task 11종을 보고한다. 이번 실행에서 다운로드 artifact, 데이터 license, split membership은 확인하지 못했다. [공식 초록·이력](https://arxiv.org/abs/2611.31022)

**Annotation·평가 정책 — 저자 설명.** 30명이 VR로 영상을 보고 QA를 만들었으며, 모델 보조 filtering과 수동 검증을 거쳤다. 원본 영상은 웹·공개 dataset에서 수집하고 긴 영상을 clip으로 나눈다. 기본 평가는 영상당 50프레임과 같은 prompt를 사용하며, 전체 점수는 task 11종의 macro 평균이다. [본문 §3–4](https://arxiv.org/html/2611.31022v1)

**진단·가설 — 추론.** VR 주석자는 확인할 수 있었지만 고정 프레임·뷰에서는 보이지 않는 정답 근거가 있을 수 있다. 같은 원본에서 나온 clip의 상관성과 source 권리도 별도 감사 대상이다. 이는 확인된 label 오류·leakage라는 뜻이 아니다.

**최소 실험 — 공개 후 제안.** QA별 정답 근거의 timestamp·방향을 기록하고 원본 VR, 기본 입력, 같은 예산의 추가 viewpoint 조건을 짝비교한다. 입력에서 근거가 빠진 오류와 근거가 있어도 틀린 오류를 분리한다. source-video 기준 split·중복을 확인하고 task별 수와 macro/micro 결과를 병기한다.

**GO:** 현재는 annotation·입력 정책 추적과 감사 설계. **KILL:** 공개 예정 데이터를 이미 내려받았다고 표현하거나 adaptive tool의 추가 프레임·token 비용을 무시한 비교. 입력 예산·투영 방식이 다르면 **not strictly apples-to-apples**다.
