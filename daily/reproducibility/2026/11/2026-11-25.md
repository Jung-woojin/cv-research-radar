## 사례 1 — resize·padding을 끄는 ablation이 실행되지 않는다

**Claim과 조건.** [PR #51191](https://github.com/huggingface/transformers/pull/51191)은 11/24 18:55 UTC 게시됐다. 작성자는 70×93 RGB 입력과 기본 processor 설정에서 OWLv2의 `do_resize=False`, DeepseekVLHybrid의 `do_pad=False` 또는 `do_resize=False`가 예외를 낸다고 보고했다. checkpoint는 필요 없다. Python·torch·torchvision의 정확한 실행 버전과 hardware는 본문에서 미확인이다.

**Observed gap — 작성자 보고.** OWLv2 resize 비활성화와 Deepseek padding 비활성화는 `KeyError`, Deepseek resize 비활성화는 `UnboundLocalError`다. PR 적용 후 출력 shape를 제시하지만, 이는 작성자의 실행 결과이며 독립 실행으로 확인하지 않았다.

**사실·진단.** base `d7ef9c406d3f2dd73102c0440ad67abb779da8be`에서 [OWLv2 소스](https://github.com/huggingface/transformers/blob/d7ef9c406d3f2dd73102c0440ad67abb779da8be/src/transformers/models/owlv2/image_processing_owlv2.py#L392)는 resize 분기 안에서만 결과 dict를 채운다. [Deepseek 소스](https://github.com/huggingface/transformers/blob/d7ef9c406d3f2dd73102c0440ad67abb779da8be/src/transformers/models/deepseek_vl_hybrid/image_processing_deepseek_vl_hybrid.py#L191)는 resize 결과 변수와 padding 결과 dict가 해당 옵션에 의존한다. [diff](https://github.com/huggingface/transformers/pull/51191/files)는 기본 입력을 유지하고 분기 밖에서도 결과를 저장하도록 바꾼다.

**가설 → 최소 실험.** 문제는 표현 능력이 아니라 옵션을 끈 경로의 값 전달 누락이다. 동일 RGB 이미지로 resize/pad의 네 조합을 단일·혼합 크기 batch에서 검사한다. base와 PR head `6998af81640b5fda11de3337b757e22e043771a7`을 고정하고 예외, 두 해상도 tensor의 shape·pixel 차이를 기록한다.

**GO/KILL.** GO는 base 실패가 재현되고 변경한 분기에서만 해결되며 기본 경로가 보존되는 경우다. 예외가 사라져도 backend 간 shape가 다르면 동등성 주장은 KILL한다. 작성자가 명시한 Deepseek의 resize-off/default-pad 조건은 fast가 square pad를 하지만 PIL은 하지 않는 잔여 차이가 있다. 이 비교는 **not strictly apples-to-apples**다. PR은 open·미병합이며 bot의 테스트 권고 댓글만 확인했다.

## 사례 2 — 4-bit weight 저장 dtype이 activation까지 바꾼다

**Claim과 조건.** [#51195](https://github.com/huggingface/transformers/issues/51195)는 11/24 21:11 UTC 게시됐다. Transformers 5.24.1, bitsandbytes 0.50.2, PyTorch 2.14.1+cu130, H100 80GB에서 Inkling-2-Mini의 BF16·4-bit·gate projection 제외 조건을 대조했다. 제시된 입력은 이미지 없는 텍스트 질의·답변이며 assistant token에만 loss를 계산한다.

**Observed gap — 작성자 보고.** 단일 입력 loss는 BF16 1.357, 4-bit 4.748, gate down-projection을 양자화에서 제외하면 1.396이다. 이를 benchmark 점수나 seed 평균으로 해석하지 않는다. 정밀도와 변환 module 구성이 달라 **not strictly apples-to-apples**이며, 원인 분리용 intervention이다.

**사실·진단.** 고정 revision `660f059e21359b27d6f83ee9b7b827393404473e`의 [gate forward](https://github.com/huggingface/transformers/blob/660f059e21359b27d6f83ee9b7b827393404473e/src/transformers/models/inkling2_loop/modeling_inkling2_loop.py#L92)는 입력을 weight dtype으로 바꾼다. [bnb quantizer](https://github.com/huggingface/transformers/blob/660f059e21359b27d6f83ee9b7b827393404473e/src/transformers/quantizers/quantizer_bnb_4bit.py#L121)는 일반 FP32 제외 목록을 전달한다. packed uint8 weight와 연속값 activation의 dtype 계약이 어긋난다는 진단을 뒷받침한다.

**수정 상태와 한계.** [PR #51204](https://github.com/huggingface/transformers/pull/51204)는 11/25 00:41 UTC 게시됐고 head `30364eb8b5c1324027f45130c26879a7bd600682`, open·미병합이다. [diff](https://github.com/huggingface/transformers/pull/51204/files)는 비부동 weight일 때 cast를 피하고 gate 제외 목록과 strict 목록 처리를 추가한다. 추가 테스트는 projection을 lambda로 대체하고 출력 shape·dtype을 확인하므로 실제 Linear4bit의 입력값·checkpoint loss 복구를 입증하지 않는다.

**가설 → 최소 실험.** cast 손상이 주요 원인이면 동일 tokenizer·checkpoint revision·입력·mask에서 gate 입력 dtype과 값이 보존될 때 loss 격차가 줄어야 한다. BF16, 원래 4-bit, gate만 제외, cast만 수정의 네 조건을 대조하고 hook으로 projection 직전 dtype·분포를 기록한다. 이후에만 이미지 입력과 짧은 SFT로 확장한다.

**GO/KILL.** GO는 실제 bnb layer에서 uint8 입력이 사라지고 단일 개입이 손실 회복을 설명할 때다. FP32 제외와 cast guard를 동시에 바꾼 결과만으로 원인을 확정하는 주장은 KILL한다. 이미지 품질·학습 seed 분산의 개선은 아직 미확인이다.

## 사례 3 — packed training에서 sample 경계가 convolution까지 도달하지 않는다

**Claim과 조건.** [#51205](https://github.com/huggingface/transformers/issues/51205)는 11/25 00:58 UTC 게시됐다. 작성자는 Transformers main `bcac86f`, kernels 0.18.3, torch 2.8.0+cu128, Linux, RTX PRO 6000 Blackwell, kernel 사용 조건의 작은 무작위 Inkling text 모델에서 검사했다. collator는 `return_seq_idx=True`로 설정했다.

**Observed gap — 작성자 보고.** sample B를 고정하고 앞 sample A만 바꾸면 B의 최대 logit 차이가 약 `3.68e-5` 발생했다. kwargs 전달 수정 후 같은 차이가 0이었다고 보고했다. 작은 단일-seed 함수 검사의 결과이며 실제 학습 오염 규모나 VLM 정확도 하락을 측정한 것은 아니다.

**사실·진단.** 전체 SHA는 `bcac86f294df3be933f57f0702acc6bb56d48ec5`로 확인했다. [attention의 두 convolution 호출](https://github.com/huggingface/transformers/blob/bcac86f294df3be933f57f0702acc6bb56d48ec5/src/transformers/models/inkling/modeling_inkling.py#L221)과 [decoder의 두 호출](https://github.com/huggingface/transformers/blob/bcac86f294df3be933f57f0702acc6bb56d48ec5/src/transformers/models/inkling/modeling_inkling.py#L579)은 kwargs를 전달하지 않는다. 반면 [kernel 호출](https://github.com/huggingface/transformers/blob/bcac86f294df3be933f57f0702acc6bb56d48ec5/src/transformers/models/inkling/modeling_inkling.py#L528)은 kwargs에서 `seq_idx`를 읽는다. 경계 정보가 collator에 존재해도 소비 지점에 도달하지 않는 경로다.

**가설 → 최소 실험.** convolution 경계 처리가 원인이면 네 호출에 `seq_idx`를 전달하는 개입만으로 앞 sample 변화에 대한 B의 민감도가 없어져야 한다. 동일 weight·dtype·길이·attention 조건에서 A만 교체하고, B 단독/packed B 및 경계 직후/멀리 떨어진 token의 logit을 비교한다. hook으로 kernel의 실제 `seq_idx`를 확인하고 여러 seed·sample 순서·kernel on/off를 분리한다.

**GO/KILL.** GO는 경계 전달 누락과 국소 영향이 재현되고 해당 개입으로 제거될 때다. kernel을 끄면서 dtype·attention까지 바꾼 대조만으로 mechanism을 확정하면 KILL한다. 다른 Inkling 계열·멀티모달 경로로의 일반화는 별도 검사한다. 이슈는 open이며 댓글은 없었다. 독립 재현·병합 수정은 확인하지 못했다.
