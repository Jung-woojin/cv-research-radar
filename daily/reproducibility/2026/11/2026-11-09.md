## 핵심 사례

### 1. vLLM GPT-J FP8 KV-cache scale mapping

- **사실:** vLLM issue #65945는 compressed-tensors (LLM Compressor) checkpoint의 FP8 KV-cache scale을 GPT-J가 조용히 무시한다고 보고하며, issue가 #65949 bugfix PR에 연결돼 있다. PR 제목은 GPT-J용 compressed-tensors KV-cache scale name mapping 수정이다.
- **재현 조건:** compressed-tensors 형식의 GPT-J checkpoint와 FP8 KV-cache scale metadata가 필요한 serving path다. 정확한 vLLM build, GPU, CUDA, model revision, quantization config는 issue/PR만으로 완결되지 않는다.
- **관찰된 gap:** 공개 issue가 주장한 문제는 fail-fast가 아니라 scale을 무시한 채 실행될 수 있다는 점이다. 따라서 output/latency가 나온다는 사실은 intended quantization configuration 재현의 증거가 아니다.
- **가능 mechanism:** checkpoint metadata key와 loader가 기대하는 GPT-J key의 이름 불일치.
- **반증 가능한 최소 실험:** 수정 전/후 build에서 동일 checkpoint를 load하고, parsed KV-cache scale key/value, generated token match, fixed prompt log-probability, peak memory/latency를 같은 GPU·precision·batch에서 비교한다.
- **GO/KILL:** 수정 전후 parsed scale이 같거나 output/metadata가 변하지 않으면 해당 build/path에는 영향이 없다는 결론(GO: no-effect 기록). scale parsing 또는 fixed-prompt output이 달라지면 기존 결과를 non-reproducible configuration으로 격리(KILL: 성능 비교 중단).
- **한계:** GPT-J 및 특정 compressed-tensors 경로 사례이며 모든 vLLM/VLM checkpoint로 일반화할 수 없다.

### 2. Transformers 5.22.2 — distributed backend 조건

- **사실:** 공식 patch release는 distributed fix로 `device_id`를 NCCL일 때만 설정하도록 수정했다고 명시한다. [release](https://github.com/huggingface/transformers/releases)
- **재현 조건:** single-GPU와 distributed launch, backend(NCCL 또는 다른 backend), PyTorch/CUDA/NCCL 조합이 분리돼야 한다.
- **진단:** 코드가 동일해도 runtime backend에 따라 device initialization 동작이 달라질 수 있다. 따라서 “같은 Transformers major/minor”만 기록하면 부족하다.
- **최소 실험:** 동일 tiny VLM/decoder smoke test를 1 GPU와 multi-GPU NCCL에서 pre/post 5.22.2로 실행하고, launch success, rank-local device, loss/logit checksum, step time을 기록한다.
- **GO/KILL:** 같은 manifest에서 checksum과 step completion이 유지되면 upgrade 가능(GO); backend-specific launch/device mismatch가 나면 version pin 및 issue reproduction bundle을 남긴다(KILL: 비교 실험 진행 중단).
- **한계:** 릴리스 노트에 seed variance나 CV metric 변화는 제공되지 않는다.

### 3. Ultralytics 8.4.207 — fresh install 및 GPU artifact 보존

- **사실:** 공식 릴리스 노트는 fresh Paddle environment에서의 missing `six` 문제를 고치고, GPU build를 CPU build로 대체하지 않도록 수정했다고 밝힌다. [release](https://github.com/ultralytics/ultralytics/releases)
- **재현 조건:** 새 environment, 설치 solver/index, Paddle GPU package, OS/CUDA 조합이 모두 manifest에 필요하다.
- **진단:** 동일 training/inference command가 성공해도 CPU wheel로 silent fallback되면 latency, memory, device behavior가 바뀌어 GPU 재현이라고 할 수 없다.
- **최소 실험:** 깨끗한 environment에서 8.4.206/8.4.207을 각각 설치하고, `six` import, installed package version, CUDA availability, one-batch device placement, deterministic inference checksum을 수집한다.
- **GO/KILL:** GPU package·device placement·checksum이 의도대로 유지되면 fresh-install recipe로 GO; CPU fallback이나 missing dependency가 나오면 benchmark/latency 결과를 무효화하고 lockfile을 고친다(KILL).

### 4. Supervision 0.31.5 — evaluator version drift

- **사실:** release는 OpenCV 환경에서 oriented-box IoU/NMS/metric의 exact clipper 사용과, 가림 중 LineZone track state 보존을 명시한다. [release](https://github.com/roboflow/supervision/releases)
- **재현 risk:** 같은 predictions라도 Supervision version, OpenCV 설치 여부, `max_absent_frames`, tracker가 바뀌면 OBB metric 또는 count가 달라질 수 있다.
- **최소 실험:** 같은 prediction JSON과 video clip을 0.31.4/0.31.5 × OpenCV 유무 × fixed parameter로 재평가한다.
- **GO/KILL:** 순위/metric/count가 안정적이면 evaluator migration을 허용(GO); 순위 reversal 또는 count drift가 있으면 version-specific 결과로 분리(KILL: historical score 직접 비교 금지).

## 오늘의 진단 → 가설 → 최소 실험

- **관찰:** 세 사례 모두 모델 weight보다 loader·backend·package/evaluator의 hidden condition이 결과를 바꾼다.
- **가설:** 재현 실패의 큰 비율은 model architecture가 아니라 artifact interpretation과 environment drift에서 생긴다.
- **최소 실험:** 실행마다 model/checkpoint hash, git commit, Python/PyTorch/CUDA/runtime, backend, precision/quantization, dataset/evaluator version을 JSON manifest로 저장하고 fixed prompt/batch checksum을 함께 남긴다.
- **성공:** 다른 clean environment에서 manifest와 checksum/metric tolerance가 재현된다.
- **실패:** checksum 또는 parsed artifact metadata가 다르면 새 score 보고보다 configuration divergence를 먼저 해결한다.

## 오늘의 GO / KILL

- **GO:** vLLM compressed-tensors나 distributed VLM을 쓰는 실험은 loader metadata assertion과 fixed-prompt checksum을 smoke test에 추가한다.
- **GO:** Ultralytics benchmark는 fresh-install GPU verification을 CI/실험 시작 단계에 둔다.
- **KILL:** evaluator version·backend·quantization metadata가 없는 과거 run과 새 run의 성능/latency를 직접 비교하지 않는다.
