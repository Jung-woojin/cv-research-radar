# CV Paper Idea Radar — 2026-11-10

## 요약

- 최근 공개된 V-Thinker artifact는 “thinking with images”의 점수보다, 합성 renderer·tool action·benchmark record가 실제로 시각적 근거를 강제하는지 진단할 수 있는 관찰 가능성을 제공한다.
- V-Perception-40K에는 이미지·좌표 질문/답·생성 Python·element attribute가 함께 있어, 의미를 보존한 재렌더링으로 visual grounding과 renderer shortcut을 분리할 수 있다.
- V-Interaction-400K에는 원본/편집 이미지·tool code·CoT가 있어, 모델이 action을 설명하는지 실제 image outcome을 예측하는지 구분할 수 있다.
- VTBench의 500 records와 1,500 QA 설명은 task-level record 구성의 audit 필요성을 드러낸다. benchmark contract를 명시하는 것이 재현성 contribution이 될 수 있다.
- Ultralytics v8.4.208은 prediction/tracking NMS default만 0.5로 바꾸고 validation은 0.7로 유지한다. architecture gain 없이 evaluation–deployment gap을 만들 수 있는 직접적인 intervention이다.
- 이번 주 1순위는 **RenderCounterfactual-VL**이다. 작은 1k-sample audit으로 시작 가능하고, renderer style을 바꿔도 좌표·답이 유지되는지라는 강한 반증 기준이 있다.
- **ActionOutcome-VL**은 image-editing agent reliability로 확장성이 있고, **ConfigParity-Det**은 작은 GPU에서도 가능한 CV systems/benchmark 논문 후보다.
- 아래 proposal은 저자 주장과 별개의 연구 제안이며, 설치·학습·재현을 수행하지 않았다.

## 근거와 후보 선별

조사 기준은 2026-11-07~10 KST의 공식 release·repository·dataset 원문이다. V-Thinker 논문/README의 model score는 **저자 주장**이고, Hugging Face viewer의 split/schema와 Ultralytics release의 default 변경은 **검증 가능한 사실**이다. 아래 proposal은 이 사실에서 출발한 **추론/제안**이다.

| 후보 신호 | 원문에서 확인한 사실 | 사용 |
|---|---|---|
| V-Thinker | point-level perception → interactive reasoning의 두 단계 curriculum과 VTBench 3 task를 설명 | A, B |
| V-Perception-40K | 36.7K viewer rows, image/question/answer/python_code/element attribute fields | A |
| V-Interaction-400K | preview 252K samples 공지, 25 parquet split, 원본/편집 image와 tool code fields | B |
| VTBench | 500 viewer records와 3 task question/answer·annotation image fields | B, C |
| Ultralytics v8.4.208 | predict/tracking NMS default 0.5, validation 0.7 | C |
| vLLM hybrid-GDN issue | batch-dependent greedy divergence 보고 | 제외: 11월 2일로 이번 핵심 창 밖이며 VLM 일반성 증거 없음 |

## Proposal A — RenderCounterfactual-VL: 코드 렌더링의 style shortcut과 실제 point grounding을 분리하는 VLM 진단

1. **문제**: 합성 도표·기하 이미지에서 좌표 정답을 맞히는 VLM이 실제 element 위치를 읽는지, renderer의 font·palette·stroke·padding 규칙을 이용하는지 알기 어렵다.
2. **근거와 gap**: V-Perception-40K viewer는 image, coordinate question/answer, `python_code`, `element_arrtibute`를 함께 제공한다. point-level perception alignment 설명은 있으나 style-preserving 또는 semantics-preserving counterfactual grounding 결과는 제공하지 않는다.
3. **가설**: element graph와 정답 좌표를 보존하고 renderer nuisance만 바꾼 counterfactual에서 성능/좌표 일관성이 떨어진다면, gain 일부는 renderer shortcut일 수 있다. counterfactual consistency regularization은 이 하락을 줄일 수 있다.
4. **방법**: code와 attribute에서 semantic graph를 추출하고 palette/font/stroke/canvas/padding intervention generator를 만든다. original–counterfactual answer/coordinate consistency loss와 optional grounding head를 사용한다. 새 backbone은 필수가 아니다.
5. **baseline**: answer-only visual SFT, 일반 image augmentation, OCR/geometry parser, consistency loss가 없는 동일 VLM.
6. **데이터·지표**: license/revision이 확인된 V-Perception subset과 1k pilot에서 coordinate exact match, normalized distance, element hit, counterfactual flip, style-family worst cell을 측정한다.
7. **ablation**: nuisance 유형, element graph, loss weight, unseen renderer, small/overlapping point, answer canonicalization.
8. **failure / negative result**: code가 viewer image를 재현하지 못하면 causal claim을 중단한다. augmentation baseline이 동등하면 graph module을 제거한다. semantics가 변한 counterfactual은 invalid bucket으로 분리한다.
9. **novelty risk와 방어**: synthetic augmentation·grounding과 겹칠 수 있다. 평균 점수가 아닌 code-derived semantic invariants 아래의 counterfactual failure cell을 측정 단위로 삼는 것이 차별점이다.
10. **4–8주 MVP**: 1주 1k schema/render audit, 2주 intervention generator, 3주 baselines, 4주 failure taxonomy; 이후 두 번째 renderer와 human semantic validation을 추가한다.
11. **예상 기여**: code-conditioned grounding counterfactual protocol; style/semantic failure taxonomy; minimal intervention의 risk–robustness curve.
12. **제목 후보**: *RenderCounterfactual-VL: Diagnosing Style Shortcuts in Point-Level Visual Grounding*; *Does the VLM See the Point?*
13. **초록/서론**: 좌표 정확도가 true grounding을 뜻하지 않을 수 있음을 보이고, semantic invariants로 style만 바꾼 audit와 consistency intervention을 제시한다.
14. **관련연구/방법**: visual grounding, synthetic data, invariant learning, renderer randomization; graph → counterfactual render → agreement → consistency training.
15. **실험 표·그림**: renderer-family × model 표, style heatmap, accuracy–flip scatter, valid/invalid failure gallery.
16. **첫 실험**: 1k records에서 palette/font/padding 세 intervention과 100개 semantic validation을 수행한다.
17. **GO/KILL**: valid counterfactual에서 flip이 non-trivial하고 unseen renderer 개선이 있으면 GO; flip이 낮거나 re-render fidelity가 낮으면 KILL.

## Proposal B — ActionOutcome-VL: image-editing reasoning에서 계획·도구 코드·편집 결과의 삼자 정합성

1. **문제**: interactive VLM이 tool code나 CoT를 출력해도, action이 원본을 올바르게 편집해 target outcome을 만들었는지는 별도로 검증되지 않을 수 있다.
2. **근거와 gap**: V-Interaction-400K에는 original image code, edited image, tool code, CoT-with-code, answer가 있다. 저자들은 image-to-code 확장 가능성을 설명하지만 tool trace와 edited outcome의 causal consistency metric은 확인되지 않았다.
3. **가설**: instruction→tool-code와 tool-code→edited-image를 분리 채점하면 code-text similarity보다 hallucinated action을 더 잘 찾을 수 있다. outcome-consistency reward는 실행 가능한 action 비율을 높일 수 있다.
4. **방법**: instruction planner, constrained code decoder, sandboxed renderer 또는 static analyzer, original/action/outcome triplet scorer, mismatch 때만 local repair하는 verifier를 둔다. MVP는 임의 코드를 실행하지 않고 AST와 image-difference metadata로 시작한다.
5. **baseline**: answer-only VLM, code SFT, CoT+code SFT, post-hoc self-reflection, human-written tool recipe.
6. **데이터·지표**: provenance/license가 확인된 subset에서 syntax/AST validity, declared-edit match, 안전한 allowlist subset의 rendered similarity, instruction success, unnecessary action, repair cost를 보고한다.
7. **ablation**: code verifier, outcome scorer, shared planner, static-only path, edit type(crop/annotation/color/geometry).
8. **failure / negative result**: file/network access code는 실행하지 않고 static bucket으로 격리한다. pixel similarity만 높고 instruction semantics가 낮으면 성공이 아니다. target이 deterministic하지 않으면 단일 perceptual score로 claim하지 않는다.
9. **novelty risk와 방어**: visual program synthesis·agent verification과 겹친다. original → action → edited outcome의 세 edge를 독립 평가하고 unsafe execution 없는 audit path를 제공하는 것이 차별점이다.
10. **4–8주 MVP**: 1주 500 triplet audit, 2주 AST/edit taxonomy, 3주 verifier/baseline, 4주 safe renderer subset; 이후 repair loop와 human task success를 추가한다.
11. **예상 기여**: action–outcome consistency metric; static-first visual-tool audit; mismatch-selective repair.
12. **제목 후보**: *ActionOutcome-VL*; *Plan, Edit, Observe: Outcome-Consistent Reasoning for Interactive VLMs*.
13. **초록/서론**: trace가 outcome과 일치하는지 측정하고 plan/code/outcome 분리 채점과 selective repair를 평가한다.
14. **관련연구/방법**: visual program synthesis, tool agents, execution verification, image editing; triplet parser → verifier → mismatch gate → repair.
15. **실험 표·그림**: edit type별 validity/success, static/rendered score 상관, repair-cost Pareto, failure gallery.
16. **첫 실험**: 500 examples에서 AST parse와 declared operation–image diff 일치를 이중 검수한다.
17. **GO/KILL**: verifier가 human outcome error를 code-text similarity보다 잘 분리하고 safe repair가 success를 올리면 GO; data alignment가 불안정하면 dataset audit으로 축소/KILL한다.

## Proposal C — ConfigParity-Det: validation과 serving default 불일치를 failure cell로 만드는 detection evaluation

1. **문제**: leaderboard validation이 좋아도 serving NMS·confidence·tracking default가 다르면 crowded, small-object, video association cell의 실제 행동은 달라질 수 있다.
2. **근거와 gap**: Ultralytics v8.4.208은 predict/tracking NMS IoU default를 0.5로, validation은 0.7로 유지한다. nearby objects가 crowded scene에서 suppress될 수 있다는 release note는 결과 방향의 증명이 아니라 configuration mismatch를 조작할 수 있는 공식 signal이다.
3. **가설**: config-paired evaluation은 “더 좋은 detector”와 “다른 decision layer”를 분리한다. dense/small cell의 validation–serving gap을 예측하는 config-sensitivity profile이 필요하다.
4. **방법**: config manifest capture, NMS/threshold/tracker sweep, crowd/small/isolated strata builder, serving-gap predictor, risk-sensitive default selector를 둔다. backbone 변경은 없다.
5. **baseline**: validation default, serving default only, global fixed NMS, class-agnostic NMS, simple grid search.
6. **데이터·지표**: license-clear 1k-image pilot에서 AP/recall, duplicate rate, false suppression, ID switch, count error, ECE, validation–serving gap을 함께 보고한다. 조건이 다르면 **not strictly apples-to-apples**로 표시한다.
7. **ablation**: IoU 0.5/0.7, confidence, tracker, strata definition, calibration selector, explicit/implicit config.
8. **failure / negative result**: sparse data에서는 crowding claim을 하지 않는다. 하나의 framework default로 detector 일반 결론을 내리지 않는다. gap이 없으면 framework-specific migration note로 축소한다.
9. **novelty risk와 방어**: NMS tuning/benchmark protocol과 겹친다. cell마다 evaluation config와 deployment config의 causal gap을 계량하고 risk-sensitive selector를 검증하는 점이 차별점이다.
10. **4–8주 MVP**: 1주 manifest/strata harness, 2주 1k differential run, 3주 tracker/metric, 4주 selector, 이후 second detector/video validation.
11. **예상 기여**: config-paired protocol; crowd/small deployment-gap taxonomy; explicit-default risk selector.
12. **제목 후보**: *ConfigParity-Det*; *When Validation Is Not Serving*.
13. **초록/서론**: 동일 checkpoint라도 decision defaults가 다르면 failure cell이 바뀐다는 점과 config-paired protocol을 제시한다.
14. **관련연구/방법**: detection evaluation, NMS, calibration, tracking, reproducibility; manifest → config pair → cell stratification → gap metric → selector.
15. **실험 표·그림**: config-pair × stratum, AP–duplicate Pareto, ID-switch heatmap, implicit-default case study.
16. **첫 실험**: checkpoint 하나와 1k images에서 0.5/0.7 NMS만 바꾸고 prediction, validation, tracking을 분리 저장한다.
17. **GO/KILL**: dense/small gap이 재현되고 selector가 global default보다 Pareto 개선을 보이면 GO; gap이 작으면 KILL/기술 보고서로 축소한다.
