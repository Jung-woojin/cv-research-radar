## Q1. Tile 경계의 작은 객체 누락 중 얼마가 feature 해상도보다 class-aware 후처리로 설명되는가?

**Observation·왜 지금:** 병합된 #27188은 tile seam fragment 복구에서 다른 class의 box가 객체를 억제하던 문제를 다룬다. PR은 NMS에는 class offset이 있지만 후속 coverage 검사에는 없었다고 설명한다. 검출 수 증가는 정답 recall 개선의 증거가 아니다. [공식 PR·원인·재현](https://github.com/ultralytics/ultralytics/pull/27188)

**문제·Gap:** 작은 객체 누락을 P2 feature나 해상도 부족으로 해석하기 전에, 이미 생성된 candidate가 merge 단계에서 사라지는 비율을 분리해야 한다. 이 버그 수정 자체의 신규성은 낮으며, 여러 장면에서 표현력과 후처리를 구분하는 오류 분해가 연구의 핵심이다.

**Diagnosis → Mechanism → Hypothesis:** 앞 단계와 뒤 단계의 class 의미가 다르면 타 class의 큰 box가 seam fragment를 제거한다. 추론상 candidate를 고정한 class-aware 복구만으로 해당 조건의 일부 recall을 회복할 수 있고, seam 밖 객체에는 영향이 작을 것이다.

**최소 개입·MVP:** PR의 parent와 병합 revision에서 동일 합성 box·score·tile geometry를 사용한다. 덮는 box의 class만 같음/다름으로 바꾸고 seam 유무 및 agnostic NMS를 대조한다. 이어 정답이 있는 aerial/UAV 이미지의 저장 candidate에 merge만 다시 적용한다. 실제 데이터 확보 전 합성 검사는 구현 계약 검증에 한정한다.

**Baseline·dataset·metric:** 동일 checkpoint의 기존/수정 merge가 baseline이다. 사용 권한과 class 매핑을 확인한 VisDrone 검증 이미지 또는 보유 UAV 주석에서 object size·seam 거리·타 class overlap별 recall, precision, 중복 검출률을 집계한다. 이미지 단위 paired bootstrap으로 불확실성을 표시한다.

**GO/KILL·ablation:** 타 class·seam 조건에서만 누락이 줄고 오검출·중복 비용을 설명할 수 있으면 확장한다. 수만 늘거나 효과가 한 예시에만 있으면 task 개선 주장은 중단한다. tile 크기·overlap·conf·max_det는 고정하고 agnostic 조건을 별도로 둔다.

**기여·위험·기간:** 기대 기여는 작은 객체 오류의 발생 단계별 진단표다. 알려진 버그 재포장과 dataset 특이성이 위험이다. 4~8주 내 여러 장면·checkpoint에서 같은 분해가 반복되면 짧은 진단 논문 후보이며, 아니면 regression audit로 축소한다. Negative result여도 모델 구조 변경 전에 제거할 후처리 confound를 정리할 수 있다. Compute는 낮음: CPU box 재처리부터 가능하며 전체 추론 비용은 미측정이다.

## Q2. UAV 안정화의 inlier 통계는 어떤 움직임 조건에서 배경 정렬 실패를 숨기는가?

**Observation·왜 지금:** Consensus Capture 논문은 같은 방향으로 움직이는 차량이 homography 추정을 끌어가는 현상을 보고한다. 공식 구현은 정지 배경 정렬을 평가하고 inlier 수를 진단용으로 구분한다. sample은 전체 순위의 증거가 아닌 smoke test라고 명시한다. [논문·이력](https://arxiv.org/abs/2611.17190) · [공식 구현](https://github.com/rfonod/stabilo-benchmark)

**문제·Gap:** 높은 내부 일관성을 외부 정확도의 대리 지표로 사용하면 객체 위치 변화가 카메라 이동으로 흡수될 수 있다. 새 architecture보다 어떤 조건에서 내부 통계가 경보 역할을 잃는지 정량화하는 질문이다.

**Diagnosis → Mechanism → Hypothesis:** moving foreground의 면적과 움직임 방향 일관성이 커질수록 잘못된 대응점 집합도 높은 합의를 만들 수 있다. 추론상 정지 지상점 오차는 inlier 비율보다 이 실패를 더 잘 구분하고, 움직이는 객체 masking이 위험 조건에서 선택적으로 도움을 줄 것이다.

**최소 개입·MVP:** 공식 sample로 입력·audit·평가 연결을 먼저 검사한다. 이후 여러 hover에서 ORB와 SIFT 각각 none/HBB/OBB masking을 비교한다. 동일 면적의 무작위 masking을 넣어 foreground 제거 효과와 단순 feature 수 감소를 구분한다. reference frame·해상도·feature budget·seed를 고정한다.

**Baseline·dataset·metric:** 공식 sample과 접근 가능한 full benchmark 또는 보유 UAV 영상의 지상점 주석을 쓴다. identity·unmasked estimator가 baseline이다. 지상점 오차, object-center error, capture 지표, 실패율과 masking 포함 latency를 측정한다. foreground 면적·방향 일관성별로 층화하고 장소 단위로 집계한다.

**GO/KILL·ablation:** 외부 오차와 내부 통계의 불일치가 장소를 바꿔 반복되고 targeted masking이 면적 대조군보다 유리하면 진행한다. reference 자체 오차나 feature budget 차이로 설명되면 가설을 축소한다. 정지 control도 포함한다. [평가·audit 방법](https://arxiv.org/html/2611.17190v1)

**기여·위험·기간:** 기대 기여는 내부 신뢰도 지표의 실패 영역과 운영 경보 기준이다. 원 논문이 이미 현상과 masking을 다루므로 단순 재현은 신규성이 낮다. 4~8주에는 장소 외 일반화와 불확실성 진단까지 필요하다. Negative result는 inlier 기반 경보가 유효한 조건을 한정한다. Compute는 낮음~중간: sample은 GPU·detector weights 없이 가능하나 full benchmark 시간은 미측정이다.

## Q3. Tagging adaptation이 novel detection과 caption을 손상시키는 원인은 shared weight 변화인가, 평가·decode 조건인가?

**Observation·왜 지금:** MUMU 보고서는 Florence-2-base를 공유하는 팀들이 서로 다른 과제별 결과를 얻었고, shared LoRA tagging adaptation과 caption 품질 저하가 함께 나타났다고 기술한다. 팀 간 학습 coverage·TTA·경로가 달라 인과적 negative transfer의 증거로는 부족하다. [보고서 방법·결과](https://arxiv.org/html/2611.16925v1)

**문제·Gap:** 종합점수로는 어떤 과제를 희생했는지 알기 어렵다. 공식 웹의 private final test 30,000장과 논문의 held-out 1,038장은 일치하지 않아 동일 manifest인지 미확인이다. 이를 해결하기 전 원 challenge 점수 재현을 주장하지 않는다. [공식 규칙·split](https://lsvos.github.io/mumu)

**Diagnosis → Mechanism → Hypothesis:** shared parameter update가 기존 caption/novel 표현을 바꿀 수 있지만 label coverage나 decode 차이도 대안 원인이다. 추론상 coverage와 decode를 맞춘 뒤에도 shared LoRA에서 손실이 남고 frozen backbone의 tagging head에서 줄어들면 weight 간섭 가설이 지지된다.

**최소 개입·MVP:** 같은 Florence-2 checkpoint로 무학습 baseline, frozen feature tagging head, shared LoRA를 비교한다. 동일 training example·label mask·step budget을 적용하고 TTA·cross-task refinement는 끈다. caption 길이·task prompt·box parser도 고정한다.

**Baseline·dataset·metric:** 접근 가능한 COCO Captions와 LVIS의 고정 검증 subset에 별도 tag label을 준비한다. 소스 이미지 중복과 누락 label을 감사하고 adaptation에서 보지 않은 class를 명시한다. tagging macro-F1, base/held-out class AP, caption 지표를 개별 보고한다. 이는 challenge hidden novel set의 대체 재현이 아니다.

**GO/KILL·ablation:** 반복 seed에서 tagging 향상과 기존 과제 손실이 동반되고 frozen 경로에서 완화되면 진행한다. coverage·decode를 맞추자 손실이 사라지면 weight 간섭 주장은 중단하고 protocol confound를 결론으로 남긴다. adapter 제거 복원도 검사한다.

**기여·위험·기간:** 기대 기여는 작은 unified model의 능력 보존 진단이다. 기존 forgetting 연구와의 중복, annotation 비용이 위험이다. 4~8주에는 한 모델의 인과 ablation까지 가능성이 있으나 학회 경쟁력은 추가 모델 검증에 달린다. Compute는 중간: 먼저 저장 feature의 head 학습과 소규모 추론을 한다. 대회의 PC inference 8GB 제한은 이 GPU의 학습 가능성을 보장하지 않는다.

## Q4. 위험을 맞힌 Video VLM은 실제 사건의 행위자·시점에도 의존하는가?

**Observation·왜 지금:** DashBench는 위험 누락과 존재하지 않는 행위자·행동 설명을 보고하고, 위험 구간만 주는 실험도 다룬다. 이는 저자 결과이며 실제 안전 성능 인증이 아니다. [논문·이력](https://arxiv.org/abs/2611.16767) · [평가·실험 본문](https://arxiv.org/html/2611.16767v1)

**문제·Gap:** 위험 존재를 맞혔어도 영상 근거 없이 상황 prior로 답했을 수 있다. 사건 clip만으로는 정상 장면의 오경보를 평가할 수 없으며, 사건 시점을 알려주는 oracle 조건은 입력 정보가 달라진다.

**Diagnosis → Mechanism → Hypothesis:** 위험 cue prompt와 도로 맥락이 언어적 정답을 유도할 수 있다. 추론상 cue가 binary recall을 높여도 정상 control의 오경보와 틀린 행위자 설명이 늘 수 있다.

**최소 개입·MVP:** 사용 권한이 있는 driving/CCTV 사건·정상 clip에서 동일 모델·16-frame sampling·해상도·decode로 중립/cue prompt를 paired 비교한다. 사건 구간 제거와 길이·밝기를 맞춘 정상 구간 교체를 별도 대조한다. 사람이 prompt 조건을 모른 채 행위자·행동·시점을 판정한다.

**Baseline·dataset·metric:** 동일 모델 중립 prompt가 baseline이다. 원 데이터 접근을 확인하지 못했으므로 자체 clip 실험을 DashBench 재현이라고 부르지 않는다. event recall, 정상 false-positive rate, 행위자·시점 일치율, 근거 없는 설명률, 출력 형식 실패를 분리한다. 가능하면 사람 판정과 LLM judge 불일치를 감사한다.

**GO/KILL·ablation:** cue 이득이 오경보 증가 또는 사건 제거 후 유지되는 설명과 연결되면 shortcut 진단으로 확장한다. 실제 근거 정합성도 함께 좋아지면 단순 prior 가설을 축소한다. shuffled frame은 시간 의존성 검사로만 사용하며 부자연스러움의 영향도 기록한다.

**기여·위험·기간:** 기대 기여는 Answer–Evidence Gap의 대조 평가다. 기존 hallucination benchmark와 중복, 장면 교체 artifact, 주관적 annotation이 위험이다. 4~8주에는 소규모 다중 prompt 진단이 가능하나 다중 모델 검증이 필요하다. Negative result도 cue가 안전하게 유효한 조건을 보여준다. Compute는 중간~높음이며 8GB에서 원 논문 모델·설정을 그대로 돌릴 수 있다고 가정하지 않는다.

## Q5. 이미지 수별 완료율을 분리하면 평균 처리량에 숨은 VLM 요청 대기 불이익이 드러나는가?

**Observation·왜 지금:** vLLM #67292는 async scheduling과 chunked prefill off에서 encoder 한도 때문에 미뤄진 큰 요청이 작은 요청에 계속 추월당하는 재현을 제공한다. #67385는 뒤따르는 encoder 요청의 배정을 잠시 막는 수정안과 tests를 제시하지만 조회 시 미병합이다. [issue·재현](https://github.com/vllm-project/vllm/issues/67292) · [수정안·한계](https://github.com/vllm-project/vllm/pull/67385) · [tests diff](https://github.com/vllm-project/vllm/pull/67385/files)

**문제·Gap:** 서비스 처리량이 유지돼도 여러 이미지를 쓰는 요청의 관측 표본이 timeout으로 탈락할 수 있다. 완료 요청만 정확도를 계산하면 serving 선택 편향이 생길 수 있다는 것이 연구 가설이다. 원 issue는 reasoning 정확도 저하를 증명하지 않았다.

**Diagnosis → Mechanism → Hypothesis:** encoder cache 점유·해제 시점과 whole-request 배정이 크기별 진행 기회를 바꿀 수 있다. 추론상 지속 부하에서는 이미지 수별 완료율 차이가 커지고, timeout을 포함한 평가와 완료본만의 평가는 달라질 수 있다.

**최소 개입·MVP:** weights 없는 공개 scheduler fixture에서 원본/PR head와 sync/async, chunked on/off를 비교한다. 큰 요청의 이미지 수·작은 요청 유입을 고정하고 최초 배정 step·추월 수·cache 여유를 기록한다. 다음 단계에서만 실제 모델 serving으로 확장한다.

**Baseline·dataset·metric:** 공개 synthetic scheduler request stream을 쓰며 text-only와 image prefix-cache-hit 요청을 대조한다. 요청 크기별 TTFT·timeout·완료율·처리량을 함께 측정한다. 정확도 단계는 고정 multi-image QA manifest를 사용하고 전체 요청 수와 미완료 수를 별도 공개한다.

**GO/KILL·ablation:** 부하를 바꿔 크기별 대기 격차와 단일 수정의 회복·작은 요청 비용이 반복되면 진행한다. synthetic 현상만 있고 실제 부하에서는 격차가 없으면 실서비스 일반화는 중단한다. cache hit, image token 수, output 길이, 도착률을 분리한다.

**기여·위험·기간:** 기대 기여는 VLM 평가의 serving 선택 편향 감사다. scheduling은 CV 능력 연구와 거리가 있고 수정 자체의 신규성도 낮다. 4~8주에는 fixture와 한 모델까지가 현실적인 범위이며 논문화에는 정확도 평가 편향의 실측이 필요하다. Negative result는 적용되지 않는 부하 영역을 한정한다. Compute는 fixture 낮음, serving 높음이며 CUDA platform 감지 요구와 실제 VRAM을 먼저 확인해야 한다.

## 공통 비교 계약과 평가

모든 실험은 dataset revision·train/val/test split·checkpoint·pretraining·외부 데이터·해상도·TTA·inference backend·reasoning/token/frame budget·compute budget·evaluator commit을 manifest에 고정한다. 확인하지 못한 값은 미확인으로 남긴다. 오늘은 구현·평가 revision을 실행 환경에 고정하지 않았으므로 재현 성공을 선언하지 않는다.

Q1의 agnostic/class-aware, Q2의 static/dynamic 및 offline/real-time, Q3의 팀별 결과, Q4의 full clip/oracle window, Q5의 sync/async는 조건 자체가 달라 **not strictly apples-to-apples**다. 조건 차이는 실험의 독립 변수로 명시하고 서로 다른 설정의 순위를 능력 차이로 단정하지 않는다.

## 오늘의 선택과 실행 순서

- **가장 먼저 테스트: Q1.** 합성 box의 class만 바꾸는 CPU paired test로 원인을 분리하고, 이후 정답 이미지에서 precision·recall을 확인한다.
- **RTX 5060 Ti 8GB에서도 시작 가능한 질문: Q1·Q2.** CPU box 검사와 GPU 없는 공식 UAV sample은 가능하다. 전체 영상 처리·모델 추론의 VRAM과 시간은 미측정이다.
- **장기 박사주제: Q4를 중심으로 Q2 연결.** 영상 근거가 실제 답변을 지지하는지 위치·시점·대조 개입으로 검증한다. UAV·maritime으로의 확장은 별도 데이터·domain 검증이 필요하다.
- **4~8주 계획:** 1~2주 기전 재현·manifest 고정, 3~4주 대조군과 다른 장면 검증, 5~8주 반복성·실패 영역·negative result 정리. 효과가 없으면 architecture 추가보다 가설을 축소한다.

오늘 바뀐 것은 새 모델 순위가 아니라 후처리 계약·외부 정렬·과제별 손실·증거 정합성·대기 공정성을 직접 감사할 근거가 늘었다는 점이다. 미해결 부분은 각 현상이 실제 task 성능과 평가 편향에 얼마나 기여하는지이며, 위 최소 실험이 이를 분리한다.
