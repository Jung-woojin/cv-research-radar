## 사례 1 — EfficientLoFTR: 배치 구성은 재현 조건이다

**Claim / 커뮤니티 재현.** Transformers 5.22.2, Python 3.14, torch 2.15.0, macOS arm64 CPU FP32에서 `zju-community/efficientloftr`와 480×640 synthetic texture 쌍을 사용했다. 배치 shape와 대상 pair B를 고정하고 동반 pair만 교체한다. #50743은 B의 match index 9,600개 중 4,144개가 바뀌었다고 보고한다. #50744는 B가 배치 index 1일 때 keypoint 9,600개 중 4,800개가 바뀌며 최대 x 차이가 약 0.317 pixel이라고 보고한다. 모두 작성자의 결과다. [index 제보](https://github.com/huggingface/transformers/issues/50743), [refinement 제보](https://github.com/huggingface/transformers/issues/50744)

**사실 / mechanism.** v5.22.2 소스에는 match index를 `cat`한 뒤 batch shape로 `reshape`하는 경로와, `spatial_expectation2d(...)[0]`으로 첫 batch의 좌표만 선택하는 경로가 있다. 전자는 pair별 행 결합을, 후자는 pair별 offset을 깨뜨릴 수 있다는 것이 작성자의 진단이다. 두 이슈는 open이며 댓글은 없었다. 수정·릴리스는 확인하지 않았다. [고정 소스](https://github.com/huggingface/transformers/blob/v5.22.2/src/transformers/models/efficientloftr/modeling_efficientloftr.py)

**진단 → 가설 → 최소 실험.** seed가 같아도 batch neighbor가 출력에 영향을 주면 데이터 순서나 batch size 변경이 재현 격차처럼 보일 수 있다. 동일 B를 `[B,A]`, `[B,D]`, `[A,B]`, `[D,B]`에 넣고 matches·scores·keypoints를 비교한다. 두 변경 제안인 `stack(dim=1)`과 `[0]` 제거를 각각/함께 적용해 원인을 분리한다. index 검사는 서로 다른 기하, offset 검사는 동일 기하를 사용해 혼입을 줄인다.

**GO/KILL.** 배치 permutation·동반 pair 교체에서 대상 pair의 의미적 출력이 유지되고 단일 pair reference도 통과하면 GO. 배치 독립성 실패가 남은 결과로 matching 성능 차이를 모델 능력이나 seed variance로 설명하는 것은 KILL. 실제 pose/geometry benchmark 영향은 미확인이다.

## 사례 2 — LTX-2.3: NaN 제거와 화질 재현은 다른 검증이다

**커뮤니티 재현 조건 / observed gap.** #15281은 Diffusers `843f1743e259`, torch 2.11.0+cu130, Transformers 5.22.2, bitsandbytes 0.50.2, Tesla T4에서 LTX-2.3 distilled를 실행했다. NF4 transformer/connectors, CPU offload, VAE tiling, 576×320·25 frames·8 steps 조건에서 FP16 출력이 전부 NaN이라고 보고한다. FP32 norm과 FP32 입력 embedding을 사용하면 NaN은 없어지지만 저대비 영상이 남았다는 것도 작성자 주장이다. [제보·전체 코드](https://github.com/huggingface/diffusers/issues/15281)

**사실 / 추가 근거.** 고정 소스의 `per_token_rms_norm`은 입력을 FP32로 올리지 않고 제곱·평균한다. 11/14 댓글 작성자는 CPU의 shipped 함수에서 상수 255는 정상, 257·300 등은 0으로 정규화되며 FP32 upcast 대조는 정상이라고 보고했다. 이는 함수 수준의 추가 측정이며 전체 T4 영상의 독립 재현은 아니다. 이슈는 open이다. [고정 함수](https://github.com/huggingface/diffusers/blob/843f1743e259/src/diffusers/models/condition_embedders/condition_embedder_ltx2.py), [댓글](https://github.com/huggingface/diffusers/issues/15281#issuecomment-6877728303)

**진단 → 가설 → 최소 실험.** 제곱 overflow와 FP16 변환 전에 이미 표현 범위를 넘는 embedding을 분리해야 한다. 100·255·257·300 및 FP16 범위 초과 입력으로 원본 dtype, cast 직후, norm 직후의 finite mask와 reference 오차를 기록한다. **이미 inf가 된 값을 뒤에서 FP32로 바꿔도 원래 값은 복구되지 않는다.** 전체 실행은 동일 prompt embedding·latent를 고정하고 norm, connectors, VAE precision을 한 요소씩 바꿔 최초 비정상 위치와 frame 통계를 검사한다.

**GO/KILL.** finite 검사와 사전 고정한 FP32/BF16 reference 허용오차를 통과하면 후속 품질 검증으로 GO. NaN만 없어졌다는 이유로 FP16 재현 완료를 선언하는 것은 KILL. dtype·양자화 연산 경로가 달라 해당 제보의 시간 차이를 일반적인 속도 향상으로 해석하는 것도 **not strictly apples-to-apples**다.

## 사례 3 — LTX tiled decode: 같은 latent라도 프레임 정렬을 검사해야 한다

**커뮤니티 재현 조건 / observed gap.** #15282는 Diffusers 0.39.0, torch 2.11.0+cpu, Python 3.13, Linux Xeon CPU에서 LTX-Video의 49-frame·256×160 입력을 latent mode로 encode한 뒤 같은 latent를 tiled/untiled로 decode한다. 작성자는 동일 프레임 PSNR 30.50 dB보다 이전 프레임과의 36.85 dB가 높고, chunk의 첫 프레임을 제거하도록 바꾸면 동일 프레임 PSNR이 41.64 dB가 된다고 보고한다. [제보](https://github.com/huggingface/diffusers/issues/15282)

**사실 / 추가 주장.** v0.39.0 소스는 후속 chunk에 `decoded[:, :, :-1]`을 적용한다. 작성자는 중복이 chunk 첫 프레임인데 끝을 제거하므로 시간축이 밀린다고 진단했다. 같은 날 댓글에서는 LTX-2.3과 LTX-2 VAE도 검사했다고 추가 보고했다. 이 확장은 같은 작성자의 후속 측정이며 독립 검증은 아니다. 이슈는 open이고 병합 수정은 확인하지 않았다. [고정 소스](https://github.com/huggingface/diffusers/blob/v0.39.0/src/diffusers/models/autoencoders/autoencoder_kl_ltx.py)

**진단 → 가설 → 최소 실험.** 시간 오정렬을 생성 품질 저하로 오인할 수 있다. decode 경계 전후에서 tiled frame과 untiled의 같은/이전/다음 frame 오차를 함께 기록한다. 원본과 첫 프레임 제거안을 비교하고, 정지 영상과 움직이는 영상을 나눠 검사한다. causal/noncausal VAE별 경계 처리는 별도 검증한다.

**GO/KILL.** 경계 뒤 최적 정렬 offset이 0으로 유지되고 frame count·경계 연속성도 통과하면 GO. seed나 video metric을 조정해 오정렬을 가리는 것은 KILL. tiled/untiled 차이가 완전히 0이어야 한다고 가정하지 않는다.

## 사례 4 — CPU Generator: seed 숫자만으로 실행 계약이 완성되지 않는다

**문서 claim / 커뮤니티 재현.** 공식 재현성 가이드는 CPU Generator를 권하고 `randn_tensor`의 CPU 생성 후 device 이동을 설명한다. #15285는 Diffusers `f598e6e6a`, Transformers 5.22.0, torch 2.15.0, Apple M1 Pro MPS에서 tiny DiffusionGemma 파이프라인의 initial canvas 생성이 CPU Generator를 거부한다고 보고한다. 이는 discrete diffusion의 인접 재현성 사례이며 CV benchmark 측정은 아니다. [공식 가이드](https://huggingface.co/docs/diffusers/using-diffusers/reusing_seeds), [제보](https://github.com/huggingface/diffusers/issues/15285)

**사실 / 검증 범위.** 고정 pipeline 소스는 `torch.randint(..., device=device, generator=generator)`를 직접 호출한다. 반면 `randn_tensor`는 CPU Generator인 경우 CPU에서 생성한 뒤 이동한다. 11/14 댓글은 GTX 1650·torch 2.15.0+cu132에서 동일한 randint 호출 형태의 CUDA 오류를 확인했지만 전체 pipeline이나 LLaDA2는 실행하지 않았다고 명시한다. 이슈는 open이다. [pipeline 소스](https://github.com/huggingface/diffusers/blob/f598e6e6a/src/diffusers/pipelines/diffusion_gemma/pipeline_diffusion_gemma.py), [helper 소스](https://github.com/huggingface/diffusers/blob/f598e6e6a/src/diffusers/utils/torch_utils.py)

**진단 → 가설 → 최소 실험.** CPU/device Generator × CPU/MPS/CUDA의 가능한 조합에서 randint·rand·multinomial 호출과 제안된 CPU 생성 후 이동 경로를 검사한다. 매 run Generator를 새로 만들고 초기 canvas·RNG state·출력 hash를 보존한다. 같은 Generator 객체의 반복 사용에 따른 state 소비도 구분한다.

**GO/KILL.** Generator/device 계약과 초기 tensor 재현을 통과한 조합만 GO. device Generator로 바꿔 실행됐다는 사실을 CPU RNG와 동일한 표본 또는 cross-device bitwise parity로 해석하는 것은 KILL. 공식 가이드도 동일 seed만으로 완전 재현이 보장되지는 않는다고 설명한다.

## 공통 비교 조건과 오늘의 GO/KILL

backbone·checkpoint revision·pretraining·data/split·resolution·hardware·precision·batch·TTA·evaluator를 맞춘 공통 성능 실험은 없다. 네 사례의 수치를 서로 비교하는 것은 **not strictly apples-to-apples**다. synthetic API fixture에는 dataset/split/TTA가 적용되지 않으며, 공개 checkpoint의 immutable revision은 제보 코드에서 별도 pin하지 않았다. 이는 후속 재현에서 보완할 조건이다.

- **1순위 GO:** EfficientLoFTR의 배치 독립성 fixture를 고정한다. seed를 바꾸기 전에 입력의 다른 batch 항목이 대상 출력을 바꾸는지 검사한다.
- **GO:** LTX는 finite mask와 시간 정렬을 품질 평가 앞단에 둔다. 둘 다 통과한 뒤 동일 조건의 seed 반복으로 넘어간다.
- **GO:** 실험 manifest에 source/package revision, weight hash, processor, batch 구성, norm dtype, tiling 경계, Generator 장치·초기 state를 기록한다.
- **KILL:** open issue를 공식 correction이나 배포된 fix로, 함수 단위 측정을 전체 모델 재현으로, 실행 완료를 품질 검증으로 바꾸어 서술하지 않는다.
- **연구 가설:** seed sweep에 앞선 배치·dtype·시간축·RNG 계약 검사가 재현 격차의 일부를 저비용으로 분리할 수 있다. 동일 fixture의 검사 결과와 downstream 실패를 함께 수집해야 반증 가능하며, 현재는 제안이다.
