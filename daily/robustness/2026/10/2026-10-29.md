## 사례 1 — Untrusted visual context는 별도의 robustness shift cell이다

**확인 사실.** [OWASP AI Security & Privacy Guide](https://github.com/owasp/www-project-ai-security-and-privacy-guide/blob/main/content/ai_exchange/content/docs/2_threats_through_use.md)는 adversarial image 안의 hidden instruction이 model behavior를 바꿀 수 있으며, 사용자 upload처럼 공격자가 입력을 통제하는 direct injection과 앱이 외부 이미지·스크린샷·문서를 자동 수집하는 indirect injection을 구분합니다. 문서는 prompt injection을 완전히 막기 어렵기 때문에 model alignment 외에 least privilege와 oversight로 blast radius를 줄여야 한다고 안내합니다.  
**공식 문서의 주장 범위.** 이는 일반적 threat model과 방어 원칙이지, 특정 VLM·특정 벤치마크의 attack success rate나 calibration 수치가 아닙니다.  
**Shift cell.** `trusted text query × untrusted visual context × action-capable agent`가 핵심 cell입니다. 일반 VQA 정확도는 높더라도, 시각 입력의 명령을 system/user instruction처럼 해석해 외부 도구·파일·계정 작업으로 연결하면 안전성은 별도 축에서 실패할 수 있습니다.  
**가능한 mechanism.** vision/OCR 표현이 prompt provenance를 보존하지 못하면, 이미지 안의 텍스트·레이아웃·시각적 cue가 신뢰 경계 밖의 data가 아니라 우선 지시처럼 작동할 수 있습니다.  
**최소 실험.** benign image 50개와 동일 이미지에 명시적/저대비/레이아웃 기반 instruction을 삽입한 50개를 준비합니다. retrieval on/off, tool 권한 read-only/action-enabled, source label 유무를 교차하고, (a) instruction-following error, (b) unsafe tool-attempt rate, (c) legitimate task completion, (d) human escalation rate를 측정합니다.  
**GO/KILL.** GO: untrusted-content label·tool allowlist·human confirmation으로 unsafe action이 줄면서 정상 task completion이 유지될 때. KILL: 차단이 단순 refusal 증가로만 나타나거나 benign input에서도 completion이 크게 떨어질 때.  
**해석.** 이는 특정 제품의 취약성 확인이 아니라, multimodal agent 평가에서 일반 정확도와 분리해야 할 robustness/grounding cell입니다.

## 공통 진단 → 가설 → 최소 개입

**진단.** 오늘 조사창에서 camera/weather/OOD의 새 정량 benchmark는 충분히 검증하지 못했습니다. 반면 untrusted visual context는 정확도 평균만으로 드러나지 않는 현실적 distribution shift이며, privilege가 붙으면 영향이 커집니다.

**가설.** 시각 입력을 단순 evidence와 executable instruction 후보로 구분하고 provenance를 보존하면, model-level 완벽 차단 없이도 실행 가능한 실패를 크게 줄일 수 있습니다.

**최소 개입.**

1. 이미지/OCR 텍스트를 별도 untrusted channel로 표시한다.
2. visual-content-derived instruction은 sensitive tool call의 근거로 단독 사용하지 않는다.
3. 읽기 전용 권한을 기본값으로 하고, write/send/login은 명시적 사람 확인을 요구한다.
4. 이미지 변형·source provenance·tool 권한을 축으로 robustness evaluation을 수행한다.

**오늘의 GO/KILL.**

- GO: 모델/agent 평가에 위 shift cell과 tool-attempt metric을 추가할 때.
- KILL/보류: 평균 VQA 성능이나 jailbreak 제목만으로 safety robustness를 주장하지 않습니다.
