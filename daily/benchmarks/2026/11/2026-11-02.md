## 1. Surya 2.5 — OCR benchmark 및 throughput 조건 갱신

**[사실]** Datalab의 공식 v0.23.0 release(2026-10-29)는 Surya 2.5를 기본 모델로 바꾸고, Surya 2 대비 1.7× pages/s 및 OmniParseBench 85.9를 보고한다. 공식 engineering note는 olmOCR-bench revision `54a96a6f`의 1,403 pages, vLLM 0.25.1, B200 1장, 24 concurrent requests, 12,384-token cap, MTP off, 3 passes를 명시한다.  
출처: https://github.com/datalab-to/surya/releases  
출처: https://app.datalab.to/blog/surya-2-5

**[저자 주장]** 2.5는 open model 중 1B parameter 미만에서 OmniParseBench 최고 성능이며, 2보다 더 빠르고 output-limit loop 비율도 낮다.

**[해석]** headline throughput과 benchmark score는 동일한 단일 조건이 아니다. DPI sweep은 별도 server/policy 조건을 포함하고, full-page regeneration은 package default와 다르다. 따라서 다른 OCR model card 또는 Surya 2의 과거 run과는 **not strictly apples-to-apples**다.

**진단 → 가설 → 최소 실험:** 동일 1,403-page revision에서 Surya 2/2.5를 같은 vLLM·GPU·DPI·concurrency·token cap으로 3회 paired run 한다. pages/s, completed-page fraction, OmniParseBench score, output-limit rate, p50/p95 page latency를 함께 기록한다.

## 2. R2R — spatial-VLM 평가 protocol의 실행 가능성

**[사실]** 공식 R2R 저장소는 inference/evaluation code와 4B·8B checkpoints를 공개하고 VSI-Bench, ReVSI, 3D-Point-QA 실행 스크립트를 제공한다. 8B paper setting은 VSI-Bench 128 frames, ReVSI 64 frames이며 4B는 16 frames다. 3D-Point-QA는 distance task에 δ1.25, point matching에 PCK@0.05, 3D coordinate mapping에 0.5m 이내 비율을 쓴다. 각 run은 raw prediction과 benchmark/frame별 metric JSON·XLSX를 남긴다.  
출처: https://github.com/yuqunw/R2R

**[저자 주장]** novel-view semantic rendering 보조 과제가 VSI-Bench·ReVSI·3D-Point-QA의 spatial reasoning을 개선한다.

**[해석]** checkpoint와 evaluator 공개는 결과 검증 가능성을 높이지만, frame count, base model revision, VGGT first-use download, GPU sharding이 비교 조건이다. training code/data-preparation이 “coming soon”이므로 full-training claim은 아직 독립 검증 범위가 아니다.

**진단 → 가설 → 최소 실험:** 고정 checkpoint/base model에서 16/32/64/128-frame sweep을 하고, accuracy/mean-relative-accuracy와 GPU memory·runtime을 병기한다. official paper frame setting은 별도 행으로 유지해 frame budget이 만든 gain과 모델 구조 gain을 분리한다.

## 오늘의 benchmark signal 3개

1. **OCR score는 harness configuration의 일부다.** Surya 2.5는 dataset revision·server·DPI·regeneration policy가 함께 공개돼 비교 가능성이 높아졌지만, 숫자만 옮기면 안 된다.  
2. **frame budget은 VLM benchmark protocol이다.** R2R는 benchmark별 frame 수와 metric을 명시해 score의 input-budget 의존성을 드러낸다.  
3. **artifact 공개가 leaderboard noise를 줄인다.** evaluator·raw prediction output이 있어야 새 주장과 기존 baseline을 실제로 대조할 수 있다.

## 내 연구에 바로 연결되는 포인트

Video/VLM 또는 aerial temporal reasoning 실험에서는 frame count·sample rule·resolution·base-model revision·evaluator commit을 논문 표의 필수 열로 둔다. OCR처럼 task별 server/retry policy가 결과를 바꾸는 경우, quality와 latency를 같은 manifest에 기록한다.
