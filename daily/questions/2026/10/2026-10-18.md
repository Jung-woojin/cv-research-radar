## Q1. 안전 VLM의 배치 기준을 전체 정확도에서 “고위험 recall×행동 근거”로 바꾸면 모델 순위가 뒤집히는가?

### 1. 문제 정의

도로·항만 위험 장면에서 높은 hazard-presence accuracy가 실제 안전 판단을 보장하는지 검증한다. 특히 고위험 사례를 빠뜨리거나 방어 행동을 맞히지 못하는 모델을 평균 정확도가 우수하다는 이유로 선택하는 문제를 진단한다.

### 2. 왜 지금 가치가 있는가

BD-HazardVLM에서 세 VLM의 위험 존재 정확도는 88.0–89.2%로 89.0% 다수 클래스 기준선과 비슷했다. 위험 시점은 1.6–12.4%, 정확한 방어 행동은 2% 미만이었고, InternVL3-8B는 심각도 정확도 61.2%에도 고위험 58건의 recall이 0이었다.

### 3. 직접 근거와 Observation → Gap

- **확인된 저자 주장:** coarse hazard recognition과 fine-grained defensive reasoning 사이에 큰 격차가 있다.
- **Gap:** 모델 선택표가 accuracy, high-severity recall, timing, action grounding을 하나의 안전 gate로 결합하지 않는다.
- **출처:** [BD-HazardVLM](https://arxiv.org/abs/2610.20627)

### 4. 핵심 가설

전체 accuracy가 비슷한 모델도 `고위험 recall × 행동 exact match × 근거 충실도`로 평가하면 순위가 달라지며, 이 순위가 인간 안전 감사와 더 잘 일치한다.

### 5. 최소 실험(MVP)

해무·항만·도로 영상 120장을 `no / visible / latent hazard`로 균형 구성한다. 공개 VLM 3개에 동일 JSON 프롬프트를 적용하고, accuracy·고위험 recall·timing·action·근거 영역 overlap을 측정한다.

### 6. baseline과 dataset

- Dataset: 공개 도로 위험 데이터의 재사용 가능 subset + 해무·항만 영상 소규모 수작업 세트
- Baseline: 다수 클래스, binary accuracy 순위, severity accuracy 순위
- Ablation: 지역 단서 제거, 위험 단서 crop, 서구식 도로 용어를 지역 표현으로 치환

### 7. 성공/실패 판정 metric

Primary는 high-severity recall과 action exact match다. **GO:** binary accuracy 상위 모델과 safety composite 상위 모델이 다르고, safety composite가 인간 2인의 배치 선호와 Kendall τ≥0.6. **KILL:** 세 모델 순위가 모든 지표에서 동일하거나 근거 overlap의 평가자 합의 κ<0.5.

### 8. compute 난이도

**2/5.** 120장 추론과 소규모 주석 중심이라 8GB GPU 또는 API 혼합으로 가능하다.

### 9. novelty 위험요인

위험 평가 자체는 이미 많다. novelty는 새로운 데이터 개수보다 지역 편향·고위험 꼬리·행동 근거를 하나의 배치 gate로 묶는 데 달려 있다.

### 10. 4~8주 내 논문화 가능성

**중상.** 두 도메인과 세 모델만으로도 evaluation/diagnostic short paper가 가능하다.

### 11. negative result여도 얻는 결론

순위가 뒤집히지 않으면 복합 safety metric의 추가 효용이 작음을 보이고, 어떤 단일 지표가 가장 경제적인 대리변수인지 남길 수 있다.

- **평가:** novelty **4/5** · feasibility **5/5** · compute efficiency **5/5** · publication potential **4/5**

## Q2. VLM 의사결정 트리에 top-k 분기와 제한적 backtracking을 넣으면 해석 가능성을 유지하면서 초기 오답을 회복할 수 있는가?

### 1. 문제 정의

탐욕적 root-to-leaf 추론이 초기에 정답 클래스를 제거하는 MYOPIA 실패를, 불확실성 기반 다중 분기와 제한적 되돌리기로 완화할 수 있는지 검증한다.

### 2. 왜 지금 가치가 있는가

MYOPIA는 GTSRB, MNIST, CIFAR-10, MSCOCO와 세 VLM의 12개 조합 모두에서 트리 순회가 zero-shot보다 낮았다고 보고했다. label 속성 회상과 image grounding의 평균 격차도 모델별 9.5–13.8%p였다.

### 3. 직접 근거와 Observation → Gap

- **확인된 사실:** 공식 아티팩트에는 동결된 결과 DB와 평가 하네스가 있고, 초기 국소 오류와 answer extraction loss를 따로 분석할 수 있다.
- **Gap:** 기존 트리는 한 분기만 고르고 되돌리지 않아 불확실성을 버린다.
- **출처:** [MYOPIA 논문](https://arxiv.org/abs/2610.21573), [공식 아티팩트](https://github.com/islammesabah/VLM_Classification)

### 4. 핵심 가설

node confidence가 낮을 때 top-2 가지를 유지하고 최대 1회 backtracking하면, 방문 노드를 2배 미만으로 제한하면서 zero-shot 격차의 절반 이상을 회복한다.

### 5. 최소 실험(MVP)

CIFAR-10 1,000장과 공개 VLM 1개에서 greedy, top-2 beam, entropy-gated backtracking을 비교한다. 기존 트리와 결과 DB를 그대로 사용하고 순회 정책만 바꾼다.

### 6. baseline과 dataset

- Dataset: CIFAR-10; 후속으로 GTSRB
- Baseline: zero-shot, greedy tree, self-consistency 3회
- Ablation: confidence source를 token probability, verbalized confidence, prompt ensemble disagreement로 교체

### 7. 성공/실패 판정 metric

Accuracy, 정답 가지 회복률, 평균 방문 노드, 비용, 설명 일관성을 기록한다. **GO:** greedy 대비 ≥5%p 회복, zero-shot과의 격차 50% 이상 축소, 평균 방문 노드 <1.8배. **KILL:** 회복이 self-consistency baseline보다 낮거나 비용이 2배를 넘는다.

### 8. compute 난이도

**2/5.** 추론 정책 비교이므로 학습이 필요 없고 8GB GPU에서 소형 open VLM로 축소 가능하다.

### 9. novelty 위험요인

beam search 자체는 새롭지 않다. perceptual answerability, 오류 회복률, 설명 비용의 Pareto를 체계적으로 제시해야 기여가 생긴다.

### 10. 4~8주 내 논문화 가능성

**높음.** 공개 아티팩트와 명확한 negative baseline이 있어 실험 회전이 빠르다.

### 11. negative result여도 얻는 결론

되돌리기가 효과 없으면 오류의 주원인이 탐색 정책이 아니라 node question의 시각적 비답변성임을 확인해 트리 생성 기준을 바꿀 수 있다.

- **평가:** novelty **4/5** · feasibility **5/5** · compute efficiency **5/5** · publication potential **4/5**

## Q3. 첫 토큰 성능과 전체 생성 성능의 괴리를 이용해 VLM KV 압축의 “평가 누설 지수”를 만들 수 있는가?

### 1. 문제 정의

decode 단계의 visual KV를 제거해도 첫 토큰형 benchmark가 이를 관찰하지 못하는 문제를 정량화하고, 압축 기법의 잘못된 성공 판정을 자동으로 경고하는 지표를 만든다.

### 2. 왜 지금 가치가 있는가

TwinPrune은 MMBench·POPE·ScienceQA가 첫 생성 토큰만 채점해 decode KV eviction을 사실상 평가하지 않으며, visual KV를 모두 버려도 이 점수는 거의 유지되지만 TextVQA·MM-Vet는 크게 훼손될 수 있다고 보고했다.

### 3. 직접 근거와 Observation → Gap

- **확인된 저자 주장:** first-token probe와 full-pipeline probe는 서로 다른 추론 단계를 측정한다.
- **Gap:** 압축 논문별 benchmark 구성이 어느 단계의 손상을 숨기는지 비교하는 공통 수치가 없다.
- **출처:** [TwinPrune v2](https://arxiv.org/abs/2610.17530), [공식 저장소](https://github.com/Kai-Liu001/TwinPrune)

### 4. 핵심 가설

keep ratio 감소에 대한 `first-token slope − full-sequence slope`가 클수록 기존 benchmark가 decode 손상을 더 많이 숨기며, 이 괴리는 답변 길이와 시각 토큰 재참조 횟수로 예측할 수 있다.

### 5. 최소 실험(MVP)

LLaVA-1.5-7B 한 모델에서 visual KV keep ratio 1.0/0.5/0.25/0.125/0을 적용한다. POPE 300개와 TextVQA 300개를 평가해 first-token accuracy, EM/ANLS, 답변 길이, peak VRAM, decode throughput 곡선을 만든다.

### 6. baseline과 dataset

- Dataset: POPE, TextVQA; 가능하면 MM-Vet 소규모 subset
- Baseline: random eviction, H2O, no eviction
- Ablation: 첫 토큰만 채점, 첫 3토큰, 전체 문자열 채점

### 7. 성공/실패 판정 metric

평가 누설 지수, Spearman 순위 반전, VRAM-품질 Pareto를 사용한다. **GO:** keep ratio 조건 중 둘 이상에서 first-token 하락 <1%p이지만 full-sequence 하락 ≥5%p. **KILL:** 두 평가 곡선의 정규화 기울기 차이가 모든 데이터셋에서 2%p 미만.

### 8. compute 난이도

**3/5.** 7B 모델 추론 최적화가 필요하지만 양자화·300개 subset으로 8GB 환경에서 단계적으로 가능하다.

### 9. novelty 위험요인

TwinPrune이 이미 문제를 제기했다. novelty는 새 압축법보다 benchmark audit 지수의 일반성, 답변 길이·재참조 메커니즘과의 연결에 달려 있다.

### 10. 4~8주 내 논문화 가능성

**중상.** 여러 압축법·두 모델 계열까지 확장하면 evaluation paper 가능성이 있다.

### 11. negative result여도 얻는 결론

괴리가 일반화되지 않으면 첫 토큰형 benchmark가 위험한 조건과 안전한 조건을 구분하는 경계 자체가 유용한 결과다.

- **평가:** novelty **4/5** · feasibility **4/5** · compute efficiency **3/5** · publication potential **4/5**

## Q4. 해양 영상 월드 모델은 입력 장면보다 모델이 새로 만든 선박·부표를 가림 뒤 더 빨리 잊는가?

### 1. 문제 정의

월드 모델이 해무·가림 뒤 다시 나타나는 장면에서 입력으로 주어진 객체와 모델이 중간에 생성한 객체를 서로 다른 속도로 잊는지 측정한다.

### 2. 왜 지금 가치가 있는가

Orbia는 720개 사례와 6개 exploration/revisit protocol을 통해 input preservation, generated-content persistence, 3D self-consistency를 분리한다. 보기 좋은 프레임과 장기 세계 일관성이 다른 능력이라는 직접 근거다.

### 3. 직접 근거와 Observation → Gap

- **확인된 사실:** 공식 benchmark는 short 22초/357 frame과 long 60초/961 frame 사례, RGB-D reference와 anchor mask를 제공한다.
- **Gap:** 해양 CCTV 연구에는 모델 생성 객체와 입력 객체의 재방문 기억을 나누는 protocol이 거의 없다.
- **출처:** [Orbia 논문](https://arxiv.org/abs/2610.20693), [공식 코드](https://github.com/worldbench/Orbia), [공식 데이터](https://huggingface.co/datasets/Orbia/Orbia)

### 4. 핵심 가설

해무·가림이 포함된 장기 rollout에서 generated-content persistence가 input preservation보다 먼저 감소하며, 작은 선박·부표에서 격차가 가장 크다.

### 5. 최소 실험(MVP)

Orbia 공개 short case 12개와 해양 합성 case 20개에 `first view → occlusion/fog → revisit` 경로를 만든다. 객체 mask별 DINO feature consistency, ID 유지, depth-scale agreement를 측정한다.

### 6. baseline과 dataset

- Dataset: Orbia short subset + 공개 해양 영상에서 만든 제한적 합성 경로
- Baseline: frame similarity, input-anchor preservation
- Ablation: 객체 크기, fog 강도, 가림 길이, input/generated 객체

### 7. 성공/실패 판정 metric

Persistence gap, ID switch rate, regional depth-scale error를 사용한다. **GO:** generated 객체의 persistence가 input 객체보다 ≥10%p 낮고 3개 조건 중 2개 이상에서 재현. **KILL:** 차이가 객체 크기 보정 후 3%p 미만이거나 evaluator 간 순위가 불일치.

### 8. compute 난이도

**4/5.** world-model 추론은 무겁지만 공개 결과·소수 사례와 evaluator audit부터 시작할 수 있다.

### 9. novelty 위험요인

Orbia의 단순 해양 적용으로 보일 수 있다. novelty를 얻으려면 안개·수평선·작은 이동 객체가 persistence failure에 주는 고유 효과를 분리해야 한다.

### 10. 4~8주 내 논문화 가능성

**중간.** 우선 benchmark extension으로 가능하며, 새 월드 모델 학습까지 요구하면 기간을 넘긴다.

### 11. negative result여도 얻는 결론

해양 도메인에서 generated/input 격차가 없으면 Orbia식 failure taxonomy의 도메인 경계를 밝히고 evaluator 전이성 문제를 제기할 수 있다.

- **평가:** novelty **4/5** · feasibility **3/5** · compute efficiency **2/5** · publication potential **4/5**

## Q5. 이미지당 1–10 pixel 주석에서 ViT token 다양성은 작은 객체 recall을 실제로 개선하는가?

### 1. 문제 정의

초저예산 semantic segmentation에서 token-space representative sampling이 전체 mIoU뿐 아니라 tiny ship·buoy·pedestrian 같은 작은 영역의 recall도 높이는지 검증한다.

### 2. 왜 지금 가치가 있는가

TEAL은 frozen ViT의 native token lattice에서 diversity selection 후 decoder grid uncertainty를 적용해, 네 데이터셋에서 1 pixel/image 조건의 최대 +24.36 mIoU와 10 pixel/image에서 fully supervised 성능의 최대 97%를 보고했다. 그러나 이는 조건별 최대치이며 작은 객체 이득을 직접 보장하지 않는다.

### 3. 직접 근거와 Observation → Gap

- **확인된 저자 주장:** 동일 DINOv3 backbone 통제에서도 token selection 이득이 유지된다.
- **Gap:** 대표성 sampling이 면적이 작은 희귀 영역보다 넓은 배경·주요 클래스 token을 선호할 수 있다.
- **출처:** [TEAL](https://arxiv.org/abs/2610.20881)

### 4. 핵심 가설

global token diversity만 사용하면 전체 mIoU는 오르지만 tiny-region recall은 정체하며, 면적 역가중 또는 boundary-aware candidate를 결합해야 작은 객체에 이득이 난다.

### 5. 최소 실험(MVP)

CamVid 또는 해양 segmentation 200장에서 1/5/10 pixel per image로 random, pixel uncertainty, token diversity, rarity-weighted token diversity를 3개 seed로 비교한다.

### 6. baseline과 dataset

- Dataset: CamVid와 선박/부표가 있는 소형 해양 subset
- Baseline: random, entropy, TEAL식 token diversity
- Ablation: small-region oversampling, boundary 제외, token layer 조합

### 7. 성공/실패 판정 metric

전체 mIoU, small-region recall, annotation hit rate, seed 표준편차를 사용한다. **GO:** 5 pixel에서 random 대비 small-region recall ≥5%p, 전체 mIoU 손실 ≤1%p. **KILL:** 이득이 seed 3개 중 2개에서 재현되지 않거나 label hit-rate 증가만으로 전부 설명됨.

### 8. compute 난이도

**2/5.** frozen encoder와 작은 decoder 중심이라 RTX 5060 Ti 8GB에 가장 적합하다.

### 9. novelty 위험요인

단순 class-balanced sampling으로 보일 수 있다. token geometry와 객체 면적·경계의 상호작용을 분석해야 한다.

### 10. 4~8주 내 논문화 가능성

**높음.** 데이터 규모와 학습 비용이 작고 negative result도 annotation policy 분석으로 남는다.

### 11. negative result여도 얻는 결론

token diversity가 작은 객체를 돕지 않으면 foundation feature의 대표성이 annotation equity와 다르다는 명확한 진단 결과가 된다.

- **평가:** novelty **4/5** · feasibility **5/5** · compute efficiency **5/5** · publication potential **4/5**

## Q6. voxel decision 변화가 작은 구조만 제거하면 실제 종단간 지연과 tail-class 안전성도 함께 보존되는가?

### 1. 문제 정의

Decision-FLIP의 output-decision 기반 pruning이 같은 수의 parameter를 제거하는 magnitude·random 기준보다 배치 latency와 작은/희귀 클래스 IoU를 안정적으로 보존하는지 검증한다.

### 2. 왜 지금 가치가 있는가

Decision-FLIP은 eligible row 12–79% 제거, bank/query-dependent latency 7–45% 감소, whole-model 최대 8.0%, peak memory 최대 16.6% 감소와 mIoU 변화 최대 0.18 point를 보고했다. FALCON은 컴포넌트 프록시가 마감을 만족해도 전체 6카메라 파이프라인은 약 1.3초/프레임임을 보여, 실제 종단간 검증 필요성을 강화한다.

### 3. 직접 근거와 Observation → Gap

- **저자 주장:** 같은 K에서 random 제거는 일부 모델을 붕괴시켰고 Mean-FLIP은 다섯 설정에서 supervised Taylor와 같거나 우수했다.
- **Gap:** 전체 mIoU의 작은 변화가 tiny/rare class와 end-to-end tail latency 보존을 뜻하는지는 불명확하다.
- **출처:** [Decision-FLIP](https://arxiv.org/abs/2610.20917), [FALCON](https://arxiv.org/abs/2610.22143)

### 4. 핵심 가설

같은 K에서 decision-flip pruning은 magnitude pruning보다 rare-class IoU 하락과 p99 latency 변동이 작지만, fixed-cost module 비중이 커지면 parameter 감소와 종단간 속도 이득의 상관은 약해진다.

### 5. 최소 실험(MVP)

공개 occupancy 모델의 validation 200개에서 동일 K의 random, magnitude, decision-flip 제거를 비교한다. compiled checkpoint를 만들고 동일 hardware·batch·precision에서 component와 end-to-end latency를 각각 1,000회 측정한다.

### 6. baseline과 dataset

- Dataset: Occ3D-nuScenes 또는 공개 occupancy 소형 validation
- Baseline: no pruning, random, magnitude, supervised Taylor 가능 시 추가
- Ablation: recovery 없음/1 epoch, frequent/rare class, component/end-to-end timing

### 7. 성공/실패 판정 metric

Primary는 rare-class IoU, p99 latency, peak VRAM이다. **GO:** VRAM ≥10%, end-to-end p99 ≥5% 개선, rare-class IoU 하락 ≤1%p. **KILL:** component는 빨라지지만 end-to-end 개선 <2%이거나 rare-class 하락이 전체 mIoU 하락의 3배 초과.

### 8. compute 난이도

**4/5.** occupancy 추론과 profiling이 필요해 8GB에서는 축소 모델·200개 calibration으로 시작해야 한다.

### 9. novelty 위험요인

pruning 비교 자체는 포화돼 있다. output decision, tail class, 실제 compiled latency를 같은 protocol로 묶는 것이 핵심 기여다.

### 10. 4~8주 내 논문화 가능성

**중간.** 공개 코드와 체크포인트 확보 여부가 가장 큰 일정 위험이다.

### 11. negative result여도 얻는 결론

decision 안정성이 latency나 rare-class 보존을 예측하지 못하면, pruning proxy와 deployment endpoint 사이의 구조적 단절을 보여준다.

- **평가:** novelty **4/5** · feasibility **3/5** · compute efficiency **2/5** · publication potential **4/5**
