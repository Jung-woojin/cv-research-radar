## 1. ModelOpt 0.48.0 BEVFormer ONNX PTQ — 코드와 평가 조건은 공개, 새 재측정 결과는 아님

- **출처:** [ModelOpt 0.48.0 release](https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.48.0), [BEVFormer README](https://github.com/NVIDIA/Model-Optimizer/blob/e2f328a/examples/onnx_ptq/bevformer/README.md).
- **사실:** 공식 release는 temporal calibration, INT8/FP8 quantization, TensorRT engine build, nuScenes evaluation을 포함한 BEVFormer ONNX PTQ 예제를 추가했습니다. README는 DL4AGX source revision `9f7b291…`, BEVFormer-tiny checkpoint SHA-256, TensorRT 10.14 container, deployment GPU에서 plugin 재컴파일을 명시합니다.
- **artifact 조건:** calibration은 ordered training sample 600개와 `prev_bev` propagation을 사용하며, full accuracy evaluation은 nuScenes validation 6,019개를 요구합니다. INT8은 entropy, FP8은 max calibration을 사용하고 custom plugin·MatMul은 FP16으로 남깁니다.
- **문서의 제한:** README의 NDS/mAP·speedup 표는 과거 TensorRT 10.14 full-validation engine reference이며, DL4AGX container integration은 3 sample로만 검증했고 NDS/mAP를 재실행하지 않았다고 적었습니다.
- **해석:** 공개된 것은 재현 가능한 code/evaluator path이지, 새 환경에서 검증된 universal performance claim이나 새 model weight release가 아닙니다.
- **10–30분 smoke test:** checksum만 확인한 checkpoint로 pinned revision/container를 빌드하고 3-sample calibration artifact 생성, FP16 engine export와 plugin load까지 확인합니다. full NDS/mAP·speedup은 smoke test 범위 밖으로 기록합니다.
- **GO/KILL:** hash·source revision·TensorRT/GPU가 모두 기록되면 GO입니다. 3-sample integration이나 historical engine 수치를 새 배포 성능으로 인용하면 KILL입니다.

## 2. Qwen3-VL/Qwen3.5-VL unified export — language-only quantization의 경계

- **출처:** [ModelOpt 0.48.0 release](https://github.com/NVIDIA/Model-Optimizer/releases/tag/0.48.0).
- **사실:** release는 PTQ 또는 QAD를 거친 Qwen3-VL/Qwen3.5-VL checkpoint의 Hugging Face unified export를 추가했다고 밝힙니다. Qwen3.5-VL에는 GatedDeltaNet linear-attention layer와 MoE shared expert 처리도 포함합니다.
- **중요한 범위:** release note는 language model만 quantize하며, vision tower는 source Hugging Face checkpoint에서 복사된다고 명시합니다.
- **해석:** export artifact를 “full VLM quantized weights”로 표시하면 vision encoder·projector의 precision, memory, latency를 오해하게 됩니다. 새 code support와 공개된 model weight는 별도의 사실입니다.
- **10–30분 smoke test:** source model revision과 export config를 고정하고, saved `config.json`·quantization metadata·vision tower file hash를 확인합니다. image 1개와 text 1개로 load/forward를 확인하되, latency/VRAM은 hardware·precision·image resolution 없이는 비교하지 않습니다.
- **GO/KILL:** language/vision component별 precision과 source revision을 metadata에 남기면 GO입니다. model card·checksum 없이 converted artifact를 재배포하거나 full-model quantization으로 홍보하면 KILL입니다.

## 3. System One Bench v1.13.0 — 결과 tag와 frozen evaluator artifact

- **출처:** [System One Bench v1.13.0 release](https://github.com/alilibx/system-one-bench/releases/tag/v1.13.0), [공식 README](https://github.com/alilibx/system-one-bench).
- **사실:** v1.13.0은 2026-11-02 release tag `54b313c`로 GLiDE를 3,250 text case와 5개 vision dataset에 실행한 round를 공개했습니다. release는 동일 request body 사용, System One Index 84.1, Vision Index 82.5, 그리고 second full run에서 4,850 decision 중 7개 답 변경을 보고합니다.
- **artifact/평가 조건:** README는 `data.lock.json`의 suite·image SHA-256, fixed source revision, `data_lock.py` 검증, pinned data requirements를 명시합니다. data/prompt/dataset을 바꾸면 새 benchmark version으로 보고 모든 model을 재실행해야 한다고 규정합니다.
- **해석:** 이것은 새 weights release가 아니라 versioned evaluator/result artifact입니다. 모델 간 비교에는 유용하지만, provider model revision·network·new data domain 차이를 제거하지는 않습니다.
- **10–30분 smoke test:** repository를 checkout한 뒤 requirements-data를 설치하고 build 후 `data_lock.py`로 text/image lock을 검증합니다. external API key가 없는 환경에서는 scoring path가 아니라 data/evaluator integrity까지만 확인합니다.
- **GO/KILL:** lock이 일치하고 model/version·run date가 기록되면 GO입니다. hash가 다른 data의 score를 기존 leaderboard와 직접 비교하거나 release tag를 model weight provenance로 표기하면 KILL입니다.
