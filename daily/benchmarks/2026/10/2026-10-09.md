## 1. Ledger: 장시간 물체 기억을 “답을 맞히는가”에서 “무엇을 보존했는가”로 분해

**무엇이 바뀌었나.** [Never Look Back](https://arxiv.org/html/2610.10538v1)은 Ledger라는 persistent 3D object memory를 제안했다. 물체의 위치, resting-location history, 문맥 설명을 보존하고, 질문 시 원본 frame이나 video를 다시 읽지 않는 조건을 명시한다. 평가 범위는 HD-EPIC의 2,400개 3D Perception/Object Motion 질문, Ego4D VQ3D validation 164 query, UCS-Bench 2,771개 질문이다.

**저자 결과.** GPT-5.4 reader 기준 HD-EPIC prototype-averaged accuracy가 blind 29.7%에서 Ledger 42.6%로 올랐고, UCS-Bench에서는 48 sampled frames에 Ledger를 더한 설정이 46.3%, DirectMe graph를 더한 설정이 42.9%였다. VQ3D는 답을 반환한 query에서 median localization error 0.99 m를 보고했다. 100개의 multi-scene stitched stream 분석에서는 scene change가 construction과 retrieval 모두를 악화시키며 per-scene construction이 손실을 일부 회복했다고 보고한다.

**비교 가능성 점검.**

- HD-EPIC의 published method 행은 answerer와 protocol이 서로 다르므로 Ledger의 동일-reader 재구현 행과만 직접 비교해야 한다.
- VQ3D는 반환한 예측의 오차와 coverage를 함께 봐야 한다. 0.99 m만으로 abstention이 많은 시스템인지 판단할 수 없다.
- UCS-Bench는 48 frames, memory-only, frames+memory가 서로 다른 evidence budget이다.
- memory construction은 offline이며, timestamp 질문에서는 이후 기록을 필터링하지만 construction 자체가 causal하지 않다는 제한이 있다.
- 공식 원문에서 별도 Ledger 공개 저장소 링크는 확인하지 못했다. 재현성은 현 시점에서 논문의 세부 appendix에 더 의존한다.

**진단 → 가설 → 최소 실험.**

- 진단: 장기 추적 실패가 association 자체보다 “scene cut 이후 좌표계와 retrieval 후보가 섞이는 문제”로 나타난다.
- 가설: scene-aware memory partition과 identity confidence decay를 함께 쓰면 false move와 cross-scene identity collision을 줄일 수 있다.
- 최소 실험: 20–30분 egocentric clip 10개에 인위적 scene cut을 0/2/5회 삽입하고, global memory와 per-scene memory를 비교한다. IDF1, move false-positive rate, query accuracy, coverage, query당 token 수를 함께 기록한다. 같은 detector·pose·reader를 고정해야 한다.

**판정:** 행동 가능성이 가장 높다. Woojin의 video tracking·persistent identity 관심과 직접 맞닿는다.

## 2. HeiCo-FOCUS: long-video VLM을 object identity와 누적 상태로 검증

**무엇이 바뀌었나.** [HeiCo-FOCUS](https://arxiv.org/html/2610.10156v1)는 96시간의 colorectal surgery video에서 30,000개 VQA pair를 구성한다. object recognition, temporal grounding, aggregation, event/procedure understanding, complex reasoning의 다섯 capability를 frame→segment→full-procedure track으로 평가한다. 39명의 수술 분야 전문가가 annotation 과정에 참여했으며, sigmoid resection procedure를 held-out test로 권장한다.

**저자 결과.** 평가한 10개 frontier VLM 중 약 절반만 text-only baseline을 명확히 넘었다. 모델 평균 accuracy는 event/procedural understanding 56.5%, temporal grounding 19.7%였다. human reference도 장시간 누적이 필요한 event aggregation 35%, duration estimation 40%였지만 각 20문항 표본이므로 정밀한 인간 상한으로 해석하기 어렵다. [공식 코드 저장소](https://github.com/IMSY-DKFZ/orena-focus)는 연결되어 있으나, 원문 작성 시 데이터는 Hugging Face 공개 예정이고 우선 저자 문의 방식이다.

**비교 가능성 점검.**

- full-procedure 성능은 frame track과 입력 길이·정보량이 다르므로 같은 열로 단순 평균하면 안 된다.
- 작은 staple처럼 개체별 annotation이 곤란한 물체와 video artifact가 명시된 난점이다.
- test split은 procedure type으로 분리되지만 병원·장비·수술자 domain shift를 완전히 대신하지 않는다.
- 데이터가 아직 즉시 공개되지 않아 현 시점의 독립 재현성은 제한적이다.

**진단 → 가설 → 최소 실험.**

- 진단: 모델은 event 의미는 어느 정도 읽지만 “언제 들어왔고 아직 남아 있는가”를 누적하는 state update에 실패한다.
- 가설: frame token을 계속 늘리는 것보다 object ledger와 enter/exit/occlusion event를 명시적으로 유지하는 편이 temporal grounding에 유리하다.
- 최소 실험: 공개 가능해지는 즉시 100개 procedure question을 골라 uniform sampling VLM과 object-state table augmented VLM을 비교한다. 동일 frame budget에서 temporal grounding accuracy, count error, identity switch, 근거 timestamp IoU를 평가한다.

**판정:** 새 benchmark 자체가 강한 신호다. 단, 데이터 공개 완료 전에는 “재현 가능”이 아니라 “protocol 검토 가능” 단계다.

## 3. SAPI: segmentation leaderboard에 에너지와 모델 크기를 포함

**무엇이 바뀌었나.** [Performance at What Cost?](https://arxiv.org/html/2610.10324v1)은 segmentation performance, energy, parameter count를 결합한 Sustainability-Aware Performance Index(SAPI)를 제안했다. 19개 pretrained/foundation model의 zero-shot과 16개 fine-tunable model의 few-shot을 CellBinDB 6개 modality, 총 1,044장·102,480개 annotated instance에서 비교한다. GPU는 Tesla V100의 NVML, CPU·DRAM은 RAPL로 측정했고 loading, CUDA 초기화, 전·후처리를 inference boundary에 포함했다.

**저자 결과.** PathoSAM ViT-B는 평균 performance 0.675, 104.8M parameter, 164.15 J/image였고 ViT-H는 0.680, 652.1M, 342.71 J/image였다. 저자 설정에서 아주 작은 성능 증가에 약 2배 에너지와 6배 이상 parameter가 필요했다. SAPI 순위는 성능 단독 순위와 달랐고, InstanSeg가 네 dataset에서 최고 zero-shot SAPI를 기록했다. [코드](https://github.com/eiram-mahera/sapi)와 [CellBinDB](https://doi.org/10.5281/zenodo.15370205)가 공개되어 있다.

**비교 가능성 점검.**

- 같은 node와 측정 범위에서 비교했으므로 내부 상대 비교는 설득력이 높다.
- wall-socket, 냉각, storage, network, pretraining energy는 포함하지 않는다.
- 한 종류 GPU/CPU에서의 상대 효율이 다른 accelerator·precision·compiler에서도 유지된다는 보장은 없다.
- SAPI는 configurable composite이므로 weight가 바뀌면 순위도 바뀐다. 절대적 단일 leaderboard로 쓰기보다 Pareto frontier를 같이 보여야 한다.
- few-shot protocol은 공정 비교를 위해 고정되어 각 모델의 최적 tuning을 나타내지 않는다.

**진단 → 가설 → 최소 실험.**

- 진단: 연구 코드의 “정확도 +0.x”는 deployment cost와 latency를 숨긴다.
- 가설: 현재 segmentation 프로젝트에서도 큰 backbone의 이득 상당수가 입력 해상도와 후처리 비용을 통제하면 줄어든다.
- 최소 실험: 동일 100-image subset에서 두 backbone을 batch=1, FP32/FP16로 각각 10회 실행한다. PQ/AJI+, p50·p95 latency, peak VRAM, J/image를 기록하고 accuracy-energy Pareto를 그린다. composite score를 만들면 weight sensitivity도 함께 보고한다.

**판정:** 즉시 도입할 수 있는 평가 규율이다. “최고 정확도”보다 “요구 품질을 만족하는 최소 비용”을 선택 기준으로 바꾼다.

## 4. TouchScale: visual-tactile benchmark를 cross-sensor transfer까지 확장

**무엇이 바뀌었나.** [TouchScale](https://arxiv.org/html/2610.10288v1)은 단일 wearable pipeline으로 500시간, 약 87,000 episode, 약 2,000 task description, 1,500개 이상 물체를 수집했다. head RGB-D, 양손 wrist RGB, bimanual tactile을 시간 동기화하며 약 20명이 참여했다. cross-dataset 평가는 서로 다른 tactile layout을 12개 anatomical hand region으로 mapping한다.

**저자 결과.** 저자는 full TouchScale 학습이 unseen tactile sensor의 zero-shot contact IoU를 0.134에서 0.383으로 높였다고 보고한다. 세부 표의 통제된 비교에서는 EgoTouch 학습 대비 TouchScale 학습이 EgoTactile에서 contact IoU 0.134→0.181, value IoU 0.185→0.243, center-of-pressure localization error 0.444→0.416, pressure magnitude error 0.184→0.148을 보였다. 서로 다른 실험 설정의 0.383과 0.181을 같은 결과로 혼합하면 안 된다.

**비교 가능성 점검.**

- sensor 간 native taxel grid가 다르므로 12-region mapping은 공정성을 높이지만 미세 접촉 패턴을 잃는다.
- 자동 품질검사에 Gemini 3.7 Flash의 wrist-video 판정을 사용하고 일부 실패는 manual review한다. QC model의 bias가 완전히 독립적이지 않을 수 있다.
- 저자는 전체 synchronized recording과 reconstructed object model 공개를 예고했지만, 원문에서 즉시 사용할 공식 저장소 링크는 확인되지 않았다.
- robot 평가는 한 platform·네 manipulation task이고 action label이 없다. 20%→100% data 확대의 future-tactile gain도 2.87%→3.31%로 작다.

**진단 → 가설 → 최소 실험.**

- 진단: scale 효과와 sensor-specific calibration 효과가 섞일 수 있다.
- 가설: anatomical-region invariant pretraining은 새 장갑 sensor에서 calibration sample을 줄이는 데 도움이 되지만 fine contact localization에는 한계가 있다.
- 최소 실험: source sensor 두 개, target sensor 하나를 두고 1/5/10/50-shot calibration curve를 만든다. region-level cIoU와 native-grid CoP error를 동시에 측정하고, TouchScale pretraining 유무의 confidence interval을 bootstrap으로 구한다.

**판정:** 규모는 큰 신호지만 release와 cross-platform 재현을 확인한 뒤 채택해야 한다.

## 5. FigCodeBench: “코드가 실행됨”과 “그림이 맞음”을 분리해 측정

**무엇이 바뀌었나.** [FigCodeBench](https://arxiv.org/html/2610.10066v1)는 실제 source에서 수집한 6,194개 instance, 7개 figure category, Python·MATLAB·R·LaTeX 네 언어를 다룬다. Easy/Medium/Hard 난이도와 함께 execution, PSNR·SSIM·LPIPS·CIEDE2000, AST similarity, code efficiency를 결합한다. 저자는 11개 proprietary와 13개 open-source MLLM을 평가했다.

**저자 결과.** 언어별 실행률과 시각 충실도가 크게 갈렸다. 예를 들어 GPT-5.4의 실행률은 Python 91.48%, MATLAB 44.67%, R 62.48%, LaTeX 52.43%였고, Claude Opus 4.7은 각각 99.29%, 98.17%, 97.35%, 88.47%였다. 이것은 저자 환경·prompt·version에 묶인 snapshot이며 일반적인 모델 우열로 확대하면 안 된다. [프로젝트](https://zijianchen98.github.io/FigCodeBench/), [코드](https://github.com/zijianchen98/FigCodeBench), [데이터](https://huggingface.co/datasets/CCZZJJ/FigCodeBench) 공개 위치가 명시되어 있다.

**비교 가능성 점검.**

- 실행 성공률이 높아도 시각 충실도가 낮을 수 있으므로 두 축을 분리해야 한다.
- pixel metric은 내용상 치명적인 작은 위치 오류를 충분히 벌하지 못할 수 있다.
- MLLM judge는 domain-specific scientific error에 둔감할 수 있고 alignment bias 위험이 있다.
- MATLAB license/runtime, font, renderer, package version 차이가 실행률에 영향을 줄 수 있다.
- 공식 데이터·코드가 “will be available” 상태인지 실제 완전 공개인지 실행 전에 확인해야 한다.

**진단 → 가설 → 최소 실험.**

- 진단: vision-to-code에서 syntax error, data extraction error, layout error가 하나의 score에 묻힌다.
- 가설: OCR/structure extraction을 먼저 고정 JSON으로 만들고 code generation을 분리하면 실패 위치가 명확해지고 재시도 비용이 줄어든다.
- 최소 실험: Python figure 30개를 end-to-end prompt와 two-stage prompt로 재현한다. execution rate, SSIM/LPIPS, text exactness, data-point error, 수정 횟수, wall time을 기록한다. renderer와 package lockfile을 고정한다.

**판정:** AI 도구 평가와 연구 figure 자동화에 유용하다. 단일 종합점수보다 failure taxonomy가 더 가치 있다.

## 오늘의 benchmark signal 3개

1. **장시간 video 평가는 frame 수보다 state integrity가 핵심이다.** Ledger와 HeiCo-FOCUS 모두 identity, enter/exit, move, occlusion, retrieval을 분리해 측정한다.
2. **정확도 leaderboard만으로 모델을 고르면 비용을 과소평가한다.** SAPI식 energy/latency/size 기록과 Pareto 분석을 기본 실험표에 넣을 시점이다.
3. **새 modality와 생성 task는 transfer·execution·coverage를 반드시 함께 보고해야 한다.** TouchScale의 cross-sensor mapping, FigCodeBench의 execution gate, Ledger의 coverage가 같은 방향을 가리킨다.

## Woojin 연구에 바로 연결

- **Video tracking / MOT:** detection AP만 보지 말고 ID persistence, false move, scene-cut recovery, memory coverage를 추가한다.
- **해무·원격탐사:** SAPI를 그대로 가져오기보다 mIoU/F1, J/image, p95 latency, peak VRAM의 Pareto frontier를 만든다. 해상도와 tiling을 고정한다.
- **Small-object detection:** 크기가 작은 대상은 annotation uncertainty가 성능 상한을 정하므로 size bin별 recall과 human disagreement를 같이 기록한다.
- **VLM 연구:** text-only, frame-only, memory-only, frame+memory를 같은 reader와 token budget으로 나눠 근거의 효과를 분리한다.
- **자동화 시스템:** figure/table 생성 agent는 “실행 성공” 후에도 숫자·축·범례·위치의 구조 검사를 통과해야 완료로 처리한다.
