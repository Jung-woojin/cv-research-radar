## 사례 1 — 입력 표현을 바꾸면 crop이라는 intervention이 사라진다

**Claim·재현 조건.** Diffusers 0.43.0.dev0, macOS arm64 CPU, Python 3.14.5·NumPy 2.5.3·torch 2.14.1·Pillow 12.3.0의 제보다. 동일한 8×16 RGB 흑백 반분 이미지를 PIL, HWC float NumPy, CHW tensor로 만들고 resize·normalize를 끈 뒤 crops_coords=(8,0,16,8)을 전달한다. weights는 필요 없다. [원문](https://github.com/huggingface/diffusers/issues/15377)

**Observed gap·사실.** 작성자는 PIL만 (1,3,8,8), 최솟값 1.0이고 나머지는 (1,3,8,16), 최솟값 0.0이라고 보고한다. 고정 750b3be2c0198e194c87e931a6904066de167a5f 소스에서도 crop 호출은 PIL 분기에만 있고 NumPy·tensor 경로에는 없다. 이는 모델 품질 하락 측정이 아니라 입력 영역 불일치다. [소스](https://github.com/huggingface/diffusers/blob/750b3be2c0198e194c87e931a6904066de167a5f/src/diffusers/image_processor.py#L685-L735)

**최신 상태.** 다른 기여자의 세 형식 crop 구현 제안 이후 maintainer는 해당 경우 오류를 내자고 답했다. 제보자는 NumPy·tensor에 crops_coords를 주면 ValueError를 내는 PR을 보내겠다고 응답했다. 따라서 동일 crop 지원이 승인·배포됐다고 해석하면 안 된다. 조회 시 이슈는 open이다. [maintainer](https://github.com/huggingface/diffusers/issues/15377#issuecomment-7116613946), [제보자 응답](https://github.com/huggingface/diffusers/issues/15377#issuecomment-7117893729)

**진단 → 가설 → 최소 실험.** “같은 seed의 생성 차이 일부는 모델이 아니라 실제 conditioning 영역 차이다”가 가설이다. 원본 fixture에서 shape·pixel hash를 비교하고, NumPy·tensor는 호출 전에 명시적으로 같은 영역을 잘라 대조한다. crop이 적용되지 않은 입력을 정상 반환하지 않는지도 검사한다. latent-channel tensor의 조기 반환은 일반 이미지와 별도 조건으로 둔다.

**GO/KILL.** 지원 경로에서 의도한 영역이 보존되거나 미지원 경로가 명시적으로 거부되면 GO한다. silent ignore를 둔 채 입력 형식 간 품질 차이를 seed variance로 해석하는 실험은 KILL한다.

## 사례 3 — 명시적 block 선택이 오히려 실행 hook을 없앤다

**Claim·재현 조건.** Diffusers 0.43.0의 FLUX.1 제보는 block-level group offload, stream/non-blocking 사용, group 크기 1에서 block_modules=["transformer_blocks","single_transformer_blocks"]를 명시하면 하위 block에 hook이 붙지 않는다고 보고한다. GPU·CUDA 버전은 미확인이다. [원문](https://github.com/huggingface/diffusers/issues/15386)

**독립 확인의 범위.** 별도 사용자는 main 750b3be의 3-block ModuleList CPU fixture에서 block_modules=None이면 각 block에 hook이 붙고, 명시적 이름을 넣으면 container에만 붙는다고 보고했다. 제안 분기 변경 뒤 block별 hook이 붙는다는 보고도 있다. 이는 hook 등록의 별도 재현이며 실제 FLUX GPU 이미지·VRAM 측정의 독립 검증은 아니다. [별도 재현](https://github.com/huggingface/diffusers/issues/15386#issuecomment-7102431366)

**Mechanism·사실.** 고정 소스는 name in block_modules 분기를 ModuleList/Sequential 검사보다 먼저 수행한다. 명시한 이름이 container이면 재귀 호출 안에서 숫자 child 이름은 명시적 목록과 맞지 않아 unmatched group이 되고 container에 hook이 붙는 경로가 된다. ModuleList의 각 block을 직접 호출하는 모델에서는 container hook이 실행되지 않는다는 설명과 일치한다. 이슈는 open이며 이번 조사에서 병합 수정·릴리스를 확인하지 못했다. [분기 소스](https://github.com/huggingface/diffusers/blob/750b3be2c0198e194c87e931a6904066de167a5f/src/diffusers/hooks/group_offloading.py#L718-L815)

**진단 → 가설 → 최소 실험.** 동일 tiny model에서 None/명시적 container/일반 submodule을 교차해 hook 소유자와 실제 forward 호출 횟수를 기록한다. ModuleList와 Sequential을 구분하고, 제안 guard만 바꾼 대조를 둔다. CPU 등록 검사를 통과한 뒤 GPU에서 block 진입 시 device와 고정 입력 출력을 확인한다. seed와 precision은 그대로 둔다.

**GO/KILL.** 실제 호출되는 block에 필요한 onload가 발생하고 output parity가 보존될 때만 GPU 반복으로 GO한다. container에 hook 객체가 존재한다는 사실만으로 offload 작동을 승인하는 것은 KILL한다.

## 사례 4 — OWL-ViT BF16 flake의 허용치 변경을 모델 개선으로 읽지 않는다

**Claim·조건.** 11/23 게시 PR은 11/17 merge-queue의 eager/SDPA BF16 검사 실패를 조사한다. 작성자는 AMD EPYC CPU, OMP_NUM_THREADS=4에서 반복 실행했고 1 thread에서는 실패하지 않았다고 보고했다. CI는 Intel Xeon m8i이므로 CPU kernel 조건이 다르다. CPU 간 비교는 not strictly apples-to-apples다. [PR·실행표](https://github.com/huggingface/transformers/pull/51148)

**Observed gap·한계.** 작성자는 main의 한 2,000회 run에서는 실패가 없었지만 이전 6,000회 run에서 1회 실패했고, 관련 tester 변경을 되돌린 2,000회에서도 1회 실패했다고 보고했다. 수정 후 OWL-ViT/OWLv2 각각 3,000회에서 실패가 없었다는 것은 허용치를 바꾼 조건의 결과다. 고정 seed별 학습 성능 분산이나 GPU task 정확도 측정이 아니다.

**소스·mechanism.** 읽은 diff는 두 모델의 테스트에 BF16 atol=5e-2 override를 추가하며 모델 forward를 바꾸지 않는다. logit_scale이 오차를 증폭한다는 것은 작성자의 설명이다. thread·kernel 의존성과 경계 허용치가 결합한다는 가설은 가능하지만 하드웨어별 수치 원인을 이번 실행에서 확정하지 않았다. 조회 시 open, merged_at=null, head 39f3627584a03fe97c3b5b4951bc8ec0c18bae13이다. [테스트 소스](https://github.com/huggingface/transformers/blob/39f3627584a03fe97c3b5b4951bc8ec0c18bae13/tests/models/owlvit/test_modeling_owlvit.py)

**진단 → 가설 → 최소 실험.** 동일 입력·weight·seed에서 FP32 기준, BF16 eager, BF16 SDPA를 비교하고 thread=1/4를 교차한다. 허용치 변경 전후의 통과 여부와 별개로 raw per-row diff·scaled/unscaled logits·ranking을 보존한다. CPU 모델·torch build·BLAS/oneDNN 설정을 기록한 뒤 다른 CPU로 옮긴다.

**GO/KILL.** raw 오차와 task 판단의 안정성을 설명할 수 있으면 GO한다. tolerance 완화로 CI가 초록색이 됐다는 이유로 수치 재현성이 개선됐다고 결론 내리는 것은 KILL한다. 작성자의 0회 실패를 앞으로의 실패 확률 0으로 해석하지 않는다.
