## Q1. 의미가 같은 class 순열이 AP에 거의 드러나지 않는 counting 오류를 만드는가?

**문제·Observation·왜 지금:** SAM wrapper는 정규화된 FP16 box에 `class × 7680`을 더해 NMS했다. #27372는 두 경로 모두 offset 이전 FP32 변환과 `batched_nms`를 적용했다. 작성자는 LVIS minival 반환 box가 줄었지만 AP도 소폭 낮아졌다고 보고한다. 수정의 올바름과 AP 상승이 일치하지 않는 사례다. [공식 PR·측정 조건](https://github.com/ultralytics/ultralytics/pull/27372) · [두 경로의 diff](https://github.com/ultralytics/ultralytics/pull/27372/files)

**Gap·Diagnosis·Mechanism:** 큰 class offset에서 좌표 간격이 FP16 표현 간격보다 작아지면 box가 퇴화한다. class 번호는 의미상 임의인데 출력 중복률에 영향을 줄 수 있다. torchvision도 class offset을 쓰는 경로가 있으므로 함수 이름 교체만으로 일반적 수치 안전성을 증명하지 않는다. [torchvision 구현](https://github.com/pytorch/vision/blob/main/torchvision/ops/boxes.py)

**Hypothesis·최소 개입:** 동일 raw box·score에서 class ID만 순열화했을 때 생기는 차이는 후처리 정밀도로 설명될 수 있다. offset 전 FP32와 class별 독립 NMS를 대조한다. 실제 prompt를 다시 입력하면 raw prediction도 바뀔 수 있으므로 별도 실험으로 둔다.

**MVP·baseline·dataset:** 합성 겹침 box로 FP16/FP32 × normalized/pixel × class 0/1/3/9를 검사한다. baseline은 구버전 offset NMS, 수정판과 class별 FP32 NMS가 대조군이다. 이후 LVIS minival의 보존 예측을 사용하고, UAV·해양 counting 확장은 별도 표본·annotation을 확보한 뒤 수행한다. 수정 revision은 `4c3d34b9ff117332d824de8bcb5a7985b9cdbb9b`다.

**Metric·GO/KILL:** finite 비율, box 면적 손실, 의미별 keep-set 불일치, 잔여 중복률, count MAE, AP를 함께 기록한다. 동점 score는 별도 층화한다. class 순열 효과가 정밀도 개입으로 사라지고 자연 예측에서도 counting 피해가 확인되면 GO. raw prediction 변화만으로 설명되거나 한 버그 회귀 검사로 끝나면 일반 연구 가설 KILL이다.

**Expected Contribution·Risk:** AP가 둔감한 후처리 계약 위반의 진단 패널이다. 이미 공개된 수정이라 novelty 위험이 높다. 음성 결과는 class 수·좌표 범위·dtype별 안전 경계를 제공한다. **Compute cost 1/5**, CPU부터 가능하다. 1~2주 합성 경계, 3~4주 cached prediction, 5~8주 다른 wrapper와 downstream counting을 검증하는 계획이다.

## Q2. 작은 객체의 INT8 위치 오차는 encoder보다 출력 tensor의 범위 경쟁에서 발생하는가?

**문제·Observation·왜 지금:** #27376은 mask coefficient를 16으로 나누고 prototype을 16배 한다. float mask logit의 역수 인자는 상쇄되지만 quantization에서는 서로 다른 출력 범위가 중요하다. 작성자는 같은 calibration을 쓴 host 검증에서 box·mask AP 회복을 보고한다. 물리 Coral·STM32 inference는 미검증이다. [공식 PR·조건·한계](https://github.com/ultralytics/ultralytics/pull/27376) · [고정 export 구현](https://github.com/ultralytics/ultralytics/blob/bff59258aefa78dd67d4b07d86bb245f48bb5a8f/ultralytics/utils/export/tensorflow.py)

**Gap·Diagnosis·Mechanism:** box·score와 coefficient가 하나의 INT8 scale을 공유하면 큰 coefficient 범위가 normalized box의 해상도를 잠식할 수 있다. 같은 절대 위치 오차도 작은 객체의 IoU에는 더 불리하다는 것은 연구 가설이며 이번 자료의 size별 실측 결론이 아니다.

**Hypothesis·최소 개입:** calibration과 weight를 고정한 reciprocal factor 변경만으로 좌표 오차와 small-object AP 일부를 회복할 수 있다. coefficient 개선 대신 prototype clipping으로 손실을 옮기는 가능성도 검사한다.

**MVP·baseline·dataset:** 저장된 float 출력에 factor 1/4/16/64를 적용해 양자화·복호화하고, float logit 동치와 quantized box·mask 오차를 분리한다. baseline은 factor 1 및 FP32 export다. 이어 COCO val2017, 동일 COCO train2017 calibration ID·hash, 해상도·decoder·evaluator를 고정해 paired 검증한다. PR의 고정 factor 16 개선을 새로운 발견으로 다시 주장하지 않는다.

**Metric·GO/KILL:** 좌표 오차 pixel, object-size별 IoU·AP, mask logit 오차·AP, clipping률, 반환 mask 수, 후처리 지연·peak memory를 측정한다. 범위 비율이 실패 경계를 예측하고 별도 모델에서도 개입 효과를 설명하면 GO. calibration 교체나 threshold 변경에서만 이득이 나면 해당 기전 KILL이다.

**Expected Contribution·Risk:** scale 공유에 따른 task 간 수치 간섭을 진단하는 기준이다. 양자화 rescaling 선행연구와 중복 위험이 크며 encoder 효과를 배제한 분석이 필요하다. 음성 결과도 출력 rescaling으로 복구할 수 없는 손실을 제한한다. **Compute cost 2/5**, 출력 감사는 CPU, 실제 export 환경은 별도 준비가 필요하다. 1~2주 tensor 감사, 3~4주 COCO paired 평가, 5~8주 다른 head와 실제 장치 검증을 계획한다. 실물 장치 없이 배포 성능을 주장하지 않는다.

## Q3. 요청 장치를 통제한 실험도 실제 실행 경로를 통제하지 않으면 잘못된 정확도–지연 결론을 내리는가?

**문제·Observation·왜 지금:** #27379는 `device=0`을 요청해도 Paddle CPU wheel이면 `config.use_gpu()`가 false인 조건을 처리한다. 이전 `elif`는 이 fallback에서 OBB·depth oneDNN workaround를 놓쳤다. [공식 PR](https://github.com/ultralytics/ultralytics/pull/27379) · [분기와 검증 문서 diff](https://github.com/ultralytics/ultralytics/pull/27379/files)

**Gap·Diagnosis·Mechanism:** 전일 질문은 연산 최적화의 의미 보존이었다. 오늘은 수정의 적용 여부 자체가 요청 상태와 실제 backend 상태의 불일치에 달린다는 새 조건이다. CPU 수정으로 정확도와 지연이 함께 바뀐 결과를 GPU 실행 효과로 오인할 수 있다.

**Hypothesis·최소 개입:** 요청 문자열 대신 실제 backend 상태로 실행 경로를 구분하면 명시적 CPU와 CPU fallback의 불일치가 줄어든다. 단순 로그 추가가 아니라 pass 적용과 raw output까지 확인한다.

**MVP·baseline·dataset:** CPU/GPU wheel × 요청 cpu/0의 matrix를 구성하고 동일 FP32 export·입력으로 `use_gpu`, 실제 provider, oneDNN pass, raw output hash를 기록한다. 수정 revision `8e593ffc89c1265c38d40617731a08c706be635e`와 부모 revision, 명시적 CPU가 baseline이다. DOTAv1 val OBB와 NYU Depth V2 val을 사용한다. CUDA가 없는 host에서 요청 거부는 fallback과 별도 상태로 둔다.

**Metric·GO/KILL:** 경로 오분류율, raw output 차이, OBB AP, depth RMSE, fresh-process 지연을 비교한다. fallback이 명시적 CPU와 동등해지고 실제 GPU 대조군이 유지되면 GO. 여러 backend로 확장해도 이미 알려진 분기 오류 한 건 외에 결과가 없으면 논문 범위는 KILL한다.

**Expected Contribution·Risk:** 실행 상태에 근거한 재현성 계약과 비교 오류 분류다. 시스템 QA로 끝날 위험이 높다. 음성 결과는 선언된 장치 정보가 충분한 환경의 범위를 제시한다. **Compute cost 2/5**, CPU 시작은 가능하지만 GPU-wheel 대조와 Windows 재현 가능성은 미확인이다. 1~2주 환경 matrix, 3~4주 동일 export 검증, 5~8주 복수 runtime으로 확장하는 계획이다.

## Q4. VQA semantic judge는 답 표현 오류를 복구하면서 불필요한 reasoning 서술에 판정을 빼앗기는가?

**문제·Observation·왜 지금:** ZeroBench #1894는 exact 정답을 유지하고 나머지 전체 응답을 ShortQA judge로 보낸다. 작성자는 의미상 같은 답의 복구와 함께, 최종 값은 인정하면서 reasoning을 비판해 거부한 사례도 보고한다. 자동 점수는 독립 재현하지 않았다. [공식 PR·실행 조건](https://github.com/open-compass/VLMEvalKit/pull/1894) · [고정 채점 diff](https://github.com/open-compass/VLMEvalKit/commit/9ffc2e37281a80729081fe52f977f088283783b3) · [원본 benchmark 채점 예시](https://github.com/jonathan-roberts1/zerobench/blob/main/README.md)

**Gap·Diagnosis·Mechanism:** exact 정답을 재심사하지 않는 구조에서 정답 수 상승은 judge 품질의 충분조건이 아니다. 전체 reasoning에 따른 판정 변화와 의미 동치 복구를 분해해야 한다. 이 text-only 채점 경로는 이미지 근거의 타당성을 직접 검사하지 않는다.

**Hypothesis·최소 개입:** 최종 답을 고정하고 불필요한 설명만 바꾸면 일부 judge 판정이 달라질 수 있다. 답만 제공하는 조건이 이를 줄이는지 검사하되, 질문이 reasoning 자체를 요구하는 항목에는 적용하지 않는다.

**MVP·baseline·dataset:** ZeroBench v3 저장 응답에서 exact 실패를 단위·수치 동치·순서·실제 오답·rubric 모호성으로 먼저 사람이 분류한다. exact, 보수적 결정론적 normalization, semantic judge를 baseline으로 비교한다. final-only/full-response paired panel과 최종 답을 의도적으로 틀린 음성 대조를 구성한다. ordered sequence와 unordered set은 질문별 rubric으로 구분한다.

**Metric·GO/KILL:** 사람 기준 false acceptance/rejection, 설명만 바꾼 판정 flip, 유형별 복구율, avg@5·pass@5·pass^5, generation/judge 실패·요청 비용을 기록한다. 표현 오류 복구와 실제 오답 오인정을 구분하고 설명 의존성이 반복되면 GO. 모호한 reference를 임의 수정하거나 점수 상승만으로 grounding 향상을 주장하면 KILL이다. 실패 slot을 조용히 분모에서 제외하지 않는다.

**Expected Contribution·Risk:** 정답 의미·설명 품질·시각 증거를 분리한 평가 진단이다. judge bias 연구와 중복되므로 실제 visual task 유형별 결과가 필요하다. 음성 결과는 해당 rubric과 judge의 서술 강건성 근거가 된다. **감사 cost 1/5, API 평가 cost 2/5**, 유료 호출은 이번 실행에서 하지 않았다. 1~2주 사람 panel, 3~4주 paired judge, 5~8주 안전 VQA로 검증한다.

## Q5. annotation과 decoder의 설치 상태가 같은 평가 명령의 점수 의미와 비용을 바꾸는가?

**문제·Observation·왜 지금:** #27382는 조건에 맞는 COCO val2017에서 공식 annotation을 사용한다. segmentation은 decoder를 확보하지 못하면 경고 후 YOLO text-label 경로로 fallback한다. 원본 해상도 mask 평가에는 추가 시간·메모리가 필요하다는 작성자 보고가 있다. [공식 PR·paired 비용 표](https://github.com/ultralytics/ultralytics/pull/27382) · [평가 경로 diff](https://github.com/ultralytics/ultralytics/pull/27382/files)

**Gap·Diagnosis·Mechanism:** 전일 recall 적분 경계와 달리 오늘은 annotation source·crowd·detection limit·mask geometry라는 평가 대상의 계약이 바뀐다. 같은 명령·모델 이름만으로 AP를 동일 조건이라 간주할 수 없다. COCO 원본도 crowd 반복 matching과 unmatched out-of-range ignore를 명시한다. [COCO reference](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py)

**Hypothesis·최소 개입:** evaluator의 실제 annotation·decoder·geometry를 기록하고 평가 경로를 명시하면 환경 차이로 생긴 점수 차이를 모델 차이에서 분리할 수 있다.

**MVP·baseline·dataset:** 동일 COCO val2017 보존 prediction으로 annotation 있음/없음 × decoder 있음/없음을 검사한다. dependency 자동 설치를 끈 격리 환경에서 수행한다. crowd·dense scene·작은 mask를 별도 층화한다. baseline은 같은 serialized prediction을 평가하는 pycocotools와 기존 text-label 경로다. revision은 `b62088e5cd032d92de9476ac84a00013b8da9256`으로 고정한다.

**Metric·GO/KILL:** 경로 선택·경고, class/IoU별 AP 차이, crowd matching 불일치, mask geometry 차이, 평가 wall time·peak allocation을 기록한다. 경로 차이가 점수 차이를 설명하고 계약 명시로 비교 오류가 사라지면 GO. prediction·annotation을 동시에 바꾼 결과만 있으면 원인 주장은 KILL한다.
