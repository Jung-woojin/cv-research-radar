## 1. MCQ 파서 — 모델 답변이 같아도 정답 판정이 달라지는 변경

**실제 변화·확인 사실.** commit b0d4d66은 WorldSense·AV Odyssey·TOMATO의 선택지 후보 검사를 단순 문자 포함에서 괄호 선택지 또는 공백 뒤 문자와 마침표 형태로 바꾼다. 복수 후보의 마지막 위치 판정도 두 형식을 함께 고려한다. 바로 앞 ce25dcb는 공통 mcq_extract의 Answer 라벨 정규식을 확장해 Markdown 강조를 처리한다. 두 수정은 서로 다른 코드 경로이므로 모든 과제가 같은 함수를 쓴다고 가정하지 않는다. [과제별 diff](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/b0d4d665953d28eaad6243b390c5b024451ddb12), [공통 추출기 diff](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/ce25dcbf95e79b18b53b476b438bdf23fd4ddc48).

**maintainer 설명·공식 테스트.** commit은 Answer의 A나 Based의 B가 후보가 되는 문제를 설명한다. 추가 테스트에는 단독 C, C. 뒤 설명, 괄호 답, 강조된 Answer 라벨, 앞 선택지를 부정한 뒤 최종 C를 고르는 경우가 있다. 공통 추출기 fixture는 강조 라벨 뒤 C or D를 정답 하나로 강제하지 않고 빈 답으로 둔다. 코드·fixture는 수정 의도와 일치한다. 실제 전체 benchmark 점수 변화는 제시된 diff에서 확인하지 못했다. [과제 회귀 테스트](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/b0d4d665953d28eaad6243b390c5b024451ddb12/test/tasks/test_parse_multi_choice_response.py), [공통 fixture](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/ce25dcbf95e79b18b53b476b438bdf23fd4ddc48/test/eval/mcq_extract/cases.json).

**관측 → 진단 → 기전·추론.** 자연어 설명과 선택지 기호가 섞이면 대문자·포맷을 의미적 답으로 오인할 수 있다. 따라서 accuracy 변화가 vision encoder나 temporal reasoning 개선 없이 발생할 수 있다. 개선 방향·크기는 원응답 분포에 달리며 모든 모델의 점수가 오른다고 단정할 수 없다.

**가설 → 최소 개입 → 실험 제안.** 보유한 해당 과제 원응답과 GT를 고정하고 수정 전후 각 파서만 교체한다. old/new label, parse abstention, 정오 전환을 sample ID별 기록한다. 전체 accuracy와 강조 라벨·설명 문장·다중 후보별 전환율을 분리하고, 달라진 응답은 사람이 blind 감사한다. 원래 random fallback 경로의 seed도 고정한다. 공통 추출기의 결과를 과제별 파서 결과로 대체하지 않는다.

**GO/KILL.** 답 의미가 같은데 판정만 변한 사례가 확인되면 기존 점수에 evaluator revision을 붙여 재발행한다. 차이가 없으면 해당 보유 표본에서는 영향이 없다는 결론만 낸다. 새 모델 우위나 일반적인 순위 역전은 주장하지 않는다.

**비교 판정.** 동일 원응답의 paired 재채점은 파서 효과를 분리한다. evaluator가 다른 과거·현재 점수는 재채점 전까지 **not strictly apples-to-apples**다. dataset split·metric 정의를 바꾼 commit은 아니지만 metric의 구현이 달라졌다.

## 2. Video VLM 입력 — 추론 능력보다 먼저 프레임 계약을 확인

**실제 변화·확인 사실.** commit 7a2de54는 vllm_generate에 _as_uint8_thwc를 추가한다. 4차원 프레임을 검사하고, 조건에 맞는 TCHW를 THWC로 전치하며, 비-uint8은 반올림·0~255 clipping 후 uint8로 바꾸고 contiguous array로 전달한다. 프레임 수·timestamp를 바꾸는 수정은 해당 diff에 없다. [공식 diff](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/7a2de540d531d801201168abc259ef5e75647b65).

**maintainer 설명.** LLaVA-OneVision-2-8B-Instruct의 nextqa_mc_test 실행에서 vLLM processor의 PIL 변환에 채널 순서가 맞지 않아 TypeError가 발생했다고 기록한다. Gemma 계열에서도 유사 dtype 오류를 언급하지만 이를 모든 Video VLM의 장애로 일반화하지 않는다. [commit 재현 설명](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/7a2de540d531d801201168abc259ef5e75647b65).

**공식 검증 범위·확인 사실.** 추가 테스트는 CPU에서 채널값 보존·전치·THWC passthrough·clipping·잘못된 rank를 검사한다. 테스트 파일 자체가 vLLM이나 영상 모델을 실행하지 않는다고 명시한다. 전체 NExT-QA 점수·처리량·VRAM 개선은 확인되지 않았다. [테스트 원문](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/7a2de540d531d801201168abc259ef5e75647b65/test/models/test_vllm_generate_video_frames.py).

**관측 → 진단 → 기전·추론.** 프레임 decode 성공과 processor 수용은 서로 다른 단계다. 평가가 중단되거나 빈 응답으로 처리되면, 모델의 시간 추론 실패와 adapter 실패가 결과에서 섞인다. 코드의 layout 판정은 shape heuristic이므로 특이하게 작은 공간 차원에서는 별도 확인이 필요하다. 현재 수정이 [0,1] 정규화 입력을 자동으로 [0,255]로 확장하는 것도 아니다.

**가설 → 최소 개입 → 실험 제안.** 먼저 모델 없이 색 채널이 구별되는 synthetic 영상으로 decode 전후 shape·dtype·범위·timestamp·채널 checksum을 감사한다. 이후 GPU가 허용하는 기존 모델과 보유 짧은 영상 소수에서 adapter만 바꿔 paired 실행한다. checkpoint·vLLM·qwen_vl_utils revision, frame budget·fps·해상도·prompt·decode seed를 고정하고 성공 완료율·입력 동일성·완료 표본 accuracy를 각각 기록한다. 오류 표본을 분모에서 조용히 제거하지 않는다.

**GO/KILL.** 입력 계약이 맞고 기존 오류만 해소되면 평가 복구로 판정한다. accuracy가 변하면 실제 프레임 내용 변화부터 검사한다. CPU 검사만 통과한 상태를 end-to-end 재현으로 보고하지 않는다.

**비교 판정.** 수정 전 실행 실패와 수정 후 정상 실행의 차이는 모델 능력 향상의 동일 조건 증거가 아니다. 성공 표본 집합·실패 정책이 다르면 **not strictly apples-to-apples**다.

## 3. 이미지 투명도 — 같은 이미지 경로가 같은 API 입력을 보장하지 않음

**실제 변화·확인 사실.** VLMEvalKit commit 57c8a2e는 GPT4V·OpenAIResponses·ClaudeSDK·LMDeploy wrapper에 convert_rgb=False 기본값을 둔다. 일반 경로는 모드·투명도 보존을 위한 PNG를 사용하고 CMYK는 JPEG다. 명시적으로 convert_rgb=True면 기존 RGB/JPEG 동작을 선택한다. shared encoder 자체는 convert_rgb=True 기본값을 유지한다. 따라서 저장소 전체의 모든 이미지 입력이 일괄 변경됐다는 뜻은 아니다. [공식 diff](https://github.com/open-compass/VLMEvalKit/commit/57c8a2e04bd9daacd3d5323f1ff1e93c9a0c9388).

**공식 검증 범위·확인 사실.** 테스트는 RGBA·LA·palette 등 모드, MIME과 실제 포맷 일치, 픽셀·alpha 보존, resize·파일 제한, 명시적 legacy 설정을 다룬다. LMDeploy local_media=True에서는 해당 인코딩 옵션이 적용되지 않는다는 경고도 있다. 실제 provider가 alpha를 어떤 배경으로 합성하는지, OCR·grounding 점수가 얼마나 변하는지는 확인하지 않았다. [회귀 테스트](https://github.com/open-compass/VLMEvalKit/blob/57c8a2e04bd9daacd3d5323f1ff1e93c9a0c9388/tests/test_api_image_modes.py).

**관측 → 진단 → 기전·추론.** 투명 영역·palette·압축은 모델이 보는 픽셀과 작은 문자·경계에 영향을 줄 수 있다. alpha 보존과 JPEG→PNG 변화가 동시에 일어나므로 성능 차이를 alpha 하나의 효과로 귀속하면 안 된다. 원 dataset revision이 같아도 payload revision은 달라졌다.

**가설 → 최소 개입 → 실험 제안.** API 호출 전 동일 원본에 legacy RGB/JPEG, 명시적 배경 합성 RGB/PNG, alpha 보존 PNG를 만들어 wire payload를 역디코드해 비교한다. 동일 크기·resize·파일 budget에서 모드·MIME·decoded pixel hash·alpha와 파일 크기를 기록한다. 그다음 작은 OCR/grounding 보유 표본에 동일 provider model ID·prompt·detail·reasoning·token budget으로 paired 호출해 accuracy·IoU·실패율·지연을 분리한다. JPEG 압축 효과와 alpha 합성 효과를 별도 대조한다.

**GO/KILL.** payload 차이가 실제 응답 차이와 연결되면 평가 provenance에 인코딩 설정을 추가한다. provider가 같은 픽셀로 정규화해 차이가 없으면 해당 provider·표본에서 alpha 효과 가설을 축소한다. 새 default가 모든 과제에서 좋다는 결론은 보류한다.

**비교 판정.** 입력 bytes·픽셀이 다른 old/new 기본 설정의 점수는 **not strictly apples-to-apples**다. 이 commit은 새 split이나 모델 학습 성과가 아니라 입력 전처리 protocol 변화다.

논문 SOTA 표와 official leaderboard를 동일 조건으로 재현한 항목은 없다. 오늘 근거는 공식 코드 변경이며 수치 상승을 만들어 채우지 않았다. detection·segmentation·aerial·maritime 전용 순위의 새 이동은 충분한 직접 근거를 확보하지 못했다.

## 오늘의 benchmark signal 3개

1. **채점 구현도 평가 계약이다.** 원응답·parser revision을 함께 보관해야 능력 변화와 파싱 효과를 분리한다.
2. **완료율과 정확도는 별도다.** 영상 입력 형식 복구를 temporal reasoning 개선으로 보고하지 않는다.
3. **파일 경로보다 전달 픽셀을 감사한다.** 색 모드·alpha·압축·실제 payload가 바뀌면 과거 점수와 비교 조건을 다시 확인한다.

## 내 연구에 바로 연결되는 포인트

- **오늘 먼저:** 보유 WorldSense·TOMATO·AV Odyssey 원응답이 있다면 수정 전후 재채점과 정오 전환 감사부터 수행한다. 없으면 공식 fixture로 파서 계약만 확인하며 모델 성능 결론은 내리지 않는다.
- **RTX 5060 Ti 8GB:** 파서 재채점과 payload 역디코드 검사는 GPU 없이 가능하다. 영상 모델의 8GB 실행 가능성은 이번 자료로 확인되지 않았다.
- **Answer–Region Gap·해상 안전 VQA:** 텍스트 정답 변화가 parser 때문인지 먼저 분리한 뒤 region IoU·부재 표적 거부를 분석한다. MCQ 파서 수정을 grounding 개선의 근거로 쓰지 않는다.
- **small/tiny object·고해상도:** P2·crop 실험 전 RGB/PNG/JPEG와 resize를 고정하고 입력 hash를 남긴다. 이번 commit이 작은 물체 AP를 개선했다는 수치는 없다.
- **video memory·CCTV:** frame shape·dtype·timestamp와 실패 분모를 남겨 adapter 결함을 memory 또는 temporal reasoning 가설과 분리한다.

독립 benchmark 실행·모델 재추론·새 점수 측정은 하지 않았다. 공식 diff와 테스트의 존재를 확인한 진단 보고서이며, 제안 실험의 결과는 후속 실행에서만 판정한다.
