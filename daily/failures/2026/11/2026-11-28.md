## 1. SavedModel NMS: index 0 padding이 실제 detection으로 되살아남

**확인 사실:** #27394는 `onnx2tf.convert`에 `output_nms_with_dynamic_tensor=True`를 추가해 병합됐다. 전일 SAM FP16 좌표 손실과 달리, 이번 실패는 TensorFlow 변환의 index padding 단계에서 발생한다. [공식 PR](https://github.com/ultralytics/ultralytics/pull/27394) · [수정 diff](https://github.com/ultralytics/ultralytics/pull/27394/files)

- **실패 조건·모델·설정:** YOLO26 SavedModel `nms=True`, NMS가 `max_det`보다 적은 index를 반환하는 경우. CPU, TensorFlow 2.19.0, onnx2tf 1.28.8 조건의 검증이 있으며 작성자는 다른 TensorFlow·onnx2tf 조합도 보고했다.
- **진단·메커니즘:** onnx2tf가 선택 index를 0으로 채우고 gather가 그 값을 최고 점수 box로 해석한다. 기존 `NMSModel`의 최종 zero padding과 겹치면서 빈 행이 유효 detection으로 바뀐다. 수정은 선택된 index만 먼저 반환하게 한다.
- **저자·community 근거:** 기여자가 coco8-pose의 score>0.25 행 수를 `60/3/89/0 → 9/3/1/0`으로 보고했다. detection coco8에서는 변화가 없었다.
- **공식 인정·별도 재현:** maintainer가 위 행 수를 재현하고 COCO val2017을 추가 측정했다. pose 대상 2,346장의 pose mAP50–95는 `0.0423 → 0.5441`, box는 `0.0278 → 0.4366`; detection 5,000장의 box는 `0.3372 → 0.3386`이었다. 같은 데이터의 ONNX `nms=True`와 수정판이 일치했다고 보고했다. 이는 maintainer의 측정이며 이번 watch의 실측은 아니다. [재현 댓글](https://github.com/ultralytics/ultralytics/pull/27394#issuecomment-7216115497)
- **기존 주장과 충돌:** coco8에서 detection이 유지됐다는 사실은 전체 detection 안전성을 보장하지 않았다. architecture·학습 실패로 보이는 큰 pose AP 하락이 export 후처리 계약에서 발생했다. pose 부분집합과 detection 전체 점수는 not strictly apples-to-apples다.
- **가설 → 최소 개입:** 핵심 원인은 검출 의미와 padding 표현의 혼동이다. dynamic selected-index 출력과 최종 zero-row padding을 분리한다.
- **최소 실험:** base `6f59d4a0cd814d49811644f9d49b0290c04ae481`, merge `df27cb0b73915192dce9a8049dde38631bceb990`를 고정한다. 우선 weight 없이 선택 index가 0개·1개·max_det 미만·이상인 합성 입력을 만들고 padding 후 score·중복률·출력 shape를 검사한다. 다음 단계에서 동일 weight·이미지·export threshold의 ONNX/SavedModel을 비교하고 `nms=None/False`를 음성 대조군으로 둔다.
- **GO/KILL:** 부족한 detection 행이 score 0으로 남고 유효 index·shape가 보존되면 GO. raw output 자체가 다르거나 threshold가 달라졌다면 padding만으로 설명하는 가설은 KILL한다.
- **점수:** 심각도 **4/5** · 재현 신뢰도 **4/5** · 연구 아이디어 가치 **4/5**.

## 2. Inkling 2 Mini: prefix cache hit가 greedy 출력의 동치를 깨뜨림

**확인 사실:** 공식 issue #70266은 open이며 최소 요청 코드와 복수 사용자의 재현·진단 댓글이 있다. maintainer의 최종 원인 확정이나 병합된 해결은 이번 확인 범위에서 찾지 못했다. [공식 issue·재현 코드](https://github.com/vllm-project/vllm/issues/70266)

- **실패 조건·설정:** 작성자는 vLLM `0.34.1rc1.dev231+g43108ffcc`, torch 2.14.0+cu130, transformers 5.22.2, Python 3.12, H100 NVL 1장·TP1을 사용했다. 모델 revision은 `7a67ae2314b44ef05c87fd1d4d311c58aaeb18f6`, temperature 0, max_tokens 256, reasoning_effort none이다. 합성 이미지 두 개와 text 16개를 세 요청 형태로 순차 반복했다.
- **저자 관찰:** cache off 서버 둘은 text 144/144·image 18/18 요청에서 동일했다. cache on의 plain image는 첫 pass 2/2만 baseline과 일치하고 두 번째·세 번째는 0/2였다. 작성자는 요청별 cached token을 기록하지 않아 cache hit 설명은 처음에는 순서 기반 추론이었다.
- **community 재현:** 별도 사용자가 GB10에서 JSON 형태를 제외한 plain/continue 이미지 차이를 재현했다. RTX PRO 6000 사용자는 긴 text에서도 cache hit 후 차이가 생긴다고 진단했다. GB10 후속 검사 역시 31-token·cached=0에서는 차이가 없고, 81-token·cached=64 등에서는 logprob 차이를 보고했다. 단, 해당 다섯 text prompt는 greedy 64-token 출력이 모두 같았다. logprob 차이와 생성 문자열 차이는 같은 지표가 아니다. [GB10 재현](https://github.com/vllm-project/vllm/issues/70266#issuecomment-7210308258) · [진단 제안](https://github.com/vllm-project/vllm/issues/70266#issuecomment-7219155297) · [긴 text 대조](https://github.com/vllm-project/vllm/issues/70266#issuecomment-7223013380)
- **의심 원인·증거 경계:** community 진단은 prefix hit가 prefill token 수 M을 줄여 kernel dispatch·reduction 순서를 바꾸는 메커니즘이다. 해당 사용자는 batch-invariance 관련 국소 변경으로 차이를 제거했다고 보고했지만, 공개 병합 fix로 검증한 것은 아니다. “이미지/KV 손상이 아니다”도 그 사용자의 진단으로 남긴다.
- **기존 주장과 충돌:** temperature 0과 단일 순차 client만으로 cache on/off의 token 동치가 보장되지 않는다. 짧은 text 대조군만 사용하면 modality 효과와 cache hit 효과를 혼동한다. 이미지 정답률·grounding 악화나 benchmark leakage는 이 자료로 입증되지 않는다. H100·GB10·RTX와 서로 다른 revision·JSON 지원 조건은 not strictly apples-to-apples다.
- **가설 → 최소 개입·실험:** image/text × 짧은/64-token 경계 이상 prompt × cache off/cold/warm을 비교한다. 동일 revision·GPU·template·이미지 hash·seed·출력 budget을 고정하고 실제 cached_tokens, 첫 불일치 token, logprob 차이, 문자열 일치율을 기록한다. 요청 순서를 교차하고 완전히 새 프로세스의 off/off 대조군을 포함한다. 단순 cache off를 정확도 개선으로 부르지 않는다.
- **GO/KILL:** cache hit·M 변화에 따라 재현되고 batch 처리 경로를 고정했을 때 줄어들면 dispatch 가설 GO. cached=0에서도 같은 차이가 나거나 media preprocessing이 달라지면 단일 원인 가설 KILL. 전체 모델은 H100급 제보 환경이므로 RTX 5060 Ti 8GB의 직접 실행 가능성을 주장하지 않는다.
- **점수:** 심각도 **4/5** · 재현 신뢰도 **4/5** · 연구 아이디어 가치 **5/5**.

## 논문 아이디어로 연결 가능한 빈틈

**조사자의 추론:** “모델 weight와 입력 의미를 고정했을 때 배포 경로가 보존해야 할 불변량”을 진단할 수 있다. detection은 유효 행·중복률·count, VLM은 cache 상태별 logprob·token·정답, multispectral은 밴드 순서·shape·calibration 분포를 검사한다.

알려진 버그 세 건의 테스트 모음만으로는 novelty가 낮다. 여러 backend에서 의미 보존 위반의 발생 조건을 예측하고, 최소 개입이 downstream count error·작은 객체 성능·grounding에 주는 영향을 별도 검증해야 한다. GO는 원인 변수 하나의 조작으로 일관된 실패 조건을 설명하는 경우다. KILL은 서로 다른 구현 버그를 하나의 메커니즘으로 억지 통합하거나 문자열 차이만으로 의미 정확도 저하를 주장하는 경우다. 음성 결과도 “수치 차이가 task 성능을 바꾸지 않는 범위”를 제공한다.

## 직접 재현해볼 최소 실험

첫 순위는 **CPU NMS padding 계약 검사**다. weight 없이 `selected_indices`와 gather·zero padding의 경계를 재현한다. 다음은 DEEPX의 config 생성·calibration shape 검사이며 실물 장치 없이도 지원 경계를 확인할 수 있다. VLM cache 실험은 필요한 GPU를 확보한 뒤 수행한다.

각 실험은 코드·dependency·evaluator revision, weight·입력·prediction·calibration hash, dataset revision·split, backbone·pretraining·외부 데이터·해상도·TTA, hardware·precision·batch·compute budget을 기록한다. VLM은 template·reasoning effort·token/frame budget·실제 cache hit도 고정한다. 원문에 없는 조건은 미확인으로 남긴다. 위 실험은 제안이며 이번 실행의 측정 결과가 아니다.
