## 1. Surya 2.5: 더 빠른 기본 OCR 경로가 표 좌표 의미론을 대체하지는 않는다

**확인된 사실.** Surya의 공식 릴리스 페이지에서 `v0.23.0`은 2026-10-29에 공개됐고, `surya-ocr` 0.23.0의 기본 모델은 Surya 2.5다. 릴리스 노트는 단일 H100 조건에서 Surya 2 대비 페이지 처리량 1.7배와 OmniParseBench 85.9를 제시한다. 같은 노트는 Surya 2.5가 row/column geometry를 내보내지 않으며 표 HTML 출력을 사용한다고 명시하고, row/column geometry 또는 `--mode simple`이 필요한 사용자는 `SURYA_MODEL_CHECKPOINT=datalab-to/surya-ocr-2`로 Surya 2를 고정하도록 안내한다.

**유지보수자 주장/인정.** 이는 추정된 버그가 아니라, 기본 모델 전환에 따라 구조화 표 출력의 한 형태가 사라진다는 공식 호환성 제한이다.

**독립 재현 상태.** 이번 검토 범위에서 같은 문서·같은 옵션으로 좌표 필드를 비교한 독립 커뮤니티 재현은 확인하지 못했다. 따라서 실제 하류 파이프라인의 오류율은 주장하지 않는다.

**진단.** 실패 조건은 표 셀의 행·열 위치를 JSON geometry로 소비하는 파이프라인이다. 모델은 Surya 2.5 기본 경로, 비교 기준은 Surya 2 고정 경로이며, 입력은 복잡한 표 페이지여야 한다.

**가설.** 새 기본 경로의 표 HTML은 렌더링/텍스트 추출에는 충분할 수 있지만, 좌표 기반 정렬·셀 병합·문서 레이아웃 검증에서는 API 의미론 불일치를 만든다.

**충돌 또는 주의점.** 속도와 OmniParseBench 수치는 좌표 필드 호환성을 측정하는 지표가 아니다. 따라서 이 수치를 기존 표 후처리의 성공 근거로 확장할 수 없다.

**최소 검증 실험.** 표 100쪽을 고정하고 Surya 2와 2.5를 각각 실행한다. (1) row/column geometry 존재율, (2) 사전 정의한 셀 좌표 스키마 통과율, (3) HTML로만 복원했을 때의 셀 경계 exact-match를 분리 기록한다. 실패가 2.5에서만 발생하면 모델 품질 문제가 아니라 출력 계약 변경으로 분류한다.

- 심각도: **4/5**
- 재현 신뢰도: **5/5** — 공식 제한 및 우회 설정이 명시됨
- 연구 아이디어 가치: **4/5**

## 2. FlashVSR: 비공식 파이프라인의 attention 대체는 고해상도 품질 비교를 무효화할 수 있다

**확인된 사실.** FlashVSR의 공식 저장소는 FlashVSR+의 추론 코드·사전학습 모델·학습 데이터를 제공한다. README는 일부 제3자 구현이 LCSA(Locality-Constrained Sparse Attention)를 생략하고 dense attention으로 대체할 수 있다고 설명한다.

**유지보수자 주장/인정.** 유지보수자는 이 대체가 특히 고해상도에서 눈에 띄는 품질 저하를 일으킬 수 있으므로, 결과 차이가 보이면 공식 저장소 파이프라인을 사용하라고 안내한다. 공식 README의 17 FPS 수치는 768×1408, A100 조건의 공식 파이프라인 수치다.

**독립 재현 상태.** 이번 검토에서 동일 체크포인트·해상도·비공식 통합체의 구현 차이를 분리한 독립 재현 결과는 확인하지 못했다. 제3자 성능값을 공식 결과와 동일 조건이라고 취급하지 않는다.

**진단.** 실패 조건은 LCSA가 없는 통합체에서 고해상도 영상을 복원하는 경우다. 모델 가중치가 같아도 attention 구현과 전체 전·후처리 경로가 다르면 PSNR/지각 품질/속도 비교는 교란된다.

**가설.** 저해상도 또는 짧은 클립에서는 차이가 작게 보일 수 있으나, 긴 시공간 의존성과 고해상도 영역에서 dense 대체의 메모리·근접성 제약 차이가 누적될 수 있다.

**충돌 또는 주의점.** 공식 속도 수치와 제3자 품질 저하 경고는 서로 모순이 아니다. 전자는 공식 파이프라인의 측정이고, 후자는 동등하지 않은 구현의 위험이다.

**최소 검증 실험.** 동일 영상 20개를 720p와 1440p로 고정해 공식 구현과 LCSA를 dense attention으로 대체한 경로에 각각 투입한다. 프레임별 지각 지표, temporal warping error, VRAM peak, 처리 실패율을 함께 기록한다. 속도만 비교하지 말고, 해상도별 품질 격차의 방향을 확인한다.

- 심각도: **4/5**
- 재현 신뢰도: **4/5** — 공식 유지보수자 경고는 명확하나, 이번 범위에서 독립 수치 재현은 미확인
- 연구 아이디어 가치: **5/5**

## 3. R2R: 공개된 체크포인트는 전체 학습 주장 재현의 충분조건이 아니다

**확인된 사실.** R2R 공식 저장소는 4B/8B 체크포인트와 추론·평가 코드를 제공하며, VSIBench·RevSI·3D point 평가 경로를 문서화한다. README는 학습 코드와 데이터 준비 스크립트를 “coming soon”으로 남긴다. 또한 Python 3.12, CUDA 13 계열 PyTorch/torchvision, flash-attn 2.8.2, 패치된 VGGT 하위 모듈 및 별도 가중치를 요구한다.

**유지보수자 주장/인정.** 이는 런타임 오류 보고가 아니라 공식적으로 명시된 산출물 공백이다. 공개 체크포인트의 추론 평가는 가능하지만, 데이터 구성·학습·중간 의사결정까지 포함하는 완전 재현은 현재 닫히지 않았다.

**독립 재현 상태.** 이번 검토에서는 해당 환경을 고정해 end-to-end 학습을 재현한 독립 보고를 확인하지 못했다. 학습 재현 성공이나 실패를 임의로 단정하지 않는다.

**진단.** 실패 조건은 논문의 학습 기여 또는 데이터 준비 선택을 검증하려는 경우다. 8B 평가에서 128프레임, 4B에서 16프레임 등 프레임 예산도 결과 비교 조건이므로, 단순 체크포인트 추론만으로 학습 주장까지 검증할 수 없다.

**가설.** 결과 차이의 일부가 모델 구조가 아니라 데이터 준비, VGGT 개정, 프레임 예산, 환경 조합에서 생길 가능성이 있다. 이는 검증해야 할 가설이며 사실로 확정하지 않는다.

**충돌 또는 주의점.** 체크포인트 공개는 추론 재현성을 높이지만, 학습 재현성 또는 인과적 성능 설명의 증거와는 다르다.

**최소 검증 실험.** 먼저 공식 4B/8B 평가만 재현하고, 모델·VGGT revision·프레임 수·GPU·seed를 실행 매니페스트로 남긴다. 이후 학습 스크립트가 공개될 때 같은 매니페스트로 checkpoint-to-checkpoint 차이를 비교한다. 현재 단계에서는 미공개 학습 부분을 임의로 보완하지 않는다.

- 심각도: **3/5**
- 재현 신뢰도: **5/5** — 공식 README가 산출물 미공개를 명시함
- 연구 아이디어 가치: **4/5**

## 오늘의 실패 패턴 3개

1. **점수 개선과 출력 계약은 별개다.** 평균 벤치마크 수치가 좋아도 하류 코드가 필요로 하는 row/column geometry가 사라지면 운영 실패가 생긴다.
2. **가중치 동일성이 파이프라인 동등성을 보장하지 않는다.** attention 연산·전후처리·해상도가 다르면 속도와 품질을 직접 비교할 수 없다.
3. **추론 공개가 학습 재현 공개를 뜻하지 않는다.** 평가 스크립트와 체크포인트만으로는 데이터 준비와 학습 선택을 검증할 수 없다.

## 논문 아이디어로 연결 가능한 빈틈

“출력 계약·연산자 동등성·학습 산출물 완결성”을 함께 검사하는 **reproducibility contract**를 제안할 수 있다. 모델 카드의 점수 표 옆에 (a) 출력 필드 schema, (b) 핵심 custom operator, (c) 학습/데이터/평가 artifact 공개 상태, (d) 비교 가능한 실행 매니페스트를 기계 판독 가능하게 기록하고, 계약 위반이 하류 실패율을 얼마나 설명하는지 측정한다.

## 직접 재현해볼 최소 실험

1. Surya 2 vs 2.5: 표 100쪽에서 geometry schema 통과율과 셀 경계 exact-match를 비교한다.
2. FlashVSR: 공식 LCSA 경로와 dense 대체 경로를 720p/1440p에서 쌍으로 실행해 품질·VRAM·실패율을 기록한다.
3. R2R: 공식 평가만 먼저 재현하고, frame budget·revision·환경을 매니페스트화해 학습 산출물 공개 이후의 비교 기준을 만든다.
