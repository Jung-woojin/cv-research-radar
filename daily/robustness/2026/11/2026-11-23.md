## 3. Embedding index — representation 진단 전에 feature의 정체를 확인한다

**확인 사실.** merge `8f8488189d94ce6a8170cb36495697e00eb86aa8`는 네 predict loop에서 음수 index를 Python layer indexing으로 해석하고 범위 밖 index를 오류로 처리한다. 기존에는 layer index가 음수가 아니어서 요청이 매칭되지 않았다. [공식 diff](https://github.com/ultralytics/ultralytics/pull/27316/files)

**작성자 보고·cell·metric.** CPU·imgsz320·공개 API에서 detection의 `embed=[-2]`는 기존 raw head `(1,84,1680)` 대신 256차원 embedding을 반환한다. classifier는 합이 1인 1000-class probability 대신 256차원 embedding이 된다. detection의 양수 `[22]`와 음수 `[-2]`가 일치하며, RT-DETR·World·YOLOE에서도 해당 양수 index와 일치한다고 보고한다. **OOD AUROC·task AP의 baseline 대비 악화 cell 수는 미확인**이다. shape/type 및 index 동등성 검증을 강건성 성능으로 바꾸어 쓰지 않는다. [PR 재현표](https://github.com/ultralytics/ultralytics/pull/27316)

**진단·남은 한계.** 이것이 OOD 진단을 오염시킬 수 있다는 것은 평가자 추론이다. 이 PR은 실제 OOD 실험을 제시하지 않는다. `[-1]`처럼 head를 직접 고르면 기존 양수 head index와 같은 AttributeError가 남으며, 모든 layer를 embedding으로 지원하는 수정이 아니다. ECE·coverage도 미보고다.

**가설 → 최소 intervention·실험.** readout 병목처럼 보인 현상이 잘못 추출한 feature 때문인지 먼저 배제한다. layer ID·shape·dtype·정규화·checkpoint hash를 manifest에 남기고 `[-2]`/동등 양수 index/`model.embed()`를 비교한다. 다음으로 동일 ID/OOD split에서 수정 전 출력과 올바른 feature의 frozen linear probe·kNN·OOD AUROC 및 risk–coverage를 비교한다. 두 출력의 차원·의미가 다르므로 기존 OOD 결과와의 비교는 **not strictly apples-to-apples**로 표시한다.

**GO/KILL.** index 동등성·feature provenance가 통과하면 probe를 GO한다. 이 audit 전에 encoder 정보 손실이나 adaptation 효과를 주장하면 KILL이다.

**GO/KILL.** 관련성 필터가 새 chart holdout에서 오류를 줄이면 GO, oracle 이득만으로 자율 항법 신뢰성을 주장하면 KILL이다. 초록은 benchmark·code 공개 예정으로 명시한다.

## 5. Leakage-Free Is Not Confounder-Free — 획득 시기 정보와 readout의 사용을 분리한다

**확인 사실·저자 보고.** v1 11/20 13:16:25 UTC. DMR-IR 236명·환자 분리 protocol에서 날짜-only AUROC는 0.980, 최고 영상 arm은 0.949다. 동일 fold의 영상 **9/9 arm이 날짜 baseline보다 낮다**. 이는 환경별 열화 cell 비율이 아니다. 촬영 연도는 feature에서 읽히지만, 진단 score에 유의하게 드러난 것은 9개 중 all-frame ConvNeXt-T 한 arm이다. [제출 이력](https://arxiv.org/abs/2611.27585), [본문 Tables 1–2](https://arxiv.org/html/2611.27585v1)

**shift·metric·한계.** acquisition era×label×frame aggregation이 cell이다. 날짜와 label이 얽힌 benchmark 진단이며 실제 새 병원 OOD 성능 측정이 아니다. ECE·selective coverage는 미확인이다. feature decodability를 모든 head의 shortcut 사용으로 단정하지 않는다. 저자는 전역 thermal offset 가능성을 제시하지만 실제 환경이 기록되지 않아 실내 온도를 원인으로 확정하지 않는다.

**가설 → 최소 실험 제안.** frame pooling이 획득 signature를 강화한다는 가설을 먼저 검사한다. 같은 encoder·환자 fold에서 frontal/all-frame score의 era predictability와 background-only 통계를 비교한다. 열 offset 정규화만 켜고 끄되, 날짜×양·음성 support와 matched size-control을 함께 기록한다.

**GO/KILL.** 날짜 교란과 크기 통제를 모두 통과한 독립 획득 holdout에서만 GO다. 통제 후 점수만으로 병리 신호를 인증하면 KILL이다. 같은 날짜의 cross-label support가 희박하므로 split 변경만으로 식별 문제를 해결할 수 없다.
