## Q1. 공간 추론 모델 순위는 shortcut 정의와 judge 선택에 얼마나 의존하는가?

**Observation·왜 지금:** SpatialChain 논문은 shortcut을 `RF <= 0.5`, README는 `RF < 0.5`로 설명한다. 논문은 별도 judge 및 threshold 분석도 제시한다. 따라서 단순 threshold sweep의 반복을 넘는 진단이 필요하다. 실행 코드의 오류가 확인됐다는 뜻은 아니다. [논문·제출 이력](https://arxiv.org/abs/2610.06413), [평가 정의·검증](https://arxiv.org/html/2610.06413v1), [공식 README](https://github.com/spatialchain/SpatialChainBenchmark)

**문제·Gap·가설:** 경계 사례의 포함 여부, judge, 모델별 정답 집합 차이가 함께 순위에 영향을 줄 수 있다. 가설은 “평균 shortcut 차이의 일부가 실제 근거 품질보다 경계 사례와 집계 분모에 민감하다”이다. 이는 추론이며 미확인이다.

**MVP·baseline·dataset·ablation:** 공개된 per-item judge 기록을 먼저 확보한다. SpatialChain의 동일 test 항목에서 `<`/`<=`, 원문 judge/두 번째 judge, 모델별 정답 집합/공통 정답 집합을 교차 집계한다. 두 분모는 서로 다른 질문에 답하므로 함께 표시한다. 정답 자체가 바뀌는 항목도 별도 보존한다. 기록이 없으면 새 유료 judge 호출을 자동 실행하지 않고 접근 제약을 기록한다.

**metric·GO/KILL:** shortcut rate, 경계 사례 비율, rank correlation, item 단위 paired bootstrap 순위 역전 확률을 사용한다. **GO:** 한 쌍 이상의 우열이 정의·judge 변경에 따라 바뀌며 불확실성 분석에서도 반복된다. **KILL/수정:** 모든 비교가 안정적이면 프로토콜 강건성을 보고한다. 통계적 순위 역전과 실질적 효과 크기를 구분한다.

**기여·negative result·compute·위험:** 기여 후보는 분모와 judge를 함께 공개하는 평가 감사다. 부정 결과도 비교의 안정성 범위를 남긴다. 재집계는 CPU로 가능해 8GB GPU가 필요하지 않다. compute cost 1/5. 이미 원문에 judge·threshold 분석이 있어 novelty 위험이 높다. 4~8주는 기록 확보 후 두 평가셋으로 확장한 진단 보고서에 조건부로 가능하다.

**점수:** novelty 2/5 · feasibility 4/5 · compute efficiency 5/5 · publication potential 2/5.

## Q2. grounded gain은 무관 이미지의 난이도에 대해 안정적인가?

**Observation·왜 지금:** ADR은 원본 이미지와 다른 source 이미지의 deterministic null을 비교한다. 공식 구현 안내는 cyclic offset을 사용하며 subset별 배정 규칙과 coverage 처리도 명시한다. 무관 이미지를 한 방식으로 구성한 gain을 다른 대조군에도 일반화할 수 있는지는 별도 질문이다. [논문](https://arxiv.org/abs/2610.06324), [평가 정의](https://arxiv.org/html/2610.06324v1), [공식 evalkit](https://github.com/GarryLarry010131/ADR)

**문제·Gap·가설:** source가 다른 것만으로 의미적으로 같은 난이도의 null이 보장되지는 않는다. 가설은 “객체·장면 유사도가 높은 null에서는 일부 readout의 gain이 작아지며, 기본 null의 모델 비교가 달라진다”이다. 원문의 결론을 반박한 결과는 아니다.

**MVP·baseline·dataset·ablation:** frozen CLIP ViT-B/16의 deployed score와 ADR을 VG-Relation left/right·COCO-spatial에서 비교한다. 기존 null, 무작위 derangement 여러 seed, 객체/장면 유사도가 맞춰진 hard null을 사용한다. 모든 readout에 같은 짝을 적용하고 같은 source를 배제한다. test 정답으로 null을 고르지 않는다. 샘플 수·coverage를 고정하며 `--limit`에 따른 null 풀 변화를 본 실험과 분리한다.

**metric·GO/KILL:** real/null accuracy, gain, null seed 변동, 동일 항목의 점수 변화와 paired 신뢰구간을 기록한다. **GO:** null 방식과 readout 간 상호작용이 두 subset에서 일관되게 나타난다. **KILL/수정:** 결론이 안정적이면 null 구성에 대한 강건성 근거를 남긴다. hard null에서 gain이 줄었다는 사실만으로 시각 활용 부재를 주장하지 않는다.

**기여·negative result·compute·위험:** 대조군 난이도를 명시한 grounding 평가가 기여 후보다. frozen feature를 캐시하는 소규모 MVP는 compute cost 2/5지만 실제 peak VRAM은 측정해야 한다. hard-negative 연구와 겹칠 위험이 있다. 4~8주는 두 subset의 통제 실험·독립 확장에 조건부로 가능하다.

**점수:** novelty 3/5 · feasibility 4/5 · compute efficiency 4/5 · publication potential 3/5.

## Q3. 긴 영상 메모리의 이득은 같은 총 시각 예산에서도 유지되는가?

**Observation·왜 지금:** VideoTapestry는 계층 메모리와 query별 재관측을 결합한다. 논문에는 single-agent와 동일 model/tool-call budget ablation이 이미 있다. 또한 direct baseline은 개별 프레임, Overview는 grid packing을 사용한다. 단순히 “agent 수를 맞추지 않았다”는 비판은 부정확하다. [논문·제출 이력](https://arxiv.org/abs/2610.06672), [설정·ablation·부록 B–C](https://arxiv.org/html/2610.06672v1)

**문제·Gap·가설:** 호출 수가 같아도 unique frame, 입력 pixels, token, 사전 메모리 비용은 다를 수 있다. 가설은 “계층 갱신의 잔여 이득은 동일 전체 예산에서 evidence를 확보하고 배치하는 방식에서 나온다”이다.

**MVP·baseline·dataset·ablation:** LongVideoBench의 long subset에서 동일 backbone으로 direct, static retrieval, append-only, hierarchy refinement를 비교한다. 모든 방식에 동일 frame/pixel 상한·grid 허용·ASR 접근을 부여한다. 사전 메모리 구축 비용을 포함한 첫 질의와 같은 영상의 반복 질의를 분리한다. oracle 시간 구간은 진단 상한으로만 사용한다. 공식 실행 코드 공개는 이번 검색에서 확인하지 못했으므로 초기 MVP는 독립 축소 구현이다.

**metric·GO/KILL:** answer accuracy, evidence hit rate, unique frames, 총 입출력 token, latency, 질의 수별 누적 비용을 기록한다. **GO:** 동일 예산에서 개선의 paired 신뢰구간이 0을 넘고 held-out 질문에서도 유지된다. **KILL/수정:** 차이가 사라지면 이득을 예산·관측 방식의 변화로 해석한다. oracle gap이 크면 memory보다 localization을 우선 진단한다.

**기여·negative result·compute·위험:** 사전 비용을 상각한 memory 평가와 실패 분해가 기여 후보다. compute cost 3/5; API 비용은 모델·실제 token을 정한 뒤 산정하고 승인 없이 유료 실험을 시작하지 않는다. 기존 통제 ablation과 겹칠 위험이 있어 pixel·token·반복 질의까지 확장해야 한다. 4~8주는 축소 구현·한 benchmark 진단에 조건부로 가능하다.

**점수:** novelty 3/5 · feasibility 3/5 · compute efficiency 3/5 · publication potential 3/5.

## Q4. 재투영 일치가 좋은 초해상도는 작은 구조의 의미도 보존하는가?

**Observation·왜 지금:** 새 EO 연구는 부분 지도 SR+segmentation과 re-projection loss를 제안한다. 연결된 `munera` 저장소에서는 현재 `.gitignore`와 짧은 README만 확인되어 구현 재현을 바로 시작할 수 없다. 원문의 hybrid/re-projection 자체를 새 방법으로 재제안하지 않는다. [논문·제출 이력](https://arxiv.org/abs/2610.06389), [공식 원문](https://arxiv.org/html/2610.06389v1), [연결된 저장소](https://github.com/lhoangan/munera)

**문제·Gap·가설:** 저해상도 입력으로 다시 내려갔을 때 일치하는 여러 HR 출력 중 의미가 틀린 출력도 있을 수 있다. 가설은 “재투영 오차 개선이 작은 객체·경계의 의미 개선을 충분히 예측하지 못한다”이다. 저자 모델에서 이미 확인된 실패가 아니다.

**MVP·baseline·dataset·ablation:** ISPRS Potsdam의 동일 HR 이미지에서 LR을 만들고, LR-only, bicubic+고정 segmenter, SR+고정 segmenter, 부분 지도 joint model을 비교한다. scene 단위로 split한 뒤 crop하고 annotation 비율·학습량·출력 해상도를 맞춘다. car 같은 작은 클래스와 boundary를 분리한다. blur/downsampling 조건을 바꿔 일반화 여부를 본다. 저자 코드가 없으면 독립 구성임을 명시한다.

**metric·GO/KILL:** PSNR/SSIM, 재투영 오차, class IoU, boundary F1, car component 단위 precision/recall의 관계를 측정한다. **GO:** 시각 품질 개선과 의미 성능 저하가 복수 degradation·seed에서 반복된다. **KILL/수정:** 일관된 동반 개선이면 재투영 규제의 유효 범위를 기록한다. metric 상관만으로 hallucination의 원인을 확정하지 않는다.

**기여·negative result·compute·위험:** SR 품질과 의미 충실도를 분리한 small-structure 진단이 기여 후보다. crop·소형 network MVP는 compute cost 3/5; 8GB 학습 적합성은 batch·crop별 측정 전 미확인이다. semantic SR 문헌과 중복 위험이 높다. 4~8주는 공개 데이터의 소규모 진단에 가능성을 두되, 저자 모델 재현은 코드 공개에 의존한다.

**점수:** novelty 3/5 · feasibility 3/5 · compute efficiency 3/5 · publication potential 3/5.

## Q5. 모델 합의로 찾은 SWIR 우위는 독립 scene 표본에서도 유지되는가?

**Observation·왜 지금:** RGB/SWIR 연구는 평균적으로 RGB가 비슷하거나 우수하지만 일부 어려운 조건에서 SWIR의 보완적 이득을 보고한다. 저자는 합의 기반 mining의 모델 편향과 연속 프레임·클래스 불균형도 한계로 인정한다. 저장소의 `weights` 디렉터리는 확인했지만 충분한 실행 코드·데이터 접근은 검증하지 못했다. [논문·제출 이력](https://arxiv.org/abs/2610.06596), [분석·한계](https://arxiv.org/html/2610.06596v1), [공식 저장소](https://github.com/comsee-research/swir-adverse-env-analysis)

**문제·Gap·가설:** 발견에 쓴 detector들의 합의가 평가 표본을 고르면 우위가 선택 편향에 의존할 수 있다. 가설은 “희귀 조건의 이득 일부는 실제 센서 차이이고 일부는 model/scene 선택에 민감하다”이다.

**MVP·baseline·dataset·ablation:** RASMD paired 데이터 접근 후, detector score를 보지 않은 annotator가 glare·droplet·low-contrast 조건을 먼저 표시한다. discovery와 평가를 주행 scene 단위로 분리한다. 같은 detector family·training 예산의 RGB-only/SWIR-only를 비교하고, mining에 사용하지 않은 detector도 평가한다. 모델 합의 선정·독립 조건 선정·무작위 표본을 구분한다. 시간 인접 frame이 split을 넘지 않게 한다.

**metric·GO/KILL:** 조건별 AP, 작은/원거리 객체 recall, false-positive rate와 scene 단위 bootstrap을 기록한다. **GO:** 독립 조건 표본과 held-out detector에서 이득 방향이 유지된다. **KILL/수정:** 합의 선정 subset에서만 이득이 보이면 선택 편향의 경계를 보고한다. calibration과 modality별 학습 데이터 차이를 별도 통제한다.

**기여·negative result·compute·위험:** 희귀 조건에서 센서 우위를 검증하는 발견/평가 분리 프로토콜이 기여 후보다. cached prediction 분석은 compute cost 1/5, detector 재학습 확장은 4/5다. 데이터 요청이 주요 제약이며 기존 sensor fusion 연구와 구분해야 한다. 4~8주는 접근 확보 후 진단에 조건부로 가능하다. 도로 결과를 해양·안개 안전 성능으로 일반화하지 않는다.

**점수:** novelty 3/5 · feasibility 2/5 · compute efficiency 4/5(캐시 분석) · publication potential 3/5.

## 우선순위와 실행 판단

점수는 에이전트의 판단이며 실측치나 게재 확률이 아니다. compute cost는 1이 가볍고 5가 무겁다. compute efficiency는 반대로 5가 효율적인 MVP를 뜻한다.

| 질문 | 첫 진단 | 주요 접근 제약 | 우선순위 |
|---|---|---|---|
| Q1 | 기존 judge 기록 재집계 | per-item 기록 확보 | 오늘 1순위 |
| Q2 | null 구성 민감도 | 원본 이미지·feature cache | 다음 실행 후보 |
| Q3 | 총 예산·반복 질의 비교 | 독립 구현·모델 호출 비용 | 조건부 |
| Q4 | 작은 구조의 의미 보존 | 코드 미공개·학습 설정 | 조건부 |
| Q5 | 독립 scene에서 센서 우위 | paired 데이터 접근 | 대기 후 판단 |

**오늘 가장 먼저 테스트할 질문:** Q1. 먼저 per-item 기록의 존재·schema·정답 분모를 확인하고 `<`/`<=`를 재집계한다. 원문에 이미 있는 분석을 반복하는 수준이면 확장하지 않는다.

**RTX 5060 Ti 8GB에서도 가능한 질문:** Q1의 CPU 재집계. GPU 모델을 돌리지 않으므로 VRAM 제약을 피할 수 있다. Q2 frozen CLIP은 다음 후보지만 실제 메모리를 측정하기 전 8GB 적합성을 보장하지 않는다.

**장기 박사주제로 키울 질문:** Q2를 중심으로 “어떤 대조군이 시각 근거 활용을 식별하는가?”를 image→video→domain shift로 확장한다. 목표는 방법 수를 늘리는 것이 아니라 null 난이도, 누락 근거, 선택 편향을 구분하는 평가 체계다. 해양·안개로의 연결은 아직 후속 가설이다.

## 공통 실험 원칙과 검색 결론

모든 MVP는 code/model/data revision, split, backbone·pretraining·외부 데이터, 해상도·TTA, 추론 도구·reasoning effort, context/frame/token·compute budget을 기록한다. 조건이 다른 결과는 **not strictly apples-to-apples**로 표시한다. 샘플·scene split과 seed를 결과를 본 뒤 바꾸지 않는다.

웹 검색과 최신 cs.CV 목록에서 후보를 찾고 공식 원문·연결된 저장소로 확인했다. MGE의 context masking도 검토했으나 오늘은 직접 연구 연결과 실행 가능성이 더 분명한 5개로 제한했다. 새 OVD negative-transfer 근거를 충분히 확보하지 못했으므로 기존 adaptation 질문을 새 질문처럼 재포장하지 않았다. [최신 cs.CV 목록](https://arxiv.org/list/cs.CV/recent), [검토한 MGE 원문](https://arxiv.org/abs/2610.06813)

오늘 확인한 변화는 공간 평가의 집계 정의, query-adaptive 영상 메모리, 부분 지도 EO 학습, 조건별 센서 평가다. 남은 문제는 **관찰된 개선을 어떤 메커니즘·대조군·예산·표본이 지지하는가**이며, 위 질문들은 이를 최소 개입으로 분해하기 위한 제안이다.
