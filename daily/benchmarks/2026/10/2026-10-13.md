## 3. OccludeBench — 문맥 추론 점수가 물리 단서 추론을 가린다

**공식 원문:** [arXiv paper](https://arxiv.org/abs/2610.13790), [HTML results](https://arxiv.org/html/2610.13790), [official dataset card](https://huggingface.co/datasets/afs07fda89sdfas90/data)

### 확인된 사실

- benchmark는 378개 수동 선별 이미지로 구성된다. 직접 단서 197개는 반사·그림자로 완전히 가려진 객체를 복원하고, 추론형 181개는 장면 문맥으로 객체를 추론한다.
- 5개 VLM의 평균 정확도는 direct 42.7%, inferential 62.7%다. 인간은 63.4%, 68.5%이며 두 인간 분포의 차이는 유의하지 않았다($p=0.079$).
- 모델별 direct/inferential은 GPT-5.4 37.6/62.4, Claude Opus 4.6 51.8/75.1, Gemini 3.1 Pro 71.6/87.8, Qwen 3 VL 8B 20.9/46.4, Llama 4 Maverick 31.6/42.0이다.
- OccludeTrace에서 실패 예와 성공 예의 격차는 cue detection 99/100%, crop recognition 79/88%, source mapping 85/82%보다 full-image highlighted-region recovery 50/91%에서 크게 벌어진다.
- inpaint-then-confront는 GPT-5.4의 direct/inferential 격차를 24.8pp에서 8.1pp($p=0.12$), Gemini 3.1 Pro를 16.2pp에서 5.6pp($p=0.15$)로 낮췄다.
- open-ended 응답은 GPT-5.4와 Claude Opus 4.6 두 judge 중 하나가 수용하면 정답으로 처리하며, 이 ensemble은 저자 gold label과 98% 일치했다.

### 저자 주장

저자는 VLM이 그림자·반사의 존재를 못 보는 것이 아니라, 전체 장면 안에서 그 투영이 나타내는 객체를 안정적으로 꺼내 쓰지 못한다고 해석한다. 시각 가설을 먼저 생성하고 물리 단서와 대조하면 이 병목이 줄어든다는 주장이다.

### 비교 가능성 감사

direct와 inferential은 같은 모델·질문 형식·judge를 쓰므로 내부 격차는 강한 신호다. 다만 378개 중 353개가 웹 이미지이고, 정답 판정에 최신 폐쇄형 LLM judge가 들어간다. 모델 버전이 바뀌면 수치가 이동할 수 있으므로 공개 annotations와 judge 판정을 함께 보존해야 한다. inpainting 개입은 생성 기능이 있는 두 모델에만 적용되어 전체 VLM에 일반화할 수 없다.

### 진단 → 가설 → 최소 실험

- **진단:** 해무·야간 해상 영상에서 선박이 직접 보이지 않아도 wake, 반사, 그림자 같은 단서가 남지만 일반 VQA 정확도는 이 능력을 분리해 측정하지 않는다.
- **가설:** direct-cue subset을 따로 만들면 문맥 shortcut에 의존하는 모델과 실제 물리 단서를 쓰는 모델이 분리된다.
- **최소 실험:** 선박 직접 가림 50장과 장면 문맥 50장을 구축해 동일 prompt로 3개 VLM을 3회 평가한다. answer accuracy와 cue-region attention/grounding을 함께 기록한다. direct-inferential gap이 10pp 이상이면 inpaint-then-confront 또는 crop-confront를 적용하고 gap 감소와 전체 정확도 변화를 측정한다.

## 4. G-RSVQA + AESP — “정답”과 “그 정답을 지지하는 box”를 분리

**공식 원문:** [arXiv paper](https://arxiv.org/abs/2610.13636), [official evaluation repository](https://github.com/pingggg516/AESP-Evaluation)

### 확인된 사실

- G-RSVQA는 DIOR 11,714개, NWPU VHR-10 800개, SODA-A 2,513개를 합친 15,027개 이미지/질문과 163,399개 관련 객체 annotation으로 구성된다.
- 질문은 existence 8,592개, counting 4,275개, comparison 2,160개다.
- AESP는 answer accuracy와 localization F1 외에, 모델이 낸 box가 모델 자신의 답을 논리적으로 지지하는지를 task-specific rule로 계산한다.
- 예시처럼 10개라고 답하면서 9개 box만 제시해도 localization F1은 94.7%일 수 있지만 counting evidence는 불충분하다. 비교 질문에서도 2 대 2 box로 “더 많다”를 지지할 수 없다.
- 7개 grounded VLM 평가에서 evidence-evaluation subset의 올바른 답 중 최대 50.82%가 제시한 grounding evidence로 지지되지 않았다.
- 공개 evaluator는 AA, localization P/R/F1, Evidence Support-Overall, Evidence Support-Correct Answers, Joint Success를 저장하며 Qwen3-14B의 고정 revision을 answer extractor로 사용한다.

### 저자 주장

저자는 높은 answer accuracy와 높은 localization score를 동시에 얻어도 answer–grounding consistency가 보장되지 않으며, 실제 사용자가 box를 “근거”로 읽는 상황에서는 joint success가 더 직접적인 신뢰성 지표라고 주장한다.

### 비교 가능성 감사

질문·box·원본 object annotation을 함께 공개해 재현성이 높다. 그러나 세 소스 데이터의 split과 class distribution이 다르고, SODA-A polygon은 horizontal box로 변환된다. answer extraction에 29.6GB BF16 Qwen3-14B checkpoint가 필요해 evaluator 자체의 비용과 parsing 오류를 별도로 기록해야 한다. 논문의 50.82%는 “최대” 실패율이며 7개 모델 전체의 공통 비율로 읽으면 안 된다.

### 진단 → 가설 → 최소 실험

- **진단:** 원격탐사·해상 VQA에서 정답 문자열만 맞히면 모델이 실제 객체를 찾았는지 알 수 없다.
- **가설:** Joint Success를 추가하면 counting/comparison에서 language prior로 답을 맞히는 사례가 크게 드러난다.
- **최소 실험:** 공개 G-RSVQA에서 existence/counting/comparison 각 100개를 stratified sample하고 현재 사용하는 VLM의 answer와 box를 저장한다. AA, Loc-F1, ES-correct, JS를 계산한다. AA와 JS 차이가 10pp 이상이면 training/evaluation objective에 evidence coverage penalty를 추가한다.

## 5. MVGraph — 사고 모드는 회복시키지만 cross-view edge composition은 남는다

**공식 원문:** [arXiv paper](https://arxiv.org/abs/2610.12961), [HTML tables](https://arxiv.org/html/2610.12961), [official repository](https://github.com/AAAndy-Zhu/MVGraph)

### 확인된 사실

- MVGraph는 8개 end-to-end graph task 8,000개와 29개 diagnostic task 64,000개, 총 72,000 instances를 제공한다. 각 항목은 2~8개 시각 graph view를 사용한다.
- single view만으로 풀 수 없도록 programmatic evidence-necessity check를 적용하며, 복수 정답 문제는 exact string 대신 task-specific verifier로 평가한다.
- thinking mode의 end-to-end 평균은 GLM-5.3-Flash 52.4%, Qwen3.8-Flash 50.4%, 최고 local model Gemma-4-12B-it 20.5%다.
- non-thinking mode에서 6개 모델 정확도는 2.6~6.4%였고, Qwen3.8-Flash는 thinking으로 2.6%에서 50.4%까지 올랐다.
- perception 단계에서 어떤 모델도 multi-view graph exact match 47%를 넘지 못했다. alignment에서는 node보다 edge가 약했고, 가장 강한 모델도 view-specific edge 정확도가 60% 미만이었다.
- 시간 순서 task에서는 Stable Topological Sorting과 Stable Bipartite Matching이 특히 어렵고, 구조를 준비해 줘도 temporal reasoning 병목이 남았다.

### 저자 주장

저자는 현재 LVLM의 다중 이미지 성능을 하나의 최종 정확도로 보면 perception·alignment·composition·reasoning 중 어디서 실패하는지 알 수 없으며, edge alignment와 relation-level composition이 주요 병목이라고 주장한다.

### 비교 가능성 감사

문제 생성과 verifier가 공개되고 zero-shot protocol이 명확한 점은 강하다. 반면 API 모델 이름은 서비스 시점의 가변 버전을 포함할 수 있다. “thinking”은 모델별 토큰 예산·추론 구현이 같다는 뜻이 아니므로 2.6→50.4%를 순수한 동일 compute 비교로 해석하면 안 된다. 시각 graph는 실제 자연영상이 아니어서 성능 저하가 원격탐사 multi-view에 그대로 전이된다는 보장도 없다.

### 진단 → 가설 → 최소 실험

- **진단:** UAV frame, AIS table, thermal view를 함께 보는 해상 감시는 동일 선박의 관계를 view 간에 맞춰야 한다.
- **가설:** object identity는 맞추더라도 relation edge와 시간 변화의 합성이 주된 실패점이다.
- **최소 실험:** 30개 해상 장면에서 RGB/thermal/AIS 세 view를 구성하고 (1) per-view extraction, (2) identity alignment, (3) relation composition, (4) 최종 질의를 단계별로 채점한다. oracle intermediate를 하나씩 제공해 최종 정확도 회복량을 비교한다. edge oracle의 회복이 가장 크면 association module을 우선 개선한다.

## 6. MMStar 사후 감사 — leaderboard 원본 artifact를 benchmark QA로 재사용

**공식 원문:** [arXiv paper](https://arxiv.org/abs/2610.13548), [official repository and artifacts](https://github.com/avos-rnd/vlm-bench)

### 확인된 사실

- 저자는 VLMEvalKit의 저장된 per-question prediction·correctness·metadata를 이용해 6개 detector와 visual input을 제거한 text-only rerun을 추가했다.
- MMStar를 3개 모델로 감사했을 때 문항 20.2%에서 이미지가 aggregate accuracy gain을 만들지 않았다.
- item-matched permutation null이 17.0%를 설명했고, 남는 초과분은 +3.2pp였다. corrected permutation $p=0.001$이다.
- 세 모델 모두 parse 가능한 응답에서 같은 오답을 고른 134개 문항을 별도 후보로 표시했다.
- LLM judge를 exact string matching으로 바꿔도 결론은 유지됐고, scoring discrepancy는 한 모델의 parser-unreadable free-form answer에서 나왔다.
- binary yes/no benchmark에서는 detector calibration이 측정 가능하게 나빠져 적용 범위를 제한했다.

### 저자 주장

저자는 evaluation artifact를 단일 점수로 버리지 말고 benchmark 자체의 shortcut, 오라벨, parser 취약성, image indispensability를 감사하는 데이터로 재사용해야 한다고 주장한다.

### 비교 가능성 감사

20.2% 중 17.0%는 null로 설명되므로 “MMStar의 20.2%가 이미지 불필요”라고 단정하면 과장이다. 핵심 신호는 보정 후 +3.2pp와 category localization이며, 저자도 지식이 시각 증거를 대체했다는 메커니즘은 item review가 필요하다고 명시한다. 또한 3개 모델 pool 결과라 모델 구성이 바뀌면 detector의 민감도가 변한다.

### 진단 → 가설 → 최소 실험

- **진단:** 자체 benchmark의 평균 정확도만 보관하면 image-free shortcut과 공통 오답을 찾기 어렵다.
- **가설:** 기존 실행 artifact에 text-only, shuffled-image, consensus-wrong detector를 붙이면 새 annotation 없이 취약 문항을 우선순위화할 수 있다.
- **최소 실험:** 현재 해상 VQA validation 500개에서 원본, image-removed, shuffled-image 세 조건을 같은 model/version으로 실행한다. paired bootstrap CI, item-matched permutation null, common-wrong count를 계산한다. 보정된 image-free excess가 3pp 이상이면 해당 category를 재검수한다.

## 7. Beyond the Snowflakes — 악천후 bin이 robustness가 아니라 쉬운 객체를 고를 수 있다

**공식 원문:** [arXiv paper](https://arxiv.org/abs/2610.13891), [HTML experiments](https://arxiv.org/html/2610.13891), [official WADS-3D dataset](https://digitalcommons.mtu.edu/wads-3d/)

### 확인된 사실

- WADS-3D는 4,100 labeled frames와 30,104 cars, CADC는 7,000 LiDAR frames를 사용한다.
- SECOND-IoU, Voxel R-CNN, PointPillars, PV-RCNN, Part-A2 다섯 detector를 비교했다. WADS-3D는 KITTI pretrained model을 그대로 쓰고, CADC는 32-channel sensor 대응을 위해 50:50 train/eval fine-tuning을 적용했다.
- 두 dataset 모두 snow intensity가 높을수록 AP가 오르는 양상이 나타났다. WADS-3D에서 snow filtering은 평균 AP를 6.72% 높였지만 상승 추세 자체는 남았다. CADC의 filtering gain은 미미했다.
- WADS-3D recall에서 point count와 distance의 Kendall $\tau$는 약 +0.3/-0.3이고, 두 변수의 SHAP importance 합은 약 40~50%였다. snow intensity importance는 0.03 미만이었다.
- snow bin과 object point count의 Pearson correlation은 WADS-3D $r=0.820$($p=3.70\times10^{-3}$), CADC $r=0.733$($p=1.86\times10^{-3}$)였다. CADC mean intensity도 $r=0.694$($p=4.12\times10^{-3}$)였다.
- voxel-based SECOND-IoU가 가장 안정적이었고, 저자는 voxel aggregation이 sparse snow noise를 완화한다고 해석했다.

### 저자 주장

저자는 snow가 성능을 높인 것이 아니라 heavy-snow bin의 차량 point count와 reflectance가 함께 높아져 쉬운 객체가 더 많이 포함된 결과라고 주장한다. snow accumulation에 따른 표면적·diffuse reflection 변화는 아직 검증 전 물리 가설로 제시한다.

### 비교 가능성 감사

동일 dataset 내 snow-bin 추세와 filter ablation은 의미가 있지만 WADS와 CADC는 센서 채널, 학습 방식, snow density가 다르므로 절대 AP를 직접 비교할 수 없다. WADS-3D의 2,050 scans를 회전해 4,100 frames로 만든 구조와 car-only annotation도 독립성·일반화 범위를 제한한다. surface accumulation 메커니즘은 관찰된 통계와 구분해야 한다.

### 진단 → 가설 → 최소 실험

- **진단:** 해무 심각도별 detector AP가 유지되거나 오르면 모델이 robust해진 것인지, 해당 bin에 더 크고 가까운 선박이 많은 것인지 구분되지 않는다.
- **가설:** fog density와 object pixel area·contrast·range를 공동 stratification하면 기존 weather robustness 순위가 바뀐다.
- **최소 실험:** 해무 dataset을 fog density × object area × range의 3차 bin으로 재구성하고 각 cell 최소 30개를 맞춘다. raw AP와 matched AP, object recall, bootstrap CI를 보고한다. 순위가 2단계 이상 바뀌면 기존 weather-only 결론을 폐기한다.

## 8. 교차 신호

1. **정답 정확도만으로는 근거 사용을 보장하지 못한다.** OccludeBench, AESP, MMStar audit 모두 “맞혔는가”와 “보이는 증거로 맞혔는가”를 분리한다.
2. **aggregate score보다 stage와 subgroup이 중요하다.** MVGraph의 edge alignment, OccludeTrace의 full-image recovery, snow LiDAR의 point-count confound가 평균 안에서만 드러나지 않는다.
3. **intervention은 메커니즘 검증이어야 한다.** inpaint-then-confront, oracle intermediate, snow filtering, image removal은 단순 성능 향상보다 실패 원인을 좁힌다.
4. **공식 release가 평가의 일부가 됐다.** 데이터, evaluator revision, parser, run manifest를 고정하지 않으면 최신 API VLM 숫자는 재현하기 어렵다.
5. **원격탐사와 해상 CV에는 joint evidence metric이 특히 적합하다.** 작은 객체 counting, multi-view association, adverse-weather stratification 모두 box·관계·조건을 함께 저장해야 한다.

## 9. 오늘의 benchmark signal 3

1. **Answer–evidence joint success:** G-RSVQA의 최대 50.82% unsupported-correct 결과는 grounded VQA의 기본 metric 재설계를 요구한다.
2. **Direct visual cue gap:** OccludeBench의 20.0pp 격차는 문맥 shortcut과 물리 단서 추론을 분리하는 간단한 stress test다.
3. **Confound-aware robustness:** snow severity와 point count의 강한 상관은 weather-only bin의 AP를 robustness 증거로 쓰면 안 된다는 경고다.

## 10. Woojin 연구에 바로 연결할 실험

- 해상 VQA 평가 표에 Answer Accuracy, Box F1, Evidence Support-Correct, Joint Success 네 열을 고정한다.
- 해무·야간·반사 장면에서 직접 단서 50개와 문맥 추론 50개를 분리해 VLM gap을 측정한다.
- RGB/thermal/AIS를 MVGraph의 perception→alignment→composition→reasoning 구조로 나눠 oracle recovery를 측정한다.
- fog severity benchmark는 object size·range·contrast matched score를 원래 AP 옆에 함께 보고한다.
- 모든 run에 model revision, prompt, judge/parser revision, image resolution, seed, failed parse count, raw prediction artifact를 보존한다.
