## 엄격 선택: LMCache nightly (2026-10-27)

- **사실:** [LMCache 공식 Releases](https://github.com/LMCache/LMCache/releases)는 2026-10-27자 Intel XPU, ROCm 7.2, Moore Threads MUSA, CUDA 12.9, CUDA 13.0 nightly를 열거한다. 이는 모델 가중치가 아닌 추론 캐시 소프트웨어 배포물이다.
- **저자 주장:** 이 보고서는 성능 수치를 새로 주장하지 않는다. 플랫폼별 배포물이 존재한다는 사실만 근거로 삼는다.
- **해석:** VLM/LLM 서빙 후보지만 플랫폼별 wheel·컨테이너가 나뉘므로 어느 GPU에서나 동작한다고 가정하면 안 된다. CV 모델 릴리스 수에도 넣지 않는다.
- **진단:** 현 서빙 환경의 CUDA/ROCm/driver와 vLLM 버전이 nightly 조합에 맞는지 확인되지 않았다.
- **가설:** 동일 입력을 반복 요청하는 문서 VLM 평가에서 캐시가 p50 지연시간을 낮출 수 있다.
- **최소 실험:** 같은 프롬프트·이미지 50개를 cache off/on에서 각 3회 실행한다. GPU·드라이버·LMCache/vLLM revision, 성공 응답 수, p50/p95만 기록한다.
- **GO/KILL:** 3회 모두 재현되고 p50이 감소하면 GO; 버전 충돌·출력 불일치·반복 실패가 한 번이라도 나면 KILL하고 안정 릴리스로 복귀한다.

## 공개됐지만 이번 신규 release로 세지 않은 관찰

### Aerial-R1

- **사실:** [논문](https://arxiv.org/abs/2610.33056)은 10월 19일 v1이다. [공식 코드](https://github.com/phy709/Aerial-R1)는 Sa2VA 기반 가중치를 준비한 뒤 `h_gawr.pth`, `sft.pth`, `sft_l.pth` LoRA 체크포인트를 올리는 절차와 [VSAI-Ref 데이터](https://huggingface.co/datasets/phy9178/VSAI-Ref)를 명시한다.
- **저자 주장:** H-GAWR가 저정보 항공 영상의 환각을 줄이고 거부 행동을 학습시킨다고 주장한다.
- **해석:** 기반 Sa2VA 가중치를 별도 변환해야 하므로 체크포인트만 받는 것으로 독립 재현이 끝나지 않는다.
- **최소 실험:** base-weight 변환과 `h_gawr.pth` 로딩이 단일 이미지에서 완료되는지 확인한다. 정상/모호 객체 각 10장에 대해 빈 마스크 비율과 추론 실패를 분리 기록한다.

### DRA-SAM

- **사실:** [논문](https://arxiv.org/abs/2610.33057)은 10월 19일 v1이다. [공식 코드](https://github.com/phy709/DRA-SAM)는 Python 3.10, PyTorch 2.5.1, CUDA 12.1과 `train-backbone`, `cache`, `train-evidence`, `evaluate`를 문서화한다. 평가 출력은 mIoU, oIoU, P@0.5–0.9와 query별 기록을 포함한다.
- **저자 주장:** RIS-LAD에서 맞춘 global SAM3-I 대비 mIoU 49.55→52.34, P@0.5 46.80→58.05의 개선을 보고한다.
- **해석:** `sam3i_pretrained.pt`와 RIS-LAD split의 접근성·정확한 버전을 확보하지 않으면 표의 수치를 검증할 수 없다.
- **최소 실험:** `scripts/run.py --help`와 config 파싱을 확인한 뒤, 5-image smoke set에서 global과 disagreement 재관측의 실행 완료율·추가 추론 횟수만 기록한다.

### OvisOCR3

- **사실:** [논문](https://arxiv.org/abs/2610.33066)은 10월 20일 v1으로 0.8B OCR 모델을 소개한다. [공식 모델 카드](https://huggingface.co/ATH-MaaS/OvisOCR3)는 Apache-2.0, Safetensors, Transformers `AutoModelForMultimodalLM`과 `vllm serve` 경로를 제공한다.
- **저자 주장:** OmniDocBench v1.6 96.74, OCRBench v2 English/Chinese 65.9/61.3을 보고한다.
- **해석:** 접근 경로는 확인됐지만 이 관측창 안의 새 게시·태그 시각을 확인하지 못했다. 따라서 신규 release 표에 넣지 않는다.
- **최소 실험:** 문서·표·수식 공개 샘플 30개에서 Transformers/vLLM의 로드 성공률, 출력 형식 파싱 성공률, 이미지당 지연시간을 기록한다. 동일 프로토콜 전에는 벤치마크 재현을 주장하지 않는다.
