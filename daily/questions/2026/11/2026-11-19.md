## Q1. 고해상도 segmentation의 실행 가능성은 모델보다 mask를 소비하는 방식에 얼마나 좌우되는가?

**문제·Observation·왜 지금:** #27265는 타일 merge에서 box-local mask를 유지하고, validator가 metric을 계산할 때 dense mask를 복원하도록 바꿨다. `.data` 접근은 여전히 전체 stack을 생성한다. 작성자는 메모리 감소와 출력 일치를 보고하지만 모든 입력·consumer에서 검증된 일반 법칙은 아니다. [공식 PR](https://github.com/ultralytics/ultralytics/pull/27265) · [실제 diff](https://github.com/ultralytics/ultralytics/pull/27265/files)

**Gap → Diagnosis → Mechanism:** 추론만 저메모리가 되어도 평가·시각화·후속 코드가 dense mask를 요구하면 병목이 다시 생길 수 있다. 검출 수×전체 canvas 크기와 실제 ROI 면적의 합을 구분해야 한다. 작은 객체가 많은 UAV 영상에서 유리할 수 있다는 연결은 추론이다.

**Hypothesis·최소 개입:** 같은 예측을 compact representation으로 유지하고 소비 경계를 늦추면 예측 의미를 보존하면서 peak memory를 줄일 수 있다. ROI가 크거나 dense 소비가 필수인 조건에서는 이점이 줄어든다.

**MVP·baseline·dataset·ablation:** base `3f5c9e6207dec8c4c2089300281d9808ce3037de`와 병합 `85d7d09659df9d0e841e9f754eb034aeacd25e68`의 동일 YOLO26n-seg weight를 사용한다. 작은 bus mosaic와 coco8-seg는 smoke test, DOTA-v1 val은 별도 접근·annotation 적합성 확인 후 자원 실험 후보로 둔다. predict만, plot, polygon/JSON, 명시적 `.data`, validation을 fresh process에서 분리한다. tile·입력 크기·max_det와 mask 면적을 바꾸되 각 paired 비교의 조건은 고정한다.

**Metric·GO/KILL:** 단계별 RSS/CUDA peak, materialization 시점, box·dense pixel·contour parity, 평가 점수를 기록한다. 소비 단계에 따른 메모리 재증가와 출력 보존이 반복되면 GO. compact predict 결과만으로 전체 평가도 저메모리라고 결론 내리는 것은 KILL한다. 서로 다른 OS의 RSS 정의는 합치지 않는다.

**Expected Contribution·negative result:** 모델 비용과 출력 표현 비용을 나눈 자원 평가 규약. 차이가 없어도 dense consumer가 지배하는 적용 한계를 얻는다.

**Compute·novelty·4~8주:** 작은 CPU fixture cost **1/5**, 확장 GPU 실험 **3/5**의 계획상 추정. 8GB에서 큰 DOTA baseline이 들어간다는 보장은 없다. 알려진 최적화 재현만으로 novelty는 낮다. 복수 segmentation 구현과 consumer에서 자원 한계·task parity를 연결하면 4~8주 내 시스템 진단 논문 후보가 된다.

## Q2. 영상 geometry 전환 후 “예외를 잡음”과 “상태가 회복됨”의 차이를 측정할 수 있는가?

**문제·Observation·왜 지금:** BoT-SORT sparse optical flow 수정안은 이전/현재 frame shape 불일치를 초기화 조건에 추가한다. 작성자는 예외 시 identity를 반환해도 history 갱신을 못 해 이후 frame이 계속 실패한다고 보고한다. 조회 시 미병합이며 독립 재현 완료로 표현하지 않는다. [PR·재현 조건](https://github.com/ultralytics/ultralytics/pull/27270) · [코드·회귀 fixture](https://github.com/ultralytics/ultralytics/pull/27270/files)

**Gap → Diagnosis → Mechanism:** 호출 성공률이나 crash 유무만으로는 stale state에 의한 지속적인 motion compensation 손실을 검출하지 못한다. GMC 회복과 tracker ID·Kalman state 회복은 별개다.

**Hypothesis·최소 개입:** geometry 전환에서 optical-flow history만 재초기화하면 전환 frame은 identity로 처리하고 다음 호환 frame부터 motion을 회복할 수 있다. ID continuity까지 개선된다는 가설은 별도 검증한다.

**MVP·baseline·dataset·ablation:** base `27cf3175a9aff96e12a65b86813d0a98bf7b1b92`와 head `d7ab0b9f2a7ffe2b6c75f614513783f6bf533f06`를 비교한다. textured 합성 sequence에 두 번의 shape 전환과 알려진 translation을 넣는다. 같은 크기 sequence, motion 없는 전환, downscale 1·2가 대조군이다. 우선 검출 모델 없이 GMC만 검사하고, 이후 고정 YOLO11n weight의 public tracking 경로를 확인한다. 실제 CCTV 성능은 annotation이 있는 별도 sequence가 필요하다.

**Metric·GO/KILL:** history shape, 전환 이후 회복까지 frame 수, affine translation 오차, 반복 warning 수를 기록한다. 정상 크기 대조군을 보존하면서 motion이 회복되면 GMC 수준 GO. IDF1/HOTA는 후속 별도 지표이며 warning 감소만으로 개선을 주장하지 않는다. 회복 실패나 정상 sequence 회귀가 생기면 개입을 KILL/축소한다.

**Expected Contribution·negative result:** 상태를 가진 vision 시스템의 fault injection·회복 진단. GMC가 회복돼도 tracking 성능이 그대로라면 “상태 수정의 downstream 영향은 제한적”이라는 경계를 얻는다.

**Compute·novelty·4~8주:** CPU MVP cost **1/5**, tracking 확장 **2/5**. 기존 state reset 개념의 novelty 위험이 높다. 복수 tracker에서 geometry·frame dropout·재접속의 회복을 같은 규약으로 비교하면 4~8주 진단 연구 후보다. 합성 resize를 실제 RTSP 관측으로 표현하지 않는다.

## Q3. 정답 box가 동일할 때 주변 설명문 때문에 grounding 결과가 달라지는 정도를 분리할 수 있는가?

**문제·Observation·왜 지금:** Supervision #3011은 응답 앞의 bracket 설명을 JSON 시작으로 오인하는 문제를 다룬다. 수정은 첫 code fence를 찾아 그 안을 사용한다. 본문과 diff는 유효 box가 있어도 빈 검출이 될 수 있는 경로를 보여준다. 작성자의 테스트 통과 보고는 이번 실행의 독립 측정이 아니다. [공식 PR](https://github.com/roboflow/supervision/pull/3011) · [diff·테스트](https://github.com/roboflow/supervision/pull/3011/files)

**Gap → Diagnosis → Mechanism:** 빈 검출에는 모델의 localization 실패와 직렬화 복구 실패가 섞인다. 첫 fence 선택도 무관한 code block이나 label 내부 backtick에서 의미를 잃을 수 있다는 반례 가설이 남는다.

**Hypothesis·최소 개입:** 문자열 내부/외부 구분과 detection schema 검증을 이용한 payload 선택은 정답 payload를 바꾸지 않는 주변 문구 변형에 더 견고할 수 있다. 여러 유효 payload가 충돌하면 억지로 하나를 고르지 않고 모호성을 반환해야 한다.

**MVP·baseline·dataset·ablation:** issue가 지목한 `887a7ae`를 원 baseline으로 확인하고 PR head `55e8cff0d56f1abc800c7bc150aca2a6abcc3a3b`, schema-aware 후보를 비교한다. 고정 box·label JSON에 bracket 설명, reasoning, 무관한 선행 fence, label 내부 backtick, 후행 fence를 넣는다. 문구만 바꾼 의미 보존 군과 실제 좌표·label을 바꾼 비불변 대조군을 구분한다. 실제 저장 Qwen 응답은 접근 가능할 때만 추가하며 현재 확보했다고 주장하지 않는다.

**Metric·GO/KILL:** box·label의 정확한 보존율, 빈 결과율, 오수락률, 모호성 반환율을 기록한다. 기존 허용 입력을 보존하고 주변 문구 실패가 줄면 GO. 잘못된 payload 수락이나 label 손상을 숨기면 KILL한다. 같은 raw output을 쓰는 CPU 실험으로 VLM의 시각 능력이 향상됐다고 주장하지 않는다.

**Expected Contribution·negative result:** 모델 생성과 parser 손실을 분리한 grounding 감사 세트. 차이가 없으면 검사 범위에서 parser가 원인이 아니라는 결론을 얻는다.

**Compute·novelty·4~8주:** cost **1/5**, GPU 불필요. 단일 parser 수정은 논문 기여가 약하다. 복수 VLM adapter, 실제 응답, 인간 검증으로 Answer–Region Gap 중 parser가 설명하는 범위를 추정해야 4~8주 진단 benchmark 후보가 된다.

## Q4. 계수 채점의 형식 관용성을 높일수록 모호한 답의 오수락도 늘어나는가?

**문제·Observation·왜 지금:** CountBenchQA는 raw string 일치에서 `parse_count`의 정수 비교로 바뀌었다. `acc`와 `exact_match` 키 모두 새 score를 받는다. helper는 마지막 `</think>` 뒤의 첫 정수를 우선하고 없으면 zero~twenty 수 단어를 찾는다. 따라서 metric 이름이 같아도 의미가 바뀌었다. [공식 commit·fixture](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/09920f2cfbb667d5278e18354e4ab9034c9806c0) · [helper 원문](https://github.com/EvolvingLMMs-Lab/lmms-eval/blob/09920f2cfbb667d5278e18354e4ab9034c9806c0/lmms_eval/tasks/countqa/utils.py)

**Gap → Diagnosis → Mechanism:** `3.`의 정답 복구와 여러 숫자가 있는 설명의 의도 추출은 다르다. 계수 정확도 상승이 perceptual gain인지 parser 관용성인지 분해하지 않으면 작은 객체 계수 연구도 혼동될 수 있다.

**Hypothesis·최소 개입:** 단일 수 답에서는 새 parser가 형식 오거절을 줄이지만, 복수 숫자·부정·자기 수정에서는 첫 정수 정책이 인간 최종 의도와 어긋날 수 있다. 방향과 빈도는 미측정이다.

**MVP·baseline·dataset·ablation:** CountBenchQA test의 동일 sample ID·정답·저장 raw response를 parent `ec8c326c56b123be8139bbfd53ac492ab71eb02c`와 수정 commit으로 재채점한다. 저장 응답이 없으면 먼저 합성 fixture만 검사한다. 마침표, 수 단어, “처음 2라고 생각했지만 최종 3”, 여러 category 수, think tag를 층화한다. 인간 최종 의도와 모호성을 정답을 가린 상태로 감사한다. 엄격 단일 정수 parser도 대조군으로 둔다.

**Metric·GO/KILL:** 전체 요청 기준 accuracy, parse coverage, 인간 의도 대비 오수락·오거절, old/new 전환표를 보고한다. 모호한 응답은 coverage에 남기고 임의 정답을 부여하지 않는다. 형식 복구와 의미 오류를 분리할 수 있으면 GO. 실제 저장 응답에서 차이가 없으면 합성 취약성을 실제 점수 문제로 확대하지 않는다.

**Expected Contribution·negative result:** counting의 perception·format·scoring 실패 분해와 metric 정의 추적. 순위가 유지되는 결과도 기존 결론의 견고성 근거가 된다. size annotation 없이 tiny-object 능력 변화라고 부르지 않는다.

**Compute·novelty·4~8주:** CPU 재채점 cost **1/5**. 파서 민감성은 알려진 주제다. 복수 모델·계수 benchmark에서 사람 감사와 결론 변화까지 확보하면 4~8주 평가 연구 후보이며 fixture만 있으면 재현 노트가 적합하다.

## Q5. 영상 구간 제한의 효과는 바깥 단서 차단인가, 같은 frame budget의 증거 밀도 증가인가?

**문제·Observation·왜 지금:** `8e07e58`은 시작·종료 시각을 chat/Gemini로 전달하고 Phi-4가 지정 구간 안에서 frame을 샘플링하도록 바꿨다. helper는 경계를 frame index로 바꾸고 `linspace`로 선택한다. 짧은 구간에서는 같은 index가 반복될 수 있다. [공식 commit·구현·테스트](https://github.com/EvolvingLMMs-Lab/lmms-eval/commit/8e07e581a8d967990b22fe1c13428e99d5173156)

**Gap → Diagnosis → Mechanism:** 구간 수정은 보는 증거 범위와 관련 frame 밀도를 동시에 바꾼다. accuracy 변화만으로 temporal reasoning 개선인지 외부 shortcut 제거인지 알 수 없다. Gemini mock metadata 테스트는 실제 서비스 관측 범위의 증명이 아니다.

**Hypothesis·최소 개입:** 구간 내 timestamp를 고정한 뒤 바깥 단서 유무만 바꾸면 shortcut 의존성을, 바깥 단서 없이 구간 내 고유 frame 수를 바꾸면 증거 밀도의 영향을 나눠 추정할 수 있다.

**MVP·baseline·dataset·ablation:** parent `7d932d24561dcee6c34d5abec267401b0d1bd21b`와 수정 commit의 CPU frame selection부터 검사한다. 색·사건 순서가 명확한 CFR 합성 영상에 질문 구간과 구간 밖 정답 암시를 분리한다. 전체 영상/구간 입력, 외부 단서 있음/없음, 고유 frame 수 조건을 교차하되 총 token·해상도·반복 frame 수를 기록한다. 실제 구간 annotation이 있는 video VQA는 이후 revision을 고정해 확장한다.
