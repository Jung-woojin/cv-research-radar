## 진단 → 가설 → 최소 실험

### 1. 원격 누락 오탐

- **진단 [사실]**: 로컬 CV/AI Tool clone의 최신 기준은 2026-10-22이지만 GitHub API에는 10월 23~27일 파일이 존재한다.
- **가설 [추론]**: 직접 파일 API 저장 이후 로컬 clone을 동기화하지 않아, health script의 로컬 파일 검사가 원격 성공 ledger와 충돌한다.
- **최소 실험 [수행 결과]**: 최근 19개 후보 경로를 GitHub contents API로 조회했다. 18개는 본문과 blob SHA를 반환했고, 10월 26일 CV brief만 404였다. 로컬 missing을 그대로 원격 missing으로 간주할 수 없다는 가설과 일치한다.
- **측정 가능한 개선 기준**: `(ledger success && remote exists)`이면 `missing` 대신 `local_stale`로 분류하고, 실제 404만 recovery queue에 넣는다.

### 2. CLI audit network timeout

- **진단 [사실]**: `github_audit.py`는 repository·commit·workflow·legacy trigger 조회를 모두 network unavailable 또는 timeout으로 반환했다.
- **가설 [추론]**: 저장소 장애가 아니라 해당 스크립트가 사용하는 전송 경로나 인증 환경의 장애다.
- **최소 실험 [수행 결과]**: 같은 실행에서 GitHub 앱으로 파일 29개, workflow 2개, commit 8개를 조회했고 응답을 받았다.
- **측정 가능한 개선 기준**: audit 결과에 transport를 기록하고, script 실패 시 읽기 전용 GitHub API probe 3개 중 2개 이상 성공하면 `repository outage` 대신 `audit transport degraded`로 분류한다.

### 3. Paper Ideas ledger SHA 불일치

- **진단 [사실]**: 10월 26일 ledger의 file SHA는 `fe2d3865...`지만 현재 원격 SHA는 `f3a28738...`이다.
- **GitHub 기록 [사실]**: 최초 저장 commit `3ddfe4ec...` 뒤에 후속 동기화 commit `37b94836...`가 같은 파일을 갱신했다.
- **해석 [추론]**: 원격 손실이 아니라 ledger 작성 뒤 파일이 수정된 경우다.
- **최소 실험**: ledger 검증 시 파일 경로의 commit history를 함께 조회해 `missing`, `mutated_after_ledger`, `unchanged`를 분리한다.
- **측정 가능한 개선 기준**: SHA 불일치가 발생해도 경로 history에 ledger commit과 후속 commit이 모두 있으면 누락으로 세지 않는다.
