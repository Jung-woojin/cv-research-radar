## 진단 → 가설 → 최소 실험

**진단(사실).** 로컬 health script는 local clone의 파일 존재 여부로 missing을 계산한다. 이 clone은 직접 GitHub 파일 API로 확인된 10월 29일 원격 파일을 반영하지 못하고 있으며, REST 기반 `github_audit.py`도 timeout이 났다.

**가설.** 원격 파일 API를 health script의 우선 검증 경로로 두고, local clone 상태를 보조 진단으로 격하하면 stale clone이 만든 false-positive missing 경고를 줄일 수 있다.

**최소 실험.** 다음 health check에서 5개 대표 path에 대해 (a) local file state, (b) GitHub file API blob SHA, (c) ledger의 file SHA를 비교한다. `remote==ledger`이고 local만 missing이면 `local_stale`로 분류하고 recovery queue에 새 누락으로 넣지 않는다.

**GO.** 원격 SHA와 ledger SHA가 일치하는 보고서를 missing으로 재등록하지 않고, 실제 원격 404만 복구 대상으로 남긴다.

**KILL.** 파일 API와 ledger SHA가 불일치하거나 branch가 main이 아니면 `local_stale` 분류를 중단하고 원격 충돌 장애로 승격한다.
