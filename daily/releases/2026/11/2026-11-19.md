## 1. Pi4 — 새 code 공개와 좌표·시각화 계약

**공개 사실.** [Initial release commit](https://github.com/yyfz/Pi4/commit/569678f66e468815d65985cb5639cf82095a0ea8)은 11월 18일 03:24:43 KST다. 현재 code revision은 `32dfbea9ce6268ea17446208a804710df9475c32`이며 이후 변경은 arXiv 링크 추가다. [논문 v1](https://arxiv.org/abs/2611.23144)은 17일 제출됐다. [Hub history](https://huggingface.co/yyfz233/Pi4/commits/main)의 weight 공개 commit은 `7aa80064f78ed01e7bac0fe32400ef946e4477af`, 12일 12:29:10 UTC다. 현재 Hub revision `59f307317fb630c9c5a5aa635038d98ed106aaf5`의 최근 변경은 README다.

**공개 범위·조건.** `model.safetensors`는 public·ungated다. original code와 weights는 CC BY-NC 4.0이며 third-party notice가 별도다. 공식 배포는 fixed inference model이지 training framework가 아니다. [GameRealm 관련 open Issue #1](https://github.com/yyfz/Pi4/issues/1)은 Hub 호스팅 제안이며, 데이터 미공개나 재현 실패의 증거로 해석하지 않는다. 이번에는 dataset manifest·checksum·전체 학습 데이터 접근성을 검증하지 않았다.

[고정 inference guide](https://github.com/yyfz/Pi4/blob/32dfbea9ce6268ea17446208a804710df9475c32/docs/inference.md)는 Linux x86-64, Python 3.11, BF16 NVIDIA GPU, CUDA 12.6 driver, torch 2.12.1·Triton 3.7.1을 안내한다. FlexGEMM pin은 `b2fadb29d41846c7981ade6801ffc689fae119cf`이며 Git·C compiler가 필요하다. 문서의 A800 측정은 tracking·512×288·25 frames에서 peak 4.13GiB, 150 frames에서 12.03GiB다. 이는 저자 측정으로 다른 GPU의 최소 VRAM 보장이 아니다. weight checksum·attestation 검증은 미실행이다.

**주장과 artifact 간극.** 저자는 약 0.5B 모델로 geometry·motion을 함께 처리하고 thousands-of-images 입력에 일반화한다고 주장한다. 공개 output 계약은 `local_points`와 camera translation이 native scale이고 `tracks_3d`는 이미 metric world 좌표임을 명시한다. 후자는 target-view pointmap을 lift한 결과다. `dynamic_mask`는 순간 속도가 아니라 sequence 안에서 움직이는 물체의 의미를 가진다. viewer export는 confidence·mask·query sampling을 적용하므로 raw prediction 평가와 같지 않다.

**진단 → 가설 → 최소 실험, 10~30분 계획.** 실패 원인이 representation보다 scale 중복 적용·visibility 처리·export filtering일 수 있다는 가설이다. 준비된 환경에서 25-frame clip·동일 weight revision·query 0을 고정하고 raw tensor와 export를 대조한다. `m*(R@P+t)`와 world track의 좌표 계약, NaN·visibility coverage, geometry/tracking confidence 구분을 확인한다. query 1과 비교할 때 mask의 query 독립성도 검사한다. seed·input·precision·batch=1을 고정하며 TTA는 사용하지 않는다.

**GO/KILL.** 좌표·coverage audit 후 tracking 평가로 GO. viewer의 보기 좋은 subset을 dense 정확도로 쓰거나 150-frame 결과를 full 750-frame 재현으로 부르는 것은 KILL이다. 해상도·frame count·hardware·evaluator가 다른 비교는 **not strictly apples-to-apples**다.

## 2. FastFrames — 공개 evaluator가 드러내는 지연 측정의 경계

**공개 사실.** [Public release code](https://github.com/apple-aiml-research/ml-fastframes/commit/a655ef0e933697233fe87bc2fe09b13dfb9efb11)는 11월 18일 06:37:06 KST다. 현재 code revision은 `a65c59240e01cf1de86197fa771ca09b38cf592a`다. [FastFrames-S history](https://huggingface.co/apple/FastFrames-S/commits/main)는 `aa099efcedf1b65447106bf9004cde75821f7387`, [L history](https://huggingface.co/apple/FastFrames-L/commits/main)는 `18f30cbdd91943baa274e4237dd09b6d19e58ca9`의 18일 05:29 UTC Public release를 반환했다. repo 생성일 16일을 다운로드 가능한 최초 weight 공개 시각으로 단정하지 않는다. [논문](https://arxiv.org/abs/2611.23226)은 17일 제출됐다.

**artifact·license.** S snapshot에는 pixel decoder·KV refiner가 있으며 Causal Forcing++ generator·Wan text encoder 등은 [설치 안내](https://github.com/apple-aiml-research/ml-fastframes/blob/a65c59240e01cf1de86197fa771ca09b38cf592a/docs/installation.md)에 따라 별도 확보해야 한다. L에는 final DiT·decoder·refiner와 학습 중간 checkpoint들이 있다. 두 snapshot에 `SHA256SUMS`가 있으나 다운로드 검산·attestation 검증은 하지 않았다. code는 Apple Sample Code License, model은 Apple AMLR로 비상업 연구 목적 조건이 있고, LingBot 부분은 upstream CC BY-NC-SA 4.0이다. 별도 구성요소의 조건을 하나의 code license로 합치지 않는다.

**설치·자원·활동.** Linux x86-64·NVIDIA·CUDA 12.8 driver, `uv sync`의 Python 3.10·torch 2.9.1+cu128·torchvision 0.24.1+cu128가 기본이다. VBench scorer는 별도 pinned 환경이다. 저자의 latency hardware는 B200이며 8-GPU 경로는 NVSwitch가 필요하다. [LingBot guide](https://github.com/apple-aiml-research/ml-fastframes/blob/a65c59240e01cf1de86197fa771ca09b38cf592a/docs/lingbot.md)의 one-GPU demo peak는 44.8GiB다. 이를 T2V-S 공통 minimum으로 쓰지 않는다. T2V 각 구성의 최소 VRAM은 이번 조사에서 확정하지 않았다. 최근 commit은 이 저장소의 Issues·PR이 비활성임을 명시한다. open issue 0을 안정성 증거로 쓰지 않는다.

**논문 주장과 측정 계약.** 저자는 S 36ms/단일 B200, L 45ms/8 B200를 주장한다. [공개 profiling protocol](https://github.com/apple-aiml-research/ml-fastframes/blob/a65c59240e01cf1de86197fa771ca09b38cf592a/docs/inference.md)은 batch 1·BF16/TF32·full 21-latent-frame cache·warm-up 뒤 component median 합을 사용한다. text encoding·host transfer·display를 제외하고 latent frame 하나가 RGB 4장을 만든다. 따라서 논문의 per-frame 표현과 실제 timing unit을 함께 기록해야 하며 36ms를 클릭부터 화면 표시까지의 지연으로 읽으면 안 된다.

VBench도 flickering은 RAFT로 선택한 static clips, 다른 차원은 raw videos로 평가하는 프로토콜이다. 공개 도구가 있다는 사실과 전체 표의 독립 재현은 다르다. training data 전체 공개 여부는 이번에 검증하지 않았다.

**진단 → 가설 → 최소 실험, 10~30분 계획.** 병목이 generator representation보다 decoder·KV write에 있다는 저자 가설을 분리한다. 환경·weights가 이미 준비된 경우 같은 latent·prompt·seed·shape에서 decoder만 VAE/pixel로 바꾸고 latent hash·출력·decode 시간을 보존한다. 이어 full-cache warm component 합과 cold startup·text encoding 포함 wall-clock을 별도로 기록한다. 전체 VBench corpus 재생성은 smoke test에 넣지 않는다.

**GO/KILL.** 먼저 revision·checksum manifest·component 조합 audit로 GO. 환경이 없으면 10~30분 안에 설치와 전체 재현까지 가능하다고 약속하지 않는다. GPU 수·timing unit·cache 상태가 다른 비교는 **not strictly apples-to-apples**이며, steady-state 숫자로 end-to-end 응답성을 증명하는 것은 KILL이다.

## 3. Supervision 0.32.0 — semantic class mask와 instance detection의 경계

**정확한 release.** [0.32.0](https://github.com/roboflow/supervision/releases/tag/0.32.0)은 11월 19일 05:31:46 KST 발행됐고 tag는 commit `40553abe4a23e23a1134f8cbaa5c76547ce5d491`을 직접 가리킨다. 이전 0.31.7 보고와 다른 실제 신규 tag다. MIT·Python ≥3.10이며 pin 후보는 `supervision==0.32.0`이다. NumPy ≥1.21.2·SciPy ≥1.10 등 범위 의존성이 있어 package pin 하나는 환경 lock이 아니다. 새 model weight·학습 dataset은 없다. CPU fixture는 GPU/VRAM이 필요 없다.

wheel의 API digest는 `sha256:8adf6f4fcf2fa960b7ae1d552aad3272e1c0e0865041b7113d0f18e20e17033d`다. 실제 다운로드·checksum 대조·attestation 검증은 미실행이다.

**코드 확인과 claim gap.** [고정 core.py](https://github.com/roboflow/supervision/blob/40553abe4a23e23a1134f8cbaa5c76547ce5d491/src/supervision/detection/core.py)의 `from_semantic_segmentation`은 클래스별 모든 pixel을 하나의 mask·tight box로 묶고 기본 background ID 0을 제외한다. `background_id=None`은 모든 클래스를 보존한다. 두 개의 분리된 물체가 같은 클래스면 detection 둘이 된다는 계약이 아니다. 이를 instance AP·물체 개수에 바로 넣으면 평가 대상 자체가 달라진다.

[PR #2898](https://github.com/roboflow/supervision/pull/2898)은 13일, [#2915](https://github.com/roboflow/supervision/pull/2915)는 16일 merge됐다. 신규 사건은 오늘 package 배포다. release는 zone dwell·WBF·YOLO pose dataset I/O와 API 제거도 포함한다. WBF score는 그룹 평균이므로 기존 NMS confidence threshold를 그대로 재사용하면 operating point가 달라질 수 있다.

조회 당시 [#3027](https://github.com/roboflow/supervision/pull/3027)·[#3028](https://github.com/roboflow/supervision/pull/3028) 등 후속 open PR이 있었다. 제목만으로 수정 완료·현재 tag 반영을 주장하지 않는다. source 경로의 첫 조회는 404였으며 tree에서 `src/` 경로를 확인해 재조회했다.

**진단 → 가설 → 최소 실험, 10~30분 CPU 계획.** 성능 저하처럼 보이는 변화가 representation 손실보다 adapter의 클래스 병합·배경 제외·score 집계 때문이라는 가설이다. 작은 정수 map에 같은 클래스의 떨어진 두 island, 유효 class 0, 빈 map을 넣는다. 기본값/`background_id=None`, dense/compact 경로의 class ID·pixel union·box·confidence를 비교한다. 고정 prediction으로 WBF/NMS도 나누되 model gain으로 해석하지 않는다. 설치된 환경이 없으면 이 실행에서는 계획만 보존한다.

**GO/KILL.** semantic output 계약을 만족하면 adapter migration으로 GO. instance 수를 보존한다고 가정하거나 evaluator·postprocessing이 다른 점수를 모델 향상으로 비교하는 것은 KILL이다. backbone·data·split·resolution·pretraining은 고정 prediction fixture에는 해당 없으며 실제 model 비교에서는 동일하게 고정해야 한다.
