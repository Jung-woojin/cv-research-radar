## ReuScope
- **출처:** [arXiv](https://arxiv.org/abs/2610.41835), 2026-10-30 v1.
- **사실:** public train–validation 경계의 byte-identical file과 Kvasir-Capsule recording 41개의 cross-partition 기여를 보고한다.
- **저자 주장:** source row/near-match 제거 시 public validation balanced accuracy 82.5%→61.2%, 다른 source validation에서는 +1.38 point였다.
- **진단/가설:** image random split은 source/video/patient identity overlap을 숨긴다.
- **최소 audit:** exact hash→embedding near-duplicate→recording/patient group overlap matrix, random/source-held-out/near-duplicate-removed 5-seed 비교.
- **한계:** patient identifier 부재로 unique shared patient 수는 미확인. 라이선스·상업 사용도 이번 실행에서 미확인.
- **GO/KILL:** source-held-out gain 유지면 GO; random split에서만 gain이면 provenance reporting 우선.

## PanoVideoBench / PanoVideoCoT
- **출처:** [arXiv](https://arxiv.org/abs/2610.42082), 2026-10-30 v1.
- **사실:** 5 범주·15 question type의 수동 annotation 1,000문항과 target search/panoramic capability diagnostic annotation을 제안한다.
- **저자 주장:** 11개 모델의 cross-view tracking/sphere-time evidence integration이 약점이며 PanoVideoCoT는 13,465 QA-CoT pair다.
- **진단/가설:** answer-only label은 실제 evidence 기반 성공을 구분하지 못한다.
- **최소 audit:** answer, target view, evidence timestamp를 50 case에서 별도 채점하고 view order/frame density consistency를 측정한다.
- **한계:** 360° taxonomy의 perspective video 호환성, 라이선스·공개 artifact 조건은 미확인.
- **GO/KILL:** evidence localization이 먼저 붕괴하면 evidence-supervised evaluator GO; 완전 동조면 별도 annotation 효용 재검토.

## System One Bench
- **출처:** [official repository](https://github.com/alilibx/system-one-bench), 2026-11-01 갱신.
- **사실:** frozen data와 identical request에서 accuracy, calibration, latency, cost를 비교하며 16 text·6 image dataset을 표기한다.
- **진단/가설:** provider version/request/data revision 변경은 leaderboard 비교 대상을 바꾼다.
- **최소 audit:** 동일 20 image case/request를 2회 실행해 success, calibration, latency, cost, artifact hash를 기록한다.
- **한계:** image task·class/geographic/sensor bias 및 원 데이터 라이선스는 이번 실행에서 미확인.
- **GO/KILL:** input/revision 추적과 반복 안정성이 있으면 smoke test GO, 아니면 migration 근거로 사용하지 않는다.
