## 4. 불균형 미세조정이 희귀 클래스 지식을 가린다

- **실패 조건:** class-imbalanced 데이터로 VLM을 미세조정한 뒤 학습 때 쓴 descriptive prompt를 그대로 추론에 재사용하면 희귀 클래스 recall이 zero-shot보다도 낮아질 수 있다.
- **모델·데이터·설정:** 저자는 다양한 VLM과 6개 데이터셋에서 matched-prompt와 다른 descriptive prompt를 교차 비교했다.
- **저자 인정:** cross-prompt inference가 희귀 클래스 recall을 일관되게 회복했지만 frequent-class recall과 trade-off가 있었고, imbalance와 visual confusability가 큰 조건에서만 효과가 강했다고 명시했다.
- **커뮤니티 재현:** 공개 검색에서 코드 저장소나 독립 재현은 확인되지 않았다.
- **재현 근거:** 6개 데이터셋의 반복 관찰과 TuCo decomposition이 내부 근거다. 절대 개선폭은 초록만으로 일반화하지 않았다.
- **의심 원인(해석):** 지식 소실보다 finetuning-induced computation에 대한 과의존이 access path를 좁힌다.
- **기존 주장과 충돌:** train-eval prompt를 맞추는 것이 distribution consistency를 높인다는 통상 관행이 희귀 클래스에서는 오히려 penalty가 될 수 있다.
- **후속 최소 실험:** 10:1 불균형 소형 분류셋에서 zero-shot·matched·cross-prompt 세 조건의 macro recall과 head/tail recall을 측정하고, frequent-class 손실을 함께 보고한다.
- **평가:** 심각도 **4/5** · 재현 신뢰도 **4/5** · 연구 아이디어 가치 **5/5**
- **출처:** [arXiv 2610.21470](https://arxiv.org/abs/2610.21470)

## 5. 시각 RL은 추론보다 지각 오류를 덜 고친다

- **실패 조건:** benchmark의 남은 오류가 reasoning보다 perception headroom에 많이 걸려 있을 때, 일반적인 RL 개선폭이 작아진다.
- **모델·데이터·설정:** PARA 진단은 4개 VLM과 17개 multimodal benchmark에서 더 정확한 시각 정보와 더 강한 reasoner를 각각 주입해 회복 가능한 오류를 나눴다.
- **저자 인정:** 지각 headroom이 클수록 RL gain이 작고, reasoning이 회복 가능 오류를 더 많이 설명할수록 gain이 커졌다고 보고했다. reward/token 신호는 visual attention에 간접적으로만 작용한다고 분석했다.
- **커뮤니티 재현:** 독립 재현과 공개 코드 링크는 수집 시점에 확인되지 않았다.
- **재현 근거:** 다수 모델·벤치마크 비교와 GRAD의 2개 model scale·7개 benchmark 개선이 저자 내부 근거다.
- **의심 원인(해석):** 최종 정답 보상은 잘못 본 위치를 직접 교정하지 못해, 모델이 reasoning trace만 다듬고 visual evidence acquisition은 그대로 둔다.
- **기존 주장과 충돌:** reasoning-oriented RL을 늘리면 시각 과제도 비슷하게 개선된다는 스케일링 가정과 충돌한다.
- **후속 최소 실험:** 동일 VLM에서 원본 이미지와 oracle crop을 각각 넣고 RL 전후 정확도를 비교해 `(oracle 회복 오류)/(전체 오류)`와 RL gain의 상관을 측정한다.
- **평가:** 심각도 **4/5** · 재현 신뢰도 **4/5** · 연구 아이디어 가치 **5/5**

## 6. On-policy distillation은 교사의 미완료 습관까지 상속한다

- **실패 조건:** student-generated trajectory에서 teacher가 안정적으로 답을 완성하지 못하는 시각 추론 과제에 OPD를 적용할 때 성능이 하락한다.
- **모델·데이터·설정:** 저자는 ChartQA와 Geometry3K에서 OPD와 filtered SFT를 데이터 예산별로 통제 비교했다.
- **저자 인정:** teacher completion이 99%인 ChartQA에서는 10% 데이터 OPD가 full-data SFT와 1.4점 차이였지만, teacher가 22% 미완료한 Geometry3K에서는 OPD가 SFT보다 7.9점 낮았고 격차 대부분이 미완료 응답으로 설명됐다고 보고했다.
- **커뮤니티 재현:** 공개 검색에서 독립 재현이나 공식 코드 링크를 확인하지 못했다.
- **재현 근거:** 두 과제의 대조 설정은 teacher reliability와 student failure의 연결을 보여주지만, 과제 수가 적어 외삽은 제한적이다.
- **의심 원인(해석):** OPD는 student가 자주 방문하는 어려운 상태에서 teacher의 정책 결함을 더 자주 노출하고 모방한다.
- **기존 주장과 충돌:** student trajectory를 따라가는 supervision이 항상 data efficiency를 높인다는 주장에 teacher reliability라는 선행 조건이 필요하다.
- **후속 최소 실험:** teacher completion rate를 100/90/80/70%로 인위적으로 마스킹하고, OPD와 filtered SFT의 accuracy·completion rate 곡선이 어디서 교차하는지 측정한다.
- **평가:** 심각도 **4/5** · 재현 신뢰도 **4/5** · 연구 아이디어 가치 **4/5**
- **출처:** [arXiv 2610.20989](https://arxiv.org/abs/2610.20989)

## 오늘의 실패 패턴 3개

1. **정답 지표가 원인 오류를 숨긴다.** 의료 ViT의 annotation-reading head처럼 출력 변화가 작아도 내부 근거는 잘못될 수 있다.
2. **개입이 실패를 제거하지 않고 이동시킨다.** 프롬프트 완화는 default label이나 VALID/INVALID threshold를 다른 쪽으로 옮길 수 있다.
3. **후처리가 상류 병목을 상속한다.** RL은 지각 병목을, OPD는 teacher 미완료를 그대로 이어받는다.

## 논문 아이디어로 연결 가능한 빈틈

- **Evidence-path validation:** 정확도와 함께 근거 영역 attention, counterfactual edit 민감도, prediction entropy를 묶는 평가 프로토콜.
- **Prompt-accessible knowledge map:** 미세조정 후 사라진 것처럼 보이는 지식을 prompt graph로 탐색하고 head/tail class별 접근성을 계량하는 방법.
- **Failure-preserving distillation:** teacher의 불확실·미완료 상태를 무시하지 않고 abstention 또는 재질문 supervision으로 변환하는 OPD.
- **Authority-style robustness:** 동일 사실을 서로 다른 typography·layout·seal·citation style로 렌더링해 시각적 권위 편향을 분리하는 benchmark.

## 직접 재현해볼 최소 실험

1. **2시간 — prompt collapse audit:** 공개 Arabic calligraphy runner로 모델 1개, 이미지 100장, 프롬프트 3개를 돌려 라벨 점유율·entropy·macro-F1을 기록한다.
2. **반나절 — shortcut audit:** 흉부 X-ray 50장의 주석을 유지/삭제/이동하고 정확도와 lung-attention ratio를 함께 비교한다.
3. **반나절 — rare-class access:** 10:1 불균형 데이터에서 matched/cross prompt의 head-tail recall trade-off를 측정한다.
4. **하루 — teacher reliability sweep:** synthetic completion masking으로 OPD 성능이 filtered SFT 아래로 내려가는 임계점을 찾는다.

이번 보고서의 핵심은 “낮은 성능” 자체가 아니라, **올바른 신호를 보고 있는지**, **개입이 오류를 줄였는지 아니면 위치만 바꿨는지**, **상류 실패가 후속 학습에 복제되는지**를 분리하는 데 있다. 다음 실행에서는 공개 코드가 있는 항목의 독립 재현 또는 issue·commit 단위 후속 신호가 생겼는지 우선 확인한다.
