## 1. PARA/GRAD — VLM benchmark 점수를 perception headroom과 reasoning headroom으로 분해

### 무엇이 실제로 바뀌었나

기존 VLM 평가가 정답률과 RL 전후 차이만 보고했다면, Perception and Reasoning Attribution(PARA)은 현재 오류가 **더 정확한 시각 정보**를 받았을 때 회복되는지, **더 강한 reasoner**를 붙였을 때 회복되는지로 model–benchmark pair의 남은 headroom을 나눈다.

### 확인된 사실

공식 논문은 4개 VLM과 17개 multimodal benchmark에서 PARA를 적용한다. 같은 benchmark라도 모델마다 perception과 reasoning 병목 비율이 다르다고 보고한다. 후속 GRAD는 그룹 내 best rollout의 visual attention을 약한 rollout에 직접 distill하며 2개 model scale과 7개 benchmark에서 평가됐다. [논문](https://arxiv.org/abs/2610.21380)

### 저자 주장

RL 이득은 perceptual headroom이 클수록 작고 reasoning이 회복 가능한 오류의 큰 부분을 차지할수록 커진다고 주장한다. 기존 reward/token signal은 visual attention에 간접적으로만 영향을 주므로 attention-level supervision이 보완책이라는 설명이다.

### 같은 조건 비교인가

PARA의 숫자는 oracle visual information과 stronger reasoner의 정의에 의존한다. 서로 다른 benchmark의 attribution 비율이나 서로 다른 model의 oracle을 직접 순위화하는 것은 `not strictly apples-to-apples`다. GRAD와 일반 RL을 비교할 때도 backbone, rollout 수, reward, image resolution을 맞춰야 한다.

### 진단 → 가설 → 최소 실험

- **진단:** VLM 성능이 낮을 때 더 긴 CoT나 RL을 바로 적용하면 perception bottleneck을 reasoning 문제로 오진할 수 있다.
- **가설:** 작은 객체·해무 영상에서는 oracle crop이 stronger reasoner보다 더 많은 오류를 회복한다.
- **최소 실험:** 200개 항만 VQA 문항에 baseline, oracle crop, gold object list, stronger text reasoner를 각각 제공한다. recovered-error overlap을 계산한다.
- **GO/KILL:** oracle crop 회복률이 stronger reasoner보다 10%p 이상 높으면 perception/evidence 개선을 우선한다. 차이가 없으면 별도 memory·reasoning 실험으로 이동한다.

### 판정

새 leaderboard라기보다 **benchmark 해석 protocol의 변화**다. “RL로 몇 점 올랐는가”보다 “그 점수에서 어떤 오류군이 회복됐는가”를 요구한다는 점에서 연구자가 바로 따라갈 가치가 높다.

## 2. Cross-Prompt Inference — long-tail 평가에서 train–eval prompt 상호작용을 독립 변수로 승격

### 무엇이 실제로 바뀌었나

불균형 데이터로 VLM을 fine-tune한 뒤 학습 때 쓴 descriptive prompt를 inference에도 그대로 사용하는 관행이 희귀 클래스 recall을 오히려 낮출 수 있다는 matched-prompt penalty가 제시됐다. 평가 protocol에 동일 prompt 1개가 아니라 matched, cross-descriptive, non-descriptive control이 들어간다.

### 확인된 사실

논문은 다양한 VLM과 6개 dataset에서 cross-prompt inference가 rare-class recall을 일관되게 회복하지만 frequent-class recall과의 trade-off가 모델·데이터마다 다르다고 보고한다. 효과는 imbalance와 visual confusability가 강해 rare-class suppression이 클 때 강하고, suppression이 없으면 약하거나 나타나지 않는다. Tuning Contribution(TuCo) 분해는 다른 inference prompt가 fine-tuning-induced computation 의존도를 낮추고 pretrained component 쪽으로 이동시킨다고 분석한다. [논문](https://arxiv.org/abs/2610.21470)

### 저자 주장

희귀 클래스 지식이 fine-tuning 중 완전히 사라진 것이 아니라, 학습 prompt와 결합된 계산 경로에 의해 접근이 억제되며 다른 descriptive prompt가 그 지식을 다시 드러낼 수 있다고 주장한다.

### 같은 조건 비교인가

prompt만 바꾼 실험은 같은 checkpoint·dataset·decoder 조건에서 직접 비교할 수 있다. 그러나 모델별 tokenizer, prompt template, class prior가 다르면 cross-model 수치는 직접 비교할 수 없다. rare recall만 높고 frequent recall이나 calibration이 무너지면 전체 개선으로 볼 수 없다.

### 진단 → 가설 → 최소 실험

- **진단:** long-tail fine-tuning 성능 하락을 catastrophic forgetting으로 단정하면 recoverable knowledge와 실제 삭제를 구분하지 못한다.
- **가설:** 해양 데이터의 드문 buoy·small craft 클래스도 matched prompt 대신 의미가 다른 descriptive prompt ensemble로 recall을 회복한다.
- **최소 실험:** 같은 fine-tuned checkpoint에서 matched prompt, paraphrase 5개, non-descriptive label prompt, zero-shot checkpoint를 비교한다.
- **측정:** rare/many-shot recall, macro-F1, ECE, false alarms per image, prompt별 variance.
- **GO/KILL:** rare recall 5%p 이상 회복, frequent recall 하락 1%p 이내면 selective prompt routing으로 확장한다.

### 판정

단순 prompt engineering이 아니라 **evaluation protocol leakage와 forgetting 진단의 변화**다. long-tail benchmark에는 prompt robustness curve와 zero-shot reference를 함께 제시해야 한다.

## 3. MYOPIA — 해석 가능한 tree reasoning이 12/12 조건에서 zero-shot보다 낮은 benchmark

### 무엇이 실제로 바뀌었나

MYOPIA는 VLM classification을 root-to-leaf 질문으로 설명 가능한 decision tree에 넣고, 최종 accuracy뿐 아니라 node accuracy, early exclusion, label knowledge–image grounding gap, answer extraction loss를 분해한다.

### 확인된 사실

공식 논문은 GTSRB, MNIST, CIFAR-10, MSCOCO용 4개 human-refined tree와 GPT-4o, Qwen-VL Max, LLaMA-3.2 11B Vision을 조합한 12개 dataset–model pair를 평가했다. tree traversal은 12개 모두에서 zero-shot보다 낮았고 paired bootstrap도 일관되게 zero-shot을 지지했다. label–image accuracy gap은 세 모델에서 평균 9.5, 13.8, 12.6점으로 보고됐다. [논문](https://arxiv.org/abs/2610.21573)

공식 [GitHub](https://github.com/islammesabah/VLM_Classification)은 frozen paper archive, 4개 result database, derived CSV, table regeneration script, tree path error analysis를 공개한다. README는 90% 미만 coverage cell을 paper table에서 제외하고, GTSRB legacy row를 전용 view로 deduplicate하지 않으면 denominator가 901에서 최대 915로 부풀 수 있다고 명시한다.

### 저자 주장

모델은 class attribute를 언어로 회상하는 능력보다 같은 attribute를 실제 image에서 grounding하는 능력이 낮다. greedy non-backtracking tree에서는 early node의 한 번의 오류가 correct class를 영구 배제한다.

### 같은 조건 비교인가

zero-shot과 tree는 같은 underlying model·dataset을 쓰지만 API call 수, prompt 길이, cumulative context가 다르다. accuracy만 같아도 비용은 같지 않다. 공개 database를 재분석할 때 archive와 development copy의 LLaMA model name, coverage filter, GTSRB deduplication을 동일하게 적용해야 한다.

### 진단 → 가설 → 최소 실험

- **진단:** 설명 가능성을 위한 greedy tree가 perception error를 구조적으로 증폭한다.
- **가설:** top-k branch 유지와 한 번의 backtracking을 허용하면 해석 가능성을 유지하면서 early exclusion을 줄인다.
- **최소 실험:** 공개 GTSRB subset에서 greedy-1, beam-2, confidence-triggered backtrack, direct zero-shot을 비교한다.
- **측정:** accuracy, early-exclusion rate, node ECE, calls/image, cost, latency.
- **GO/KILL:** beam/backtrack이 zero-shot gap의 절반 이상을 회복하고 호출 수가 2배 이내면 후속 연구 가치가 있다.

### 판정

“해석 가능한 과정이 정확도도 높일 것”이라는 leaderboard 가정을 깨는 강한 negative benchmark다. 특히 **재현 artifact가 denominator와 coverage 규칙까지 공개**했다는 점이 유용하다.

## 4. Spurious Attention Heads — 출력 성능이 그대로여도 annotation-reading shortcut은 존재

### 무엇이 실제로 바뀌었나

정답률·AUC 중심 평가에 causal mechanistic audit가 추가됐다. 특정 attention head가 폐 모양 대신 모서리 annotation text를 읽는지 확인하고, inpainting과 head ablation으로 원인을 검증한다.

### 확인된 사실

논문은 ViT-B/16의 L8H10이 200개 COVID-19 X-ray 중 62%에서 corner text에 집중했다고 보고한다. annotation 제거 뒤 영향을 받은 image에서 lung attention이 1.52배 증가했으며, NIH ChestX-ray14 79%, DeiT-Base 88%, ViT-L/16 80%에서도 유사 행동을 보고했다. full fine-tuning 뒤 spurious image의 98.4%가 그대로 남았다. single-head와 multi-head ablation의 output-level 검정은 각각 p=0.340, p=0.532로 유의하지 않았다고 보고한다. [논문](https://arxiv.org/abs/2610.21638)

### 저자 주장

annotation content가 shortcut을 인과적으로 유발하지만, 모델의 출력 점수만 보는 평가에서는 그 회로가 보이지 않는다고 주장한다.

### 같은 조건 비교인가

62%, 79%, 88%, 80%는 dataset와 architecture가 달라 직접적인 모델 순위가 아니다. attention 정의, affected-image selection, inpainting method가 결과에 영향을 준다. 임상적 유효성으로 확대 해석할 수 없으며 독립 재현 전의 mechanistic case study다.

### 진단 → 가설 → 최소 실험

- **진단:** clean test accuracy가 유지되더라도 모델이 camera overlay·timestamp·기관 mark를 shortcut으로 쓸 수 있다.
- **가설:** 해양 CCTV detector도 화면 모서리 timestamp와 camera ID를 fog/ship label의 proxy로 사용한다.
- **최소 실험:** overlay 원본, inpaint, 위치 이동, 내용 shuffle 4조건을 동일 checkpoint에서 평가하고 attention/gradient attribution과 output 변화를 함께 본다.
- **GO/KILL:** output 차이가 작아도 internal attribution이 overlay에 반복 집중하고 domain-shift split에서 성능이 무너지면 shortcut mitigation을 진행한다.

### 판정

benchmark가 output metric만으로 충분하지 않다는 신호다. domain shift가 중요한 의료·CCTV·remote sensing에서는 **artifact intervention set**이 필수 보조 평가가 되어야 한다.

## 5. FALCON — 평균 latency에서 deadline·tail latency로, proxy 인증과 full system은 분리

### 무엇이 실제로 바뀌었나

FALCON은 camera-based 3D occupancy를 AMD Kria KR260 FPGA에 배포하고, 평균 latency 대신 PL cycle bound, 100k-frame trace envelope, watchdog의 stale-output 표시를 포함한 layered deadline protocol을 제시한다.

### 확인된 사실

저자들은 board가 idle 4.3 W, inference 최대 6.6 W라고 보고한다. 세 차례 100k-frame run의 300k proxy frame 모두가 100 ms deadline + 최대 10.2 ms 안에 output을 냈다. 그러나 이 deadline run은 **full occupancy network가 아니라 frame당 ResNet-50 DPU inference 6회인 fixed-work proxy**다. full six-camera FlashOcc pipeline은 board에서 frame당 약 1.3초로 아직 10 Hz가 아니다. Occ3D-nuScenes validation mIoU는 29.88, 실행 불가능한 FP32 baseline의 92.8%라고 보고한다. [논문](https://arxiv.org/abs/2610.22143)

### 저자 주장

commodity accelerator의 평균 latency는 OS jitter·thermal throttling·contention 때문에 worst-case bound가 아니며, safety-critical system은 deadline violation과 stale output 정책까지 평가해야 한다고 주장한다.

### 같은 조건 비교인가

KR260, Jetson Orin, NVIDIA L4의 tail/median ratio는 hardware, runtime, workload mapping이 다르다. proxy 100 ms 결과와 full FlashOcc 1.3 s 결과는 서로 다른 endpoint다. mIoU 29.88과 FP32 baseline도 precision과 accelerator support가 다르므로 정확도 보존 비율이지 architecture superiority가 아니다.

### 진단 → 가설 → 최소 실험

- **진단:** 평균 30 FPS를 만족해도 P99/P100 latency가 위험 시점에서 deadline을 넘을 수 있다.
- **가설:** 해양 경보 pipeline의 tail은 detector보다 decode·resize·tracking synchronization에서 더 크게 발생한다.
- **최소 실험:** 100k-frame replay에서 decode, preprocess, inference, NMS, tracking을 각각 timestamping하고 P50/P95/P99/P100, deadline miss, stale-output age를 기록한다.
- **GO/KILL:** 실제 full pipeline이 설정 deadline을 99.99% 이상 만족하고 stale output이 명시적으로 감지될 때만 “real-time”으로 표기한다.

### 판정

하드웨어 benchmark의 좋은 정직성 사례다. 저자들이 proxy 인증과 full system 10 Hz 미달을 분명히 구분했으므로, headline latency만 인용하지 말고 endpoint 범위를 그대로 유지해야 한다.

## Apples-to-apples 체크표

| 항목 | 직접 비교 가능한 범위 | 직접 비교하면 안 되는 범위 | 현재 artifact 상태 |
|---|---|---|---|
| PARA/GRAD | 같은 model–benchmark, 동일 oracle·reasoner·rollout budget | 서로 다른 oracle 정의의 attribution 비율 | arXiv 원문 확인, 독립 재현 전 |
| Cross-Prompt | 같은 checkpoint·dataset·decoder에서 prompt만 변경 | 모델별 tokenizer·prior가 다른 cross-model 비교 | arXiv 원문 확인, 공개 code는 원문에서 확인하지 못함 |
| MYOPIA | 같은 dataset·model에서 tree vs zero-shot, 동일 coverage | API 비용·call 수를 무시한 accuracy 비교 | code·frozen DB·HF benchmark·MIT license 확인 |
| Spurious Heads | 같은 image와 controlled inpainting/ablation | dataset별 spurious rate를 모델 순위로 사용 | arXiv 원문 확인, clinical conclusion 불가 |
| FALCON | 동일 workload·hardware의 latency distribution | 6×ResNet proxy와 full FlashOcc latency 혼합 | arXiv 원문, HLS source·trace release 주장 확인 |

## 오늘의 benchmark signal 3개

1. **점수 향상의 원인을 귀속하라.** PARA는 perception과 reasoning, Cross-Prompt는 pretrained와 fine-tuning contribution을 분리한다.
2. **평균값 밖의 구조적 실패를 측정하라.** MYOPIA의 early exclusion과 annotation-reading head는 최종 accuracy가 숨기는 오류다.
3. **시스템 endpoint를 정확히 이름 붙여라.** proxy deadline, kernel latency, full-pipeline latency는 서로 다른 지표이며 “real-time” 주장을 공유할 수 없다.

## 내 연구에 바로 연결되는 포인트

- 항만·해무 VQA에 oracle crop, gold object list, stronger reasoner를 넣어 perception–retrieval–reasoning 병목을 먼저 귀속한다.
- long-tail 선박·부표 분류에서는 matched prompt 한 개 대신 prompt robustness curve와 rare/frequent recall을 함께 보고한다.
- 작은 객체 분류를 tree로 설명할 때 greedy path만 쓰지 말고 beam-2와 backtracking을 baseline으로 둔다.
- CCTV overlay, timestamp, camera ID를 제거·이동·shuffle한 artifact intervention split을 만든다.
- RTX 5060 Ti 환경의 “실시간” 평가는 inference만 재지 말고 decode부터 tracking까지 100k-frame tail latency와 stale-output age를 기록한다.
- 첫 실행 우선순위는 200개 항만 VQA에서 oracle crop 대 stronger reasoner 비교다. 새 학습 없이 benchmark 병목을 결정할 수 있다.

## 출처 확인 기록

- arXiv 공식 초록·submission history에서 다섯 논문의 v1 날짜와 주장 범위를 확인했다.
- MYOPIA는 공식 GitHub의 frozen archive, result database, coverage·deduplication 규칙을 논문과 교차검증했다.
- FALCON의 100 ms 결과가 full occupancy network가 아닌 fixed-work proxy임을 원문에서 확인했다.
- 주말 신규 배치가 없어 발견 창의 가장 최근 공식 공개 목록을 사용했고, 전날 다룬 항목은 제외했다.
- 확인되지 않은 leaderboard 순위, code release, 독립 재현 수치는 추가하지 않았다.
- 모든 정량 결과는 저자 보고값이며 독립 재현 결과와 구분했다.
