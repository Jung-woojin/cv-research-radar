## 3. reViT — 저장 파라미터와 실행 깊이를 분리

**공식 원문:** [arXiv paper](https://arxiv.org/abs/2610.12448), [HTML tables](https://arxiv.org/html/2610.12448)

### 확인된 사실

- reViT는 하나의 Transformer block을 깊이 방향으로 반복하고, 정규화된 깊이 좌표가 FFN expert bank의 가중합을 결정한다.
- ImageNet-1k 동일 학습 recipe 비교에서 reViT-B/16(E=4)는 23.6M params, 34.3 GFLOPs/image, Top-1 83.0%다. DeiT III-B/16은 86.6M, 33.9 GFLOPs, 82.8%다.
- L/16에서는 reViT가 40.9M, 121.5 GFLOPs, 83.8%; DeiT III가 304.4M, 119.9 GFLOPs, 84.1%다.
- 저자 표의 reViT 수치는 세 번 실행 평균이다. DINOv2 distillation 비교는 reViT가 final-layer feature만, Raptor가 intermediate feature도 사용해 학습 목표가 다르다.

### 저자 주장

저자는 depth-programmed weight-space merging이 한 개 FFN을 실행하는 계산 예산에서 token routing·output mixture보다 recurrence 손실을 더 잘 복구하며, 한 checkpoint의 추론 깊이를 바꿀 수 있다고 주장한다.

### 비교 가능성 감사

B/16과 L/16의 DeiT III 비교는 같은 데이터·base recipe·가까운 FLOPs로 설계되어 강한 내부 비교다. 그러나 compact dynamic graph와 fixed-depth materialization은 저장 공간이 달라지고, GFLOPs가 latency나 energy를 보장하지 않는다. DINOv2/Raptor 표는 supervision이 다르므로 절대 순위로 사용하지 않는다.

### 진단 → 가설 → 최소 실험

- **진단:** CV backbone의 저장 파라미터가 deployment 병목일 때 layer sharing은 정확도를 잃기 쉽다.
- **가설:** depth-conditioned FFN expert 네 개가 단일 공유 block의 표현 병목을 완화하며, B-scale에서 저장량을 크게 줄이고 Top-1을 유지한다.
- **최소 실험:** ImageNet-1k validation 10k 고정 subset에서 DeiT III-B/16과 reViT-B/16을 같은 batch·precision·compiler로 각각 3회 실행한다. Top-1, median/p95 latency, peak VRAM, checkpoint MB, GPU energy를 기록한다. 통과 기준은 Top-1 차이 ≥ -0.3pp, checkpoint ≤ 35%, p95 latency ≤ 1.10×다.

## 4. BudgetPix — 생성 품질을 유지하는 동적 토큰 예산

**공식 원문:** [arXiv paper](https://arxiv.org/abs/2610.12307), [author project page](https://karaozgur.com/BudgetPix/)

### 확인된 사실

- BudgetPix는 entropy-guided quadtree encoder, multi-scale decoder, variable-token training/sampling으로 pixel-space diffusion의 토큰 수를 조절한다.
- PixelDiT-T2I 1024²에서 25% token budget의 BudgetPix는 GenEval 0.725, DPG-Bench 83.7이다. Base model의 100% budget은 각각 0.721, 84.8이다.
- 같은 표에서 25% budget의 base model은 GenEval 0.323, DPG-Bench 55.1로 급락한다.
- 프로젝트 페이지는 MiniT2I-L 512²에서 25% budget GenEval 0.874와 full-budget 0.882를 보고한다. 코드는 현재 “soon”으로 표시되어 있다.
- 논문 프로토콜은 prompt, initial noise, solver, step count, attention arithmetic을 맞추고 cost를 wall-clock으로 측정한다.

### 저자 주장

저자는 이미지 복잡도에 따라 토큰을 배치하면 하나의 checkpoint로 넓은 계산 예산 범위에서 기존 token-merging baseline보다 좋은 품질-비용 trade-off를 얻는다고 주장한다.

### 비교 가능성 감사

동일 prompt와 noise를 쓰는 paired protocol은 강점이다. 다만 BudgetPix는 released backbone에 별도 fine-tuning과 새 encoder/decoder를 추가하므로 “무료 75% 절감”이 아니다. GenEval 0.725가 0.721보다 높아도 작은 차이의 통계적 유의성은 표만으로 확인되지 않으며, DPG-Bench는 1.1점 낮다.

### 진단 → 가설 → 최소 실험

- **진단:** 해무·해상 영상처럼 평탄 영역과 세부 경계가 공존하는 장면에서 균일 patch는 배경에 계산을 낭비한다.
- **가설:** entropy-based token allocation은 안개·하늘을 coarse token으로, 선박 경계와 부표를 fine token으로 남겨 동일 평균 token budget에서 객체 보존율을 높인다.
- **최소 실험:** 공개 checkpoint가 나오면 50개 maritime prompt와 고정 noise seed 5개로 100/50/25% budget을 평가한다. CLIP/DINO similarity, 작은 객체 검출 recall, wall-clock, peak VRAM을 측정한다. 25% 조건에서 recall 감소 ≤ 5pp이고 wall-clock ≤ 0.45×면 후속 검증한다.

## 5. Slot3R — 긴 스트림에서 정확도·속도·OOM 경계를 함께 이동

**공식 원문:** [arXiv paper](https://arxiv.org/abs/2610.12282), [author project page and code link](https://ashleyxyz.github.io/Slot-3R/)

### 확인된 사실

- Slot3R은 frozen Point3R에 set-associative K-way memory, 최대 640-token sparse readout, filtering·global anchors를 추가한 training-free retrofit이다.
- 7Scenes 500 frames에서 Point3R의 Acc/Comp/NC는 0.0745/0.0265/0.5510, Slot3R Core는 0.0275/0.0158/0.5790이다.
- 같은 표의 평균 처리율은 Point3R 16.77 FPS, Slot3R Core 19.17 FPS다.
- NeuralRGBD 500 frames에서 Acc는 0.2106→0.0589, Comp는 0.0706→0.0236, NC는 0.6025→0.6728이다.
- 저자 장기 시퀀스 프로토콜에서 Slot3R은 600–1000 frames를 약 19 FPS로 완료했고, Point3R·InfiniteVGGT는 800 frames 이상에서 OOM이었다.
- runtime/OOM 측정은 단일 RTX 4090 24GB, fused RoPE3D, data loading·metric 계산 제외 조건이다.

### 저자 주장

저자는 공간적으로 가까운 관측을 무조건 합치지 않고 같은 주소에 여러 상태를 보존하면 상충하는 viewpoint·surface evidence를 잃지 않으며, bounded readout이 persistent memory 성장과 frame당 attention cost를 분리한다고 주장한다.

### 비교 가능성 감사

Point3R 계열은 같은 fused RoPE3D 구현을 사용해 내부 비교가 비교적 공정하다. 그러나 논문 자체가 fused kernel이 Point3R을 4.547→14.750 FPS로 바꾼다고 보고하므로 커널·환경이 다른 외부 숫자와 직접 비교하면 안 된다. FPS는 encoder 선처리와 metric 시간을 제외한 forwarding speed다.

### 진단 → 가설 → 최소 실험

- **진단:** 장시간 해상 CCTV에서는 반복 배경과 카메라 회전으로 memory가 팽창하고, 근접 위치의 서로 다른 관측을 평균하면 작은 선박 구조가 흐려질 수 있다.
- **가설:** K-way 상태 보존과 bounded readout이 1000-frame 스트림에서 OOM을 늦추고, 얇은 구조의 geometry consistency를 지킨다.
- **최소 실험:** 공개 코드로 200/500/1000-frame 세 구간을 Point3R과 비교한다. 같은 GPU·fused kernel·resolution에서 Acc/Comp/NC, FPS, peak VRAM, final tokens를 3회 기록한다. 1000 frames 완료, peak VRAM ≤ 22GB, NC 비열화 ≤ 0.01을 통과 기준으로 둔다.

## 6. DVD — MLLM 위치 출력을 text coordinate에서 compact vector token으로 이동

**공식 원문:** [arXiv paper](https://arxiv.org/abs/2610.12266), [HTML results](https://arxiv.org/html/2610.12266)

### 확인된 사실

- DVD는 2D box, mask, 3D box를 1D vector sequence로 바꾸고 shared vector autoencoder/codebook의 discrete token으로 출력한 뒤 lightweight de-tokenizer로 복원한다.
- 동일 DVD 모델이 3D grounding, 2D grounding, referring segmentation을 수행한다.
- DVD-8B의 AP3D@15는 SUN-RGBD 40.3, Hypersim 18.4, ARKitScenes 62.1, KITTI 28.7, nuScenes 24.4다.
- DVD-2B는 RefCOCOg val/test Precision@0.5 89.9/90.0이고, Qwen3-VL-8B는 87.7/88.4다.
- DVD-8B가 모든 곳에서 2B를 이기지는 않는다. 예를 들어 ARKitScenes는 62.1 대 62.4, KITTI는 28.7 대 31.4다.

### 저자 주장

저자는 text coordinate의 긴 출력과 fixed-range quantization의 범위·정밀도 제약을 compact high-dimensional code로 피하면서 2D·3D perception을 하나의 decoder로 통합한다고 주장한다.

### 비교 가능성 감사

3D 표는 Omni3D의 AP3D@15를 사용하지만 각 baseline의 공개 항목이 달라 전체 평균을 만들 수 없다. 2D Precision과 3D AP는 의미가 다르다. 또한 8B가 2B보다 일부 dataset에서 낮으므로 parameter scaling만으로 결과를 설명할 수 없다. latency 절감은 hardware·decoding length가 명시된 동일 환경 재측정 전까지 방향성 주장으로 취급한다.

### 진단 → 가설 → 최소 실험

- **진단:** 해상 객체의 box·mask·거리 같은 구조 출력을 자연어 숫자로 생성하면 token 수와 parsing failure가 늘어난다.
- **가설:** compact vector tokens가 구조 출력 길이와 invalid-coordinate 비율을 낮추며, 특히 긴 mask polygon과 3D box에서 이점이 커진다.
- **최소 실험:** 같은 2B backbone으로 text-coordinate head와 DVD head를 500개 샘플에서 비교한다. output tokens, time-to-first-structure, total latency, invalid rate, 2D IoU/3D AP를 기록한다. token 수 ≤ 40%, invalid rate ≤ 1%, task metric 비열화 ≤ 1pp면 채택 후보로 둔다.

## 7. SiGMA — 산업 anomaly benchmark의 강한 결과와 강한 비교 경고

**공식 원문:** [arXiv paper](https://arxiv.org/abs/2610.12310), [HTML table and disclosures](https://arxiv.org/html/2610.12310)

### 확인된 사실

- MMAD는 7개 task의 39,670 multiple-choice questions로 구성된다.
- SiGMA는 frozen MLLM agents, reference-based defect expert, reliability controller를 결합하며 학습 없이 MMAD 평균 85.2%를 보고한다.
- 표의 학습형 최고 평균은 JUDO 81.2%다. SiGMA의 anomaly detection/defect localization은 82.6/79.6이고, JUDO는 65.0/73.0, OmniAD는 68.8/75.5다.
- 저자는 팀과 hyperparameter를 MMAD 정답으로 선택했고, controller는 평가 batch의 unlabeled predictions에 transductive fit했다고 명시한다.
- 표의 baseline들은 원 연구의 결과를 가져왔으며, prompt·reference image·parsing 등 평가 설정이 동일하다고 확인되지 않는다.

### 저자 주장

저자는 in-domain training이 domain language는 개선하지만 fine-grained perception gap을 닫지 못하며, 외부 defect expert와 이질적인 frozen agents의 역할 분리가 이를 보완한다고 주장한다.

### 비교 가능성 감사

85.2%는 주목할 결과지만 held-out benchmark의 unbiased estimate가 아니며, 학습형 baseline과 frozen-agent row의 조건 차이가 제목의 핵심 진단을 교란할 수 있다. 따라서 오늘의 “movement”는 확정된 leaderboard 교체가 아니라 동일 조건 rerun을 요구하는 강한 가설이다.

### 진단 → 가설 → 최소 실험

- **진단:** anomaly benchmark에서 평균 점수는 reference 제공 방식과 prompt/parsing 차이를 숨길 수 있다.
- **가설:** 같은 one-shot reference·prompt·parser를 적용하면 SiGMA의 절대 우위는 줄어도 reference-based defect expert의 detection/localization 이득은 남는다.
- **최소 실험:** MMAD의 고정 500-question stratified subset에서 Qwen2.5-VL-7B, JUDO/OmniAD 공개 checkpoint, SiGMA의 agent-only와 +defect-expert를 같은 protocol로 평가한다. task별 accuracy, reference retrieval 실패율, calibration false-positive rate, latency를 기록한다. defect expert 추가 이득이 detection/localization 각각 ≥ 5pp이고 다른 task 평균 손실 ≤ 1pp인지 본다.

## 8. 교차 신호

1. **Parameter count보다 접근 경로가 중요해졌다.** reViT는 depth별 weight를 저장하는 방식을, Slot3R은 매 frame 전체 memory를 읽는 방식을 바꾼다.
2. **Budget 축을 명시한 benchmark가 늘고 있다.** token budget, recurrent depth, readout size, output token length가 단일 정확도 옆의 독립 변수로 올라왔다.
3. **내부 protocol 통제가 leaderboard보다 중요하다.** BudgetPix의 paired noise, Slot3R의 fused kernel, SiGMA의 baseline protocol 차이는 숫자의 해석을 바꾼다.
4. **작은 모델이 항상 열등하지 않다.** DVD-2B는 일부 dataset에서 8B보다 높아 representation head와 dataset 특성이 규모 효과를 앞설 수 있음을 보여준다.
5. **재현 시 최소 세 축을 함께 본다.** task metric, wall-clock/VRAM, 조건 일치 여부를 한 표에 기록해야 실제 deployment 우위를 판단할 수 있다.

## 9. 오늘의 benchmark signal 3

1. **Slot3R long-stream OOM boundary:** 1000-frame 완료 여부와 peak VRAM을 먼저 재현할 가치가 가장 크다.
2. **BudgetPix 25% token budget:** 품질 수치와 실제 wall-clock 절감이 함께 유지되는지 확인해야 한다.
3. **reViT stored-parameter frontier:** checkpoint 크기 감소가 compiler 후 latency·energy에서도 이득인지 검증해야 한다.

## 10. Woojin 연구에 바로 연결할 실험

- 해무/해상 영상 1000-frame clip에서 Slot3R식 bounded memory를 적용해 작은 선박 경계의 geometry consistency와 OOM 시점을 측정한다.
- 생성형 augmentation pipeline에 BudgetPix식 entropy token allocation을 붙이고, 안개 영역과 선박 영역의 token density를 분리 기록한다.
- CNN/ViT 경량화 연구에서는 MACs만 보고하지 말고 stored params, compiled artifact MB, peak VRAM, p95 latency를 공동 지표로 둔다.
- VLM 기반 해상 객체 grounding은 text coordinate와 compact vector output을 같은 backbone에서 비교해 parsing failure까지 benchmark에 포함한다.
- 모든 결과에는 seed 수, 해상도, precision, GPU, kernel, data-loading 포함 여부를 명시한다.
