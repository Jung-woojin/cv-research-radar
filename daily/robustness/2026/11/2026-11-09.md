# Daily Robustness & Shift Watch — 2026-11-09

## 범위와 판정

조사 창은 2026-11-06~09 KST의 공식 release/repository/dataset 원문이다. 여기서 **사실**은 원문에 명시된 변경·구조이고, **가설**은 그 변경이 어떤 failure cell에서 결과를 바꿀지에 대한 검증 전 추론이다. 새 weather, camera, geography 또는 adversarial robustness 수치를 주장하는 자료는 찾지 못했으므로 만들지 않았다.

- V-Thinker는 perception·instruction-guided interaction·interactive reasoning을 분리한 VTBench를 공개했다. 과제별 입력 템플릿과 annotation image에 대한 민감도는 아직 측정되지 않았다.
- vLLM의 FP8 KV-cache scale 이슈는 정량화 런타임의 조건 의존성을 보여 주지만, vision robustness/hallucination의 직접 증거가 없어 후보에서 제외했다.
- 유지 후보는 3건이며, 모두 “진단 → 가설 → 최소 실험”으로 바로 검증할 수 있다.

## 유지 신호 1 — 가림 처리 변경은 카운트의 정의를 바꿀 수 있다

**사실.** Supervision 0.31.5 release note는 LineZone이 occlusion 동안 track state를 보존하도록 바뀌었고, `max_absent_frames`로 허용 부재 프레임 수를 설정할 수 있다고 명시한다. 이는 detector 모델 자체의 정확도 변경이 아니라 counting state machine의 변경이다.

**가설.** 가림 뒤 재등장한 객체가 새 track으로 처리되던 기존 파이프라인에서는 중복 계수가, 반대로 너무 긴 부재 허용에서는 실제 새로운 객체가 기존 track으로 흡수되는 누락 계수가 늘 수 있다. 효과는 가림 길이와 crossing 간격이 짧은 cell에 집중될 것이다.

**최소 실험.** detector, tracker, 영상은 고정하고 가림 길이(0/5/15/30 frames)와 `max_absent_frames`만 sweep한다. 각 cell에서 unique-object count error, false re-count, missed count, IDF1을 기록하고, release 전 버전과 0.31.5를 같은 입력으로 비교한다.

**GO / KILL.** 가림 cell에서 count error가 감소하면서 비가림 cell의 false re-count가 증가하지 않으면 GO다. 어느 설정도 두 오류를 동시에 줄이지 못하면 이 변경을 robustness 개선으로 일반화하지 않고 KILL한다.

## 유지 신호 2 — 추론과 검증의 NMS 기본값 분리는 crowding shift를 만든다

**사실.** Ultralytics v8.4.208 release note는 prediction 및 tracking의 NMS IoU 기본값을 0.7에서 0.5로 변경하고 validation 기본값은 0.7로 유지한다고 밝힌다. 같은 release에는 TensorRT 11 FP16 NMS-free export 개선도 있지만, 조건이 갖춰진 benchmark 표는 제공되지 않는다.

**가설.** 0.5 NMS는 가까운 중복 상자를 더 적극적으로 제거하므로 dense/small-object cell에서 detection 수, tracker association, count가 0.7 기반 validation과 다르게 움직일 수 있다. 방향과 크기는 데이터에 따라 달라 측정 전에는 주장할 수 없다.

**최소 실험.** 동일 checkpoint와 image size에서 IoU 0.5/0.7을 isolated, moderate-crowd, high-crowd 및 small-object strata로 나눈 holdout에 적용한다. detection 수, AP, recall, duplicate rate, ID switch와 calibration curve를 함께 저장한다. validation은 두 NMS 값으로 재실행하여 online–offline gap도 별도로 계산한다.

**GO / KILL.** high-crowd에서 duplicate rate 또는 ID switch가 의미 있게 줄고, isolated cell의 recall/calibration이 악화되지 않으면 0.5를 후보 기본값으로 GO한다. validation과 serving의 sign이 갈리거나 모든 crowding strata에서 recall 손실이 우세하면 KILL하고 explicit setting으로 고정한다.

## 유지 신호 3 — VTBench의 과제 분리는 template robustness를 직접 측정할 기회다

**사실.** V-Thinker repository는 perception, instruction-guided interaction, interactive reasoning을 구분하고, VTBench dataset은 이미지와 text parquet으로 500행의 `train` split을 제공한다. repository 설명은 해당 세 과제 유형을 벤치마크 범위로 제시하며 dataset viewer는 reasoning question/answer, perception question/answer, instruction, annotation image 관련 필드를 보여 준다.

**가설.** 모델이 시각적 근거보다 annotation image의 형식, instruction의 어순, 또는 질문 template에 의존하면 task family별 점수는 높아도 의미 보존 paraphrase·annotation ablation cell에서 급락할 수 있다. 이는 prompt injection의 증거가 아니라 template sensitivity 검증 가설이다.

**최소 실험.** 원본 500행에서 (a) 의미 보존 instruction paraphrase, (b) annotation image 제거 또는 중립화, (c) 질문 형식만 바꾼 조건을 만든다. 세 task family별 exact/semantic correctness, refusal/error rate, 그리고 원본 대비 flip rate를 분리 기록한다. 이미지 내용과 정답 의미는 바꾸지 않는다.

**GO / KILL.** 모든 task family에서 원본 대비 flip rate가 낮고 semantic correctness가 유지되면 template robustness를 GO한다. 특정 family에서 annotation 또는 paraphrase에만 오류가 집중되면 해당 입력 채널을 failure cell로 등록하고 KILL(배포 전 prompt/template 고정 또는 재학습 필요)한다.

## 해석상 주의

- Supervision·Ultralytics는 release-note 기반 **구현 변경 사실**이며, 실제 성능 방향은 위의 실험 전에는 알 수 없다.
- VTBench의 세 과제 구분과 dataset 필드는 **사실**이나, template shortcut은 **가설**이다.
- 이번 창에서 조사한 원문은 weather/geography/OOD 성능표, 공격 성공률, 또는 hallucination 비율을 제공하지 않았다. 따라서 그런 수치나 “더 robust” 결론은 보고하지 않는다.
