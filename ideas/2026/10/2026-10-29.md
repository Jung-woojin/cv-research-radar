# CV Paper Idea Radar — 2026-10-29 (Asia/Seoul)

## 핵심 요약

- 이번 회차는 10월 27일 공개된 cs.CV 원문에서 6편을 선별했다. 모두 arXiv v1 시각을 원문으로 확인했다.
- 강한 공통 신호는 더 긴 text chain-of-thought가 아니라 **시각 증거를 다시 읽는 방식·표현·도구 동작을 검증하고 제어**하는 쪽이다.
- VideoLVR은 잠재 visual token으로 영상 근거를 되살리고, PerceptRL은 도구 좌표 drift를 명시적으로 문제화하며, ImagiRep은 RGB 상상이 맞아도 공간 추론이 틀릴 수 있음을 보인다.
- CodeCap-Bench는 자연어 대신 실행 가능한 구조 표현을 영상의 보조 caption으로 시험한다. GroundControl은 위성 관측을 외부 공간 제약으로 사용한다.
- 가장 실용적인 빈틈은 ‘불확실/불일치가 있을 때 무엇을 재관측하거나 어떤 표현으로 바꿔야 실제로 정답이 좋아지는가’를 사전에 예측하지 않는 점이다.
- 이번 주 1순위는 **Evidence Utility Routing**: 작은 후보군에서 추가 crop·frame·표현 전환의 실제 이득을 예측하는 controller다. 실패해도 “추가 관측이 평균적으로 이득인지, 어떤 실패군에서 손해인지”라는 결과가 남는다.

## 관찰 → 진단 → 연구 기회

**확인된 사실:** VideoLVR은 latent visual evidence를, PerceptRL은 tool coordinate drift와 grounding-aware process reward를, ImagiRep은 질문별 표현 선택을 각각 전면에 둔다. CodeCap-Bench와 GroundControl은 표현 형식과 외부 관측의 가치가 task에 따라 달라질 수 있음을 시험한다.

**진단:** 현 접근은 대체로 (a) 근거를 재삽입/재구성하거나, (b) 올바른 도구 행동을 reward하거나, (c) 표현을 선택한다. 하지만 추가 관측·고해상도 crop·표현 변경이 **이 입력에서 실제 정답 이득을 낼지** 예측하고, 이득이 없을 때 실행을 멈추는 공통 controller는 명확히 검증되지 않았다.

**가설:** answer entropy나 단일 confidence보다, 후보 답변 간 불일치·grounding 안정성·표현 간 예측 변화의 조합이 추가 시각 compute의 조건부 utility를 예측할 수 있다.

## Proposal 1 — Evidence Utility Routing for Budgeted Visual Re-observation

1. **문제/가치:** 영상·고해상도 VLM은 모든 crop/frame/representation을 다시 읽을 수 없다. 제한된 token·GPU 예산에서 재관측이 실제로 정답을 바꾸는 sample만 선택한다.
2. **기존 gap:** VideoLVR은 근거 재방문을 가능케 하고 PerceptRL은 도구 행동을 보상하지만, action 전의 answer gain을 직접 예측하지 않는다.
3. **핵심 가설:** initial answer의 entropy, prompt disagreement, grounding-box stability, low/high-resolution prediction delta가 재관측 후 정답 개선 확률을 예측한다.
4. **구조/모듈:** frozen VLM → cheap probes(두 prompt·두 해상도·짧은 temporal view) → utility predictor → action selector {stop, crop, extra-frame, representation switch} → verifier. selector는 budget penalty를 받는다.
5. **baseline:** no extra observation, random action, entropy-only routing, fixed top-k crop/frame, oracle utility upper bound.
6. **데이터/지표:** TextVQA/DocVQA의 tiny-text subset과 NExT-QA 또는 EgoSchema의 evidence-dependent subset; accuracy, action rate, accuracy-per-extra-token, calibration(ECE), selective-risk curve.
7. **필수 ablation:** probe feature 제거, action type별 제거, oracle grounding 대 predicted grounding, fixed/variable budget, selector 학습 label의 temporal split.
8. **실패/negative result:** 추가 관측이 정확도를 올려도 token당 이득이 없거나, low confidence가 단순히 어려운 문제를 표시해 false positive routing을 만들 수 있다. 이 경우 utility signal의 비식별성을 보고한다.
9. **novelty 위험/방어:** 단순 dynamic routing으로 보일 위험이 있다. ‘조건부 action value’를 사전 예측하고 stop action까지 평가하며, evidence attribution으로 gain의 원인을 분해해 방어한다.
10. **4–8주 MVP:** 1주 probe/cache, 2주 offline utility label 생성, 2주 selector, 1주 ablation·재현. frozen 7B급 VLM과 2개 benchmark subset으로 시작한다.
11. **성공 시 contribution:** (i) re-observation utility benchmark/label, (ii) budgeted controller, (iii) 추가 compute가 해로운 failure strata 분석.
12. **제목 후보:** `Should the Model Look Again?`; `Evidence Utility Routing for Budgeted VLM Inference`; `Stop, Crop, or Revisit`.
13. **Abstract 개요:** evidence revisit의 비용 문제 → utility prediction formulation → cheap probe controller → accuracy/token 및 selective-risk 실험 → failure analysis.
14. **Introduction 흐름:** VLM evidence failure → 현재 uniform compute의 낭비 → action utility gap → controller와 benchmark → 실용적/과학적 기여.
15. **Related Work:** video/visual reasoning; adaptive computation; uncertainty/calibration; grounding/tool use; selective prediction.
16. **Method:** notation/budget; probe extraction; offline gain label; selector objective; action executor; verifier와 stop policy.
17. **표/그림:** action pipeline 그림; accuracy–token Pareto; utility calibration/reliability; action confusion matrix; 6개 성공·실패 사례.

**평가:** Novelty 4/5, Feasibility 5/5, Compute cost 2/5, Publication potential 4/5.

## Proposal 2 — Representation Disagreement as an Adaptation Gate

1. **문제/가치:** 같은 입력의 RGB, crop, depth proxy, top-down/geometry proxy가 다른 답을 줄 때, adaptation·prompt tuning이 도움이 될지 또는 더 나빠질지 모른다.
2. **기존 gap:** ImagiRep은 질문별 표현 효용을 보이고, data-efficient finetuning 연구는 backbone/transfer 조합을 비교한다. 둘을 연결해 sample/domain별 adaptation utility를 예측하지 않는다.
3. **핵심 가설:** representation disagreement가 높은 표본은 단일 representation fine-tuning에서 negative transfer가 크며, disagreement pattern이 adapter/LP/VP 중 안전한 intervention을 예고한다.
4. **구조/모듈:** frozen encoder의 multi-view representations → disagreement profile → gate {no-update, LP, LoRA, visual prompt} → small adapter; gate는 held-out gain과 degradation을 함께 예측한다.
5. **baseline:** global best adaptation, random per-sample method, entropy-only gate, always-LoRA, always-LP, oracle per-sample choice.
6. **데이터/지표:** DomainNet 또는 VTAB transfer와 aerial small-object crop subset; average accuracy, worst-domain accuracy, negative-transfer rate, gain prediction AUROC, update FLOPs.
7. **필수 ablation:** representation family 수, disagreement statistic, backbone family(CNN/ViT/SSM 가능 범위), per-domain vs per-sample gate, calibration set size.
8. **실패/negative result:** disagreement가 noise/occlusion만 반영하거나, per-sample intervention overhead가 gain을 상쇄할 수 있다. 이 경우 domain-level gate로 축소해 보고한다.
9. **novelty 위험/방어:** meta-learning/gating의 재포장 위험이 있다. 핵심은 representation disagreement를 ‘adaptation 전 안전성 진단’으로 정의하고 negative transfer의 사전 예측을 평가하는 데 있다.
10. **4–8주 MVP:** 두 backbone × LP/LoRA × 4 target domain; 10-shot calibration으로 시작한다. 먼저 offline predictor만 검증해 action learning 복잡도를 피한다.
11. **성공 시 contribution:** (i) representation disagreement와 negative transfer의 관계, (ii) safe adaptation gate, (iii) accuracy뿐 아니라 avoided degradation report.
12. **제목 후보:** `Adapt Only When Views Agree`; `Representation Disagreement Predicts Adaptation Utility`; `Safe Visual Transfer by Gated Updates`.
13. **Abstract 개요:** transfer의 평균 점수 한계 → representation disagreement → safe gate → negative-transfer reduction과 low-shot result.
14. **Introduction 흐름:** adaptation이 항상 이롭지 않음 → 현재 global policy → representation evidence gap → pre-update diagnostic → contribution.
15. **Related Work:** parameter-efficient tuning; domain generalization; uncertainty/disagreement; representation probing; negative transfer.
16. **Method:** multi-representation construction; disagreement features; utility/degradation labels; gate objective; deployment policy.
17. **표/그림:** domain별 gain/decline 표; disagreement–gain scatter와 calibration; Pareto(accuracy/update FLOPs); error taxonomy.

**평가:** Novelty 4/5, Feasibility 4/5, Compute cost 3/5, Publication potential 4/5.

## Proposal 3 — Executable Evidence Traces for Auditing Long-Video Reasoning

1. **문제/가치:** 자연어 reasoning trace는 실제 화면 증거와 느슨하게 연결될 수 있다. 긴 영상에서 answer가 맞아도 evidence 사용의 충실성은 알기 어렵다.
2. **기존 gap:** CodeCap-Bench는 code caption을 평가하지만 reasoning trace의 evidence fidelity를 검증하지 않는다. VideoLVR은 latent evidence를 쓰지만 외부 감사 가능한 trace가 아니다.
3. **핵심 가설:** 시간 구간·객체·공간 관계를 가진 실행 가능한 evidence program은 자연어 trace보다 counterfactual edit에 민감하며, answer correctness와 evidence faithfulness를 분리 평가하게 한다.
4. **구조/모듈:** frame/object extractor → compact event/layout DSL generator → program executor가 선택된 evidence를 재생/마스킹 → answerer → counterfactual verifier. 자연어 explanation은 program에서만 생성한다.
5. **baseline:** direct VLM QA, natural-language CoT, textual coordinate trace, VideoLVR-style latent evidence(공개 구현 가능 시).
6. **데이터/지표:** CodeCap-Bench 323 videos + NExT-QA/STAR의 temporal-relation subset; answer accuracy, program execution validity, counterfactual flip rate, trace length, hallucinated-object rate.
7. **필수 ablation:** DSL component(time/object/relation) 제거, program supervision source, executor 없이 program text만 사용, oracle detection vs predicted detection.
8. **실패/negative result:** DSL이 너무 좁아 open-world semantics를 잃거나, program syntax는 맞지만 perception이 틀릴 수 있다. syntax-validity와 evidence-validity를 별도 보고한다.
9. **novelty 위험/방어:** scene graph/video program 계열과 겹칠 수 있다. contribution을 ‘answer 감사용 counterfactual execution’과 fidelity metric에 제한해 명확히 한다.
10. **4–8주 MVP:** 2D structured subset 80개에서 4개 primitive(appear, move, overlap, before/after)만 사용한다. 이후 natural video로 확대한다.
11. **성공 시 contribution:** (i) executable evidence audit protocol, (ii) counterfactual faithfulness metric, (iii) correct-but-unfaithful 사례 분석.
12. **제목 후보:** `Can a Video Rationale Run?`; `Executable Evidence Traces for Auditable Video QA`; `Programmed Evidence, Verified Answers`.
13. **Abstract 개요:** natural-language trace의 검증 한계 → evidence DSL/executor → counterfactual audit → correctness–faithfulness 분리 결과.
14. **Introduction 흐름:** long-video reasoning 확산 → trace가 증거를 보장하지 않음 → executable representation 기회 → audit protocol과 분석.
15. **Related Work:** video QA; program induction; faithful explanations; scene graphs; counterfactual evaluation.
16. **Method:** DSL; perception-to-program; execution; answer conditioning; counterfactual edit; fidelity score.
17. **표/그림:** DSL/executor 그림; accuracy vs faithfulness 표; counterfactual sensitivity; validity/error breakdown; visual audit 사례.

**평가:** Novelty 5/5, Feasibility 3/5, Compute cost 3/5, Publication potential 4/5.

## 이번 주 1순위와 첫 실험

**선정: Proposal 1 — Evidence Utility Routing.** 이유는 (a) 최신 논문 세 축(VideoLVR·PerceptRL·ImagiRep)을 직접 연결하지만, (b) frozen VLM과 cached probes만으로 1~2주 내 판정 가능하고, (c) 실패해도 추가 visual compute의 조건부 이득/손해 지도를 남길 수 있기 때문이다.

**첫 MVP:** TextVQA/DocVQA에서 작은 글자 또는 표본 500개를 고정한다. base 7B VLM의 low-resolution answer를 얻고, 2× crop과 high-resolution 재질문의 실제 answer gain을 offline label로 만든다. probe는 answer entropy, 두 prompt 간 answer mismatch, predicted crop confidence, low/high-resolution logit delta 4개만 쓴다. logistic utility predictor를 random·entropy baseline과 비교한다.

- **GO:** top 25% routing이 random 25%보다 accuracy gain-per-extra-token을 뚜렷하게 높이고, bootstrap 95% CI가 0보다 크다.
- **KILL:** oracle action gain 자체가 1 percentage point 미만이거나, learned router가 random보다 낫지 않다. 이 경우 controller 대신 benchmark의 resolution/annotation artifact 분석으로 전환한다.

## 주의사항

- PerceptRL의 71.6% 및 상대 개선은 shared tool-use protocol 내부의 저자 보고치이며, 다른 모델/도구와 strictly apples-to-apples가 아니다.
- ImagiRep의 representation 결론은 simulator-grounded benchmark에서 나온다. 실제 aerial/video data로의 일반화는 가설이지 확인된 사실이 아니다.
- 새 논문들의 공식 코드·가중치 공개는 원문에서 확인되지 않은 경우 ‘없다’고 단정하지 않고 미확인으로 남겼다.
