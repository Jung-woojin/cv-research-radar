## LMCache v0.5.7rc4 — 버전명이 같아도 binary recipe는 같지 않음

**확인된 사실.** LMCache는 2026-11-03에 `v0.5.7rc4`와 CUDA 12.9, ROCm 7.2/7.2.4, Intel XPU/SYCL, MUSA, RBLN용 wheel을 따로 공개했다. ROCm 7.2.4 artifact는 `rocm/pytorch:rocm7.2.4_ubuntu24.04_py3.12_pytorch_release_2.10.0` container digest, Torch `2.10.0+rocm7.2.4.git3d3aa833`, CPython 3.12, C++11 ABI를 명시한다. CUDA 12.9 artifact는 linux/amd64·linux/arm64 wheel이며, XPU artifact는 host oneAPI/SYCL library에 bind된다고 설명한다.  
출처: https://github.com/LMCache/LMCache/releases

**확인된 사실.** MUSA artifact는 TorchMUSA·MUSA SDK·userspace runtime이 PyPI wheel에 포함되지 않고 matching runtime image에서 smoke-test됐다고 밝힌다. RBLN artifact도 `torch-rbln`, `rebel-compiler`, RBLN driver가 host-owned이며 bundle되지 않는다고 명시한다. 따라서 동일한 Python package tag만 맞추는 설치는 runtime equivalence를 보장하지 않는다.

**해석.** KV-cache/serving 실험에서 latency, cache hit, memory, crash 여부가 다르면 먼저 model/algorithm 효과가 아니라 `(wheel tag, accelerator backend, Torch/ABI, container digest, host driver, vLLM base image)`가 동일한지 확인해야 한다. 서로 다른 backend 결과는 **not strictly apples-to-apples**다.

**가능한 메커니즘.** wheel은 Python/API layer만 같아도 kernel, compiler, driver, linked library, ABI가 다르면 cache serialization·allocator·P2P path와 attention execution이 달라질 수 있다. 이 회차에서는 그 차이의 실제 크기나 오류율을 재현하지 않았다.

**진단 → 가설 → 최소 실험.**
- 진단: `pip freeze`만 저장하면 host-owned runtime과 base image 차이를 잃어 재실행 시 같은 cache/throughput claim을 검증할 수 없다.
- 가설: recipe manifest에 wheel filename/hash, base image digest, `torch.__version__`, backend runtime, driver, GPU architecture, model revision, engine/cache directory hash를 넣으면 결과 차이의 환경 기여를 분리할 수 있다.
- 최소 실험: 고정 prompt batch와 고정 model revision에서 (A) 완전 pin된 upstream container, (B) 같은 package tag지만 base image 또는 host runtime이 다른 조건을 각각 3회 실행한다. first-token latency, decode throughput, cache hit/miss, peak memory, generated-token hash, crash/retry를 비교한다.
- **GO:** 3회 모두 동일 artifact hash에서 token hash와 service-level metric이 사전 tolerance 안에 있을 때. **KILL:** backend/runtime만 바꿨는데 output·cache compatibility·latency가 달라지거나 runtime metadata가 수집되지 않을 때.

## 오늘의 재현 규칙

1. `package==version`만이 아니라 wheel URL/hash, base container digest, backend SDK, Torch/ABI, driver와 GPU architecture를 결과표에 기록한다.
2. generated text/video 결과뿐 아니라 engine/cache directory hash와 first-token/decode 구간 metric을 분리한다.
3. runtime smoke test 성공을 manuscript-level checkpoint score 재현으로 과장하지 않는다.

## 한계

- LMCache release는 지원·빌드·smoke-test 환경을 밝힌 공식 artifact이고, 이번 실행은 설치·벤치마크·독립 reproduction을 수행하지 않았다.
- 이 회차에는 최신 공식 원문으로 확인되는 독립 재현 실패나 seed-variance 수치가 부족했다.
- 따라서 특정 backend가 더 빠르거나 더 정확하다는 결론은 내리지 않았다.
